- Semantics notes (each comes from the C# read at the baseline):
  1. **Provider order.** `[Wpf?], WicDirect, [TurboJpeg], [LibRaw]`. The Wpf entry exists only when the host gives a provider. TurboJpeg and LibRaw are listed only if
     their probe says available. Each probe is called exactly once. Building the list constructs no decoder (all providers lazy; a test that counts constructions must see 0).
  2. **Logging.** TurboJpeg unavailable: `error_forced("TurboJPEG decoder backend is not available and will not be registered: {reason}", ProbeFailure(reason or "TurboJPEG probe failed."))`.
     LibRaw unavailable: needed (closure absent, or returns true) => `error_forced("LibRaw decoder backend is not available and will not be registered: {reason}", ..)`;
     not needed => `info("LibRaw decoder backend is not available (RAW support is off, so it is not needed): {reason}")` and NO error. A `None` reason prints empty in
     the message (C# string interpolation of a null). `is_libraw_needed` is evaluated only on the unavailable path. Available LibRaw logs nothing about LibRaw.
  3. **LibRaw preview fallback.** `format != Orf` => `DecodeError::NotSupported` with message `LibRaw thumbnail fallback is not enabled for {format}.` (format = the C# enum name,
     which the derived `Debug` of `RawFormat` prints) BEFORE the path is touched (the C# test uses a path on drive Z that does not exist). `Orf` delegates unchanged to
     `pr_libraw::decoder::read_jpeg_thumbnail(api, path, &CancelToken::none())`: a blank path is its `InvalidArgument` (C# `ArgumentException`), a missing file its
     `InvalidData`. The result is the complete JPEG (starts FF D8, ends FF D9; the trimming is LibRaw's, not ours).
  4. **RAW wiring.** `libraw_probe` once. Available: fallback and no-preview decoder are both created (once each) and both set. Unavailable: neither closure runs, both `None`.
     Never a half wiring (fallback without the no-preview decoder, or the reverse).
  5. **WebP/HEIC chain.** Always `WicDirect` over the SHARED source reader; with a Wpf fallback it is wrapped in `FallbackImageDecoder(wic, WicDirect, wpf, log or NullLog, metrics)`,
     without one `WicDirect` stands alone (Win32 host, NE-8). The Rust app is always the Win32 host, so production passes `None`.
  6. **Source prefetch.** A path the router would refuse (`WebpHeicRoutingDecoder::will_refuse`: switch off, or a WebP/HEIC file whose Windows codec is missing) is never opened:
     no `SourceReader::open_source` call, no cache entry. The five theory rows: `a.jpg` enabled => read; `a.heic` enabled without HEIF => no read; `a.webp` enabled with WebP => read;
     `a.webp` switch off => no read; `a.heic` enabled with HEIF => read. The switch and the codec probe are closures read per call. A token cancelled before the call gives
     `Err(Canceled)` (C# `Task.Run(..., token)`), checked AFTER the refusal test (a refused path returns `Ok` even when cancelled, as the C# conditional does).
  7. **Recovery retry.** `create_recovery_retry_service` reads the permanent-delete setting from the store at EVERY retry (the closure captures the `Arc<SettingsStore>`, not a bool).
     Test 1: the setting off, a Delete-group member marked `permanent` => result not succeeded, the fake bin has NO recycled and NO permanently-deleted path, both files still exist.
     Test 2: off then on (a NEW `AppSettings` saved) => the second retry succeeds, the JPG is recycled, the RAW (no-bin drive) is deleted permanently.
  8. **Shared contracts.** `SharedServiceOptions` has no `IServiceProvider` argument (no DI container): its closures are plain `DecoderProvider`s. `thumbnail_decoder` is reserved (C# only
     null-checks it). `MainViewModelSinkCallbacks` closures run on the UI thread only (no `Send`).
- Traps checklist:
  - **T1 Lazy providers.** Do not call a decoder constructor while building the list or the options (C# uses `Func<>` everywhere). A test with a counting closure pins it.
  - **T2 Probe once.** Calling a probe twice changes log output and, for a flaky native load, the result. `create_raw_decoder_with` probes exactly once.
  - **T3 Severity.** LibRaw missing with RAW support off is `info`, never an error: otherwise every start of a machine without `libraw.dll` writes an error into the log.
  - **T4 Case of messages.** The message texts are English literals and exact (the C# tests only check `Contains("TurboJPEG")` / `Contains("LibRaw")`, but logs are read by support). Not UI text (D-W8-4
    does not apply: these are diagnostics, like the rest of `AppLog`).
  - **T5 Setting read at call time (Q-R8).** A closure that captured `settings.allow_permanent_delete_without_recycle_bin` as a value would pass test 1 and fail test 2.
  - **T6 No read for refused paths (INV-8, AGENTS.md priority 1).** `will_refuse` must run before `try_prefetch`; do not call `try_prefetch` and discard the result.
  - **T7 Cancelled token order.** Refusal test first, then the cancel check, then the read (see note 6).
  - **T8 `SourceBytesError` mapping.** `Io(Arc<io::Error>)` is not `Clone`: rebuild an `io::Error` with the same kind and message for `DecodeError::Io`.
  - **T9 Recycle Bin.** The recovery tests use `pr_test_support::FakeRecycleBin` and `TempRoot`; never the real bin (AGENTS.md).
  - **T10 Thread affinity.** `composition::contracts` closures are UI-thread-only; everything in `decoders`/`factories` is `Send + Sync` and may run on any worker thread.
  - **T11 Non-Windows.** `pr_platform_win::wic` is `#[cfg(windows)]`; the workspace builds on Windows only (CI `windows-latest`), so `decoders.rs`/`factories.rs` do not add a `cfg`.

## Open questions (each has a recommended default; the stubs follow it)
- **O1 Native seams in `DecoderDeps`.** The C# decoders reach the OS on their own; the Rust ones need `MemoryInfoSource`, `LibRawApi`, `FineScaler`, `TurboJpegTexts` by constructor.
  Default (used): one `DecoderDeps` value built by the host. No production `MemoryInfoSource` impl for `pr_platform_win::memory_probe::WindowsMemoryProbe` and no `FineScaler` adapter over
  `wic::scaler::resize` exist yet: W8-09b/W8-17c must add them (or a closure `|| WindowsMemoryProbe...` through the blanket impl). Not decided here.
- **O2 `Func<IServiceProvider, IImageDecoder>`.** Became `DecoderProvider` (no container). Alternative: keep an `&dyn ServiceProvider` trait; rejected (P-38: explicit builder).
- **O3 Production codec.** `PixelBufferImageCodec` (`pr_imaging::pixel_memory`) is the Win32 shell's codec; W8-09b passes it. This unit takes `Arc<dyn PlatformImageCodec>` only.
- **O4 `AppLog` signatures.** `CompositionLog` forwards to `AppLog::error_forced` / `AppLog::info` of the B1 stub (`misc::app_log`); if W8-04d changes them the adapter follows.
- **O5 Prefetch result.** C# returns a `Task` whose `bool` result is dropped; Rust `PrefetchSourceBytesFn` returns `Result<(), DecodeError>`. Used as is.
- **O6 Changes to B1 stubs:** none required.
