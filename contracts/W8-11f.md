## Semantics notes (C# is the spec)

### What is retired and why (audit table of the four files)
| C# member | Fate | Reason |

| `ComInterop.Wrap<T>(nint)` | **retired** | windows-rs returns owned, reference-counted interface values; there is no raw pointer to wrap |
| `ComInterop.QueryInterface(nint, Guid)` | **retired**, replaced by `Interface::cast::<T>()` | `cast` is `QueryInterface` and returns an owned interface; use `.gfx("QueryInterface IDXGIDevice")` for the error name |

### `com.rs`
1. `GfxError` is `Copy`: an HRESULT and a `&'static str`. No `String`, no source chain; the message is `"{operation} failed with HRESULT 0x{hresult as u32:08X}"`, identical to
   `RenderError::Device` of W8-12a, so W8-12b..12i convert field by field.
2. `check(op, hr)`: **`hr >= 0` is success** (S_OK, S_FALSE, `DXGI_STATUS_OCCLUDED`, `DXGI_STATUS_*`). Only negative values are errors. Mirrors `if (hr < 0)`.
3. `is_device_lost(hr)` is true for exactly `0x8899000C`, `0x887A0005`, `0x887A0007` (the values as `i32`, i.e. negative). `DXGI_ERROR_WAS_STILL_DRAWING`, `DXGI_STATUS_OCCLUDED`, `E_FAIL`, 0 and
   `DXGI_ERROR_INVALID_CALL` (0x887A0001) are NOT device losses.
4. `describe_hresult(hr)` formats `hr as u32` as `0x` + 8 upper-case hex digits, zero padded, invariant (C# `"0x" + ((uint)hr).ToString("X8", InvariantCulture)`): `-2005270523` gives `0x887A0005`.
5. `ResultExt::gfx` keeps `e.code().0` (the HRESULT of the `windows` error). A `windows` error whose code is not negative (should not exist) is passed through unchanged.
6. `hwnd(raw)` is `HWND(raw as *mut c_void)`: `pr_app` carries window handles as `isize` (C# `nint`, D-W8-16e-2). 0 maps to a null `HWND`; the callers (`create_window_swap_chain`) reject it.

### `extras.rs`
7. `WaitableTimer::new()` tries `CreateWaitableTimerExW(None, None, CREATE_WAITABLE_TIMER_HIGH_RESOLUTION, TIMER_ALL_ACCESS.0)` and, if it fails (Windows 10 before 1803), the same call with
   flags 0 (C# `GpuKeepAlive.Run` lines 169-173). `is_high_resolution()` says which one succeeded. Both failing is `Err` with the last error's HRESULT; what to do then is the caller's choice
   (`GpuKeepAlive` sleeps with `std::thread::sleep`, the host clock fails to start, as C# `TimerFrameClock` threw `Win32Exception`).
8. `set_relative_ms(ms)` uses `relative_due_time_100ns(ms) = -(ms as i64) * 10_000` (negative = relative, 100 ns units; `ms <= 0` gives 0 = fire at once). `set_due_100ns(d)` passes `d`
   through (period 0, no completion routine, `resume = false`).
9. `wait(timeout_ms, alertable)` is `WaitForSingleObjectEx`. `timeout_ms = u32::MAX` is `INFINITE`. The C# `WaitForNextFrame` clamps a negative timeout to 0 before the cast: W8-12d does that.
   An invalid or null handle gives `WaitResult::Failed` (the call returns `WAIT_FAILED`), never a panic.
10. `WaitableTimer` owns its handle through `Owned<HANDLE>`: dropping it closes the handle once. `handle()` returns a COPY of the raw handle for `MsgWaitForMultipleObjectsEx`; the caller must
    not close it and must not use it after the timer is dropped. The type is automatically `!Send` (raw pointer inside `HANDLE`): create the timer on the thread that waits on it, as C# did
    (`GpuKeepAlive.Run` creates it on the keep-warm thread).
11. `create_ellipsis_trimming_sign(factory, format)`: `factory.CreateEllipsisTrimmingSign(format)`. An `IDWriteTextLayout` derefs to `&IDWriteTextFormat`, so a layout may be passed as the format
    (C# passed the layout).
12. `set_character_ellipsis_trimming(factory, layout)` is exactly `DWriteTextRenderer.Build` lines 123-125: sign, then `SetTrimming(&DWRITE_TRIMMING { granularity:
    DWRITE_TRIMMING_GRANULARITY_CHARACTER, delimiter: 0, delimiterCount: 0 }, &sign)`. The caller (W8-12i) has already set `SetWordWrapping(DWRITE_WORD_WRAPPING_NO_WRAP)`; this helper does not.
    The layout holds its own reference to the sign, so the local `sign` is dropped when the function returns. Without the sign DirectWrite cuts the text without drawing "...".

## Safety rules (every `unsafe` block gets a `// SAFETY:` comment; the lint `undocumented_unsafe_blocks` is on)
- All windows-rs COM calls are `unsafe fn`. The SAFETY comment names (a) the validity of every pointer argument (locals that outlive the call), (b) that the interface receiver is a live owned
  value, (c) which thread (UI thread / the thread that created the object).
- No raw pointer to a COM object is stored. No `ManuallyDrop` of interfaces except the `colorContext` field of `D2D1_BITMAP_PROPERTIES1` (11h), always `ManuallyDrop::new(None)`.
- No `mem::forget`, no `from_raw` of interfaces. `Owned::new(handle)` is the only ownership transfer of a raw value, and only for a handle that the API documents as caller-closed
  (`CreateWaitableTimerExW`, `GetFrameLatencyWaitableObject`).
- Thread affinity: `com.rs` and `guids.rs` are plain data. `WaitableTimer` is `!Send` (see rule 10). Nothing in this unit spawns a thread, takes a lock or reads the environment.
- COM apartment: DXGI, D3D11, Direct2D and DirectWrite factories work without `CoInitializeEx` on the calling thread. This unit never initializes COM; the host does (W8-13).
- `unsafe_op_in_unsafe_fn = deny` applies: no `unsafe fn` in this unit (every public function is safe and checks what it must).

## Error mapping
- Every fallible function returns `GfxError { hresult, operation }`; `operation` is a `&'static str` naming the API (`"CreateWaitableTimerExW"`, `"IDWriteFactory::CreateEllipsisTrimmingSign"`,
  `"IDWriteTextFormat::SetTrimming"`, `"SetWaitableTimer"`, `"CancelWaitableTimer"`).
- Device loss: no function in this unit can tell a device is lost except by the HRESULT; `GfxError::is_device_lost()` is the single predicate. Callers in W8-12b/12d/12g test it after
  `EndDraw`, `Present`, `ResizeBuffers` and after bitmap uploads, then recreate the device; those flows are theirs (D2DERR_RECREATE_TARGET, DXGI_ERROR_DEVICE_REMOVED, DXGI_ERROR_DEVICE_RESET).
- `GfxError` -> `pr_app::services::render::RenderError::Device { hresult, operation }` is a field-for-field copy done in `pr_platform_win::render` (W8-12b), never in `gfx` (no `pr_app` import).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (COM lifetime): Rust drops struct fields in DECLARATION order. The teardown order of `DeviceResources.ReleaseAll` (target bitmap, probe, wait handle, brush, context, device, factory,
  `ClearStateAndFlush`, swap chain, D3D device) must be reproduced by field order or explicit `take()` calls in W8-12b/12c. `com.rs` cannot enforce it; the tests of 12b/12c do.
- T2 (HRESULT sign): `0x887A0005` as a Rust literal is `u32`; store `i32` via `as i32`. A comparison of an `i32` HRESULT with a `u32` literal never matches.
- T3 (`>= 0` is success): S_FALSE and `DXGI_STATUS_OCCLUDED` must not become errors in `check`; `classify_present` (11g) treats OCCLUDED before any error test.
- T4 (handle ownership): `GetFrameLatencyWaitableObject` returns a handle that THE CALLER CLOSES (C# `DeviceResources.ReleaseAll` calls `CloseHandle`); the comment in `Dxgi.cs` line 252
  ("do not close") contradicts the code (which is what ran in production and in the leak tests). Wrap it in `Owned<HANDLE>` exactly once (11g does).
- T5 (i64 due time): `-(ms as i64) * 10_000`; an `i32` product overflows at about 214 seconds. C# casts to `long` first.
- T6 (INFINITE): `u32::MAX` waits forever; the helper does not special-case it.
- T7 (timer not shared): never move a `WaitableTimer` to another thread; the keep-warm thread creates its own.
- T8 (ellipsis order): `NoWrap` first (caller), then the sign, then `SetTrimming`. With wrapping on, a trimmed layout wraps instead of cutting.
- T9 (no `String` in `GfxError`): it must stay `Copy` so it can be returned from hot paths (`Present`) without allocation.

## Decisions taken in this contract (D-W8B3G-n; the lead may overrule in `contracts/README.md`)
- **D-W8B3G-1 `gfx` is std + `windows` only**: no `pr_app`, no `pr_core` type in any `gfx` signature (window handles are `HWND` here, `isize` at the `pr_app` boundary via `com::hwnd`).
- **D-W8B3G-2 One error type `GfxError`** (`Copy`, `{ hresult, operation }`) for the whole `gfx` layer; `RenderError::Device` is its twin in `pr_app`.
- **D-W8B3G-4 One waitable timer** (`extras::WaitableTimer`) for `GpuKeepAlive` and the host `TimerFrameClock`; `PendingKernel32` is not ported; `CancelWaitableTimer` becomes `cancel()`.
- **D-W8B3G-5 `DeviceLoss` helpers live in `com.rs`**, not in the `DeviceResources` port, so W8-12b and W8-12d share one definition.
- **D-W8B3G-7 `ComInterop.Wrap/QueryInterface/Release` are retired**, not re-created as helpers; `Interface::cast` and `Drop` are used directly.
  (D-W8B3G-3, -6, -8, -9 belong to 11g/11h and are listed in `contracts/README.md`.)

## Open questions
1. **Where does the host `TimerFrameClock` get its timer?** Recommended (taken): `extras::WaitableTimer` (D-W8B3G-4). Alternative: W8-11b's `win32::api` re-exports kernel32 wrappers and the clock uses those;
   rejected because 11b's C# input (`Kernel32.cs`) has no timer calls and a second implementation would drift.
2. **`WaitableTimer: Send`?** Recommended: no (`!Send`, rule 10). If W8-13 wants to create the timer on one thread and wait on another, it must say so before the port; `unsafe impl Send` would need a
   contract change.
3. **Should `guids.rs` stay at all?** Recommended: yes, 27 constants and one test, about 100 lines, no production use. Alternative: delete the file and keep only the test that every C# IID string appears in the
   windows-rs interface list; rejected because the table documents the C# members for the audit.
