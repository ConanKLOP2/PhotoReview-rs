## Semantics
1. **Key (D-07, persisted: byte-identical).** `build_stamp = format!("{full_path}|{length}|{ticks}|800|orient=1")`, `full_path`
   exactly as `get_full_path` returned it (case, Unicode form and `\\?\` prefix kept; NOT upper-cased, unlike the preview key and
   `perf::path_id`); `build_key` = lowercase hex SHA-256 of its UTF-8 bytes (64 chars); file = `<dir>\<key>.png`
   (`Path::join`, C# `Path.Combine`). `C:\A.jpg` and `c:\a.jpg` are two keys (golden `lowercase-spelling-is-another-key`), and so
   two RAM entries and two loads: parity, do not "fix" it. Length is `u64` in Rust (`long` in C#): same decimal text up to
   `i64::MAX` (golden `max-length`).
2. **`get` order** (C# `GetAsync`): (a) `source_path` empty or all `char::is_whitespace` -> `Err(BlankPath)` (BEFORE the disposed
   check: a blank path on a disposed cache is BlankPath); (b) perf `t0` when `PhotoReviewPerf::log().is_enabled()`; (c) lifecycle
   lock: disposed -> `Err(Disposed)`; clone the dispose token; (d) `get_full_path(source_path)` (W2-00): `Err(e)` ->
   `Ok(Ready(Err(InvalidPath(e))))`; (e) key: `known_stat` `Some(s)` -> `build_key(full, s.length, s.last_write_utc.ticks())`
   without touching the disk; `None` -> `fs.get_file_stat(full)`, `None` (missing file OR a directory) -> `Ok(Ready(Err(Stat(
   io::Error NotFound))))`; (f) RAM `try_get(key)` hit -> perf `thumb_end(nav_context(), path_id(full), "ram", ms(t0))` (only when
   t0 != 0) and `Ok(Ready(Ok(Some(img))))`; (g) lock `in_flight`: an entry for the key -> join it; else insert a new
   `SharedLoad` (C# `GetOrAdd`); release the map lock; THEN read the generation (C# `Volatile.Read` at the top of
   `AwaitAndCacheAsync`, which runs after `GetOrAdd`; reading it under the lifecycle lock is fine); THEN, only if this call
   inserted, spawn the job (C# `lazy.Value` starts the load after the read); return `Pending { load, key, generation }`.
   Consequence (parity, do not "fix"): the STARTER's generation predates the load, but a JOINER's generation is the one at join
   time, so a caller that joins a load after `clear_memory` caches that load's result (C# does the same).
3. **Shared load job** (C# `Lazy` + `ContinueWith`): runs `load_or_create` inside `catch_unwind` (panic -> `Err(Panicked(msg))`),
   publishes the outcome in the `SharedLoad` and `notify_all`, THEN removes the map entry only if it is still this load
   (`Arc::ptr_eq`, C# `TryRemove(KeyValuePair)`). A failed spawn publishes `Err(Spawn(e))` and removes the entry the same way.
   Failures are never cached: the next `get` starts a new load (test `FailedLoad_IsNotCached`).
4. **`load_or_create`** (C# `LoadOrCreateAsync`): `token.check()` -> `Err(Canceled)`; perf context comes from the CALLER (nav is a
   thread-local in Rust: capture `nav_context()`, `path_id(full)`, `t0 = timestamp()` before spawning; C# reads its AsyncLocal on the
   caller's thread too); `cache_path = cache_file_path(dir, key)`; if `fs.file_exists(cache_path)`: `token.check()` (C#
   `Task.Run(.., token)`: a cancelled token is `Canceled`, NOT a cache-entry failure), then `decode_disk_thumbnail`:
   `Ok` -> `disk_store.note_accessed(cache_path)`, perf `"disk"`, `Ok(Some)`; `Err(e)` with `is_cache_entry_failure(&e)` ->
   `log.error("Disk thumbnail read failed: {cache_path}", Some(&e))`, W4-09 free fn `try_delete(cache_path, Some(log))`, fall
   through; other `Err(e)` -> `Err(Decode(e))` (entry kept). Then `is_raw_path(full)` -> `Ok(None)` WITHOUT a perf event and WITHOUT
   calling the reader; else `embedded_reader(full, token)?` (errors propagate as they are), perf `"embedded"` / `"none"`, return it.
   There is no full-source decode fallback, ever (I-09 perf rule), and this type never WRITES the disk cache.
5. **RAM caching** (C# `AwaitAndCacheAsync`): a waiter that observes `Ok(Some(img))` (`wait`, `wait_timeout` returning `Some`,
   `try_result` returning `Some`) takes the lifecycle lock and `ram.set(key, img)` only when `!disposed && generation ==
   current`. It returns the image in every case. A handle dropped without observing caches nothing (C#: a cancelled caller skips
   the set). `Ready` results are never re-set. RAM capacity `max_ram_bytes`, size = `estimated_bytes()` (W1-08 LRU).
6. **`decode_disk_thumbnail`** (C# `DecodeDiskThumbnail`, WP-04): `fs.open_read_shared(path, 1)` (ReadWrite|Delete sharing,
   SequentialScan: INV-8); length via `seek(End)`+rewind; `0` or `> MAX_DISK_ENTRY_BYTES` -> `InvalidData("Thumbnail cache entry has
   an invalid length.")` before allocating; `read_exact` (a shrink is an `Io` UnexpectedEof: a cache-entry failure); then
   `reader.decode(&bytes, None, DecodeBox::new(800, 0), 0, 0)`; `codec.image_from_pixels(pixels)`; `DecodedImage::new(img, w, h,
   i64::from(w) * i64::from(h) * 4, { downscaled: info.downscaled, orientation: 1, WicDirect, original: info.source_* })`; a
   `DecodedImage` guard error -> `DecodeError::InvalidArgument` (C# `ArgumentException`). The handle is closed before decoding.
   Golden error mapping (.NET -> Rust): `InvalidDataException` -> `InvalidData`; `FileNotFoundException` -> `FileNotFound`;
   `COMException` -> `Com { hresult }`; `InsufficientMemoryException` -> `OutOfMemory` (NOT a cache-entry failure).
7. **`clear_memory`**: lock; `generation = generation.wrapping_add(1)`; `ram.clear()`. **`clear_disk`**: lock; generation += 1;
   unlock; `disk_store.clear_directory()`; `Err(e)` -> `log.error("Thumbnail disk cache clear failed: {dir}", Some(&e))`. It does
   NOT clear RAM, does NOT check `disposed` and does not touch in-flight loads. Per-file delete failures are logged by W4-09
   (`Delete failed: {path}`; temp files unlogged).
8. **`dispose`** (idempotent; also from `Drop`): lock; if disposed return; disposed = true; generation += 1; `ram.clear()`; unlock;
   `dispose_token.cancel()`. Running loads keep going (the injected reader may ignore the token: test `DisposeDuringLoad`); a
   pending `wait` still returns their result; nothing is cached afterwards; later `get` -> `Err(Disposed)`. Pending handles hold an
   `Arc` of the shared state, so they stay valid after the cache is dropped.
9. **Construction**: `max_ram_bytes <= 0` -> `MaxRamBytes`, then `max_disk_bytes <= 0` -> `MaxDiskBytes` (C# order: codec, RAM,
   disk); `DiskCacheStore::new(dir, "*.png", max_disk_bytes, Some(log), Some(clock))` (W4-09: `Result<_, InvalidStoreArgument>`;
   a blank directory -> `BlankDiskDirectory`, the C# `ArgumentException` of the store ctor; the pattern is a constant and never
   fails); spawn the start-up sweep W4-09 free fn `delete_stale_temp_files(dir, clock.utc_now(), 5000, Some(log))` with the
   spawner (it logs its own listing failure; spawn failure: log `Stale temp file cleanup failed: {dir}` and mark the signal
   done; OQ8); build the LRU (`BoundedLruCache::new(max_ram_bytes, ..)` cannot fail after the check). No file is created by
   construction (the directory is not created either: C# never creates it here; a missing directory makes the sweep and
   `clear_directory` no-ops).
10. **Default reader**: `token.check()` -> `Canceled`; then W4-02b `try_read(Path::new(full), fs, backend, codec)`:
    `Ok(Some(img))` -> `Ok(Some(Arc::new(img)))`, `Ok(None)` -> `Ok(None)`, `Err(BlankPath)` (impossible after `get_full_path`) ->
    `Err(InvalidPath(PathError::Argument))`. **Default spawner**: `thread::Builder::new().name("PhotoReview.ThumbnailLoad")`
    (`PhotoReview.ThumbnailCleanup` for the sweep); `Err` from `spawn` is returned.

## Traps checklist (MULTI-AGENT-PLAN §7 + this unit)
- §7.1: the in-flight and RAM keys are lowercase hex, so C# `OrdinalIgnoreCase` there is moot; but the STAMP is case-sensitive
  (semantics 1). Do not route the path through `pr_core::text::ignore_case_key`.
- §7.3: `estimated_bytes = i64::from(w) * i64::from(h) * 4` (C# `(long)width * height * 4`); never `i32` math. Generation
  `wrapping_add` (D3).
- §7.5: ticks are `DateTimeUtc::ticks()` (.NET 100 ns since 0001-01-01), not Unix time (golden `max-ticks`, `zero-length-zero-ticks`).
- §7.7: `get_full_path` before keying (goldens `forward-slashes-normalized`, `dot-segments-normalized`, `extended-prefix-kept`).
- §7.9: three different failure classes after a disk read: cache-entry failure (delete + fall back), cancellation (propagate, keep
  the entry), other (propagate, keep the entry). Do not collapse them into one `Err(_)`.
- INV-2: generation captured per caller after `GetOrAdd` and, for the starter, BEFORE the load starts (semantics 2g); checked
  under the same lock as `disposed` when caching. A mutant
  that drops `generation == current` or `!disposed` must fail `ClearMemoryDuringLoad_ResultIsNotCached` / `DisposeDuringLoad`.
- INV-8: one shared open of the disk entry, closed before the decode; the source is opened only by the embedded reader (W4-02b),
  and never for a RAW (`RawSource_Skips...`).
- R0003: never hold the lifecycle, in-flight or `SharedLoad` lock across file I/O, the reader, the decode, `note_accessed`,
  `try_delete` or the spawner call. Lock order when nested: lifecycle -> LRU's internal lock only.
- Perf: no event for the RAW early return; `"none"` when the reader returned `Ok(None)`; no event when the reader failed.
- `wait_timeout` must not consume the outcome: several handles (and several observations of one handle) all see it.

   `decoder_traits`), and W4-11e adds a small adapter implementing it, mapping `CacheImageError` -> `DecodeError`:
   `InvalidData(t)` -> `InvalidData { message: t }`, `Com { hresult }` -> `Com { hresult, message }`, `InsufficientMemory` ->
   `OutOfMemory { "Not enough memory to decode the cache entry." }`, `Pixels(OutOfMemory)` -> `OutOfMemory`, other `Pixels(_)` ->
   `InvalidArgument` (C# `ArgumentOutOfRangeException` from `PixelBuffer.Allocate`); `WicCacheImageInfo` -> `CacheImageInfo`.
   Optionally W4-08b's `decode_jpeg` adapter reuses the same trait.
3. **Async shape.** Recommended (this stub): `get` returns a `ThumbnailRequest` handle; caller cancellation = dropping the handle
   (R0003 "queue work and return a handle"). Alternative: `get(path, stat, &CancelToken) -> ThumbnailResult` blocking with a
   `wait_timeout` slice loop to notice the token; rejected: polling and one blocked thread per waiter.
4. **`pixels_sha256` stability** across Windows images (Fant scaler). Recommended: compare it; if two runner images disagree, keep it
   informational and compare dimensions/layout only (record `// DIVERGENCE:`).
5. **File-system seam.** This unit reads through `FileSystem` (stat, `file_exists`, `open_read_shared`); C# uses `File.*` directly.
   W4-09's store may use `std::fs`. Recommended: keep `FileSystem` here (fakes for the corrupt/locked cases) and let W4-09 decide its
   own; the wiring step aligns `DiskCacheStore::new`'s signature (D28).
6. **Default disk directory.** Recommended: none (required `PathBuf`; App passes `AppPaths::thumbnail_cache_dir`, R0002). The C#
   default points into the C# app's data and must not be reproduced.
7. **When RAM caching happens.** C# caches in each caller's continuation as the load completes; here when a waiter observes the
   result. End states are the same for every interleaving of `clear_memory`/`clear_disk`/`dispose` (the generation/disposed check
   runs under the lock in both); the only difference is that a result nobody ever waits for is not cached. Lead confirms.
8. **Start-up sweep spawn failure** (C# `Task.Run` cannot fail): recommended log + mark done (above); alternative run inline.
