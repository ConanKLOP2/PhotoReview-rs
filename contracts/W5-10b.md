- Algorithm (the order below is the C# order; keep it, because the header-budget cost of a file depends on it):
  1. `can_read`: `eq_ignore_case(extension, ".cr3")` first; then `first_64_bytes.len() >= 12`; then bytes `4..12 == b"ftypcrx "`. (Pure; no allocation.)
  2. `read`: `source.length() < 16` => `Err(RawHeaderError::invalid_data("File too short for CR3 container."))` BEFORE the cancellation check (a canceled token with a
     15-byte file is `InvalidData`, golden `read-cancelled-but-too-short-fails-first`). State: `orientation = 1`, `sensor 0x0`, empty collector, empty exif list.
  3. Top-level scan: `offset = 0; while offset <= length - 8 { ct.check()?; match bmff::try_read_box(source, offset, None)? { None => break, Some(b) => {..} }; offset += b.total_size }`.
     The cancellation check runs once per top-level iteration and nowhere else. `total_size >= 8` and `<= length - offset` hold by the navigator's contract, so the loop makes
     progress and `offset` cannot overflow; do not "defend" with extra reads. Per box, FIRST match wins, in this order:
     a. `b.uuid == Some(PREVIEW_UUID)` => `parse_preview_uuid_box`. (`uuid` is `Some` only for a parsed `uuid` box.)
     b. `b.box_type` equals `"PRVW"` ASCII-case-insensitively (the type is the navigator's 4-char ASCII string, `?` for bytes above 0x7F: use `eq_ignore_ascii_case`) => `add_prvw_box`.
     c. `b.box_type == "moov"` (exact) => `parse_moov_box`.
     d. anything else (including a `uuid` box with another uuid, `ftyp`, `mdat`, `free`): ignored.
  4. Result: `RawContainerInfo { format: Cr3, sensor_width, sensor_height, orientation, previews: collector.into_ordered(), exif_blocks }`.
  5. The helpers follow the doc comments in the stub; the points that are easy to get wrong are in the traps below.
- Semantics notes (all comparisons are the C# ones):
  1. **Three preview lists, one order.** PRVW previews (from `preview-uuid/PRVW` and top-level `PRVW`, in file order), then track JPEGs (in `trak` order), then THMB previews (in
     file order), whatever order the boxes appear in; `index` is the position in the final list. All previews are `Jpeg`, `Unknown` colour space, `header_resolved == false`.
  2. **Headered JPEG** (`PRVW` inside the preview uuid and top-level headered `PRVW`: size @12, width @6, height @8; `THMB`: size @8, width @4, height @6; all big-endian, widths/heights
     are the raw 16-bit values, `0` allowed): needs `payload_size >= 18`; `jpeg_offset = payload_offset + 16`; `available = payload_size - 16`;
     `jpeg_length = if 0 < declared <= available { declared } else { available }` (so declared 0 and declared above the box both mean "the whole rest of the box", declared 1 stays 1 and is
     then rejected by `jpeg_length < 2`, declared 2 is a 2-byte preview); the SOI (`FF D8`) must be at `jpeg_offset`.
  3. **Top-level `PRVW`** (any ASCII case, e.g. the `prvw` of `SyntheticRawBuilder.BuildIsoBmff`): payload under 2 bytes => nothing; SOI at the payload start => the WHOLE payload (trailing bytes
     included) is one preview with width = height = 0; otherwise the headered rule with the PRVW layout.
  4. **Preview uuid.** Children are read with an 8-byte skip; only when that yields no child at all is the box read again with no skip. A `PRVW` child inside is matched case-SENSITIVELY
     (`prvw` lowercase is not accepted there, unlike at the top level) and a direct-JPEG payload is NOT accepted there (headered rule only). A uuid without the 8-byte prefix is therefore
     usually mis-parsed, not recovered (golden `prvw-uuid-with-no-prefix-but-zero-first-word-is-misparsed` vs `prvw-uuid-with-no-8-byte-prefix-falls-back`): port the quirk, do not "fix" it.
  5. **CMT1.** See the stub doc of `parse_cmt1` / `read_cmt1_value`. Inline values (`type_size * count <= 4`) are read from the entry as it is; out-of-line values are relative to the CMT1
     payload and must lie fully inside it; orientation is accepted only in `1..=8`, sensor sizes only in `1..=i32::MAX`; a later valid entry overrides an earlier one; tags other than
     `0x0112`, `0x0100`, `0x0101` cost no read. The exif block `(payload_offset, payload_size, is_tiff_header = true, ifd_is_exif = false)` is added for EVERY `CMT1`, even when the TIFF is
     unusable or the payload is empty. `CMT2` adds `(.., true, true)` and nothing else. Blocks are in file order.
  6. **Track.** `trak -> mdia -> minf -> stbl` by the FIRST child of each type (a second `mdia`/`stsz`/`stco`/`co64` is never looked at; a missing level silently ends the track).
     `stsz`: payload >= 12 else size 0; uniform size > 0 wins; else count >= 1 and payload >= 16 gives the first table entry. `stco` wins over `co64` whenever it exists with payload >= 8
     (even when it holds no usable offset); `co64` is used only when there is no `stco` or its payload is under 8 bytes. The range test is `chunk_offset > 0 && sample_size > 0 &&
     chunk_offset < length && sample_size <= length - chunk_offset`, then the lossy-frame probe decides (SOF3 lossless raw track, arithmetic frames, 12-bit, zero size, no SOI: no preview).
  7. **Caps.** Every `read_child_boxes` is capped at 256 children per parent (W5-10a), top-level boxes are NOT capped: a CR3 whose `moov` is the 300th top-level box is read, 300 tiny
     boxes cost one 64 KiB block; a `uuid`/`moov`/`trak`/`mdia`/`minf`/`stbl` with more than 256 children before the wanted one does not see it (goldens `cap-*`).
  8. **Budget.** The only limit on the top-level scan is the header budget of the source: 1 000 000 `free` boxes (8 MB) fit, 1 200 000 do not and the reader returns the source's
     `InvalidData` (not an I/O failure) -- goldens `read-flood-*`. No reader-side counter exists; do not add one.
  9. **Errors.** Malformed boxes never fail: they end a child walk or skip a preview. `Err` comes only from the source (propagate with `?`, unchanged: the I/O failure marker must survive,
     I-13), from the 16-byte minimum, and from cancellation. A `RawHeaderError::ArgumentOutOfRange` cannot come from this reader (every offset/count it passes is non-negative).
- Traps checklist (docs/MULTI-AGENT-PLAN.md §7):
  - 3 (numbers): C# `long`/`int`/`uint` mixes. File sizes, offsets and lengths are `i64`; `declared` is `u32` compared as `0 < declared && i64::from(declared) <= available`; the stsz/stco/co64
    words are `u32`/`u64` (`co64` raw above `i64::MAX` => 0); `value_or_offset` is `u32` and `absolute > u32::MAX` => `None`; `payload_size - type_size` may be negative; never write
    `offset + length` of untrusted values before the overflow-free comparison (`length - offset`). `sensor_*`/`orientation` are `i32` (the C# `(int)` casts follow range checks).
    The `(int)Math.Max(0, (payload - ifd0 - 2) / 12)` cast wraps for a payload above 25 GiB: reproduce it with `as i32` (negative => take 0); it is unreachable for real files and costs nothing.
  - 1 (OrdinalIgnoreCase): only the extension (`pr_core::text::eq_ignore_case`) and the top-level `PRVW` type (ASCII, `eq_ignore_ascii_case`); every other type/uuid comparison is exact.
  - 8 (null vs empty): C# `FirstOrDefault` + `TotalSize == 0` is `Option` (`first_child_of_type`); `BmffBox.uuid` `None` vs `Some` matters (a `uuid` box never has `None`).
  - 9 (exceptions): the one `catch (InvalidDataException) when (!IsIoFailure)` of this file (`TryProbeTrackJpeg`) is already inside `jpeg_probe::try_read_lossy_frame`; do not add a second one that
    would swallow an I/O failure. Nothing else is caught.
  - 10 (order): the three `Vec`s and `exif_blocks` are insertion ordered; no `HashMap`/`HashSet` anywhere.
  - Borrow rule (the trait): the slice returned by `source.read` is invalidated by the next read; the C# reads `header` and uses it before the next read, but a compiler-visible port must copy the
    fields out first (`let hdr: [u8; 16] = slice.try_into()...`). Short slices from a non-conforming source must be `Err(invalid_data(..))`, never an index panic (the C# fuzz source and
    `ShortReadSource` of the navigator tests return short data); no `unwrap`, no `[]` on source data, no `as usize` of an unchecked i64.
  - Read parity (bytes_charged is a golden field): exactly the C# reads, in the C# order: 12 bytes `stsz` header, 4 bytes first sample size, 8 bytes `stco`/`co64` header then the 4/8 byte offset,
    16 bytes preview header, 2 bytes SOI (`has_soi`), CMT1 header read of `min(payload, 4096)` bytes. `has_soi` performs NO read when its offset is outside the source.
  - INV ids: none of INV-1..INV-11 applies (no cache, gate, generation or file handle in this unit). INV-8 is honoured one layer up (W5-12 opens the file with the shared mode); this unit
    only guarantees bounded header reads (see Read parity).
  - Hot path: `read` runs once per RAW preview request and per folder scan of RAW files; no allocation except the navigator's `Vec<BmffBox>`, the result lists and small copies; no logging, no
    `format!` on the success path. 1.2 million loop iterations (the flood case) must finish well under a second in a release build and a few seconds in debug.
  - Native libraries: none. No `unsafe`. No test is `#[ignore = "native"]`; corpus tests return early (skip) when the corpus is missing, unless `PHOTOREVIEW_RAW_CORPUS_STRICT` is `1`/`true`
    (trimmed, case-insensitive), in which case they panic with a message naming the missing file (a line port of C# `RawCorpus`; if `pr-test-support` or W5-01 already has it, use it).

## Golden package
- `oracle/W5-10b.cs`: command `raw-cr3-reader` (`Commands.RawCr3Reader`; dispatch line and wiring notes are in the file header; needs `W5-10a`'s wiring of `PhotoReview.Imaging.Raw`).
- `golden-inputs/raw-cr3-reader.json` (generated by `gen-inputs.js`, committed; the node script is a convenience and contains a small self-check of the box language): 321 cases
  `{name, op?, ext?, cancel?, optional?, source}`.
  - `op`: `"read"` (default) or `"can-read"`; `ext` default `".cr3"`; `cancel` = the token is already canceled when `read` starts; `source` is
    `{"kind":"nodes","nodes":[...],"truncate_to"?:n}` or `{"kind":"corpus","file","sha256"}` (with `"optional": true` on the case: a missing file records `{"skipped": true}`, a hash mismatch fails).
  - **Box language** (`nodes` is an array; a node is an array = concatenation, or an object with one of these keys; integers are JSON numbers, `u64` is a decimal string):
    `hex` | `zeros` n | `ascii` (Latin-1 text, may hold `\u0000`) | `u16` | `u32` | `u64` (all big-endian) | `mark` name (zero bytes, records the absolute offset) | `off32` / `off64` name (+`plus`, may be
    negative: big-endian absolute offset of a mark; marks are resolved by a first pass, box sizes never depend on an offset value) | `u32_len_of` node (+`plus`: big-endian u32 of the emitted length) |
    `jpeg` [w,h] (`SyntheticRawBuilder.CreateMinimalJpeg`, 163 bytes) | `sof3` [w,h] (`LosslessJpeg`, 271 bytes) | `tiff` {`le`, `size`, `ifd0`, `magic`?, `signature_hex`?, `ops`: `ifd`
    {`at`, `next`, `entries`, `pad`?, `count`?} / `u16` / `u32` / `hex`} (entries: `short`, `long`, `at` {`type`,`count`,`v` or `v_mark`+`plus`}; a SHORT with count 1 is left-justified as `TiffBytes.Ifd`
    does) | `box` type (+`children`, `size32` = override of the written size field, `large` = 16-byte header with `size64` decimal override) | `uuid` which (`canon`, `preview`, `foreign`, `hex:<32 hex digits>`; +`children`,
    `size32`) | `repeat` n + `node` | `slice` (an array of nodes) + `from`/`to` (byte slice of the emitted bytes). `truncate_to` cuts the final file.
  - The Rust test file implements the same language in ~130 lines over `serde_json::Value` (a line port of `W510bEmit`) and compares `file_length` and `file_fnv1a64` (FNV-1a 64, written in the
