- Semantics notes (all comparisons are the C# ones; port in the C# order so the first failing check is the same):
  1. **Constructors.** C# `ArgumentException.ThrowIfNullOrWhiteSpace(path)` first (empty or whitespace-only => `InvalidInput`, reader NOT called; `Path` cannot be null; "whitespace" is
     `char.IsWhiteSpace`, i.e. `str::trim().is_empty()` on `path.to_string_lossy()`), then `open_source(path, priority, BLOCK_SIZE)`, then the length. Any `io::Error` of `open_source` or of the length
     read escapes as is (never wrapped in `RawHeaderError`). The length is `seek(SeekFrom::End(0))`; `u64 -> i64` with `i64::try_from(..)` (`InvalidData` if it does not fit). If it fails, the
     stream has already been moved into the constructor and is dropped on the error return: that is the C# `LengthOrDispose` (test: the Drop flag). The stream position after the length read is irrelevant:
     every block read seeks first.
  2. **`read` checks, in order** (the golden `argument-and-range-messages`, `over-max-header-bytes-checked-before-the-range-or-allocation` pin the order and the texts):
     (a) `offset < 0 || count < 0` => `ArgumentOutOfRange { param: "offset", message: "Offset and count must be non-negative." }`; (b) `offset > length - count` (overflow-free; `length - count`
     cannot overflow, both are non-negative and `count <= i32::MAX`) => `InvalidData("Attempted to read past end of stream (offset: {offset}, count: {count}, length: {length}).")`;
     (c) `count > MAX_HEADER_BYTES` => `InvalidData("RAW header read of {count} bytes exceeds hard limit of {MAX_HEADER_BYTES} bytes.")` BEFORE any allocation; (d) `count == 0` => `&[]` (no stream access, so it
     succeeds even after `dispose`); (e) the block loop.
  3. **Block arithmetic.** `start_block = offset / BLOCK_SIZE`, `end_block = (offset + count - 1) / BLOCK_SIZE` (safe: `offset + count <= length`); single block => slice of the cached block at
     `offset % BLOCK_SIZE`. Several blocks => `multi_block_buffer` is grown to `count` when shorter (`resize`, never shrunk) and each block is copied in order with
     `bytes_from_block = min(remaining, block.len() - in_block_offset)`; return `&multi_block_buffer[..count]`. Borrow-checker shape: call `ensure_block(b)?` (needs `&mut self`) and only then
     take the slice from `self.block_cache[&b]` (no `entry()` API trick that holds the borrow across the stream read).
  4. **Budget.** `ensure_block`: `bytes_to_read = min(BLOCK_SIZE, length - block_start)`; `bytes_to_read > MAX_HEADER_BYTES - total_bytes_read` => `InvalidData("RAW header read exceeded hard limit of {MAX_HEADER_BYTES} bytes.")`
     BEFORE reading the stream. `total_bytes_read` is increased and the block inserted only after a complete read. A multi-block read that fails midway therefore keeps (cached and charged) every block
     it finished (golden `multi-block-exhausts-budget-keeps-earlier-blocks`), and a block that fails is neither charged nor cached, so a retry reads it again (golden `short-stream-single-block`,
     `io-fault-on-second-block-of-multi-block-read`).
  5. **Errors from the stream.** Seek and read errors both: `RawHeaderError::invalid_data_io(format!("Unable to read RAW header block at {block_start}: {err}"), err)`; the text uses the `io::Error`
     `Display` (the golden uses a custom-message error, `disk`, so it compares equal to .NET's `ex.Message`; OS errors differ in wording and are never compared). A stream that returns 0 bytes
     before `bytes_to_read` (or fewer bytes in total) => `invalid_data("Unexpected EOF while reading block at {block_start}.")` with NO inner error, so `is_io_failure()` is false for a truncated file and
     true for a disk failure (`RawDecoder` keys its behaviour on that).
  5b. **Narrower C# catch (deviation).** C# wraps only `IOException`/`ObjectDisposedException` (`catch ... when`); any other exception (`NotSupportedException`, `UnauthorizedAccessException`) escapes unwrapped. Rust
     wraps every `io::Error` of seek/read (there is no other error type), including kinds such as `Unsupported`/`PermissionDenied`, so `is_io_failure()` is true for them. Document this in the stub's `ensure_block` doc and in a test.
  6. **Read loop and `Interrupted`.** Loop `read(&mut block[total..])` until `total == bytes_to_read` or a 0-byte read (C# `if (read == 0) break;`). Rust adds one deviation: `ErrorKind::Interrupted` is
     retried (`std` itself does this in `read_exact`); .NET has no such error. Do not use `read_exact` (its EOF error would lose the message above).
  7. **Dispose.** `dispose()` takes the stream out (`Option::take`, dropping it closes it) and clears `block_cache`; `multi_block_buffer`, `length` and `total_bytes_read` are left alone. With the stream gone, `ensure_block`
     returns the same `invalid_data_io(.., io::Error::new(ErrorKind::Other/BrokenPipe, "stream is closed"))` path as a failing read, so the post-dispose `read` is `InvalidData` with an inner error (C# gets
     `ObjectDisposedException` from `Position`'s setter, wrapped by the same `catch`). Golden `dispose-drops-the-cache` fixes: the post-dispose message is NOT compared (.NET text).
  8. **No `Sync`/thread safety is added**: like C# the source is single-threaded (`&mut self`); it is created per decode in `RawDecoder` and dropped at the end. `Send` is automatic (`ReadSeek: Send`).
  9. **No allocation proportional to input claims**: blocks are `vec![0; bytes_to_read]` with `bytes_to_read <= 65 536`; the multi-block buffer is bounded by `count <= MAX_HEADER_BYTES` (checked first). Never
     `Vec::with_capacity(length)`.
- Traps checklist: §7 items 3 (i64 offsets: only the forms above; `offset + count` may be computed only after check (b); `block_index * BLOCK_SIZE` as `i64` is safe because `block_index <= offset / 65536`),
  8 (`count == 0` at `offset == length` is `Ok`, but `(length + 1, 0)` is the past-end error), 9 (three distinct `InvalidData` kinds: over-limit read, budget exhausted, short block; each its own message),
  10 (cache is a `HashMap` but never iterated). INV-8: the source reads only the 64 KiB blocks the callers touch, never the payload beyond them, and never more than 8 MiB in total.
  Parsers must never panic on malformed input: the 5 000-pair fuzz test above runs with `i32::MIN`/`i32::MAX`/`i64::MAX` arguments.

  constructor outcome (`ArgumentException` / `IOException` with message / ok), whether the stream was disposed, the `OpenSource` arguments, and per step the bytes (`len`, `first`, `last`, `sum`), the
  exception type, `ParamName`, inner type, message and `TotalBytesRead`; also the number of `Read` calls on the stream. **Not run by this step**: the wiring step runs it and writes
  `tests/golden/raw-header-source-io.json`.

  (single-block, multi-block crossing, an empty last block, declared 10 bytes but holds 0), I/O faults (first read, second block of a multi-block read, after a cached block, in the middle of a block after partial chunks,
  disposed-type inner), `Dispose` (cache dropped, double dispose, argument checks before stream access), argument/range messages with `i64::MAX`/`i32::MAX`, the over-limit check before the range check on a 20 MiB
  source, the budget-exhausted message, shared-buffer reuse across multi-block reads, and the constructors (length fault for both overloads, priority and 65 536-byte buffer passed to the reader, empty and
  whitespace paths, a path with surrounding spaces passed unchanged).
- Case design: every `throw` of the C# class has a case that reaches it and a neighbour that just passes (past-end by one, count `MAX_HEADER_BYTES` +- 1, a short block of 1 byte, fault on call 70 of a 66-calls-per-block stream).

## Open questions
0. **Two `RawHeaderError` drafts.** W5-01a (`formats.rs`: struct with `cause: Option<RawHeaderCause>`, free `is_io_failure`) and W5-01b (`contracts.rs`: enum `InvalidData{message,io}`/`ArgumentOutOfRange`/`Canceled`, `invalid_data`, `invalid_data_io`, method `is_io_failure`) both define the type. This unit is written against W5-01b's (it needs `ArgumentOutOfRange` and `invalid_data_io`); the lead must keep only one definition. The stub was compile-checked (clippy `-D warnings`, toolchain 1.99.0) against a minimal copy of W5-01b's three items.
1. **Error type of the constructors.** The stub returns `io::Result<Self>` (C# lets the `IOException`s escape; `RawDecoder` reports them as I/O failures and maps `ArgumentException` to a bug). Alternative: return
   `RawHeaderError` with an `io` inner for the open/length failures too, so `RawDecoder` has one error type to inspect. Recommended: keep `io::Result`; W5-12b converts with one line.
2. **`SourceReadPriority` default.** C# has `priority = Viewer`; Rust has no default arguments. The stub makes the parameter explicit instead of adding an `open_viewer` overload. W5-12b passes the request's priority anyway.
3. **`from_stream` taking `Box<dyn ReadSeek>`.** Tests and corpus runners pass `Cursor<Vec<u8>>` / `File` (boxed). A generic `from_stream<R: ReadSeek + 'static>(r: R)` would save the `Box::new` at call sites but
   cannot be used with the `Box<dyn ReadSeek>` that `SourceReader::open_source` returns; one constructor taking the box keeps a single path. Lead decides; the logic is identical.
4. **Where `RAW_HEADER_BLOCK_SIZE` lives.** W5-01b defines it so `InMemoryRawHeaderSource` has no dependency on this file; `SourceRawHeaderSource::BLOCK_SIZE` is an alias (C# name kept for the ported tests).
