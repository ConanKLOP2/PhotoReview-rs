- Semantics notes (each from the C# read at the baseline):
  1. **List.** `shown` keeps journal order; an unchecked row (no verdict) matches `All` only. `summary_text` distinguishes an empty list (`recovery.summary.empty`) from a count
     (`recovery.summary.count`, plural). `filter_empty_visible(n)` is `rows > 0 && n == 0`, so an EMPTY list is not "nothing matches".
  2. **Buttons.** Tuple order Retry, Clear selected, Clear all. All false while retrying. Retry needs a retry delegate AND a single selected row whose check `allows_retry`; Clear selected needs a
     dismiss delegate and `selected_count > 0`; Clear all needs a dismiss delegate and at least one row. Test rows: `(true,true,true)`, `(false,true,true)` for a non-retry verdict, `(false,false,true)`
     for no selection, `(false,true,true)` for two selected (no single row).
  3. **Details.** See the stub doc. A group hides both path panels and the "no destination" text; a checked entry without destination shows the "no destination" text; the
     folder-missing note appears only on the DESTINATION view and only when the result says so; `error_visible` follows `errors::describe(error_code, error, ..)`.
  4. **Live check.** Read-only. Order of view calls: `row_changed` for every reset, `set_recheck_enabled(false)`, `set_check_status(progress 0/n)`, then per result `row_changed` and
     `set_check_status(progress k/n)`, then `set_recheck_enabled(true)`, `set_check_status(done)`, `check_completed()`. Empty list: only `set_check_status("")`.
  5. **Cancellation (INV-9 style).** Each run has its own token. A new run or `cancel_check()` cancels the old one. A message of a cancelled run changes NOTHING (no row, no status, no button):
     this covers (a) a failure that arrives after the cancel and must not re-enable the newer run's button or clear its status, and (b) results already posted before the cancel but delivered
     after it. A run cancelled between rows posts nothing more.
  6. **Dismiss.** No delegate or no rows: no call, `{None, 0}`. A failing delegate removes nothing and returns its message. Success removes ALL requested rows (dismissed and stale) by ordinal Id and
     reports `skipped.len()`.
  7. **Retry.** `begin_retry` without a delegate refuses before anything changes. Busy is `true` before the work and `false` on EVERY path of `finish_retry`, including an `Err`.
     A superseded result (P02) removes the matching rows (ordinal Id) and calls `rows_changed` once; any other result leaves the rows.
  8. **`describe_retry`**, **`retry_confirm_text`** (setting read at call time, `None` = false): see the stub doc; the permanent-delete warning of a CANCELLED group Undo is suppressed (10f logic).
- Traps checklist:
  - **T1 Index stability.** The C# rows are objects; Rust rows are indices, which change when a row is cleared or dropped. Results are keyed by Id; selection helpers (`shown`, `dismiss`) take
    indices only for the current snapshot and must be re-derived after any `rows_changed` / `check_completed`.
  - **T2 Token per message.** Check the token of the MESSAGE, not the presenter's current one: a message of run 1 delivered during run 2 is dropped even though run 2 is live (test
    `late_result_of_an_earlier_run_is_dropped_during_a_new_run`, new).
  - **T3 `finally` semantics of busy.** `finish_retry` releases busy before looking at the outcome. Missing this leaves the window unclosable after a failed retry.
  - **T4 Dismiss failure is not evidence of dismissal.** Keep every row on `Err`. On `Ok`, remove the stale ones too (a row whose Id was resolved elsewhere must not look current).
  - **T5 Ordinal Id compare.** `String ==` on the Id (32 hex digits), never a case-insensitive compare.
  - **T6 Read-only check.** The checker is the only collaborator of `RecoveryCheckRun`; it must not receive the retry or dismiss delegates. A test compares the folder listing before and after
    (as the C# does) and uses a recording `RecoveryChecker`.
  - **T7 Panics are failures.** A checker or retry delegate that panics becomes `Failed` / `Err` (`catch_unwind`), never an unwinding UI thread.
  - **T8 No sleeps.** Use the inline `post` (deliver at once) and a collecting `post` (deliver later) as the two C# `SynchronizationContext` fakes; no thread, no timing.
  - **T9 Thread affinity.** `RecoveryWindowPresenter`, the view and `DismissFn` are UI-thread only; `RecoveryCheckRun`, `RecoveryRetryJob`, `RetryFn`, `RecoveryChecker` are `Send`.
  - **T10 Recycle Bin.** No test performs a real retry or delete: `RetryFn` is a fake; `RecoveryFileCheck` over a real temp directory only stats files (AGENTS.md).
  - **T11 Plural summary.** `recovery.summary.count` has `.one` / `.other` forms: use `Localizer::format_plural`, not a manual `if n == 1`.
