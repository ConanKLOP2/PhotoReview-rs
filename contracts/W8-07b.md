## Semantics notes
1. **Late order** (`apply_late_order`, C# lines 273 to 311): see the stub doc for the exact sequence. Checks in order: token canceled or folder generation stale -> nothing; interaction generation stale -> INV-7 ignore;
   `try_validate` failure -> fallback; `replace_order` false -> ignored; true -> `on_order_applied(count, current_index, current_kept = !may_replace)` with
   `may_replace = initial_path.is_none() && current_navigation == presentation_generation && catalog.count() > 0`, and then `set_current(0)` + `present(0, clock.current_navigation())`.
   A valid order for a FILE open keeps the opened file (`current_kept == true`, no re-present: test `..PresentsRequestedFileBeforeSnapshot_ThenAppliesOrderKeepingIt` asserts one present).
2. **Pending-order gate** (INV-9): opened by 07a only for a file open whose snapshot was not complete at catalog time; `pending_order()` is true until `finish_load`, a superseding `load`, or `dispose`
   (`LoadAsync_SupersedingLoad_ReleasesPendingOrderGate`). Released exactly once per opening; every release sets `order_gate_released` on the update that did it.
3. **`finish_load` = the C# `finally`, once per load, on every exit** (applied, ignored, timed out, failed, canceled, superseded): release the gate if this load owns it; if `probe` is `Running`
   and this load is still the active one (`load_id` equals the active id, C# `ReferenceEquals(_loadCts, thisLoadCts)`) publish it (`published: true`; a `Ready` result is applied now); otherwise drop it
   (a failed dropped probe is logged: C# `FireAndLog`). The active slot is cleared (`phase = Idle`) only when this load is still the active one.
4. **Errors** (`report_load_error`): cancellation while the token is canceled -> silent; error while the token is live AND `is_folder_current` -> `sink.on_failed(folder, error)`; any other error ->
   `log.warn("Superseded folder load failed in '<folder>': <type>: <message>")` and nothing else (RV-A05). A failed Explorer query (`snapshot == None`) is the C# exception from `await explorerTask`
   and takes this path.
5. **Probe job** (`run_probe`): up to `PROBE_PARALLELISM` (8) worker threads over the listing order; the token is checked before each file; `try_probe_readable(path)` `Err(reason)` AND `file_exists(path)`
   -> unreadable with that `reason` (`""` when empty), kind `FileUnreadable`; a file deleted since the listing is NOT unreadable (test `Probe_FileDeletedAfterListing_IsNotReportedOrRemoved`). The result is in
   listing order, not completion order. `Err(Canceled)` when the token fired.
6. **Probe application** (`apply_probe`, UI thread): gated by the LOAD token only, never by the folder generation (`Probe_StopForActionWhileProbing_StillRemovesAndReportsOnce`: a file action bumps the folder
   generation while the folder is unchanged); no unreadable file -> nothing; `catalog.remove_paths(&unreadable_paths)`: empty result -> nothing (`Probe_StopForActionAndFileAlreadyRemoved_ReportsNothing`);
   `probe_skipped` = unreadable entries whose path is in the removed set (case-insensitive); `log.warn("Readability probe skipped N unreadable file(s) in '<folder>': <first 20 'path (reason)' joined by '; '>")`;
   `sink.on_files_skipped(folder, listing_skipped ++ probe_skipped)`; perf "probeApplied"; `current_removed` computed from the current path BEFORE `remove_paths`;
   `sink.on_unreadable_removed(&removed, current_removed)`. A capture with one unreadable image member degrades to its survivor at the same position (done by `remove_paths`, W2-10); both members -> both reported.
7. **Dispose**: idempotent (the second call returns `Ignored`, no effect), sets `disposed`, releases the gate, cancels the active token. Later events of the active load are dropped (`Probe_DisposedBeforeResult_IsDropped`,
   `Probe_DoneButNotYetApplied_ThenDisposed_IsDropped`, `Dispose_WhileExplorerOrderPending_ReleasesGate_AndAppliesNothing`).

## Traps checklist (concrete)
- Probe publication order: a probe that finished BEFORE the load's `finish_load` is applied at `finish_load` (after the Explorer order, INV-7/INV-9: `Probe_DoneBeforePendingExplorerOrder_IsAppliedAfterTheOrder`); a probe
  that finishes after is applied when its event arrives. Never apply while the load is still `AwaitingOrder`.
- RV-A06: a superseded load unwinding late must not overwrite the newer load's probe state. All state lives in `ActiveLoad`, keyed by `load_id`; `finish_load(old_id)` for a replaced load touches nothing of the new one.
- `current_removed` must come from the path BEFORE the catalog changes; use `catalog.current().map(|e| e.path().to_owned())`.
- `remove_paths` takes `&[String]`, the skipped entries hold `PathBuf`: convert with `to_string_lossy` for the comparison and keep the original `PathBuf` in the report.
- Case-insensitive path comparison through `pr_core::text::{eq_ignore_case, ignore_case_key}`, never `to_lowercase`.
- No `block_on`, no thread spawning in the coordinator itself: the probe job spawns its (at most 8) scoped threads INSIDE the job on the probe lane; the UI thread never joins them.
- Gate must be released even if an event arrives for a load that was just disposed (idempotent `finish_load`).
- `log.warn` strings are machine-read diagnostics: invariant culture for the count (`to_string()`, no thousands separators).

## Open questions (each has a recommended default that the stub follows)
- **O1 Probe parallelism inside the job.** Default: `std::thread::scope` with `min(PROBE_PARALLELISM, paths.len())` threads sharing an `AtomicUsize` index; results written to a pre-sized `Vec<Option<String>>`
  guarded by a `Mutex` (no async, no rayon: rayon is the decode pool, R0003). Alternative: rayon `par_iter().with_max_len(..)`; rejected because probing is file I/O, which R0003 keeps off the decode pool.
- **O2 `ProbeFinished` when the load is `Idle`.** If the probe was published and the load finished, the event is applied at once; if the coordinator was disposed it is dropped. A stale `load_id` is dropped and a
  failed one is logged. Default as stated; no alternative.
- **O3 `pending_order` as a bool.** The C# `Task` lets many callers await it. Default: a bool plus `order_gate_released` on the update; the view model keeps its own list of deferred navigations
  (W8-08x). Alternative: a `Condvar` gate, rejected (nothing blocks on the UI thread, R0003).
- **O4 Probe results are not forwarded to the Skipped list window.** The sink gets the combined list through `on_files_skipped` (unchanged C# behaviour); the window is W8-19x.
