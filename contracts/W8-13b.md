## Semantics
### SwapChainFrameClock (C# 17-99)
1. **What it is.** The waitable object of the swap chain signals when the swap chain accepted a frame; with a `Frame` handler that presents on every tick that is "once per frame about to be presented". The clock never closes the handle (the swap chain owns it); `dispose_core` is the default no-op.
2. `SwapChainPolicy::new`: `wait_handle == 0` -> `InvalidArgument { param: "frame_latency_wait_handle", message: "A swap chain frame latency waitable handle is required." }`; `fixed_period <= 0` -> `ArgumentOutOfRange { param: "fixed_period" }` (the handle is checked first, as in C#); `period = fixed_period` or `qpc_frequency() / 60`.
3. `deadline_timestamp(armed)`: `!armed` -> `i64::MAX`; `deferred` -> `last_tick + period`; else `max(last_tick, armed_at) + 2 * period`. Additions saturate (T2).
4. `should_tick(now, signaled)` (port as is): `frame = now`. If `signaled`: when `last_tick != 0 && now - last_tick < period / 2` set `deferred = true` and return `None` (a burst signal within half a period of the last tick waits for the end of the period; the loop then calls `on_deadline`, which sees `deferred`).
   Else (deadline call): `now < deadline_timestamp(true)` -> `None`. Then: no fixed period and `timing.refresh_period > 0` -> `period = refresh_period`, `frame = next_grid_point(timing, now)`. `deferred = false`, `last_tick = now`, `Some(frame)`. NOTE `last_tick = now` (the wall time), not `frame`.
5. `on_armed_changed(true)`: `armed_at = now`, `deferred = false`. `(false)`: nothing (the C# does not reset anything on disarm).
6. Integer division `period / 2` truncates (odd periods): keep it.

### `contracts.rs`
7. `WindowMessage` is `Copy`; `wparam: Wparam = usize`, `lparam: Lparam = isize` (the 11a aliases). `try_handle(&self, ..) -> Option<Lresult>` replaces `bool TryHandle(in message, out nint result)`: `Some(r)` = handled with result `r`; the first handler that returns `Some` ends the chain (13f).
   `&self` and `Rc<dyn WindowMessageHandler>` (D-W8B3H-6): a handler can be re-entered when it triggers a nested `SendMessage`.
8. `ShellWindowApi` is the object-safe twin of `IShellWindow` (name D-W8B3H-3). Events: `subscribe(ShellWindowEvent, WindowEventHandler)` and `subscribe_closing(ClosingHandler)` return a `u64` id; `unsubscribe(id)` removes either kind; handlers run in subscription order with no borrow held (13e `EventList`).
   `set_title` is the only fallible member (`SetWindowText failed`); `close` is infallible in Rust: a panic of a `Closing` handler resumes through `pending_panic::rethrow_pending` (13c) instead of being a returned error.
9. `SizeD`/`PointD`: `Default`, `Copy`, record equality with `double.Equals` semantics (NaN equal, `0.0 == -0.0`). They are field-for-field the types of `pr_app::input::primitives` and will be replaced by imports (D-W8B3H-1).
10. `new_rect`/`rect_width`/`rect_height`: field setters / `wrapping_sub` (unchecked C# `int`, T1).

### `icons.rs` (C# `ShellIcons`)
11. `load(cx, cy)`: `cx <= 0 || cy <= 0` -> `0` with NO OS call (test); else `load_from(exe module, ..)`. `load_from(instance, ..)` = `native::load_shared_icon(instance, RESOURCE_ID, cx, cy)` (`LoadImageW`, `IMAGE_ICON`, `LR_SHARED`: the system owns and shares the handle, never destroy it).
    The C# fallback to the test assembly module is dropped (D-W8B3H-16).
12. `metric(index, dpi)`: `dpi == 0` -> `get_system_metrics(index)`, else `get_system_metrics_for_dpi(index, dpi)`. `load_big(dpi) = load(metric(SM_CXICON), metric(SM_CYICON))`; `load_small` with the `SM_*SMICON` pair. `dpi == 0` is how the window CLASS asks (no window, system dpi).
13. `apply(hwnd, dpi)` = `apply_with(hwnd, dpi, &load)`; `apply_with`: `hwnd == 0` -> `false`; `big = loader(metric(SM_CXICON, dpi), metric(SM_CYICON, dpi))`, `small = loader(SM_CXSMICON, SM_CYSMICON)`; `big != 0` -> `SendMessage(hwnd, WM_SETICON, ICON_BIG, big)`; `small != 0` -> `ICON_SMALL`; result `big != 0 || small != 0`.
    Send BIG first, then SMALL (C# order). `SendMessage` is `dialog_native::user32::send_message` (`pub unsafe fn`): the call is `unsafe` with `// SAFETY: WM_SETICON takes an HICON in lParam, a handle the OS validates; no memory is dereferenced`.
14. Never panics, never errors: a missing resource sets nothing.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1: `rect_width`/`rect_height` and every QPC sum wrap or saturate like C# unchecked `long`/`int` but never panic in debug.
- T2: `deadline_timestamp` saturates (`fixed_period` may be `Period * 1_000_000` in a test); `last_tick + 2 * period` with `last_tick` near `i64::MAX / 2` must not overflow.
- T3: `deferred` is the whole mechanism of the deferred tick: set on an early signal, read by `deadline_timestamp`, cleared by `should_tick` AND by arming. A mutant that forgets to clear it at arming keeps a stale `last_tick + period` deadline.
- T4: the early-signal test uses `<` (strict) `period / 2`: a signal exactly at half a period ticks.
- T5: `ShellCursor` and the `ShellWindowEvent` order are public: asserted by value tests; `ShellCursor` as `i32` is 0, 1, 2.
- T6: `apply` sends ICON_BIG before ICON_SMALL and skips a zero handle individually (a loader that finds only the small icon still returns `true`).
- T7: `load` with a non-positive size must not reach `LoadImage` (which would load the default-size icon for `0, 0`): the test passes `(0, 16)` and `(16, -1)`.
- T8: `native::get_capture` etc. return `0` for none; never compare against a stored `HWND` that may be stale after destroy (13e rule).

## Safety
`native.rs`: four wrappers over calls with no pointer inputs except `LoadImageW`'s resource id (an integer atom, `MAKEINTRESOURCEW`) and `ValidateRect`'s null rect: each `unsafe` block states that. `icons.rs`: the `send_message` call above. No other `unsafe`.
