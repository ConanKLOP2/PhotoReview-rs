## Semantics

1. Rust has no `native/` directory or pin at HEAD. Import pin values and licence/source files from the C# baseline only through a reviewed sync (not by inventing values); the C# TurboJPEG script pins the DLL but not its NuGet package, so add and verify a package pin before extraction. All downloads use HTTPS with HTTPS-only redirects, hash the package **before** extraction, reject traversal/absolute archive entries, extract to an owned temporary directory and hash the DLL before staging. Mismatch fails closed; no fallback to an unpinned system DLL.
2. `crates/pr-libraw/src/native.rs` lines 286 and 397-400 builds an absolute `current_exe()` sibling path and uses `LoadLibraryExW`; `crates/pr-turbojpeg/src/native.rs` lines 527-531 does the same. Stage `PhotoReviewRs.exe`, `libraw.dll`, and `turbojpeg.dll` side by side. Do not depend on PATH or working directory.
3. Stage `LibRaw-LICENSE.LGPL`, `LibRaw-LICENSE.CDDL`, `LibRaw-NOTICE.txt`, `LibRaw-SOURCE.zip` next to the exe, following the C# `native/README.md` and `verify-release.ps1`; add a libjpeg-turbo licence/notice file, the application's own licence and a new, synced reviewed copy of `d92d6aae:THIRD-PARTY-NOTICES.md` (line 1 title; review entries against Rust's actual bundle). The corresponding-source offer in release notes names the exact LibRaw archive and pinned hash, with a durable release asset or URL. Keep LibRaw dynamically linked and replaceable as a separate DLL; do not statically incorporate it into the exe. The proposed zip also ships `Languages/en.json` and `Languages/vi.json` from `assets/languages/`; D-W10release-7 can revise this after runtime validation.
4. `tools/verify-release-native.ps1` checks every required staged file and the two DLL/source archive hashes. It checks the exe's byte length against a plausible min/max **measured from the first Rust release build** (unset bounds fail verification; do not copy C# AOT numbers), requires at least one `RT_GROUP_ICON`, and rejects `PhotoReview.exe`, `PhotoReview.App.exe`, `PhotoReview.App.dll`, `PhotoReview.dll`, `PhotoReview.runtimeconfig.json`, `PhotoReview.deps.json`, `PhotoReview.Shell.WpfBridge.dll`, `PhotoReview.App.WpfWindows.dll`, `PhotoReview.Imaging.Wpf.dll`, `PresentationFramework.dll`, `WindowsBase.dll`, `coreclr.dll` and `hostfxr.dll` (`d92d6aae:tools/verify-release.ps1` lines 64-68 for the managed/WPF set). It checks the chosen catalog layout, including both files under `Languages/` if D-W10release-7 selects the folder. `docs/drafts/release.yml` also checks the zip's entry names after packing.

## Traps and open questions

- LibRaw's dual-license choice and what the bundled archive contains as corresponding source need legal/maintainer verification. The C# `native/README.md` calls it a source archive; do not assert that merely linking to a binary package satisfies LGPL source obligations without inspecting it.
- TurboJPEG NuGet package hash and package-internal licence path were **not verified**. Add the package pin and notice mapping before enabling R1. `docs/drafts/release.yml` deliberately calls the future script and cannot publish until these inputs exist.
- `crates/pr-l10n/src/localizer.rs` line 362 embeds English. `crates/pr-l10n/src/loader.rs` lines 1-3 and 212-234 reads shipped/user catalogs and resolves requested/UI culture, while `crates/pr-shell/src/composition/registry.rs` lines 180-184 specifies `<exe>/Languages` but its localization body is still `todo!()`. Packaging of Vietnamese is therefore an open release gate (D-W10release-7), not proved by the English embed.
