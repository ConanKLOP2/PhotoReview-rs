- Semantics notes (C# `RunPreparedAsync`, in this exact order):
  1. **Mapping.** `Task` -> blocking call (R0003; the executor spawns whatever threads it needs, `run_prepared` itself is single-threaded and calls the
     executor and the measure step on the calling thread). `IProgress<T>.Report` -> `BenchmarkProgressSink::report`, synchronous (C# `Progress<T>` posts
     to a sync context; the W8 presenter marshals to the UI thread itself). `Environment.MachineName` -> `COMPUTERNAME`. `DateTimeOffset.UtcNow` ->
     `options.clock.utc_now()`. `FileLog.Default` -> the caller passes the log (no default in `run_prepared`; `RunPreparedOptions::new` takes it).
  2. **Preconditions, before any log line and before `started` is read:**
     (a) `folder.chars().all(char::is_whitespace)` (`string.IsNullOrWhiteSpace`; same set as .NET for the Latin-1 range and the Unicode space separators) -> `Err(FolderRequired)`;
     (b) `!Directory.Exists(folder)` (a file, a missing path or any stat error) -> `Err(DirectoryNotFound(folder as given))`; use
     `std::fs::metadata(folder).map(|m| m.is_dir()).unwrap_or(false)`;
     (c) `validate_profile(profile)` -> `Err(Profile(e))`. The order matters (goldens `empty-folder-is-checked-before-the-profile`,
     `missing-folder-is-checked-before-the-profile`). The executor is never called when any of these fail.
  3. **Start.** `started = options.clock.utc_now()`; `run_id = options.run_id` or `pr_core::io::physical::new_guid_n()` (32 lowercase hex). Log (Info), one line:
     `Benchmark start runId={run_id} profile={profile.id} workload={profile.workload} folder={full} iterations={profile.iterations} workers={profile.workers}`
     where `full = pr_core::text::dotnet_path::get_full_path(folder)` (the same value later stored in the report; on `PathError` map to
     `DirectoryNotFound(folder)`, which cannot happen after step 2b except for >MAX_PATH, document as DIVERGENCE if hit) and `{workload}` is the enum
     name (`FirstFrame`, `FileAction`, ...; W7-01 `Display`). Integers print plain (`{}`).
  4. **Warm-ups** (`for w in 0..profile.warmup_count`; a negative count runs none, golden `negative-warmup-is-allowed-and-runs-none`):
     `options.cancel.check()` FIRST, OUTSIDE the error handling: a token canceled at the top of the loop returns `Err(Canceled)` and logs NOTHING
     (goldens `token-canceled-in-warmup-...`, `token-canceled-in-last-warmup-...`). Then `measure = operation(profile, profile.workload, w, cancel)?`
     and `outcome = measure()?`; `warmup_baseline = outcome.metrics.or(warmup_baseline)` (a warm-up with no metrics keeps the previous baseline). The
     warm-up's `correct` is ignored. Not timed, no progress, no sample, no per-warm-up log line. Failure of the prepare OR the measure step:
     `Err(Canceled)` -> Info `Benchmark canceled runId={id} profile={profile.id} warmup={w}` and return the error; any other error -> Error
     `Benchmark warmup failed runId={id} profile={profile.id} warmup={w}` with the error object attached (`log.error(msg, Some(&err))`), return it.
  5. **Timed iterations** (`for i in 0..profile.iterations`, `total = iterations`): `cancel.check()` first, outside the handling (no log, as above).
     Then: `measure = operation(..., i, ..)?` (UNTIMED prepare); `t0 = time.timestamp()`; `outcome = measure()?`; `elapsed_ms =
     elapsed_milliseconds(time.timestamp_frequency(), t0, time.timestamp())`. The end timestamp is read immediately after the measure step returns
     and before anything else (no log call between). Failures as in 4 with the texts `Benchmark canceled runId={id} profile={profile.id}
     iteration={i}` (Info) and `Benchmark phase failed runId={id} profile={profile.id} iteration={i}` (Error + error). Note `i` is 0-based in these
     two lines. After success: `samples.push(elapsed_ms)`; `metrics = outcome.metrics.or(metrics)` (last NON-null wins); `all_correct &= outcome.correct`;
     Info `Benchmark sample runId={id} profile={profile.id} phase={profile.workload} iteration={i+1}/{total} elapsedMs={format_ms(elapsed_ms)}
     correct={outcome.correct}` (`correct=True`/`False`: C# `bool.ToString()` is capitalised; in Rust print `True`/`False`, not `true`/`false`);
     then progress `BenchmarkProgress { profile_id, workload, completed: i+1, total, message: PROGRESS_OK or PROGRESS_CORRECTNESS_FAILED }`.
  6. **Finish.** `if let (Some(m), Some(b)) = (&metrics, &warmup_baseline) { metrics = Some(crate::metrics::since(m, b)) }` (baseline absent, e.g. warm-up
     0 or no warm-up reported metrics: the cumulative snapshot stays; metrics absent: stays `None` even with a baseline). `correct = !samples.is_empty()
     && all_correct`. Phase: status `InsufficientData` when no samples (unreachable after validation, port it), else `Pass` when `correct`, else `Fail`;
     message `None` when `correct`, else `RESULT_CORRECTNESS_FAILED` (so the empty-samples case also carries the message); `images_per_sample: None`
     (the runner stamps it). Info `Benchmark complete runId={id} profile={profile.id} phase={profile.workload} status={phase.status}
     p50Ms={format_ms(p50)} p95Ms={format_ms(p95)} maxMs={format_ms(max)}` (`status` is the enum name: `Pass`, `Fail`). Report:
     `BenchmarkReport { run_id, started_utc: started, folder: full, phases: vec![phase], metrics, machine }`.
  7. **Samples are `f64` milliseconds** from `TimeSpan.TotalMilliseconds`: ticks of 100 ns / 10 000.0, clamped (see `elapsed_milliseconds`, `ticks_to_milliseconds`). Arrival order is kept in
     `samples` (the percentile getters sort a copy: W7-01).
  8. **`format_ms`.** `value.ToString("F1", InvariantCulture)`. Verified with .NET 10.0.401 (probe, not the oracle): `0.25 -> 0.2`, `0.75 -> 0.8`,
     `1.25 -> 1.2`, `1.75 -> 1.8`, `2.25 -> 2.2`, `0.05 -> 0.1` (the double is slightly above 0.05), `0.4999 -> 0.5`: ties go to even on the exact binary value,
     which is what Rust `format!("{value:.1}")` does. Never use the shortest-round-trip digits and re-round. Decimal point is always `.`.
  9. **`TimeSource` / `elapsed_milliseconds`.** C# `GetElapsedTime(a, b)` = `new TimeSpan((long)((b - a) * (10_000_000.0 / frequency)))`. Rust:
     `((end - start) as f64 * (10_000_000.0 / frequency as f64)) as i64` (the `as` cast truncates toward zero like the C# cast; saturates on overflow, which
     the C# cast does not specify: not reachable) then `ticks_to_milliseconds(ticks)` = `TimeSpan.TotalMilliseconds`: `ticks as f64 / 10_000.0` CLAMPED to `[-922337203685477.0, 922337203685477.0]`
    (.NET clamps to `long.MaxValue / 10_000`; probe on .NET 10.0.401: `TimeSpan.FromTicks(long.MaxValue).TotalMilliseconds` = `922337203685477`, unclamped
    would be `...477.58`; golden `ticks-long-max-clamped`). A negative delta gives a negative value (golden `elapsed-negative-delta`); a tiny negative value
    formats as `-0.0` in both .NET and Rust (probe: `-0.0001 -> "-0.0"`, goldens `ticks-minus-1`, `ticks-minus-2500` -> `-0.2`).
     `SystemTimeSource` returns nanoseconds from a process-wide `OnceLock<Instant>` with frequency `1_000_000_000` (precision of a real clock; tests use a
     manual one).
  10. **`BenchmarkError`.** `Display`: `FolderRequired` -> `Folder is required (Parameter 'folder')`; `DirectoryNotFound(p)` -> `p`; `Profile(e)` -> `e`'s text;
      `Canceled` -> `The operation was canceled.`; `Operation(e)` -> `e`'s text. `source()`: `Profile(e)` -> `Some(e)`, `Operation(e)` -> `Some(&**e)`, others `None`.
      The log call for a non-cancel failure passes the `BenchmarkError` itself as the error object (so `RecordingLog` would show `"{message}: {error}"`).
  11. **Machine.** `options.machine` or `std::env::var("COMPUTERNAME").ok()`. The report field is `Option<String>` (C# `string?`).
  12. **No hidden state.** `run_prepared` keeps no global; two runs may interleave on different threads (the executor and sink are `&mut`/`&` borrowed).

## Golden package
- `oracle/W7-03a.cs`: commands `bench-engine-run` (scripted executor + hand-driven `TimeProvider` + capturing `ILog` + capturing `IProgress`; reports samples, status,
  message, the metrics subset, normalised log, progress events, call order, exception type/message/profile problem) and `bench-engine-format-ms` (the `Ms` format of
  `TimeSpan.FromTicks(n).TotalMilliseconds` and `GetElapsedTime` for `{frequency,start,end}`). Dispatch lines are in the file header. Needs `W2-00.cs`.
  Wiring needs a `PhotoReview.Benchmarking` reference in `OracleCs.csproj` and `tools/oracle.ps1` copying `PhotoReview.Benchmarking.dll` (lead). NOT run here.
- `golden-inputs/{bench-engine-run,bench-engine-format-ms}.json` (40 and 34 cases), outputs in `golden-reference/` after the first oracle run.
- Case design: sample timing excludes prepare; warm-up counts 0/1/2/3/negative; every `??` combination of warm-up and timed metrics (null last warm-up, all timed
  null, no baseline); failing sample vs warm-up failure ignored; fractional milliseconds (ties `.25`/`.75`) in the log; each throw/cancel position (warm-up prepare, warm-up
  measure, timed prepare, timed measure) with its log line; token canceled after a measure step stopping at the next loop top WITHOUT a log line; token canceled in the LAST
  sample still returning a report; folder/profile validation order; unsorted samples; large and zero elapsed; integer conversion rules of `GetElapsedTime` (truncation,
  negative delta, odd frequencies).
- Determinism (D19): no wall-clock, machine name, run id or temp path reaches the golden (run id and folder are normalised; `started_utc`/`machine` are reported as booleans).

## Open questions
- `BenchmarkProgress` fields use `i32` like the C# `int`; `BenchmarkProgressSink` takes the value by move. If W8's presenter wants a channel instead, a
  `Sender<BenchmarkProgress>` impl of the trait is a one-liner there; no change here.
- Cancellation granularity: C# can cancel an in-flight `await` only if the executor passes the token on; the Rust executor receives `&CancelToken` and decides.
  The engine itself never interrupts a running measure step (same as C#).
- W7-01 is the owner of the names listed under "Depends on". If W7-01 returns `BenchmarkProfile` by value from `find`, the golden harness clones it.
