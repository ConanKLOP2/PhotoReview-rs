## Semantics notes (line numbers refer to `PointerInputController.cs`)
1. **Window press (384).** `_pressStoppedGlide = StopKinetic()` for EVERY press of the window (the tunnel runs before the image's handler). It overwrites the previous value (R10).
2. **Image press (390-421), in order.** `stoppedGlide = _pressStoppedGlide | StopKinetic()` (non-short-circuit: `StopKinetic` always runs), then the flag is cleared. A LEFT press that is a double click (`click_count >= 2`) cancels any pan, requests Fit through the command and returns true
   (DF03: before the pan check, because `CanPan` is false at Fit; its release finds no tracked press). Otherwise `canPan = CanPan()`; when `!canPan && !ClickToZoomEnabled` the press is not taken (false, nothing captured). Else the press is tracked: `_isPanning`, `_pressCanPan = canPan`,
   `_pressConsumed = stoppedGlide`, start / last point, `_pressTimestamp`, the velocity tracker is reset and gets the sample `(0, x, y)`; a pannable press sets the pan cursor and, with `KineticPanEnabled` and a smoothing other than `Off`, reads `DisplayTiming` once (starts the vblank clock); the mouse is captured; true.
   Note that the button argument is only compared for the double click; a non-left press that passes the other checks is tracked too (as in C#, the WPF handler is only wired to the left button).
3. **Move (424-458).** `!_isPanning || !leftButtonPressed` returns false and changes nothing. Else the delta to the LAST point, the last point is updated, the velocity sample is `(timestamp - _pressTimestamp, x, y)` (wrapping `int` subtraction, then to double), the drag threshold is tested only while `!_panMoved`
   (total distance from the START point against `surface.DragThreshold`, per axis, inclusive; it stays crossed once crossed), and only a pannable press scrolls (`CalculatePanOffsets` with the pointer delta, one `ScrollTo`). The return value is `_panMoved`.
4. **Release (461-494).** Not tracked: `CancelPan`, false. Else the final velocity sample, `ClassifyRelease(dragged: _panMoved, panned: _pressCanPan, pressWasConsumed: _pressConsumed, ClickToZoomEnabled, KineticPanEnabled)`, `moved = _panMoved`, `CancelPan()` (capture released, cursor off, flags cleared) BEFORE acting,
   then `ClickZoom` (the click-zoom pass at the release point, handled = true), `StartKinetic` (release velocity), `None`. `if (moved) handled = true`. A tracked click at Fit with click-to-zoom on is handled even though it only started a pass.
5. **Click zoom (497).** Target `ClickZoomFactor(ClickZoomPercent)`; `DecideClickZoom(IsFit, Zoom, target) == Fit` requests Fit (command), else `ZoomAtPoint(mouse, SetZoom(target))`. The Fit branch awaits nothing in the controller.
6. **ClickZoom key (513).** No images: nothing at all (no cancel, no stop). Else cancel / stop; at the click zoom with `ClickZoomKeyTogglesFit` off it does NOTHING more (no zoom, no scroll, no Fit); otherwise `ClickZoom(ResolveKeyboardAnchor())`. It ignores `ClickToZoomEnabled`.
7. **Context menu level (529).** Always the viewport centre; `ClickZoomFactor(percent)` (clamped 10 to 800 %, integer clamp first); never toggles Fit.
8. **Kinetic start (557).** `_kinetic.Start(pointerVx, pointerVy)` false: no glide, nothing hooked. True: `_glideClock.Start(KineticGlideSmoothing, TicksPerMs)`; hook once (`_kineticHooked`). **Impulse (572):** `AddImpulse`; the glide clock is (re)started only when the glide was not already active;
   the hook is registered only when not hooked (no re-hook on auto-repeat). The impulse sign is the SCROLL-offset direction (`KeyboardPan.ImpulseVelocity(target - current)`), not the pointer direction.
9. **Arrow pan (596-627).** Keys other than the four arrows, an unloaded surface and no images give false. The step comes from the CURRENT (possibly mid-glide) offsets, so an auto-repeat during a glide computes its edge decision from the already-scrolled position; a `Panned` result with `KineticPanEnabled` adds an impulse and
   does NOT scroll; without it the glide is stopped and one instant `ScrollTo(h, v)` is done. `NotScrollable` / `AtEdge` return `KeyboardPan.ConsumesKey(..)` (default: consumed while zoomed, so only Fit falls through; with `ArrowKeyNavigatesAtZoomEdge`: a fresh press at the edge falls through, a repeat is swallowed).
10. **Kinetic frame (642-664).** Inactive or unloaded: stop (unhook) and return. No rendering time: return (nothing else). `elapsed = GlideFrameClock.Advance(renderingTimeMs, surface.Timestamp, needsDisplayTiming ? surface.DisplayTiming : null)`; `<= 0` returns; else `Step`, one `ScrollTo`, and stop when the glide ended. `Off` never reads `DisplayTiming`.
11. **Window closed (667).** `StopKinetic`, then `CancelPan`.

## Traps checklist
- **T1 Non-short-circuit or.** `_pressStoppedGlide | StopKinetic()`: write `let stopped = self.press_stopped_glide | self.stop_kinetic(..)` (the bit operator on `bool`), NOT `||`. With `||` a set flag skips the stop and a running glide survives the press (test `PressDuringAGlide_StopsIt_..` would still pass; add the new test `press_stops_the_glide_even_when_the_flag_is_already_set`).
- **T2 Stopped-glide press is never a click.** `press_consumed = stopped`; cleared by `cancel_pan` at the release. The flag `press_stopped_glide` is cleared by the image press, overwritten by the next window press (R10); do not clear it elsewhere.
- **T3 Release order.** `cancel_pan` runs BEFORE the click-zoom / kinetic action and AFTER the classification (classification reads the flags that `cancel_pan` clears). Reversing it classifies every release as a plain click.
- **T4 Sticky drag threshold.** Once `pan_moved` is true it is not re-tested; the delta for scrolling is vs the LAST point, the threshold vs the START point.
- **T5 Wrapping time.** `timestamp.wrapping_sub(press_timestamp) as f64`; `i32` overflow must not panic. Velocity samples start with time 0 at the press.
- **T6 Hook balance.** One `hook_render_frame` per glide (also across auto-repeat impulses), one `unhook_render_frame` per stop; `kinetic_hook` is the single source of truth. The registered handler is a no-op (see the stub doc); the shell routes frames while `is_kinetic_hooked()`. Never leave a hook behind on `on_window_closed`.
- **T7 Glide clock start.** `glide_clock.start(..)` for a fresh glide only; an impulse mid-glide must keep the existing anchoring (`was_active` is read BEFORE `add_impulse`).
- **T8 Edge decision uses current offsets.** `keyboard_pan_step` receives `surface.horizontal_offset()/vertical_offset()` at the time of the key, not a remembered target.
- **T9 NaN / -0.** Offsets, velocities and thresholds follow the 05f helpers (`.NET` min / max / clamp copies); the controller adds no float rule of its own except the strict `> + 0.5` in `can_pan` (05g) and `elapsed <= 0` (NaN is NOT `<= 0`, so a NaN elapsed steps: pin with the golden of `GlideFrameClock` rather than here).
- **T10 TimeSpan to ms.** `ticks as f64 / 10_000.0` (`TimeSpan.TotalMilliseconds`); a negative or huge tick count follows the same expression with no clamp in the controller.
- **T11 No time-based waits** in tests; all frames are driven by the test.
- **T12 Viewer updates.** `click_zoom` / `set_click_zoom_level` go through `zoom_at_point`, which records the `ViewerUpdate`; nothing in this file calls `ViewerState` directly except reading `is_fit()` / `zoom()`.

## Open questions (each with a recommended default; the stubs follow the default)
- **O1 Frame hook.** See `contracts/W8-05g.md` O1: the controller registers a no-op handler to obtain the `RenderHookId`; the shell routes frames. Recommended B1 change (lead, optional): drop the handler parameter from `ImageSurface::hook_render_frame`.
- **O2 Pointer button on press.** C# compares `changedButton` only for the double-click rule. The Rust signature keeps the parameter (the shell passes `PointerButton::Left`); a right / middle press that the shell forwards would be tracked like a left press, exactly as the C# method would. Recommended: keep (identical behaviour); W8-14 must forward only the left button.
- **O3 `PointerRelease` carries a continuation.** The C# `OnImageRelease` returns a plain bool because the click-zoom task is `FireAndLog`ged. Recommended (used): return `PointerRelease { handled, step }` and make the shell resume `step`.
- **O4 Arrow while `AwaitRender` pending.** A key pressed while a zoom pass waits for its render calls `try_pan_by_arrow` with the pre-pass offsets, as in C# (the pass placed its scroll already). No special handling.
- **O5 `rendering_time_ticks` unit.** `TimeSpan` ticks (100 ns) as in `ImageSurface`'s `RenderFrameHandler` doc. If the Win32 surface reports `QueryPerformanceCounter` ticks instead, it must convert before calling `on_kinetic_frame` (W8-14c).
