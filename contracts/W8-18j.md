## Semantics (C# is the spec)
1. **`initialize_dialog`**: the seven steps of the doc, in that order. Items are read once. A template control that does not exist (`get_dlg_item` = 0) is skipped silently, as the C#. `hook_list_view` is called BEFORE the child joins `children`. `chrome.apply` is called exactly once, with the controls in item order. `content.on_initialized`, `preferred_client_size` and `layout_controls` run with no `RefCell` borrow held (D-W8B4I-1).
2. **Focus**: `initial_focus_id != 0` -> `get_dlg_item(hwnd, id)` (NOT `item(id)`: child hosts do not exist yet); else `first_tab_stop()`. `set_focus` result ignored. `first_tab_stop` reads a SNAPSHOT of `children`; `is_tab_stop(style) = style & 0x0001_0000 != 0` with `style = get_window_long_ptr(child, GWL_STYLE) as u32`.
3. **`center_single_line_edits`**: `item.class == Edit && item.style & ES_MULTILINE == 0` (use `dialog_native::ES_MULTILINE`) and `get_dlg_item(hwnd, item.id) != 0` -> `edit_centering::attach(edit)`; the result is ignored.
4. **`command_route`**: `Ok` iff `id == ID_OK && notification == BN_CLICKED`; `Cancel` iff `id == ID_CANCEL && notification == BN_CLICKED` (`BN_CLICKED = 0`); otherwise `Other`. `handle_command` as the doc: `on_ok` true -> `end_modal(ID_OK)`, `on_cancel` false -> `end_modal(ID_CANCEL)`, both return `true` even when they do not close. `split_command_wparam(w) = ((w & 0xFFFF) as i32, ((w >> 16) & 0xFFFF) as i32)`.
5. **`handle_notify`**: the four steps of the doc. The reads are typed (D-W8B5-311): `&*(lparam as *const NMHDR)` and, for `NM_CUSTOMDRAW` of a button, `&*(lparam as *const NMCUSTOMDRAW)`, each under `// SAFETY: for WM_NOTIFY lParam points to an NMHDR (an NMCUSTOMDRAW for NM_CUSTOMDRAW) valid for the call`. `code as i32` before the comparisons. `set_text_color(hdc, ..)` result ignored. The `DWLP_MSGRESULT` writes use `set_window_long_ptr` (SAFETY: the dialog's own result slot).
6. **`on_scroll_message`**: `lparam != 0` -> `content.on_scroll(self, get_dlg_ctrl_id(lparam), low_word(wparam))`.
7. **List view hook**: `hook_list_view` pushes, then `set_window_subclass(.., list_view_subclass_proc, LIST_VIEW_SUBCLASS_ID, self_ref_data())` (a `false` result is ignored: no header drawing). `list_view_subclass_proc` runs its body under `pending_panic::guarded` returning an `Option<Lresult>` (`Some(r)` = return `r`, `None` = fall through to `def_subclass_proc`); the dialog comes from `NativeDialog::from_cookie(ref_data as isize)`; the `sorts` borrow is released before `draw_header_item`; the `NMCUSTOMDRAW` is the typed reference described above. The procedure removes itself on `WM_NCDESTROY` and still calls `def_subclass_proc` (as the C#).
8. **`set_list_view_sort`** as the doc. **`is_button`/`is_edit`**: `comctl::user32::get_class_name(hwnd)` -> `Some(name)` and `class_name_is(&name, "Button" | "Edit")`; `None` or `hwnd == 0` -> `false`. `class_name_is` compares ASCII case-insensitively and requires equal length (the C# reads at most 16 / 8 units and checks the length).
9. **Tooltips**: as the C# section. `ensure_tooltip` creates the window once; a failed creation returns `0` and the next call retries (the C# did). `TTM_SETTIPBKCOLOR` uses `DialogColors::from_key("Dark.Tooltip").unwrap_or(0)`. `add_tool` builds a `TTTOOLINFOW` (`windows` struct) zeroed, `cbSize = TTTOOLINFOW_V2_SIZE as u32`, `uFlags = TTF_IDISHWND | TTF_SUBCLASS`, `hwnd`, `uId = control as usize`, `lpszText`; `send_message(tooltip, TTM_ADDTOOL, 0, &tool as *const _ as isize)` with SAFETY (the struct is live for the call, the OS copies it); the text pointer of `set_tooltip` is a local NUL-terminated `Vec<u16>` alive for the call (the tooltip copies fixed text).
10. **`provide_tip_text`**: `header` is `*mut NMTTDISPINFOW`; `control = (*header).hdr.idFrom as isize`; the provider is cloned out of `item_tips` BEFORE it runs; `tip_buffer` is resized to `tip_capacity(len + 1)` units (never shrunk), filled with the UTF-16 text and a `0`; `lpszText = tip_buffer.as_ptr()` taken AFTER the last write (SAFETY comment: the buffer is private to the dialog, replaced only here; the tooltip reads the pointer before the next request). `tip_capacity(c) = max(c, 256)`. `last_tip_item` is updated only when a provider exists and the cursor position is known.
11. **`item_tip_subclass_proc`**: the same guard pattern as 7. `WM_MOUSEMOVE` -> `on_item_tip_mouse_move(hwnd, signed_low_word(lparam), signed_high_word(lparam))`; `on_item_tip_mouse_move` compares with the stored last row and pops the tip as the doc says.
12. **No `unwrap`/`expect`/`panic!`**; nothing indexes a slice without a bounds check.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T3 (arithmetic): `wparam & 0xFFFF` on `usize` before narrowing; the mouse coordinates are SIGNED words (negative when the cursor leaves the control to the left or top); `len + 1` and the capacity cannot overflow `usize` for a `String`.
- T8 (null vs empty): a provider returning `None` and `Some("")` both give an empty tip (the C# `text ??= ""` then empty).
- T9 (exception to Result): the two `catch (Exception) { }` of the subclass procedures become `guarded` (D-W8B5-314); a failed `SetWindowSubclass` is not an error.
- T10 (order): `InitializeDialog` order is observable (the hook sees fonts but not layout; `chrome.apply` once); the dictionary order of `_itemTips` is not exposed to callers but `cleanup` (18k) walks it in insertion order, so it is a `Vec`.
- Handles (R0003): `children`, `list_views`, `item_tips` hold plain `isize`s; the subclasses are removed by 18k before the cookie is freed; the tooltip window is an owned popup of the dialog (D-W8B5-319).
- Handles in TESTS (the leak test of 18k shares the process GDI/USER counters): every DC, memory bitmap and brush a native test creates is released/deleted on every path, also when an assertion fails (a small RAII guard in the test file).
- Re-entrancy: `content.on_notify` / `on_command` may call `close()` or `set_item_text` (which sends messages that come back here); no `RefCell` is borrowed across them.

## Safety rules (`// SAFETY:` per `unsafe` block)
Blocks: the typed reads of `lParam` (`NMHDR`, `NMCUSTOMDRAW`, `NMTTDISPINFOW`) with the layout assertions of D-W8B5-311 (`size_of::<NMHDR>() == 24`, `offset_of!(NMCUSTOMDRAW, dwDrawStage) == 24`, `offset_of!(NMCUSTOMDRAW, hdc) == 32`, `offset_of!(NMTTDISPINFOW, lpszText) == 24`); `send_message(TTM_ADDTOOL ...)` (pointer to a live struct), `send_message` with integer-only tooltip messages; `set_window_long_ptr(DWLP_MSGRESULT)`; `set_window_subclass`/`def_subclass_proc`; `from_cookie`; the two `extern "system"` procedures (never unwind; `// SAFETY` on the contract that `ref_data` is the cookie of a live dialog because 18k removes the subclass before freeing it).

## Error mapping
| C# | Rust |
|---|---|
| `catch (Exception)` in the two subclass procedures | `pending_panic::guarded`, still `def_subclass_proc` |
| `CreateWindowEx` returns 0 (tooltip) | `ensure_tooltip` returns `0`; `set_tooltip` / `set_item_tooltips` do nothing |
| `SetWindowSubclass` returns false | ignored |
| `GetCursorPos` / `GetClassName` fail | no row index / `false` |
| null `lParam` (crash) | `0` / ignored (Rust-only guard) |
