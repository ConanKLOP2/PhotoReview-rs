## Decision D15e-1: composition tree (C# `PanelElement` subclasses in Rust)
C# `StatusPanel`, `ToolbarPanel` and `ZoomIndicatorPanel` inherit `PanelElement`, and the shell reads typed children
(`Toolbar.Fit`, `Status.ViewList`, `ZoomIndicator.Text`). A `Vec<Box<dyn ElementNode>>` owned by `PanelElement` (the W8-15d
shape, mirroring `LayerElement`) would lose those typed handles. So in Rust each composite:
- owns its typed children as fields (`ButtonElement`, `TextElement`, and for the status panel a private-to-the-module
  but `pub` type `SkippedRow`), and a `PanelElement` (W8-15d) that carries only the box style (background, corner radius,
  padding, orientation) and the base state;
- implements `ElementNode` itself (W8-15a trait): `base`/`base_mut` delegate to the `PanelElement`; `measure_core`,
  `arrange_children`, `render_core`, `find_at`, `find`, `release_resources` walk the typed children in C# `Add` order
  using the W8-15d stack helpers (open question O1);
- so `Box<dyn ElementNode>` can hold a composite inside `LayerElement` (W8-15a) with no change to the trees above.
Child order (must match C# `Add`): status panel = status line, EXIF line, skipped row (row = warning text, view-list
button); toolbar = open folder, settings, fit, tools; zoom indicator = text.

## Semantics

### StatusPanel (`status.rs`)
1. Panel box: `horizontal_alignment = Left`, `vertical_alignment = Bottom`, margin 8, padding `(6, 4)`, corner radius 4,
   background `Dark.Overlay` (the `PanelElement` default). Typed children in order: `status` (`TextElement(STATUS_TEXT_ID)`,
   trimming `CharacterEllipsis`), `exif` (`TextElement(EXIF_TEXT_ID)`, trimming `CharacterEllipsis`, margin `(0, 2, 0, 0)`,
   colour `Dark.TextSecondary`), `skipped_row` (`SkippedRow`, see 2).
2. `SkippedRow`: `PanelElement` with orientation `Horizontal`, margin `(0, 4, 0, 0)`, background `ColorF(0, 0, 0, 0)`. Children:
   `warning` (`TextElement(SKIPPED_WARNING_ID)`, style `(Segoe UI, 13)`, colour `Dark.Warning`, vertical alignment `Center`),
   `view_list` (`ButtonElement(SKIPPED_VIEW_LIST_ID)`, padding `(8, 2)`, margin `(8, 0, 0, 0)`, background `Dark.Input`,
   border colour `Dark.BorderToolbar`, corner radius 0, vertical alignment `Center`).
3. `apply(model)` (C# `Apply`): panel `is_visible = model.status_panel_visible`; `status.is_visible = model.file_info_visible`,
   `status.text = status_text`, `status.style = (Segoe UI, font_size)`; `exif.is_visible = exif_visible`, `exif.text =
   exif_text`, `exif.style = (Segoe UI, exif_font_size)`; `skipped_row.is_visible = has_skipped_entries`;
   `warning.text = skipped_warning_text`. Nothing else (T3).
4. `apply_localization(texts)` (C# `ApplyLocalization`): `view_list.content = MAIN_SKIPPED_VIEW_LIST`,
   `view_list.automation_name = MAIN_SKIPPED_VIEW_LIST_AUTOMATION_NAME`. `new(texts)` calls it once.
5. Element tree: the status panel's children are `[status, exif, skipped_row]`; `skipped_row`'s children are `[warning,
   view_list]`. `find(id)` returns self when `id` equals the panel id, else the first match in child order (ordinal). The
   ids used by `find` are the `*_ID` constants.

### ToolbarPanel (`toolbar.rs`)
1. Panel box: `horizontal_alignment = Left`, `vertical_alignment = Top`, margin 8, padding `(6, 4)`, corner radius 4,
   orientation `Horizontal`, background `Dark.Overlay`.
2. Buttons (C# `CreateButton`: `style = (Segoe UI, size)`, background `Dark.Input`, border `Dark.BorderToolbar`, corner radius 0):

   | field | id | content | size | padding | margin | fixed size |
   |---|---|---|---|---|---|---|
   | `open_folder` | `OPEN_FOLDER_ID` | `OPEN_FOLDER_GLYPH` | 16 | `(8, 2)` | zero | none |
   | `settings` | `SETTINGS_ID` | `SETTINGS_GLYPH` | 12 | `(8, 4)` | `(5, 0, 0, 0)` | none |
   | `fit` | `FIT_ID` | `""` then localised (`MAIN_TOOLBAR_FIT`) | 12 | `(8, 4)` | `(5, 0, 0, 0)` | none |
   | `tools` | `TOOLS_ID` | `TOOLS_GLYPH` | 18 | zero | `(5, 0, 0, 0)` | width 34, height 32 |

3. Tooltips and automation names (`apply_localization`, C# `ApplyLocalization`):
   `open_folder`: `MAIN_TOOLBAR_OPEN_FOLDER_TOOL_TIP`, `MAIN_TOOLBAR_OPEN_FOLDER_AUTOMATION_NAME`;
   `settings`: `MAIN_TOOLBAR_SETTINGS_TOOL_TIP`, `MAIN_TOOLBAR_SETTINGS_AUTOMATION_NAME`;
   `fit`: content `MAIN_TOOLBAR_FIT`, `MAIN_TOOLBAR_FIT_TOOL_TIP`, `MAIN_TOOLBAR_FIT_AUTOMATION_NAME`;
   `tools`: `MAIN_TOOLBAR_TOOLS_TOOL_TIP`, `MAIN_TOOLBAR_TOOLS_AUTOMATION_NAME`.
   The glyph contents never change with language.
4. Focus (C# `MoveFocus`, `SetFocus`, `ClearFocus`): `focused_index: Option<usize>`, `None` at start. `move_focus(forward)`:
   `next = match focused_index { None => if forward {0} else {3}, Some(i) => if forward {i+1} else {i-1} }` (with
   signed arithmetic, so `Some(0)` backward gives -1); `set_focus(next if 0..4, else None)`; return
   `focused_index.is_some()`. `set_focus` stores the index and sets `is_focused = (i == index)` on every button.
   `clear_focus` = `set_focus(None)`. `has_keyboard_focus()` = `focused_index.is_some()`; `focused_button()` = the button at
   the index.
5. `buttons()` / `buttons_mut()` return the four fields in Tab order (`[open_folder, settings, fit, tools]`).
6. Element tree: children `[open_folder, settings, fit, tools]` in that order.

### ToolsMenu (`tools_menu.rs`)
1. `build(has_images)` = `menus::builder::build_tools_menu(has_images)` (W8-02a): six items, ids exactly `TOOLS_IDS` in
   order, the two `REMOVE_*` items disabled when `!has_images`, the other four enabled; no shortcut text; automation names
   from the catalog (done by W8-02a).
2. `execute(id, commands, has_images)`: `RECOVERY` -> `show_recovery()`, `DIAGNOSTICS` -> `show_diagnostics()`,
   `BENCHMARK` -> `show_benchmark()`, `CLEAR_CACHE` -> `clear_cache()`, `REMOVE_NUMBERED_DUPLICATES` ->
   `remove_duplicates(true)` if `has_images`, `REMOVE_ORIGINAL_DUPLICATES` -> `remove_duplicates(false)` if `has_images`.
   Returns `true` for the six ids (also for the two duplicate ids with no images, no call), `false` for `None` and any other
   string, and calls nothing in that case.
3. `OverlayCommands` is the seam to the view model; the shell implements it and tests use a recording fake.

### ZoomIndicatorPanel (`zoom_indicator.rs`)
1. Panel box: `horizontal_alignment = Right`, `vertical_alignment = Top`, margin 8, padding `(6, 4)`, corner radius 4,
   background `Dark.Overlay`. Child: `text` (`TextElement(TEXT_ID)`, default style and colour, no trimming).
2. `apply(model)`: panel `is_visible = model.zoom_indicator_visible`; `text.text = model.zoom_indicator_text`;
   `text.style = (Segoe UI, model.font_size)`.
3. `apply_localization(texts)`: `automation_name = MAIN_ZOOM_INDICATOR_AUTOMATION_NAME`. `new(texts)` calls it.

## Traps (check each in the verifier pass)
- **T1 Glyph code points:** `OPEN_FOLDER_GLYPH` is U+1F4C2 (C# `"\U0001F4C2"`), `SETTINGS_GLYPH` is U+2699 with NO
  variation selector (C# bytes `E2 9A 99`), `TOOLS_GLYPH` is U+22EE (`E2 8B AE`). A test asserts the three code points.
- **T2 Tools button box:** fixed 34 x 32 and zero padding, so the toolbar height is `32 + 4 + 4 = 40` (the test
  `box_and_button_spacing_match_the_xaml_exactly`). Do not give the tools button the `(8, 4)` padding of the others.
- **T3 Focus does not wrap:** past index 3 (forward) or before 0 (backward) focus goes to "no button" (`false`), it never
  wraps. From "no button", forward starts at 0 and backward at 3. Signed arithmetic (`i - 1` for `i = 0` is `-1`, not
  `usize` underflow): use `isize` or `checked_sub` (no `unwrap`).
- **T4 Focus mirror:** `focused_index` and every button's `is_focused` change together in `set_focus`; no other code
  writes `is_focused` on the toolbar buttons.
- **T5 Margins:** `open_folder` has zero margin, the other three have left margin 5; this is the spacing the geometry test checks.
- **T6 EXIF spacing:** the EXIF line's top margin is 2 DIP; the EXIF top equals the status bottom plus 2 (the test
  `exif_line_sits_two_dip_below_status_line`). Do not replace the margin with a separate spacer element.
- **T7 Skipped warning:** its font size is fixed at 13 and is never taken from `model.font_size` or `exif_font_size` (C#
  `new TextStyle(Family, 13)` in the constructor only). `apply` does not write its style.
- **T8 Zoom indicator text:** not trimmed (C# sets no `Trimming`); the default `TextElement` colour (`Dark.TextBright`) applies.
- **T9 Ordinal ids:** `execute` matches `Tools.*` with exact string equality. `"tools.recovery"` and `" Tools.Recovery"` are
  unknown (`false`, no call). `None` is `false`.
- **T10 Sync commands:** the C# `Task` returns are gone. A duplicate-removal command with no images does nothing and still
  returns `true` (C# returns a completed Task, trap for a `false` return that would make the host show "unknown tool").
- **T11 `apply` is narrow:** `StatusPanel::apply` and `ZoomIndicatorPanel::apply` write only the properties listed in
  Semantics 3 and 2. A test changes an unrelated field of the model and checks the button or warning style is unchanged.
- **T12 Localization order:** `new(texts)` calls `apply_localization(texts)` after building the tree (C# constructor
  order). The Fit button has empty content before `new` finishes; nothing else reads it in between.
- **T13 Child order:** `find` and layout use the child order in "Semantics" (status: `status, exif, skipped_row`; row:
  `warning, view_list`; toolbar: `open_folder, settings, fit, tools`). A reordering mutant must fail a test.
- **T14 Composition, not sharing:** each typed child is owned once. A composite never stores a copy of a child, so `view_list_mut`
  changes the same button that `find` returns.
