## Semantics

1. `crates/pr-core/src/identity.rs` owns exact names. `crates/pr-core/src/app_paths.rs` uses `%LOCALAPPDATA%\PhotoReviewRs` for config, `Data/operations.jsonl`, `Data/Sessions`, `logs/app.log`, cache, thumbnails and window placement; its overrides are `PHOTOREVIEW_RS_DATA_ROOT` and `PHOTOREVIEW_RS_ISOLATE_CONFIG`. `crates/pr-app/src/startup/options.rs` names `PHOTOREVIEW_RS_INSTANCE_PREFIX`. Never name the exe `PhotoReview.exe`, claim either C# `Local\PhotoReview_*` or `Local\PhotoReviewShell_*` mutex/pipe, or write C# journal, sessions, cache, log or config. The one permitted C# read is first-run `config.json` import, read-only (`docs/adr/R0002-coexistence-with-csharp-app.md`).
2. Zip extraction is installer-less: no registry or association change and no uninstall action by default. Do not write a shared updater. The Rust checker currently has the **wrong product feed**: `crates/pr-core/src/updates/checker.rs::LATEST_RELEASE_URL` and `version.rs::RELEASES_PAGE_URL` point to the C# GitHub project. Before enabling update checks in a release, change both to the Rust project's own verified GitHub API/page and test host/path validation; otherwise disable update checking explicitly. The Rust repository URL is **not verified** here, so no new URL is invented.
3. Release notes must say that pending undo/recovery remains in the app that started it (`docs/adr/R0002-coexistence-with-csharp-app.md`). A process-level test should use temporary roots, a test-owned named mutex, a bounded wait and only kill its own spawned process. A path test must enumerate every `AppPaths` field and prove none enters the C# root, including environment overrides; import must show read operations only.
