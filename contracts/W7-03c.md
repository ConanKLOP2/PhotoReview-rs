## Semantics notes

### DotNetRandom (`new System.Random(int seed)` on .NET 6+; the seeded path is the legacy `CompatPrng`)
```
new(seed):
  subtraction = if seed == i32::MIN { i32::MAX } else { seed.abs() }
  mj = 161803398 - subtraction;  a[55] = mj;  mk = 1;  ii = 0
  for _ in 1..55 { ii += 21; if ii >= 55 { ii -= 55 };  a[ii] = mk;  mk = mj - mk;  if mk < 0 { mk += i32::MAX };  mj = a[ii] }
  for _ in 1..5 { for i in 1..56 { n = i + 30; if n >= 55 { n -= 55 };  a[i] -= a[1 + n];  if a[i] < 0 { a[i] += i32::MAX } } }
  inext = 0; inextp = 21                       // a has 56 slots, a[0] stays 0
internal_sample():
  inext += 1; if inext >= 56 { inext = 1 };  inextp += 1; if inextp >= 56 { inextp = 1 }
  r = a[inext] - a[inextp];  if r == i32::MAX { r -= 1 };  if r < 0 { r += i32::MAX };  a[inext] = r;  r
next()          = internal_sample()
next_max(n)     = (internal_sample() as f64 * (1.0 / i32::MAX as f64) * n as f64) as i32      // n < 0 -> panic BEFORE sampling
                                                                                  // n == 0 -> 0, but it still CONSUMES one sample
// (re-verified in this review: the algorithm above reproduces the C# goldens [93, 922, ...] and [[4,4],[3,2],...] exactly)
```
**Every `+`, `-` above is C# unchecked `int` arithmetic and DOES overflow** (`mj` starts negative for a large seed, so
`mj - mk` and `a[i] - a[1 + n]` wrap; verified against .NET `Random` on seeds 758877054 (= `preview-balanced`), `i32::MAX`,
`-i32::MAX`, `i32::MIN`): use `wrapping_sub` / `wrapping_add` everywhere, the debug build would panic otherwise. The
`if x < 0 { x += i32::MAX }` fixups use the wrapped value. `Sample() * maxValue` multiplies the `f64` sample by the
`i32` converted to `f64`, then truncates (`as i32` truncates toward zero, same as C# `(int)`). Do NOT use `n as f64 / i32::MAX`.
The oracle pins 12 seeds (zero, negative, `i32::MIN`, `i32::MAX`) and 23 profile ids, 24 draws each.

### create_seeded_random / stable_hash
`hash = 17i32`; for every UTF-16 code unit `c` of the id: `hash = hash.wrapping_mul(31).wrapping_add(c as i32)`. The seed may be
negative (then `new` takes the absolute value as above). Case matters (`PREVIEW-BALANCED` seeds differently). The empty id hashes to 17.
A non-BMP character (the oracle has U+1F600) contributes two units, so `str::chars()` is wrong.

### images_per_sample
`workload in {FirstFrame, Preload, WarmNext, FileAction}` -> 1, else `min(max(1, workers), max(1, file_count))`. `Correctness`
and `Sequential` and `Random` are the parallel kinds. `workers` and `file_count` are `i32` and may be `<= 0` or `i32::MAX`. The
golden `bench-images-per-sample` is the cross product 7 workloads x 7 worker values x 10 file counts (490 rows).

### select_index / select_parallel_indices
See the stub docs. All arithmetic is C# unchecked `int`: `iteration + o` and `iteration * 2` WRAP (use `wrapping_add` /
`wrapping_mul`; the golden has `i32::MAX` iterations), `%` truncates toward zero so a negative dividend gives a negative or zero
index (golden `overflow-high-*`, `negative-iteration-*`: do not "fix" them with `rem_euclid`, and do not clamp). `Random` consumes
one `next_max(file_count)` per element, in element order; the other workloads never touch `random`. Precedence: WarmNext is
`(iteration / 2) % n` and `n - 1 - ((iteration / 2) % n)`; Preload is `(iteration * 2) % n`. `select_parallel_indices` with
`file_count == 0` is an empty vector for every workload and does not touch `random`.

### prepare_iteration (decision order is part of the contract)
1. **Refusal first, before the file list is looked at.** `profiles::is_not_implemented(profile)` (W7-01: workload Correctness AND id
   exactly `explorer-reindex` or `cache-recovery`, case-sensitive) -> `Err(BenchmarkError::Profile(e))` with
   `e.problem == NotImplemented`, `e.profile_id == profile.id`, and `e.message ==
   "Benchmark profile '{id}' does not implement a real {name} check yet; a decode-only stand-in would misreport results, so it refuses to run."`
   where `{name}` is `profile.name`. The check reads the PROFILE's workload, not the `workload` argument (golden
   `refusal-checks-profile-workload-not-argument`). The message is English, byte-exact (CLI, logs and the report use it). W7-01
   owns the error type (`BenchmarkProfileError::new(problem, id, message)` in the W7-01a draft); this function builds it with that constructor.
2. Workload `FileAction` -> `prepare_file_action`.
3. `FirstFrame` -> `path = files[select_index(.., FirstFrame, ..)]` = `files[0]`; call `executor.evict_for_cold_decode(path)`
   NOW (untimed); an `Err(PreviewError)` from the eviction (C# would throw) is returned from prepare (cancellation ->
   `BenchmarkError::Canceled`, else `Operation(WorkloadError::Decode)`). Step: `executor.decode(path, ct)` (a `PreviewResult`; an `Err` is
   mapped like in step 5); correct = `pixel_width() > 0 && pixel_height() > 0` (trait `pr_imaging::decode_types::DecodedImageView`, import
   it); metrics = `Some(executor.metrics())`.
4. `Preload` and `WarmNext` -> `center = select_index(..)`. Step: `executor.decode(files[center], ct)`, THEN `executor.warm_preload_around(center)`
   (inside the timed step, fire-and-forget as in C#; not reached when the decode failed), correct as above, metrics = `Some(executor.metrics())`.
5. Anything else (Sequential, Random, Correctness) -> `count = min(max(1, workers), files.len())`, `selected = files[i]` for
   `i in select_parallel_indices(files.len(), ..)` chosen NOW (so `random` is consumed during prepare, never in the step).
   `selected.len() == count`, so the C# `Parallel.ForEachAsync(MaxDegreeOfParallelism = count)` has every item in flight at once.
   Step: start every item with `executor.decode_async(path, ct)` in index order (W7-03b exposes the not-yet-awaited
   `PreviewHandle`; no thread of our own, no rayon: R0003), then `wait()` every handle. A `decode_async` that returns `Err`
   synchronously (cancelled token, missing file: C# threw inside the task) is that item's result and does not stop the loop. The
   result is correct only when EVERY image has both dimensions > 0. The first failing item (index order) is returned: a
   cancellation (`PreviewError::is_canceled()`) -> `Err(BenchmarkError::Canceled)`, anything else -> `Operation(WorkloadError::Decode(e))`.
   A token already canceled when the step starts MUST give `Err(Canceled)` (every `decode_async` refuses it); a token canceled while
   decodes run is nondeterministic in C# too (`ForEachAsync` may finish), do not test it. Metrics = `Some(executor.metrics())`.
   `// DIVERGENCE:` C# reports whichever failure happens first in time (and may aggregate); Rust reports the lowest index.
6. Empty `files` (steps 2 to 5): `Err(BenchmarkError::Operation(Box::new(WorkloadError::InvalidArgument("..."))))` returned from `prepare_iteration` itself. C# throws
   `IndexOutOfRangeException` (FirstFrame), `DivideByZeroException` (Preload, WarmNext, FileAction) from prepare and
   `ArgumentOutOfRangeException` (Sequential, Random, Correctness: `MaxDegreeOfParallelism = 0`) from the step; golden
   `bench-prepare-edge` records both stage and type. `// DIVERGENCE:` Rust fails every empty case at prepare; the engine treats a
   prepare error and a step error the same way (one try block), so no observable difference. No file is created or evicted first.

### prepare_file_action / the measure step
Names: `<std::env::temp_dir()>\PhotoReview-Benchmark-Action-<guid N>.bin`, `+ ".moved"`, `+ ".copy"` where "guid N" is 32 lowercase
hex digits. Untimed setup: read the whole file `files[iteration % files.len()]` (`std::fs::read`; `%` truncates, so a negative `iteration`
gives a negative index: C# throws `IndexOutOfRangeException` from inside the setup try block; Rust must not panic, it returns
`WorkloadError::InvalidArgument` after `cleanup()`; this is a unit test, the oracle does not cover it) and write it to `temp`
(`std::fs::write`); on ANY error call `cleanup()` and return it (`Operation(WorkloadError::Io)`). C# passes `ct` to the file reads: a
token already canceled before the read gives `Err(Canceled)` (check `ct.is_canceled()` right after the empty-list check, before any
file is created). The step is `FnOnce` and owns clones of the `Arc`s, the profile id and the `CancelToken`:
1. Start the decode of `temp` BEFORE mutating: `let started = executor.decode_async(temp_str, &ct);` (`temp_str` from `temp.to_str()`; the
   name is ASCII and the temp dir is the OS one). Awaiting it first would turn the workload into "decode, then act" and hide the
   lifetime race these profiles exist to expose. Do not add synchronization to make the race deterministic. An `Err` returned by
   `decode_async` itself (cancelled token, `Key(SourceNoLongerExists)`) is NOT returned yet: it is the decode OUTCOME, judged in
   step 4 after the mutation (C# `DecodeAsync` is an async method, so such a throw only surfaces at the later `await`).
2. `op = file_action_op(profile.id, iteration)`; run it: Move = `rename(temp, moved)` then `remove_file(moved)`; Delete =
   `recycle_bin.send_to_recycle_bin(temp)` (the injected bin, never a global; signature `send_to_recycle_bin(&self, &Path) ->
   io::Result<()>`); Copy = `std::fs::copy(temp, copied)` (overwrites).
3. If the mutation failed: `wait()` the handle (if any) and ignore ITS result (never leave it running against files `cleanup()` is about
   to delete), then return the mutation's error (`Operation(WorkloadError::Io)`). The scratch files are cleaned up in every outcome (a
   `Drop` guard or a labelled block, not just the success path).
4. `wait()` the handle: outcome = `started.and_then(PreviewHandle::wait)`. `Ok(_)` is fine. A cancellation (`is_canceled()`) ->
   `Err(BenchmarkError::Canceled)`. A failure that `is_tolerated_race_failure(&PreviewError)` is the EXPECTED outcome of losing the race
   and is swallowed: `error.is_io_exception()` (SourceChanged, Io, SourceBytes(Io), Key(SourceNoLongerExists), and `Decode(e)` for
   FileNotFound/DirectoryNotFound/MemoryAdmission/`Io`), or `Decode(e)` with `e.is_not_supported()` (NotSupported, MissingCodec) or
   `e.kind()` being `DecodeError::Format` (`kind()` peels `WithSourceBytes`/`Localized`). Any other failure (`Decode` of `InvalidData`,
   `InvalidOperation`, `OutOfMemory`, `Busy`; `DiskEntry`; `Panicked`; `Spawn`; `Key(InvalidPath(Argument))`) is returned as
   `Operation(WorkloadError::Decode(e))`. (A panic inside the decode is already a `PreviewError::Panicked`, nothing to resume.)
5. Correctness = `temp.exists() == (op == Copy)` (move and delete must remove the source, copy must keep it; `Path::exists`
   returns false on error like `File.Exists`). Metrics = `Some(executor.metrics())`.
`cleanup()` removes `temp`, `moved`, `copied` independently, ignoring every `io::Error` (C# only swallows IOException and
UnauthorizedAccessException; every Rust IO failure is one of those).

### Runner
`run_profile_with` forwards to `crate::engine::run_prepared(folder, profile, &mut |_profile, w, i, ct| prepare(w, i, ct), options)`
(the engine passes the profile; the runner ignores it like the C# `_`) then sets
`phase.images_per_sample = Some(images_per_sample(profile, phase.workload, file_count))` on every phase (the engine produces one
phase). Engine errors pass through untouched (no stamping). `run_profile` is `run_profile_with` with
`prepare = |w, i, ct| prepare_iteration(executor, &files_arc, profile, w, i, random, recycle_bin, ct)` and `file_count = files.len()` as a
saturating `i32`; `files_arc: Arc<[String]> = Arc::from(files)` is built once per run. The closure borrows `random` mutably, which is why
`run_profile_with` takes `&mut PrepareIteration`. `options` (W7-03a `RunPreparedOptions`) already holds progress, time source, clock, log
and the token; progress is invoked synchronously on the run thread (C# `Progress<T>` posts to the captured context; the CLI only prints).
There is no `None` log in the engine: the caller passes the log (C# default `FileLog.Default`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- 3 (arithmetic): wrapping hash, `iteration + o`, `iteration * 2`; `file_count`/`workers` of `i32::MAX`; negative `%`; negative
  `iteration % files.len()` as a slice index.
- 8 (None vs empty): `RunPreparedOptions` has no optional log/clock/time: the caller supplies them (tests use the manual `TimeSource`).
- 9 (exceptions -> Result): each C# `catch` in `PrepareFileActionAsync` is its own branch (setup failure, mutation failure, decode
  race failures, cancellation); do not merge them. A synchronous `decode_async` error is a decode outcome, not a setup failure.
- 10 (order): the order of `random` draws is element order; do not collect indices in a `HashSet`.
- Real I/O: file-action tests touch only `std::env::temp_dir()` scratch names created by the code and a `TempRoot` source image;
  they never touch the user's Recycle Bin (AGENTS.md). The test bin must be `Send + Sync` (`RecycleBin: Send + Sync`): record paths in a `Mutex`.
