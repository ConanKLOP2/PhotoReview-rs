- Semantics notes (from contract writer; each one is a C# behaviour the golden checks):
  1. **Delayed layout.** `set_input` and `scroll_to` change no visible value. `update_layout` applies them. A fresh state is pending
     (`_inputDirty` starts true) with the default input (all zeros, `Auto`, `None`) and offsets 0. `update_layout` returns false and
     calls NO engine function when nothing is pending.
  2. **Engine calls per update.** When pending: `compute` only if the input is dirty (then the dirty flag clears), `clamp_offset`
     always. The golden records `compute_called`, `clamp_called`, `compute` and `clamp` per step; the porter's `ScriptedEngine`
     returns them in order. A call the golden does not expect is a failure.
  3. **Requests.** `scroll_to(h, v)`: each axis that is not NaN is stored as C# `Math.Max(0.0, value)` (see T3); a NaN axis keeps its
     previous request; the scroll is then pending. Offsets are clamped to `[0, max]` only in `update_layout` (via the engine), so a
     request larger than the current extent is remembered and applied once the viewport grows.
  4. **Equal input.** `set_input(x)` when the stored input (`has_input`) is equal to `x` (T1 equality) changes nothing: not dirty.
  5. **`update_layout` return value.** True iff the triple (layout, horizontal offset, vertical offset) differs from the triple before the
     call, compared with T1 equality (NaN equals NaN, `0.0 == -0.0`).
  6. **Image origin.** `image_origin = (layout.image_rect.x - horizontal_offset, layout.image_rect.y - vertical_offset)`;
     `to_image_element(p) = p - image_origin`. `image_actual_width/height` are the `image_rect` width and height of the current layout.
  7. **Arrow pan (C# `ArrowPanRule`).** `StepLength`: `shorter = min(w, h)`, `length = shorter * fraction`, returns `length` if finite and
     > 0, else 0. `Step(dx, dy, h, v, layout, fraction)`: `horizontal_axis = dx != 0`; `max` is the max offset of that axis;
     `max <= 0.5` gives `NotScrollable` with the inputs returned unchanged; `step = StepLength(...) * (dx + dy)` (integer sum, so
     `(1, 1)` is 2 steps and `(1, -1)` is 0); `target = clamp(current + step, 0, max)`; `|target - current| < 0.5` gives `AtEdge` with
     inputs unchanged; else `Panned`, the target on the moved axis, the other axis returned unchanged.
  8. **ViewportInput default and layout default.** `Default` equals C# `default(T)`: zeros, `ScrollBarPolicy.Auto`,
     `ViewerStretchMode.None`, `RectD` zeros.
  9. **Snapshot text.** C# `ToString()` (exact template in the stub doc comment). The number formats are `F2` (zoom), `F0` (sizes and
     max sizes), `F1` (offsets). Stretch prints the enum name; a bar prints `Visible` or `Collapsed`.
  10. **RectD.** `right = x + width`, `bottom = y + height`. `contains`: closed box with the C# formula (T4).

- Traps checklist (MULTI-AGENT-PLAN section 7 items 1, 3, 4, 8, 10 apply; the items below are specific to this unit):
  - **T1 NaN and -0 equality.** C# `record struct` `Equals` uses `EqualityComparer<double>.Default`, i.e. `double.Equals`: NaN equals NaN,
    and `0.0` equals `-0.0`. A derived Rust `PartialEq` says NaN != NaN, so every struct holding `f64` implements `PartialEq` by hand
    with `f64_same`. This matters twice: `set_input` shortcut (a NaN input must not re-dirty the state) and `update_layout`'s change test.
  - **T2 Rust float min/max/clamp vs .NET.** `f64::min`/`max` IGNORE a NaN operand; C# `Math.Min`/`Math.Max` propagate it.
    `shorter = min(w, h)` with `w = NaN` must give NaN, so `step_length` returns 0 (Rust `min` would give `h * fraction`, a
    positive step). Write the minimum by hand: `if a.is_nan() || b.is_nan() { f64::NAN } else if a <= b { a } else { b }` (for equal
    values the choice is irrelevant to the result). `f64::clamp` PANICS when a bound is NaN, and in `step` a NaN max passes the
    `max <= 0.5` test (the comparison is false). Use the .NET `Math.Clamp` order instead:
    `if value < min { min } else if value > max { max } else { value }`. With `max` NaN this returns `value`, as C# does.
  - **T3 `Math.Max(0.0, x)` and the sign of zero.** `scroll_to` stores `+0.0` for `x <= 0` (`-0.0` becomes `+0.0`, because .NET prefers
    `+0` in `Math.Max`). Write `if x > 0.0 { x } else { 0.0 }` after the NaN check. The sign shows in the snapshot text ("-0.0").
  - **T4 `RectD.Contains` formula.** Use `p.x >= x && p.x - width <= x && p.y >= y && p.y - height <= y` exactly. `p.x <= x + width`
    rounds differently. Example: x = 0.1, width = 0.2, p.x = 0.1 + 0.2 = 0.30000000000000004. The `x + width` form says inside; the C#
    form computes `p.x - width` (about 0.10000000000000003), which is above x, so C# says OUTSIDE. The golden case
    `rect_contains: right edge reached through the subtraction formula` records the oracle answer (expected false). A negative
    width contains nothing; a NaN point is never contained (every comparison is false).
  - **T5 `ToString("F<n>")` rounding.** .NET formats the exact binary value and rounds HALF AWAY FROM ZERO on the decimal digits (for
    example 0.125 `F2` gives "0.13"; 2.5 `F0` gives "3"). Rust `format!("{:.N}")` rounds half to EVEN on the exact value ("0.12", "2").
    `format_fixed` must reproduce .NET: take the exact decimal expansion (`format!("{:.1100}", value)` is exact for any finite `f64`),
    round at `decimals` half away from zero, keep the sign of `-0.0` and of values that round to zero (`"-0.00"`, `"-0"`).
    NaN gives `NaN`; infinities give `Infinity` / `-Infinity` (invariant culture symbols, D-W8-01a-5).
  - **T6 Requested offset is clamped at request time only below 0.** The upper clamp happens in the engine on every layout. Do not clamp
    to `max` inside `scroll_to` (the state has no `max` before a layout exists; the golden case `shrink and regrow` fails if you do).
  - **T7 Arrow step with two non-zero deltas.** Use the horizontal axis when `dx != 0`, even if `dy != 0`. `(1, -1)` is a zero step (AtEdge
    unless not scrollable). `(0, 0)` uses the vertical axis with step 0.
  - **T8 Inputs returned unchanged.** On `NotScrollable` and `AtEdge` the function returns the original `horizontal`/`vertical` bit for bit
    (a `-0.0` stays `-0.0`). Only `Panned` replaces an offset.
  - **T9 Module placement of shared types** (D-W8-01a-1, D-W8-01a-2): `PointD`/`RectD` and `ViewerStretchMode` are declared here, so the
    plan edges `05a -> 01a` and `01d -> 01a` hold. Do not add `ViewerStretchMode` to `viewmodels` or `PointD` to any other file.
