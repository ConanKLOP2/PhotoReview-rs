## Semantics (C# is the spec)
1. **`apply_before_show(hwnd, data, is_visible, native, log)`**, in this order, as ONE block inside `catch_unwind(AssertUnwindSafe(..))`: `data == None || hwnd == 0` -> `None`; `state = plan_state_before_show(data.show_command)`; `!is_visible(data)` -> `Some(state)` only when `state == Maximized`, else `None` (the off-screen Maximized window still opens Maximized, `set_hidden` is NOT called); else `native.set_hidden(hwnd, data)` -> `Some(state)` when it returned `true`, else `None`. A panic in the block -> `log.error("Could not restore window placement before show", Some(&io::Error::other(<panic payload text, `"panic"` when it is not a string>)))` (when `log` is `Some`; the Rust `Log::error` takes an `Option<&dyn Error>`, the C# passed the exception) and `None`.
2. **`save(..)`**: `hwnd == 0` -> `false`; `native.try_get(hwnd)` `None` -> `false`; `resolved = current` with `show_command = resolve_show_command(current.show_command, fullscreen_restore_state)`; when `fullscreen_restore_state.is_some()` AND `fullscreen_normal_bounds` is `Some((l, t, r, b))` the four `normal_*` fields are replaced (ONLY then: outside F11 the override is ignored); `store.save(placement_path, &resolved)`: `Ok` -> `true`; `Err(e)` -> `log.error("Could not save window placement", Some(&e))` and `false` (every `io::Error`: the C# catches `IOException` and `UnauthorizedAccessException`). There is no other catch: a panic in the store is a bug and propagates.
3. **`show_command_for(state, activate)`**: `Some(Maximized)` -> `SW_SHOWMAXIMIZED` (3) whatever `activate` is; otherwise `activate` -> `SW_SHOWNORMAL` (1), else `SW_SHOWNOACTIVATE` (4). `Some(Minimized)` is "otherwise" (the planner never returns it).
4. **`NativeWindowPlacement::set_hidden`**: a `WindowPlacement` from `new_window_placement()` with `flags = WINDOWPLACEMENT_FLAGS(data.flags as u32)`, `showCmd = SW_HIDE as u32`, `ptMinPosition = (min_x, min_y)`, `ptMaxPosition = (max_x, max_y)`, `rcNormalPosition = (normal_left, normal_top, normal_right, normal_bottom)`; `user32::set_window_placement(hwnd, &placement).is_ok()`. `try_get`: `let mut p = WindowPlacement::default(); user32::get_window_placement(hwnd, &mut p).ok()?` then `WindowPlacementData { length: p.length as i32, flags: p.flags.0 as i32, show_command: p.showCmd as i32, min_x: p.ptMinPosition.x, ... normal_bottom: p.rcNormalPosition.bottom }`. (The exact `windows` 0.62 field types are `flags: WINDOWPLACEMENT_FLAGS`, `showCmd: u32`; check them in the compiler.)
5. **`ShellPlacementSaver::save(hwnd, file, restore_state, restore_bounds)`** = `save(hwnd, &file.to_string_lossy(), &*self.store, &*self.native, restore_state, Some(&*self.log), restore_bounds)`.
6. **`StartupCloak::new(dispatcher, options)`**: defaults: `set_cloaked` = `try_set_cloaked`, `safety_timeout` = `SAFETY_TIMEOUT`, `schedule_timeout` = `schedule_on_thread`. State = `Mutex<CloakState { handle: 0, cloaked: false, revealed: false, timer: None }>` inside an `Arc<CloakInner>`.
7. **`hide(hwnd)`**: under the lock, `revealed || cloaked || hwnd == 0` -> return; `handle = hwnd`; drop the lock; `ok = set_cloaked(hwnd, true)`; lock, `cloaked = ok`; when `ok`: drop the lock, `timer = schedule_timeout(safety_timeout, Box::new(move || dispatcher.post(Box::new(move || inner.reveal()))))` (the closure holds `Arc<CloakInner>` clones, not `&self`), store the handle. A `false` from DWM leaves `cloaked == false`, so a LATER `hide` tries again (C# parity: only a successful cloak closes the gate).
8. **`reveal()`**: `stop()` first; lock; `revealed` -> return; `revealed = true`; `!cloaked` -> return; read `handle`; drop the lock; `set_cloaked(handle, false)` (result ignored); then `on_revealed()` when set. `note_first_present` = `reveal`. `is_hidden` = `cloaked && !revealed`; `is_revealed` = `revealed`.
9. **`stop()`**: `state.timer.take()` under the lock, dropped AFTER the lock is released (dropping a handle may join or signal a thread). It never changes `cloaked`/`revealed`. `Drop` = `stop`. `StartupCloakPort::{stop, note_first_present}` forward to these.
10. **`schedule_on_thread(delay, job)`**: one thread named `"startup-cloak-deadline"`; it waits `WindowCancel::wait_timeout(delay)`; when NOT canceled it runs `job`; the returned handle holds the `WindowCancel` and its `Drop` cancels it (the thread then exits without running the job). A failed spawn returns a handle that does nothing (no deadline, the first present still reveals).
11. **`try_set_cloaked(hwnd, cloaked)`**: `hwnd == 0` -> `false`; `let value: i32 = if cloaked { 1 } else { 0 }; dwmapi::dwm_set_window_attribute(hwnd, DWMWA_CLOAK, &value).is_ok()` (the wrapper passes `size_of::<i32>()`; `S_OK` is `Ok`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (thread model): the deadline job runs on the timer thread and must only POST; every state change happens on the UI thread. `CloakInner` is `Send + Sync` (all fields are), so the posted closure is `Send`; `on_revealed` and `set_cloaked` are `Send + Sync` closures (a start-up mark and a DWM call).
- T2 (no lock across a seam): `set_cloaked`, `schedule_timeout`, `on_revealed` and the dropped timer handle are never called or dropped under the `Mutex` (a seam may call back into the cloak, e.g. a test's `on_revealed` calling `is_hidden`).
- T3 (handle leaks): the timer thread holds only the job and the cancel flag; dropping the handle must wake and end the thread (no thread parked until the 3 s end after the window closed).
- T4 (reveal after destroy): a late reveal on a destroyed HWND makes `DwmSetWindowAttribute` fail with `E_HANDLE`: `set_cloaked` returns `false` and nothing else happens; `reveal` never panics and never touches the window after `stop` unless a reveal was already posted.
- T5 (ordering with the first show): the cloak must be set BEFORE `ShowWindow` (17e's order); `hide` itself does not show anything.
- T6 (placement): `set_hidden` uses `SW_HIDE` so the window is positioned without being shown; the caller shows it with `show_command_for(state, activate)` right after; `apply_before_show` returns the state even when `data` is not visible on any monitor and the state is Maximized (R2-F-26 / R7-10 rules live in `pr_app::windowing::contracts`).
- T7 (no panic on the UI thread): no `unwrap`/`expect`; `Mutex` poison recovered.
- T8 (units): `WindowPlacementData.flags` and `show_command` are `i32`, the OS fields are `u32`: convert with `as` (bit pattern kept), never `try_into().unwrap()`.

## Safety rules (`// SAFETY:` per `unsafe` block)
No new `unsafe`: the OS calls are the safe wrappers `user32::{get_window_placement, set_window_placement}` and `dwmapi::dwm_set_window_attribute`. The native test reads the cloak state with `DwmGetWindowAttribute(hwnd, DWMWA_CLOAKED, &mut u32, 4)`: a `// SAFETY:` comment (pointer to a live local `u32` of the stated size) in the TEST file only.

## Open questions (recommended default in bold)
1. **`StartupCloakPort` stays an interim port** (D-W8B4X-1): **yes**, `StartupCloak` implements it; `MainWindowDeps.cloak` keeps `Rc<dyn StartupCloakPort>`. A rename-only follow-up (the window takes `Rc<StartupCloak>`) is optional and lead-owned.
2. **`on_revealed` as `Arc<dyn Fn() + Send + Sync>`**: **yes** (it is only the `"windowRevealed"` start-up mark in C#). Alternative: a `!Send` closure kept on the UI side and called by `reveal` only when it runs on the UI thread; rejected because the posted job is `Send` and has to carry it.
3. **The deadline reveal on a window that was destroyed meanwhile**: **harmless** (T4). Alternative: `stop()` clears an `alive` flag checked by the posted job; not needed because the C# had no such flag.
4. **`ShellPlacementSaver` owns `Arc<dyn WindowPlacementStore>`** (the store is `Send + Sync`): **yes**. 17e passes the same `Arc<JsonWindowPlacementStore>` it uses for the read, so `is_visible` and `save` agree on the monitor layout.
