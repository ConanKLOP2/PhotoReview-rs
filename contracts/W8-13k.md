## Semantics (C# is the spec)
### `ShellFullscreen` (C# 90-163)
- `apply(hwnd, fullscreen)`: `hwnd == 0 || fullscreen == active` -> `false`, nothing touched (idempotent: a second enter must NOT overwrite the saved state with the fullscreen state, a repeated exit is a no-op). Enter: `controller.enter(&*ops, hwnd, native.current_state(hwnd))`, THEN `active = true`; if `controller.enter_needs_maximized_state()` (no monitor information: the OS maximises) `native.show(hwnd, Maximized)`. Exit: `controller.exit(&*ops, hwnd)`, THEN `active = false`; if `controller.exit_needs_state_restore()` `native.show(hwnd, controller.state_before())`. Returns `true`.
- `restore_state()` = `controller.state_before()` while active else `None`; `restore_bounds()` = `controller.normal_bounds()` while active else `None` (R7-10: GetWindowPlacement reports the monitor rect while the Normal window covers it; the Normal rect from before F11 is what a close must save).
- `refit(hwnd)`: `!active || hwnd == 0 || controller.enter_needs_maximized_state()` -> `false` (the maximise fallback keeps the window covering the monitor by itself). Else both `native.try_get_monitor_rect` and `try_get_window_rect` must succeed and `window != monitor`; then `native.move_to(hwnd, monitor)` and `true`.
- `reset()`: `active = false`. Minimised at enter counts as `Normal` (`FullscreenController`, 03b; test `F11WhileMinimized_...`: the window is restored first, then covers the monitor).
### Interior mutability and re-entrancy (D-W8B4M-10, the main trap)
`Enter`/`Exit` call `SetWindowPos`, which synchronously raises `WM_SIZE` and, when the window lands on a monitor with another dpi, `WM_DPICHANGED` (handlers: `on_windowing_dpi_changed` -> `refit`, `on_client_size_changed`) BEFORE `apply` returns. C# survives because `_active` is assigned after `Enter`/`Exit` and `Refit` reads it. Rust: all methods take `&self`; `active` is a `Cell<bool>` (assigned after `enter`/`exit`, same order); the controller sits in a `RefCell<FullscreenController>` borrowed ONLY around the `enter`/`exit` call; `refit` checks `active` first and uses `controller.try_borrow()` (a failure means "an enter/exit is in progress": return `false`). Consequences: during `enter` a re-entrant `refit` sees `active == false` and returns `false` (C# identical); during `exit` the C# `Refit` could re-fit the window back onto the monitor mid-exit (state `active` still true), Rust returns `false` there (no C# test pins it; the exit finishes with one SetWindowPos to the saved rect, which is the documented intent: "ONE SetWindowPos"). Test `refit_during_enter_or_exit_is_a_no_op` with a `WindowOps` fake whose `set_window_pos` calls `refit`.
### `apply_fullscreen` and the window glue (C# `ShellMainWindow.Windowing.cs` 34-126)
`register_windowing` (once, from `register_features`): seams = `options.windowing` or default; `apply_title_bar(hwnd, seams.dwm)` (dark caption BEFORE the window is revealed: the startup cloak is still on, test `TitleBar_IsMadeDark...BeforeTheWindowIsRevealed`); `ShellFullscreen::new(FullscreenController::new(seams.monitor_layout or Box::new(Win32MonitorLayout)), seams.ops or Rc::new(Win32WindowOps), seams.native or Rc::new(Win32FullscreenNative))`; `window.add_message_handler(DisplayChangeHandler)`; subscribe `DpiChanged` -> `on_windowing_dpi_changed` (id kept). The viewer's `IsFullscreen` subscription of C# is `apply_changes` step 5 (`on_viewer_fullscreen_changed`).
`on_viewer_fullscreen_changed`: not disposed and window not destroyed -> `apply_fullscreen(viewer.borrow().is_fullscreen())` (the value is copied out; no borrow while applying). `apply_fullscreen(f)`: `fullscreen.apply(hwnd, f)` false -> `false`; true -> `viewport.invalidate_layout()`; `window.invalidate()`; `true`. F11 is ONE `SetWindowPos`, so the client size changes exactly once (test `F11Transition_IsOneResizeStep_NoIntermediateClientSize`): no extra `refit` after `apply`.
`on_windowing_dpi_changed`: not disposed -> `fullscreen.refit(hwnd)`; it runs BEFORE 13h's `on_dpi_changed` (subscribed earlier by `register_features`): while F11 the OS suggested rect is the Normal window rect for the new monitor, so the window is put back on the monitor first, then the decode box reads the final client size.
`on_display_changed` (`WM_DISPLAYCHANGE`): not disposed and F11 active -> `post_to_window(dispatcher, id, UiPriority::Render, job)` where `job`: window alive, not destroyed, `fullscreen.refit(hwnd)` returned `true` -> `viewport.invalidate_layout()`; `window.invalidate()`. Posted (not inline) so it runs AFTER the OS finished moving the window. Not in F11: nothing (test `DisplayChangeWhileNotFullscreen_DoesNotMoveTheWindow`). `DisplayChangeHandler::try_handle` returns `None` for every message (observer only; default processing still runs).
`dispose_windowing` (once via `windowing_disposed`): unsubscribe `DpiChanged`; `fullscreen.reset()`.
### `apply_title_bar` (C# `TitleBar.Apply`)
`hwnd == 0` -> `false`, no call. `dark = dwm.set(hwnd, DWMWA_USE_IMMERSIVE_DARK_MODE (20), 1) || dwm.set(hwnd, 19, 1)` (19 only when 20 failed); then ALWAYS `dwm.set(hwnd, DWMWA_CAPTION_COLOR (35), CAPTION_COLOR_BGR)`, result ignored; returns `dark`. The real seam `Win32DwmWindowAttributes::set` is `dwmapi::dwm_set_window_attribute(hwnd, attribute, &value).is_ok()` (bound at run time, `size_of::<u32>()` = 4; an unsupported attribute is `E_INVALIDARG`, not undefined behaviour). `win32::api::dwmapi` is already a safe wrapper; this unit has no `unsafe` for it.
### Real Win32 (`Win32WindowOps`, `Win32FullscreenNative`, `Win32MonitorLayout`)
All coordinates are physical pixels. `Win32WindowOps` (D-W8B4M-9): `is_iconic` = `win32::startup::is_iconic`; `show_normal`/`show_maximized` = `user32::show_window(hwnd, SW_SHOWNORMAL / SW_MAXIMIZE)`; `normal_position` = `get_window_placement` (the wrapper sets `length`) -> `rcNormalPosition` as `ScreenRect`, `None` on `Err`; `window_rect` = `get_window_rect`; `nearest_monitor` = `monitor_from_window(hwnd, MONITOR_DEFAULTTONEAREST)`, `0` -> `None`, then `get_monitor_info` -> `MonitorSnapshot { handle, monitor: rcMonitor, work: rcWork }`, `Err` -> `None`; `window_style` = `get_window_long_ptr(hwnd, GWL_STYLE)`; `set_window_style` = `unsafe set_window_long_ptr(hwnd, GWL_STYLE, style)` (`// SAFETY:` a style bit set, no pointer); `set_window_pos(hwnd, rect, flags)` = `user32::set_window_pos(hwnd, 0, rect.left, rect.top, rect.width(), rect.height(), flags)` (width and height by the wrapping subtraction of `ScreenRect`; the result is ignored like C#; `flags` are the `SWP_*` of `fullscreen.rs`).
`Win32FullscreenNative`: `current_state` = `is_iconic` -> `Minimized`; `IsZoomed` -> `Maximized`; else `Normal`. `win32::api` has no `IsZoomed` wrapper: the unit calls `windows::Win32::UI::WindowsAndMessaging::IsZoomed` in one `unsafe` block (`// SAFETY:` a handle value the OS validates, no pointers) and the lead may later move it to `win32::api` (rename only). `try_get_monitor_rect`/`try_get_window_rect`/`move_to` (`SWP_NOZORDER | SWP_NOACTIVATE`)/`show` (`Maximized` -> `SW_SHOWMAXIMIZED`, anything else `SW_SHOWNORMAL`) as listed in the trait.
`Win32MonitorLayout`: `monitor_of(hwnd)` = `monitor_from_window(hwnd, 2)`; `try_get_work(m)` = `m != 0` and `get_monitor_info` ok -> `rcWork`; `work_areas()` = `enum_display_monitors(None)` (the OS order) filtered through `try_get_work` (a monitor whose info call fails is skipped), an `Err` of the enumeration -> empty vector. C# returns the list the callback built; a callback that could not read the data pointer returned 0 and stopped: not representable here (the wrapper owns the callback).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7 and window-specific)
- T1 (re-entrancy during `SetWindowPos`): see D-W8B4M-10; no `RefCell` borrow across `ops.set_window_pos`; `enter`/`exit` run inside a borrow of the controller only (the controller takes `&dyn WindowOps` and does the OS call itself: this borrow IS held across the OS call, which is why `refit` uses `try_borrow`).
- T2 (idempotence): the second `apply(true)` returns `false` before touching the controller; a test pins `restore_bounds` after the second call.
- T3 (units): `ScreenRect` is `i32`, width/height wrap like unchecked C# `int`; never `abs`/`clamp` that can panic (`i32::clamp` panics when lo > hi: not used here).
- T4 (order of DPI handlers): windowing's `DpiChanged` handler before the core's; asserted by a recording test.
- T5 (DWM): never panics, never errors for an old Windows; `dark_title_bar::WindowsDarkTitleBar` is NOT used by the shell title bar (it panics on a load error other than `ERROR_MOD_NOT_FOUND`; the shell must stay quiet).
- T6 (handle values): `Hwnd` is `isize` (`0` = none); `Hmonitor` `isize`; no cast to `i32`.
- T7 (post, not inline): `on_display_changed` posts; the job re-checks `disposed`/`is_destroyed` (the window can close between the post and the run).
- T8 (minimised): `current_state` reports `Minimized`; `controller.enter` maps it to `Normal` and restores (`show_normal`) before moving; do not call `show` again.

## Safety rules (`// SAFETY:` per block)
Two blocks: `Win32WindowOps::set_window_style` (`set_window_long_ptr`: the value is a style bit set, never a pointer or an index the callee dereferences) and `Win32FullscreenNative::current_state` (`IsZoomed(HWND)`: a handle value, validated by the OS). Everything else uses the safe wrappers of `win32::api`/`win32::startup`.
