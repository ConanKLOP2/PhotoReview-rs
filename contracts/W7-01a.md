- Semantics notes:
  1. **Statistics.** `P50/P95/P99` = `pr_core::diagnostics::bench_stats::percentile(sorted, 0.50/0.95/0.99)` (linear interpolation, `Ok(0.0)` for an
     empty list; the percentiles are in range so the `Err` is unreachable: map it to `0.0`, no `unwrap`). `Max` = 0 for no samples, else the last
     of the sorted samples. The sorted copy is built at most once per instance (`OnceLock`) and ordered like .NET `Samples.OrderBy(x => x)`:
     `double.CompareTo` (NaN before every number, NaN equal to NaN, `-0.0` equal to `0.0`), STABLE (`sort_by`). Do NOT use `f64::total_cmp`: it
     orders `-0.0` before `0.0` and flips the sign of a zero `Max` (golden `negative-zero-max`, `zero-then-negative-zero-max`: `Max` is the last element
     of the stable order, so `[-0, 0]` gives `0` and `[0, -0]` gives `-0`). `pr_perf::report` has the same comparer as a private `cmp_dotnet`: copy it.
  2. **Copies.** C# `phase with { Samples = x }` must not reuse the original's cache (that was a real bug, see the C# comment). `with_samples` and
     `with_images_per_sample` build through `new` (fresh `OnceLock`); `samples` stays private so nothing can change them behind the cache.
  3. **Images per sample.** `effective_images_per_sample` = `max(1, stamp)` when `images_per_sample` is `Some(stamp)` (the lookup is NOT called, even
     for `Some(0)` or `Some(-7)`, both give 1); else `max(1, lookup(profile_id, workload).unwrap_or(1))`. The lookup receives the PHASE's workload
     (golden `derived-uses-phase-workload-*`: `fast-sequential` is 8 for `Sequential`, 1 for `FirstFrame`/`Preload`/`WarmNext`/`FileAction`).
     `p95_per_image` = `p95() / f64::from(effective)` (plain f64 division; `i32::MAX` stays exact in f64).
  4. **Rank.** Keep a phase when `workload` matches, status is NOT `Fail` and NOT `InsufficientData` (`Pass` and `Warn` stay), and BOTH
     per-image P95 and P50 are finite (a NaN or infinite phase must never win: LINQ sorts NaN first). Order by (per-image P95, per-image P50)
     ascending, STABLE (`sort_by`, ties keep input order; `-0.0` ties with `0.0`). Compute each key once per element, not inside the comparator.
     Finite keys make `partial_cmp(...).unwrap_or(Equal)` safe. Returns references to the input phases (golden `ranked` holds input indexes).
     A `Pass` phase with no samples has P95 0 and ranks first (golden `pass-with-no-samples-ranks-first-at-zero`): do not "fix" that.
  5. **Validation.** `validate_profile`: (a) `id.chars().all(char::is_whitespace)` (also true for `""`) -> `MissingIdOrMode`, `profile_id = id`,
     message `Profile id and loading mode are required`; (b) else any of `workers < 1`, `next_window < 0`, `previous_window < 0`, `iterations < 1`
     -> `InvalidSettings`, `profile_id = id`, message `Invalid benchmark settings for profile '{id}'` (the id verbatim, quotes and padding kept);
     (c) else `Ok`. `.NET char.IsWhiteSpace` and Rust `char::is_whitespace` agree on every code point (U+0085, U+00A0, U+1680, U+2000..U+200A, U+2028,
     U+2029, U+202F, U+205F, U+3000 are whitespace; U+180E and U+200B are not): the golden pins this. `warmup_count` is never checked.
     `target_width`: ordinal match, `preview-light` 960, `preview-balanced` 1600, `preview-quality` 2400, `preview-high-quality` 3200,
     `original-correctness` 0, else 1920.
  6. **Report JSON, shape.** Indented, 2 spaces, `"Name": value`, CRLF line ends (System.Text.Json writes `Environment.NewLine`; README D9), no trailing
     newline, `[]` / `{}` for empty containers. Property names are PascalCase, in this order (record positional properties first, then the computed
     ones in declaration order; `_sorted` is private and never written):
     `BenchmarkReport`: `RunId`, `StartedUtc`, `Folder`, `Phases`, `Metrics`, `Machine`.
     `BenchmarkPhaseResult`: `ProfileId`, `Workload`, `Samples`, `Status`, `Message`, `ImagesPerSample`, `Count`, `P50`, `P95`, `P99`, `Max`,
     `EffectiveImagesPerSample`, `P95PerImage`, `P50PerImage`. `null` is written for a missing `Message`, `ImagesPerSample`, `Metrics`, `Machine`.
     `Workload` and `Status` are written as their NUMBER (no string converter on these enums). `StartedUtc` is `BenchmarkTimestamp::to_json_text`.
     `Metrics` is the `ReviewMetricsSnapshot` object as W2-17 already serializes it (its `Serialize` impl). Expected start of the golden
     `report-empty-phase-is-finite` (check against the golden, the golden wins):
     `{`, `  "RunId": "run",`, `  "StartedUtc": "1970-01-01T00:00:00+00:00",`, `  "Folder": "C:\\x",`, `  "Phases": [`, `    {`,
     `      "ProfileId": "x",`, `      "Workload": 1,`, `      "Samples": [],`, `      "Status": 3,`, `      "Message": null,`, `      "ImagesPerSample": 1,`,
     `      "Count": 0,`, `      "P50": 0,` ... and ends `  "Metrics": null,` / `  "Machine": null` / `}`.
  7. **Report JSON, tokens.** Numbers that are f64 use `pr_perf::rules::fmt_double` (the `R` text System.Text.Json writes: `10` not `10.0`, `1E-07`,
     `1E+21`, `0.30000000000000004`, `-0`). A non-finite f64 anywhere (a sample, or a derived `P50/P95/...` that comes out NaN or infinite) makes
     `to_json` return `Err(NonFiniteNumber)`, as C# throws `ArgumentException` from `Utf8JsonWriter` (goldens `report-nan-samples-throw`,
     `report-infinity-sample-throws`, `batch-nan-outcome-throws` carry `"throws"`). Strings use the default `JavaScriptEncoder` escaping, exactly
     `pr_perf::report::json_string_literal` (`"` `&` `'` `+` `<` `>` `` ` `` and U+007F as `\u00XX` UPPER hex, `\\`, short escapes `\b \f \n \r \t`,
     every non-ASCII UTF-16 unit as `\uXXXX`, `/` not escaped); this also applies to the strings inside `Metrics` (W2-17 documents that plain
     `serde_json` does not escape them: DIVERGENCE there, none allowed here because the golden compares bytes). Recommended writer: `Serialize` impls for
     the four record types driven through `serde_json::Serializer::with_formatter(.., Formatter)` where a private `Formatter` wraps
     `PrettyFormatter::with_indent(b"  ")`, overrides `write_f64` (fmt_double, error when not finite), `write_string_fragment` (the escapes above) and
     `write_char_escape` (serde_json prints control characters as LOWER-case hex `\u001f`; STJ prints `\u001F`), then replaces `\n` by `\r\n` in the
     finished text (safe: string content never holds a raw `\n`). A hand-written writer is equally fine; the golden decides. DateTimeOffset text:
     `yyyy-MM-ddTHH:mm:ss` of the LOCAL time, `.fffffff` with trailing zeros trimmed and absent when zero, then `+hh:mm` / `-hh:mm` (`+00:00` for UTC,
     never `Z`). Use `DateTimeUtc::checked_add_ticks(offset * 600_000_000)` to get the local fields and `to_json()` of it minus the `Z`.
  8. **Batch JSON.** `BenchmarkBatchSummary::to_json` uses the reflection serializer with only `WriteIndented`: same token rules as 7. Properties:
     `Dataset` { `Folder`, `Files` (string array), `UnsupportedExtensions` (object, KEY order = insertion order, values i32), `FileLimit`,
     `SupportedFileCount`, `UnsupportedFileCount` }, `Reports` (array of report objects as in 6), `ProfileOutcomes` (array of phase objects).
     `SupportedFileCount = files.len()`, `UnsupportedFileCount = sum of the values` (saturating cast, see DIVERGENCE). The computed phase properties
     call the same lookup. Empty arrays are `[]`.
  9. **Executor seam.** `BenchmarkPreparedWorkloadExecutor` has no body to port. The C# delegate is `Task<Func<Task<(bool, ReviewMetricsSnapshot?)>>>`;
     R0003 says no async: `prepare` runs the untimed step on the calling worker thread and returns a `MeasureStep`; cancellation is the
     `CancelToken` argument and `ExecutorError::Canceled` (C# `OperationCanceledException`). W7-03 owns the engine that calls it.

## Open questions
- **Lookup seam vs direct calls.** The stub passes `ImagesPerSampleLookup` into `effective_images_per_sample`, `p95_per_image`, `p50_per_image`, `rank` and both
  `to_json`, because `BenchmarkProfiles.Find` (W7-01b) and `BenchmarkWorkloadRunner.ImagesPerSample` (W7-03) live in units that merge later and `models.rs` must
  compile alone. Recommended (used by the stub): keep the parameter; after W7-01b and W7-03 merge, one lead-owned line in `lib.rs` (or W7-03) adds
  `pub fn registry_images_per_sample(id, workload) -> Option<i32>` for callers. Alternative: `models.rs` calls `crate::profiles::find` and
  `crate::runner::images_per_sample` itself and drops the parameter (simpler call sites; makes W7-01a depend on two later stubs and fixes the merge order
  01b -> 03 -> 01a). Lead decides; the golden tests work either way.
- **Executor shape.** `MeasureStep`/`ExecutorError` are the smallest sync translation of the C# delegate. W7-03 may need more (progress, log); if it
  does, W7-03 changes `BenchmarkPreparedWorkloadExecutor` in `models.rs` in its own PR (a one-trait edit), recorded in its contract.
- **`BenchmarkTimestamp`.** A tiny local `DateTimeOffset` (UTC instant + offset minutes). It could move to `pr_core::time` if another unit needs the type;
  kept here because only this report prints an offset today.
- **Oracle wiring.** `OracleCs.csproj` has no `PhotoReview.Benchmarking` reference and `tools/oracle.ps1` must copy `PhotoReview.Benchmarking.dll` (plus the
  `PhotoReview.Imaging*` dependencies it loads, which are already referenced) into `$(CSharpCoreDir)`. If the baseline build of that project needs the
  Windows-only App assemblies, the fallback is to drop `derived_images`/`derived` from the oracle and hand-write the two registry answers used by the goldens
  (`fast-sequential` and `ssd-throughput` workers 8 and 12, `no-preload-baseline` workers 1, `original-correctness` workers 1).
