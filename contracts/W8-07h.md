## Shared design (W8-07h..07k)
1. **One thread, one owner.** The presenter, its sink, compare view model, zoom loader and inbox live on the UI thread. Workers only capture `Arc`s, `String`s, `CancelToken`s and a `CompletionInbox` clone and send
   `PresenterEvent`s. No `Rc<RefCell>` anywhere (D-W8-1), no `async` (D-W8-2).
2. **Per-call environment.** C# holds `ReviewCatalog`, `Func<AppSettings>`, `Func<SessionState?>` and static `StatusFormatter`; Rust lends them in `PresenterEnv` to every call that needs them
   (`present`, `pump`, `clear_presentation`, `remove_missing_catalog_item`). The catalog is `&mut` because `ReviewCatalog` is UI-thread-only and mutated (`set_current`, `update_metadata`, `remove`, `restore`). Between two
   calls the main view model may mutate the catalog; every continuation re-reads what it needs from `env.catalog` (AR16 index rebase, tests `PresentAsync_EarlierEntryRemovedWhileDecoding_*`, `CurrentEntryLeavesCatalogWhileDecoding_*`).
3. **Settings snapshot.** C# reads `_getSettings()` once after the initial stat (line 369) and reuses it; `Navigation::settings` is that snapshot. `ImagePresenter` never keeps `&AppSettings` across calls.
4. **The navigation record.** `Navigation` holds the C# locals of one `PresentCoreAsync` (token, request, path, previous path, retry counter, viewer-decode token CLONE, stopwatch, key, initial size / entry metadata, settings, image, dimensions) and a
   `Phase` (the `await` it is suspended at). At most one `Navigation` exists: a new `present` replaces the old one (the old one is dead anyway: its token is no longer current, so every one of its late events is dropped). Handlers
   `take()` the navigation, check `nav.token == event.token` and the phase, and put it back when they wait again.
5. **Events.** `PresenterEvent` (stub) is the complete list of worker completions; the dispatch table is below. The generation check is the FIRST thing a continuation does where the C# does it (INV-1). A completion for a token
   that is no longer current is dropped; it changes no state, calls no sink, takes no catalog lock.
6. **Workers.** Waits on `PreviewHandle::wait`, `ThumbnailRequest::wait`, `try_get_original_dimensions`, the compare previews / sizes / hashes run through `BackgroundRunner::run` (one job per wait). Stats go to the
   dedicated `NavigationStatWorker` (Q-R29 option C) through `submit_stat`. The UI-scheduler "yield" is `UiScheduler::post(action)` whose action sends a `FrameYielded` event.
7. **Sink protocol.** `IPresentationSink` is owned by the presenter. The C# sink callbacks that read presenter state (`MainViewModel.NotifyCurrentImageChanged` reads `CurrentPresentedPath`, `IsSameSourceSwap`,
   `CurrentOriginalWidth/Height`) get them as an `ImageChange` argument; the C# re-entrant `ZoomModeChanged -> SetViewerZoom` is a pull: after `set_current_image` and `apply_initial_view_mode` the presenter calls
   `sink.take_viewer_zoom_change()` and forwards a `Some(zoom)` to the zoom loader (`sync_viewer_zoom_from_sink`). This keeps the C# order: the zoom reaches the loader BEFORE `on_preview_presented` arms the target
   (tests `NavigatingAway_*`, `RawOnZoom_SupersededLoad..` drive the zoom from `ApplyInitialViewMode`).
8. **Changes.** Every public mutator returns the `PresenterChanges` it accumulated in `self.changes` (`take_changes`). No observer lists.
9. **Dispatch table (`ImagePresenter::dispatch`).**

   | event | continuation | file |
   |---|---|---|
   | `Stat { purpose: Initial }` | `on_initial_stat` | present_a (07i) |
   | `Thumbnail` | `on_thumbnail` | present_a (07i) |
   | `Preview` | `on_preview` | present_a (07i) |
   | `FrameYielded { DeferredKick { index } }` | `on_deferred_kick_due` | present_a (07i) |
   | `FrameYielded { PostFrame }` | `on_post_frame_yield` | present_b (07j) |
   | `Dimensions` | `on_dimensions` | present_b (07j) |
   | `Stat { purpose: Refresh }` | `on_refresh_stat` | present_b (07j) |
   | `Stat { purpose: Recheck }` | `on_recheck_stat` | present_b (07j) |
   | `ComparePreview` / `CompareSizes` / `CompareHash` | `on_compare_preview` / `on_compare_sizes` / `on_compare_hash` | present_b (07j) |
   | `Stat { purpose: NextForMissing }` | `on_missing_next_stat` | missing (07k) |

   A present event needs `navigation.is_some() && navigation.token == token && phase matches`; a missing-run event needs `missing.is_some() && missing.token == token`; else it is dropped.
10. **Test shape.** A test builds the presenter with a recording sink, a `RecordingPreload`, a `PreviewImageService` over fake decoders (helpers of W8-07g `tests/support/preview_fakes.rs`), a `ThumbnailCache` with an injected
    embedded-thumbnail reader, and a `NavigationStatWorker::new()` of its own. It calls `present(..)`, then `while !presenter.is_idle() { presenter.wait_for_event(20 s); presenter.pump(&mut env) }` (a helper). Gates are
    `Condvar`/channel based; no sleeps.

- Semantics notes (this unit):
  1. **Construction** stores the dependencies and builds `ZoomDetailLoader::new(preview_service, clock, runner, wake)` with the same `wake` and `indicator_delay`. It starts no task, reads no file, decodes nothing, posts nothing.
     Defaults: `file_system = PhysicalFileSystem`, `busy_retry_delay = default_busy_retry_delay()`, `runner = ThreadRunner`, `stat_worker = NavigationStatWorker::shared().clone()`.
  2. **`update_current_image` (800 to 818).** Order is observable: dimensions first (0 for `None`), then the image field, then `is_file_change`, then the file identity, then the sink call, then the zoom sync. `is_file_change =
     ImageTransitionDecision::should_transition(presented_file_path, image.and(path), compare.is_visible())`. `presented_file_path`: `None` when `image` is `None`; else the new `path` when one is given; a call without a
     path (zoom-detail swap) keeps it (R10: the next navigation must still see a previous path and fade).
  3. **`update_status`.** `status_text`, `status_needs_attention`, then `sink.set_status_text`. Marks `STATUS`.
  4. **`show_zoom_detail_image` / `_core` (133 to 159).** The flag `is_same_source_swap` is true only around the core call. The core decides `showing_original` from the SHOWN bitmap (`same_platform_image(held.platform_image(), image)` and the
     held image is not a RAW preview), not from `is_showing_original()`. `info_while_original_shown` is ALWAYS reassigned while the original is shown (`None` for a non-RAW photo), so a value left by an earlier photo can never be restored.
     Restoring: only when the saved info is `Some`; `current_photo_info` is replaced only if it is still `Some` (never resurrected after `clear_presentation`); the saved copy is cleared either way.
  5. **`clear_presentation`.** The order of 204 to 212: path, info, saved info, zoom reset (with its effects), image `None`, compare clear. It does not cancel anything.
  6. **`evict_cached_path`** is per path; the callback given to the service removes the preloaded keys of the normalized path. Errors of the service (invalid path, source-bytes failure) are returned, never swallowed.
  7. **`pump`** drains the zoom loader first, then the presenter inbox, until both are empty. It never blocks. A handler that queues a new event (inline scheduler) is covered by the loop.
  8. **`is_idle`**: `navigation.is_none() && missing.is_none() && inbox.is_empty() && !zoom_detail.pending_load() && zoom_detail.queued_events() == 0`.
- Traps checklist (MULTI-AGENT-PLAN section 7; the items below are specific):
  - **T1 INV-1 first.** Every continuation checks `clock.is_navigation_current(token)` before it mutates state or calls the sink. The dispatch `take()`s the navigation: a handler that returns early MUST put it back only when it still waits.
  - **T2 the flag is a window, not a state.** `is_same_source_swap` must be false after `show_zoom_detail_image` returns, and false for every `update_current_image` called from the present path (test: the sink records the flag per call).
  - **T3 clone the token.** `viewer_decode_cancel` is replaced per present and the old token cancelled; the navigation keeps its OWN clone (APP-P01). Never read the shared field from a continuation.
  - **T4 no re-entrancy by construction.** The sink cannot call the presenter (it is owned); the viewer-zoom channel is the pull of note 7 above. A sink that wants to start a present records it and the shell does it after the call.
  - **T5 identity of images.** Every "is this the same bitmap" test uses `same_platform_image` (pointer identity), never pixel equality.
  - **T6 Debug.** Every `pub` type derives or implements `Debug` (`missing_debug_implementations`): `ImagePresenter`, `ImagePresenterDeps`, `PresenterEnv` and `ImageChange` are covered in the stub. `PresenterEvent` / `Navigation` are `pub(super)` and need none.
  - **T7 no UI text literals.** Every status string comes from `viewmodels::format::status` with `env.format` (D-W8-4).

## Open questions (each has a recommended default; the stubs follow it)
- **O1 Catalog ownership.** Default: borrowed per call in `PresenterEnv` (the W8-07a draft makes `FolderLoadCoordinator` OWN a `ReviewCatalog`; if the lead keeps that, one owner must lend it to the others, e.g. the main view model).
  Alternative: `Rc<RefCell<ReviewCatalog>>`, rejected by D-W8-1. Whatever is chosen, the presenter code only needs `&mut ReviewCatalog` during a call.
- **O2 Sink ownership.** Default: the presenter owns `Box<dyn IPresentationSink>` (C# `Sink` becomes `sink_mut()`). Alternative: pass `&mut dyn IPresentationSink` in `PresenterEnv` (then `pump` needs the sink at every call, but the shell can keep one sink for all coordinators).
  The stubs choose ownership because the sink is built before the window (C# comment on `Sink`) and handed over once.
- **O3 `get_current_cache_key_for_entry` failure.** C# lets the exception fault the `PresentAsync` task; Rust returns `Result`. Default: route it to the generic failure branch (`PresentFailure::CacheKey`), which shows an error status. A silent drop would leave "Loading" forever.
- **O4 `OriginalShown` event.** Default: an optional hook (`set_original_shown_hook`), used by measurement code only; the effect is otherwise ignored.
- **O5 `UiScheduler::post` as `YieldAsync`.** The C# yield resumes at Background priority (after the frame). `UiScheduler` has no priority; `UiDispatcher::post_with_priority(.., Background)` would be exact. Default: `Arc<dyn UiScheduler>` (so `QueuedUiScheduler` works in tests);
  the composition root may pass a dispatcher adapter that posts at Background.
