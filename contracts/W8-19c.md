## Semantics (C# is the spec)
1. **`add` (private)**: `counter = counter.saturating_add(1)`; if `counter > MAX_CONTROLS` record `TooManyControls` and return `None` (nothing else changes); `id = id_base + counter` (saturating); then exactly the C# order: group-box test, the pending cut (`style |= WS_GROUP`, `break_group = false`), the `&` doubling of a Button-class text (provider and item text), `items.push(DialogItem::new(class, id, text_now_or_empty, style).with_ex_style(ex_style))`, `texts.insert(id, provider)` when a text was given. Every declaration method stops at the first `None` and returns zeros: `group` 0 (the content closure is NOT run), `check` 0, `combo`/`edit` `SettingsRow { 0, 0 }`, `slider` zeros, `buttons`/`check_flow` a list of the input length holding the ids allocated before the failure and zeros after them, `radio` `texts.len()` zeros, `key_grid` the cells added so far (the cell being built is dropped). Items added before the failure STAY, no layout element is added for the failed call (D-W8B5-704).
2. **Styles and classes** are exactly the C# table above; the Rust constants are the ones named in "Depends on". `DIALOG_STYLE_CHILD` is `WS_CHILD | WS_VISIBLE`. The group-box test is `(style & 0xF) == BS_GROUPBOX` and applies to the Button class only.
3. **Group**: allocate the box id (one `add`), push a fresh container, `content(self)`, pop it, then add `GroupElement::new(id, children)` to the container below. The content closure receives the same builder (`&mut Self`); elements it declares go into the new container.
4. **Radio**: validation first and before any state change (`texts.len() < 2` -> `RadioNeedsTwoOptions`; `hints` of another length -> `RadioHintCountMismatch`; a pending group cut and the counter are untouched). Then the radios (first one `| WS_GROUP | WS_TABSTOP`), then `break_group = true`, then the hints (each `Some` is a Static note; the first hint's `add` consumes the cut), then one `RadioElement` per radio with its hint id. The cut stays pending after the call when there is no hint, so the NEXT declared non-group-box control gets `WS_GROUP`.
5. **Key grid**: per spec in order: label Static (`add`), key box Edit, `key_boxes.insert(box)`, and the clear button only when `clearable` (provider `|| "×".to_owned()`, Button class so it also gets the `&` doubling, which leaves `×` unchanged); then ONE `KeyGridElement` for the whole list.
6. **`set_group_visible(title_id, visible)` / `group_visible(title_id)` / `flatten()`**: walk the tree pre-order through `as_group()`/`children()`; `set_group_visible` returns whether a group with that title id exists. `elements()` is the root container; `elements_mut()` the same mutably. These replace the frame's `Flatten` + `_groupsById` (D-W8B5-713).
7. **Registrations**: `notes` = ids of `note()` statics and radio hints; `warning_texts` = ids of `warning()`; `key_boxes`; `combo_items[combo_id]` only when `items` is `Some` (an empty `Some(vec![])` registers an empty list); `sliders[slider_id] = (min, max)`; `texts` holds an entry for every control declared with a `Some` text, never for a control declared with `None`. The maps are `BTreeMap`/`BTreeSet` (iteration by id, which is the declaration order because ids increase).
8. **`KeyGridElement::place_visible`**: as the formula above, with the guards of D-W8B5-703: `columns`'s divisor `cell_min + column_gap` of `0` gives 1 column (the C# would divide by zero), the clamp is `max(1).min(2)`, `/ columns` has `columns >= 1`, all `+ - *` saturate, `cells.get(i)` instead of indexing. The element is NOT hidden by `is_hidden` of the surface (only by `visible`).
9. **`error()` / `errors()`**: a recorded violation never clears; the frame treats a non-empty list as "this page failed to declare" (19j).
10. **Debug, Clone**: `SettingsPageBuilder` is not `Clone`; `Debug` is the hand-written summary in the stub.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T3 (arithmetic): the counter, the id sum and the layout use saturating operations; `MAX_CONTROLS` is exactly 999 (the 999th control is allowed, the 1000th is not).
- T8 (null vs empty): `text: Option<TextFn>` (`None` registers no provider and gives item text `""`; `Some(|| String::new())` registers an empty provider); `combo_items` `None` versus `Some(vec![])`; `hints[i] = None` adds no control.
- T9 (exception to Result): three throws become three `SettingsBuilderError` variants; the oracle golden's `{"threw": "InvalidOperationException"}` corresponds to `TooManyControls`, `{"threw": "ArgumentException"}` to the two radio variants; the count of `threw` entries equals `errors().len()`.
- T10 (order): item order = declaration order = Tab order; hints after radios; a group box id before its children; `texts()`/`notes()` iterate by id.
- The textual `&`: only Button-class texts are doubled (`"Display & performance"` shows the ampersand); Static, Edit and ComboBox texts are not. The doubling applies to the item text AND to the stored provider, which the frame calls again on a language change.
- UTF-16 / non-ASCII: texts are Rust `String`s; the template writer (18d) converts. Vietnamese in the golden is compared as text.
- R0003: `content(self)` runs page code on the UI thread: the closure may declare but must not panic; no `unwrap`/`expect`/indexing in the builder.

## Error mapping
| C# | Rust |
|---|---|
| `InvalidOperationException("A settings page can declare at most 999 controls.")` | `SettingsBuilderError::TooManyControls` recorded, call returns zeros |
| `ArgumentException("A radio group needs at least two options.")` | `RadioNeedsTwoOptions`, returns `texts.len()` zeros, no state change |
| `ArgumentException("There must be one hint (or null) per radio option.")` | `RadioHintCountMismatch`, same |
| `ArgumentNullException.ThrowIfNull(...)` | unrepresentable |
| `try { content(this) } finally { Pop }` | pop after the closure returns (a panic in page code is a bug and propagates) |

## Open questions (recommended default in bold)
1. **Sticky recorded error versus `Result` on every method**: **recorded errors** (D-W8B5-704): a page body of 30 declarations with `?` on each would be unreadable and the failure is a programmer error.
2. **`group` takes `impl FnOnce(&mut SettingsPageBuilder)`**: **yes**; the C# `Action<SettingsPageBuilder>` receives the same builder, which is the same borrow.
3. **Key cell field name for C# `Box`**: **`box_id`** (`box` is a Rust keyword).
4. **`Vec<TextFn>` clones**: the builder takes slices and clones the `Rc`s; the C# keeps the caller's list. **Clone** (cheap).
