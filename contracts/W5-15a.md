## Semantics notes
1. **Loading (I-15, the security rule).** `LibraryHandle::load_next_to_exe(name)`: `std::env::current_exe()` -> `library_path_next_to`
   -> `load_from(abs)` = `LoadLibraryExW(abs_utf16_nul, null, LOAD_WITH_ALTERED_SEARCH_PATH)`. Never call the loader with a bare name, never
   use `SetDllDirectory`/PATH. Do not canonicalize the exe path (keep what `current_exe` returns). Null => `LoadFailed { path, os_error:
   GetLastError() }`. `cfg(not(windows))`: every load returns `Err(LoadError::Unsupported)` (the crate must still build and the pure tests
   must run). `Drop` = `FreeLibrary` (ignore its result). The test exe lives in `target/<profile>/deps`, so native tests need the DLL there.
2. **`api()`** loads once per process (success or failure cached in `static API: OnceLock`), resolves all 23 exports with `GetProcAddress`
   (NUL-terminated `CString`/byte literal per name; transmute of the non-null `*mut c_void` to the field's fn-pointer type, one SAFETY
   comment naming the LibRaw 0.22 prototype from `libraw.h`). First missing export => `Err(MissingExport { name })` (the `&'static str`
   from `ENTRY_POINTS`). The library inside `LibRawApi` is never freed. It is independent of W5-15b's probe (C# P/Invoke vs
   `NativeLibrary.TryLoad`): the probe loads, checks and frees its own handle; `LoadLibraryExW` refcounts, so both may coexist.
   C# re-attempts a failed P/Invoke load on every call; Rust caches the failure: harmless, because W5-15b caches the probe answer for the
   process lifetime too and nothing calls LibRaw when the probe failed (note it as DIVERGENCE in the module doc).
3. **`try_read_raw_structure(block)`**: `block.len() < IPARAMS_READ_LEN` => `None`. `colors = i32::from_ne_bytes(block[340..344])`;
   `!(1..=4).contains(&colors)` => `None`; for `i in 0..colors` `block[420 + i]` must be `b'A'..=b'Z'`, else `None`; `filters =
   i32::from_ne_bytes(block[344..348]) as u32`. Use `get(..)`/`try_into` (never index-panic). Native wrapper `raw_structure_with`: gate
   first (`false` => `None` without calling `libraw_get_iparams`), then null => `None`, else `slice::from_raw_parts(ptr as *const u8,
   IPARAMS_READ_LEN)` (SAFETY: `libraw_get_iparams` returns `&imgdata.idata`, a `libraw_iparams_t` of more than 425 bytes inside the live
   `libraw_data_t`; the slice does not outlive `&self`). `raw_structure()` uses `crate::availability::is_exact_pinned_version` (W5-15b).
4. **White-balance proof (`try_set_use_camera_wb_core`)**: exact C# order (see the stub doc): gate (once) -> 3 sentinel sets (color, bps,
   bright) -> 3 reads at `layout` -> 3 real sets -> mismatch => `false` -> write `1` at `use_camera_wb` -> return `read == Some(1)`.
   Sentinels `0x5EA10C01/02/03`. The gate failing means NO setter call and NO read/write (the fake checks `calls.is_empty()`).
   `impl WhiteBalanceTarget for LibRawHandle`: setters call the `libraw_set_*` exports; `read_i32`/`write_i32` refuse `offset < 0` or
   `offset + 4 > DATA_PROBE_LIMIT` (`None` / `false`, checked arithmetic, no overflow on `i32::MAX`), else `ptr::read_unaligned` /
   `write_unaligned` at `raw + offset` (SAFETY: offset window inside `libraw_data_t`: `color` (`libraw_colordata_t`, which STARTS
   with `ushort curve[0x10000]`) comes after `params` (at 5232), `rawparams`, `progress_flags` and `process_warnings`, so the struct
   exceeds 5232 + 131 072 bytes > 65 536; the handle is open and not shared).
   The window guard is a Rust-only safety net, unreachable with the pinned or the tests' shifted layouts (all within 5376..5500); C# would
   read wherever the layout points. Production `try_set_use_camera_wb` = `_with(.., is_exact_pinned_version, PINNED_WHITE_BALANCE_LAYOUT)`.
5. **`NativeOwner`**: invalid = `0` or `usize::MAX`; `close()` sets `closed = true` and, only if valid and `release` is still `Some`,
   `take()`s and calls it; `Drop` = `close()`. `LibRawHandle::init`: `api()?` (=> `Unavailable`), `libraw_init(flags)`, null =>
   `InitReturnedNull` (no owner created), else `NativeOwner::new(ptr as usize, move |p| unsafe { (api.libraw_close)(p as *mut c_void) })`.
   `LibRawImage` likewise with `libraw_dcraw_clear_mem`. Use `expose_provenance()` / `with_exposed_provenance_mut()` for the `usize`
   round-trip (or `as` casts; clippy must stay clean).
6. **`LibRawImage`**: on `dcraw_make_mem_*` success read the header with `ptr::read` (SAFETY: LibRaw returns a `libraw_processed_image_t`
   with at least the 16-byte header); `data()` = `None` when closed, else `slice::from_raw_parts(base + 16, header.data_size as usize)`
   (SAFETY: LibRaw allocates `sizeof(header) + data_size` bytes, `libraw_memmgr` / `dcraw_make_mem_image` in `utils_libraw.cpp`). The
   image does NOT borrow the handle: C# closes the handle first and keeps the image (W5-16's peak-memory rule). Null return =>
   `Err(error_code)`, the `out int` value as written by LibRaw (initialised to 0 before the call).
7. **Cancellation callback**: `set_cancel_token(token)`: `let boxed = Box::new(token)`; call `libraw_set_progress_handler(raw,
   Some(cancellation_progress_callback), &*boxed as *const CancelToken as *mut c_void)`; then `self.cancel = Some(boxed)` (old box dropped
   after LibRaw holds the new pointer). The callback: null => `1`, else `progress_verdict(Some(&*data.cast::<CancelToken>()))` (SAFETY: the
   pointer is the handle's own box, alive until after `libraw_close` because `owner` is declared and therefore dropped before `cancel`).
   No panics across `extern "C"` (only an atomic load; do not add logging or allocation).
8. **Strings**: `open_wfile` takes `&OsStr` (WTF-16 on Windows via `std::os::windows::ffi::OsStrExt::encode_wide` + trailing 0; unpaired
   surrogates pass through like a C# string; `cfg(not(windows))` path: `to_string_lossy().encode_utf16()`). C strings out of LibRaw
   (`version`, `strerror`, decoder name): `CStr::from_ptr(..).to_string_lossy().into_owned()` (C# `PtrToStringAnsi`; all LibRaw strings
   are ASCII, so ANSI vs UTF-8 cannot differ). `format_error_message`: `None` or `trim().is_empty()` => `format!("LibRaw error {code}")`.
9. **Closed handle**: after `LibRawHandle::close()` every method returns the neutral value without touching LibRaw (`-1` error code,
   `0` sizes, `None`, `Err(-1)` for make_mem, setters no-op, `read_i32` `None`). C# would throw `ObjectDisposedException`; W5-16 never
   calls after close. Document as DIVERGENCE (unreachable).
7a. **`open_shared_buffer(Arc<[u8]>)`**: same call as `open_buffer` over `buffer.as_ptr()` / `len()`; then `self.shared_buffer =
   Some(buffer)` (field declared after `owner`, so it is freed after `libraw_close`). Closed handle => `-1` without storing.
   Exists for W5-16c's `LibRawSession` adapter (`open_buffer(SourceBytes)` on a `Box<dyn LibRawSession>`, which cannot carry a
   `'buf` borrow). Native test: `open_shared_buffer` + `unpack_thumb` on a corpus CR2 with the caller's `Arc` dropped before the
   call (proves the handle keeps it alive).
10. **Thread rules**: `LibraryHandle`: `Send + Sync` (explicit `unsafe impl` with SAFETY, already in the stub); `LibRawApi`
    gets `Send + Sync` automatically (fn pointers + `LibraryHandle`; no extra `unsafe impl`).
    `LibRawHandle`, `LibRawImage`: `Send` (auto, through `NativeOwner`'s `Send` closure), not `Sync`. Do not add `unsafe impl Sync`.
11. **No panics** anywhere in this file on any input (malformed iparams blocks, offsets, null pointers, missing DLL). No `unwrap`/`expect`
    in production paths; `OnceLock` init must not panic.

## Traps checklist (MULTI-AGENT-PLAN section 7 + FFI)
- §7.3 arithmetic: offset checks with `checked_add`; `data_size as usize` (u32 -> usize lossless on x64); `filters` reinterpret (`as u32`),
  never `try_into` (negative i32 filters are valid bit patterns).
- §7.8 null vs empty: `version_string` `None` (null) vs `Some("")`; `decoder_name` null => `None`; `format_error_message(Some(""))` => fallback.
- §7.9 exceptions to results: missing DLL (`DllNotFoundException`) => `Err(Unavailable)`; entry point missing (`EntryPointNotFoundException`)
  => `Err(MissingExport)`; init null => `InitReturnedNull`. Keep the three apart (W5-15b reason texts depend on it).
- FFI: every `unsafe` block has `// SAFETY:` (workspace lint `undocumented_unsafe_blocks`); `unsafe_op_in_unsafe_fn` is deny, so the
  bodies of `call_version`/`call_init_close` need inner `unsafe {}` blocks. Calling convention: `extern "C"` (= cdecl on x64; the C#
  `CallConvCdecl`).
- Drop order: `owner` before `cancel` in `LibRawHandle` (field order, do not reorder; a test with a fake is not possible, keep a comment).
- `open_buffer` lifetime `'buf`: never use `'static` or transmute the borrow; W5-16 keeps the buffer alive by type.
- Do not load `libraw.dll` from tests by bare name or `current_dir`; native tests use `api()` / `LibraryHandle::load_next_to_exe`.
- The source-scan test depends on the exact markers and the `libraw_xxx:` field syntax; keep one field per line.

- None. The unit is an FFI binding: its observable outputs are either pure functions already pinned by exact C# test transliterations

## Open questions
1. **Getting `libraw.dll` next to Rust executables.** C# copies `native/x64/libraw.dll` (+ LICENSE.LGPL/CDDL, source zip, NOTICE) next to
   the build output via MSBuild and re-verifies the pin each build (`tools/fetch-libraw.ps1`). Rust: recommended a lead-owned
   `tools/stage-native.ps1` that verifies the SHA-256 pin (`native/libraw.sha256`, copied into this repo under `native/`) and copies the DLL
   into `target/<profile>/` and `target/<profile>/deps/` (tests), run by CI before `cargo test -- --ignored`. Alternative: a `build.rs` in
   `pr-libraw` copying into `OUT_DIR/../../..` (fragile, and the license files must ship with the app anyway). The packaging step must copy
   the license files too (LGPL obligation).
2. **No `libloading` / `windows` feature.** The stub declares `LoadLibraryExW`/`GetProcAddress`/`FreeLibrary`/`GetLastError` itself
   (`#[link(name = "kernel32")]`, 4 functions), so `pr-libraw` needs no new dependency. Alternatives: `windows` crate with feature
   `Win32_System_LibraryLoader` (lead adds the feature; heavier compile) or `libloading` (new external crate, R0003 list). W5-13a
   (TurboJPEG) faces the same choice; both crates should use the same approach (they cannot share code without a common crate;
   duplicating 4 extern declarations is acceptable). Lead decides; recommended: hand declarations.
3. **`RawStructure` and `ProcessedImageHeader` ownership (review: conflicting drafts).** `RawStructure`: W5-16b's draft defines it in
   `memory_guard.rs` (C# `DecodeMemoryGuard`) and W5-16c imports `crate::memory_guard::RawStructure`; this draft now only re-exports
   it (fixed). `ProcessedImageHeader`: W5-16c's draft `decoder.rs` ALSO defines it (same fields, `DATA_OFFSET` assoc const).
   Recommended: keep it here (it is a `repr(C)` layout in the fn-pointer types and read by `unsafe`; defining it in `decoder.rs` would
   make `native` depend on the whole decoder unit) and have W5-16c `pub use crate::native::ProcessedImageHeader;`. Lead decides.
   Also W5-16b's draft says the `TryReadRawStructure_*` tests belong to "the FFI sub-unit of W5-16a": they are THIS unit's (W5-16a
   is `FullDecodeGate`); W5-16b's text needs the fix.
4. **Cancellation (review: duplicated in W5-16c).** `CheckCancellation_*` are in `LibRawDecoder` in C#, but the verdict is ported
   here. W5-16c's draft `decoder.rs` declares its own `CancellationState` (Arc), `check_cancellation(Option<&CancellationState>)`
   and a `pub unsafe extern "C" fn libraw_progress_callback`, i.e. a second callback and a second `unsafe`. Recommended: one owner =
   this unit (`progress_verdict` + private callback + `set_cancel_token`); W5-16c drops its callback (keeps `CancellationState` only
   if its seam needs it, mapping to `set_cancel_token(state.token().clone())`) and does not port `CheckCancellation_*` again.
   Alternative: W5-16c owns all of it and this unit's `set_cancel_token` takes the state pointer. Lead decides; W5-16c has no
   contract.md yet, so its writer must be told either way.
5. **Closed-handle behaviour** (Semantics 9) and **failure caching in `api()`** (Semantics 2) are small, unreachable DIVERGENCEs; if the
   lead wants them as PARITY `Different` notes, the porter adds the sentence to its PARITY report.
6. **`DATA_PROBE_LIMIT` = 65 536**: derived from the 0.22.2 header layout, not measured. The native test `wb_target_out_of_window_is_a_mismatch`
   and the pinned-layout test exercise the window; a verifier with the LibRaw 0.22.2 headers can confirm `sizeof(libraw_data_t)` and the
   `color` offset (expected far above 65 536).
