## Semantics notes
1. **Start** (lines 92 to 125): `file_actions` None or `is_busy()` -> Done, NO status; catalog empty -> Done; `pre_hash_generation = clock.current_folder()`; `candidates = catalog.paths()` (empty -> Done); a new `CancelToken` replaces and cancels a previous slot
   (`hash_gate`); status `status.duplicateCheckRunning`; job on `WorkerLane::Hashing`: `pr_core::file_actions::duplicates::find(&candidates, remove_numbered, &mut hash, file_system, &token)` then `token.check()`.
2. **Hash closure** (lines 115 to 123): first `!clock.is_folder_current(pre_hash_generation)` -> `HashFailure::Canceled` (stop hashing the remaining same-size files); no hash service -> record `HashServiceMissing` and return `Canceled`;
   else `hasher.get(Path::new(path), &token)`: `Ok(h)` -> `Ok(h)`; `Err(FileHashError::Canceled)` -> `HashFailure::Canceled`; every other `FileHashError` (`Path`, `Io`, `Source`, `ChangedWhileHashing`: the C# `ArgumentException`/`IOException` family that `DuplicateFinder` skips) ->
   `HashFailure::Unreadable(io::Error::other(error.to_string()))`.
3. **Classification of the hash result** (`on_hash_finished`, lines 126 to 168), in this order: the slot is cleared in every case (C# `finally`: only if it is still this run's slot); `Found(list)`: if `!is_folder_current(pre_hash_generation)` -> status `status.duplicateCheckCanceledFolderChanged`, Done;
   `Canceled`: folder not current -> `duplicateCheckCanceledFolderChanged`; else token canceled -> if the slot was superseded by a newer run: silent, else `status.duplicateCheckCanceled`; else -> `status.duplicateCheckFailed(<canceled text>)`;
   `HashServiceMissing` -> `status.duplicateCheckFailed(err.io.hashServiceMissing text)`; `Failed(text)` -> `duplicateCheckFailed(text)`. Done.
4. **After a valid list** (lines 164 to 202): empty -> status `status.noDuplicatesFound`, Done; first `lacks_recycle_bin` file -> status `status.batchCanceled` + error dialog (`dialog.batchErrors.title`, `core.recycle.unsupportedDrive(fileName)`), Done (Q-R14);
   with a dialog service: `dialog_folder_generation = clock.current_folder()`, `show_batch_review(&items)` where `items[i] = BatchReviewItem{ path, length: catalog.find(path).length }` (unknown size = `None`); not confirmed -> `batchCanceled`; folder changed -> `duplicateCheckCanceledFolderChanged`;
   executor busy -> Done silently; re-filter by `catalog.index_of(path) >= 0`; empty -> `batchCanceled`. Without a dialog service the list goes straight to the batch.
5. **Batch** (lines 204 to 273): `clock.stop_for_action()`, `preload.cancel()`, `action_folder_generation = clock.current_folder()`; ONE recycle job per file, strictly in sequence (the next is submitted only when the previous event arrived), request
   `FileActionRequest::new(path, Recycle)` with `CancelToken::none()`. Per result: `succeeded` -> `succeeded += 1` and `preview_service.evict_cached_path(path, Some(&|n| preload.remove_preloaded_keys_for_path(n)))`;
   failed -> `"<file name>: <error>"`; `Panicked(text)` -> `log.error`, failure `"<file name>: <text>"`, the batch continues; `Canceled` -> the batch stops and the step is `Canceled` (C# lets the `OperationCanceledException` escape).
6. **Finish** (lines 242 to 272): folder no longer `action_folder_generation` -> if `succeeded > 0 || failures > 0`: `sink.show_late_action_status(status.lateBatchRecycled(done, failed))`, Done (the batch is never registered for undo; nothing is reloaded);
   else if `succeeded > 0` and the first file has a parent folder: `sink.reload_folder(parent)` (reload FIRST, because opening a folder clears the status line); `false` -> `show_late_action_status(lateBatchRecycled)`, Done; `true` -> `awaiting_reload`, `Pending`
   until `on_reload_finished(still_current)`; `still_current == false` -> late status, Done; `true` -> status `status.batchDone(succeeded, failures)` and, with failures and a dialog service, `show_error(dialog.batchErrors.title, failures.join(CRLF (carriage return, line feed)))`, Done.
7. **`clear_cache`** (lines 275 to 304): dialog service present -> `show_confirmation(dialog.clearCache.title, dialog.clearCache.message)`, declined -> Done; then in this order `preload.cancel()`, `thumbnail_cache.clear_memory()`, `preview_service.clear_cache()`, `preview_service.clear_source_bytes_cache()`,
   `preload.clear_preloaded_keys()` (RAM first: it also bumps the epochs so in-flight writers stop persisting), then the disk clear (`clear_disk_caches` or thumbnail `clear_disk()` then preview `clear_disk()`) as a job on `WorkerLane::CacheClear`.
   `Cleared` -> status `status.cacheCleared`; `Panicked(text)` -> `log.error("Clear cache failed")` and status `ActionFailed(dialog.clearCache.title, text)`; `Canceled` -> no status, step `Canceled`.
8. **`cancel_duplicate_check`** (Q-R25): `&self`, locks `hash_gate`; a slot present -> `token.cancel()`, true; else false (after hashing ended it is false, so Esc can never reach the review dialog or the batch).

## Traps checklist (concrete)
- **Two generations**: `pre_hash_generation` guards hashing and the review dialog; `action_folder_generation` (read AFTER `stop_for_action`) guards the batch. Do not reuse one for the other (test `..FolderChangedDuringBatch_ReportsLateCompletion`).
- **Reload and status order**: reload first, status after (`..BatchDoneStatus_SurvivesFolderReload`); a folder opened DURING the reload writes nothing into the new folder (`..FolderOpenedDuringReload_WritesNothingIntoNewFolder`, D-03 via `still_current`).
- **Superseded run stays silent**: only the run that still owns the slot may write the "canceled" status.
- **One unexpected throw must not abort the batch** (`..AnUnexpectedThrowForOneFile_DoesNotAbortTheBatchAndIsReported`), but a cancellation must not be reported as a file failure.
- **INV-6/INV-4**: each recycle goes through `IFileActionExecutor::execute`, which journals and takes the service gate; the controller never deletes files itself. The batch never sets `allow_permanent_delete`.
- The hash job and the recycle jobs run off the UI thread; `ReviewCatalog` and the sink are touched only from `handle_event` / `remove_duplicates` / `clear_cache` on the UI thread. The candidates list is copied before the job starts.
- `hash_gate` is a `Mutex<Option<HashSlot>>`: poisoning recovered with `PoisonError::into_inner`; never hold it while calling the sink or the dialog.
- Dialog (`show_batch_review`) is modal and synchronous: after it, re-check the generation, `is_busy()` and the catalog (R7-4).
- Failure lines join with CRLF (C# `Environment.NewLine` on Windows); counts in `log` and `LocArg` use invariant formatting.
- No `async`, no `block_on`, no `unsafe`, no `windows` crate.

## Open questions (each has a recommended default that the stub follows)
- **O1 Reload completion** (this closes W8-06d open question 1 for W8-07f). `IDuplicateCleanupSink::reload_folder` returns once the request is posted, but the status must be written after the load, and "another folder opened during the reload" must be known. Default (used): the sink keeps its
  signature; `reload_folder` returning `true` means "accepted"; the shell calls `DuplicateCleanupController::on_reload_finished(cx, still_current)` when that load ended (`still_current` = no other load started meanwhile, decidable by the shell from `FolderLoadUpdate`/the generation).
  Alternative: `reload_folder(folder, on_done: Box<dyn FnOnce(bool)>)` (a B1 change). Not applied; the lead decides. Required B1 stub changes: none.
- **O2 `IUiScheduler` dropped** (D-07f-1). The review dialog call is already on the UI thread in the continuation, so `InvokeAsync(ShowBatchReview)` is a direct call. The constructor loses one argument.
- **O3 Cache eviction errors** (D-07f-2). `PreviewImageService::evict_cached_path` returns `Result<(), PreviewError>` (C# throws, which would abort the whole batch with files already in the Recycle Bin). Default: log and continue.
- **O4 `ThumbnailCache`/`PreviewImageService` thread-safety**: they are used from the UI thread (RAM clears) and, inside `clear_disk_caches`, from the cache lane. Both are `Arc`-shared services in pr-imaging; the porter confirms `Send + Sync` and, if not, passes closures built by the composition root.
- **O5 Hash error mapping** (note 2): `FileHashError::Source` may carry errors that C# would NOT skip. Default: treat as unreadable (skip the file). Verify against `SourceBytesError` when W8-04e is ported.
- **O6 `Canceled` step**: C# lets `OperationCanceledException` out of `RemoveDuplicatesAsync`/`ClearCacheAsync`; the view model decides (W8-08x). No state is restored.
