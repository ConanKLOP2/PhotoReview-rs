- Semantics notes:
  1. **The Explorer-order gate (INV-9, K-01).** C# `await WaitForPendingExplorerOrderAsync()` completes synchronously when `PendingOrder` is already complete. Rust: `park_if_order_pending(cmd)` is false (and the
     command runs inline) unless `folder_coordinator.pending_order()`; then the command is queued in `deferred` and returns an EMPTY change set. When any coordinator update has `order_gate_released`
     (`handle_folder_event`, `dispose`), `resume_deferred` runs the queue in submission order; a command that parks again (a new gate opened by a newer load) stops the loop and stays at the front.
  2. **`open_folder_core` order** (C# 385 to 437): blank folder `Err` first (even when closed); `is_closed` -> finish with `None`; `required_epoch` mismatch -> finish with `None` (checked ONCE, before the
     ownership call, not again after it); no ownership -> `start_load`; ownership -> worker `before_open(folder, initial, none)` and `MainEvent::Ownership` carrying `epoch_at_request`.
  3. **`on_ownership_decided`** exactly as the doc in the stub (C# 399 to 419): AfterOpen is called only for a GRANTED (`Proceed`) open that is then dropped; a refusal never calls it; a refusal superseded by a newer open
     writes no status. The status texts use the folder's last path segment (`get_file_name(trim_ending_directory_separator(folder))`), keys `status.folderOpenedInOtherWindow` / `status.folderOpenInOtherWindowNoResponse`.
  4. **`start_load`** (C# 421 to 436): `folder_load_epoch += 1` FIRST (the value is the open's epoch), `status_text = ""` WITHOUT a report (C# `_statusText = ..`), `presenter.reset_file_identity()`, then `load`. The finally-block
     (`ownership.after_open(folder, shown_folder)`) and `NotifyNavigationStateChanged` run in `finish_open`, once per started open, also when the load ends in a failure (the coordinator reports it through the sink, the
     task still completes) or is superseded.
  5. **Superseded opens.** A new `load` supersedes the previous one inside the coordinator: the old load's events are dropped, so no `Finished` ever arrives for it. The view model finishes the old `PendingOpen` itself right after
     the new `load` call returns (its epoch is the old one, `purpose` follow-ups see `epoch != folder_load_epoch`). `close_session` (08d) finishes a pending open the same way. Exactly one `after_open` per started open.
  6. **Presentation requests** all go through `present_request` (08a): `next` = `min(current + 1, count - 1)`, `previous` = `max(current - 1, 0)`, `first` = 0, `last` = `count - 1`; each first returns for an empty catalog, calls
     `clock.next_interaction()`, clears the event status silently and presents. No explicit `notify_navigation_state_changed` (R05: the presenter drives it through the bridge).
  7. **`skip`**: needs `0 <= current < count`; `next_interaction`; with a session: append unless present (OrdinalIgnoreCase), `updated_utc = now`, `persist_session`; then the `next` target (`min(current + 1, count - 1)`, i.e.
     the last image stays). The persisted session JSON is unchanged (D-W8-5).
  8. **`toggle_compare`**: `compare.set_visible(enable)` BEFORE the present; the override is `presented_path_of_current_entry()` (None when stale), `include_capture_group_in_compare = enable`. It does not wait for the Explorer order.
  9. **`open_path`**: `pr_core::catalog::drag_drop::parse(Some(&[path]), settings.raw_support_enabled, settings.webp_heic_support_enabled, file_system)` with the CURRENT settings; the warning text is the catalog text of
     `warning.catalog_key()` (`core.dragDrop.*`); an invalid result without a warning would use `status.noValidInput`.
  10. **Sibling folder**: `begin_navigate(direction, session folder, catalog current path)` on the UI thread; the search runs on a worker (`BackgroundRunner::run`) and must not touch the view model; `complete_navigate` checks
      the folder generation (INV-5 style) before it writes anything.

## Open questions (each has a recommended default; the stubs follow it)
- **O1 Resume order of parked commands.** The C# gate is a `TaskCompletionSource` created with `RunContinuationsAsynchronously` (FolderLoadCoordinator.cs line 233): each parked command's continuation is posted to the UI context when the source completes; no C# test pins the order of two parked commands. Default: FIFO (submission order).
- **O2 A load that never reports `Finished`.** `FolderLoadCoordinator::dispose` drops events of the active load, so its `PendingOpen` would hang; `close_session` finishes it (note 5). Confirm with the 07b porter that every other end of a load is a `Finished` update.
- **O3 `PresentError::PathNotInEntry`.** C# lets the `ArgumentException` fly out of `PresentAsync`. Default: `present_request` logs and ignores it (callers pre-validate the override with `presented_path_of_current_entry`).
- **O4 Direction check.** `navigate_sibling_folder` returns `Err(InvalidDirection)` before anything (RV-A08). The shell's PageUp / PageDown always pass +-1.
- **O5 Ownership cancellation.** C# passes no token; a closing window cannot interrupt a blocking `before_open`. Default: `CancelToken::none()`; the worker result is dropped by the `is_closed` check.
