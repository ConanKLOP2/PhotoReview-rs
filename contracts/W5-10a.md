- Semantics notes (all comparisons are the C# ones, written overflow-free; port in the C# order so the first failing check is the same):
  1. **`try_read_box` header.** `length = source.length()`; `offset < 0 || offset > length - 8` => `Ok(None)`. Read 8 bytes at `offset`; a slice shorter than 8 => `Ok(None)`.
     `size32 = u32::from_be_bytes(first 4)`, `box_type` = the next 4 bytes mapped one by one (`b <= 0x7F` => that char, else `'?'`, which is what `Encoding.ASCII.GetString`
     does; the oracle pins it with `type-non-ascii-bytes`). `total_size = size32`, `header_size = 8`.
  2. **`size32 == 1` (largesize).** `offset > length - 16` => `Ok(None)`; read 8 bytes at `offset + 8` (short => `Ok(None)`); `u64::from_be_bytes`; `> i64::MAX as u64` => `Ok(None)`;
     `total_size = that`, `header_size = 16`. **`size32 == 0`** (to the end of the container): `end = match container_end { Some(e) if e >= 0 => e.min(length), _ => length }`,
     `total_size = end - offset` (can be negative: `Some(0)` with `offset >= 8` and a container end before the offset; the next check rejects it). Note `Some(0)` is a real container end.
  3. **Bounds.** `total_size < header_size || total_size > length - offset` => `Ok(None)` (the second form is the overflow-free `offset + total_size > length`; never write the sum).
  4. **`uuid`.** `box_type == "uuid"` (case-sensitive; `"UUID"` is an ordinary box): `total_size < header_size + 16` => `Ok(None)`; read 16 bytes at `offset + header_size`
     (short => `Ok(None)`); `uuid = Some(bytes)`; `header_size += 16`. `payload_offset = offset + header_size`, `payload_size = total_size - header_size`. The reads and the
     checks interleave exactly as in C#: a size check that fails first means NO later read is issued (golden `source-fail-not-reached-when-offset-invalid`,
     `source-fails-after-all-reads-needed-is-fine` count the reads).
  5. **`read_child_boxes`.** `start = parent.payload_offset`; `start < 0 || start > length || parent.payload_size < 0 || payload_skip < 0` => empty `Vec`.
     `limit = start + min(parent.payload_size, length - start)` (the clamp keeps the sum inside `0..=length`). `current = start`;
     `payload_skip as i64 > limit - current` => empty (equal is allowed: then the loop simply does not run); `current += payload_skip`.
     Loop `while limit - current >= 8 && list.len() < MAX_CHILD_BOXES`: `try_read_box(source, current, Some(limit))?`; `None` => stop; `child.total_size > limit - current` => stop
     (the child is NOT added); else push and `current += child.total_size`. A child of `total_size >= 8` always advances, so the loop ends; there is no other termination argument to add.
  6. **Errors.** The only way out through `Err` is `source.read` failing (budget, I/O, closed stream); propagate it unchanged with `?` (both kinds, `io` inner or not). Do not catch it and
     do not convert it into "no box": W5-10b relies on `is_io_failure()` to keep disk errors visible. `Ok(None)`/short list means "malformed", never an error.
  7. **Only the payload fields of the parent are read.** `parent.box_type`, `offset`, `total_size` and `uuid` are ignored (golden `parent-fields-ignored-except-payload`); do not "validate" the parent.
  8. **Cap.** `MAX_CHILD_BOXES` bounds the returned children, not the top-level siblings: W5-10b loops over top-level boxes with `try_read_box` and bounds that loop with the header budget
     (`Cr3BmffBudgetAndStblGapTests`), not with this constant. Do not apply the cap in `try_read_box`.
  9. **No allocation proportional to input claims**: start with `Vec::new()`; at most 256 boxes of ~64 bytes are ever built.
  10. **`BmffBox` value semantics.** `Clone`, `PartialEq`, `Eq`, `Hash` derive; `uuid: Option<[u8;16]>` compares by content (C# compared the array reference; every C# caller uses `SequenceEqual`).
      `BmffBox::new` is the C# constructor with its `uuid = null` default.
- Traps checklist: §7 items 3 (every sum/difference on `i64` offsets: use the forms above; a plain `+` on a hostile `payload_size = i64::MAX` panics in debug), 8 (`container_end` `None` vs `Some(0)`:
  C# default `-1` vs a real 0), 9 (each `return false` is its own `Ok(None)`; do not merge them with the `Err` path), 10 (children keep file order: `Vec`).
  INV-8: header reads only, never the payload, never more than the three reads per header.
  Parsers must never panic on malformed input: the golden includes `i64::MIN`/`i64::MAX` fields, a 4 GiB-1 size and `u64::MAX` largesize.

## Open questions
1. **`container_end` type.** The stub uses `Option<i64>` and maps any negative `Some` to "unspecified", like C# `containerEnd >= 0`. Alternative: keep `i64` with the `-1` sentinel for a 1:1
   signature. `Option` is recommended (the sentinel is a trap, see Traps 8); the golden is written so either passes (`container_end` absent or negative = unspecified).
2. **Error type.** The stub is written against W5-01b's `RawHeaderError` / `RawHeaderSource::read(&mut self, offset: i64, count: i32)`. W5-01a's draft `formats.rs` also defines a `RawHeaderError`
   (struct with `RawHeaderCause`) and W5-02b's shim uses `count: usize`. If the lead keeps W5-01a's type instead, only the `use` line and the `Err` plumbing change; no logic does.
3. **`box_type` as `String`.** A `[u8; 4]` would avoid an allocation per box (at most ~260 per file); `String` keeps `box.box_type == "moov"` readable in W5-10b and in the golden. Chosen: `String`.
4. **Reading via `&mut dyn RawHeaderSource`** (not generic): matches `RawContainerReader::read(&self, source: &mut dyn RawHeaderSource, ..)` of W5-01b, so W5-10b passes its parameter straight through.
