## Semantics notes
1. **`recycle`** (lines 118 to 136): (a) `source = compare_selected.or(current)`; (b) `refuse_recycle_without_bin(source)` FIRST (before "confirm before delete": the answer would not matter); (c) `selected_group` = the capture group of `source`
   in the catalog; (d) `permanent_prompt = selected_group.is_none() && will_ask_permanent_delete(source)`; (e) generic confirmation only when `selected_group.is_none() && settings.confirm_before_delete && dialog_service.is_some() && !permanent_prompt`:
   `folder_before = clock.current_folder()`, `show_confirmation(DialogConfirmActionTitle, DialogConfirmActionMessage(ActionRecycleName))`; declined -> `Done(Finished{false})`; after it: folder changed OR executor busy OR the source left
   the catalog -> `Done(Finished{false})` silently (R7-4). (f) core with `Recycle` and the localized name.
2. **`refuse_recycle_without_bin(source)`** (lines 162 to 176): false when `source` is empty/None, no executor, catalog empty, or `allow_permanent_delete_without_recycle_bin` is on (the permanent prompt handles it).
   Else the paths = the capture's `paths()` or `[source]`; the first one with `lacks_recycle_bin` -> status `core.recycle.unsupportedDrive` (`name` = file name), error dialog `dialog.recycleNoBin.title` /
   `dialog.recycleNoBin.message` (`fileName`, `settingName` = `settings.allowPermanentDelete.label`, `settingsPage` = `settings.nav.files`), `sink.notify_navigation_state_changed()`, returns true. Nothing else changes.
3. **`will_ask_permanent_delete(source)`**: source non-empty AND setting on AND executor present AND `lacks_recycle_bin(source)`.
4. **`will_ask_group_confirmation(operation, compare, source)`** (lines 143 to 152): false without source/executor/file system or without a capture group; true for Recycle or Move started from a Compare selection
   (the C# expression `compareSelectedPath is not null && operation is Recycle or Move` has pattern precedence `is (Recycle or Move)`); false for non-Recycle; for Recycle: `confirm_before_delete ||
   (allow_permanent && any member lacks a bin)`. Keep in step with `prepare_core`.
5. **`prepare_core`** (lines 207 to 276), in this order: reset `last_partner_missing_warning` and `present = None`; catalog empty -> Refused; no executor -> Refused; executor `is_busy()` -> Refused (INV-4);
   source empty -> Refused; `selected_group` present but no file system -> Refused; single-file permanent prompt (`operation == Recycle`, no group, `will_ask_permanent_delete`): no dialog service -> Refused (nothing is deleted without a confirmation);
   `show_confirmation(DialogConfirmPermanentDeleteTitle, DialogConfirmPermanentDeleteMessage(fileName))` declined -> Refused; re-check (folder, busy, in catalog) -> Refused; `allow_permanent = true`.
   Group prompt (lines 239 to 267): `permanent_group_paths` = members lacking a bin, only for Recycle with a group and the setting on; `from_compare_group` = compare selection AND group AND (Recycle OR Move)
   (same precedence note); prompt when a group exists AND ((Recycle AND (`confirm_before_delete` OR permanent members)) OR `from_compare_group`); message by priority: permanent members ->
   `dialog.confirmGroupPermanentDelete.message` (`permanentCount`, `count`, `fileName`); compare group -> `dialog.confirmCompareGroupMove/Recycle.message` (`fileName`, `files` = member names joined ", ");
   else `dialog.confirmGroupRecycle.message` (`count`, `fileName`); title = `dialog.confirmPermanentDelete.title` for permanent members else `dialog.confirmAction.title`; no dialog service or declined -> Refused;
   re-check -> Refused; `allow_permanent = Recycle && permanent members exist` (so a generic group prompt NEVER grants permanent delete: test `..AfterTheGenericGroupPrompt_StaysNonPermanent`).
   Finally the group is re-read; `group != selected_group` (equality of `CaptureGroup`) -> status `status.groupChangedDuringConfirm(fileName)` and Refused.
6. **Entry point result.** `Refused` -> `Done(Finished{false})`. `Ready(p)` -> `execute_core(cx, p, AfterCore::Nothing)` (07d) which returns `Pending`.

## Traps checklist (concrete)
- **INV-3 / F-07** is in 07d, but the precondition here is: nothing may leave the catalog, no `stop_for_action`, no `preload.cancel()` in a refused path; assert "catalog and generation unchanged" in every Refused test.
- **INV-4**: `is_busy()` is read before the prompts AND again after each prompt (R7-4). The gate itself is the caller's.
- **R7-4**: each dialog runs a nested loop (a forwarded open can switch the folder); after EVERY dialog re-check `clock.current_folder() == folder_before`, `!is_busy`, `catalog.index_of(source) >= 0`.
  Group dialogs additionally compare the group again (step 5 end). Use `pr_core::text::eq_ignore_case` for path comparisons; `catalog.index_of` is already case-insensitive.
- **Q-R8**: `allow_permanent_delete` in the request is true ONLY after an explicit permanent confirmation (single) or when permanent members were named in the prompt (group). With the setting off the request stays
  false and the service refuses BEFORE journaling (tests in `RecycleSafetyGap`: a setting that flips between the up-front check and the core must not grant permission; read the setting through `get_settings()` at each use).
- **One prompt, not two**: the generic prompt is skipped when `permanent_prompt` or `will_ask_group_confirmation` holds.
- Compare selection: Delete/Move act on the WHOLE capture; the user is always asked (even with confirm-before-delete off).
- Threading: this unit runs on the UI thread only; the dialog service is `!Send`. Only `IFileActionExecutor` (Send+Sync) crosses to the worker.
- Settings: `AppSettings` is read through `get_settings()` at use time, never cached (R2-F-03).
- No `async`, no `unsafe`, no `windows` crate; all sentences via `TextSource` with the `pr_l10n::keys` listed above (D-W8-4).

## Open questions (each has a recommended default that the stub follows)
- **O1 Catalog/sink per call** (same as 07a O1). Default: `FileActionCx`. Alternative: the controller owns `Box<dyn IFileActionSink>`; rejected (cycle with the view model).
- **O2 Present completion.** `IFileActionSink::present(index)` returns when the request is posted, but the C# code awaits the present at six places (statuses must be written AFTER the presenter's own "Ready", RV-A09, R08).
  Default (used): the shell calls `FileActionController::on_present_finished(cx, faulted)` when the present it started finishes; the continuation parks in `ParkedTail`. No change to B1 stubs. Alternative: change `IFileActionSink::present`
  to return a completion handle (a B1 change). The W8-08x/W8-16 contract writers must implement the callback.
- **O3 `IFileActionExecutor` is not `Send + Sync`** in `coordinators::traits` (no supertraits); the executor runs on a worker, so the stubs ask for `dyn IFileActionExecutor + Send + Sync`. Suggested B1 change (not applied): add `: Send + Sync`
  to the trait; `FileActionServiceExecutor` already satisfies it.
- **O4 `UndoService` sharing.** `UndoService` methods take `&mut self` and the struct is `Send` (assertion in `undo.rs`); the controller holds `Arc<Mutex<UndoService>>` (also used on the file-action lane for `undo_last`). The composition root shares the same `Arc`.
- **O5 Texts.** `TextSource` supplies the current `Localizer`; tests give `built_in_english_localizer()`. Alternative: pass `&Localizer` per call (W8-10c-3 style); rejected here because every entry point and event handler would need it.
- **O6 `FileActionDone::Canceled`.** C# lets `OperationCanceledException` escape; Rust reports it as a step result. The caller decides (W8-08x). No state is restored for a cancelled executor (as C#).
- **O7 Plan line ranges** are approximate (D-07c-1); the brief's module list wins.
