## Semantics notes
1. **Line split.** Split ONLY at `\n`; a line's bytes include its `\n`; a final line without `\n` is a line (C# `IndexOf('\n') < 0`
   => rest of the snapshot). `line_content`: strip one trailing `\n`, then one trailing `\r` (`x\r\r\n` -> `x\r`: an INNER `\r`, golden
   `double-cr-before-lf-is-inner-cr`; final `x\r` without `\n` -> `x`, golden `final-unterminated-cr-only-line`).
2. **Blank** = content trimmed of `' '`, `'\t'`, `'\r'` only (C# `Trim(" \t\r"u8)`) is empty. `\x0C`, `\x0B`, NBSP, NUL are NOT blank
   and not entries => kept (golden `other-whitespace-is-not-blank`). Blank lines are dropped and counted in `dropped_lines`.
3. **Recognized entry** = not blank AND no `\r` anywhere in content AND `journal_line::try_parse_utf8(content)` is `Some`. Everything
   else non-blank is kept verbatim: malformed JSON, unknown `Type`/`State` text from a newer build, missing Id, invalid UTF-8, a UTF-8 BOM
   before `{`, a quarantined group line (blank member Source). Such lines also never become an Id's latest line, so a superseded line
   before an unrecognized "newer" line IS dropped when the recognized latest is Committed (golden `unknown-state-from-newer-build-...`,
   `invalid-utf8-superseding-line-not-latest`).
4. **Latest per Id** (ordinal, case-sensitive key: `a` and `A` are two Ids). In file order, an entry replaces the Id's latest unless
   `is_stale_reconcile_after_committed(entry, Some(&current_latest))`: Failed + code exactly `PendingUnconfirmed` or
   `SourceStillExistsAfterRecovery` after a Committed latest. Two stale verdicts in a row are both skipped. A reconcile Failed after
   Prepared/Dismissed/Failed IS the latest. `RetryVerifyFailed` or no code after Committed IS the latest (nothing of that Id dropped).
5. **Window.** From the LAST line backwards over ALL lines (blank and unrecognized included), collect the indices whose `line_content`
   passes `journal_rules::try_parse_tail_committed_move` until 200 are collected. Uses raw content, so an inner-`\r` committed Move takes a slot
   (not droppable anyway, but it pushes an older one out: golden `window-inner-cr-line-takes-a-slot`). A line holding the exact bytes
   `"Type":"Copy"` / `"Type":"Recycle"` anywhere is never in the window (even a Move with such a nested member), but `"Type": "Copy"`
   (with a space) does not trigger the shortcut. Latest Committed Moves also take slots (`window-latest-committed-moves-take-slots`).
6. **Evidence** (W2-FA-04). Per Id: the index of the LAST recognized entry with `group_members == Some(v)` and `!v.is_empty()`. It is
   evidence when the Id's latest has `group_members` `None` OR `Some(empty)` and latest state != Dismissed. `Some(empty)` on the earlier line
   is not a members line (`evidence-empty-member-list-is-not-evidence`). The evidence line may be AFTER the latest (a stale reconcile line):
   then it is kept anyway because `i > L_index`.
7. **Droppable(i)** = blank, or (recognized AND latest(id).state in {Committed, Dismissed} AND `i < L_index` AND not window AND not evidence).
   `i == L_index` is never dropped; lines of the Id after L are kept. Duplicate identical Prepared lines before a Committed are both dropped.
8. **Output.** `kept` = concatenation of the kept lines' ORIGINAL bytes (terminators included, CRLF/LF/none preserved, never re-encoded);
   `kept_lines + dropped_lines` = number of lines; empty snapshot => `default()`. Pre-size `kept` with `Vec::with_capacity(snapshot.len())`
   (C# `new MemoryStream(snapshot.Length)`; AGENTS.md priority 2). Single parse per line: keep `Vec<Option<JournalEntry>>`, do not re-parse
   in the drop pass. The window pass DOES call the tail predicate (which parses again) on lines from the end, like C#; it stops after 200 hits.
9. **`open_read_deny_writers`.** Blank path (`ThrowIfNullOrWhiteSpace`) => `InvalidInput`. Share `READ | DELETE`, `FILE_FLAG_SEQUENTIAL_SCAN`,
   read access, `OPEN_EXISTING`; `BufReader::with_capacity(65536, file)` boxed as `ReadSeek`. Errors UNWRAPPED (`raw_os_error` 32 when an
   appender holds the file: W3-01 maps 32/33 to `Busy`; 2 when missing).
10. **`create_staged_replacement`.** Order: blank => `InvalidInput`; not Windows => `Unsupported` + `NOT_WINDOWS_MESSAGE`;
    `full = dotnet_path::get_full_path(temp)` (through `io::physical::full_path`: `Argument` => `InvalidInput`, `TooLong` => raw 206); open
    `write(true)`, `create_new(true)`, `access_mode(GENERIC_WRITE | DELETE)`, `share_mode(FILE_SHARE_READ)`, `attributes(0x80)`;
    failure => `CompactionFileError::new("Could not create the journal compaction file " + full, os_err).into_io_error()` (same kind,
    `to_string()` = the message, `os_error_code` = 80 for an existing file). An existing file is never truncated or deleted (no Drop ran).
    Open the plain `full` (std adds the extended prefix only for long paths, Open question 4); std ORs `FILE_FLAG_OPEN_REPARSE_POINT`
    into a `create_new` open (no observable difference: `CREATE_NEW` fails on any existing name, link or not).
11. **`PhysicalStagedReplacement`.** `write` = `BufWriter::write_all`; `flush_to_disk` = `flush()` then `sync_all()`; `replace_atomically`:
    blank => `InvalidInput` (before flushing); flush_to_disk (error propagates unwrapped); `name = get_full_path(destination)` (plain, no
    `\\?\`); FILE_RENAME_INFO in a zeroed `Vec<u64>` buffer: Flags u32 at 0 = `0x1 | 0x2`, RootDirectory null at `size_of::<usize>()`,
    FileNameLength u32 (BYTES, `2 * utf16_len`) at `2 * size_of::<usize>()`, name units at `2 * size_of::<usize>() + 4`, buffer size =
    name offset + name bytes + 2; `SetFileInformationByHandle(handle, 22, buf, size)`; `0` => `CompactionFileError("Could not replace " +
    name + " with the compacted journal", last_os_error)`; success => `replaced = true`. `// SAFETY:` comments on the FFI call and on the
    raw-pointer writes (or build the buffer with safe `to_ne_bytes` copies into a `Vec<u8>` then copy into the aligned `Vec<u64>`).
12. **Drop** (C# `Dispose`): take the writer, flush ignoring the error, close the file (drop it) BEFORE deleting; if `replaced` return;
    else delete `path` like .NET `File.Delete` (`DeleteFileW`), ignoring every error. Never panics, never deletes after a successful rename
    (the file is then the journal). C# `ObjectDisposedException` after Dispose cannot happen in Rust (ownership): no test.

## Traps checklist
- §7.3 counts are `usize` (C# `int`, < 2^31 lines); no arithmetic beyond indices.
- §7.7 `get_full_path` for the temp path and the rename target (C# `Path.GetFullPath`), not `std::path::absolute`.
- §7.8 `group_members`: `None` vs `Some(vec![])` matter in both directions (notes 6).
- §7.9 Drop: the flush error and the delete error are swallowed separately (two C# `catch` blocks); nothing else is caught.
- §7.10 `HashMap`/`HashSet` are fine for latest/window/evidence ONLY because output order comes from the line index loop; never iterate a
  map to build output.
- T1 (INV-6 / D-03) never re-serialize a kept line; compare bytes in tests (`assert_eq!(plan.kept, expected_bytes)`).
- T2 a line with an inner `\r` is NOT recognized (`ReadEntries` would split it), but IS seen by the window predicate (note 5).
- T3 FA-01 is skipped only after a COMMITTED latest; read the latest through the same map the drop pass uses.
- T4 evidence is the LAST members line, not the first; and not for Dismissed.
- T5 the staged file shares Read only: tests and W3-01 must drop it before reopening the renamed target (C# comment in the test).
- T6 `std::fs::remove_file` deletes read-only files on Windows; .NET `File.Delete` does not. Use `DeleteFileW` (Open question 1).
- T7 Recycle Bin: nothing here touches it; native tests only create/delete files under their own `TempRoot`.
- Mutation gate (Wave 3): `cargo-mutants` on `file_actions::compaction` must leave no live mutant; the goldens plus the evidence/window
  cases are designed for that (e.g. `<` vs `<=` on `L_index`, `Count < 200`, trim set, `\r` check).
