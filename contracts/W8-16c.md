## Semantics (C# is the spec)
1. **Order and ownership.** Draw order, bottom to top: main image, crossfade layer, compare panel (the XAML order). The canvas is cleared by the caller (the window). The composer is the OWNER of `current`/`pending`; `current` is "the bitmap the layout measured with" (13j re-measures on `CurrentChanged`).
2. **`set_incoming`** (C# 124-147), in this order: `Err(Disposed)` if disposed; `pending = None` (ALWAYS, also on the immediate-replace paths); replace `current` and return `Ok(true)` when `image` is `None`, or `is_file_change`, or `current` is `None` or disposed, or `image` is disposed, or `i64(width) * i64(height) * 4 < defer_upload_bytes` (the C# `(long)` casts; no overflow). Otherwise it is a same-image upgrade: `cache.prefetch(&image)` (an `Err` becomes `ComposerError::Render` and nothing else changed except `pending = None`); if `cache.is_fully_uploaded(image.id())` -> `current = image`, `Ok(true)` (no `CurrentChanged`: the caller sees `true`); else `pending = image`, `pending_since = now()`, `pending_token += 1`, schedule the deadline with that token, `Ok(false)`.
3. **Deadline and promotion.** `arm_pending_deadline(token)`: `schedule_on_ui(Duration::from_millis(MAX_DEFER_MS), job)`; the job (on the UI thread) does nothing when disposed, `pending` is `None` or `token != pending_token`; else `try_promote_pending()` and, when it promoted, `invalidate()`. `try_promote_pending`: `pending` None -> false; disposed pending -> `pending = None`, false; `waited = now() - pending_since`; not fully uploaded and `waited < MAX_DEFER_MS * ticks_per_second / 1000` (i64, saturating) -> false; else `current = pending`, `pending = None`, `promotion_count += 1`, raise `CurrentChanged`, true. `CurrentChanged` handlers run on a snapshot, no state borrow held (D-W8B4V-9).
4. **`UploadCompleted`**: the handler registered in `new` ignores the event when disposed, `pending` is None, or `pending.id() != id` (an older upgrade finishing first is NOT promoted over the newer pending one); otherwise `try_promote_pending()` and `invalidate()` when it promoted.
5. **Crossfade**: `begin_crossfade(d)` -> `Err(Disposed)` if disposed; `last_drawn()` None -> `Ok(false)`; else `crossfade.start(buffer, frame, interpolation, d)` (its `Ok(false)` is returned as is). `LastDrawn` is the frame that was actually DRAWN (`has_last_drawn` set only when `try_draw` returned true), so a navigation request before the new image was ever drawn freezes nothing new and the running fade keeps showing what the user saw. `cancel_crossfade` = `crossfade.cancel()`. `collect_retained_ids`: `current` and `pending` when not disposed, plus `crossfade.outgoing_buffer_id()`.
6. **`draw`** (C# 224-275): `interpolation = from_scaling_quality(effective_quality)`; `viewport_rect = (0, 0, viewport.width, viewport.height)`. When `current` is `Some` and not disposed: `now = now()`; `moved = id == last_drawn_id && has_last_drawn && last_drawn_rect != destination` (`RectD` equality is NaN-aware); if moved `last_motion_ticks = now`; `in_motion = now - last_motion_ticks < settle_ticks` (saturating); `dpi = if dpi_scale > 0 { dpi_scale } else { 1.0 }` (NaN gives 1.0: `NaN > 0` is false); `choose(requested, width, height, dest.width * dpi, dest.height * dpi, in_motion)`; `degraded = chosen != requested`; `push_clip(viewport_rect)`; `try_draw(cache, ctx, &pixels, destination, chosen, 1.0, 1)`; `pop_clip()` (always); on success of the draw `last_drawn_* = (id, destination, chosen)`, `has_last_drawn = true`. Then `set_settle_armed(degraded)` (also when nothing was drawn: unarms), then `crossfade.draw(cache, ctx, viewport_rect)`, then, when `compare_visible`, `compare::draw(cache, ctx, viewport, &compare, from_scaling_quality(compare_quality))` else 0. The compare cells use the setting, NOT the forced HQ of Refresh.
7. **Settle clock.** `set_settle_armed(armed)`: no change when equal or (`disposed && armed`); arming subscribes ONE frame handler (a `Weak` upgrade) and calls `clock.request_frame()`; disarming unsubscribes. The handler: `now() - last_motion_ticks < settle_ticks` -> `clock.request_frame()` (keep polling), else `invalidate()` (one more frame; `draw` chooses the requested filter again and unarms). Exactly `settle_ms` after the last motion the handler stops waiting (`119` ms no, `120` ms yes). `settle_ticks = max(0, settle_ms) * ticks_per_second / 1000`.
8. **Errors in `draw`** behave like the C# exception: nothing after the failing step runs (the settle state is not updated, no crossfade, no compare), the clips pushed by this call are popped first. The host logs and skips the frame.
9. **`dispose`**: idempotent; unsubscribes `UploadCompleted`, disarms the settle clock, `crossfade.dispose()`, `pending = None`, `current = None`. `set_incoming` and `begin_crossfade` afterwards are `Err(Disposed)`; `draw` still works and draws nothing (current None), `crossfade()` stays usable but empty.
10. **Time base**: `timestamp` is QPC ticks (`qpc_now`) and `ticks_per_second` its frequency (`qpc_frequency()` when `<= 0`); the SAME domain as `HostFrameTick::timestamp` and the crossfade animator. Keep-warm ticks are another clock (nanoseconds, D-W8B3S-8) and never mix with these.
11. **GPU keys**: the composer never sees a path; every bitmap is the cache entry of `PixelBuffer::id()` (INV-1). The id of a buffer is stable, the buffers of two files never share one, so "which image is on screen" can only be wrong through a state bug, which the stale-order tests hunt.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (INV-1 + upgrade race): a stale upload completion or a stale deadline must never promote an older buffer (the token and the `pending.id()` check are BOTH needed: the token guards a re-armed pending of the same id, the id guards a different buffer).
- T2 (re-entrancy): `invalidate`, `clock.*`, `cache.*` and the `CurrentChanged` handlers run while the composer's own state is NOT borrowed; `cache.prefetch` may raise `UploadCompleted` synchronously for a tiny image (the cache raises it after releasing its borrow) which re-enters `on_upload_completed` while `set_incoming` is mid-way: set `pending` BEFORE the first call that can raise it, or re-check after `prefetch` (the C# order is prefetch, then `IsFullyUploaded`, then set `_pending`, so an event inside `Prefetch` sees `_pending == null` and is ignored; the Rust order must produce the same observable result; test it).
- T3 (arithmetic, section 7 item 3): `now - last_motion_ticks` with `last_motion_ticks = i64::MIN / 2`; use `saturating_sub`; `MAX_DEFER_MS * tps / 1000` and `width * height * 4` in `i64` with `saturating_mul`.
- T4 (`f64` rects): `last_drawn_rect != destination` uses the NaN-aware `RectD` equality (a NaN destination always counts as moved only if the stored one is not also NaN).
- T5 (clip balance): `push_clip(viewport)` / `pop_clip()` around the main draw on every path, including `Err`.
- T6 (settle subscription leak): disarm before dispose; the handler holds a `Weak`; `dispose` leaves `clock` with 0 subscribers (test `Dispose_StopsListening...`).
- T7 (not a timer): `schedule_on_ui` is a host service; the composer never sleeps, spawns or reads a clock for scheduling. The F tests collect `(delay, job)` pairs and run them by hand.
- T8 (`Arc` lifetime, D-W8B4V-12): the composer holds up to three strong buffers (`current`, `pending`, the outgoing crossfade image) plus the frozen `last_drawn` reference through `current`; they are released on replace / promote / dispose, never leaked past `dispose`.

## Open questions (recommended default in bold)
1. **`ScheduleOnUi` provider** (D-W8B4V-4). The composer needs "run this closure on the UI thread after 1 s". `UiAction` is `Send`, the closure reaches an `Rc`, so the host must keep the closure in a UI-thread queue and post a `Send` wake job; a timer thread (or `SetTimer` on the message window) supplies the delay. Cross-unit assumption on **W8-13j**: it builds this closure for the composer and the prefetcher. Recommended: one small shared helper (a thread-local queue of `Box<dyn FnOnce()>` plus `Win32UiDispatcher::post_with_priority` of a `Send` job that pops one) lives with 13j; alternative: 13d grows a `post_local` (merged unit, lead action).
2. `Rc<dyn PrefetchStatus>` as the cache type: **yes** (the 12g adapter implements it); alternative: the concrete `D2dGpuImageCache<D>` (rejected: generic over the device, un-fakeable).
3. `draw` returns `Result<ComposedFrame, RenderError>`: **yes**; alternative: log and return a default frame (rejected: hides the error from the frame loop).
4. `invalidate` as `Rc<dyn Fn()>`: **yes** (shared with the crossfade layer).
5. Where `PromotionCount`'s `i32` could overflow: not reachable (one per navigation); **plain `i32`**.
