## Semantics notes (C# line numbers refer to UndoService.cs at d92d6aae)

1. **Gate (INV-4, l.72-99).** With a shared gate (`with_gate`) every gate call forwards to it; otherwise the own `AtomicBool`:
   `try_begin` = `compare_exchange(false, true, SeqCst, SeqCst).is_ok()`, `end` = `store(false)`, `is_busy` = `load`. Every path that took
   the gate releases it exactly once, also on panic: hold a `GateHold` (stub) from `begin_hold()` for the whole undo.
2. **`register` (l.104-120).** Ignore unless `succeeded && !rejected`. Move with `destination_path` `Some` and NON-EMPTY: push
   `(source, destination)`, set `move_fingerprints[ignore_case_key(destination)] = (size, last_write_utc)` (overwrites), set the last action
   to a new single Move record. Recycle: last action = new single Recycle record with `permanent = permanently_deleted`, `destination None`
   (no history, no fingerprint). Anything else (Copy, Move without destination): nothing changes (the previous last action stays).
   `register` never touches the partial-undo memory.
3. **`register_group` (l.122-148).** `rejected` => return. `succeeded`: members = `entry.group_members` when `entry` is `Some` and the list
   is non-empty, else return. Not succeeded and Recycle: members = the `member` of every `completed` member result, in order; none => return.
   Not succeeded and not Recycle => return. Then ONLY for Move or Recycle (a succeeded Copy group changes nothing, the previous action stays):
   last action = new group record with `source = entry.source` (else `members[0].source`), `destination = entry.destination` **falling back to
   `members[0].destination` when the entry's destination is `None`** (C# `??` on a nullable member), `size`/`last_write_utc` likewise from
   the entry else `members[0]` (`last_write_utc.value`), `permanent = (Recycle && every member permanent)`, `group_members = members`,
   `failed_entry = (!succeeded && entry is Some && entry.state == Failed && entry members non-empty) ? entry : None`,
   `current_failed_entry = failed_entry`.
4. **`undo_move` (l.153-296).** Busy => `UndoResult{succeeded:false, operation:Some(Move), source:"", destination:None,
   error: core_undo_busy, rejected:true}`. Empty history => `(false, Some(Move), "", None, core_undo_no_move_to_undo)` (not rejected).
   Else pop the top `(source, destination)` and run, with `permanently_broken = false`, `move_returned = false`, any failure being an
   `io::Error` `ex` caught at the end:
   4.1 destination missing (`file_exists`) => `permanently_broken = true`, fail `core_undo_source_or_destination_changed`. Source exists =>
       fail with the same text (NOT broken).
   4.2 `dest_stat = get_file_stat(destination)` (read BEFORE the fingerprint lookup). Fingerprint: `move_fingerprints[key(destination)]`;
       missing => `journal.read_committed_moves()?` and take the LAST entry whose destination equals `destination` OrdinalIgnoreCase
       (`None` => fail `core_undo_fingerprint_missing`); cache it in the map.
   4.3 `dest_stat` `None` or `!matches_moved_destination(&dest_stat, fp.size, fp.last_write_utc)` (±2 s inclusive, RV-C01) => fail
       `core_undo_destination_changed_after_move`.
   4.4 Journal (INV-6): Prepared entry `{id: new_guid_n(), Move, Prepared, source: destination, destination: Some(source), size: fp.size,
       last_write_utc: JournalDateTime::utc(dest_stat.last_write_utc) (the stamp AS IT IS NOW, not the fingerprint's), timestamp: clock,
       undo: Some(true), everything else None}` through a non-retry `JournalTransaction` (`retry_of: None`). The C# inner `try` starts
       BEFORE `begin()`: a failed Prepared append also goes through `tx.fail` (which then writes nothing and returns `(None, None)`,
       because the transaction is not prepared) and then reaches 4.5. Inside the inner `try`, after `begin()`:
       re-stat the destination (R18): `None`, other length or other EXACT write time than `dest_stat` => fail
       `core_undo_destination_changed_after_move`; `create_directory(get_directory_name(source))` when that is `Some` and non-empty (RV-C07);
       reverse move `(destination -> source)` via the move override if any, else `file_system.move_file`; `move_returned = true`;
       `tx.verify_moved(fs, destination, source, VERIFY_SIZE_CHANGED)` (source-still-there => `MoveSourceNotRemoved`, size => `VerifySizeChanged`).
       Any failure inside => `tx.fail(&err)` (ignore its result) and propagate. Success => `tx.commit()` (a failed Committed append does
       NOT fail the undo), remove the fingerprint of `destination`, and clear the last action ONLY when it is a single Move
       (`group_members None`) with source AND destination equal OrdinalIgnoreCase (RV-C06); return `(true, Some(Move), source,
       Some(destination), None)`.
   4.5 Failure (anything from 4.1-4.4, also a failed Prepared append): if `move_returned && !permanently_broken && file_exists(source) &&
       !file_exists(destination)` => `permanently_broken = true`. Broken => remove the fingerprint and clear the last action when it is ANY
       Move record (group included: asymmetric with 4.4) whose destination equals `destination` OrdinalIgnoreCase; not broken => push the
       entry back. Return `(false, Some(Move), source, Some(destination), core_undo_failed(&ex.to_string()))`.
5. **`undo_last` (l.312-389).** `is_busy()` => `(false, None, "", None, core_undo_busy, rejected:true)` BEFORE reading any state (also for a
   permanent Recycle or an empty undo). No last action => `(false, None, "", None, core_undo_nothing_to_undo)`. Move with non-empty members
   => group Move (8); other Move => `undo_move()` (it pops the TOP of the history, which may not be the last action). Recycle with members
   => group Recycle (9). Single Recycle: `permanent` => clear the last action, `(false, Some(Recycle), source, None,
   core_undo_permanently_deleted(get_file_name(source)))` (no gate, no bin call). Else take the gate (busy => rejected Recycle result with the
   source); `file_exists(source)` => `core_undo_recycle_target_exists(file name)` and KEEP the action; `recycle_bin.try_restore(source,
   u64::try_from(size).unwrap_or(0), last_write_utc)` and IGNORE its verdict (R18): success only when `get_file_stat(source)` has length == size AND write time
   EXACTLY equal; then clear the action and return `(true, Some(Recycle), source, None, None)`; otherwise `core_undo_recycle_restore_failed(file
   name)` and keep the action (Q1: C# reports `core_undo_failed(fault message)` when the bin threw). Single Recycle is NOT journaled.
   A record whose operation is neither Move nor Recycle => `(false, Some(op), source, None, core_undo_unsupported)` (unreachable:
   `register`/`register_group` only ever store Move or Recycle records; keep the branch for parity, no test can reach it).
6. **Results never carry a journal error;** `UndoResult` has no such field. A failed Prepared append makes the undo fail with the append's
   message; failed Committed/settle/resolve appends are swallowed.
7. **Partial-undo memory (l.492-523).** `remember_partial_undo(action, restored_by_this_undo, failed_entry)`: `earlier` = the memory when it
   belongs to `action` (`Arc::ptr_eq`); `restored_by_this_undo == 0 && earlier is None` => return (nothing remembered); else memory =
   `{action, earlier entries ++ [failed_entry if Some]}`. `resolve_partial_undo(action)`: take (clear) the memory ALWAYS; return false unless
   it belonged to `action`; for each remembered Failed line, oldest first: `committed = failed with {state: Committed, timestamp: clock,
   error: None, error_code: None}`, `journal.append_if_unchanged_since(&failed, &[], &committed)`, result and any error ignored; return true.
8. **Group Move (l.391-490).** Busy => rejected `(false, Some(Move), action.source, action.destination, busy)`. `restored: Vec<String>`
   (original paths back, in discovery order), `restored_by_this_undo = 0`, `tx = None`.
   - Undo members (in member order, ALL built first: C# `Select(..).ToArray()` runs before the preflight loop): `{source:
     member.destination (None on ANY member => fail core_undo_source_or_destination_changed before any I/O at all, `tx` still None,
     `restored` empty; golden `group-move-member-without-destination`), destination: Some(member.source), size, last_write_utc: member.last_write_utc, permanent: false}`.
   - Preflight per member (`s` = stat of the moved file at undo.source, `d` = stat of the original path): both `Some` => fail
     `source_or_destination_changed`; `s None && d Some && matches_moved_destination(d, size, stamp)` => already back: push the original path
     to `restored`, continue; `s None || d Some || !matches_moved_destination(s, size, stamp)` => fail `destination_changed_after_move`;
     else replace that undo member's `last_write_utc` with `JournalDateTime::utc(s.last_write_utc)` and add it to `pending`.
   - `pending` empty: `resumed = resolve_partial_undo(action)`; `drop_group_undo(members)` (fingerprints of every member destination +
     last action); resumed => `(true, Some(Move), action.source, action.destination, None, restored_paths: Some(all member sources in member
     order))`; else fail `core_recovery_already_handled` (goes through the failure path below).
   - Prepared: `{new_guid_n(), Move, Prepared, undo_members[0].source, undo_members[0].destination, undo_members[0].size,
     undo_members[0].last_write_utc, clock, undo: Some(true), group_id: Some(new_guid_n()), group_members: Some(ALL undo members)}` (Id
     generated before GroupId); `begin()`.
   - R18: re-stat EVERY pending member before the first move (length == size AND write time EXACTLY equal to the journaled one, else fail
     `destination_changed_after_move`), then per pending member again right before its move; `create_directory(dir of member original)`;
     move (override or `move_file`); verify `file_exists(moved path) || stat(original)` missing or of another length than `size` => coded `VERIFY_SIZE_CHANGED` (even
     when the moved file is still there: NOT `MoveSourceNotRemoved`); push to `restored`, `restored_by_this_undo += 1`.
   - Success: `mark_mutation_completed`, `commit` (ignore errors), `resolve_partial_undo(action)`, `drop_group_undo(members)`, result as in the
     resumed case (ALL member sources, member order).
   - Failure (any error `ex`, including already-handled): `failed = tx.as_mut().and_then(|tx| tx.fail(&ex).0)` FIRST (C# `tx?.Fail(ex, out _)`;
     the entry is `Some` only when the Failed line really reached the journal), then `remember_partial_undo(action,
     restored_by_this_undo, failed)`; return `(false, Some(Move), action.source, action.destination, core_undo_failed(ex), restored_paths:
     restored non-empty ? Some(restored in DISCOVERY order) : None)`. The last action stays unless it was dropped above.
9. **Group Recycle (l.588-682).** `permanent` => clear, `(false, Some(Recycle), source, None, core_undo_permanently_deleted(file name of
   action.source))` with no gate. Busy => rejected. Preflight per member: `permanent` => `unrecoverable`; stat `None` => `pending`; stat with
   other length or other EXACT write time => fail `core_undo_recycle_target_exists(file name of member)`; else already back => `restored`.
   - `pending` empty: clear the last action FIRST; `resolve_partial_undo` true => `settle_failed_delete_line(action, restored)` and
     `(true, Some(Recycle), source, None, unrecoverable_note(..), restored_paths: Some(restored_in_order(..)))`; false => fail
     `core_recovery_already_handled` (the failure path settles when `restored` is non-empty).
   - Prepared: `{new_guid_n(), Recycle, Prepared, undo_members[0].source, None, size, last_write_utc, clock, undo: Some(true), group_id:
     Some(new_guid_n()), group_members: Some(every NON-permanent member, unchanged)}` (already-back members included); `begin()`.
   - Per pending member, in order: `try_restore(source, u64::try_from(size).unwrap_or(0), stamp.value)` false => fail `core_undo_recycle_restore_failed(file
     name)`; then stat must be length == size AND exact write time, else the same failure; push, `restored_by_this_undo += 1`.
   - Success: `mark_mutation_completed`, `commit`, `resolve_partial_undo`, `settle_failed_delete_line(action, &restored)`, clear the last
     action, `(true, Some(Recycle), source, None, unrecoverable_note, Some(restored_in_order))`.
   - Failure: `tx.fail` first, `remember_partial_undo`, then `restored` non-empty => `settle_failed_delete_line`; return `(false,
     Some(Recycle), source, None, core_undo_failed(ex), restored non-empty ? Some(restored in DISCOVERY order) : None)`.
10. **Settling a part-way group Delete (l.531-573), best effort, never fails the undo (swallow every `io::Error`).**
    `anchor = current_failed_entry` must be `Some` with state Failed, else return. `try_settle_from(anchor)` true => return. Else
    `latest = journal.read_latest_entry(&anchor.id)?`; continue only when latest is Failed with non-empty members AND `latest != anchor`
    (structural `JournalEntry` equality) AND the action's ORIGINAL `failed_entry` has non-empty members AND every latest member source is
    one of the original member sources (OrdinalIgnoreCase); then `try_settle_from(latest)`.
    `try_settle_from(anchor)`: members of anchor empty/None => false. `remaining` = anchor members whose source is NOT in `restored`
    (OrdinalIgnoreCase), order kept. Replacement: none remaining => `anchor with {state: Dismissed, timestamp: clock, error: None,
    error_code: None}` (other fields kept); else `anchor with {timestamp: clock, source/destination/size/last_write_utc of remaining[0],
    group_members: remaining}` (state Failed and error/error_code KEPT; appended even when nothing was removed). Append with
    `append_if_unchanged_since(anchor, &[], &replacement)?`; true => `action.set_current_failed_entry(replacement)`.
11. **`restored_in_order` / `unrecoverable_note` (l.684-692):** member sources contained in `restored` (OrdinalIgnoreCase), MEMBER order, as the
    member spells them. Note: `None` when `unrecoverable` is empty, else `core_undo_group_partially_restored(restored_in_order.len(),
    members.len(), file names of the unrecoverable members joined with ", ")`. The note is the `error_message` of a SUCCESS result.
12. **`drop_group_undo` (l.579-586):** remove the fingerprint of every member destination that is `Some`, clear the last action.

## Traps (MULTI-AGENT-PLAN §7 + unit specific)
- §7.1 OrdinalIgnoreCase everywhere a path is compared or keyed: `text::ignore_case_key` for the fingerprint map,
  `text::eq_ignore_case` for comparisons; NEVER `to_lowercase`. Result paths keep the spelling of the record/member, not of the disk.
- §7.3 `size` is `i64`, `FileStat::length` is `u64`, `try_restore` takes `u64`: compare through `i64::try_from(stat.length) == Ok(size)` (as
  `matches_moved_destination` does) and pass `u64::try_from(size).unwrap_or(0)`; never `as` casts that wrap.
- §7.5 Exact write-time equality (`DateTimeUtc ==`, i.e. ticks) in the R18 re-checks and the Recycle proofs, but the ±2 s tolerant
  `matches_moved_destination` in the Move preflights. Mixing them up passes most tests; the golden has 2 s / 2 s + 1 tick / 3 s cases.
- §7.8 `destination_path: Some("")` is NOT undoable; entry destination `None` falls back to the first member's.
- §7.9 Every C# `catch` keeps its own branch: the single-move inner `catch` (fail the tx, rethrow) vs the outer one (broken/push back);
  the group `catch` calls `tx.fail` BEFORE `remember_partial_undo` and the settle (journal line order is in the golden); settle/resolve
  swallow everything; a failed Commit is ignored.
- §7.10 `restored_paths` on FAILURE are in discovery order (already-back members found by the preflight first, then restored ones);
  on SUCCESS in member order (Recycle: `restored_in_order`; Move: all member sources). Golden `group-recycle-failure-reports-restored-in-discovery-order`.
- INV-4: `undo_last` reads `is_busy()` BEFORE any state; the callee takes the gate itself. A panic inside must not leave the gate held.
- INV-6: every mutating undo (single Move, group Move, group Recycle) journals Prepared BEFORE the first mutation and the outcome after;
  `undo: Some(true)`; single Recycle is not journaled (C# design). The Prepared `LastWriteUtc` is the CURRENT stat stamp (single Move) /
  the per-member current stamp (group Move), the Prepared `Size` the fingerprint's.
- Identity of the action is by reference (`Arc::ptr_eq`), not by value: two registrations of equal results are different actions
  (golden `group-move-partial-of-another-action-is-not-resolved`).
- `resolve_partial_undo` clears the memory even when it belongs to another action.
- Ids: `crate::io::physical::new_guid_n()` (32 lowercase hex, as C# `Guid.NewGuid().ToString("N")`); the group undo draws the entry Id first,
  then the GroupId.
- Messages: `core_undo_failed(&err.to_string())`. A coded error's text is its localized message (`JournalCodedError` Display). An OS error's
  Rust text ends in ` (os error N)` where .NET has none: accepted divergence of the UI message (D5 precedent), no golden case uses OS errors.
- Never call `RecycleBin::send_to_recycle_bin`, `delete_permanently` or anything that touches the real bin; tests use fakes only (AGENTS.md).
- The service is `&mut self` for state and `&self` for the gate; do not add interior locks around the undo state, and never hold a lock
  of your own across file I/O (R0003). The journal's own reentrant gate is W3-01's business.

## Open questions
- **Q1 (lead, before the porter starts): a Recycle Bin restore that fails with an error.** C# `IRecycleBin.TryRestore` may throw (COM/shell
  failure); the single-Recycle undo then says `core_undo_failed(<fault message>)` instead of `core_undo_recycle_restore_failed(<name>)`, and
  a group restore fails with that message. The Rust trait (`abstractions::recycle_bin`, lead-owned) returns `bool`.
  A (recommended, used by the stub): keep the trait; the platform bin logs its error and returns false. Pros: no trait churn, behaviour
  identical (fails, stays retryable, the file proof decides); cons: the message names "could not restore" instead of the shell's error.
  Record a `Different` row (message only). B: change the trait to `fn try_restore(..) -> io::Result<bool>` (touches W0 abstractions, the
  fake bin, the platform crate and every test bin); pros: message parity with C#; cons: churn across waves for a rare UI text.
  C: `catch_unwind` around `try_restore`: rejected (a panic is a bug, not a COM failure).
- **Q2 (resolved by review): `JournalTransaction` API.** W3-01 is now drafted (`contracts/drafts-w3/W3-01/transaction.rs`); "Depends on"
  quotes its real signatures (`fail` takes `&(dyn Error + 'static)`, the transaction borrows journal and clock). If the lead changes the
  W3-01 draft, re-check "Depends on" and the borrow note.
- **Q3 (resolved by review): `MoveOverride` sharing.** The W3-04 draft already imports `file_actions::undo::{FileActionGate, MoveOverride}`
  and W3-06 imports `FileActionGate`; keep both here (no hoisting needed). Consequence: W3-05 must merge before W3-04 and W3-06.
- **Q4: open_append counting in the golden.** The `on_append`/`append_fail_from` hooks count `FileSystem::open_append` calls; this assumes the
  Rust journal (W3-01) opens the file once per append exactly like C# `AppendLines` (no extra open for the tail probe, which uses
  `file_exists` + `open_read_shared`). The W3-01 draft's `append` doc matches (steps 6-7). The injected failure is a plain
  `io::Error::other(..)` / C# `IOException(message)`: NOT a sharing/lock violation, so neither side retries the open (a retry would shift
  the numbering). If W3-01 differs, the W3-01 contract must be fixed, not the golden.
