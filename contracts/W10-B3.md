## Semantics

### Location and section order

Use `docs/drafts/bench-parity/YYYY-MM-DD-<machine>-<scenario>.md`, with sibling `.json`. Fixed order:

1. Title, date, scenario, overall verdict.
2. Build and invocation identity.
3. Machine/environment block.
4. Dataset manifest and profile selection.
5. C#/Rust benchmark comparison table.
6. Exact metrics parity table.
7. Attended production surface table (B2).
8. Decision and waiver record.
9. Not measured / limitations.
10. Raw evidence paths and commands.

### Tables and formatting

Timing table columns: Profile, Workload, Status C#/Rust, Count C#/Rust, p50 C#/Rust (ms), p95 C#/Rust (ms), max C#/Rust (ms), delta p95 (ms), allowed delta (ms), verdict. Use milliseconds, 2 decimals for values and deltas, 1 decimal for ratios/percent, integer counts, decimal point, no thousands separator. Round to nearest 0.01 with ties away from zero. Exact metrics table columns: Metric, C#, Rust, Equal, Notes; counters remain integers and ordered collections retain JSON order.

B2 table columns: Display/DPI, Adapter, Keep-warm, Run, p50 ms, p95 ms, max ms, frames >50 ms, IME observations. Use 2 decimals for timing and integer frame counts. Include held-key 40 ms result in its own row.

Machine block includes CPU, GPU(s), active/default adapter, driver versions, RAM, OS, power plan, AC state, panel/monitor DPI, display foreground state, fixture count/size, executable hashes or version identities, and repeat/cold-warm method.

### Verdict block

Quote rule IDs: B1 `D-W10BENCH-1` and `D-W10BENCH-5`: three paired repeats, median repeat statistics, `allowed = max(5% * |B|, 1 ms)`, and the strict-majority rule for Regression; only p95 Regression fails exit code 1. `D-W10BENCH-5` metrics are diagnostic and never fail the gate. B2 `D-W8B3S-11` plus `D-W10BENCH-6`: production p95 is actionable only after P0; >10 ms starts W8-12j, clean <8.5 ms cancels it. A regression may be waived only by an ADR explaining the intentional difference and a corresponding PARITY row marked `Different`.

Not measured unless separately evidenced: native decode correctness over full RAW/HEIC corpus, UI behavior outside B2's attended scenarios, GPU completion time, disk-cold state, long-term soak, and performance on unrecorded hardware. Never call these parity passes.

### Compare JSON form (proposal)

Top-level object fields: `schemaVersion: integer`, `scenario: string`, `overallVerdict: string`, `exitCode: integer`, `thresholds: { ratioTolerance: number, absoluteFloorMs: number, minimumRepeats: integer }`, `csharpSummary: string`, `rustSummary: string`, `datasetEqual: boolean`, `notes: string[]`, `diagnosticMetrics: { name: string, csharp: string|null, rust: string|null, delta: string|null }[]`, `profiles: ProfileComparison[]`.

`ProfileComparison`: `profileId: string`, `workload: string`, `correctnessOnly: boolean`, `verdict: string` (`Pass|WithinNoise|Regression|Improvement|Incomparable|Skipped`), `reason: string`, `repeatCount: integer`, `sampleCountCsharp: integer`, `sampleCountRust: integer`, `csharp: { p50Ms: number|null, p95Ms: number|null, p99Ms: number|null, maxMs: number|null }`, `rust: { p50Ms: number|null, p95Ms: number|null, p99Ms: number|null, maxMs: number|null }`, `allowedP95DeltaMs: number|null`. Serialise absent/incomparable timing as JSON null, never NaN or infinity.

## Traps

- Generate Markdown from the serialized compare result; do not independently derive a different verdict.
- Keep profile status and correctness separate from timing.
- Record only actual hardware and conditions; placeholders are never copied into Measured evidence.
