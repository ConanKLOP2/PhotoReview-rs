## Semantics notes

### Layout of a real file (from `PerfCsvListener`)
```
# commit=1.0.1+build.sample diag=PHOTOREVIEW_DIAG_PRELOAD_WORKERS=4;PHOTOREVIEW_DIAG_PREREAD=1 qpcFrequency=10000000
utcTicks,qpcTicks,thread,event,nav,pathId,a,b,c,d,text
638600000102019968,102020000,1,ShowStart,1,,0,,,,Preview
...
# dropped=0
```
Writer rule for a field: wrapped in `"` only when it contains `,` or `"` (embedded `"` doubled); line breaks inside a field were already flattened to a space by the writer. Column meaning is explained in W1-19.

### `parse_text` / `read`, line by line (apply in THIS order)
1. **Decode** (`decode_bytes`): UTF-8; a leading EF BB BF is dropped; invalid bytes become U+FFFD (`String::from_utf8_lossy`; the golden file `invalid-utf8` pins that .NET and Rust replace the same way for lone continuation bytes, truncated sequences and `C0`/`F5` bytes). The result of an empty file is `""`.
2. **Lines**: split on `\r\n`, `\n` and a lone `\r` (all three end a line, like `StreamReader.ReadLine`). A final line without terminator still counts. (`str::lines()` does NOT split a lone `\r`: write your own splitter.)
3. For each line:
   - length 0 -> skip.
   - first char `#` -> comment: run the comment parser below, then go on with the next line.
   - `line.starts_with("utcTicks,")` (case sensitive; the line is NOT trimmed, so `" utcTicks,..."` is not a header) -> skip.
   - `fields = split_csv_line(line)`; fewer than 11 fields -> skip. A line of only spaces is one field -> skipped.
   - `fields[0]` must pass `parse_integer_i64`, `fields[1]` `parse_integer_i64`, `fields[2]` `parse_integer_i32`, else skip the line (each of the three alone is enough to skip).
   - else push `PerfRow { utc, qpc, thread, event: fields[3], nav: fields[4], path_id: fields[5], a: fields[6], b: fields[7], c: fields[8], d: fields[9], text: fields[10] }`. Fields 11.. are ignored. No trimming of any string field.
4. `qpc_frequency` = the parsed header value when it is > 0, else `STOPWATCH_FREQUENCY` (golden: `0`, `-5`, `abc`, an overflowing number and "no header" all give 10000000). `dropped_rows` = last valid `dropped=` value (default 0, may be negative). `path` = the argument unchanged.

### Comment parser (`ParseCommentLine`)
- `content = line.trim_start_matches(|c| c == '#' || c == ' ')` (ANY mix of `#` and spaces at the start: `## x`, `# #x`, `#   qpcFrequency=1` all work; tabs are not trimmed).
- Split `content` on the space character, dropping empty pieces (`split(' ').filter(|t| !t.is_empty())`). For each token: `eq = token.find('=')`; if `eq` is `None` or `0` -> ignore the token; `key = token[..eq]`, `value = token[eq+1..]` (so `a=b=c` has key `a`, value `b=c`).
- Keys are case-sensitive (`Dropped=9` is ignored):
  - `qpcFrequency`: if `parse_integer_i64(value)` is Some -> overwrite the frequency candidate (an invalid later value does NOT reset an earlier valid one; the last VALID one wins; a valid `0`/negative later value DOES overwrite and later falls back to the default).
  - `dropped`: same rule for `dropped_rows`.
  - `diag`: split `value` on `;` dropping empty pieces; for each `pair`: `i = pair.find('=')`; if `i` is Some and > 0 -> `diag_flags.insert(&pair[..i], &pair[i+1..])` (value may be empty: `k=` gives `k` -> `""`; `novalue` and `=x` are ignored).
  - any other key -> ignored. Comment lines may appear anywhere in the file (header, middle, trailer), all are processed in file order.

### `split_csv_line` (private, exact state machine; fields.len() == commas outside quotes + 1)
`in_quotes = false`, current field empty. For each char `c` (use `chars()`; the C# indexes UTF-16 units, but `"` and `,` are ASCII so the result is identical):
- in quotes: `"` followed by another `"` -> push one `"` and skip the second; `"` otherwise -> leave quotes; any other char -> push.
- not in quotes: `"` -> enter quotes (the quote itself is not pushed, wherever it appears: `ab"c,d"` is the field `abc,d`); `,` -> end the field; other -> push.
At the end push the last field. An unterminated quote swallows the rest of the line (commas included).

### `parse_integer_i64` / `parse_integer_i32` / `parse_double_finite` — .NET semantics, NOT Rust's
All three: first remove trailing `'\0'` characters (the .NET parser tolerates them: `"5\0"` is 5, `"5 \0"` is 5, but `"5\0 "` and `"\05"` are rejected), then trim .NET whitespace from both ends: exactly `\t \n \u000B \f \r` and space (`U+0009..=U+000D`, `U+0020`). Do NOT use `str::trim()` (it also trims U+00A0, U+2028, ...; golden: `" 3"` is rejected).
- Integer (`NumberStyles.Integer`): optional one `+`/`-`, then one or more ASCII digits `0-9` and nothing else (no `,` `_` `.` `e`, no Arabic-Indic or full-width digits, no `0x`). Whitespace between sign and digits is rejected (`- 5`). Overflow -> `None` (`9223372036854775808`, `2147483648` for i32). `-0`, `+9`, `007` are fine. Rust's `i64::from_str` does the digit/sign/overflow part correctly once the text is trimmed; check it is not empty first.
- Double (`NumberStyles.Float`, invariant): `[sign] digits [. digits] [e|E [sign] digits]` with at least one digit in the mantissa (`5.`, `.5`, `+.5`, `1.e5` are valid; `.`, `.e5`, `1e`, `1e+`, `-`, `1,5`, `0x10`, `1_0`, `1d`, `(1)`, `$1`, `1%` are not). `str::parse::<f64>` accepts exactly that grammar (plus `inf`/`infinity`/`nan`, which are non-finite and rejected below), so: trim as above, call `parse::<f64>()`, require `is_finite()`.
  Consequences pinned by the golden `num` cases: `NaN`, `nan`, `Infinity`, `-Infinity`, `inf`, `∞`, `1e999`, `-1e999`, `1e0400`, `1.7976931348623159e308` -> `None`; `1e-999`, `2.4703282292062327e-324` -> `Some(0.0)`; `4.9e-324` -> `Some(5e-324)`; `-0` -> `Some(-0.0)`; empty text -> `None` (checked before parsing).
- `PerfRow::a_num..d_num` = `parse_double_finite(&self.a)`; `nav_id` = `parse_integer_i64(&self.nav)` (so `" 5 "`, `"007"`, `"+9"`, `"2147483648"` are ids; `"abc"`, `""`, `"1.5"` are not; `0` and negative values parse fine here — W1-19 decides they are not navigations).

### `DiagFlags`
Case-insensitive keys via `pr_core::text::eq_ignore_case` (NOT `to_lowercase`). `insert(k, v)`: if an existing key is `eq_ignore_case` to `k`, replace its VALUE and keep its first spelling and position; else append. `get` is case-insensitive. Iteration = insertion order (golden `comment-diag`: `PHOTOREVIEW_DIAG_PRELOAD_WORKERS=8` — the value of the second, lower-case spelling replaced the first — then `PHOTOREVIEW_DIAG_PREREAD=1`, `k=`, `a=b=c`).

### `qpc_to_ms`
`delta_ticks as f64 * 1000.0 / self.qpc_frequency as f64` exactly in this order (multiply first). Golden `qpc` cases include a zero frequency (non-finite result, written as `null`) and `i64::MAX` deltas.

### Errors
`read`: any `std::io::Error` (missing file, a directory, access denied) -> `Err(PerfError::Io(e))`. Nothing else can fail. No `unwrap()`/`expect()` on file content.

## Traps checklist (docs/MULTI-AGENT-PLAN.md §7)
1 (DiagFlags keys use `eq_ignore_case`), 2 (parsers are invariant: no locale), 3 (every integer parse is overflow-checked, never `as`), 8 (`""` vs `None`: empty `a` is `None`, but `nav`/`text` stay `""`), 9 (`File.ReadLines` exceptions -> `PerfError::Io`), 10 (`DiagFlags` keeps insertion order), plus: `str::lines`/`str::trim` are wrong here (see above).

## Open questions (do NOT decide yourself)
1. `File.ReadLines` also decodes UTF-16/UTF-32 files that start with the matching BOM. The listener never writes them, so `decode_bytes` supports UTF-8 only. Accept as a documented difference?
2. `STOPWATCH_FREQUENCY` is a constant (Windows 10+ always reports 10 MHz). C# asks the OS. Is a constant acceptable (no `windows` dependency in `pr-perf`)? Matters only for a file whose header has no valid `qpcFrequency`.
3. The trailing-`\0` tolerance of the .NET parsers is reproduced because it is cheap; if the lead prefers stricter parsing, the 3 golden cases with NUL must be dropped from the oracle input.
