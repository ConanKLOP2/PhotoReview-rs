- Semantics notes:
  1. **Routing key.** `pr_core::catalog::types::get_wic_format(path)`, i.e. .NET `GetExtension` + OrdinalIgnoreCase on `.webp` / `.heic` / `.heif`
     (already ported, W1). `.avif`, `.cr2`, `.jpg` are `None` and go to `inner` WITHOUT calling `is_enabled` or `codecs` (the C# `Route` returns before
     both). `a.webp ` (trailing space), `C:\p.webp\file` (dot in a directory) and `a.heic.` are `None`; `.webp` (a file named just that) IS WebP.
  2. **Order of checks in `route`** (observable through probe count, golden `disabled-short-circuits-probe`):
     format none -> inner; `is_enabled()` false -> refuse localized (probe NOT called); `codecs()` called exactly once; `!supports(format)` ->
     refuse missing codec (and log once); else `wic_decoder`.
  3. **Two refusal kinds, different types.** Switch off: `DecodeError::not_supported_localized(english, text)` (variant `NotSupported`; it is
     fallbackable by the generic whitelist but the router sits in front so it never reaches the fallback; do NOT use `MissingCodec` here: the
     C# test asserts `IsNotType<MissingImageCodecException>`). Missing codec: `DecodeError::missing_codec_localized` (variant `MissingCodec`:
     preload skips it without a log line).
  4. **English messages (log/type control flow), exact:**
     - switch off: `WebP/HEIC support is disabled; cannot decode '{fileName}'.`
     - WebP missing: `WebP needs the Windows "WebP Image Extensions" (Microsoft Store); cannot decode '{fileName}'.`
     - HEIF missing: `HEIC/HEIF needs the Windows "HEIF Image Extensions" and "HEVC Video Extensions" (Microsoft Store); cannot decode '{fileName}'.`
     `{fileName}` = `get_file_name(path)` (W2-00 `dotnet_path`): for `C:/p/a.webp` it is `a.webp`.
  5. **UI sentence.** The `UserText` closure captures `Arc<dyn WebpHeicTexts>` and the file name and calls the matching `WebpHeicTexts` method AT
     DISPLAY TIME (never pre-rendered: a language switch must apply to an error already held by the status bar).
  6. **Log once per format.** Warning text, exact: `{message}; files of this format are skipped until the codec is installed and the app restarted.
     Probe: {codecs.detail}` where `{message}` is the English format-specific prefix WITHOUT the `; cannot decode ...` tail (the strings of note 4 up
     to `(Microsoft Store)`). One `AtomicBool` per format; `swap(true, SeqCst) == false` => log. The flags are per router instance (C# instance
     fields); `read_info` and `decode` share them. WebP and HEIF are logged independently (golden `webp-missing-logs-separately`: 2 warnings for 4 calls).
     `log` is `warn` level only; `None` log = `NullLog`. Do not check `log.enabled()` yourself (C# does not).
  7. **`as_cancellable()` stays `None`.** The C# router does not implement `ICancellableImageDecoder`, so `PreviewImageService` never takes the
     token overload for a router-wrapped decoder. W4-01c trap 7 says "wrappers must forward"; that advice is about wrappers that DID implement it in C#
     (check `FallbackImageDecoder`). Here parity wins: keep the default. See Open questions 3.
  8. **`read_info` argument check.** C# `ArgumentException.ThrowIfNullOrWhiteSpace(path)` runs BEFORE routing: `""` and `"   "` give
     `DecodeError::InvalidArgument` (golden `read-info-blank-path`: `throws: ArgumentException`). `decode` has no such check (the path comes from a
     `DecodeRequest`; an empty path goes to `inner`).
  9. **`will_refuse(None, ..)`** is false without calling either closure; `will_refuse(Some(p), ..)` for a non-WebP/HEIC path never calls them; for a
     WebP/HEIC path `!is_enabled() || !codecs().supports(format)` short-circuits (switch off => probe not called). Note `will_refuse` and `route` count
     probe calls independently (a preload prefetch check followed by a decode probes twice; the probe itself is cached upstream, W4-11b `Current`).
  10. **Paths.** `DecodeRequest.path` is `PathBuf` (W4-01b) and `read_info` takes `&str` (W4-01c): use `request.path.to_string_lossy()` for the
      routing key and pass the request through UNCHANGED to the chosen decoder (C# forwards the same object; the inner double records `request.path`).
  11. **Thread-safety.** The router is `Send + Sync` (all fields are); no lock is needed: decoders are stateless and the flags are atomics.

## Open questions
1. **A1: where does the localized sentence ride on a `DecodeError`?** C# attaches a `Func<string>` to `Exception.Data` (`UserFacingError.Localized`).
   W1-11 chose a payload inside `io::Error` (`pr_l10n::localized_io`), but `DecodeError::NotSupported`/`MissingCodec` are separate variants (the
   fallback whitelist and preload match on them), so they cannot be an `io::Error`. Recommended amendment to W4-01c (the RAW router W5 and
   W4-12a/b need the same): add `user_text: Option<UserText>` to `NotSupported` and `MissingCodec`
   (`pub type UserText = Arc<dyn Fn() -> String + Send + Sync>`, identical to `pr_l10n::LocalizedText`, so pr-imaging needs no `pr-l10n`
   dependency), constructors `not_supported_localized(message, text)` / `missing_codec_localized(message, text)`,
   `describe(&self) -> String` (calls the closure inside `catch_unwind`, falls back to `message()`; same rule as `UserFacingError.Describe`),
   `is_localized(&self)`. Existing patterns `NotSupported { message }` become `NotSupported { message, .. }`. Alternative: a single new variant
   `Localized { source: Box<DecodeError>, text: UserText }` (no change to existing patterns, but every `matches!` on `NotSupported` would miss it:
   rejected). Impact: this stub and `FormatRoutingDecoder` (W5) only call the two constructors.
2. **`WicCodecSupport` home.** C# defines it in `Decoding/Wic/WicCodecAvailability.cs` (W4-11b, `pr_platform_win`). The router (pure crate)
   and `CreateSourcePrefetch` (App) need it without the WIC COM code. This stub defines the plain-data type in `pr_imaging::webp_heic` and
   W4-11b must `use` it (its probe `WicCodecAvailability::current()` returns it). Alternative: put it in `pr_core::abstractions` (no consumer
   outside imaging/app today). Recommended: keep here.
3. **Cancellation through the router.** C# parity says `as_cancellable() == None`. If the lead wants cancellable WebP/HEIC decodes (PreviewImageService cancellation, W4-14; INV-2),
   that is a behavior change: forward to `wic_decoder.as_cancellable()` only for WebP/HEIC and to `inner.as_cancellable()` otherwise, after the
   same refusals. Not done here; recommended to leave as a Wave 5+ improvement (it changes `PreviewImageService` token handling for these formats).
4. **Sibling name mismatch.** 01c's draft imports `DecodedImage` as a trait; 01b exports the trait as `DecodedImageView`. This stub follows 01b.
5. **`WebpHeicTexts` vs a static `Tr`.** C# calls the generated `Tr.*` statics. Rust has no ambient localizer in pr-imaging, so the sentences are
   injected (D13 pattern). The App composition (W8) implements the trait over the loaded `Catalog`. If the lead prefers a single
   `pr_l10n`-backed `Texts` super-trait for all imaging messages (RAW has four more keys), only the trait name changes.
