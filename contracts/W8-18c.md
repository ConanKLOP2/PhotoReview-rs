## C# source (baseline `d92d6aae`)

- `interface IClipboardApi { bool Open(nint owner); void Close(); bool SetUnicodeText(string text); }` ("clears the clipboard, then sets `CF_UNICODETEXT`; false when it fails, no memory leaks").
- `sealed class Win32ClipboardService : IClipboardService`: `Attempts = 5`, `RetryDelayMilliseconds = 20`; public ctor `(Func<nint> ownerProvider)` uses `NativeClipboardApi` and `Thread.Sleep`; internal ctor `(IClipboardApi, Func<nint>, Action<int> sleep)`. `TrySetText(text)` (47-76, summary at 46): `owner = _ownerProvider(); if (owner == 0) return false;` (comment: with no owner window `EmptyClipboard` sets the owner to NULL and `SetClipboardData` fails); `try { for (attempt = 0; attempt < 5; attempt++) { if (attempt > 0) sleep(20); if (!api.Open(owner)) continue; try { return api.SetUnicodeText(text); } finally { api.Close(); } } } catch (ExternalException or OutOfMemoryException or InvalidOperationException) { return false; }`; after the loop `return false`. So: a successful `Open` ends the loop in every case (a `false` from `SetUnicodeText` is NOT retried), `Close` runs exactly when `Open` succeeded, and the sleep happens BEFORE every attempt but the first (so 4 sleeps for 5 attempts).
- `NativeClipboardApi` (**78-115**, class at 79): `Open = OpenClipboard(owner)`, `Close = CloseClipboard()` (result ignored), `SetUnicodeText` (85-114): `bytes = (text.Length + 1) * sizeof(char)`; `memory = GlobalAlloc(GMEM_MOVEABLE, bytes)`, 0 gives `false`; `ownedByClipboard = false`; `try { target = GlobalLock(memory); 0 gives false; try { copy the chars, write a final '\0' } finally { GlobalUnlock }; if (!EmptyClipboard()) return false; ownedByClipboard = SetClipboardData(CF_UNICODETEXT, memory) != 0; return ownedByClipboard; } finally { if (!ownedByClipboard) GlobalFree(memory); }` (after a successful `SetClipboardData` the system owns the memory).

## Semantics (C# is the spec)
1. **`try_set_text(text)`**: `owner = (self.owner)()`; `owner == 0` -> `false` with ZERO calls on the API. Then `for attempt in 0..ATTEMPTS { if attempt > 0 { (self.sleep)(RETRY_DELAY_MILLISECONDS) } if !api.open(owner) { continue } let result = api.set_unicode_text(text); api.close(); return result.unwrap_or(false); }` and `false` after the loop. `close` is called on every path after a successful `open` (including `Err`); a panic inside `set_unicode_text` also closes the clipboard (use a small guard struct whose `Drop` calls `close`, not a bare call after, so the unwind does not leave the clipboard open: the C# `finally`). `Err(_)` (the C# `ExternalException` / `OutOfMemoryException` / `InvalidOperationException`) is `false`; it does not log (the C# did not).
2. **`NativeClipboardApi::open`** = `user32::open_clipboard(owner).is_ok()`; **`close`** = `let _ = user32::close_clipboard();`.
3. **`NativeClipboardApi::set_unicode_text(text)`**, in this order and with these results: `block = utf16_block(text)` (the units, an embedded NUL is KEPT as the C# copies `text.Length` chars, plus the final `0`; so `block.len() == units + 1`); `bytes = block_byte_len(block.len() - 1)` (`None` on overflow -> `Ok(false)`); `memory = kernel32::global_alloc(GMEM_MOVEABLE, bytes)`: `Err` -> `Ok(false)`. From here on a guard owns `memory` and calls `unsafe { kernel32::global_free(memory) }` on drop UNLESS it was handed over. `target = kernel32::global_lock(memory)`: `Err` -> `Ok(false)`. Copy the whole `block` (terminator included) to `target` with ONE `std::ptr::copy_nonoverlapping`, `kernel32::global_unlock(memory)` (result ignored: `false` is "lock count reached zero", not an error). `user32::empty_clipboard()`: `Err` -> `Ok(false)`. `unsafe { user32::set_clipboard_data(CF_UNICODETEXT, memory) }`: `Ok(_)` -> mark handed over (the guard no longer frees), `Ok(true)`; `Err` -> `Ok(false)` (the guard frees). After `Ok(true)` the memory belongs to the system: never touch, lock or free it.
4. **Threading**: every call is on the thread that owns the owner window (the UI thread). `OpenClipboard` is per-task; `Open`/`Set`/`Close` must be on the same thread (the service never defers or posts).
5. **The default sleep** is `std::thread::sleep(Duration::from_millis(ms.into()))` (blocking the UI thread for at most 4 x 20 ms, as in C#). Tests inject a recording closure: no real sleeping, no fixed-delay asserts (AGENTS.md).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (HGLOBAL ownership): freed exactly once and only when `SetClipboardData` did NOT succeed; after success the system owns it. Test with the fake API only proves the retry logic; the real hand-over is reviewed by hand and run by the native test (the clipboard still holds the text after `close`).
- T2 (numbers, trap 3): `(len + 1) * 2` with `checked_*`; the C# `(text.Length + 1) * sizeof(char)` could wrap for impossible lengths; Rust must not panic in debug builds.
- T3 (UTF-16): count UTF-16 code units (`encode_utf16`), not `chars().count()` or `len()`; a surrogate pair is two units, an emoji string needs `2 * n` bytes. The fake API cannot see the block, so these rules are tested on the pure helpers `utf16_block` / `block_byte_len` (tests below), and again with an astral character in the native test.
- T4 (retry shape): sleep BEFORE each attempt but the first; `false` from `set_unicode_text` ends the loop (no retry); busy `open` never calls `close`.
- T5 (owner 0): checked BEFORE any API call (the comment in the C# explains the OS behaviour); the owner closure is called once per `try_set_text`.
- T6 (R0003): no `unwrap`/`expect`/`panic`; every wrapper result is mapped to `false`/`Ok(false)`; the unwind guard only closes and frees.
- T7 (unsafe): the three `unsafe` spots are the pointer copy, `set_clipboard_data` and `global_free`; each has a SAFETY comment (below). No `unsafe` outside `NativeClipboardApi`.
- T8 (clipboard side effects in tests): the native test restores TEXT only; it must never `EmptyClipboard` without writing something back; it is the only test that touches the real clipboard and is `#[ignore]`.

## Safety rules (`// SAFETY:` per `unsafe` block)
- pointer copy: "`target` is the address returned by `global_lock` for a block of `bytes` bytes == `block.len() * 2`, u16-aligned (GMEM_MOVEABLE blocks are at least 8-aligned), `block` is a live local; the regions cannot overlap; the block stays locked until `global_unlock`";
- `set_clipboard_data`: "`memory` is a GMEM_MOVEABLE handle holding a NUL-terminated UTF-16 string, the format is `CF_UNICODETEXT`; on success ownership passes to the system and the guard is disarmed";
- `global_free`: "`memory` was allocated here, is unlocked, and was not handed to the system".

## Error mapping
| C# | Rust |
|---|---|
| `Open` false | `continue` (retry) |
| `GlobalAlloc` 0 / `GlobalLock` 0 / `EmptyClipboard` false / `SetClipboardData` 0 | `Ok(false)` and the memory is freed |
| `ExternalException`, `OutOfMemoryException`, `InvalidOperationException` from `SetUnicodeText` | `Err(Win32Error)` from the trait -> `try_set_text` returns `false` |
| owner window 0 | `false`, no API call |
