- Semantics notes (from `SiblingFolderNavigator.cs`):
  1. **Direction (RV-A08).** Only -1 and +1. Any other value is an error BEFORE the session, catalog or disk is touched. `FindImageFolder` repeats the check (so a bad direction can never loop).
  2. **Start folder.** `session?.Folder`; when there is no session at all, the directory of `catalog.Current.Path` (`Path.GetDirectoryName`); when neither, a no-op. The session folder wins over the catalog entry
     (test `SessionFolderDiffersFromTheCatalogEntry`). A session with an empty `Folder` string is NOT null, so it does not fall back; it is then a no-op through `IsNullOrWhiteSpace`.
  3. **Full path.** `Path.GetFullPath(folder)` before the generation is read. A bad path escapes as an exception in C#; `Err(InvalidPath)` here.
  4. **Generation (INV-9 style).** `folder_generation` is read BEFORE the worker starts; after it, `IsFolderCurrent(generation)` false means: no status, no open (test `FolderGenerationChangesDuringSearch`).
     The clock is the folder clock, not the navigation clock.
  5. **Sorted list.** `GetSorted(currentFolder)` with NO log. Hidden and System sibling folders are not targets, but the opened folder stays in the list even when it is Hidden/System. Natural name order
     (`ManagedNaturalComparer`). A drive root, an unreadable or missing parent gives an empty list, so the search finds nothing and the boundary status is shown (the test only asserts "nothing opened").
  6. **Index.** Both sides go through `GetFullPath` + `TrimEndingDirectorySeparator`, compared ordinal ignoring case. Not found gives the empty result (no previous, no next).
  7. **Probe.** For `i = index + d, index + 2d, ...` while in range: check cancellation, list the sibling's files with pattern `"*"`, accept the first one that `is_supported_with(path, raw, webp_heic)`.
     The two getters are read once per probe loop, not once per sibling. A sibling whose listing fails is skipped (see O2). The probe never reads file content.
  8. **`FindSiblingImageFolders`.** Whitespace/empty argument is an error; the listing happens BEFORE the first cancellation check (a cancelled token still lists once); `previous` is searched before `next`;
     each is `None` when nothing qualifies. The result for "current folder not in list" is `default` (both `None`).
  9. **Boundary text.** `StatusFormatter.SiblingFolderBoundary(direction)`: `direction > 0` means `status.siblingFolder.last`, otherwise `.first`. Set only when no target and the generation is current.
  10. **Open.** `OpenFolderAsync(targetFolder)` with the default `initialPath = null`: `sink.open_folder(target, None)`; the request is posted, nothing awaits it (traits D-06d-2).

- Traps checklist:
  - **T1 Generation placement.** Read before the worker, compared after it, on the UI thread. Comparing at the start of the search, or not at all, lets a stale search open a folder the user already left.
  - **T2 UI thread.** `find_next_image_folder` and `find_sibling_image_folders` do blocking `read_dir` / `enumerate_files`; never on the UI thread. `begin_navigate` and `complete_navigate` do no I/O (except `get_full_path`, pure).
  - **T3 Case-insensitive paths.** Index lookup is ordinal ignoring case (Windows paths); use `pr_core::text::eq_ignore_case`, never `==`.
  - **T4 Trailing separator.** `C:\parent\b\` must find `C:\parent\b` (test `TrailingSeparatorOnCurrentFolder`). `trim_ending_directory_separator` removes exactly one and never from a root.
  - **T5 Direction 0 spin.** The loop `i += direction` with 0 never ends. Validate in `find_image_folder` as well as in `begin_navigate`.
  - **T6 Cancellation order.** In `find_sibling_image_folders` the token is checked after the listing and before each probe, NOT before the listing; a token cancelled up front still raises (test `CancelledToken_Throws`).
  - **T7 Getter timing.** The raw / WebP-HEIC getters are read on the worker (C# `Task.Run`), once per `find_image_folder` call; read them lazily so a setting changed while the search waits is honoured.
  - **T8 Eager listing cost.** `FileSystem::enumerate_files` returns a full `Vec`, C# `EnumerateFiles(..).Any()` stopped at the first image. A large sibling folder costs a full listing here (metadata only). See O3.
  - **T9 `SiblingImageFolders` ownership.** Do not re-declare it; import from `viewmodels::info_overlay`.

## Open questions (each with a recommended default; the stub follows the default)
- **O1 Three calls instead of `Task`.** `begin_navigate` / `find_next_image_folder` / `complete_navigate` replace the one async method (D-W8-2). The caller (W8-08b) owns the worker hop and the completion post.
  Alternative: a single blocking method plus a callback; rejected because the generation compare must run on the UI thread after the worker. Recommended: as stubbed.
- **O2 Which `io::Error`s skip a sibling.** C# catches `IOException` and `UnauthorizedAccessException` only (an `ArgumentException` from a malformed path would escape and abort the search). `FileSystem::enumerate_files`
  returns `io::Result`, which has no such distinction for most kinds, so every `Err` skips the sibling. Differences are limited to pathological directory names the OS itself returned, which cannot be malformed. Recommended: skip all.
- **O3 Eager listing.** No lazy "first match" API exists on `FileSystem` (`enumerate_files` returns `Vec<PathBuf>`). Recommended: use it as is. Only if a profile on large sibling folders shows a cost, add a
  `first_supported_file` seam to `FileSystem` in a core unit; do not add it here.
- **O4 No catalog or sink in the constructor.** The navigator takes `session_folder` and `catalog_current_path` as arguments and the sink per completion (no shared `ReviewCatalog`, no `Arc<Mutex<_>>`).
  This changes the constructor of C# (5 to 7 parameters) but not the behaviour; W8-08b passes `catalog.current().map(|e| e.path.as_str())` and the session's folder.
- **O5 Boundary at a root.** For a drive root the C# code shows the boundary status (no target), although the test is named "NoOp" (it asserts only that nothing opened). The port keeps the C# behaviour (status shown).
