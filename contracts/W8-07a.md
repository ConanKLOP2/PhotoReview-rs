## Semantics notes (all from the C# source and tests read)
1. **Sync prefix of `load`** (lines 61 to 130; runs on the UI thread, exactly like the C# code before its first `await`): disposed -> `Err(Disposed)`; blank
   or whitespace folder -> `Err(BlankFolder)`, both before any side effect (test `LoadAsync_BlankFolder_IsRejectedUpFront`: `reset_caches` count 0).
   Then: cancel the previous token, new token, `clock.next_folder()`, release the previous pending-order gate, perf "start", normalize the
   folder (`get_full_path`, then `trim_ending_directory_separator`; the C# comment: trimming first turned `C:\` into `C:`), `directory_exists`.
2. **Failures are routed, not thrown.** An invalid path or a missing directory is delivered to `sink.on_failed(folder, &error)` and the load is
   over (`Finished`). `on_failed` receives the ORIGINAL argument when `get_full_path` failed and the normalized folder when the directory is missing
   (the C# variable `folder` is reassigned only after `GetFullPath` succeeded).
3. **Settings snapshot, once** (lines 95, 128 to 130): sort mode, `raw_support_enabled`, `raw_pair_mode` (`Separate` when RAW is off), `webp_heic_support_enabled`
   are read together in `load`; the scan job gets the copy (tests `..UsesOneSnapshotForListingAndPairing`, `..UsesTheSnapshotTakenAtLoadStart`).
4. **Explorer query before the scan** (D: perf(startup)). Only `uses_explorer_order(sort_mode)` (`Name`, `SizeDescending`, `SizeAscending`) starts it. Order of `submit`
   calls: Explorer lane first, Scan lane second (test `LoadAsync_StartsExplorerQueryBeforeScanning`). The query job calls
   `ExplorerOrderProvider::try_get_snapshot_progressive(Path::new(folder), EXPLORER_QUERY_TIMEOUT, None, EXPLORER_BATCH_SIZE, &token)`, completes the
   `ExplorerQueryHandle` (also published to `latest_explorer`) and returns `ExplorerFinished`; a panic in the provider is turned into `snapshot: None` by the
   port plus `handle.fail()`. For an app-decided mode: no query, `latest_explorer.set(None)`, perf "explorerSkipped", and an already completed placeholder
   `ExplorerViewSnapshot { status: NativeViewUnavailable, reason: "Explorer order not used by this sort mode", folder, empty lists }` is used.
5. **Scan job** (`run_scan`, lines 131 to 169): on `WorkerLane::Scan`; never touches the catalog. Predicate = `is_supported_with(path, raw, webp_heic)` OR (`raw` and extension
   `.xmp`, OrdinalIgnoreCase); the listing yields `(path, Option<FileStat>)`; `on_skipped` collects `skipped`. Sidecars are the `.xmp` paths. Images become
   `CatalogEntry::new(path)` with `length`/`last_write_utc` from the stat when present. Sorting: `sort_entries(&scanned, sort_mode, None)`; the result takes, per
   sorted entry, the FIRST scanned entry with the same `ignore_case_key(path)` (C# `firstByPath` with `TryAdd`), so stat metadata travels with the item.
   Perf marks "scanned"(count), "sorted".
6. **Continuation** (`on_scan_finished`, lines 170 to 266), in this order: `Canceled` -> silent (`finish_load`); `Failed(e)` -> `report_load_error` (07b helper);
   `requested_path = initial_path.map(get_full_path)` (an invalid initial path is a load failure reported with the normalized folder, AFTER the scan: test
   `LoadAsync_MalformedPath_ReportsFailure` row 2, `catalog_ready` count 0); `token.is_canceled() || !is_folder_current(load_generation)` -> drop (INV-9);
   then `sink.reset_caches()`, `session_writer.flush()`, `session_store.load(folder)` ONCE, `catalog.reset(entries, raw_pair_mode, Some(&sidecars))`,
   `sink.on_catalog_ready(folder, catalog.count(), &session)`; skipped non-empty -> `log.warn` line + `sink.on_files_skipped(folder, &skipped)`; perf "catalogReady";
   `interaction_generation = clock.current_interaction()`; `resume_path = requested_path.or(session.current_path)`.
7. **Early Explorer order** (lines 204 to 227): if the slot is already completed (placeholder, `Done`, or the handle's `snapshot()` is `Some`): `order_settled = true`;
   `try_validate(snapshot, scanned_files)`; valid and `catalog.replace_order(&order)` true -> `sink.on_order_applied(order.len(), catalog.current_index(), false)`, perf
   "explorerApplied", and `initial_path.is_none()` clears `resume_path`; otherwise perf "explorerIgnored"/"explorerFallback". Not completed and `initial_path.is_some()`:
   the load owns the pending-order gate (`order_gate_open = true`, INV-9 file open). Folder open never opens the gate.
8. **First image** (lines 237 to 266): `catalog.count() > 0`: index = `catalog.index_of(resume_path)` if found else 0 (`resume_path = None` -> 0), `catalog.set_current(index)`,
   `presentation_generation = clock.current_navigation()`, `sink.present(index, presentation_generation)`, then `start_probe()` (07b, never for an empty catalog).
   Empty: `clock.next_navigation()`, count immediate subfolders with `file_system.enumerate_directories(folder)` (any `Err(io::Error)` counts as 0, like the C# catch of `IOException`/`UnauthorizedAccessException`;
   test `..SubfolderListingThrows..` has both exception types) -> `on_empty_with_subfolders(folder, &session, n)` if n > 0 else `on_empty`.
9. **Hand-off to 07b.** If `order_settled`: `finish_load`. Else `presentation_generation = clock.current_navigation()` (read AFTER the present/empty branch, line 273), phase
   `AwaitingOrder`, and if the Explorer slot is complete by now continue with `apply_late_order`, else wait for `ExplorerFinished`.

## Traps checklist (concrete)
- **INV-9 / generation**: three different guards, do not merge them. (1) `load_id` + token cancel = "this load was superseded": drop the event. (2) `clock.is_folder_current(load_generation)` =
  "the folder is still the one this load started" (a file action's `stop_for_action` bumps it too). (3) `interaction_generation` = INV-7. The C# order of checks in the code above is part of the contract.
- A superseded load must not call the sink, the catalog or `session_store` (tests `..FirstLoadIsDroppedSilently`, `..RapidSwitches_OnlyTheLastIsApplied`, `..FolderGenerationBumpedDuringScan_AppliesNothing`).
  Events carry `load_id`; compare it before anything else.
- `ReviewCatalog` is UI-thread only (`bind_to_current_thread`): the scan job gets owned data and returns owned `CatalogEntry` values; never move the catalog into a closure.
- Session is read exactly once per load, after `session_writer.flush()` (a pending write for this folder must be visible, test `..ReadsSessionOnce..`). Slow storage: before the first
  `present`, only the session `file_exists` and `directory_exists` may touch the file system per load, never per file (`Load_PerFileCallsBeforeFirstFrame_DoNotGrowWithFolderSize`).
- Do not read the live settings in the scan job (two reads can pair RAW and non-RAW listings).
- `get_full_path` on `C:\` keeps the root: trim only after normalizing (`LoadAsync_DriveRoot_*`); a trailing separator is accepted (`LoadAsync_TrailingSeparator_LoadsTheFolder`).
- A direct file open keeps its scan position; it is never moved to the front (`LoadAsync_DirectFileOpen_KeepsTheFileAtItsSortedPosition`); `catalog.index_of` is case-insensitive
  (`..InitialPathInTheMiddleDifferentCase..`); a path not in the folder falls back to index 0 without failure.
- Paths compare with `pr_core::text::{eq_ignore_case, ignore_case_key}`, never `to_lowercase`.
- Thread/lane: the Explorer query is blocking COM on its own STA lane; the scan job is `WorkerLane::Scan`. Neither may call back into the UI; they only return the event.
- Sink order is observable: `reset_caches` -> `on_catalog_ready` -> `on_files_skipped` -> `present`/`on_empty*` -> (07b) `on_order_applied`. Port the tests with a recording sink.
- No `async`, no `block_on`, no `unsafe`, no `windows` crate. Texts only through `pr_l10n` (the `DirectoryNotFound` display uses the generated `Tr` accessor `StatusFolderNotFound`).

## Open questions (each has a recommended default that the stubs follow)
- **O1 Catalog and sink are borrowed per call, not owned.** Default (used): `FolderLoadCx { catalog: &mut ReviewCatalog, sink: &mut dyn IFolderLoadSink }` on every call.
  `ReviewCatalog` has `RefCell`s and is shared by four C# objects; an `Rc<RefCell<..>>` graph is forbidden by D-W8-1 and a sink owned by the coordinator would create an ownership cycle
  with the view model that owns the coordinator. Alternative: the coordinator owns `Box<dyn IFolderLoadSink>`. W8-07c/07f/other B2 groups should make the same choice; the lead decides once.
- **O2 `WorkerPort`/`WorkerLane` are new local types.** No equivalent in `pr_core`/`coordinators::traits`. `coordinators::zoom_detail` (W8-07g draft) defines `BackgroundRunner` + `CompletionInbox`
  for the same purpose; a `WorkerPort` over them is a ten-line adapter. Default: keep `WorkerPort` here and let the lead unify; move it to `coordinators::traits` in the lead's wiring PR.
- **O3 No completion signal from `present`.** `IFolderLoadSink::present(index, generation)` returns when the request is posted (D-06d-2). In C# the probe starts and the late Explorer order
  is awaited AFTER the present completed. Default (used, "Different" D-07a-2): the probe is submitted right after the `present` call (the probe lane is a separate thread and probing is
  light); the late order is applied as soon as the snapshot is known. Alternative: the shell calls a `coordinator.on_first_present_finished()` and the probe starts there. Not used: an
  extra callback for a perf nicety.
- **O4 The listing cannot be aborted from the predicate.** `FileSystem::enumerate_files_with_stat(.., include: &dyn Fn(&Path) -> bool, ..)` has no way to stop (C# throws
  `OperationCanceledException` from the predicate, RV-A07). Default (used, D-07a-3): after cancel the predicate returns `false` for the remaining entries and the job returns `Canceled`
  when the listing returns, so nothing is kept and nothing is applied. Test `LoadAsync_CancelledDuringScan_StopsEnumerating` is ported as "after cancel no further entry is accepted".
  Alternative: change the pr-core trait (out of scope).
- **O5 Perf marks.** `FolderPerf` (optional trait) replaces `PhotoReviewPerf.Log.Folder/FolderInfo`; there is no Rust emitter. Default (used): the trait exists, `perf: None` in production until a W8 perf unit supplies it.
- **O6 Texts.** `FolderLoadError::DirectoryNotFound` displays the generated accessor `pr_l10n::tr::StatusFolderNotFound(folder)` (name taken from `tests/golden/l10n-generator.json`; the
  porter confirms the exact signature in the generated `tr_fns.rs`). This uses the ambient localizer exactly like the C# `Tr`; no other text is needed in this unit.
- **O7 `async`-to-event mapping.** `FolderLoadUpdate`/`FolderLoadStep::Finished` stands for "the `LoadAsync` task completed"; it completes when the last `present` is POSTED, not
  finished (see O3). The caller that awaited `LoadAsync` (view model, W8-08x) uses `Finished` + `order_gate_released`. Confirm with the W8-08 contract writer.
