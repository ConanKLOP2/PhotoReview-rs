- Semantics notes (each one is a C# behaviour the F tests check; line numbers are `ZoomDetailLoader.cs`):
  1. **Effects instead of callbacks.** `_show` (lines 161, 170), `OriginalShown` (172) and `RawDecodeIndicatorChanged` (287) become `ZoomDetailEffect`s, pushed in C# call order; the
     caller applies them in that order. The held original / target state of the loader is already final when the effects are returned (C# invokes `_show` before setting
     `_showingOriginal = true` on line 171, but nothing reads the loader in between; the presenter reads `held_original()` AFTER the call, which is equivalent).
  2. **`update` (151 to 189).** Order of the early returns: no target or target token not current: nothing. `zoom == None && !refresh_hold`: if showing the original, set the flag false and push
     `ShowImage(target.preview, target.original_width, target.original_height)`; stop. Held original: if not showing, push `ShowImage(original.platform_image, original.pixel_width,
     original.pixel_height)`, set showing true, push `OriginalShown(path)`; stop. Then `!refresh_hold && zoom.is_some() && zoom * original_width as f64 <= preview_pixel_width as f64`: stop (the preview
     has enough pixels). A load already in flight: stop. `failed_token == target.token`: stop. Otherwise start a load: new `CancelToken`, slot id, RAW indicator when
     `service.is_raw_full_decode_request(path)`, then one worker job that does `service.decode_original(path, key, &cancel).wait()` and sends `OriginalDecoded { load_id, target_id, result }`.
  3. **Completion (191 to 235), in `pump`.** `slot_owner = (load slot id == load_id)`. On `Ok(original)`: if the target is the same one (`target.id == target_id`) AND the clock says the target's
     token is current: `original = Some(original)`, log `ZoomDetail original ready token=.. WxH ms=.. path=..` when `AppLog::global().enabled()`; otherwise the pixels are dropped (INV-1). On
     `Err(e)` with `e.is_canceled()`: nothing (not a failure, no latch). On any other `Err(e)`: `AppLog::global().error("ZoomDetail original decode failed token=.. path=..", Some(&e))`, and ONLY
     when the target is still the same one `failed_token = target.token`. Then the `finally`: if `slot_owner` { stop the RAW indicator; `load = None` }. Only after a successful, accepted
     decode: `update` (the C# `try`/`catch` around it only logs; in Rust no show can throw, see the twin test of `WhenShowingTheOriginalThrows`).
  4. **`reset` (81 to 89).** `cancel_pending` (cancel the slot's token, forget the slot), stop the indicator, `target = None`, `original = None` (drops the ~96 MB), `showing_original = false`,
     `refresh_hold = false`. `failed_token` stays (a new target has a new token, so the latch no longer matches). `zoom` stays (the viewer zoom outlives the image).
  5. **`set_zoom` (93 to 99).** `if zoom != self.zoom { refresh_hold = false }` with IEEE `!=` on `Option<f64>` (`Some(NaN) != Some(NaN)` is true, `0.0 == -0.0`), store, `update`.
  6. **`refresh` (112 to 128).** Order matters: (a) no target or token not current: `AlreadyFullResolution`; (b) `retried = failed_token == target.token`, then `failed_token = -1` (BEFORE the
     next checks, so even an early return clears the latch); (c) showing original: `AlreadyFullResolution`; (d) `!(effective_zoom > 0.0) || effective_zoom * original_width as f64 <= preview_pixel_width as f64`:
     `PreviewSufficient` (NaN and non-positive land here); (e) `refresh_hold = true`, `held = original.is_some()`, `update`; `ShowedOriginal` when `held || showing_original`, else `RetryingOriginal` when
     `retried`, else `LoadingOriginal`. The effects of the `update` are returned with the result.
  7. **`on_preview_presented` (132 to 149).** `reset` first (its effects come first). A preview that is not `downscaled()` arms nothing. When `!service.is_raw_full_decode_request(path)`: a RAW path (`is_raw_path`)
     arms nothing in ANY loading mode (the ordinary decoder would re-decode the embedded JPEG), and an Original-mode key (`key.is_original()`) of an ordinary image arms nothing. Otherwise a new target is
     created (`id = next_id`, `preview = preview.platform_image().clone()`, `preview_pixel_width = preview.pixel_width()`, `original_width/height = preview.original_width()/original_height()`), then `update`.
  8. **RAW indicator (247 to 288).** `start`: stop first, new slot, a worker job `if (self.indicator_delay)(RAW_INDICATOR_DELAY, &cancel) { inbox.send(IndicatorElapsed { indicator_id }) }`. `stop`: take the slot,
     set visible false (effect only on a change), cancel it. On `IndicatorElapsed`: visible true only when the slot id still matches and its token is not cancelled. `set_visible` pushes an effect only on a transition.
     The C# indicator token is LINKED to the load token; Rust has no linked tokens, and `cancel_pending` is only called from `reset`, which stops the indicator too, so cancelling the slot explicitly is equivalent.
  9. **Identity.** Target, load and indicator are compared by `u64` ids from one counter, never by value. A new target with the same path and token is a different target (the `ASupersededTarget_OnTheSameNavigation`
     test).
 10. **`pending_load`** is true from the moment a load slot exists until its completion is pumped (C# `_pendingLoad` is cleared in the `finally` and is only set when the task was not complete at creation; a
     RAM-hit original is "complete" in C# and "pending until pumped" here: documented difference, tests pump first).
- Traps checklist:
  - **T1 INV-1.** The completion must check BOTH the target identity and `clock.is_navigation_current(target.token)` before it stores pixels. A decode that finishes after `reset`/navigation is dropped and must not
    touch `failed_token` unless it is still the same target.
  - **T2 finally ownership.** A superseded load finishing late must not stop the newer load's indicator and must not clear its slot (`slot_owner` check). Mutating it away makes
    `RawOnZoom_SupersededLoadFinishingLate_*` and `Reset_DuringInFlightDecode_*` fail; keep both tests.
  - **T3 cancellation is not failure.** `PreviewError::is_canceled()` (covers `Canceled`, `Decode(Canceled)`, `DiskEntry(Canceled)`) never sets the latch; a failure (`Decode(Io)`, `Panicked`, ...) does, once per navigation.
  - **T4 Refresh clears the latch before its early returns** (note 6b), so `Refresh` on an image whose decode failed retries even when it then returns `PreviewSufficient`.
  - **T5 RAW never re-decodes the embedded JPEG.** Both RAW rules of note 7 matter: without them a RAW preview would trigger a pointless decode and shrink the layout.
  - **T6 no wall-clock.** The 300 ms delay is injected (`with_indicator_delay`); tests release a gate. Never `sleep`. The wait for a worker completion is `wait_for_event(timeout)` (a hang guard, not a delay).
  - **T7 one original only.** Never insert the original into the preview RAM or disk cache (the service guarantees it; the test `OriginalDecode_IsNotAddedToThePreviewRamCache` checks `cache_bytes()`).
  - **T8 UI-thread affinity.** Everything except the worker jobs runs on one thread; the jobs capture only `Arc`s, `String`s, `CancelToken`s and a `CompletionInbox` clone. The loader is not `Sync`.
  - **T9 `f64` compare.** `zoom * original_width as f64 <= preview_pixel_width as f64`: both sides are converted exactly as C# (`int` to `double`); NaN zoom compares false and therefore starts a decode.
  - **T10 localized text.** None here; log lines are English diagnostics (D-W8-4 does not apply to logs).

## Open questions (each has a recommended default; the stub follows it)
- **O1 Effects instead of a `show` callback.** Default (used): the loader returns `ZoomDetailEffect`s and the presenter applies them. Alternative: a `&mut dyn ZoomDetailSink` argument on every method. Rejected: the presenter would have to lend itself
  (and the loader is a field of the presenter), which the borrow checker refuses.
- **O2 `BackgroundRunner` and `CompletionInbox` live in this file.** They are shared by the five presenter units. Default: keep them here (this is the first unit that needs them). Alternative: a new `coordinators::inbox` file; that is a new `mod` line the lead owns.
  Move them when W8-07a/07c (which also need worker completions) pick the same pattern; the names are not part of the plan.
- **O3 `PreviewImage` instead of `Arc<DecodedImage>`.** The service returns `Arc<dyn DecodedImageView>`; there is no way to get a `DecodedImage` from it. Default: use `PreviewImage` / `PlatformImage` everywhere in W8-07g..k. This forces the "Changes to B1 stubs" listed in W8-07h.
- **O4 No `UiScheduler` in the loader.** C# takes an `IUiScheduler?` only to post `ShowIfCurrent` from the pool thread. The inbox + `pump` is the Rust form. Default: removed. The shell's `WakeFn` is where `UiScheduler::post` is used.
- **O5 Fake service builder for tests.** `crates/pr-imaging/tests/support/preview_service.rs` is test-only in another crate. Default: copy what is needed into `crates/pr-app/tests/support/preview_fakes.rs` (owned by this unit, reused by 07h..k).
  Alternative: move the helpers into `pr-test-support` (needs a `pr-imaging` dev-dependency there). The lead decides; the tests do not change.
- **O6 Hang-guard wait.** `wait_for_event(timeout)` blocks on a condvar. It is a test/probe helper, never called by production code. Default timeout in tests: 20 s, like the C# `GateTimeout`.
