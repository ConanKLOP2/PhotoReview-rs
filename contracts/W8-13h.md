## Semantics (C# is the spec)
### The change entry point (replaces the C# `PropertyChanged` subscriptions; D-W8B4M-2)
The C# window listened to `MainViewModel.PropertyChanged`, `Viewer.PropertyChanged` (also `IsFullscreen`, 13k), `Compare.PropertyChanged` and `CurrentIndex` (13j), the `ImageChanging` event and the hub (`ImageChanged`). The Rust view models return a `ChangeSet`; nothing is observable. So **every caller of a view-model method forwards its `ChangeSet` to `MainWindow::apply_changes`** (the input, menus and overlay features through `update_view_model`; the pump through `pump_view_model`; `open_path`; the title/label setters). `apply_changes` is a no-op when disposed and fans out in this order (one view-model call; the order is the C# raise order, pinned by the contract text of 13j/13k):
1. `image_changing.is_some()` -> `on_image_changing(is_file_change)` (13j), BEFORE any image is handled (C# raised `ImageChanging` before the sink told the hub).
2. `drain_pending_images()` (13j; images the hub reported during the call, FIFO; renders the first image in this call). If `main` contains `CurrentImage` and `viewer.borrow().is_fit()`: `post_to_window(dispatcher, id, UiPriority::Render, update_fit_size_if_alive)` (C# `Post(UpdateFitSizeIfAlive, Render)`).
3. `main` contains `FolderTitle` -> `window.set_title(vm.folder_title())` (short borrow to copy the string; an `Err` is logged `"SetWindowText failed"`).
4. `main` contains `CurrentIndex` -> `on_navigation_changed()` (13j) then the features' `on_current_index_changed(index)`.
5. `viewer` not empty -> `on_viewer_changed()`; contains `IsFullscreen` -> `on_viewer_fullscreen_changed()` (13k).
6. `compare` not empty -> `on_compare_changed()` (13j).
7. every feature's `on_changes(changes)`.
No `RefCell` borrow of the view model or the viewer is held while any step runs (steps read what they need with a borrow that ends before the call). `update_view_model(f)`: `let changes = { let mut vm = view_model.borrow_mut(); f(&mut vm) }; self.apply_changes(&changes)`; `f` must not call back into the window (a re-entrant `borrow_mut` would panic with `BorrowMutError`: the closure type gives it no window reference).
`apply_viewer_changes(c)`: steps 5 only, for callers that changed the viewer directly (`wheel_zoom`, `set_dpi_scale`, `update_viewport`).
### Pump and wake (D-W8B4M-6)
`pump_view_model`: a `Cell<bool>` guard (re-entry through a nested message loop returns at once); `let changes = { vm.borrow_mut().pump() }`; `apply_changes(&changes)`. `view_model_wake(dispatcher)` is `coalesced_wake(dispatcher, None, UiPriority::Normal, MainWindowInner::pump_view_model)` and is what the composition root passes as `WakeFn` when it builds the view model's `CompletionInbox` BEFORE the window exists. While no window is registered the wake is dropped; the window's first `pump_view_model` (called by `open_initial`) drains the inbox anyway.
### IForwardedOpenTarget members
`is_minimized`: `hwnd != 0 && win32::startup::is_iconic(hwnd)`. `restore`: `hwnd != 0` -> `show_window(hwnd, SW_RESTORE)` (restores the PRE-minimise state: maximised or F11 stay, R7-5; never `SW_SHOWNORMAL`). `activate`: `window.is_destroyed()` -> `Err(WindowDestroyed)`; else `set_foreground_window(hwnd)`; a `false` (foreground lock) is NOT an error. `open_path(path)` = `update_view_model(|vm| vm.open_path(path))`. `is_closing_or_closed()` is the 13g accessor.
### Layout helpers
`content_from_viewer`: `viewer = vm.viewer().borrow()`; `image = self.image.borrow()`; bitmap size = the image's `width()/height()` as `f64` when `Some` and `!is_disposed()`, else 0; `is_fit = viewer.is_fit()`.
`update_fit_size`: `(w, h) = viewport.viewport_size()`; `update = viewer.borrow_mut().update_viewport(w, h, false)`; `apply_viewer_changes(update.changes)`; `update_target_decode_box(None)`; republish the size. `update_target_decode_box(size)`: `(w, h) = size.unwrap_or(viewport.viewport_size())`; `dpi = window.dpi_scale()`; `apply_viewer_changes(viewer.borrow_mut().set_dpi_scale(dpi))`; `size_source.set_target_decode_box(calculate_target_decode_box(if w > 1 { w } else { 2200 }, if h > 1 { h } else { 1400 }, dpi, 1.15))` (`pr_imaging::adaptive_preview`; an `Err` for a NaN input is logged and the old box stays; C# `CalculateTargetDecodeBox` throws only on invalid input, and the fallbacks make that unreachable). The decode box is updated in the SAME turn as the viewer scale (test `DpiChange_..._InTheSameTurn`): `on_dpi_changed` calls it synchronously, never through a post.
`on_viewer_changed`, `on_client_size_changed`: not disposed -> `viewport.invalidate_layout()`; `window.invalidate()`. `on_dpi_changed`: not disposed -> `update_target_decode_box(None)`; `viewport.invalidate_layout()`; `window.invalidate()`. It runs AFTER 13k's `on_windowing_dpi_changed` (subscribed earlier by `register_features`): when F11 is active the refit puts the window back on the monitor first, so the decode box reads the final client size (`DpiChangedWhileFullscreen_...`).
### Closing (C# 341-362) and the deferred close
`on_closing(args)`: if `vm.borrow().defer_close_for_file_action()` (R7-7: closing while a file action holds the gate would kill a cross-drive Move half way): `args.cancel = true`; if `!close_when_file_action_done` set it and call `vm.when_file_action_idle(waiter)` where `waiter` is a `Send` closure `move || with_window(id, |w| w.close_when_file_action_done_waiter())` (the gate posts it through its scheduler, or runs it inline when already free; either way it reaches the UI thread); return. Else: `is_closing_or_closed = true`; `save_placement()`; `release_renderer()` **while the HWND is alive** (a flip-model swap chain with a queued `Present` released after the window is destroyed can hang the flush for ever on a WARP + DWM runner; this is the root cause recorded in the C# comment, D-W8B4M-8). The waiter: `close_when_file_action_done = false`; unless disposed or destroyed `window.close()` (this raises `Closing` again, now not deferred); a panic is not caught.
`save_placement`: `options.placement_file` set -> `placement.save(hwnd, file, windowing.restore_state(), windowing.restore_bounds())` where the two come from `ShellFullscreen` (R7-10: closing during F11 saves the state and the Normal rect from BEFORE F11). The `bool` is ignored; the port logs failures.
### Closed (C# 390-403) and release/dispose order
`on_closed`: `is_closing_or_closed = true`; `cloak.stop()` (a close before the first frame must not wait for the cloak's safety deadline); `vm.borrow_mut().close_session()` (the returned `ChangeSet` is dropped: the window is gone); even if that panics, the preload controller is stopped: `Drop` guard calling `vm.preload_controller().cancel()` and, once `IPreloadController` has it (Open question 3), `dispose()`.
`release_renderer` (idempotent, reverse of creation): every feature's `release_renderer` (reverse registration order: the keep-warm thread, which owns its own device, stops BEFORE the window's device goes away), `dispose_viewing()` (13j: composer holds GPU bitmap references), `cache.take()` (its `Drop`/`dispose` returns the bitmaps through the device), `surface.take()`. It uses `try_borrow_mut` on the surface/cache cells; if a frame is somehow in progress (impossible from a message, since drawing pumps nothing) it logs and skips, and `dispose_inner` retries.
`dispose_inner(rethrow)` (C# 421-445), idempotent (`disposed`): 1. `disposed = true`; 2. unsubscribe the window events (`window_subscriptions`), the layout subscription, the hub subscription; 3. features' `dispose` (reverse order: the overlay, input...); 4. `size_source.set_viewport_size_fn(Arc::new(|| (0.0, 0.0)))`; 5. `cloak.stop()`; 6. `image = None`; 7. `dispose_windowing()` (13k); 8. `release_renderer()`; 9. `viewport.dispose()`; 10. unregister from the registry; 11. `if rethrow { window.dispose() }` (destroys the native window if it still exists, then resumes a captured panic); when `!rethrow` (dropped while unwinding) the `Rc<ShellWindow>` drop does the same without resuming.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7 and window-specific)
- T1 (re-entrancy, the big one): `apply_changes` is re-entered by messages sent during its own steps (`set_title` -> `WM_SETTEXT`, `render_now` -> nothing pumps but `SetWindowPos` in 13k does, `window.close()`). The fan-out reads flags into locals first, holds no borrow across a step, and each step is idempotent. A test feeds a feature whose `on_changes` calls `apply_changes` again with an empty set (must not recurse for ever or panic).
- T2 (the view-model borrow): `defer_close_for_file_action`, `when_file_action_idle`, `close_session` are called with a short `borrow()`/`borrow_mut()`; the waiter passed to the gate must not capture the borrow. `when_file_action_idle` may run the waiter inline when the gate is free: the borrow is already released by then (we call it after dropping the borrow, with an owned waiter).
- T3 (closing twice): `Closing` can be raised twice for one close (deferred then real); `close_when_file_action_done` prevents a second waiter while one is registered; a close after dispose is a no-op (`is_destroyed`).
- T4 (graphics before HWND): `release_renderer` runs inside `Closing`, not `Closed` (the HWND is still alive in `Closing`); test `Closing_ReleasesTheRenderSurface_WhileTheWindowIsStillAlive`.
- T5 (event order across units): the startup code's own `Closing` handler (secondary windows) is subscribed after this one so it runs after `on_closing` and sees `cancel = true`; `Closed` handlers of the features (scroll bars, input) run before `on_closed`. Both are consequences of subscription order and are asserted in a test with recording handlers.
- T6 (`WM_QUIT`): this unit never posts it; the startup code's `Closed` handler does (13e T5).
- T7 (dispose twice / drop after dispose): idempotent; `Drop` after an explicit `dispose` does nothing.
- T8 (numbers): the decode box uses `f64` DIP (`px / dpi`), not pixels; `w > 1` is the C# test (strictly greater than 1 DIP).

## Safety rules
No `unsafe` of its own (all OS calls through `win32::startup`, `win32::api`, `ShellWindow`). The `Drop` guard around `close_session` uses `catch_unwind`-free RAII only (no unwinding is swallowed).

## Error mapping
| C# | Rust |
|---|---|
| `InvalidOperationException("The main window is already destroyed.")` | `MainWindowError::WindowDestroyed` |
| `ObjectDisposedException` on use after dispose | the methods are no-ops (the C# handlers returned early on `_disposed`) |
| `_log.Error("Close after file action failed", ex)` (the `catch` of `CloseWhenFileActionDoneAsync`) | none: `window.close()` does not throw; a panic propagates (R0003) |
| `Win32Exception` from `SetTitle` | logged `"SetWindowText failed"` |

## Open questions (recommended default in bold)
1. **`apply_changes` as the only entry** (no per-property observers): **yes**; alternative: the view model gains an observer list (rejected in D-W8-1).
2. **Images arrive from the hub callback, handled after the borrow ends** (13j): **yes** (cross-unit: 16i keeps the hub callback shape, the sink replay runs inside a view-model call). Alternative: derive the image from `vm.current_image()` + `image_changing` in `apply_changes` and ignore the hub callback; then `is_file_change` is reconstructed and 16i's `ImageChanged` becomes unused.
3. **`IPreloadController` has no `dispose`** (C# `as IDisposable`): **add `fn dispose(&self) {}` to the trait with the concrete `PreloadController::dispose` as the override (lead edit of the B2 trait)**; until then `on_closed` calls `cancel()`. Alternative: a `preload_shutdown: Box<dyn FnOnce()>` in `MainWindowDeps`.
4. **Who implements the startup trait `ForwardedOpenTarget` for `MainWindow`**: **17a declares the trait, 17e (or 17a) writes the 5-line impl** over this unit's inherent methods (13h cannot name a B6 trait).
5. **`SettingsSource` for the input/menu services**: `MainViewModel` exposes `settings()` (an `Arc<AppSettings>`) but not its `SettingsSource`; 14c/14f need `begin_edit/commit_edit`. **Amendment A6: `MainViewModel::settings_source(&self) -> SettingsSource` (a clone of the field; D-W8B4X-18)**; the services read it through `with_view_model`/the accessor, no `FeatureOptions` entry (the earlier "composition root passes it in `FeatureOptions`" is withdrawn).
6. **`defer_close_for_file_action` consumes a held gate even if `Closing` is raised by `dispose`**: not applicable (`dispose` never raises `Closing`).
