- Semantics notes:
  1. **Thread safety.** Both types are `Send + Sync` with ONE `std::sync::Mutex` over all fields (C# `lock (_gate)`); never hold the guard across a
     call into other code. `Mutex::lock().unwrap()` is acceptable (no panic can occur while the guard is held); do not use `parking_lot` (new dep).
  2. **Pass counter.** `begin_pass`: `pass = pass.wrapping_add(1)` (C# unchecked `int` increment; wrap after 2^31 passes is unreachable, but
     do not use a `+` that panics in debug). Counter starts at 0 and `clear` does NOT reset it (golden `clear-does-not-reset-pass-counter`).
  3. **`note_busy`.** `count = if state exists and state.key == key { state.busy_count + 1 } else { 1 }` (wrapping add), then store
     `State { key: key.clone(), last_pass: pass, busy_count: count }`; return `count`. Equality is WHOLE-VALUE `ImageCacheKey` equality, so a different
     length, write time, box, orientation flag, backend or source kind all count as "the file changed" (goldens `write-time-difference-...`,
     `box-difference-...`). The scheduler passes keys it built with its current box, so a box change (window resize) restarts the busy history:
     that is the C# behaviour, keep it.
  4. **`should_skip`.** In this order: no state => `false`; `state.key != key` => REMOVE the state, return `false` (golden
     `changed-key-should-skip-removes-state-so-old-key-restarts`: after the removal, asking again with the OLD key finds nothing); else
     `state.busy_count > MAX_RETRIES || pass.wrapping_sub(state.last_pass) <= COOLDOWN_PASSES`. Note `<=`: a path noted busy in pass P is skipped in
     passes P..=P+3 (the same pass counts, golden `same-pass-as-busy-is-skipped`) and retried in P+4 (golden
     `cooldown-is-exactly-three-passes-then-retry`: `[true, true, true, false]` at P+1..P+4). The cap is `> 5`, so 5 busy outcomes still only cool
     down and the 6th (`MAX_RETRIES + 1`) skips forever (goldens `five-busy-outcomes-...` vs `retry-cap-six-...`). `should_skip` with a stale
     cooldown does NOT remove the state (so the busy count keeps growing across retries; only `record_success`, `clear` and a key change reset it).
  5. **Path key.** C# dictionary uses `StringComparer.OrdinalIgnoreCase`. Rust: `HashMap<String, State>` keyed by
     `pr_core::text::ignore_case_key(path)` (text module, trap 1). No path normalization (no `get_full_path`, no separator folding): `a/b` and
     `a\b` are different keys, exactly like C#. Do NOT key by `ImageCacheKey::path()`; the caller's `path` argument is the key.
  6. **`record_success`/`clear`.** `remove(ignore_case_key(path))` (no-op when absent) and `HashMap::clear`.
  7. **Sampler.** State starts as `DecodeBox(0, 0)`, total 0, count 0 (so the very first `record` with the unbounded box accumulates without a
     reset; golden `initial-box-is-unbounded-...`). `record`: `bytes <= 0` returns BEFORE anything (a non-positive sample at a new box does not
     switch the box, golden `non-positive-bytes-ignored-and-do-not-change-box`); on `box != stored` replace the box and zero total and count; then
     `total = total.wrapping_add(bytes)`, `count = count.wrapping_add(1)`. `mean_bytes`: `Some(total as f64 / count as f64)` only when
     `box == stored && count >= MINIMUM_SAMPLES`; it never mutates (golden `mean-for-other-box-is-null-and-does-not-reset`). Division is
     `f64 / f64` (C# `(double)_totalBytes / _count`): the mean is fractional (golden `mean-keeps-fraction`: seven 1s and one 2 => 9/8 = 1.125).
  8. **No `Default` derive surprises.** `PreloadBusyBackoff::new()` and `Default` are the same. Types stay `!Clone` (C# is a reference type that
     is shared by reference: the scheduler owns it in an `Arc`/field).
- Traps checklist (docs/MULTI-AGENT-PLAN.md §7): item 1 (OrdinalIgnoreCase: path map key via `pr_core::text`), item 3 (numeric: `i32` counters
  and `i64` bytes with wrapping ops; mean in `f64`), item 10 (no ordering is observable: the map is never iterated, so `HashMap` is fine here),
  item 12 (locking: one mutex, no guard held across calls). Specific traps:
  1. **`<=` versus `<`** in the cooldown (see note 4); `Cooldown + 1` passes is the whole busy window.
  2. **Removing on key change inside `should_skip`** is a side effect of a read-looking method; keep it (it is what makes the retry cap "forget" a
     file that was replaced on disk even if `note_busy` is not called first).
  3. **Equality is whole key, not path+length+ticks.** Do not "simplify" to a subset of the key fields.
  4. **`mean_bytes` before the minimum returns `None`, never `Some(0.0)`.**

## Golden package
- `oracle/W4-06b.cs`: commands `preload-backoff-script` and `preview-size-sampler-script` (dispatch lines in the file header). The oracle needs
  the `PhotoReview.Imaging.dll` reference (same wiring as W4-05a). `PreloadBusyBackoff` is `internal`; the oracle reaches it by reflection
  (`Activator.CreateInstance(type, nonPublic: true)`, `GetMethod(..., NonPublic)`, private `_pass` field), so the C# repo is not touched.
- `golden-inputs/preload-backoff-script.json` (18 cases), `golden-inputs/preview-size-sampler-script.json` (9 cases). Each case is an op script;
  output per case `{name, results:[...], pass}` (backoff: one entry per op: `null` for `begin_pass`/`record_success`/`clear`, the count for
  `note_busy`, a bool for `should_skip`; `pass` = the private counter at the end) and `{name, results:[...]}` (sampler: `null` for `record`,
  the mean or `null` for `mean`). `begin_pass` / `record` take `times`. Keys are built from `{path, length, written?, box_width?, box_height?}`
  with `ImageCacheKey.Create(new CatalogEntry(path).WithMetadata(length, written), false, new DecodeBox(w, h))`, defaults 100x100 and
  2026-01-01T00:00:00Z. Rust builds the same key with `create_for_entry`.
- Case design: never-busy; the cooldown boundary (same pass, +1..+3 skipped, +4 retried); 5 versus 6 busy outcomes and the cap surviving 50 passes;
  key changes by length, write time and box; removal on a key-mismatching `should_skip`; per-path independence and OrdinalIgnoreCase paths;
  `record_success` after the cap and on an unknown path; `clear` mid-cooldown and `clear` not resetting the counter; cooldown restarting from the
  latest busy pass. Sampler: 7 vs 8 samples, box change restart, non-positive samples (also at a new box), fractional mean, initial unbounded
  box, mean query at another box not resetting, totals beyond `i32`, swapped width/height.
- Values worked by hand: the eighth sample mean `(7*100+900)/8 = 200.0`; `mean-keeps-fraction` 9/8 = 1.125, then after a 9th sample of 2
  11/9 = 1.2222222222222223; `large-total-beyond-int32` 4 000 000 000.0. The oracle run is the authority.

## Open questions
1. **Visibility.** C# `PreloadBusyBackoff` is `internal`. Recommended and used by the stub: `pub` in a `pub mod` so integration tests and W4-15 see
   it. Alternative: `pub(crate)` plus unit tests inside the module (then the file is not `tests/`-only). Lead decides; the API is the same.
2. **`pass_for_tests`.** Replaces the C# reflection read of `_pass`. Recommended: keep it `pub` and `#[doc(hidden)]`. Alternative: expose a
   plain `pass()` getter (useful for scheduler logging); behaviour is identical.
3. **Counter type.** C# `int`; kept `i32` with wrapping ops. A `u64` would be simpler and unreachable-overflow-safe but changes the (unreachable)
   wrap behaviour; not worth a proposal. Left as is.
