## Semantics notes (each one is a C# behaviour the F tests check)
1. **Defaults.** `PanelElement`: base defaults (visible, opacity 1, zero margin, Stretch/Stretch, `MaxWidth = +inf`), `background = OVERLAY`,
   `corner_radius = 0`, `padding = zero`, `orientation = Vertical`, no children.
2. **Add / Remove / Children.** `add` appends in order and returns `&mut Self`. `remove(child_id)` removes the first child whose `id()` is ordinal-equal,
   returns true; otherwise false and nothing changes. `children()` is insertion order.
3. **Measure (`measure_core`).** `inner_w = max0(avail.w - padding.horizontal())`, `inner_h = max0(avail.h - padding.vertical())`, where
   `max0(v) = if v > 0 { v } else if v.is_nan() { NaN } else { 0.0 }` (trap T2). Vertical: `width = 0, height = 0`; for each child (in order)
   `size = child.measure(SizeD { width: inner_w, height: max0(inner_h - height) })`, then `width = dmax(width, size.w)`, `height += size.h`.
   Horizontal: for each child `size = child.measure(SizeD { width: max0(inner_w - width), height: inner_h })`, then `width += size.w`,
   `height = dmax(height, size.h)`. Result `SizeD { width: width + padding.horizontal(), height: height + padding.vertical() }`.
   The child's own `measure` (W8-15a base, C# `OverlayElement.Measure`) returns and stores `default` (zero) for a hidden child and does not call
   `measure_core`; this unit calls `child.measure` for every child, hidden or not, and relies on that.
4. **Arrange (`arrange_children`).** `x = bounds.x + padding.left`, `y = bounds.y + padding.top`, `inner_w = max0(bounds.w - padding.horizontal())`,
   `inner_h = max0(bounds.h - padding.vertical())`. For each child in order: if `!child.is_visible()`: `child.arrange_in(RectD { x, y, width: 0, height: 0 })`
   and the cursor does NOT move. Vertical visible: `arrange_in(RectD { x, y, width: inner_w, height: d.height })` with `d = child.desired_size()`, then
   `y += d.height`. Horizontal visible: `arrange_in(RectD { x, y, width: d.width, height: inner_h })`, then `x += d.width`.
5. **Render (`render_core`).** If `background.a > 0.0` and `bounds.width > 0.0` and `bounds.height > 0.0`: `corner_radius > 0.0` gives
   `dc.fill_rounded_rectangle(bounds, corner_radius, background)`, else `dc.fill_rectangle(bounds, background)`. Then every child's `render(dc)`
   in order (a hidden child returns from its own `render`, W8-15a). A NaN alpha is not `> 0`, so nothing is filled.
6. **FindAt.** `None` when `!self.hit_test(point)` (the base test, which includes visibility and opacity). Else the LAST child (highest index) whose
   `find_at` returns `Some` wins, searched from the end; when no child hits, `Some(self)`.
7. **Find.** `Some(self)` when `self.id() == id` (ordinal, case-sensitive); otherwise the first child, in insertion order, whose `find` returns `Some`; else `None`.
8. **ReleaseResources.** Forwards to every child in order; the panel owns no native resource.
9. **CapturePairBadge defaults.** Alignments `Center` / `Top`, `Margin = OverlayThickness::new(8, 44, 8, 8)`, `Padding = OverlayThickness::hv(6, 4)`,
   `CornerRadius = 4`, child 0 = `TextElement::new(TEXT_ID)`, `tool_tip = ""`. The badge is visible by default (the base default).
10. **CapturePairBadge::apply order.** `is_visible = model.capture_pair_visible`; `text.set_text(model.capture_pair_text)`;
    `text.set_style(TextStyle { font_family: "Segoe UI", font_size_dip: model.font_size, ..Default })`; `tool_tip = model.capture_pair_tool_tip`.
    Applied regardless of visibility. An unknown or wrong child type gives `None` in `text()` and skips the text update (no panic).
11. **FolderInfoPanel defaults.** Alignments `Right` / `Bottom`, `Margin = OverlayThickness::uniform(8)`, `Padding = OverlayThickness::hv(6, 4)`,
    `CornerRadius = 4`, `MaxWidth = MAX_WIDTH` (640) set on the base, child 0 = `TextElement::new(TEXT_ID)` with `set_trimming(CharacterEllipsis)`;
    then `apply_localization(texts)`. The 640 cap is enforced by the base measure (W8-15a), this unit only sets it.
12. **FolderInfoPanel::apply.** `is_visible = model.folder_info_visible`; `text.set_text(model.folder_info_text)`;
    `text.set_style(TextStyle { font_family: "Segoe UI", font_size_dip: model.font_size, ..Default })`. The C# order is the same.
13. **apply_localization.** `automation_name = texts.get("main.folderInfo.automationName")`. Nothing else is read from the catalog. Calling it again
    replaces the name (language switch).
14. **Delegation.** `CapturePairBadge` and `FolderInfoPanel` forward every `OverlayElement` hook to `self.panel`, so their behaviour is exactly the
    panel's (the same measure, arrange, render, find rules).

## Traps (MULTI-AGENT-PLAN section 7 items 3, 4, 8, 10 apply; the items below are specific)
- **T1 Child order and "last wins".** `find_at` searches children from the end (C# `for (int i = Count - 1; ...)`). A forward loop would return
  the bottom sibling for overlapping panels (test `find_at_prefers_the_later_sibling_where_children_overlap`).
- **T2 NaN in `Math.Max`.** C# `Math.Max(0, x)` and `Math.Max(a, b)` propagate NaN; Rust `f64::max` ignores it. Use `dmax(a, b)` = `if a.is_nan() || b.is_nan() { NaN } else if a >= b { a } else { b }`
  and `max0(v)` from note 3. Also `max0(-0.0)` must be `+0.0` (`-0.0 > 0.0` is false, so `0.0` is returned). A test with `NaN` available width must give a NaN desired width
  (`nan_available_width_propagates_like_math_max`, new). This is a Haiku trap: do not use `f64::max` or `f64::clamp`.
- **T3 Arithmetic on sizes.** Plain `f64` (no integer overflow). No `unwrap` on the children lookup (child access returns `Option`).
- **T4 Downcast by type.** `child::<T>(i)` uses `as_any()`/`as_any_mut()` and `downcast_ref`/`downcast_mut`; a child of another type gives `None`. Do not
  search children by id to find the text (ids can repeat across the panel tree; index 0 is the contract).
- **T5 Remove by id, not identity.** C# `Remove(child)` compares references; Rust removes the first child with the same `id()` (open question 2). A test
  `remove_takes_the_first_child_with_the_id` (new) pins it. Ids inside one panel are unique in every caller of this unit.
- **T6 Tooltip is copied, not cleared.** C# `ToolTip` doc says "empty while hidden", but `Apply` copies `CapturePairToolTip` unconditionally; the
  model is the source of the empty string. Test: hidden model with a non-empty tooltip still yields that tooltip (`capture_badge_tool_tip_is_copied_from_the_model`).
- **T7 Wrapper identity.** `find`/`find_at` on the badge or folder panel return the INNER `PanelElement` (`&dyn OverlayElement` of the panel), because
  the delegation forwards to `self.panel` and the panel has no pointer to its wrapper. Callers (W8-15f/15h/15g) must hold the typed wrapper to read
  `tool_tip()`, `automation_name()`, `text()`. Test `badge_find_returns_the_panel_with_the_badge_id` (new) documents it. Do not "fix" it by storing a back-reference.
- **T8 Margins and paddings are ctor-specific.** `OverlayThickness::new(8, 44, 8, 8)` for the badge margin (left, top, right, bottom), `hv(6, 4)` for the padding
  (left = right = 6, top = bottom = 4). Using `uniform(8)` for the badge margin is wrong (the 44 DIP top offset is the point of the badge).
- **T9 Hidden child.** A hidden child gets `arrange_in(RectD { x, y, 0, 0 })` at the current cursor and the cursor does NOT move, so the next visible
  sibling starts where the hidden one would have started (test `hidden_child_takes_a_zero_slot_and_no_space`). Do not skip hidden children in the loop:
  the base `arrange_in` of a hidden child also records its bounds (C# sets `Bounds` to the zero rect), which the hit test and the next frame read.
- **T10 Use the measured size.** Arrange uses `child.desired_size()` (set by measure), never `child.bounds()` (the previous arrange).
- **T11 No English literals in UI text (D-W8-4).** The folder-info automation name comes only from the catalog key; the tooltips come from the model.
  `"Segoe UI"` is a font family name, not UI text, and is allowed.
- **T12 Fluent `add` in Rust.** C# `Add` returns `this` for chaining. Rust returns `&mut Self`; a builder-style chain is therefore
  `let mut p = PanelElement::new("A"); p.add(a).add(b);`. Do not change the return type to `Self` (it breaks the ctor that adds child 0 to `self`).
- **T13 No `unwrap`/`expect`.** The overlay is UI state, but the crate rule forbids them in production paths (AGENTS.md "Errors").

## Open questions
1. **Shape of `OverlayElement` (W8-15a, not yet drafted).** This stub assumes a trait (`OverlayElement`) plus a plain `ElementBase` struct, with
   `PanelElement` owning `Vec<Box<dyn OverlayElement>>`. Alternative: an enum of all element kinds (`Element::Panel(..)`, `Element::Text(..)`)
   with no trait objects. Recommended: the trait (matches C# polymorphism and `Find`/`FindAt` recursion). If 15a chooses the enum, `child::<T>` becomes
   a match and `PanelElement` changes only in `children`, `add`, `child`, `child_mut` and the trait impl; the semantics do not change.
   Also the base's `measure` must return zero for a hidden child and store it as `desired_size` (note 3, C# `Measure`). Lead decides at the 15a/15d merge.
2. **Remove by id versus by reference.** Recommended: by id (T5). Alternative: keep a `usize` handle returned by `add`. The C# callers (ToolsMenu, StatusPanel)
   only remove whole panels; W8-15e decides if it needs more.
3. **`as_any` on the trait (W8-15a).** Required for `child::<T>` (T4). If 15a does not add it, `child` and `child_mut` are dropped and the badge keeps
   its text in a field of its own, which requires the panel to own a `TextElement` outside the children list (a change of C# structure).
4. **Composition instead of `class CapturePairBadge : PanelElement`.** Decision D-15d-1: the badge and the folder panel wrap a `PanelElement`
   and forward the hooks (T7 identity consequence). Alternative: plain factory functions `capture_badge::new() -> PanelElement` and
   `apply(&mut PanelElement, &OverlayModel)`, with the tooltip stored in the caller. Rejected: the tooltip and the automation name are then
   read through untyped lookups by id, which W8-15g and W8-15f would each re-implement.
5. **Test fakes.** `RecordingDraw` (a `DrawContext` that records calls) and `FakeTextRenderer` are defined in each of the three test files for now.
   W8-15a and W8-15c need the same fakes. Recommended: the lead hoists them into `pr-test-support` (`pr_test_support::overlay`) at the first merge
   that needs them twice; until then the copies are identical text.
6. **`pr_l10n::keys` constant.** `AUTOMATION_NAME_KEY` is a string literal here. If the W2-04 key generator emits a constant for it, use the constant
   and delete the literal (the value does not change).
7. **`DarkPalette.Overlay` value.** The pin uses a placeholder `ColorF` (alpha 0). The real value is W8-15b's; the tests of this unit do not compare it
   except through the "background alpha > 0" rule (note 5), which they check with an explicit `background` set by the test.
