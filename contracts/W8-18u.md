## Semantics (C# is the spec)
1. **`build_details_text`** exactly as the C# above (`"\r\n"` literals; `action_label` is passed in so the function is pure; the golden `action_label` equals `RECOVERY_DETAIL_ACTION` of the English catalog). `group_heading: None` with members is an empty heading line (C# `Append(null)`).
2. **`update_details`** (C# 437-522), in this order: nothing when `dialog.item(LIST_ID) == 0`; `row = list::single_selected`; `has_details = row.is_some()`; show `DETAILS_EMPTY_ID` when none, `VERDICT_LABEL_ID`, `VERDICT_BADGE_ID`, `DETAILS_ID` when some. None: the four visibility flags false, both stored paths cleared, hide the twelve controls of the C# list (error, the five source, the five destination, no-destination: lines 454-465), `DETAILS_ID` text `""`, `relayout`, return. Some: `details = RecoveryWindowPresenter::details(&rows[i], &texts)` computed under a short borrow and cloned out; `verdict_tone`; `VERDICT_BADGE_ID` text; `error_visible` and the `ERROR_ID` text/visibility; the source group: `source_visible = details.source_visible && details.source.is_some()`; when `Some(source)` and visible: tone, stored path, titles and texts of `SOURCE_TITLE_ID`, `SOURCE_STATUS_ID`, `SOURCE_PATH_ID`; otherwise the stored path is cleared (the tone is NOT reset: C# parity); show the five source controls = `source_visible`; the same for the destination; `no_destination_visible`; `DETAILS_ID` text = `build_details_text(&details, &texts.text(RECOVERY_DETAIL_ACTION))`; `relayout`.
3. **`relayout`**: `dialog.run_layout()` only when `list.initialized` (the first layout is the base class's `place_initially`).
4. **`text_color_for` / `static_text_color`**: per the stub doc; the C# palette keys `Dark.ErrorText` and `Dark.TextMuted` through `DialogColors::from_key` (a `None` falls back to `DialogColors::text()`).
5. **`layout_details` / `place_path_group`** (C# 925-985) with D-W8B5-312 arithmetic. Order of `place` calls: the centred "details empty" static ALWAYS first; then, when `has_details`: verdict label, verdict badge, error (if `error_visible`), source group (if `source_visible`), destination group (if `destination_visible`), "no destination" (if `no_destination_visible`), `DETAILS_ID`. `place_path_group` returns `y + path_height + Dy(8)`; its path box height is `min(max(wrapped + Dy(4), FieldHeight), 6 * LineHeight + Dy(4))` where `wrapped = measure_text_height(path_text, max(1, path_width - Dx(6)))`.
6. **Buttons** (`update_buttons`): the focus is read BEFORE enabling (`GetFocus`), `states = presenter.button_states(single, selected.len())` under a short borrow; `enable(RETRY_ID, states.retry)`, `CLEAR_SELECTED_ID`, `CLEAR_ALL_ID`; then `focus != 0 && !is_window_enabled(focus)` -> `set_focus(dialog.item(LIST_ID))`. `enable(id, e)`: `enable_window(item(id), e)` when the control exists. `is_enabled(id)`: control exists and `is_window_enabled`.
7. **`command_action` / `on_command`**: the table in the stub doc. `FILTER_ID` + `CBN_SELCHANGE` and `LIST_ID` + `LBN_SELCHANGE` are handled for that notification only; every button only for `BN_CLICKED` (`0`); anything else `false`. The path buttons act on the STORED path of their panel (empty = nothing happens).
8. **Background check** (D-W8B5-602, -603): `start_checks` as its doc. The `RecoveryCheckView` the presenter receives is `CheckEffects`; effects are applied after the borrow ended, in order, by `apply_check_effects`: `RowChanged(i)` -> `list::on_row_result_changed(i)` ALWAYS, visible or not (the C# `ResultChanged` handler repaints the list unconditionally; the function compares `i` with the single selected row; the stub doc says the same); `CheckStatus(t)` -> `set_item_text(CHECK_STATUS_ID, t)` only when `dialog.hwnd() != 0`; `RecheckEnabled(e)` -> read the focus first, `enable(RECHECK_ID, e)`, and when `!e` and the focus was the Re-check button, `set_focus(list)` (only when `hwnd != 0`); `Completed` -> `list::refresh_entries` only when `hwnd != 0`.
9. **Pump** (D-W8B5-602): `pump` first checks `actions.closed` (after `on_closed` it returns), moves `inbox.drain()` to `ready`, and loops `let next = ready.borrow_mut().pop_front()` (the borrow ends at the semicolon) until `None`; `handle_completion` runs with NO borrow of `ready` held. `on_window_message(WM_RECOVERY_COMPLETIONS)` -> `pump`, `Some(0)`. `post_wake(target)`: `h = target.load(Acquire)`; `h != 0` -> `PostMessage(h, WM_RECOVERY_COMPLETIONS, 0, 0)`, the result ignored (`win32::api::post_message` is an `unsafe fn`: one call, `// SAFETY:` = no pointer in the parameters). It runs on worker threads: it touches no UI state.
10. **`confirm` / `notify`**: `content.messages.show(dialog.hwnd(), title, message, kind)`; `confirm` is `== IDYES` (`win32::messages::IDYES`); `notify` ignores the answer; kind `Error` for `warning`, else `Information`. No presenter borrow is alive at the call.
11. **`copy` / `show_in_explorer`**: `explorer_arguments(path, &|p| std::fs::metadata(p).is_ok_and(|m| m.is_file()), &|p| std::fs::metadata(p).is_ok_and(|m| m.is_dir()))`; `Some(args)` -> `(content.explorer)(&args)`; `Err(message)` -> `notify(RECOVERY_EXPLORER_FAILED_TITLE, message, true)`. The nearest-folder search is `recovery_presentation::nearest_existing_folder`. Blank (empty or whitespace) path: nothing. `copy`: empty path: nothing; else the seam, result ignored.
12. **`start_explorer`** (D-W8B5-605): `Command::new("explorer.exe").raw_arg(arguments).spawn()`; the child handle is dropped (not waited, not killed); `Err(e)` -> `Err(e.to_string())`. Explorer's own exit code 1 is normal and not observed.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (borrow discipline, the main risk of this unit): `RecoveryWindowPresenter` calls its view and the `set_busy` / `rows_changed` callbacks from INSIDE `&mut self`. The view here only records. A `presenter.borrow()` or `borrow_mut()` held while `set_item_text`, `place`, `enable`, `confirm` or `notify` runs is a `BorrowMutError` panic on the UI thread (R0003) or a nested-loop re-entrancy bug. Review rule: grep every `presenter.borrow` in the two files; the borrow must end in the same statement or block that needs it.
- T2 (pump FIFO): a handler may open a message box; its nested loop dispatches `WM_RECOVERY_COMPLETIONS` again. One queue (`ready`) popped one element at a time keeps order and never handles an element twice. A `drain()` into a local `Vec` that the outer loop iterates would reorder (test `a_nested_pump_continues_the_same_queue`).
- T3 (thread safety): `post_wake` and the worker closures capture only `Arc<AtomicIsize>`, `Arc<AtomicBool>`, `CompletionInbox` and the `Send` jobs; nothing `Rc`.
- T4 (`PostMessage` to a dead window): ignored result; `on_closed` zeroes `wake_target` first.
- T5 (focus): `update_buttons` reads the focus BEFORE the enabling (a disabled control loses it); `RecheckEnabled(false)` moves the focus off the Re-check button only when it HAD it.
- T6 (paths): `explorer_arguments` quotes the path with plain `"` characters and does not escape; a path containing `"` cannot exist on Windows. Never `Command::arg` (it would escape the quotes).
- T7 (read-only, INV-5): nothing in these files writes, moves or deletes a file: no `std::fs::{write, remove_*, rename, copy, create_*}`, no `OpenOptions`. The verifier greps for it.
- T8 (`i32::clamp`): see Semantics 5.
- T9 (`RowChanged` and stale indices): `RowChanged(i)` carries the presenter index valid when the presenter reported it; effects are applied right after the borrow ended in the same UI turn, so `i` is still valid (no row is removed by a check). `on_row_result_changed` still uses `.get(i)`.

## Error mapping
| C# | Rust |
|---|---|
| `Win32Exception` / `InvalidOperationException` from `StartExplorer` | `Err(String)` from the seam -> `notify(RECOVERY_EXPLORER_FAILED_TITLE, message, warning)` |
| any other exception from the Explorer seam | not representable (a seam returns `Result`); a panic is the base's business |
| `File.Exists` / `Directory.Exists` | `std::fs::metadata(..).is_ok_and(..)` (any I/O error = false, as .NET) |
| faulted check task (`Observe`) | the presenter logs `Recovery live check failed`; spawn failure is logged by `ThreadRunner` |
| `Hwnd == 0` guards in `IRecoveryCheckView` | `dialog.hwnd() == 0` guards in `apply_check_effects` |

## Open questions (recommended default in bold)
1. **Wake by window message or by `UiScheduler::post`?** **Window message** (D-W8B5-602): the dialog has no handle on a scheduler, the message works in every nested loop, and `PostMessage` is thread-safe.
2. **`std::process::Command` or `ShellExecuteW` for Explorer?** **`Command` with `raw_arg`**: no `unsafe`, same effect; C# used `UseShellExecute = true` only because `Process.Start` needs it for a non-exe lookup (`explorer.exe` is found on the path either way).
3. **Where does `Tr.RecoveryDetailAction` come from in a pure function?** **A parameter** (`action_label`).
