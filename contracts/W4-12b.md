- Semantics notes:
  1. **Decode flow (exact order).** (a) `primary.decode(request)`; on `Ok(image)` return `image` unchanged when `image.actual_backend() ==
     primary_backend`, else `Arc::new(BackendRelabeledImage::new(image, primary_backend))`. (b) On `Err(e)` with `!is_fallbackable(&e)` return
     `Err(e)` untouched: no log, no metric, no fallback call. (c) On a fallbackable `Err(e)`: `log.warn(format!("Decoder {primary_backend} failed
     for '{path}', falling back to {FALLBACK_BACKEND}: {message}"))`, THEN `metrics.record_decoder_fallback(primary_backend)` (when present),
     THEN build the fallback request, THEN `fallback.decode`. (d) The fallback's result gets the same unchanged-or-relabel rule against
     `FALLBACK_BACKEND`; its error propagates as is (the primary's error is dropped; the fallback is never retried and never wrapped in a second
     fallback).
  2. **Text of the warning.** `{primary_backend}` / `{FALLBACK_BACKEND}` are the C# `DecoderBackend.ToString()` names (`TurboJpeg`, `WicDirect`,
     `Wpf`, `LibRaw`): use whatever `DecoderBackend` already provides for the C# name (the metrics JSON uses it; do not use `{:?}` of a renamed
     Rust variant). `{path}` is the request path as given (`path.display()` of the `PathBuf`; golden `com-message-text-in-warning` has non-ASCII,
     `path-with-quote-in-warning` an apostrophe, neither is escaped). `{message}` is `DecodeError::message()` (C# `Exception.Message`).
     `ReadInfo` uses `"Decoder {primary_backend}.ReadInfo failed for '{path}', falling back to {FALLBACK_BACKEND}: {message}"`. Tests assert
     the full string, not `contains`.
  3. **Source-bytes hand-over.** `fallback_request = if request.bytes.is_none() && let Some(b) = failure_source_bytes(&e) { request.clone().with_bytes(b) }
     else { request.clone() }`. Only `bytes` is replaced (path, box, `apply_orientation`, `priority`, `source_orientation` unchanged). A request
     that already carries bytes, even an EMPTY buffer, keeps them (C# `Bytes.HasValue`); an attached EMPTY buffer is still handed over
     (golden `source-bytes-empty-buffer-is-still-handed-over`: `bytes_len` 0). Bytes are attached to the error the primary returned; a failure that
     is not fallbackable is returned as is and never looked at. `read_info` has no bytes concept.
  4. **`is_fallbackable` is a whitelist.** True for: `NotSupported`, `MissingCodec` (C# subtype of `NotSupportedException`: `IsFallbackable` is true for
     it, the WebP/HEIC router sits in front so it normally never arrives), `InvalidCast`, `Overflow`, `Format`, `InvalidData`, `Com`, `DllNotFound`,
     `BadImageFormat`, `EntryPointNotFound`. False for every other variant: `FileNotFound`, `DirectoryNotFound`, `Canceled`, `OutOfMemory`,
     `MemoryAdmission`, `Busy` (explicit INV-12 exclusions, kept first in the C# `or` chain) and `InvalidOperation`, `InvalidArgument`, `Disposed`,
     `Io`, `Other` (not whitelisted: C# keeps `InvalidOperationException` non-fallbackable "it signals a programming error"). Write it as an
     exhaustive `match` with NO `_ =>` arm so a new `DecodeError` variant is a compile error and must be classified (mutation-resistant).
  5. **Relabel wrapper.** Forwards `pixel_width`, `pixel_height`, `downscaled`, `orientation`, `estimated_bytes`, `platform_image`,
     `original_width`, `original_height`, `is_degraded_fallback`, `exif` to the inner image and answers `actual_backend` with the stamped one.
     It does NOT forward `source_bytes_read` / `embedded_preview_size`: the C# `DecodedImageWithBackend` implements neither `ISourceReadMetrics` nor
     `IRawPreviewInfo`, so a relabelled image loses them (`PreviewImageService` then falls back to `key.Length`, `ImagePresenter` treats it as
     not-a-RAW-preview). Keep the trait defaults (`None`); see Open question 2.
  6. **No state.** The decoder holds no mutable state, so concurrent `decode` calls on one instance are fine; do not add a lock or a counter.
     Metrics counting is `ReviewMetrics`' own atomic.
  7. **Identity.** "Returned as is" means the SAME `Arc` (`Arc::ptr_eq`), never a clone of the inner image.
  8. **Cancellation.** C# `FallbackImageDecoder` is NOT an `ICancellableImageDecoder`; keep `as_cancellable() -> None` (parity). Open question 1.

## Open questions
1. **Forward `as_cancellable` or not?** C# parity says no (the wrapper is not `ICancellableImageDecoder`, so `PreviewImageService` line 845 takes the
   plain overload for a decoder the factory wrapped, i.e. a LibRaw decode is not cancellable through the factory). W4-01c's trap 7 asks the W4-12
   wrappers to forward it. Forwarding would make a RAW decode abort on supersede, a deliberate behaviour change that touches INV-1/INV-2 timing
   and the RAW preview paths. Recommended: parity now (default `None`), file a Wave 6 follow-up decision. Impact: one method in `fallback.rs` + two
   tests.
2. **Relabel wrapper drops `source_bytes_read` / `embedded_preview_size`.** Parity (this contract) vs forwarding (a visible improvement: the RAW
   preview badge and the source-bytes metric would survive a relabel). The relabel only happens when a decoder reports a backend other than the one it
   was registered under, which no baseline decoder does on the happy path, so the difference is nearly unobservable. Recommended: parity.
3. **`Arc<ReviewMetrics>`.** The stub takes `Option<Arc<ReviewMetrics>>` because the factory (W4-12a), `PreviewImageService` and the composition root all
   hold the same instance. If the lead settles on `&'static`/a trait object instead, only the field type and `new` change.
4. **`log` is not optional in Rust.** C# `ILog? = null` becomes a required `Arc<dyn Log>`; pass `Arc::new(NullLog)`. Alternative `Option<Arc<dyn Log>>`
   is equivalent; recommended: keep (matches `ImageDecoderFactory`'s `log`).

## Problems found in sibling drafts (lead must settle before any W4-12b port)
1. **Source bytes have no home in `DecodeError` (W4-01b/W4-01c gap).** C# carries the bytes in `Exception.Data`; W4-01b says "W4-01c's decode
   error variants that can carry it embed one of these", but the W4-01c enum has no such field, so `failure_source_bytes` cannot be written and the
   TurboJpeg -> WPF "decode the copy already read" optimisation (semantics 3) is impossible. Recommended W4-01c change, compatible with every
   `match` in this unit: add `DecodeError::WithSourceBytes { error: Box<DecodeError>, bytes: DecodeFailureSourceBytes }` plus
   `DecodeError::attach_source_bytes(self, SourceBytes) -> Self`, `source_bytes(&self) -> Option<&SourceBytes>` and `kind(&self) -> &DecodeError`
   (peels the wrapper); `message`, `is_io_exception`, `is_not_supported` and `Display` delegate to `kind()`. `is_fallbackable` then matches on
   `error.kind()` and `failure_source_bytes` is `error.source_bytes().cloned()`. Only a fallbackable failure may be wrapped (C# TurboJpeg rule).
2. **Type names disagree between W4-01b and W4-01c.** W4-01c says `Arc<dyn DecodedImage>` and defines `PlatformImage = Arc<dyn Any + Send + Sync>`;
   W4-01b defines `DecodedImage` as a STRUCT, the trait as `DecodedImageView`, and `PlatformImage` as an ENUM. This stub follows W4-01b
   (`Arc<dyn DecodedImageView>`, `crate::decode_types::PlatformImage`); W4-01c must be changed to match (compile-checked here with that
   substitution). `PixelLease` also has a lifetime in W4-01b while W4-01c's `to_pixels` elides it (a `mismatched_lifetime_syntaxes` warning that
   fails clippy `-D warnings`: write `PixelLease<'_>`).
3. **WAVE-4-PLAN row W4-12b names no models/crates beyond Sonnet**; no other WU is needed for the stub (nothing platform specific, no `unsafe`).
