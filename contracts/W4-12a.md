- Semantics notes:
  1. **Constructor (registry).** Build the map by iterating `providers` in order; a later entry for the same backend REPLACES the earlier
     one (`dict[backend] = factory`; golden `duplicate-provider-last-wins`). Then, if there is no `Wpf` entry: `wpf_decoder_factory` fills it;
     else if a `WicDirect` entry exists, `Wpf` gets the WicDirect provider and `wpf_mapped_to_wic_direct = true`; else
     `Err(NoWpfDecoder)`. An explicit `Wpf` provider always wins over `wpf_decoder_factory`, and then `wpf_mapped_to_wic_direct` stays false
     even if a WicDirect provider exists. Order of the three checks matters and is exactly that. The C# exception is `ArgumentException`
     (`paramName: "providers"`); the message text is byte-identical in `NO_WPF_DECODER_MESSAGE`.
  2. **`is_registered`** = the registry contains the key AFTER the Wpf slot was filled, so `Wpf` is always `true`, a mapped `Wpf` is `true`
     though the persisted setting is "Wpf" (NE-8), and `TurboJpeg` without a provider is `false`. It does not look at `wpf_decoder_factory`
     for any other backend.
  3. **`create` / `build_decoder` decision table** (backend = the REQUESTED one, `reg` = registry):
     | request | condition | result |
     |---|---|---|
     | `Wpf` | always | `decorate(Wpf, reg[Wpf]())`, never fallback-wrapped (a mapped slot returns the WicDirect decoder unwrapped) |
     | other | not in `reg` | `log.warn("Decoder backend {backend} is not registered, falling back to Wpf.")`, then `decorate(backend, reg[Wpf]())`, unwrapped |
     | `WicDirect` | `wpf_mapped_to_wic_direct` | `decorate(WicDirect, provider())`, unwrapped (no fallback to itself) |
     | other (registered) | otherwise | `primary = provider()`, `fallback = reg[Wpf]()` (a NEW call), `decorate(backend, FallbackImageDecoder::new(primary, backend, fallback, log, metrics))` |
     `{backend}` is the .NET enum name (`TurboJpeg`, `LibRaw`): use `LenientEnum::name()` of `DecoderBackend`. The Wpf provider is called
     again for every non-Wpf backend built: do NOT cache the Wpf decoder across backends and do not share it with `create(Wpf)`; C#
     builds a separate instance for each wrapper and tests count provider runs (golden `provider_runs`).
  4. **Build once (RV-I07, IMG-08).** The C# uses `ConcurrentDictionary<_, Lazy<_>>` with `ExecutionAndPublication`: provider, fallback
     wrapper AND decorator run exactly once per requested backend, and every caller (also concurrent first callers) gets the same
     `Arc`. Rust: `Mutex<HashMap<DecoderBackend, Arc<OnceLock<Arc<dyn ImageDecoder>>>>>`; lock the map only to fetch-or-insert the
     cell `Arc`, DROP the guard, then `cell.get_or_init(|| self.build_decoder(backend)).clone()`. Never run a provider, the decorator
     or the log under the map lock (a provider may take a while: 16 racing threads in the test spin 2 000 000 iterations; a decorator
     may even call `create` of another backend in the App, `FormatRoutingDecoder`). `Create(Wpf)` and `Create(WicDirect)` on a mapped
     slot are two cells and so two provider runs (golden `decorator-with-mapped-wpf-slot`).
  5. **Decorator.** Runs once per cell, after the fallback wrapping, with the REQUESTED backend: an unregistered `TurboJpeg` request is
     decorated as `TurboJpeg` around the Wpf decoder. `None` = identity. The decorator may return a wrapper (routing decoders); the
     factory hands that out unchanged.
  6. **Poisoning / panics.** C# `Lazy` caches a provider exception and rethrows it on every call (so a failing provider fails every
     `Create`). Rust: `OnceLock::get_or_init` leaves the cell empty after a panic and the next call retries. This is intentional and
     documented (providers are infallible by type: `DecoderProvider` returns an `Arc`, not a `Result`; W4-01c open question 4 recommended
     an infallible `create`). The mutex around the map is only held for fetch-or-insert, so it cannot be poisoned by a provider; use
     `lock().unwrap_or_else(PoisonError::into_inner)` anyway (the repo idiom, see `RecordingLog`).
  7. **Log default.** `None` = `NullLog` (`pr_core::abstractions::NullLog`); never print or create anything when off (INV-10).
  8. **No reflection.** C# AR01 removed `Type.GetType`/`Activator`; the Rust factory only calls the supplied closures.
  9. **Thread-safety.** `DefaultImageDecoderFactory: Send + Sync` (the trait demands it): every field is `Send + Sync`, no interior
     state besides the mutex-guarded map.

## Open questions
1. **`FallbackImageDecoder::new` shape.** W4-12b is not drafted yet; C# is `(primary, primaryBackend, fallback, log = null, metrics = null)`.
   The 12b draft is now `(Arc, DecoderBackend, Arc, Arc<dyn Log>, Option<Arc<ReviewMetrics>>) -> Self` (stub body uses `Arc::new(...)`). If 12b changes
   `new` again, adjust the single call in `build_decoder`. Impact: one line.
2. **Infallible providers.** `DecoderProvider` returns `Arc<dyn ImageDecoder>`; a provider that can fail at build time (the TurboJpeg
   native library missing is probed BEFORE registration in C#: `TurboJpegAvailability.Probe()`) would return an error-returning decoder.
   Alternative: `Fn() -> Result<Arc<dyn ImageDecoder>, DecodeError>` and cache the `Err` like `Lazy`. Recommended: keep infallible (matches
   W4-01c open question 4); the App wave registers a provider only when the codec probe passed, as C# does.
3. **Type name.** The concrete class is `DefaultImageDecoderFactory` because the trait owns `ImageDecoderFactory` (W4-01c). If the lead
   renames the trait to `IImageDecoderFactory`-style, this struct can take the unprefixed name; pure rename.
4. **Constructor with a decorator that needs the factory.** C# decorators capture services, not the factory. If W4-15 needs a decorator
   that calls `create` of another backend, the `OnceLock` build must tolerate re-entrancy for a DIFFERENT backend (it does: separate cells)
   and deadlocks for the SAME backend (C# `Lazy` throws `InvalidOperationException` there). Not exercised anywhere at the baseline.
