- Semantics notes (every line is verified against the C# source above; "golden" names a case of `raw-dng-synthetic`):
  1. **`can_read`.** `extension` equals `.dng` under `pr_core::text::eq_ignore_case` (so `.DNG`, `.DnG` yes; `dng`, `.dngx`, `.dng ` and `""` no); then the 64-byte block must have at least
     4 bytes and begin `49 49 2A 00` (II, magic 42) or `4D 4D 00 2A` (MM). Nothing else is looked at (no ORF `0x4F52`, no RW2 `0x55`, no `CR` marker). Each byte of the 8 signature bytes
     is independently checked (`CanRead_AnySingleSignatureByteWrong`); a 3-byte slice is false. Goldens `ext-*`, `magic-*`, `byte-order-*`.
  2. **Prologue.** `source.length() < 16` => `InvalidData("File too short for DNG container.")` (exact text; golden `reader_message`). Then `source.read(0, 16)`, `pr_imaging::tiff::try_read_header`
     on the returned bytes: `None` (byte order not `II`/`MM`) or `magic != 42` => `InvalidData("Invalid DNG TIFF header.")`. Copy the three header values out before the next `read`
     (the returned slice is valid only until the next read on the same source). `ifd0_offset` is a `u32` widened to `i64`; it is NOT range checked here (0, 7, past EOF are all fine and
     give an empty result because `read_ifd_entries` returns an empty list: goldens `ifd0-*`). Defaults: orientation 1, sensor 0x0, no previews.
  3. **Step 1, the IFD walk** (port the `while` literally):
     ```
     offsets = [ifd0]; visited = {}; current = ifd0; chain = 0; subs = 0
     while current > 0 && chain < MAX_IFD_COUNT(64):
         ct.check()?
         if !visited.insert(current): break            // BEFORE chain += 1
         chain += 1
         (entries, next) = read_ifd_entries(current)
         for entry in entries where tag == 0x014A:     // SubIFDs, in EVERY chain IFD
             for s in read_tag_unsigned_array(entry, max_items = 64):
                 if s > 0 && subs < 64 && !offsets.contains(s): offsets.push(s); subs += 1
         if next > 0 && !offsets.contains(next): offsets.push(next)   // registered even when the chain loop is about to stop
         current = next
     ```
     Consequences pinned by tests/goldens: the chain cap and the SubIFD cap are separate counters (64 SubIFDs do not stop IFD1+: `Dng_SixtyFourSubIfds_...`); after 64 chain IFDs the last `next`
     pointer is still registered, so the 65th IFD is parsed and the 66th never (`Read_ChainOfSixtySixIfds...` => width 164, golden `chain-66-ifds-only-first-65-considered`); a `next` that is already
     registered as a SubIFD is not added twice but the chain still continues to it, and `visited` (chain only) stops a cycle (goldens `chain-self-loop-parsed-once`, `chain-two-cycle`);
     `offsets` deduplicates by value with `Vec::contains` (at most ~130 entries, O(n^2) is fine); a SubIFD pointer equal to IFD0 is skipped. The SubIFDs of a SubIFD and the `next` pointer of a
     SubIFD are NOT followed (step 2 ignores `next`; goldens `subifd-own-next-pointer-is-not-followed`, `subifd-own-subifds-are-not-followed`). `s` is a signed `i64` from the helper (RATIONAL items are
     rounded, SHORT/LONG/IFD(13) read per type); `s > 0` filters 0 and negatives. A 70-item array only yields its first 64 (golden `subifd-array-count-70-reads-first-64`).
  4. **Step 2, per offset** in `offsets` order: `ct.check()?`; `read_ifd_entries(offset)` AGAIN (C# does not cache; the second read is free of header budget because blocks are cached,
     caching the entries is allowed only if every golden stays identical, the literal re-read is recommended). Per-IFD locals and the tag table (this is where most bugs hide):
     | tag | rule |
     |---|---|
     | 0x00FE NewSubFileType | `if let Some(v) = read_tag_unsigned` => `sub_file_type = v as u32` (wrapping cast: SLONG -1 => 0xFFFFFFFF => secondary; golden `subfiletype-slong-minus-1-wraps-to-secondary`). `None` leaves the earlier value. |
     | 0x0100 / 0x0101 | ALWAYS assign `clamp_to_int(read_tag_unsigned)`: `None`, 0 and negative => 0; >= 2^31 => `i32::MAX`. A later unreadable duplicate resets to 0 (golden `size-duplicate-width-later-unreadable-resets-to-zero`); the last readable duplicate wins. |
     | 0x0106 Photometric | `if let Some(v)` => `photometric = v` (i64). `None` keeps the earlier value. |
     | 0x0103 Compression | `if let Some(v)`: `0..=65535` => `v as u16`, otherwise `0` (never truncate 65542 onto 6; negative => 0). Default when absent: 1. |
     | 0x0112 Orientation | only when `ifd_offset == ifd0_offset`; `if let Some(v)` and `1..=8` => `orientation = v`; later entries override earlier ones; out of range keeps the earlier value (tests). Compare by VALUE: a SubIFD pointer equal to IFD0 never gets here (deduped). |
     | 0x0201 / 0x0202 | ALWAYS assign the `Option<i64>` (a later unreadable duplicate resets it to `None`; golden `interchange-duplicate-offset-later-unreadable-resets`). |
  5. **Preview decision** (`else if`, the first match wins, in this order):
     a. `jpeg_offset` and `jpeg_length` both `Some` and `starts_with_soi(source, jo, jl)` (length >= 4, range inside the file, offset > 0, first two bytes FF D8): `pw, ph = width, height`;
        `reconcile_jpeg_size(source, jo, jl, &mut pw, &mut ph)` (only when both are > 0 does it consult the JPEG frame; a non-IO budget error is swallowed inside and keeps the declared size);
        push `EmbeddedPreview { index: previews.len(), offset: jo, length: jl, kind: Jpeg, width: pw, height: ph, color_space: Unknown, header_resolved: false }`. There is NO frame-type probe here:
        a lossless SOF3 payload behind a JPEG-interchange pointer is listed (golden `interchange-lossless-sof3-still-listed-without-probe`).
     b. else `compression == 6 || compression == 7` AND `try_read_single_strip` is `Some((off, len))` AND `jpeg_probe::try_read_lossy_frame(off, len)` is `Some((w, h))`: push a preview with the PROBED
        `w, h` (the declared IFD size is ignored). Evaluate in this order and short-circuit (the helper reads can charge header budget and raise I/O errors).
        Compression 7 is also lossless-JPEG raw data: only SOF0/1/2 with 8-bit precision counts (the probe decides; goldens `strip-*`).
     `is_preview` is true after either branch, whatever NewSubFileType says (a reduced-resolution preview IFD is still a preview).
  6. **Primary (sensor) IFD.** Only when `!is_preview && (sub_file_type & 0x1D) == 0` (`0x1 | 0x4 | 0x8 | 0x10`; bit 0x2 and bits >= 0x20 are NOT secondary). `candidate = (width, height)`;
     if `try_read_default_crop_size` is `Some((cw, ch))` AND (evaluated only then) `has_square_default_scale`, `candidate = choose_active_sensor_size(width, height, cw, ch, 0, 0)` (the crop wins only when
     `cw, ch > 0` and, if the raw size is known (`width > 0 && height > 0`), `cw <= width && ch <= height`; a crop with an unknown/zero raw size is accepted). `area = min(w as i64 * h as i64, i32::MAX as i64) as i32`
     (saturates: two huge IFDs tie and the first wins, golden `size-area-saturates-at-int-max-first-wins`). `is_raw = photometric in {32803, 34892}`. Replace the current primary when
     `cw > 0 && ch > 0 && ((is_raw && !primary_is_raw) || (is_raw == primary_is_raw && area > primary_area))` (initial: area 0, not raw). Hence: raw beats any non-raw whatever the area; among equals
     the larger area wins; equal area keeps the FIRST; an IFD with a zero dimension never wins.
  7. **After the loop.** `if sensor_width == 0 && !previews.is_empty()`: the preview with the largest `width * height` (i64 product, FIRST on a tie: C# `OrderByDescending(..).First()` is stable) supplies both
     dimensions (they may be 0). Only the WIDTH is tested: that is equivalent because step 6 sets both or neither. Then ONE EXIF block: `compute_exif_block(source, little_endian, ifd0_offset)` =>
     `[ExifBlock { offset: 0, length: .., is_tiff_header: true, ifd_is_exif: false }]`. Result: `RawContainerInfo { format: Dng, sensor_width, sensor_height, orientation, previews, exif_blocks }`.
  8. **Errors and cancellation.** C# throws `InvalidDataException` (the reader's own two texts, the header source's, and the helpers' budget/range errors) and `OperationCanceledException`. Rust: every `?` returns the
     helper's `RawHeaderError` unchanged (the variant for an I/O failure must survive: `RawDecoder` unwraps it, W5-12); `ct.check()?` converts to the cancelled variant; never wrap or map either.
     Nothing in this reader catches an error itself (the swallowing lives inside `reconcile_jpeg_size`, `try_read_lossy_frame`, `compute_exif_block`).
  9. **Never panic.** All offsets are `i64`, all counts `usize`/`i32` come from the helpers; no direct slice indexing of file data in this file (only the 16-byte header copy and the 4-byte signature in `can_read`,
     both length-checked). `previews.len() as i32` cannot overflow (at most 130 IFDs). `i32 * i32` is done in `i64`. No `unwrap`/`expect`/`[i]` on anything derived from file bytes.

   `&self` returning `Vec<u8>`/`Cow`: simpler for callers, one allocation per read; the C# doc says the span is valid only until the next read, which `&mut self` models exactly), one `RawHeaderError` enum with a `Canceled` variant (alternative:
   readers return a separate cancellation result), `i32`/`i64` widths kept from C#, helpers at `crate::tiff_navigator::*` and `crate::jpeg_probe::*` taking `&mut dyn RawHeaderSource`. If W5-01/02 chose differently only the call sites in
   `dng.rs` change; the semantics section does not.
