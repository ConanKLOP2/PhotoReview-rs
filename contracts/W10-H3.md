## Semantics
1. The C# null DI fallback means a Settings click still invokes the default network checker. Rust currently has `update_checker: None` in `composition::graph::dialog_services_of` (doc at 84-85), and `SettingsPresenterOptions` also defaults to `None`. The merged `UpdateCheckJob` therefore returns a failure until H3 injects the factory. Both composition graph and secondary dialog adapter currently contain `todo!()` in this checkout; H3 must coordinate with their owner before claiming a working app.
2. Existing Rust logic covers `begin_update_check`/`UpdateCheckJob::run`/`finish_update_check`/`cancel_update_check` in `pr-app/src/presenters/settings/apply.rs` (551-663), and the General page worker/poster, checking and failure text, button visibility and enabling in `pr-platform-win/src/dialogs/settings/pages/general.rs` (288-296, 390-430). Close cancellation is **specified but still `todo!()`** in `dialogs/settings/dialog/close.rs`. `SettingsPageContext::open_url` forwards to `PageHost::open_url`; both that method and `default_open_url` are **still `todo!()`** in `dialogs/settings/dialog/host.rs`. These are concrete gaps, with existing W8-19k/19m ownership; the lead must coordinate their completion before P-09 is Done.
3. The C# opens only a URL revalidated by `UpdateUrlPolicy`, hides the open button before checking, prints Checking, then displays translated UpToDate/Available/Failure. Available text uses parsed current version or raw/empty fallback. A canceled check returns no display. The Rust presenter already mirrors these decisions; F tests should expose any gap instead of recoding them.
4. A worker-start failure in the Rust General page currently sets BadResponse and re-enables the button. C# `RunUpdateCheckAsync` has no analogous worker-start branch; this is a Rust-only robustness path. Avoid labeling it a C# port.
5. The Rust General page retries `apply_update_result` when the presenter is borrowed. Verify the dialog poster drops a late completion after close. A prompt native cancel is H2's responsibility; the UI may safely ignore a late result but must not keep a worker blocked forever.
