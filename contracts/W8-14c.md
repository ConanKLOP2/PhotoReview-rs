## Semantics (C# is the spec)
1. **`ViewportImageSurface`** forwards every member to `Rc<dyn ViewportControllerApi>` and adds `capture()`. `capture()`: `layout = viewport.layout()`; `viewer = self.viewer.borrow()` (IMMUTABLE, taken only for the five reads `zoom()`, `stretch()`, `max_image_width()`, `max_image_height()` and dropped before `viewport.*` are read; `ViewerState` is `Copy`-cheap to read); the snapshot is `ViewportSnapshot { zoom, stretch, max_image_width, max_image_height, actual_image_width: viewport.image_actual_width(), actual_image_height, extent_width: layout.extent_width, extent_height, viewport_width: layout.viewport_width, viewport_height, horizontal_offset: viewport.horizontal_offset(), vertical_offset, horizontal_scroll_bar_visible: layout.horizontal_bar_visible, vertical_scroll_bar_visible }`. The C# `YieldToRenderAsync` of `IFitSurface` is gone (`FitStep::AwaitRender`, W8-01d); `ImageSurface::yield_to_render(continuation)` calls `viewport.yield_to_render`. `SetPanCursor`, `CaptureMouse`, `ReleaseMouseCapture` map to the window through the controller (`ShellCursor::SizeAll`/`Arrow`, `capture_pointer`/`release_pointer`).
2. **Frame hooks.** `hook_render_frame(handler)` calls `viewport.hook_render_frame(Box::new(move |ticks| { handler(ticks); if let Some(router) = &router { router(ticks) } }))` with the router captured at hook time; the pointer controller passes a no-op handler and the router does the work (D-W8B4I-5). `unhook_render_frame(id)` forwards. `set_frame_router` stores the router. The ticks are `TimeSpan` ticks (`Some(trunc(rendering_time_ms * 10_000))`, made by 16h); a frame without a time is `None`.
3. **`create_viewport_input_hooks(window)`**: `drag_metrics_pixels = move || native::drag_metrics_pixels(native::dpi_of(window.dpi_scale()))` (read at each call); `cursor_screen_pixel = native::cursor_screen_pixel`. 16h builds `ViewportControllerOptions` from them (`drag_metrics_pixels`, `cursor_screen_pixel`); 13g's `ViewportFactory` calls this function, which removes the edge 13g -> 14c (D-W8B4M-4).
4. **`MainWindowInput::register`** (C# `RegisterInput`), in this order: `surface = Rc::new(RefCell::new(ViewportImageSurface::new(services.viewport(), services.viewer())))`; the host (`MainWindowInputHost`, rule 5); `ShellInput::new(ShellInputDeps { window: services.window(), surface, viewer, settings: Rc::new(move || services.settings().current()), host, dispatcher: services.dispatcher(), environment: services.input_environment(), log: services.log(), ticks_per_ms: services.ticks_per_ms() })` (R2-F-27 is satisfied by `SettingsSource::current()`: the view model, the router and the input read one source; there is no `Settings = ` assignment to port); the drop target (rule 6). The window's `Closed` subscription (C# 77) is `MainWindowFeature::dispose`/the window `Closed` event calling `on_window_closed`: the production `InputFeature` (a `MainWindowFeature`, name `"input"`) maps `on_current_index_changed(i)` -> `input.note_current_index_changed(i)`, `on_changes(&ChangeSet)` -> `on_view_model_changes`, `on_scroll_bar_press()` -> `input.pointer_press_tunnel()` (the C# `onPress: () => _input?.Pointer.OnWindowPreviewMouseDown()` of the scroll bars; implemented as a `ShellInput` method that calls `pointer.on_window_preview_mouse_down(surface)`; declared in the 14b stub by the B4 reconciliation (D-W8B4X-8); no cross-file edit), `dispose()` -> `on_window_closed`.
5. **The host (C# `IShellInputHost` + `ExecuteAsync`).** Queries read the view model through `services.with_view_model(..)` / the viewer handle: `has_images`, `viewer.borrow().is_fullscreen()`, `vm.compare().is_visible()`, `vm.current_has_compare_pair()`, `vm.current_has_capture_pair()`, `vm.cancel_duplicate_check()`. `next()`/`previous()` run `vm.next()`/`vm.previous()` through `with_view_model` (the returned `ChangeSet` is applied by the window). `report_action_failed(name, e)`: `log.error(&format!("{name} failed"), Some(e))`; `services.show_status(&services.action_failed_text(name, e))`. `zoom_action_name()` = `action_names().zoom`. `execute(command)` (every arm outside the view-model borrow when it can re-enter: `Close` calls `services.close_window()` directly, never inside `with_view_model`):
   `Fullscreen` -> `vm.toggle_fullscreen()`; `ExitFullscreen` -> `vm.exit_fullscreen()`; `Close` -> `close_window()`; `NextFolder` / `PreviousFolder` -> guarded (`action_names().next_folder` / `previous_folder`) `vm.navigate_sibling_folder(1 / -1)` (its `Err(SiblingNavError)` is the failure); `FirstImage` / `LastImage` -> `vm.first()` / `vm.last()`; `ToggleInfoOverlay`; `Undo`; `ToggleCompare`; `ToggleCaptureMember` -> `vm.toggle_capture_group_member()`; `RunAction` -> `index = command.action_index`, name = `settings.actions[index].name` when `0 <= index < len` else `""`, guarded `vm.run_action(index)`; `Recycle` / `Skip` / `Next` / `Previous`; `MoveToFolder` / `CopyToFolder` -> guarded (`move_to_folder` / `copy_to_folder` names) `vm.move_to_folder(command.force_picker)` / `copy_to_folder`; `ToggleKeepZoom` -> `toggle_keep_zoom_across_images()`; `OpenFolder` -> guarded (`open_folder` name, already trimmed of `…`, `.`, space by the services) `vm.pick_and_open_folder()`; `CustomZoom` -> guarded (`zoom`) `open_click_zoom_custom_dialog()`; `Refresh` -> `refresh_view()`. The viewport kinds never arrive here (ShellInput handled them). "Guarded" = an `Err` is `report_action_failed(name, e)` and the method returns `Ok(())` (C# `RunGuardedAsync` swallowed after reporting); unguarded arms return their `Err` to `ShellInput::execute_guarded`, which reports with the command name.
6. **Drop target.** `ShellDropTarget::new(DropCallbacks { open_path: |p| { with_view_model(|vm| vm.open_path(p)); Ok(()) }, on_failure: |e| report_drop_failure(e), files: None, has_files: None })`; `register(window.hwnd())`: `Err` logs `"Drag and drop is unavailable (RegisterDragDrop failed)."` (warn) and goes on; the object is revoked in `on_window_closed` (the window's `Closed` fires inside `WM_DESTROY`, when the HWND is still valid, so the revoke succeeds). `open_path` runs inline inside the OLE callback, like the C# `OpenFirstAsync` ran its synchronous part there; it only starts the view model's step machine and applies the returned `ChangeSet` (open question 3).
7. **`on_view_model_changes(changes)`**: `changes.main` contains `CurrentIndex` -> `input.note_current_index_changed(vm.current_index())` (the window passes the index through the feature hook instead; only one of the two paths is wired, the feature hook); `changes.viewer` contains `Zoom` or `Stretch` -> `input.on_zoom_mode_changed()` (C# `ViewerState.ZoomModeChanged` event: stop the glide on every zoom change, also those made by the toolbar or the menu).
8. **`refresh_view`**: `input.stop_kinetic()`; `with_view_model(|vm| vm.refresh_view().1)` (the `ViewRefreshOutcome` is not used here); `services.invalidate_layout_and_window()` (`viewport.invalidate_layout()` then `window.invalidate()`). **`toggle_keep_zoom_across_images`**: `save_setting(|s| s.keep_zoom_across_images = !s.keep_zoom_across_images, "Could not save the keep-zoom setting")`. **`open_click_zoom_custom_dialog`**: `zoom_prompt.prompt_custom_zoom(settings.current().click_zoom_percent)` -> `Some(p)` -> `apply_zoom_menu_selection(p)`; `None` or no prompt: nothing. **`apply_zoom_menu_selection(p)`**: `settings.current().set_zoom_also_sets_click_level` ? `apply_click_zoom_level(p)` : `input.set_click_zoom_level(p)`. **`apply_click_zoom_level(p)`**: `save_setting(|s| s.click_zoom_percent = p, "Could not save the click zoom level setting")` then `input.set_click_zoom_level(p)` (zooms even when the save failed). **`save_setting(mutate, failure_text)`** = `let edit = source.begin_edit(mutate); if let Err(e) = source.commit_edit(edit) { log.error(failure_text, Some(&e)) }` (the failed commit keeps the provisional override, so the session keeps the value; exactly the intent of C# mutating the live object before `Save`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (viewer borrows): `capture()` takes an immutable `ViewerHandle` borrow and no controller call happens while it is held; `apply_fit` uses the `ViewerFitAdapter` of 14b. The surface never takes `borrow_mut`.
- T2 (RefCell vs re-entrancy): `close_window()` and `window.invalidate()` can send/post messages; they are called outside `with_view_model`. `with_view_model` implementations (13h `update_view_model`) release the VM borrow before applying the `ChangeSet` (D-W8B4M-2); this unit never calls `apply_changes` inside the closure.
- T3 (drag drop COM lifetime): `ShellDropTarget` owns the COM object; `register` makes OLE hold its own reference; `on_window_closed` revokes BEFORE the HWND is gone; dropping `MainWindowInput` without `on_window_closed` still revokes (`ShellDropTarget` implements `Drop` = `dispose`, W8-14d, because OLE holds a reference to the object until `RevokeDragDrop`; `on_window_closed` also calls `dispose` explicitly so the revoke happens while the HWND is valid).
- T4 (handler order): the main window registers scroll bars first, then this input (`ShellInput::new` adds keyboard, pointer, wheel), then the context menu (14f); overlay and keep-warm insert FIRST (`insert_message_handler_first`, 15j/16d). The scroll-bar handler sees a press before the image does (D-W8B4I-14).
- T5 (settings object identity): the lazy rebuild in 14b relies on `SettingsSource::begin_edit` installing a NEW `Arc` per edit; do not mutate in place.
- T6 (DPI): `create_viewport_input_hooks` must read the DPI of the window at each call; a captured `dpi` would break the monitor change.
- T7 (no `unwrap`/`expect`): a missing prompt, store or window is a no-op, not a panic.
- T8 (localized names): the guarded action names are fetched at call time (`action_names()` is a method, not a field), because the language can change while the window lives.

## Open questions (recommended default in bold)
1. **`MainWindowInputServices` as a trait** (D-W8B4I-6) vs a direct dependency on `MainWindow`: **trait now, adapter after 13g/13h merge** (the adapter is `MainWindowInputAdapter { main: Weak<..> }` in `main_window.rs`). Alternative: 13g exposes a public `MainWindow::services()` bundle and the trait is dropped.
2. **`ViewportControllerApi` trait** vs holding `Rc<ViewportController>` directly: **trait** (a fake controller makes `capture()` and the router testable; the `impl` for the real controller is 5 lines per member). 16h's stub already exposes the same member names with `&self`, so the impl is a forwarder.
3. **Drop opens the file inline** (C# parity) vs posts it at Normal priority so the OLE callback returns first: **inline**; revisit if a desktop run shows the drag source freezing while the first image decodes (the decode itself is on workers, only the `ChangeSet` application is inline).
4. **Where `ShellInput::pointer_press_tunnel` lives**: **`dispatch.rs`, declared in the 14b stub** (D-W8B4X-8, resolved); the hook name on the window is `MainWindowFeature::on_scroll_bar_press`, which the 13g stub already has.
5. **`on_view_model_changes` index path**: **the feature hook `on_current_index_changed(i)` of 13h** (it already fans out `CurrentIndex`, D-W8B4M-7); `on_view_model_changes` then only handles the zoom bits. If 13h drops the hook, `on_view_model_changes` reads `vm.current_index()`.
6. **Input environment and zoom prompt reach the unit through `FeatureOptions`** (13g): **yes**: `get::<ShellInputEnvironment>()` (missing = default) and `get::<ZoomPromptOption>()` (a newtype over `Rc<dyn ZoomPromptService>`, defined in `main_window.rs`, because `insert` needs a sized `Any` type).
