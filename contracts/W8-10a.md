## Semantics (numbers are cited by the stubs and goldens)
1. **Copy semantics.** The presenter edits a copy. `new` clones every action, so later changes to the caller's list do not leak in
   (test `presenter_edits_a_copy`).
2. **Row identity (C# reference equality becomes `RowId`).** `open(Some(id))` sets `loaded` to `id`. `save_current` writes only when
   `loaded` names a live row; a removed row or a row of an old list fails (`false`). The detached object keeps its own values (the test
   reads the removed row's name after Remove). An unknown id behaves like `None`: `open` returns `None` and `loaded` becomes `None`.
3. **`open`.** Returns the form: name, shortcut, `operation_to_index`, destination, confirm (the values are copied, not trimmed).
4. **`save_current`.** Name and destination are trimmed with `str::trim` (T2). Shortcut is `canonicalize(Some(shortcut))`, which
   trims and maps aliases to the canonical spelling (`" f8 "` gives `"f8"`; `"enter"` gives `"Enter"`). Operation is `index_to_operation`.
   Confirm is copied.
5. **`add`.** New row: name `texts.get(keys::ACTION_PROFILES_NEW_ACTION_NAME)`, shortcut `next_free_shortcut(actions)`, operation Move,
   destination `"Output"`, confirm false. It is appended, so its index is `len - 1`. The row id is new.
6. **`remove(row, selected)`.** A stale or unknown id removes nothing. When the list is still non-empty the result is
   `min(selected, len - 1)`. When the list is empty the result is `None`, and `loaded` is cleared (C# returns -1). The C# view passes a
   valid index; `usize` removes the C# negative case (open question 4).
7. **`replace_all`.** Replaces the list, issues new row ids for every row, clears `loaded`.
8. **`apply`.** `has_invalid_actions` gives `actionProfilesInvalid.message` (not accepted). Otherwise `find_destination_problem` gives its
   message (not accepted). Otherwise accepted with no message. The C# order is kept.
9. **`has_invalid_actions` (key check).** True when the list is empty; when a name is blank (`trim().is_empty()`); when a shortcut does
   not parse (`parse_shortcut` is `None`); or when two actions parse to the same `KeyId` (aliases Return/Enter, Prior/PageUp, Next/PageDown,
   `f6`/`F6` are duplicates). Recycle is not special. The Rust port has no `Enum.IsDefined` check: `FileOperationType` cannot hold an
   undefined value (see T12).
10. **`next_free_shortcut`.** Tries `F6`..`F12` in order and returns `k.name()` for the first key that no action's parsed key equals.
    Actions whose shortcut does not parse are ignored (they use no key). When all seven are used the result is `"F6"`.
11. **`find_destination_problem`.** Walks the actions in order. Recycle is skipped. `destination_policy::validate(Some(&destination))`:
    `Ok` continues; `EscapesSourceFolder` returns `actionProfiles.error.destinationEscapes` with `{name}`; `Empty` and `InvalidChars`
    return `actionProfiles.error.destinationInvalid` with `{name}`. The first problem wins.
12. **`try_import(path)`.** Reads the file as UTF-8 text, then `action_list_json::deserialize_or_null(text, default_name)`
    where `default_name` is the English value, not the localized one (see open question 5). Outcomes, in order:
    - an I/O error reading the file (missing, denied, illegal name, invalid UTF-8): `Err(dialog.importActions.failed.message{error})`
      after `AppLog::global().error("Action import failed: <path>", Some(&e))`;
    - `Err(Malformed)` (text, shape, null element, unknown operation name), `Ok(None)` (literal null) or `Ok(Some(empty))`:
      `Err(dialog.importActions.invalid.message)`;
    - otherwise `Ok(list)` with the rows copied.
    C# catches `JsonException`/`NotSupportedException`/`InvalidCastException` as invalid, and `IOException`/`UnauthorizedAccessException`/
    `SecurityException`/`ArgumentException` as failed. Rust has two error types, so the split is by source: parse errors are invalid, I/O errors are failed.
13. **`try_export(path, actions)`.** Writes `serialize_for_export(actions)` with `std::fs::write`. Success is `None`. A failure is
    logged to `AppLog` and gives `Some(dialog.exportActions.failed.message{error})`. The target may be a directory or a missing folder.
14. **`parse_shortcut`.** The W8-04c `try_parse` on `Some(shortcut)`. Blank text, digits, comma lists and reserved keys are `None`.
15. **`operation_to_index` / `index_to_operation`.** Move 0, Copy 1, Recycle 2. Any other index reads as Move.
16. **`ActionListJson::serialize`.** Pretty JSON with two-space indent and `\n` line ends (`WriteIndented`); property order
    `Name, Shortcut, Operation, Destination, Confirm`; `Operation` by name; empty list `[]`; non-ASCII characters written as they are.
    Escaping is the relaxed set (T8).
17. **`serialize_for_export`.** The same shape with the DEFAULT .NET escaping (T8).
18. **`deserialize`.** Literal `null` gives `[]` (C# `?? []`). Each object: missing property takes its initialiser value (`Name` = `default_name`,
    `Shortcut` `"Enter"`, `Operation` Move, `Destination` `"Group-2"`, `Confirm` false); unknown properties are ignored; `Operation` is read
    with the lenient rules of `FileOperationType` (names, numbers, alias `Delete`). A non-object element, a non-list document or
    malformed text gives `Malformed`.
19. **`deserialize_or_null`.** Like `deserialize`, but the literal `null` gives `Ok(None)`.
20. **`throw_if_invalid`.** Fails with `Invalid("An action has no name, an invalid shortcut or an invalid operation.")` when a name is
    blank, a shortcut is blank or does not parse. Fails with `Invalid("Two actions use the same shortcut.")` when two actions canonicalize
    to the same shortcut TEXT under ordinal-ignore-case (`ignore_case_key` of the `canonicalize` result). An empty list passes (it is not
    checked here; `has_invalid_actions` rejects it).

## Traps (docs/MULTI-AGENT-PLAN.md section 7; the stubs and tests cite these ids)
- **T1 Two duplicate checks.** `has_invalid_actions` compares parsed KEYS; `throw_if_invalid` compares canonical TEXT. They agree on every
  alias listed in `ALIAS_PAIRS`. The C# code uses both, so keep both. No golden case shows a difference; do not merge them.
- **T2 Trim.** C# `Trim()` and `IsNullOrWhiteSpace` use `char.IsWhiteSpace`; Rust `str::trim` uses the Unicode White_Space set. The golden
  `script-save-trims-but-not-bom` covers U+00A0 and U+0085 (trimmed in both) and U+FEFF (kept in both). Use `trim()`, not `trim_matches`.
- **T3 Null and empty.** C# `string?` null is "no value" and `""` is empty; both fail the name checks. Rust has no null string: the
  JSON `null` for a string property is mapped to `""` (see T10), and the golden leaves those cases out.
- **T4 Identity.** Use `RowId`, never a list index, for the open row (C# `ActionProfiles_RemovedRowIsNotWrittenBack`: the open row is
  removed by its object, not by its position).
- **T5 Clamp.** `remove` returns `min(selected, len - 1)` when the list is not empty. Test the case where the removed row is the last one.
- **T6 Localized defaults.** `add` takes its name from the catalog (`actionProfiles.newActionName`). The English default is `"New action"`.
- **T7 Errors.** Split the C# exception filters by source (parse versus I/O), not by type name. Never fold them into one catch (rule 9 of section 7).
- **T8 Escaping.** `serialize` (relaxed, `UnsafeRelaxedJsonEscaping`) writes non-ASCII as is and escapes only `"`, `\`, and control
  characters. `serialize_for_export` (`JavaScriptEncoder.Default`) writes every non-ASCII character as `\uXXXX` (lowercase hex digits as
  .NET writes them) and also escapes the HTML and JS sensitive ASCII characters `< > & ' + \`` (the golden fixes the exact set).
  `serde_json` writes neither set by default. Write a small escaping writer (the `serde_json::ser::Formatter` trait, or a hand written
  string writer). Do not post-process the output of `serde_json`. The export file is read by people and by C#, so the escapes must match.
- **T9 Property names.** The C# source-generated context uses default options: property names are case-SENSITIVE (`"name"` does not match
  `Name`). Unknown properties are ignored. Missing properties take the C# initialisers. Golden `deserialize-property-names-are-case-sensitive`.
- **T10 Null elements and null strings.** C# `Deserialize` keeps a `null` list element (it is caught later as an invalid file by `TryImport`).
  Rust rejects it in `deserialize` (`Malformed`), which gives the same user outcome. A JSON `null` string property becomes `""` in Rust
  (C# keeps null); both fail the name check. These two cases are DIVERGENCE comments, not golden cases.
- **T11 Lenient operation.** `Operation` accepts names, numbers and the alias `Delete` (lenient converter, W1-02). Write it by name.
- **T12 Undefined operation.** C# can hold `(FileOperationType)99`; Rust cannot. The C# `Enum.IsDefined` checks have no twin, and the
  test `HasInvalidActions_UndefinedOperation` is ported as "not representable" (a comment), not as an assertion. The JSON value `99` is a
  `Malformed` error in Rust. Not in the golden (open question 6).
- **T13 Destination policy.** Only Move and Copy are checked. The C# `default:` branch (not Ok, not escapes) is `invalid`, which includes
  `Empty`. Recycle destinations are never read.
- **T14 Stale rows.** After `replace_all` every old row id is dead; a save through an old id returns `false` (golden
  `script-replace-all-makes-open-row-stale`).
- **T15 Localized arguments.** Use `LocArg::new("name", ...)` and `LocArg::new("error", ...)`. Do not format the message in Rust.
