## Semantics (C# is the spec)
1. **`supports`** (baseline): `true` for Diagnostics, SkippedFiles, BatchReview, ZoomPrompt, Benchmark, ActionProfiles, Recovery; Settings -> `settings_enabled()`; ExternalEditors and RenamePrompt -> `false` (they are Rust-only variants, D-W8B5-415). `settings_enabled()` = the option when given, else `settings::catalog::is_complete()`. The golden has 24 port rows (8 windows x `settings_enabled` true / false / default) and 16 router rows (`supports` is `true` for all of them), plus 3 `initial` rows (one per `settings_enabled` true / false / default: open count 0, benchmark not open, the `settings_enabled` value) and 1 `kinds` row (24 + 16 + 3 + 1 = 44) (the 8 baseline names in order `Settings, Recovery, Diagnostics, Benchmark, SkippedFiles, BatchReview, ZoomPrompt, ActionProfiles`; the Rust enum lists these 8 first and then the 2 extra variants).
2. **Common rules.** Every method first checks `disposed` and answers the "cancelled" value (`false`, `None`, nothing) without calling the factory (stricter than the C#, where `ShowSkippedFiles`, `ShowBatchReview`, `PromptCustomZoom` and `ShowActionProfiles` built the dialog first and only `Run` answered `IdCancel`; no observable difference except that no dialog object is constructed). `run(dialog, owner)`: registers `OpenDialog { id, dialog }` (a counter, not a handle comparison), `dialog.show_modal(owner, ready.as_deref(), message_loop.as_ref())`, removes the entry on every path (a guard struct, also when `show_modal` fails or a hook panics); `Err(DialogError)` -> `log.error("Secondary window failed", Some(&error))` and `ID_CANCEL` (D-W8B5-414); a panic is not caught (it was captured by `pending_panic` and resumed by `show_modal`). `run_prepared(prepared, owner)` = `(prepared.finish)(run(&prepared.dialog, owner))`. A method whose factory answers `None` returns the cancelled value.
3. **`show_settings`**: `dialogs.settings(target, opener)` where `opener` is the `ActionProfilesOpener` made from `Weak<Self>`: `move |owner, actions| weak.upgrade().and_then(|port| port.show_action_profiles(owner, actions))` (the C# passed the method group `ShowActionProfiles`, which closes over `this`; a `Weak` avoids the cycle port -> factory -> dialog -> opener -> port). `finish` answers the C# `dialog.Saved` (true after Save or Apply).
4. **`show_recovery`**: the factory reads the journal (it calls `try_read_recovery_entries`, RV-A14) and builds the dialog; `None` -> nothing. The port only runs it.
5. **`show_benchmark`** (the single instance): `disposed` -> nothing; `benchmark` slot is `Some(d)` with `!d.dialog.is_closed()` -> `d.dialog.activate()` and return (no factory call); else `dialogs.benchmark(folder)` -> `None` -> nothing; else store `OpenDialog` in the `benchmark` slot AND in `open`, then `show_modeless(owner, message_loop.clone(), ready.as_deref(), Some(closed))` where `closed` (a `FnOnce` holding a `Weak<PortState>` and the id; D-W8B5-421) removes the entry from `open` and clears the slot only when the slot still holds THIS id (the C# `ReferenceEquals`). `Err` from `show_modeless`: remove from `open`, clear the slot, log `"Secondary window failed"` (the C# `catch { ..; throw; }`). The Benchmark window is not modal and the owner stays enabled.
6. **`dispose`**: idempotent (`disposed` set first). Take a snapshot of `open` (clone the `NativeDialog` handles; do not hold the `RefCell` borrow while closing: a modeless dialog removes itself from `open` from its `closed` callback during `close()`), then `close()` each from the LAST to the FIRST. The router's `dispose` forwards to `native.dispose()`.
7. **`router`**: `pick(kind)` = `native.supports(kind)` then the native port; each method is `pick(kind).map_or(cancelled, |port| port.method(..))` with the kinds Settings, Recovery, Diagnostics, Benchmark, SkippedFiles, BatchReview, ZoomPrompt, ActionProfiles. The C# router uses `SecondaryWindowKind.ExternalEditors` / `RenamePrompt` for four more members that are not ported.
8. **`try_read_recovery_entries`**: `read()` -> `Ok(v)` -> `Some(v)` (no log, no dialog); `Err(e)` -> `log.error("Could not read the operation journal for the Recovery window", Some(&e))`, `show_error(&recovery_title(), &recovery_read_failed(e.to_string()))`, `None`. Only `io::Error` is caught (the C# `IOException or UnauthorizedAccessException`): other error types are the caller's type system, a panic propagates.
9. **Thread affinity.** The C# `VerifyUiThread` throws on another thread. The Rust port holds `Rc` and is `!Send`, so another thread cannot hold it: compile-time (D-W8B3H-4). Nothing to port; the pure test `win32_secondary_window_port_is_not_send` documents it.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (leaks): every dialog that is opened is removed from `open` exactly once (guard), `PortState` is shared with the `closed` callback of the Benchmark window by `Weak` (the port owns the dialog and the dialog owns the callback: a strong `Rc` would be a cycle for as long as the window stays open, e.g. when the port is dropped without `dispose`; a failed `upgrade()` makes the callback a no-op), the `ActionProfilesOpener` holds only a `Weak` of the port.
- T2 (re-entrancy): the modal loop dispatches messages and dispatcher work; a hook may call `dispose`, `show_*` again (nested Settings -> Action profiles) or `open_count()` from inside `run`; no `RefCell` borrow of `open` / `benchmark` is held across `show_modal`, `show_modeless`, `close`, `activate` or a factory call (clone the handle out, release the borrow, then call).
- T3 (panics): R0003 - no `unwrap` / `expect` / `panic!`; a `DialogError` is logged and answers "cancelled"; a panic captured by `pending_panic` is resumed by `show_modal` and passes through.
- T4 (identity): dialogs are identified by the counter id, never by `hwnd` (a closed dialog has `hwnd == 0`) and never by `Rc::ptr_eq` (the handle has no such method).
- T5 (disposed): after `dispose` no factory method is called and the owner is never disabled.
- T6 (ownership of the router): `SecondaryWindowRouter` holds the port by `Rc`; `LazySecondaryPort` (18b) holds the router; nothing holds the `LazySecondaryPort` strongly from inside a dialog.

## Error mapping
| C# | Rust |
|---|---|
| `InvalidOperationException` (wrong thread) | unrepresentable (`!Send`) |
| `GetService<T>() is null` -> return | the factory answers `None` |
| exception from `ShowModal` (`Win32Exception`, `ArgumentException`, `InvalidOperationException`) reaching the guarded caller | `log.error` + "cancelled" (D-W8B5-414) |
| `ShowModeless` throws after registering | removed, slot cleared, logged |
| `ArgumentNullException.ThrowIfNull(actions/entries/items)` | unrepresentable (slices) |
| `IOException` / `UnauthorizedAccessException` reading the journal | `io::Error` in `try_read_recovery_entries` |
