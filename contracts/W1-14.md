## Semantics notes

### The line format (writer: `JournalEntry::to_line`)
Equals `JsonSerializer.Serialize(entry)` with default options (the journal appends the CRLF terminator elsewhere).
- One compact object, no spaces. Member order: `Id, Type, State, Source, Destination, Size, LastWriteUtc, TimestampUtc, Error`, then ONLY when `Some`: `ErrorCode, Permanent, Undo, GroupId, GroupMembers`. `Destination` and `Error` are written as `null` when `None`. This is exactly the declaration order of the stubbed struct with `rename_all = "PascalCase"`; `Some(vec![])` for `GroupMembers` is written as `[]`.
- `Type`/`State` are the variant names. `Size` is a plain decimal i64. Booleans `true`/`false`.
- Group member objects: `Source, Destination (null when None), Size, LastWriteUtc, Permanent` (always, `false` included).
- Timestamps: `JournalDateTime::to_json`. Kind Utc: `yyyy-MM-ddTHH:mm:ss[.fffffff]Z`, fraction trimmed of trailing zeros and omitted when zero (`DateTimeUtc::to_json`). Kind Unspecified: the same text WITHOUT `Z` (so `default(DateTime)` is `0001-01-01T00:00:00`). A missing timestamp member therefore round-trips as `"LastWriteUtc":"0001-01-01T00:00:00"`.
- String escaping is NOT serde_json's default. The default `JavaScriptEncoder` of System.Text.Json writes:
  - `"` as `"` (not `\"`), `\` as `\\`, `/` unescaped
  - control chars: `\b \t \n \f \r` for 0x08 0x09 0x0A 0x0C 0x0D; every other 0x00-0x1F as `\u00XX`
  - `& ' + < > `` ` `` and DEL 0x7F as `\u00XX`
  - EVERY non-ASCII char as `\uXXXX`, per UTF-16 code unit (U+1F600 -> `😀`, U+0085 -> `\u0085`, U+2028 -> ` `)
  - hex digits are UPPERCASE everywhere (`é`, `\u007F`, `\u000B`).
  Implement this as `DotNetJsonFormatter` (a `serde_json::ser::Formatter`): `serde_json` calls `write_char_escape` for `"`, `\` and ASCII control chars (override with the .NET spelling above; its own spelling is lowercase `\u001f`), and `write_string_fragment` for all other text runs (escape `& ' + < > `` DEL` and non-ASCII there). `to_line` = `Serialize` the entry with `serde_json::Serializer::with_formatter(Vec::new(), DotNetJsonFormatter)`, then `String::from_utf8`. No `unwrap`/`expect`: on the impossible error return an empty string.
- Rust `String`s cannot hold lone surrogates, so C#'s `�` replacement of a lone surrogate has no Rust counterpart (no golden case).

### The reader (`try_parse`, `try_parse_utf8`) - accept/reject rules
`try_parse` takes text, `try_parse_utf8` takes bytes (no terminator); both must give the same answer for the same valid UTF-8 (the golden asserts both for every line). Apply the steps in this order; any failure -> `None`. Never panic.
1. **Depth.** More than 64 nested containers anywhere in the line (count `{`/`[` outside strings) -> `None`. 64 is accepted (an object plus 63 nested arrays), 65 is rejected. (`serde_json`'s own limit is 128, so count yourself, once, before parsing.)
2. **Strict JSON, one value.** RFC 8259 only: no comments, trailing commas, single quotes, unquoted keys, BOM, NUL bytes or UTF-16 text; whitespace is space/tab/LF/CR only; exactly one top-level value, nothing but whitespace after it (so `{...}{...}`, `{...}garbage` and `{...} // c` are rejected; a trailing CR/LF/CRLF is fine). Empty or whitespace-only input -> `None`. Use `serde_json::Deserializer::from_str` / `from_slice` and call `.end()`.
3. **Top level must be an object.** `null`, `[]`, `"x"`, `1`, `true` -> `None`.
4. **Members are read in file order with a hand-written `Visitor::visit_map`** (a derived `Deserialize` is NOT enough: serde's derive rejects duplicate names). Names are matched exactly and case-sensitively after JSON unescaping (`"Id"` is `Id`; `"id"`, `"ID"` are unknown and ignored). An unknown name: skip its value with `serde::de::IgnoredAny` (any valid JSON, including nesting up to the depth limit and a lone-surrogate escape such as `"\ud800"`, is fine inside it).
5. **Duplicate names:** every occurrence is decoded and validated in sequence, the LAST one wins. A bad earlier occurrence rejects the line even if a later one is good (`"Size":"x","Size":5` -> `None`), and a good earlier one is overridden by a bad later one (`"Type":"Move","Type":"Bogus"` -> `None`).
6. **Leaf values: decode from the raw JSON text.** Read each known member's value as `Box<serde_json::value::RawValue>` and decode `raw.get()` yourself (see "Why RawValue"). Per member:

| Member | Accepts | Anything else | Missing |
|---|---|---|---|
| `Id`, `Source`, `Destination`, `Error`, `ErrorCode`, `GroupId` | JSON string, or `null` (= `None`) | reject the line | `None` |
| `Size` | integer token: optional `-`, digits, NO `.`/`e`/`E`, fits i64 (`-0` is `0`) | `null`, string, `1.5`, `12.0`, `1e3`, overflow: reject | `0` |
| `LastWriteUtc`, `TimestampUtc` | JSON string accepted by `JournalDateTime::parse_json` | `null`, number, garbage text, `2026-13-01...`: reject | `JournalDateTime::default()` |
| `Permanent`, `Undo` (entry level) | `true`, `false`, `null` | strings, numbers: reject | `None` |
| `GroupMembers` | `null` (= `None`) or an array whose elements are objects or `null` | object, string, number, a non-object element (`[5]`, `["x"]`, `[[]]`): reject | `None` |
| `Type`, `State` | see 7 | see 7 | not seen |

   Group member objects follow the same rules per member: `Source`, `Destination` (string or null), `Size` (as above, missing = 0), `LastWriteUtc` (as above, missing = default), `Permanent` (`true`/`false` ONLY: `null` or a string rejects the line; missing = `false`); unknown member names are skipped; names are case-sensitive (`"source"` alone leaves Source missing). A `null` element is remembered as "null member" (rejected in step 8, but a later duplicate `GroupMembers` can replace the whole list first).
7. **`Type` and `State` recognition** (the heart of the C# class). For each occurrence decide "recognized or not" and the value; the final entry is accepted only if the LAST occurrence of BOTH members is recognized (a missing member counts as not recognized).
   - JSON string: contains `,` anywhere -> not recognized (`"Move,Copy"`, `"Move, Copy"`, `","`). Otherwise `t = trim(text)` with Unicode whitespace (`str::trim`, so NBSP/ideographic space are stripped, NUL is not). Recognized when `t` equals, ASCII-case-insensitively (use `pr_core::text::eq_ignore_case`), a variant name (`Move Copy Recycle` / `Prepared Committed Failed Dismissed`), or (only for `Type`) the alias `Delete` (= `Recycle`; NOT valid for `State`), or `t` is `[+-]?[0-9]+` (ASCII digits only, e.g. `"1"`, `" 2 "`, `"+1"`, `"01"`, `"-0"`) fitting i32 and equal to a defined discriminant (`Move=0 Copy=1 Recycle=2`; `Prepared=0 Committed=1 Failed=2 Dismissed=3`). Not recognized: `""`, `"  "`, `"Rename"`, `"0x1"`, `"1.0"`, `"1 2"`, `"9"`, `"Mo\u0000ve"`, `"Move\u0000"`, Arabic-Indic digits, fullwidth letters, and `"Dismiſſed"` (U+017F is NOT folded to `s`).
   - JSON number: recognized only when it is an integer token (no `.`/`e`/`E`; `-0` counts as 0) that fits i32 and is a defined discriminant. `1.0`, `1e0`, `2.5`, `-1`, `3` (for Type), `4` (for State), `2147483648` -> not recognized.
   - `null`, `true`, `false`, objects, arrays -> not recognized (their content is skipped).
   - The value of a recognized occurrence is the variant it names (`"delete"` -> `Recycle`, `"1"` -> `Copy`, `2` -> `Recycle` for Type / `Failed` for State).
8. **Acceptance of the assembled entry** (all must hold): Type and State recognized (7); `Id` is `Some` and non-empty (a single space is fine; NUL inside is fine); `Source` is usable; every `GroupMembers` element is non-null with a usable `Source` and a `Destination` that is `None` or contains no NUL. "Usable" = `Some`, not empty/whitespace-only (`char::is_whitespace` for EVERY char, so `" 　"` is blank), and no NUL char (`'\0'`) anywhere.
9. **Destination normalisation:** an entry-level `Destination` that is `Some` but not usable (empty, whitespace-only, containing NUL) becomes `None`. Member destinations are NOT normalised (`""` and `"  "` stay as they are).
10. **Timestamps:** `JournalDateTime::parse_json` wraps `DateTimeUtc::parse_json` (already pinned by `datetime-json` golden: it accepts `yyyy-MM-dd`, `THH:mm`, `:ss`, any fraction digits, `Z`, offsets). Source kind `Utc` -> `JournalDateTime::utc(v)`; `Unspecified` (no zone, date-only, `T08:15`) -> `JournalDateTime::unspecified(v)`; `Offset` -> `JournalDateTime::utc(v)` where `v` is already converted to UTC (deliberate difference D1 below).

### Why RawValue
`serde_json` parses `-0` as a float, but `System.Text.Json` accepts `"Size":-0` and `"Type":-0` as the integer 0 (`TryGetInt32`/`GetInt64`), and `1.0`/`1e3` as NOT integers. Only the raw text can tell `-0` from `-0.0`, so leaf values are decoded from `RawValue::get()`: first byte `"` -> `serde_json::from_str::<String>(raw)` (this also rejects bad escapes and lone surrogates, like `GetString()`); first byte `-`/digit -> an integer iff it has no `.`, `e`, `E`, then `raw.parse::<i64>()`; `n`/`t`/`f` -> `null`/`true`/`false`. RawValue of an invalid-UTF-8 string is an error (reject), while `IgnoredAny` of an unknown member does not validate UTF-8 (accept), exactly like C# (golden bytes case "invalid byte FF inside an unknown member string").

### Deliberate differences from C# (no golden; document in the module doc, already there)
- D1: a timestamp with a UTC offset (`+07:00`) is converted to UTC and written back with `Z`. C# turns it into a `DateTimeKind.Local` value whose ticks and re-serialized text depend on the machine time zone, so no portable golden exists. The app never writes such texts.
- D2: invalid UTF-8 inside a property NAME rejects the line (`serde_json` validates keys); C# tolerates it in an unknown name. The app never writes such lines.

## Traps checklist
§7 items 5 (kind Utc vs Unspecified; ticks), 6 (exact property names; missing -> defaults; unknown ignored; round-trip must not drop a field: `Error:null` and `Destination:null` are written), 8 (`None` vs `Some("")`: member destinations keep `""`, entry destination `""` becomes `None`), 9 (each C# `catch (JsonException)` branch is a reject; a lone `Err(_)` for several causes is fine here because C# also returns plain `null`), 1 (enum names via `eq_ignore_case`), 2 (no locale anywhere; digits are ASCII). Also: serde derive for `Deserialize` is forbidden here (duplicates, per-occurrence validation, `Delete` alias, recognition tri-state).

## Open questions
1. `JournalGroupMember` is also listed in W1-09 (`file_actions::types`). This unit defines it here with `JournalDateTime` (needed for byte-identical missing/Unspecified timestamps). The lead must remove it from W1-09 or make `types` re-export this one; two definitions would not interoperate.
2. `JournalDateTime` instead of plain `DateTimeUtc` in the entry: required because `default(DateTime)` and zone-less texts are `Unspecified` and serialize without `Z`. Other units that fill a `JournalEntry` (journal writer, undo, recovery) must construct `JournalDateTime::utc(..)`.
3. C# `Equals` on `JournalEntry` ignores `DateTime.Kind` (compares ticks); `JournalDateTime`'s `PartialEq`/`Hash` do the same. If a later unit needs the strict comparison it can compare `unspecified` explicitly.
4. The depth pre-scan and `RawValue` add a little overhead per line; the C# class was tuned for startup scan speed (single pass). Measure in the journal WU; do not optimise here.
5. `FileOperationType` / `JournalState` ownership (W1-01) is assumed to provide the exact variant names above; if W1-01 names differ, only the three helper `match`es change.
