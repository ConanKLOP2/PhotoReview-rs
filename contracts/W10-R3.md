## Semantics

- `Cargo.lock` version 4 and `cargo metadata --locked --offline --format-version 1` at this HEAD show only `registry+https://github.com/rust-lang/crates.io-index` external sources. External crate licence expressions observed: `MIT`, `MIT OR Apache-2.0`, `Apache-2.0 OR MIT`, `Unlicense OR MIT`, `(MIT OR Apache-2.0) AND Unicode-3.0`. Thus allow MIT, Apache-2.0, Unlicense, Unicode-3.0; deny unknown/unlicensed and copyleft Rust crates pending review. Re-run metadata at implementation; the lockfile itself has no licence fields.
- `[advisories]`: fail on active vulnerability and unsound advisories; do not blindly ignore a yanked/unmaintained dependency. `[bans]`: warn on multiple versions because `cargo metadata --locked --offline` currently contains both `syn` 2.0.119 and 3.0.9; deny wildcards and unknown git sources unless reviewed. `[sources]`: only crates.io registry; no git source. Proposed exact TOML is in `docs/drafts/deny.toml` and must be checked against the installed cargo-deny schema.
- `crates/pr-libraw/Cargo.toml` is MIT (workspace), while the **native** `libraw.dll` is loaded at run time by `crates/pr-libraw/src/native.rs`. Cargo-deny never sees that DLL. R4's verifier enforces dynamic loading, separate DLL, pins, LGPL/CDDL texts, notice and corresponding-source offer. Do not assert that `cargo deny` proves LGPL compliance.
- CI fragment runs its audit steps on Cargo file PR changes and scheduled nightly advisory checks; the job itself reports success when a PR has no Cargo change. The existing `.github/workflows/ci.yml` already runs on all PRs. Add `schedule: [{cron: '...'}]` to its `on` block after choosing the nightly time. Pin the chosen installer/action and version before integration. D-W10release-4 recommends a locked `cargo install` only after a real version is selected.
