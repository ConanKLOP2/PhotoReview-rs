## Semantics notes (C# is the spec; line numbers are of RenderGeometry.cs)

### Colours and interpolation (1-26)
1. `color_from_rgb(r, g, b, a)`: each channel is `channel as f32 / 255.0` (C# `r / 255f`: a float division of the byte; never integer
   division). Alpha is also divided by 255 (`a / 255f`). `dark_canvas()` = `color_from_rgb(0x10, 0x10, 0x10, 0xFF)`.
2. `image_interpolation_from_scaling_quality`: `Linear` -> `Linear`; `HighQuality` -> `HighQualityCubic`. The Rust type is closed, so the C# rule
   "anything that is not Linear is cubic" has no reachable input beyond the two members; write it as `if Linear {Linear} else {HighQualityCubic}`.

### EXIF orientation (33-69)
3. `is_transposed` = `pr_imaging::orientation::is_transposed` (5..=8). Do not write a second copy.
4. `unoriented_rect(o, dest)`: `(0, 0, dest.height, dest.width)` when transposed, else `(0, 0, dest.width, dest.height)`. Origin is always 0,0.
5. `for_exif_orientation(o, dest)`: `raw = unoriented_rect(o, dest)`; `w = raw.width as f32`, `h = raw.height as f32` (the cast is of the
   unoriented rect, so for 5..=8 `w` is the destination HEIGHT). The orientation matrix `orient` is chosen by `o` (the C# switch expression in
   `ForExifOrientation`; copy the values literally, all f32):
   - 2: `(-1, 0, 0, 1, w, 0)`; 3: `(-1, 0, 0, -1, w, h)`; 4: `(1, 0, 0, -1, 0, h)`;
   - 5: `(0, 1, 1, 0, 0, 0)`; 6: `(0, 1, -1, 0, h, 0)`; 7: `(0, -1, -1, 0, h, w)`; 8: `(0, -1, 1, 0, 0, w)`;
   - any other `o` (including 1, 0, -1, 9): `IDENTITY`.
   The result is `compose(orient, translation(dest.x as f32, dest.y as f32))` (C# `orient * CreateTranslation(...)`: orient first).
   Pixel meaning (checked against `PixelOps.ApplyOrientation` in the C# test; raw pixel (u, v) of a W x H raw image goes to):
   1 (u,v); 2 (W-1-u, v); 3 (W-1-u, H-1-v); 4 (u, H-1-v); 5 (v, u); 6 (H-1-v, u); 7 (H-1-v, W-1-u); 8 (v, W-1-u). Here W, H are the RAW dimensions.

### Pixel types and tiling (72-143)
6. `PixelRect::right` = `x + width`, `bottom` = `y + height`, `is_empty` = `width <= 0 || height <= 0` (integers; no NaN case).
7. `compute_tiles(width, height, max, gutter)`: checks in this order, each one error variant: `width < 1` -> `Width`; `height < 1` -> `Height`;
   `max < 4` -> `MaxTextureSize`; `gutter < 0` -> `Gutter`. Then `gutter = min(gutter, max / 4)` (integer division, positive operands).
8. `split_axis(length, max, gutter)`: if `length <= max`: one span `(start 0, length, tex_start 0, tex_length length)`, no gutter. Otherwise
   `core = max - 2 * gutter`, `count = ceil(length / core)` (compute as `(length + core - 1) / core` in i64, see trap T5), and for each `i`:
   `start = i * core`, `end = min(start + core, length)`, `tex_start = max(0, start - gutter)`, `tex_end = min(length, end + gutter)`,
   span `(start, end - start, tex_start, tex_end - tex_start)`.
   `core >= max / 2 >= 2` after the clamp, so `count` is always finite and positive.
9. `compute_tiles` output: for each ROW span (outer loop), for each COLUMN span (inner loop): `TileSpec { texture: PixelRect(col.tex_start, row.tex_start,
   col.tex_length, row.tex_length), core: PixelRect(col.start, row.start, col.length, row.length) }`. Order rows-then-columns is part of the golden.

### Draw geometry (146-235)
10. `intersect(a, b)`: `x = max(a.x, b.x)`, `y = max(a.y, b.y)`, `right = min(a.right, b.right)`, `bottom = min(a.bottom, b.bottom)`, using
    `math_max` / `math_min` (NaN propagating, trap T2). Return `(x, y, right - x, bottom - y)` if `right > x && bottom > y`, else the zero rect
    `(0, 0, 0, 0)` (C# `default`). `right`/`bottom` are `a.x + a.width` etc. (C# `Right`, `Bottom`).
11. `rect_is_empty(r)` = `!(r.width > 0.0 && r.height > 0.0)` (trap T3).
12. `pixel_rect_to_rect_d(p)` = `(p.x as f64, p.y as f64, p.width as f64, p.height as f64)`.
13. `map_to_destination(source, dest, part)`: `sx = dest.width / source.width`, `sy = dest.height / source.height` (f64 division, no zero
    check: a zero source width gives inf/NaN, golden `map_to_destination` source `[0,0,0,50]`). Result
    `(dest.x + ((part.x - source.x) * sx), dest.y + ((part.y - source.y) * sy), part.width * sx, part.height * sy)`. Keep the exact operation order.
14. `try_snap_pixel_exact(device, dest, source)` (C# 175-234). Returns `PixelSnap { snapped, exact }`; `snapped` starts as `dest` and stays
    `dest` on every `exact: false` path.
    a. `if rect_is_empty(source) || rect_is_empty(dest)` -> `exact: false`.
    b. `sx = dest.width / source.width`, `sy = dest.height / source.height`.
    c. Linear part of `diag(sx, sy) * L`, where `L` is the device matrix: `a = sx * m11`, `b = sx * m12`, `c = sy * m21`, `d = sy * m22`, all
       computed in f64 (m11..m22 converted from f32 with `as f64` BEFORE multiplying; trap T4).
    d. `axis_aligned = is_zero(b) && is_zero(c) && is_unit(a) && is_unit(d)`; `swapped = is_zero(a) && is_zero(d) && is_unit(b) && is_unit(c)`.
       If neither -> `exact: false`.
    e. Corner in device space, f64: `cx = dest.x * m11 + dest.y * m21 + m31`, `cy = dest.x * m12 + dest.y * m22 + m32` (left-to-right sums).
       `dx = round_ties_even(cx) - cx`, `dy = round_ties_even(cy) - cy` (trap T1).
    f. If `is_zero(dx) && is_zero(dy)` -> `exact: true`, `snapped = dest` (returned BEFORE the determinant check).
    g. `det = m11 * m22 - m12 * m21` (f64, the device matrix, NOT `sx`-scaled). If `|det| < EPSILON` -> `exact: false`.
    h. Move the corner by the inverse of the device linear part (row vector): `lx = (dx * m22 - dy * m21) / det`, `ly = (dy * m11 - dx * m12) / det`;
       `snapped = (dest.x + lx, dest.y + ly, dest.width, dest.height)`; `exact: true`.
    `is_zero(v) = |v| < EPSILON`; `is_unit(v) = | |v| - 1 | < EPSILON`. Both f64 and both with `<` (not `<=`).

## Traps (write these as tests; each one has a golden case)
- **T1 Banker's rounding.** C# `Math.Round(double)` is `MidpointRounding.ToEven`. Rust `f64::round` rounds half away from zero. Use
  `f64::round_ties_even` (stable). Golden `snap` cases with destination 10.5/4.5 (-> 10, 4) and 11.5/0.5 (-> 12, 0) pin it.
- **T2 NaN in Min/Max.** `Math.Max`/`Math.Min` return NaN when an operand is NaN (.NET Core 3.0+). `f64::max`/`min` IGNORE a NaN operand.
  Use `math_max`/`math_min` (write them with explicit `if a.is_nan() || b.is_nan() { return f64::NAN }` or an `if`/`else` on comparisons).
  Golden `intersect` cases with `"NaN"` in `a.x` / `b.y` return the zero rect; with `f64::max` the Rust result would be a non-empty rect.
- **T3 NaN in emptiness.** `IsEmpty` is `!(w > 0 && h > 0)`: NaN is EMPTY. The Rust form `w <= 0.0 || h <= 0.0` says NaN is not empty. Golden
  `is_empty` rows `[0,0,"NaN",1]` and `[0,0,1,"NaN"]` must be `true`.
- **T4 Operation order and f32 -> f64.** C# multiplies a float matrix entry by a double (`sx * deviceTransform.M11`): the float is widened to double
  first. Rust must do `(m11 as f64)`, not f32 arithmetic. In `ForExifOrientation` the arithmetic stays f32 (`w`, `h` are f32 casts) and the
  translation is added as `compose`. Do not reorder any sum: `((a*b) + (c*d)) + e` is the order of the C# expression.
- **T5 Integer overflow in `Split`.** C# computes `length + core - 1` in int (unchecked), which wraps for `length > i32::MAX - core + 1`
  and then throws `OverflowException` from the array allocation. Rust computes the ceiling in i64. No golden case reaches that range
  (see D-W8c-6). Do not add a `checked_*` that changes the other ranges.
- **T6 `gutter` clamp before everything.** `gutter = min(gutter, max / 4)` happens AFTER the `gutter < 0` check and BEFORE the split. Golden
  `tile_layout` `500x500 max 256 gutter 1000` clamps to 64 (core 128, 4 columns). Without the clamp, `core` is negative.
- **T7 Snap returns early.** When the corner is already on the grid, `exact` is true with `snapped == dest`, even if the determinant would be
  tiny; the `det` check is after it. A degenerate device matrix (all zeros) returns `exact: false` at step d, not at step g.
- **T8 Destination flip is not drawn.** `try_snap_pixel_exact` with a negative destination width returns `exact: false` (step a: `rect_is_empty`).
  A negative SOURCE width does too. Do not "fix" it by taking `abs`.
- **T9 Matrix product order.** `Matrix3x2 * Matrix3x2` in System.Numerics: `(a * b)` applies `a` first. In `compose(self, rhs)`:
  `m11 = a.m11*b.m11 + a.m12*b.m21`, `m12 = a.m11*b.m12 + a.m12*b.m22`, `m21 = a.m21*b.m11 + a.m22*b.m21`, `m22 = a.m21*b.m12 + a.m22*b.m22`,
  `m31 = a.m31*b.m11 + a.m32*b.m21 + b.m31`, `m32 = a.m31*b.m12 + a.m32*b.m22 + b.m32`. Verify with the golden `exif_matrix` rows
  (`compose` with a translation fills m31/m32 from `b`).
- **T10 `Vector2.Transform` and CreateRotation in tests.** C# test helpers use f32 `Vector2.Transform` and `Matrix3x2.CreateRotation`. In Rust
  the test helpers compute `x*m11 + y*m21 + m31` in f32 in that order; `rotation(r)` = `(cos r, sin r, -sin r, cos r, 0, 0)` in f32.
- **T11 Colour division.** `r / 255f` is float division. `16 / 255f` in the C# test is also a float expression. In Rust write `r as f32 / 255.0_f32`.
  Do not compute `(r as f32 * (1.0 / 255.0))`: it can differ in the last bit (the golden compares bits).
- **T12 Exif value outside 1..8.** Identity, not an error: `o = 0, -1, 9, 10` all give the identity matrix plus translation. The
  `unoriented_rect` for them is NOT transposed (only 5..=8 swap).

## Decisions taken in this contract (D-W8c-n; the lead may overrule in `contracts/README.md`)
- **D-W8c-1 Owner of `ColorF`, `ImageInterpolation`, `Matrix3x2`, `PixelRect`, `TileSpec`.** These are geometry and draw-parameter types that the
  pure geometry produces, and W8-12a (`render::contracts`, which depends on 01c) imports them. They live in `viewport::render_geometry`.
  `RectD` is NOT defined here; it is 01a's (`input::primitives`, D-W8-01a-1: 01a ports the whole `InputPrimitives.cs` because `viewport` needs `RectD`).
  W8-05a adds tests only to that file.
- **D-W8c-2 `is_transposed` is re-exported**, not re-ported (`pr_imaging::orientation::is_transposed`; C# `ImageTransforms.IsTransposed` and
  `ExifOrientation.IsTransposed` are the same expression).
- **D-W8c-3 `Matrix3x2` is our own type** (no `windows`/`System.Numerics`), f32, row-vector convention. The draw context converts it to the
  Direct2D matrix at the boundary (W8-12).
- **D-W8c-4 Errors as values.** `ArgumentOutOfRangeException` becomes `TileLayoutError`; the golden records `param` names
  (`width`, `height`, `maxTextureSize`, `gutter`) so the variant mapping is checked.
- **D-W8c-5 `PixelSnap` instead of `out` + `bool`.** `snapped` is always set (C# also sets it on the false paths).
- **D-W8c-6 Accepted divergence (`// DIVERGENCE:`):** for `length > i32::MAX - core + 1` C# throws `OverflowException` (negative array size),
  Rust returns the tiles (T5). No real image reaches it (images are decoded in memory first). No golden case.
