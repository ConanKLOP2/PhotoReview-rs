## Semantics
1. Send one GET of the given HTTPS URL, with the supplied User-Agent and Accept and no body. The request starts at HTTP/1.1 (`HttpRequestMessage.Version` default). `get` returns after the final response headers; `HttpResponse.body` streams the rest. Transfer decoding must be complete before the checker applies its 1 MiB cap. Apply content decompression only if a local .NET 10 probe proves that the default handler does. Content-Length is represented as `Option<u64>`, never truncated to `usize`.
2. Use the .NET 10 proxy selection and redirect policy of H1. WinHTTP's machine preconfiguration is not the user's `HttpClient.DefaultProxy`; read environment first, then current-user WinINet/IE configuration and PAC/WPAD. Resolve proxy again on a redirected URL. Use Windows certificate validation; do not disable errors or pin certificates.
3. One deadline starts before proxy discovery and runs through DNS, connect, TLS, redirects, headers and **every** body read. The returned body retains the deadline and a cancellation registration. An expired deadline yields `HttpError::Timeout`; user cancellation yields `HttpError::Canceled`. Close the request handle to cancel pending asynchronous operations; lifetime and completion callbacks must not use freed memory. `WinHttpSetTimeouts` is a secondary per-phase cap only.
4. Apply the H1 classification table to WinHTTP/OS errors. A successful HTTP 403/429 is a response, not a transport error. Reject an invalid/malformed response as `HttpRequestError::InvalidResponse` only if supported by an OS error code or local socket repro. Preserve repeated headers; the checker parses Retry-After and X-RateLimit-Remaining.
5. Release session/connection/request handles on success, failure, timeout, cancellation and body drop. A response body that is not consumed still closes its request handle. Keep FFI and `// SAFETY:` comments in this crate.

No pure oracle can prove live WinHTTP proxy/TLS/redirect behavior. Use a fake in-process local socket server for F tests, with responses for redirects, slow headers, slow body, oversized headers/body, truncated chunked response and cancellation. Use a separately ignored N test for current-user proxy, PAC, Windows trust and desktop cancellation; never contact GitHub in automated tests.

## Traps
- Synchronous `WinHttpReadData` plus phase timeouts does not prove prompt cancellation. Use asynchronous WinHTTP and request-handle cancellation; heed the documented race where close and completion can both occur.
- Automatic decompression and HTTP version must follow measured .NET defaults, not WinHTTP defaults.
- The checker requests one response and streams; buffering the whole response defeats its cap.
