## Semantics (C# is the spec)
1. **Shape (D-W8B5-601, -301).** `RecoveryContent` is the C# object minus the base class; `RecoveryDialog` pairs it with `NativeDialog::with_chrome(content, chrome)`. A content method never stores the `NativeDialog`; every hook gets it. `RecoveryDialog::new` = `RecoveryContent::new` then `NativeDialog::with_chrome(content.clone(), chrome)`.
2. **`RecoveryContent::new`.** `presenter = RecoveryWindowPresenter::new(entries, options)`; seam defaults: `messages = NativeTaskDialogPort::new()`, `copy = |_| false`, `explorer = path_panel::start_explorer`; `ActionsState::new()` creates the inbox whose wake posts to `wake_target`. Nothing touches the OS.
3. **`on_initialized(dialog)`**, in this order: fill the combo box (`ComboBoxControl::add` the four `RECOVERY_FILTER_*` texts in that order, `select(0)`); `dialog.set_tooltip(id, text)` for `FILTER_ID` (`RECOVERY_FILTER_AUTOMATION_NAME`), `RECHECK_ID` (`RECOVERY_CHECK_RECHECK_AUTOMATION_NAME`), `CLEAR_SELECTED_ID`, `CLEAR_ALL_ID`, `RETRY_ID` (their `*_AUTOMATION_NAME`), `COPY_SOURCE_ID` and `COPY_DESTINATION_ID` (`RECOVERY_DETAIL_COPY_PATH_AUTOMATION_NAME`), `SHOW_SOURCE_ID` and `SHOW_DESTINATION_ID` (`RECOVERY_DETAIL_SHOW_IN_EXPLORER_AUTOMATION_NAME`); `wake_target.store(dialog.hwnd())`; `list::refresh_entries`; `initialized = true`; and when `auto_check`: `actions::start_checks`. (The C# subscription of `ResultChanged` is the presenter's `row_changed` call, D-W8B5-603.)
4. **`on_closed(dialog)`**: `presenter.borrow_mut().cancel_check()` (a short borrow); `closed.store(true)`; `wake_target.store(0)`; drain the inbox and `ready`: a `Retry` completion found there is logged (`AppLog::info("Recovery retry finished after the window closed: ..")` / `error` for an `Err`), `Check` completions are dropped (their token is cancelled). Idempotent. The worker side of a retry re-checks `closed` after its `send` and drains/logs leftovers itself (18v trap T9), which closes the window between the worker's check and the `on_closed` drain.
5. **Hooks** exactly as the stub docs: `on_cancel` = `!presenter.can_close()` (a failed `try_borrow` answers `true`: stay open); `can_close_by_user` = `presenter.can_close()` (a failed `try_borrow` answers `false`); `wait_cursor` = `restore::is_busy` (a `Cell`, no borrow).
6. **List.** `visible` holds presenter row indices (D-W8B5-604). `refresh_entries` in the order of its doc: the selected ENTRY IDS are read first (`ids[selected_rows]`), then the list is rebuilt, then `carried_selection(&ids, &new_visible_ids)` re-selects; an index that is no longer valid is skipped, never a panic. `list_item_text` for another control id or an out-of-range index returns `ListItemText { text: ListBoxControl::text_at(dialog.item(id), index), badge: None }`. The text is `row.title(&texts)` (the same string `refresh_entries` adds to the list box), `badge` is `Some(row.badge_text(&texts))`, the subtitle `row.subtitle(&texts)`, the colour `to_color_ref(row.badge_tone())` (each channel widened to `u32` before the shift: `rgb` gives `u8`). **Stale indices (D-W8B5-604):** `ListState` holds `visible_ids` (entry ids, same order as `visible`) next to `visible`; `refresh_entries` reads the selected ids from `visible_ids` by LIST POSITION, never from `presenter.rows()[visible[i]]`: after `dismiss` or a superseded retry the presenter rows shifted while the list still shows the old rows, and reading through the indices would re-select the NEIGHBOURS of the removed rows (C# kept row objects, so removed rows simply vanished from the selection). A test pins it: select rows 0 and 1 of 4, Clear selected, assert the list has 2 rows and NOTHING selected.
7. **Sizes and `layout_controls`.** Per the stub docs and the C# lines 861-923, with D-W8B5-312 arithmetic (`wrapping_*`, `/` truncating): `left_width = max(Dx(150), (content - gap) * 5 / 11)`, `right_width = max(Dx(150), client_width - m - right_x)`, `height = max(Dy(30), content_bottom - y)`. `SetListItemHeight(ListId, 2 * LineHeight + Dy(5))` is called between the list `place` and the "filter empty" `place`. The order of the `place` calls is part of the contract (the hand table).

**Hand table** (derived from the C# by a script replica; the golden `sizes` rows are authoritative for the sizes). ## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (re-entrancy / borrows): `presenter` is a `RefCell`; a borrow lives for ONE presenter call and never across `place`, `SendMessage`, a hook, `confirm` or `notify` (every OS call can re-enter the dialog procedure). Hooks that read the presenter (`list_item_text`...) use `try_borrow` and answer the default when it fails (a hook is never allowed to panic, R0003).
- T2 (stale indices): `visible` is rebuilt in the same UI turn as every row mutation; every `visible[i]` and `rows()[i]` is `.get(i)`.
- T3 (integer): `(content - gap) * 5 / 11` truncates; do not use `i32::clamp` where min can exceed max (see 18u `place_path_group`); layout arithmetic is `wrapping_*`. `to_color_ref` widens the `u8` channels to `u32` first (`u8 << 8` overflows).
- T3b (RefCell across the OS): `list.visible` / `list.visible_ids` are never borrowed across a `ListBoxControl::*` or `send_message` call: `LB_ADDSTRING`, `LB_SETSEL` and `LB_RESETCONTENT` can run `WM_DRAWITEM` / `WM_MEASUREITEM` synchronously, which calls `list_item_text` and borrows `visible` (a `BorrowMutError` panic on the UI thread, R0003). Replace the vectors in one statement, then call the controls.
- T4 (selection): `LBS_EXTENDEDSEL` list: selection is read with `ListBoxControl::selected_indices` (`LB_GETSELITEMS`), set with `set_selected`, cleared with `select_all(false)`.
- T5 (texts): no literal text outside tests; the Vietnamese/English switch is the localizer's.
- T6 (modal `show_modal`): the dialog is `Resizable`; `default_button_id = CLOSE_ID = ID_CANCEL`, so Enter closes (C# parity).
- T7 (UI-thread): no `unwrap`/`expect`/`panic!`; `unsafe` only in `pr-platform-win`. The three `LB_GETTOPINDEX` / `LB_SETTOPINDEX` / `LB_INITSTORAGE` messages have no `ListBoxControl` wrapper (`basic::send_int` is `pub(super)` to the controls module), so `list.rs` calls `user32::send_message` (an `unsafe fn`) three times with value arguments, each with a `// SAFETY:` comment. Everything else (`invalidate_rect`, `get_focus`, `set_focus`) is safe.
