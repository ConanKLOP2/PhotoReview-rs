## Semantics
### ScalingPolicy (scaling_policy.rs)
1. `choose`: returns `requested` unless `requested == HighQualityCubic && in_motion && is_heavy_downscale(...)`, then `Linear`.
   `NearestNeighbor` and `Linear` are never changed, in motion or not.
2. `is_heavy_downscale`: false when either source side is `<= 0`, or either destination side is `<= 0` or NaN (the C# check covers
   `destinationPixelWidth/Height` NaN only; a NaN destination is caught by the same test). Otherwise
   `ratio = (f64(sw) * f64(sh)) / (dw * dh)` and heavy means `ratio > 4.0` (strict; exactly 4.0 is not heavy).
   Destination `Infinity` gives `ratio = 0`, not heavy (golden case).
### FrameStats (frame_stats.rs)
3. `ticks_to_ms(ticks, freq) = ticks as f64 * 1000.0 / freq as f64` (C# `ticks * 1000.0 / Stopwatch.Frequency`, same operation order).
4. `record(frame, present)`: the ring holds the last `CAPACITY` frames (overwrite at `next`), `count` = min(count+1, CAPACITY), `total` + 1 always,
   `blocked_presents` + 1 when `present_ms >= 8.0` (at or above, `>=`).
5. `is_slow(end, present)`: `present >= 8.0 || end >= 8.0` (NaN is never slow here: both comparisons are false).
6. `record_slow`: kept only while `slow.len() < 64` AND `is_slow(end_draw_ms, present_ms)`. The first 64 are kept, never the last.
7. `frame_ms(p)` / `present_ms(p)` / `max_present_ms()`: empty ring gives `0.0`. Nearest rank over the samples held in the ring
   (`count` samples, not the whole capacity): sort a copy ascending, `rank = ceil(clamp(p, 0, 100) / 100 * count) - 1`, clamped to `[0, count-1]`.
   `max_present_ms` is the maximum over the held samples (not over `total`).
8. `reset()`: `next = 0`, `count = 0`, `total = 0`, `blocked_presents = 0`. The `slow` list is NOT cleared (C# `Reset`, trap T10).
### FramePacer (pacer.rs)
9. `mode_for(fullscreen, awaiting)`: `Immediate` if `degraded || awaiting || !fullscreen`, otherwise `VSync`.
10. `should_defer(ready)`: if `ready`: `deferred = 0`, return `false`. If not ready: if `deferred >= 3`: `deferred = 0`, return `false`
    (DeferredTotal unchanged). Else `deferred += 1`, `deferred_total += 1`, return `true`.
11. `observe_present(mode, present_ms)`: if `mode != VSync`: `consecutive_blocked = 0`, return `false`. If `present_ms < 40.0` (strict):
    `consecutive_blocked = 0`, return `false`. Otherwise `consecutive_blocked += 1`; if `consecutive_blocked >= 2 && !degraded`: set
    `degraded = true` and return `true`; else `false`. The counter keeps growing after degrading (harmless).
### ImageLayer (image_layer.rs)
12. `try_draw`: (a) `pixels.is_disposed()` -> `Ok(false)` with no cache call; (b) destination `width <= 0 || height <= 0` or any component NaN ->
    `Ok(false)`; (c) `cache.get_or_upload(pixels)`: `Err(RenderError::Disposed { .. })` -> `Ok(false)`; any other `Err` is returned;
    (d) `exif_orientation` in `2..=8` and `context.as_oriented()` is `Some(o)`: `o.draw_image_oriented(&*gpu, destination, exif_orientation,
    None, interpolation, opacity)`, then `Ok(true)`. Otherwise (orientation 1 or out of range, or `as_oriented()` is `None`):
    `context.draw_image(&*gpu, destination, None, interpolation, opacity)`; (e) `Ok(true)`. The C# null checks (`ArgumentNullException`) have no Rust counterpart (references cannot be null).
### FrameLog (frame_log.rs)
13. `format`: `format!("F gap={} frame={} endDraw={} present={}", fmt(gap, 1), fmt(frame, 2), fmt(end, 2), fmt(present, 2))` with
    `fmt` = `pr_perf::rules::fmt_fixed` (D-16a-7). No trailing line ending.
14. `open(path, freq)`: `OpenOptions::new().create(true).append(true).open(path)`; on success the log is open; errors are returned.
15. `from_environment(get, freq)`: `get(ENV_VARIABLE)`; `None` when absent or `trim().is_empty()`; else `open(path)`, with any error -> `None`.
16. `record(start, end, end_draw, present)`: no-op when closed. `gap = if last_frame == 0 { 0.0 } else { ticks_to_ms(start - last_frame, freq) }`;
    `last_frame = start` (set BEFORE the write, as C#); then write `format(gap, ticks_to_ms(end - start, freq), end_draw, present)` followed by
    `\r\n` in ONE `write_all` on the file. On any write error: `close()` (C# disposes on IOException; Rust closes on any io::Error).
17. `close()`: drops the file; idempotent; later `record` calls do nothing.

## Traps (docs/MULTI-AGENT-PLAN.md section 7; each has a golden or a test)
- T1 `int` product overflow: `sourcePixelWidth * sourcePixelHeight` in C# is cast to double FIRST (`(double)sw * sh`). In Rust use
  `f64::from(sw) * f64::from(sh)` (`i32 * i32` overflows at 46341). Golden `is_heavy: large source area ... 46340^2 over 1x1`.
- T2 Strict `>` for the heavy threshold (exactly 4x is not heavy): golden `is_heavy: exactly 4x`.
- T3 NaN destination: the `dw.is_nan() || dh.is_nan()` test runs before the multiply (C# returns `false`); golden `NaN destination height`.
- T4 The C# test is `presentMs < 40.0` (fast). For NaN that is false, so a NaN present counts as BLOCKED (golden `NaN counts as blocked`).
  Write it as `if present_ms < BLOCK_THRESHOLD_MS { fast } else { blocked }`. Do NOT rewrite it as `if present_ms >= BLOCK_THRESHOLD_MS { blocked }`
  with the branches swapped in a different shape: `NaN >= 40.0` is also false, so a `>=` test would make NaN FAST. Keep the `<` form.
- T5 `ObservePresent` on `Immediate` clears the streak; `ShouldDefer` at the limit does NOT count `DeferredTotal` (golden `defer: busy streak`).
- T6 `++_consecutiveBlocked >= 2 && !IsDegraded`: the event fires once (golden `raised once`), the streak keeps counting.
- T7 `ToMs` operation order: `ticks as f64 * 1000.0 / freq as f64`. Do not precompute `1000.0 / freq`: that rounds differently.
- T8 FrameLog gap quirk: `_lastFrame == 0` means "no previous frame", so a first frame at tick 0 keeps the next gap at `0.0` (golden
  `first frame at tick zero`). Keep the quirk.
- T9 FrameLog lines end with CRLF (C# `StreamWriter.WriteLine` on Windows = `Environment.NewLine`); the golden lines are compared after
  stripping CR/LF because `File.ReadAllLines` strips both. The Rust test reads with `lines()` and checks the raw bytes once (`\r\n`).
- T10 `FrameStats::reset` keeps `Slow` (golden `reset clears ring and counters but keeps the slow list`, `slow_count = 1`).
- T11 Percentiles use `count` samples (not `CAPACITY`), nearest rank, `clamp` before the division; the golden checks the 100-sample series
  and the ring (`count = 2048`, `frame_p100 = 1`).
- T12 `Format` decimals: C# `F` format and `pr_perf::rules::fmt_fixed` agree on exact ties (half to even on the exact binary value), and
  print `NaN`, `Infinity`, `-Infinity` (Rust's `{:.N}` prints `inf`). Use `fmt_fixed`, not `format!("{:.N}")`. Goldens: `exact binary ties`,
  `infinity is written as Infinity`.
- T13 Negative values that round to zero keep their sign (`-0.004` at `F2` is `-0.00`, `-0.001` at `F1` is `-0.0`; `fmt_fixed` does this). Golden
  `negative values that round to zero keep the sign`.
- T14 Counters are `i64` (C# `long`); `Count` is `usize` (C# `int`, never negative).
- T15 `FromEnvironment` whitespace-only value is `None` (`IsNullOrWhiteSpace`); a path with an interior NUL fails to open and is `None`.
- T16 Append mode creates the file if missing and never truncates; the open file must be readable by another process (Rust's default
  share mode on Windows includes `FILE_SHARE_READ`; golden-free test `record_is_visible_to_a_reader_while_open`).
- T17 `frame_stats` samples are always finite (they come from ticks), so the percentile sort needs no NaN ordering; do not add a `NaN` branch
  that changes the order of finite values.

## Open questions and decisions
- **D-16a-1 Crate placement and the `pr-app` edge (decision needed from the lead).**
  The plan puts `shell_viewing` in `pr_platform_win`, and this unit's ImageLayer and ScalingPolicy use `pr_app` traits and types. Today
  `pr-app` depends on `pr-platform-win` (its `spike` module and `r0001_spike` bin only), so the edge must be REVERSED for these stubs to
  compile: `pr-platform-win` depends on `pr-app`, and `pr-app` drops `pr-platform-win` when the spike is removed (W8-20b) or moved. Options:
  (A, recommended, used by the compile check) reverse the edge in the B1 integration PR (remove the `spike` module and the r0001 bin from
  `pr-app` first; the `ui-spike` feature moves with them) and let the whole `shell_viewing` tree depend on `pr-app`, as the plan's layering
  rule already implies; (B) move ScalingPolicy and ImageLayer to `pr_app::viewing` (pure, traits only) and keep the three std-only units in
  `pr_platform_win`; (C) keep the edge and put these two units in `pr-app`. Writer's choice: (A).
  The orientation seam is NOT decided here: W8-12a's D-W8-12a-5 (`DrawContext::as_oriented() -> Option<&mut dyn OrientedDrawContext>`,
  default `None`) is adopted as written. An earlier draft of this contract proposed a `draw_image_oriented` default method on `DrawContext`;
  it is withdrawn (it would not fix the `begin_draw` upcast by itself and duplicates W8-12a).
- **D-16a-2 Tick frequency is a parameter.** C# reads `Stopwatch.Frequency` inside the class. Rust takes `ticks_per_second` in `FrameStats::new`
  and `FrameLog::open/from_environment`; W8-13 passes the `QueryPerformanceFrequency` value once. Recommended (chosen); needed so that the goldens and
  the tests are deterministic.
- **D-16a-3 Environment variable and line ending.** AGENTS.md says Rust env vars use `PHOTOREVIEW_RS_*`, so the Rust variable is
  `PHOTOREVIEW_RS_FRAME_LOG`; the C# name is kept only as `CSHARP_ENV_VARIABLE` for the golden (same rule as D4 of `contracts/README.md`). The
  stall tool (`tools/diag/stall-experiment.ps1`, C# repo) must read the Rust file name when it is pointed at this app: this is a Different row.
  Lines end with CRLF (C# on Windows), so the file is byte-identical in format to the C# log.
- **D-16a-4 Degraded event.** The C# `event EventHandler? Degraded` becomes the `bool` returned by `observe_present` (true once). A callback
  would make `FramePacer` hold `Box<dyn FnMut()>` on the UI thread; the bool keeps the type `Debug`/`Default` and the logging at the caller.
- **D-16a-5 `PixelBuffer` disposal.** C# `IsDisposed` is kept as `PixelBuffer::is_disposed()` (pr_imaging). The caller that holds only a
  `Weak` or an `Option` decides what "released" means; this unit takes `&PixelBuffer`.
- **D-16a-6 Test kind.** The plan row says G for the whole unit. ImageLayer has no C# unit test and needs a `DrawContext` with a D2D draw target
  for its golden, so it is F (fakes, written from the C# doc comment). The other four are G (goldens) with F extras.
- **D-16a-7 Shared decimal formatter.** `FrameLog::format` reuses `pr_perf::rules::fmt_fixed` (already golden-checked against C#
  `F` output by W1-16/W1-17). Consequence: `pr-platform-win` depends on `pr-perf` (no cycle: `pr-perf` depends only on `pr-core`).
  Alternative: hoist `fmt_fixed` to `pr_core::text` (D8 of `contracts/README.md`, lead-owned); the lead may do that instead.
