## Precedence (the exact order of C# `TryResolve`; first match wins)
Keys: `pressed = (key == System) ? system_key : key`. "Ctrl" = `modifiers.contains(CONTROL)` (bit test, extra bits allowed).
"Bare" = `modifiers == NONE` (exact).
1. Fullscreen: `pressed == fullscreen` (any modifiers, any state) -> `Fullscreen`.
2. Escape (`key`, not `pressed`): `is_fullscreen` -> `ExitFullscreen`; otherwise `Close`. No image needed.
3. NextFolder, then PreviousFolder (any modifiers, no image needed).
4. FirstImage: on match, `has_image ? FirstImage : None` and STOP (no fall-through). Same for LastImage.
5. Undo: match AND Ctrl -> `Undo`; otherwise fall through. No image needed.
6. ToggleInfoOverlay (any modifiers, no image needed), then ToggleKeepZoom (same).
7. OpenFolder: match AND Ctrl -> `OpenFolder` (no image needed); otherwise fall through.
8. **Image gate:** `!has_image` -> `None`. Everything below needs an image.
9. Compare: on match, `(!is_compare_visible && !has_compare_pair) ? None : ToggleCompare`, and STOP (no fall-through).
10. ToggleCaptureMember: match AND `has_capture_pair` AND `!is_compare_visible` -> it; otherwise fall through.
11. Actions: the first `ActionBinding` (in list order) whose key matches AND Bare -> `RunAction(index)`.
12. Recycle: match AND Bare -> `Recycle`.
13. Skip (any modifiers). 14. ToggleFit. 15. ZoomIn, ZoomOut, ZoomActualSize. 16. ClickZoom.
17. FitWidth, FitWidth2, FitHeight. 18. CustomZoom. 19. Refresh. 20. Next, then Previous.
21. Only when NOT Ctrl: `Shift` bit -> `ForcePicker` = true. MoveToFolder (match), then CopyToFolder (match).
22. Otherwise `None`.

## Semantics notes
S1. Fullscreen is the only rule that reads `system_key`. Alt+F11 arrives as `(System, F11, Alt)` and matches; `(System, F4, Alt)`
    does NOT trigger the F4 action because every other rule uses `key` (= `System`, which never binds).
S2. Escape closes the window with no image and no binding (C# `key == KeyId.Escape`). The router with no settings still closes.
S3. `Rebuild` assigns every field from the settings: an empty or unparseable value is `None`; an action keeps the index of its
    position in the FULL list, so a skipped entry does not renumber the later ones.
S4. `ParseKey`: blank or whitespace (C# `string.IsNullOrWhiteSpace`) is `None`; otherwise `ShortcutKeyName.TryParse` (canonical
    spelling, reserved names rejected, numbers and comma lists rejected). Duplicate bindings are NOT rejected here (the validator
    in W2-02 does that); the precedence above decides between them.
S5. `ReviewCommand` for `Move/Copy` carries `ForcePicker` (C# `ForcePicker`). `Action(i)` carries the index; every other command has
    no action index (C# `ActionIndex = -1`; Rust `action_index: None`, see N2).
S6. Auto-repeat is NOT decided here (`ReviewCommandType.IgnoresAutoRepeat`, W8-05a).

## Traps (docs/MULTI-AGENT-PLAN.md section 7, plus the router-specific ones)
T1. **Early returns versus fall-through** (items 4, 9): `FirstImage`/`LastImage` without an image and `Compare` with nothing to
    toggle return `None` at once. A lower rule bound to the same key must NOT run (test 41). `Undo`, `OpenFolder` and
    `ToggleCaptureMember` fall through when their condition is false.
T2. **Ctrl is a bit test, Bare is an equality test.** `Undo`/`OpenFolder` accept `Ctrl+Shift+Z` (contains); actions and Recycle
    do not accept any extra bit (`==`); Move/Copy need NO Ctrl bit and Shift forces the picker; zoom, navigation, toggles accept
    every modifier (`Ctrl+Right` is Next, `Ctrl+Add` is ZoomIn, `Ctrl+I` toggles the overlay). Do not "simplify" these.
T3. **Image gate position:** folder navigation, Escape, Fullscreen, Undo, ToggleInfoOverlay, ToggleKeepZoom and OpenFolder
    resolve without an image; everything after step 8 does not.
T4. **Precedence of duplicate keys** (test 39 and the `collisions` fixture): `D5` bound to Recycle AND an action -> `RunAction`;
    `D1` bound to ZoomIn AND ZoomActualSize AND an action -> `RunAction`; `Compare` before actions; ToggleCaptureMember before actions.
T5. **Action indices** are positions in the full `Actions` list (fixture `remapped`: `Fourth` is index 3 after an empty and an
    unparseable entry). Keep the scan in list order and return the first match.
T6. **Rebuild resets everything** (sequence `rebuild-clears-stale-bindings`): a binding absent from the new settings must stop
    working; the action list is replaced, not appended.
T7. **Reserved names never bind** (fixture `collisions`: `ToggleInfoOverlay = "Escape"` stays unbound; `Fullscreen = "F4"` works).
T8. **Blank text versus C# whitespace.** Use the predicate of C# `string.IsNullOrWhiteSpace` for the blank test; the golden
    contains `"  "` and `"NotAKey"`. Whether NBSP / U+0085 / other Unicode spaces count as blank is decided by the oracle run
    (open question Q3); do not guess from Rust `char::is_whitespace`.
T9. No `unwrap()`/`expect()` in production code (AGENTS.md). The router has no fallible path.
T10. Pure: no clock, no I/O, no `windows` crate, no `unsafe`, no `HashMap` iteration (all lookups are direct field reads).

## Open questions (each with a recommended default; the porter follows the default and reports if it does not fit)
- **N1 (04c edge).** The plan does not list W8-04c, but `ParseKey` is `ShortcutKeyName.TryParse`. Options: (A) add the edge and
  call `services::shortcut_key_name::try_parse(&str) -> Option<KeyId>` (recommended: one parser for the settings page, the key
  capture box and the router); (B) move the parse into `input::key_mapping` (05c). Recommendation A because 04c already owns the
  reserved-name rules and the golden of 04c covers them. The stub keeps `parse_key(Option<&str>)`, so both options keep the signature.
- **N2 (`ReviewCommand` shape, W8-05a).** This unit needs: a constructor per payload-free `ReviewCommandType`, `ReviewCommand::action(usize)`,
  `ReviewCommand::move_to_folder(force_picker: bool)` / `copy_to_folder(bool)`, fields `command_type`, `action_index: Option<usize>`,
  `force_picker: bool`. Recommended: `Option<usize>` for `ActionIndex` (C# `-1` means none). W8-05a must match; if it chooses `i32`, the
  golden mapping of -1 in this unit changes and nothing else does.
- **N3 (validator test).** Test 34 (`open_folder_and_custom_zoom_defaults_do_not_collide_with_other_defaults`) builds
  `SettingsValidator` (pr_core, W2-02) with a `KeyNameValidator` that the Rust test implements by calling `shortcut_key_name::try_parse`,
  and the English `SettingsTexts` that W2-02 tests use. Recommended: keep it here (the C# test lives in this file). Alternative: move it
  to W2-02's test file; the behaviour is the same.
- **Q3 (blank text).** Whether `"\u00a0"` and `"\u0085"` are blank in C# is decided by the golden only if the oracle inputs contain them.
  The committed inputs do not (they use spaces and `NotAKey`). Recommended: the porter adds one fixture row with NBSP to the input,
  the lead regenerates the golden, and `parse_key` follows the result. Until then the porter uses `trim()` and records a `// DIVERGENCE:`
  only if the oracle disagrees.
- **Q4 (golden size).** 9 604 cases is roughly 1 MB of JSON (estimate, not measured). Alternative: drop the `ALT|CONTROL` mask (3) and
  two key pairs, which cuts about a fifth. Recommended: keep all, the golden is compact and the cost is one-off.
