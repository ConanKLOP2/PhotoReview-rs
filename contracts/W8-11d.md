## Semantics and wrapper rules (C# is the spec; the conventions of D-W8B3-4 apply to every function)
1. **`create_dialog_indirect_param`.** Modeless dialog from an in-memory `DLGTEMPLATE` or `DLGTEMPLATEEX` (the C# `DialogTemplate` builder, W8-13c, produces the bytes). The template must start on a DWORD boundary: the wrapper copies `template` into a `Vec<u32>` (length `ceil(len / 4)`, zero padded) and passes its address, so the caller's `Vec<u8>` alignment
   does not matter (the C# caller pins a `byte[]`, whose data is 8-aligned in .NET). `WM_INITDIALOG` arrives with `lparam = init_param` before the call returns. `Err(Win32Error::last())` when the handle is `0` (for example a malformed template). With `DS_SETFONT` the template carries the font; the dialog procedure
   receives `WM_SETFONT` first. The dialog is NOT shown unless `WS_VISIBLE` is in the template or the caller calls `ShowWindow`. The dialog procedure is the same `WndProc` type as a window procedure but its return value means "message handled" (`TRUE`/`FALSE`) and the real result goes through `DWLP_MSGRESULT`.
2. **`is_dialog_message(dialog, msg)`**: `true` = the message was consumed (keyboard navigation, `IDOK`/`IDCANCEL` on Enter/Esc); then the caller must not `translate_message`/`dispatch_message` it. It may call back into the dialog procedure.
3. **Text.** `set_window_text` copies the text (UTF-16, NUL-terminated); `get_window_text_length` is UTF-16 units without the NUL; `get_window_text(hwnd)` = C# "length, then a buffer of length + 1": allocate `len + 1` units, call `GetWindowTextW(hwnd, buf, len + 1)`, return `utf16_to_string(&buf[..copied])`; `""` for a window without text. Text of controls of
   another process is returned by the OS without sending a message (not our case).
4. **`send_message`** is the only way into the controls (`CB_ADDSTRING`, `LVM_INSERTITEM`, `WM_SETFONT`...). It is `unsafe fn` because `wparam`/`lparam` may be pointers the callee reads or writes. It blocks until the target window procedure returns; sending to a window of another thread waits for that thread's message loop (hang risk: use only on the UI thread's own windows). No typed helpers in this unit (open question 1).
5. **`draw_text(hdc, text, rect, format)`** (D-W8B3-9): passes `text` as UTF-16 **without** a NUL and `count = units.len()` (the C# passes `count`, so `-1` is never used); clears `DT_MODIFYSTRING` (0x10000) from `format` because the buffer is not writable. With `DT_CALCRECT` the rect is updated and nothing is drawn. The result is the text height in logical units (`0` on failure).
   `DT_EDITCONTROL` (0x2000), `DT_WORDBREAK` (0x10), `DT_NOPREFIX` (0x800), `DT_END_ELLIPSIS` (0x8000), `DT_SINGLELINE` (0x20), `DT_CENTER` (1), `DT_VCENTER` (4) are the flags the dialogs use; `DT_HIDEPREFIX` (0x100000) and `DT_RIGHT` (2) are the chrome's.
6. **`non_client_metrics_for_dpi(dpi)`** is the one C# use of `SystemParametersInfoForDpi`: a `NONCLIENTMETRICSW` with `cbSize = 504` (the Vista+ size, `NONCLIENTMETRICSW_SIZE`), `SPI_GETNONCLIENTMETRICS` (0x29), `uiParam = 504`, `winIni = 0`. The C# caller falls back to Segoe UI 9 pt when the call fails or `lfMessageFont.lfHeight == 0`:
   that fallback (`-(round(9 * dpi / 72))`, weight 400, `DEFAULT_CHARSET` 1, `CLEARTYPE_QUALITY` 5, face `"Segoe UI"`) is W8-13c's, not here. The font is `lfMessageFont` (offset 408). The generic `unsafe fn` exists for the second C# use (`OwnerDrawMenuSession`, `lfMenuFont` at 224).
7. **GDI return conventions** (C# returns them as is): `set_text_color`/`set_bk_color` give the previous colour or `CLR_INVALID` (`0xFFFF_FFFF`) on failure; `select_object` gives the previous object (`0` on failure; `HGDI_ERROR` = -1 for regions) and the caller must reselect it before deleting what it created; `delete_object` is `false` when the object is still selected into a DC;
   `get_dc`/`create_*` return `0` on failure. A colour is a `COLORREF` (`0x00BBGGRR`). `get_text_extent_point32` returns `Some(Point { x: cx, y: cy })`. `get_text_metrics` returns the whole `TEXTMETRICW` (the C# reads the first five `LONG`s: height, ascent, descent, internal leading, external leading).
   `get_object(handle, buf)` passes `buf.len()` as the size; `get_log_font` calls it with a 92-byte buffer and returns `None` when the OS wrote fewer than 92 bytes (not a font).
8. **Painting.** `begin_paint` must be called only while handling `WM_PAINT` (or `WM_PRINTCLIENT` code that paints through its own DC) of that window; it returns the DC and the `PAINTSTRUCT` (72 bytes) that `end_paint` needs; every successful `begin_paint` is paired with exactly one `end_paint`. `get_window_dc` is for `WM_NCPAINT` (the DC covers the non-client area) and is
   released with `user32::release_dc`. A memory DC (`create_compatible_dc`) is deleted with `delete_dc`, its bitmap with `delete_object` after the DC no longer selects it.
9. **`track_mouse_event(flags, hwnd, hover_time)`** builds `TRACKMOUSEEVENT { cbSize: 24, dwFlags: flags, hwndTrack: hwnd, dwHoverTime: hover_time }` (the wrapper sets `cbSize`; the C# caller fills 24 bytes by hand). `TME_LEAVE` (2) asks for ONE `WM_MOUSELEAVE` and is cancelled by the leave itself: re-arm on the next `WM_MOUSEMOVE`.
   (`shell_viewing::scrollbar_native::track_mouse_leave` is the W8-16e twin for the scroll bars; it stays as it is.)
10. **Window properties.** `set_prop(hwnd, name, value)` stores a `HANDLE`-sized value under the string name (copied by the OS); `get_prop` returns `0` when absent; `remove_prop` returns the removed value. A window must remove every property it set before it is destroyed (`WM_NCDESTROY`), or the OS leaks the atom entry in the property list.
    The C# chrome uses a fixed name and the value `1` as the "attached" flag.
11. **`polyline(hdc, points)`**: the OS needs at least 2 points (`false` otherwise); the wrapper does not special-case it. The pen and brush come from the DC's current selection.
12. **`set_window_theme(hwnd, sub_app_name, sub_id_list)`**: `Some("DarkMode_Explorer")` / `Some("DarkMode_CFD")` select the dark control themes (Windows 10 1809+), `Some("")` + `Some("")` removes the theme, `None` + `None` restores the default. `Err(Hresult)` for a negative result; callers ignore failures like the C# `_ =`.
13. **`get_gui_resources(process, flags)`**: `process` is `get_current_process()`; `GR_GDIOBJECTS` (0) and `GR_USEROBJECTS` (1) give the handle counts (a leak test compares before/after).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (item 3, integers): the colour helpers return `u32`; compare with `0xFFFF_FFFF` (`CLR_INVALID`), not `-1i32`. `GR_*` and `DWLP_*` are `i32` in the C# table; the API takes `u32`/`i32`: cast at the call site with a comment.
- T2 (item 8, null vs empty): `get_window_text` of a window with no text is `""`, never an error; `get_dlg_item` returns `0` (not an error) when the id is unknown.
- T3: the `DT_MODIFYSTRING` mask (note 5) is a soundness rule (writing into immutable memory), written as a pure helper with an exact-value test so a mutant that removes it fails.
- T4: DWORD alignment of the dialog template (note 1): an unaligned template makes `CreateDialogIndirectParam` fail or mis-parse on some Windows builds.
- T5: dialog procedures return `LRESULT` = `TRUE`/`FALSE` for "handled", with the real result in `DWLP_MSGRESULT` (offset 0) for most messages; `WM_CTLCOLOR*` and `WM_INITDIALOG` are the exceptions that return the brush / focus flag directly. That is W8-13c, but the constants (`DWLP_MSGRESULT` 0, `DWLP_USER` 16) are here: x64 values; the C# comment says so.
- T6: `select_object` must be paired with a reselect of the old object before `delete_object`, else `delete_object` returns `false` and leaks (the C# NativeDialog leak tests count `GR_GDIOBJECTS`).
- T7: `WM_PRINTCLIENT`/`WM_PRINT` pass the DC in `wparam`, not through `begin_paint`; the chrome paints into it directly.
- T8: use one fixed spelling for a window-property name (the C# chrome does); do not rely on how the OS compares property names.

## Safety rules (a `// SAFETY:` per `unsafe` block)
- Template: "`words` is a `Vec<u32>` that owns a copy of the template, 4-aligned, alive for the call; the template is well-formed (`# Safety`)".
- `send_message` and `is_dialog_message`: obligations in `# Safety`; the block repeats "upheld by the caller of this function".
- `draw_text`: "`units` is a local `Vec<u16>` of exactly `count` units, `rect` is a live `RECT`, `format` has `DT_MODIFYSTRING` cleared so the OS never writes to `units`".
- `get_window_text`: "the buffer is `len + 1` units and that is the size passed".
- `get_text_metrics`, `create_font_indirect`, `get_object`: "pointers to locals of the exact SDK struct (`TEXTMETRICW`, `LOGFONTW`) or to a slice whose length is passed as the size".
- `begin_paint`/`end_paint`: "the `PAINTSTRUCT` is a local owned by `PaintSession`; the OS fills it in `BeginPaint` and reads it in `EndPaint`".
- `polyline`: "`points` is a live slice of `POINT` (8 bytes each) and the count passed is its length (as `i32`, `points.len()` is checked to fit)".

## Decisions taken in this contract (D-W8B3-n; the lead may overrule in `contracts/README.md`)
- **D-W8B3-9 `draw_text` never lets the OS write into the text:** it clears `DT_MODIFYSTRING` and passes `count`. C# callers do not set the flag (they cannot: it is not in `DialogConstants`), so no behaviour changes; the rule keeps a future caller from turning a read-only slice into undefined behaviour.
- **D-W8B3-5 (applies):** `DialogChromeNative` stays in its own file `dialog_chrome.rs` (the plan row names `win32::dialog_native`; the C# class is separate and a second file keeps two ~300-line stubs reviewable).
- **Typed convenience wrappers over `send_message` (`set_text`, `lb_add_string`, `cb_get_cur_sel`...) are NOT added here** (open question 1); `non_client_metrics_for_dpi` and `get_log_font` are the only typed forms because the C# code builds those buffers by hand (offsets 408/92).

## Open questions
1. **Typed `SendMessage` helpers.** 102 C# call sites each need `unsafe` in Rust. Recommended: W8-18's native controls module defines a handful of private safe helpers (`add_string(list, &str)`, `get_cur_sel`, `set_check`...) each with its own SAFETY; this unit stays a faithful mirror. Alternative: add ~15 typed helpers here (more code, more review, risk of drifting from the C# call sites).
2. **`create_dialog_indirect_param` and a leaked `init_param`.** C# passes `GCHandle.ToIntPtr(self)`. In Rust the dialog base will pass a `Box::into_raw` pointer and free it on `WM_NCDESTROY`; the contract for that is W8-13c's. Nothing to decide here.
3. **Should `get_window_text` use `GetWindowTextW` or `SendMessageW(WM_GETTEXT)`?** Recommended `GetWindowTextW` (same as C#; for controls of this process it sends `WM_GETTEXT` itself). No alternative needed.
