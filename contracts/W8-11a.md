## Semantics notes (C# is the spec)
1. **Layout.** The C# numbers (size and field offsets, x64) are the golden `layout` cases; the windows-rs aliases reproduce all of them. Rust field names for the offset checks (a test table `(C# field, offset_of!(Rust field))`):
   `Rect` left top right bottom; `Point` x y; `WndClassEx` cbSize style lpfnWndProc cbClsExtra cbWndExtra hInstance hIcon hCursor hbrBackground lpszMenuName lpszClassName hIconSm;
   `Msg` hwnd message wParam lParam time pt.x pt.y (`Private` at 44 has **no Rust field**: windows-rs `MSG` stops at `pt` and the 4 bytes are tail padding; the golden offset 44 is checked only through `size_of::<Msg>() == 48`);
   `MonitorInfo` cbSize rcMonitor rcWork dwFlags; `MonitorInfoEx` monitorInfo (offsets 0..40 as `MonitorInfo`) szDevice (40); `WindowPlacement` length flags showCmd ptMinPosition ptMaxPosition rcNormalPosition;
   `InputMessageSource` deviceType originId; `TaskDialogButton` nButtonID pszButtonText; `TaskDialogConfig` cbSize hwndParent hInstance dwFlags dwCommonButtons pszWindowTitle Anonymous1 pszMainInstruction pszContent cButtons pButtons
   nDefaultButton cRadioButtons pRadioButtons nDefaultRadioButton pszVerificationText pszExpandedInformation pszExpandedControlText pszCollapsedControlText Anonymous2 pszFooter pfCallback lpCallbackData cxWidth;
   `ScrollInfo` cbSize fMask nMin nMax nPage nPos nTrackPos; `ActCtx` cbSize dwFlags lpSource wProcessorArchitecture wLangId lpAssemblyDirectory lpResourceName lpApplicationName hModule;
   `FormatEtc` cfFormat ptd dwAspect lindex tymed; `StgMedium` tymed u pUnkForRelease; `PointL` x y; `ComdlgFilterSpec` pszName pszSpec. Rust `TaskDialogConfig` is `packed(1)`: read fields by value (`{ cfg.cButtons }`), never take references.
2. **Constants.** Names are the SDK names (the C# names are `PascalCase` spellings of them; D-W8B3-2); the stub carries the C# comment as a trailing `// WmNull`. Rules the generator used: prefix group + remainder upper-cased without separators
   (`WmSetText` -> `WM_SETTEXT`, `SwpNoZOrder` -> `SWP_NOZORDER`, `WsExNoRedirectionBitmap` -> `WS_EX_NOREDIRECTIONBITMAP`); exceptions: `MonitorInfoFPrimary` -> `MONITORINFOF_PRIMARY`, `GHnd` -> `GHND`, `InfiniteWait` -> `INFINITE`,
   `IdOk`/`IdCancel`/`IdYes`/`IdNo` -> `IDOK`/`IDCANCEL`/`IDYES`/`IDNO`, `WaitObject0` -> `WAIT_OBJECT_0`, `WmDpiChangedBeforeParent`/`AfterParent` -> `WM_DPICHANGED_BEFOREPARENT`/`_AFTERPARENT`.
   Types are the C# types: `WS_POPUP` is `u32` `0x8000_0000` (not `i32`), `GWL_*` negative `i32`, `HWND_*` `isize`.
3. **The values were cross-checked twice** while writing the stub: against the oracle output (all 163 `WindowMessages` cases and, through the same generator, the 382 constants of the other classes that 11b..11e embed) and against the value of the
   same-named constant in the `windows` crate 0.62.2 (every constant whose value a script could parse out of that crate matched; the 4 `TD_*_ICON` icons differ on purpose, see 11c trap T3).
4. **Handles.** `isize` (C# `nint`), `Wparam` is `usize` (C# `nint`; same bits, the SDK type is unsigned, `windows::Win32::Foundation::WPARAM(usize)`), `Lparam`/`Lresult` `isize`. The aliases are not newtypes (D-W8B3-3): they exist so signatures read like
   the SDK and so `pr_app` never names a `windows` type.
5. **Size setters.** `new_*` return a zeroed struct with the size field the SDK requires: 80, 40, **104** (`MonitorInfoEx`, not 40), 44, 28, 160, 56. Defaults for every other field are zero/null (Rust `Default` of the windows-rs type, which is `zeroed()`).
6. **Strings.** `to_utf16z("abc")` = `[0x61, 0x62, 0x63, 0]`; `""` = `[0]`; non-BMP text gives surrogate pairs; an embedded NUL stays. `utf16_to_string` stops at the first NUL (`[0x61, 0, 0x62]` -> `"a"`), keeps a slice without NUL whole, and turns an
   unpaired surrogate into U+FFFD (C# `new string(char*)` keeps it; Rust cannot, D-W8B3-5). Both allocate; they are not for hot paths.
7. **Errors.** `Win32Error::last()` is `GetLastError()` of the calling thread, `Display` = `Win32 error {n} (0x{n:08X})`; `Hresult(i32)` `Display` = `HRESULT 0x{n as u32:08X}`; `succeeded()` is `n >= 0`. Both are `std::error::Error`.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (item 3, integers): `WS_POPUP` = `0x8000_0000` is only representable as `u32`; `WAIT_FAILED` and `INFINITE` are `0xFFFF_FFFF` (`u32`); `CW_USEDEFAULT` (11b) is `i32` `-2147483648`. A port that types them `i32` compiles and breaks at the use site.
- T2: `MonitorInfoEx` size is 104 and `cbSize` must be 104 (C# comment and test). `new_monitor_info_ex` sets 104; a port that reuses the 40 of `MonitorInfo` makes `GetMonitorInfoW` fail with `ERROR_INVALID_PARAMETER`.
- T3 (layout, written here because the layout lives here): the C# `TaskDialogConfig` is `Pack = 1` and the windows-rs `TASKDIALOGCONFIG` is `packed(1)` too; taking `&cfg.field` of a packed field is a compile error / UB. The golden pins offsets 4, 28, 60, 64, 140, 156.
- T4: `Msg` has 48 bytes but the Rust struct has no `Private` field; never construct it with a struct literal that lists fields positionally: use `Msg::default()` and assign.
- T5: `HWND_TOPMOST` = -1 and `HWND_NOTOPMOST` = -2 are `isize`; `SetWindowPos` takes `Hwnd` (also `isize`), so no cast; compare with `==`, not `>`.
- T6: value-only duplicates are not an error: `messages` is the single definition of every constant that C# repeats in another class (`User32.WmCreate`, `DialogChromeNative.WmPaint`...); the other modules `pub use` it (11b, 11c, 11d).

## Decisions taken in this contract (D-W8B3-n; the lead may overrule in `contracts/README.md`)
- **D-W8B3-1 One shared golden `win32-constants`** (oracle command in this unit) carries the constants of all five units and the layouts; 11b..11e only read it. Reason: one reflection pass, one regeneration, and a unit cannot forget a class.
- **D-W8B3-2 Constants use SDK names and the C# types; the stub already holds the values.** Alternative: C# `PascalCase` names (`WmSetText`): rejected, windows-rs, MSDN and every Rust Win32 snippet use the SDK form, and a name check against windows-rs
  found the right constant for 499 of 545 on the first try (the rest are the `<STRUCT>_SIZE` and spelling exceptions listed in 11c/11d/11e).
- **D-W8B3-3 Struct aliases of the windows-rs types, named like the C# structs** (`Rect = RECT`), instead of hand-written `#[repr(C)]` twins. Reason: identical layout (proved by the asserts), no second definition to drift, direct use with windows-rs calls.
  Handles are plain integers (`Hwnd = isize`).
- **D-W8B3-5 Gathering:** `ScrollInfo`, `ActCtx`, `FormatEtc`, `StgMedium`, `PointL`, `ComdlgFilterSpec` aliases live in `structs.rs` although C# declares them in other files; `Win32Error`, `Hresult`, `WndProc`, `to_utf16z` are new here
  because five units share them (plan edge 11d -> 11b would otherwise force 11c/11e to depend on 11b).

## Open questions
1. **`Wparam` as `usize` vs `isize`.** Recommended `usize` (SDK `WPARAM`; C# used `nint` only because it has no unsigned pointer-size type at the call sites). Alternative `isize` keeps a 1:1 look with C# but every `WM_COMMAND` mask needs a cast. Decide before 11b is ported.
2. **Should `Msg::Private` be reachable?** Recommended no (no C# caller reads it). Alternative: a `#[repr(C)]` twin of `MSG` with the field; costs a second definition.
3. **`utf16_to_string` lone surrogates.** Recommended U+FFFD. Alternative `Result<String, _>`; no caller can act on the error.
