## Lead prerequisites (decide BEFORE the porter starts)
**P1. The "path cannot be inspected" seam (open question, recommendation A).** C# `IFileSystem.GetFileStat` returns `FileStat?` but THROWS
(`UnauthorizedAccessException`, `IOException`, `ArgumentException`, `NotSupportedException`) and `RecoveryFileCheck` turns exactly those into `Unreadable`
(the `Unknown` verdict; 2+1 tests of RecoveryFileCheckTests, 2 of the mutation tests). The Rust trait `FileSystem::get_file_stat` returns `Option<FileStat>`
("`None` when the file does not exist (or cannot be stat'ed)"): an access-denied stat is indistinguishable from "missing", so the real Recovery window would
say `Lost`/`RecycleUnverifiable` where C# says `Unknown` (a user-visible wrong verdict: "your file is gone" versus "cannot tell"). `FakeFileSystem` also
swallows an injected `FsOp::Stat` fault (`.ok()?`). Options:
- **A (recommended).** Add a default method to `pr_core::abstractions::FileSystem`:
  `fn try_get_file_stat(&self, path: &Path) -> io::Result<Option<FileStat>> { Ok(self.get_file_stat(path)) }` ("`Err` = the path cannot be inspected").
  Overrides: `FakeFileSystem` (records the `FsOp::Stat` count FIRST, then a blank/whitespace path returns `Err(InvalidInput)` like the C# fakes and
  `PhysicalFileSystem` do (`ThrowIfNullOrWhiteSpace`), then an injected `FsOp::Stat` fault returns `Err`; keeps `get_file_stat` as is; the blank rule
  is REQUIRED: the golden `stat_calls` of the blank-source cases depend on it, see note 2(b)), `PhysicalFileSystem` (W2-14, `physical.rs`:
  `Err` of kind `InvalidInput` for blank/NUL paths and for a metadata error that is not NotFound/PathNotFound; `Ok(None)` for missing, directory, bad name),
  `CountingFileSystem` (forward, `record_stat()` first like `get_file_stat`). Pros: the C# behaviour and all five tests port 1:1; no behaviour change for the
  other callers of `get_file_stat`. Cons: touches three lead/Wave-2-owned files (small, additive; trait default keeps every other impl compiling).
- **B.** No trait change: `RecoveryFileCheck` uses `get_file_stat` and `Unreadable` arises ONLY from the lexical pre-checks (blank source/folder, NUL).
  Pros: nothing outside this unit changes. Cons: a real access-denied/locked-metadata path becomes `Missing` (wrong verdict, see above); the 3+2 tests cannot be
  ported through the seam (port them through `decide` with hand-built `RecoveryPathCheck` only) and a `Different` PARITY row + ADR is needed.
- **C.** Make `get_file_stat` itself return `io::Result<Option<FileStat>>`. Cons: every call site in pr-core (catalog, sorting, duplicates, ...) changes: out of
  scope for a 🟡 unit.
After the lead picks, the porter writes `fn stat(&self, path: &str) -> Result<Option<FileStat>, ()>` privately (A: `try_get_file_stat`; B: `Ok(get_file_stat)`).
The stub keeps it out of the public API so the choice does not change any signature here.

**P2. `Path.GetDirectoryName` and friends.** Use `crate::text::dotnet_path::get_directory_name` (W2-00, merged): `None` for blank/root, `Some("")` for a bare name.

## Semantics notes (each is pinned by a C# test or a golden case unless marked UNPINNED)
1. **`check` for a single entry.** `entry.group_members` is `None` or empty => single path (an EMPTY list is not a group: golden
   `group-empty-list-checks-the-entry-itself`). Source = `check_path(entry.source, entry.size, entry.last_write_utc, compare_last_write: true)`.
   Destination = `None` when `entry.destination` is `None`, `""` or whitespace-only (`char::is_whitespace` = .NET `char.IsWhiteSpace`, identical sets), else
   `check_path(dest, entry.size, entry.last_write_utc, compare_last_write: false)` (the destination fingerprint uses the SOURCE's size, never the
   destination's last-write). The result keeps the entry untouched (`entry.destination` may be `""` while `result.destination` is `None`).
2. **`check_path` order.** (a) `folder = get_directory_name(path)`; when `Some(f)` and `f` non-empty: if `f` is whitespace-only return `Unreadable` with
   `folder_exists = false` (C# `DirectoryExists` throws `ArgumentException`: golden `source-folder-part-whitespace-is-unreadable`, `p-whitespace-folder`),
   else `folder_exists = directory_exists(f)`. (b) if `path` is whitespace-only or contains U+0000 return `Unreadable` with the `folder_exists` computed so far
   (C# `GetFileStat`/`new FileInfo` throws `ArgumentException`; the folder check ran first, so a NUL in the FILE NAME keeps `folder_exists = true`: golden
   `p-nul-in-source`). **This pre-check exists only under option B.** Under option A the seam itself returns `Err` for blank (fake and physical) and NUL
   (physical) paths AFTER counting the stat, exactly like the C# proxy (`StatCalls++` then throw): a Rust pre-check that skips the call would make the
   virtual golden `stat_calls` of `source-empty-string-is-unreadable`, `source-whitespace-is-unreadable`, `source-tab-is-unreadable` 1 instead of 2.
   Rule: under A do NOT pre-check blank/NUL, always call the seam. Pre-check (a) (whitespace FOLDER part) stays under both options: C#
   `DirectoryExists` throws BEFORE any stat (golden `stat_calls` 0 for that source) and the Rust `directory_exists` returns `bool`. (c) stat via the seam (P1): `Err` => `Unreadable` (size/time `None`, `folder_exists` as computed: a stat error AFTER a folder check
   that said true keeps `true`: golden `stat-throws-after-folder-exists-keeps-folder-true`); `Ok(None)` => `Missing`; `Ok(Some(stat))` => `changed =
   i64::try_from(stat.length) != Ok(recorded_size) || (compare_last_write && stat.last_write_utc != recorded_last_write_utc)`, status `Changed`/`Exists`,
   `current_size = Some(saturating i64)`, `current_last_write_utc = Some(stat.last_write_utc)`.
   The C# catch filter (`UnauthorizedAccess`/`IO`/`Argument`/`NotSupported`) has no Rust analogue: every `Err` is `Unreadable`; golden case
   `stat-throws-InvalidOperationException-propagates` carries `"rust_skip": true`.
3. **Last-write comparison is by ticks only.** `JournalEntry.last_write_utc` is a `JournalDateTime`; compare `.value` (ticks) with `stat.last_write_utc`, never
   the `unspecified` flag (golden `source-unspecified-kind-same-ticks-exists`). One tick of difference on the SOURCE is `Changed`
   (`source-last-write-plus-1-tick-is-changed`); on the destination it is ignored (`dest-last-write-plus-1-tick-still-exists`). No tolerance here (unlike
   `FileFingerprint.matches_moved_destination`, W1-09): do not reuse it.
4. **`decide` (pure; table in the stub doc).** Branch order matters: Recycle first (ignores destination and state), then "no destination => Unknown",
   then Committed, then non-Prepared/Failed => Unknown, then any Unreadable => Unknown, then the S/D grid. `entry.permanent == Some(true)` only (`Some(false)`
   and `None` behave alike). Golden `recovery-decide` is the full product 3 types x 4 states x 3 permanent x 4 S x 5 D (`destination: null` = no destination
   check) = 720 rows: the test builds the entry/path checks from the golden axes and compares the verdict name.
5. **Group member check (`check_group_member`).** Build a single entry from the group: `source`, `destination`, `size`, `last_write_utc` from the member,
   `permanent = Some(member.permanent)` (always `Some`, never `None`), `group_id = None`, `group_members = None`, `undo = None`; everything else (id, type, state,
   timestamps, error, error_code) from the group. Run `check` on it. If `group.undo == Some(true) && group.op_type == Recycle`: `entry = group.clone()` and the
   verdict is replaced by the "is the file back" rule: `Exists` with `current_size == Some(member.size)` and `current_last_write_utc == Some(member.last_write_utc.value)`
   (ticks only as in note 3: C# `DateTime ==` ignores Kind; never compare `JournalDateTime.unspecified`)
   => `AlreadyDone`; `Exists` otherwise => `Conflict` (unreachable in practice, keep it); `Missing` => `RecycleUnverifiable` (even for a `permanent` member:
   golden `group-recycle-permanent-flag-on-undo-member-missing-is-unverifiable`); `Changed`/`Unreadable` => `Unknown`. For every other group the member
   check is exactly the single-entry check on the synthesized entry (so a Failed Move group member uses the Move table, a Recycle member `decide` rule 1).
   `check_group_member` may call `check` recursively, but the synthesized entry has no members, so it never recurses further.
6. **Group result.** Members are checked eagerly in list order, once each (per member: folder check then stat of the source, then, when the member has a
   non-blank destination, folder check then stat of the destination: golden `stat_calls`). The result's `source`/`destination` are the FIRST member's; `entry`
   is the group entry; `verdict = aggregate_group_verdict` (rules in the stub doc, first match wins; the order is behaviour: e.g. an undo Move group of
   `{CanRetry, Conflict}` is `Conflict` because rule 1 requires ALL members in `{CanRetry, AlreadyDone}`, and a plain Delete group of
   `{NotRecycled(Changed), RecycleUnverifiable}` is `NotRecycled`, not `CanRetry`).
7. **Group-level `permanent`/`undo`/`state` are not consulted by the member check except `undo`+`Recycle`.** A Committed or Dismissed group still goes through the
   same aggregation (goldens `group-move-committed-state-undo-retry-done`, `group-move-dismissed-state-all-unknown`: Dismissed members are all `Unknown` and the
   aggregate falls to rule 6's `Unknown`).
8. **Read-only.** Only `directory_exists` and the stat seam are called; never `file_exists`, `delete`, `move_file`, `copy_file`, `open_*`, `enumerate_*`,
   `create_directory`. The Rust twin of `Check_NeverMutates_OnlyStatCalls` asserts the counters.
9. **Sizes.** `RecoveryPathCheck.current_size` is `Option<i64>`; `FileStat.length` is `u64`: saturate to `i64::MAX` (C# length is `long`). A journal `size` of
   `-1` or `i64::MAX` is just compared (goldens `size-negative-journal`, `size-max-long-journal`: both `Changed`).
10. **Thread/blocking.** Pure synchronous code, no locks; the caller runs it on a background thread (the window passes an `Arc`). Do not spawn threads or
    cache results: a Re-check must re-stat.

- §7.10 ordering: members stay in input order everywhere (result list, call order).

  journal and never mutates; the only file-system calls are the two read-only ones (note 8). INV-3/4/5/8/11 do not apply (no gate, catalog or shared open).
- Never call anything that can reach the real Recycle Bin: not applicable (no bin access); tests use `FakeFileSystem` only, the `physical` golden cases use a private
  `TempRoot` and are `#[ignore = "native: real disk"]`.

2. **`FileInfo`/`Path` quirks not reproducible with `get_file_stat` alone.** Pre-checks cover blank and NUL. Whether other C# `ArgumentException`/`PathTooLong`
   cases exist (a path longer than the Windows limit, device names, `\\?\` oddities) is answered by the physical goldens (`p-path-40000-chars`,
   `p-reserved-device-name`, `p-unc-missing-server`, `p-colon-stream-in-source`). After the oracle run the lead decides per case: an `Unreadable` the Rust
   pre-checks cannot see goes either into `PhysicalFileSystem::try_get_file_stat` (option A, preferred: one place) or a documented `Different` row. UNPINNED until
   the oracle runs.
3. **`dir_throws` cases** (virtual): `directory_exists` returns `bool` in Rust, so a throwing `Directory.Exists` equivalent does not exist (C# Physical
   `DirectoryExists` only throws for blank paths, which pre-check 2(a) handles). Accepted divergence for the two injected cases; a `Different`-free row.
4. `RecoveryFileCheck::decide` is `pub` here (C# `internal`) for the table golden; if the lead prefers `pub(crate)`, the table test moves into the module's own
   `#[cfg(test)]` block (the golden loader is in `pr-test-support`, a dev-dependency, so that works too).
