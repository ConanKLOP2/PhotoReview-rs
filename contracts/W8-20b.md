## The rig `UiSmokeRun` (`common/ui_smoke_fixture.rs`, stub written by the contract)
Self-contained (D-W8B6-47): it uses only the public API of `pr_shell::startup` and `pr_platform_win`, never the `startup_fixture.rs` of 17d/17e. What it does, in the order the porter implements it:
1. **Photos and paths**: a `TempRoot` (`pr_test_support`), `<root>/photos/<name_prefix>NN.jpg` (default `sNN.jpg`) = `photo_count` copies of `tests/fixtures/turbojpeg/<fixture>` read once through `pr_test_support::golden::repo_root()` (the only allowed repo-relative lookup, AGENTS.md "Tests"); `AppPaths::new(<root>, Some("<root>/data"), true)` (isolated: config, journal, sessions, log, cache and placement all under the root); a `TempFolderRecycleBin` over `<root>/bin`. `config_json`, when given, is written to `AppPaths::config_file` (parent created) before the start.
2. **Options**: `ShellStartupOptions::default()` then the rig's fixed edits (`instance_name_prefix = "PhotoReviewRsTest" + 10 hex digits of a GUID`, `prefer_warp = true` except in S6, `activate = false`, `warm_graphics = false`, `install_process_hooks = false`, `start_perf_listener = false`, `graph_builder = Some(..)`), then `configure(&mut options)`, then the rig wraps `mark` (records the name under the lock, calls the user's) and `on_main_window_ready` (stores the `UiProbe` in a thread-local of the UI thread, stores `hwnd`, subscribes `window().subscribe_render(..)` so every frame refreshes the snapshot and `notify_all`s, sets `main_ready`, calls the user's). The graph: `GraphChoice::Production` = `production_graph_builder_with(GraphOverrides { paths: Some(app_paths), recycle_bin: Some(bin), log: Some(<test log>), ..Default::default() })`; `Custom(f)` = `f(&AppPathsForRig)`.
3. **The thread**: `std::thread::Builder::new().name("UiSmokeRun")`, which first enters `StaApartment::enter()` (the C# `ShellRun` thread is STA), then `catch_unwind(|| ShellStartup::run(&args, options))`; the result (`Ok(code)` or the panic text) is stored under the lock and `notify_all`ed. The args: `FirstPhoto` = `[<root>/photos/<name_prefix>00.jpg]`, `PhotosFolder` = `[<root>/photos]`, `Nothing` = `[]`, `Arguments(v)` = `v`.
4. **Waiting**: every wait is a `Condvar::wait_timeout_while(.., BOUND, ..)` on the one `(Mutex<RunState>, Condvar)`; there is no `sleep` and no polling loop anywhere in the rig. A wait that expires returns `Err(format!("{what}: {diagnostics}"))`. `wait_first_image` = `main_ready && snapshot.first_image_presented`.
5. **Input**: `key(vk)` = `ui_driver::post_key(hwnd, vk, true)` then `(.., false)`; `wheel`, `mouse_move`, `click` likewise. All from the TEST thread (a different thread than the UI thread, as in C#). Coordinates are client pixels; the client centre is read once with `on_ui`.
6. **`on_ui`**: `ui.post(Box::new(move || { let r = f(probe); tx.send(r) }))` with the window's `UiScheduler` (kept as `Arc<dyn UiScheduler>` in `RunState` by the ready hook); `rx.recv_timeout(BOUND)`; a panic in `f` is caught by the dispatcher (D-W8B3H-10) and reported as `Err`. **The barrier idiom**: a key is posted with `PostMessage` and `on_ui(|_| ())` is posted with the dispatcher's wake message; both are posted messages of the same thread queue and run in posting order, so `key(..)` followed by `on_ui(|_| ())` returns after the key was handled. It proves a decision the view model makes SYNCHRONOUSLY (a clamped `Right` at the last photo changes nothing); it does NOT wait for work that hops to a worker and back (a navigation, a recycle): those are waited with `wait_until` on the snapshot.
7. **Snapshot**: built on the UI thread after every frame from `MainViewModel::{current_index, total_files, folder_title, status_text, current_image}`, the viewer state (zoom, fit) and `MainWindow::first_image_presented`; plain data, `Clone`. The porter checks the exact accessor names on the merged code; if the zoom or the current path has no accessor, add a read-only one to `MainViewModel` (a 3-line amendment, recorded in the PR) rather than reading private state.
8. **Close and drop**: `request_close` = `ui_driver::post_close(hwnd)`; `close_and_wait` waits for the exit code; `Drop` = `request_close` (errors ignored), wait up to 45 s for the exit, then join the thread with a 15 s bound. A window can only be destroyed by the thread that owns it, so a hung run cannot be forced down from the test thread: it is marked abandoned (`static ABANDONED: Mutex<Option<String>>`, text = root + marks) and the next `start` returns `Err` naming the first hung run (C# `s_abandoned`: one hang must not make every later test wait 60 s). The temp root is removed last; a removal error is ignored (a handle still open: the OS cleans the temp folder).
9. **`TempFolderRecycleBin`**: the semantics in its stub doc. It exists because the production `RecycleBin` is the user's Recycle Bin (AGENTS.md: never touched by a test) and `FakeRecycleBin` works on an in-memory `FakeFileSystem`, while the shell lists and decodes REAL files; this one really moves the file, into the temp root.
10. **Requirement on W8-09b (lead action, D-W8B6-47)**: `pr_shell::startup::graph` must offer `pub fn production_graph_builder_with(overrides: GraphOverrides) -> GraphBuilder` with `#[derive(Default)] pub struct GraphOverrides { paths: Option<AppPaths>, log: Option<Arc<dyn Log>>, recycle_bin: Option<Arc<dyn RecycleBin>>, explorer_order: Option<Arc<dyn ExplorerOrderProvider>>, clock: Option<Arc<dyn Clock>>, decoder_wrapper: Option<Arc<dyn Fn(Arc<dyn ImageDecoderFactory>) -> Arc<dyn ImageDecoderFactory> + Send + Sync>> }`: the Rust twin of C# `ShellStartupOptions.ServiceOverrides` (`services.AddSingleton<IAppPaths>(..)`, `ILog`, and the decorated `IImageDecoderFactory` of `ShellStalePreviewTests`). The 09b contract writer must include it; if 09b merges without it, slice S1 adds it to `graph.rs` as amendment A1 (about 40 lines) and says so in the PR. `production_graph_builder()` stays as `production_graph_builder_with(GraphOverrides::default())`.

## Semantics (summary of the rules the tests enforce)
1. **No sleep, no polling** (AGENTS.md "Tests"): every wait of the rig is a `Condvar` on the frame/exit notifications or a channel `recv_timeout(BOUND)`. The timed ticks of the whole unit are exactly three, all listed in D-W8B6-45: the two of the process tests of 20a (200 ms, perf CSV and "the exe has a window yet"), the 50 ms tick of `wait_for_owned_window` (S5), and the S6 report's 250 ms switch interval (a `Condvar::wait_timeout` that a frame notification can cut short). No `std::thread::sleep` anywhere.
2. **Test isolation**: unique instance prefix, `TempRoot` data root with config isolation, WARP, `activate = false`, no process hooks, no perf listener, fake journal recovery where the test does not exercise it (`options.journal_recovery = Some(Box::new(|_, _, _| Vec::new()))`, so a left-over journal of the machine can never prompt), the temp-folder bin; no test reads or writes `%LOCALAPPDATA%\PhotoReviewRs` or `\PhotoReview`.
3. **One shell at a time per process**: the tests of one binary run on the same process; the D3D/WARP device and OLE are process-wide, so every `ui_smoke*.rs` file serialises its tests on a file-local `static SERIAL: Mutex<()>` taken at the start of each test (the C# `[Collection("ShellStartup")]`), in addition to the abandoned-run guard.
4. **Hidden desktop**: the tests create real windows; the lead runs them through `tools/run-tests-hidden.ps1`-style launching when it exists, or on an interactive session; they never call `SetForegroundWindow` or `SendInput` (C# N-8) and never move the real cursor.
5. **Order is behaviour**: where the C# test asserts an order (marks, "window closed before services"), the Rust test asserts the same order on `marks()` or on the observable it names.
6. **The map is a contract with the future**: `ui_parity_map` fails when a row, a test file or a smoke test disappears; fix the table, never weaken the test.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (threads): the window is `!Send`; the test thread owns only `Send` data (`Hwnd` is `isize`, the `UiScheduler` is `Send + Sync`, snapshots are plain). Nothing holds a `RefCell` borrow of the view model across an `on_ui` return.
- T2 (hangs): a test that waits on something that can never happen hangs the whole `cargo test`; every wait has the 60 s bound, the abandoned guard stops the chain, and the CI job has its own timeout (AGENTS.md "Hang guard"). Run with `timeout`/job limits.
- T3 (foreground): never `SetForegroundWindow`; WARP keeps the GPU out of it; the window is created with `activate = false`.
- T4 (data safety): the recycle test must use `TempFolderRecycleBin`. A test that constructs the production `RecycleBin` or passes no bin override is a bug (the graph would use the user's real bin): every `GraphChoice::Custom` closure must build its graph through `production_graph_builder_with(GraphOverrides { recycle_bin: Some(paths.bin.clone()), .. })` (reviewed in the PR; the verifier greps the test files for `production_graph_builder()` without overrides and for `RecycleBin` types other than `TempFolderRecycleBin`).
- T5 (DPI and size): the hidden window is 1200x800 at the thread's DPI; tests must not assume 96 dpi or an exact pixel size; zoom tests compare relations (greater, smaller, equal to the fit value), not absolute pixel values, except 100 %.
- T6 (temp paths): CI temp paths can be 8.3 short names; compare file NAMES, never whole paths printed by the code under test (AGENTS.md).
