- Semantics notes (each from the C# read at the baseline; full step lists are in the stub doc comments):
  1. **Import is transactional.** `try_apply_imported_json` replaces the working copy, calls the view's refresh, and on ANY failure restores the previous working copy and calls the refresh
     AGAIN. Test `Import_Unusable_RestoresPrevious`: unparsable text fails BEFORE the first refresh, so the refresh runs exactly once (the restore). Test `Import_ViewReloadThrows_RestoresPrevious`:
     the first refresh fails (Rust: returns `Err("view broke")`), the second succeeds, total 2 calls, the message contains `view broke`, the settings are the previous ones.
  2. **Half-valid file.** `SettingsStore::parse_text` salvages property by property: `"ClickZoomPercent":"abc"` is reset to the default and named in the notice, while
     `KeyboardZoomStepPercent` 40 and `Shortcuts.Next` "N" are kept. The notice is `build_repair_text(repairs, for_import = true, ..)`, only when `repairs` is non-empty.
  3. **JSON `null`** is refused (`is_json_null`) with the text "The file does not contain a settings object."; an unparsable text with the parser's message. Both end as `dialog.importSettings.failed`.
  4. **Export writes the config.json contract** (`to_json`, UTF-8 without BOM). Import of that text gives back the same values (test `ExportThenImport_RoundTrips`).
  5. **Update check, three steps.** `begin_update_check` clears the stored URL and stores a fresh cancel token. `UpdateCheckJob::run` is the only blocking part (worker). `finish_update_check`
     returns `None` (a cancelled check, "the dialog closed: do not touch the controls") when the outcome is `Canceled` OR the token is cancelled by then, even if a result arrived (C#
     `if (cts.IsCancellationRequested) return null`). `update_cancel` is cleared in every case. A panic of the checker is `Failed` (displayed as `badResponse`); `OutOfMemoryException` has no Rust twin.
  6. **Only validated URLs are offered or opened.** `validate_update_url` runs when the result arrives AND again on every `open_update_page` call; the test stores a foreign URL with
     `set_update_url` and expects `open_url` never called and `None` returned.
  7. **Failure texts:** `Offline`, `Timeout`, `RateLimited`, `InvalidVersion` have their own key; every other failure (`BadResponse`, `None`) is `update.status.failed.badResponse`.
  8. **Explorer integration.** Unavailable when the executable path is invalid or is `dotnet` (case-insensitive file name stem); buttons: `add_enabled = state != Registered`,
     `remove_enabled = state != NotRegistered`, label `settings.shell.update` only for `RegisteredElsewhere`. A failing register/unregister replaces ONLY the text with
     `settings.shell.status.error` and keeps the buttons computed from the current state.
  9. **Language picker** without a service: every function returns its "nothing" value: `None`, `None`, `(None, None)`, `SettingsExplorerRequest { None, None }`.
  10. **Log location.** `arguments` starts with `/select,` and contains the log file path (`AppLog::global().file_path()`).
  11. **Context-menu rows.** One per `context_menu::ITEMS` entry (18), table order; children flagged by `parent`; `locked_tooltip` only on the locked `Settings` row; label never blank.
  12. **Capture.** Reserved keys (`is_reserved`) give `None` so Tab/Escape/modifiers keep focus movement; any other key gives `canonicalize(Some(key_name))`
      (`Return` -> the canonical alias name `canonicalize` returns; the test compares with that call, not with a literal).
  13. **Zoom summary.** Eight lines, `"\r\n"`-joined, blank or missing entry -> `settings.zoomShortcuts.none`, typed text trimmed.
- Traps checklist:
  - **T1 Restore on failure (Q-R50).** Do not assign `self.settings` until `parse_text` succeeded; the restore path must also run when the FIRST refresh fails.
  - **T2 Stale completion (INV-9 style).** `finish_update_check` must check the token of the check that produced the answer, not the current `update_cancel`
    (a second check may have replaced it). `UpdateCheckCompleted` carries its own token for that reason.
  - **T3 No network in tests.** `begin_update_check` uses the configured fake `UpdateCheck`; the real checker needs an `HttpTransport` that does not exist yet (O3).
  - **T4 No sleep polling.** The cancelled-check test: the fake checker signals "started" through a channel and then spins on `cancel.is_canceled()` with `std::thread::yield_now()`
    under a hang guard (fail after 10 s of wall time). Never `sleep` to wait for a state.
  - **T5 Registry and Explorer.** Tests use a fake `ShellIntegration` (records calls). `try_start_explorer` is never called by a test (it would open a window). No test touches the real registry.
  - **T6 Case.** `dotnet` stem compare is ASCII case-insensitive in C# `OrdinalIgnoreCase`: use `pr_core::text::eq_ignore_case`.
  - **T7 Culture.** All formatting goes through `ctx.numbers`; `AppVersion` text is invariant.
  - **T8 Files.** Export/import tests write only under `pr_test_support::TempRoot` (removed on drop). Missing directory and missing file are `io::Error`s, never panics.
  - **T9 Threads.** Everything except `UpdateCheckJob::run` is UI-thread only. `UpdateCheckJob` is `Send` (an `Arc` checker, a `String`, a `CancelToken`).
  - **T10 Ambient localizer.** Only `reload_translations` may call `Localizer::current()`, after the reload (see the stub). Everything else takes `ctx`.
  - **T11 `ActionsForEditor("null")` returns the DEFAULT list** (`ReviewAction::defaults`, same arguments as `AppSettings::new`), not an empty list; `deserialize` (not `_or_null`) would give empty.

## Open questions (each has a recommended default; the stubs follow it)
- **O1 `LocalizationService::export_todo` is missing in the B1 stub (`localization/service.rs`).** C# `ExportTodo(language)` = `TranslationExport.Export(ResolveCode(language), ShippedLanguagesDir, UserLanguagesDir)`
  (verified). The Rust service has `resolve_code` and `user_languages_dir` but no shipped directory accessor and no `export_todo`. Required change to the B1 file (lead; W8-04a porter):
  `pub fn export_todo(&self, language: Option<&str>) -> Result<PathBuf, localization::export::TranslationExportError>`. `apply.rs` calls it; until then `export_translation` cannot compile (the stub body is `todo!()`
  and does not call it, so the stubs compile today).
- **O2 `ShellIntegration::get_state` is infallible** in `pr_core`; C# catches `IOException`/`UnauthorizedAccessException`/`SecurityException` there and returns an error row with Add enabled and Remove off. Recommended
  (used): no catch arm; a registry failure inside the real implementation maps to `NotRegistered` (pr-platform-win owner). Alternative: change the trait to `io::Result<ShellMenuState>`.
- **O3 Missing production pieces:** an `HttpTransport` for the real `UpdateChecker`, and a registry `ShellIntegration` implementation (see W8-10d O5). Default: `update_checker: None` -> `BadResponse` text.
- **O4 Update-check shape.** Three steps instead of an awaited method (D-W8-2). The view posts `job.run()` to a worker and the result back with `UiScheduler::post`, then calls `finish_update_check`.
  `check_for_update_blocking` exists for tests and tools only.
- **O5 `RefreshView` signature.** C# `Action refreshView` may throw. Recommended (used): a closure over `&SettingsPresenter` returning `Result<(), String>` (the C# exception message). Alternative: no error channel
  (a panic would then have to be caught), rejected.
- **O6 `try_start_explorer`** uses `std::os::windows::process::CommandExt::raw_arg`; the Rust app is Windows-only, so no `cfg`. It lives in `pr_app` (no `unsafe`, `std` only).
- **O7 Changes to B1 stubs:** only O1.
