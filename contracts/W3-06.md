## Semantics (C# line numbers refer to RecoveryRetryService.cs)
Notation: `fp(stat, size, lw)` = `same_fingerprint`; `stat(p)` = the stat seam (one file-system stat call, may be `Err`); `name(p)` =
`dotnet_path::get_file_name(p)`; "refuse X" = `Ok(RecoveryRetryResult::new(false, texts.X(), None))`, nothing journaled or mutated.

**E. Entry (`retry_move_or_copy`, l.55-71).** 1. Gate `Some(g)`: `!g.try_begin()` => `Ok(new(false, busy, None))` BEFORE anything else (no stat, no
journal read, no cancel check; `end()` is NOT called). Otherwise hold an RAII guard that calls `g.end()` on every exit (Ok, Err, panic). 2. `retry_core`.

**S. Single (`retry_core`, l.73-116).** 1. `failed.error_code == Some("CancelledByUser")` (ordinal, `errors::CANCELLED_BY_USER`) and not
`confirmed_finish_cancelled` => refuse `cancelled_needs_confirm`. 2. `group_members` is `Some` and non-empty => **G** (an empty list is a single
entry; `Some(vec![])` is kept in `prepared` and serialized as `"GroupMembers":[]`, golden `single-move-with-empty-member-list...`). 3. `op_type`
not Move/Copy => refuse `only_move_copy`. 4. `is_null_or_white_space(destination)` => refuse `no_destination`. 5. Pre-checks, in this order (golden
`ops`): `file_exists(source)` false => refuse `source_missing`; `stat(source)`: `None` or `!fp(stat, failed.size, failed.last_write_utc)` => refuse
`source_changed`; `file_exists(destination)` => refuse `destination_exists`. A stat `Err(e)` => `Ok(new(false, e.to_string(), None))` (C# catch
filter; D5 free text). 6. `prepared = failed.clone()` with `state Prepared, error None, error_code None, size = stat.length as i64,
last_write_utc = JournalDateTime::utc(stat.last_write_utc), timestamp_utc = JournalDateTime::utc(self.clock.utc_now())`; EVERYTHING else kept
(`undo`, `permanent`, `group_id`, `group_members`: dropping `undo` turns a retried undo-Move into a redo after restart). 7. `cancel.check()?`
(the `Task.Run(.., ct)` hand-off: `Err(Canceled)` = C# `TaskCanceledException`). 8. `execute_retry`.
The clock read in 6 is the SERVICE clock (`self.clock`), and the transaction gets the same clock (golden: Prepared/Committed/Failed lines carry
`service_clock_ticks`, the seed lines `journal_clock_ticks`).

**X. `execute_retry` (l.295-341).** 1. `journal.live_operations().is_live(&failed.id)` => `already_handled()` (nothing journaled). 2. `tx =
JournalTransaction::new(&self.journal, &*self.clock, prepared, Some(failed.clone()))` (W3-01 takes `retry_of` by value; dropped at the end =
C# `using`: releases the live marker). 3. Body (`run_single`):
`tx.try_begin()?` (`Ok(false)` => return `already_handled()` directly, NOT through the failure arm); R17 re-stat: `stat(source)?` must be
`Some` with `fp(.., prepared.size, prepared.last_write_utc)` else `Err(plain(source_changed))`; `dir = get_directory_name(destination)`, when
`Some(d)` and `!d.is_empty()` (IsNullOrEmpty: a whitespace folder IS created) `create_directory(d)?`; Copy: `copy_new_or_keep_leftover(source,
destination)?` then `tx.verify_destination(fs, dest, RETRY_VERIFY_FAILED)?`; Move: `move_file(source, dest)?` then `tx.verify_moved(fs, source, dest,
RETRY_VERIFY_FAILED)?`. 4. Success: `(entry, err) = tx.commit()`: `err None` => `new(true, succeeded, Some(entry))`; else
`not_journaled(true, succeeded_journal_failed, Some(entry), err)`. 5. Any `Err(e)` from 3 (including an `Err` from `try_begin`, i.e. the Prepared
append failed): `(entry, fail_err) = tx.fail(&e)`; `tx.superseded()` => `already_handled()`; `fail_err None` => `new(false, failure_message(&e),
entry)` (succeeded is false EVEN IF the mutation completed); else `not_journaled(tx.mutation_completed(), if mutation_completed {
completed_failure_not_journaled } else { failure_message(&e) }, None, fail_err)`.

**G. Group (`retry_group`, l.118-194).** 1. `op_type` not Move/Copy/Recycle => refuse `only_move_copy` (unreachable; keep). 2. `is_live(id)` =>
`already_handled()`. 3. `check = RecoveryFileCheck::new(fs.clone()).check(failed)`; `check.verdict != CanRetry || group_members None` => map:
`AlreadyDone` => `already_handled()`, `Conflict` => refuse `conflict`, `DestinationChanged` => refuse `destination_changed`, anything else
(`SourceChanged`, `Lost`, `Unknown`, `RecycleUnverifiable`, `NotRecycled`, ...) => refuse `source_changed`. 4. `pending = select_pending(failed,
members)` (doc on the fn); empty => `already_handled()` (C# spells the same record out, l.143). 5. Recycle and `recycle_bin` None => refuse
`only_move_copy`. 6. Recycle, `undo != Some(true)`: call `allow_permanent_delete` ONCE (absent = false); not true and the FIRST pending member
with `permanent` => refuse `core_recycle_unsupported_drive(name(member.source))`. 7. Per-member pre-check in pending order (`precheck_group_members`),
first failure wins, all => refuse `source_changed`; a stat `Err(e)` => `Ok(new(false, e.to_string(), None))`:
   - Recycle undo: `member.permanent` => refuse (no file-system call at all for undo members);
   - Recycle delete: `stat(source)?` `None` or `!fp` => refuse; then `member.permanent && bin.can_recycle(source)` => refuse (drive gained a bin: never
     delete permanently); `!member.permanent && !bin.can_recycle(source)` => refuse (would be deleted permanently);
   - Move/Copy: `stat(source)?` `None` or `!fp`, or `is_null_or_white_space(member.destination)`, or `file_exists(destination)` => refuse.
   8. Recycle, `undo != Some(true)`: `errors::first_overflow(bin, &pending_members)` `Some(m)` => refuse `core_recycle_bin_cannot_hold(name(m.source))`.
   9. `prepared = failed.clone()` with `state Prepared, error None, error_code None, timestamp_utc = utc(clock.utc_now())` (size and last write
   KEPT: the group fingerprint is per member). 10. `cancel.check()?`. 11. `execute_group_retry`.

**GX. `execute_group_retry` (l.196-270).** `tx` as in X (no live check here: done in G2). Body (`run_group_members`): `tx.try_begin()?` (`Ok(false)` =>
`already_handled()` directly); then for each pending member: `cancel.check()` => `Err(io::Error::other(Canceled))`; then
   - Recycle undo: `file_exists(source)` => `Err(plain(undo_recycle_target_exists(name)))` (R15: never count a foreign file as restored, never ask the
     shell to replace it); `permanent` => `Err(plain(source_changed))`; `try_restore(source, size, last_write)` false or `!is_restored_file(member)?` =>
     `Err(plain(undo_recycle_restore_failed(name)))`; after the bin call (below) `!is_restored_file(member)?` again => same error. So a successful
     restore reads the member's stat TWICE (golden `ops`).
   - Recycle delete: `permanent`: `bin.can_recycle(source)` => `Err(plain(source_changed))`, else `bin.delete_permanently(source)?`; not permanent:
     `bin.send_to_recycle_bin(source)?`. Then `file_exists(source)` => `Err(coded(SOURCE_STILL_EXISTS_AFTER_RECOVERY))`.
   - Move/Copy: `stat(source)?` `None`/`!fp(member)` => `Err(plain(source_changed))`; `is_null_or_white_space(destination)` or `file_exists(destination)`
     => `Err(plain(destination_exists))`; `get_directory_name(destination)` not null/WHITESPACE (note: IsNullOrWhiteSpace here, IsNullOrEmpty in X) =>
     `create_directory`; Copy: `copy_new_or_keep_leftover` then `stat(destination)?` length `!= member.size` (None counts as mismatch) =>
     `Err(coded(RETRY_VERIFY_FAILED))`; Move: `move_file`, then `file_exists(source) || stat(destination)?` length `!= member.size` =>
     `Err(coded(RETRY_VERIFY_FAILED))` (NOT MoveSourceNotRemoved: the group path does not use `verify_moved`).
   After the loop `tx.mark_mutation_completed()`. Success: as X4. Failure `Err(e)`: `(entry, fail_err) = tx.fail(&e)`; superseded =>
   `already_handled()`; `fail_err None` => `new(tx.mutation_completed(), failure_message(&e), entry)`; else `not_journaled(tx.mutation_completed(),
   completed_failure_not_journaled, None, fail_err)` (ALWAYS that text in the group path, unlike X5). A retry never undoes members it already
   completed (golden `group-move-cancelled-during-first-member`).

**H. Helpers.** `copy_new_or_keep_leftover`: `fs.try_copy_new(src, dst)?` (trait DEFAULT method: `file_exists(dst)` then `copy_file`) `false` =>
`Err(plain(destination_exists))`; never deletes. `is_restored_file`: `stat(source)?` is `Some` and `fp(stat, member.size, member.last_write_utc)`.
`try_restore` takes `u64`: `u64::try_from(member.size)` failing (negative size, hand-edited journal) => treat as "restore failed" WITHOUT calling the
bin (Open question 4). `coded_error(code)` = `JournalCodedError::new(code, errors::text(code, &|k| journal.texts().localized(k)))
.into_io_error()`; the journal then stores the code plus ENGLISH text (W3-01's `fail` uses `errors::for_journal`). `failure_message(e)`:
`OPERATION_CANCELED_MESSAGE` if `e.get_ref()` downcasts to `Canceled`, else `e.to_string()`. `already_handled()` = `new(false, already_handled,
None)` with `superseded: true`, `journal_persisted: true`.

**C. Cancellation.** Refusals decided before the hand-off are `Ok` even with a cancelled token (golden `single-cancelled-before-but-refused-earlier`,
`group-cancelled-before-and-live-is-already-handled`); the single path's live check is AFTER the hand-off, so cancelled + live => `Err(Canceled)`
(golden `single-cancelled-before-and-live`). The gate refusal wins over cancellation. Inside the group loop a cancellation is a journaled failure
(`ErrorCode CancelledByUser`, message `OPERATION_CANCELED_MESSAGE`), never `Err`. The single path never checks the token after the hand-off.

## Traps (MULTI-AGENT-PLAN §7 + invariants)
- **INV-4** gate: taken first, released on every path including panic (guard), not released when refused. **INV-6**: Prepared strictly before any
  mutation, exactly one outcome line, same Id as the snapshot; never append Prepared when the pre-checks refused. INV-3 / INV-5 (catalog and
  presenter ordering), INV-8 (decoder handles) and INV-11 (settings) do not apply: this unit touches no catalog, decoder or config (the App
  presenter that refreshes the Recovery list after a retry is W8).
- **P02** (two processes, one journal): only the transaction's conditional appends decide `superseded`; never append anything yourself.
  **Q-R27**: never call `live_operations().begin` here (the transaction does); only `is_live`.
- **Data safety (R01a, RV-C03, R15, R17, R18, Q-R8, F-WIN-2):** never call `delete`/`delete_permanently` except the Q-R8 path in GX; never overwrite
  (`try_copy_new`, `move_file` without overwrite); re-prove identity right before each mutation; refuse before journaling whenever possible.
- §7.9 exceptions -> Result: the C# catch FILTERS (IO/UnauthorizedAccess/Argument/NotSupported) exist only around the pre-checks; every other error
  is a journaled failure. Rust has one `Err` kind for both; keep the two catch sites distinct (pre-check => no journal; execute => `tx.fail`).
- §7.8 null vs empty: `Some(vec![])` members => single path; destination whitespace => refused; folder `IsNullOrEmpty` (X) vs `IsNullOrWhiteSpace` (GX).
- §7.3 `FileStat.length` is `u64`, journal sizes `i64`: compare via `i64::try_from(len)` (never `as i64` on the compare path; `prepared.size =
  stat.length as i64` is safe below 2^63 but prefer `i64::try_from(..).unwrap_or(i64::MAX)`).
- §7.5 `DateTime ==` ignores `Kind`: compare `JournalDateTime.value` only (a snapshot parsed from an Unspecified text must still match).
- Exact file-system call ORDER and COUNT are observable (C# tests hook "the Nth stat of a path"; the golden `ops` list): no extra `file_exists`
  before a stat, no stat caching across steps, one `stat` per C# `GetFileStat`.
- `RecoveryFileCheck` is constructed per call over the same `Arc<dyn FileSystem>` (no shared state).
- AGENTS.md Recycle Bin rule: tests use `FakeRecycleBin` or the harness `ScriptedBin`; never `pr-platform-win`'s bin, also not in mutation runs.

## Open questions
1. **JournalTransaction surface.** "Depends on" now mirrors the W3-01 draft `transaction.rs` (review: `retry_of` is an owned
   `Option<JournalEntry>`, paths and codes are `&str`; the first draft of this contract assumed `Option<&JournalEntry>` and `&Path`). If W3-01
   changes again, only the private bodies here change; the public API of W3-06 does not. Recommendation: the lead freezes the W3-01 surface
   before both porters start.
2. **Gate trait.** W3-05 drafts `undo::FileActionGate { try_begin, end, is_busy }`; this stub imports it instead of declaring a twin (the first
   W3-06 draft had `FileActionInterlock`). Recommendation: hoist it to a lead-owned `file_actions/gate.rs` (W3-04 implements it); then only the
   `use` line here changes.
3. **Stat seam (W3-07 P1).** Under option A every stat here goes through `try_get_file_stat`; under option B stats cannot fail: 5 C# rows
   (FileCheckFault 1, Mutation theory 4) and the 6 `needs_stat_seam` golden cases become `// DIVERGENCE:`
   with a `Different` note on F-18. Recommendation: A (same as W3-07).
4. **Negative member size on undo restore** (`RecycleBin::try_restore` takes `u64`): recommended "restore failed, bin not called" (unreachable for
   app-written journals; `// DIVERGENCE:` comment, no golden case). Alternative: change the trait to `i64` (touches W0 + pr-platform-win).
5. **Texts overlap with W3-05.** `core_undo_recycle_target_exists/restore_failed` exist in both `UndoTexts` and `RecoveryRetryTexts`; the App root
   implements both from one catalog. Acceptable now; a shared `FileActionTexts` can come with W3-04.
6. **Threading tests** (`RunsMutationOffCallerThread`, `RunsTheBinCallsOffTheCallerThread`): not ported per R0003 (blocking API; the presenter
   picks the thread). Lead to confirm no ADR beyond R0003 is needed (recommended: none; a note on F-18).
7. **Stat errors inside the transaction's verify (W3-01 x W3-07).** C# `VerifyDestination` calls `GetFileStat`, which can throw (journaled
   failure). W3-01's `verify_destination` calls `get_file_stat` (cannot fail), so under P1 option A a seam error at the single path's verify
   stat is not reproducible. No C# test and no golden case injects a fault there (the `needs_stat_seam` cases hit the pre-check, R17 and the
   group loop only), so nothing fails today. Recommendation: under option A, W3-01 switches `verify_destination`/`verify_moved` to
   `try_get_file_stat` too (one place for every stat); otherwise a one-line `Different` note on F-18.
8. **Oracle language.** The golden `result.message` values are the ambient `Tr` texts; the oracle relies on `Localizer.Current` defaulting
   to English (the oracle process must not have run `l10n-localizer` / `SetCurrent` before `recovery-retry`). The lead checks this when
   wiring the dispatch line (expected: one command per process, nothing to do).
