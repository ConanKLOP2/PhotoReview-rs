- Semantics notes (C# line numbers refer to the baseline file):
  1. **Decode entry (`Decode`).** (a) No `bytes` and `path` empty or all whitespace -> `Err(InvalidArgument)`; this check is OUTSIDE the
     relabel, so it stays `InvalidArgument` (not fallbackable). `DecodeRequest::path` is a `PathBuf` (W4-01b): blank means
     `request.path.to_str().is_some_and(|s| s.chars().all(char::is_whitespace))` (empty included; a non-UTF-8 path is never blank). With `bytes`, the path is only a label (`""`, `"   "`, a missing file: all
     decode from the bytes; golden `bytes-with-*`). (b) Source: `bytes` -> `ComStream::from_bytes(bytes.clone())` (no copy; never touches the
     file system: `reader_calls` is empty in the golden); else `source_reader.open_source(Path::new(path), request.priority,
     DECODE_SOURCE_BUFFER_SIZE)` wrapped in `SourceStreamBackend` -> `ComStream::new`. An open error goes out through `From<io::Error>`
     unchanged (missing file -> `FileNotFound`; trap T5 for a missing directory). (c) Pipeline errors -> `relabel_invalid_argument(e,
     DECODER_LABEL)`. (d) The stream (and with it the file handle) is released before `decode` returns, on every path (INV-8): no WIC
     object may outlive the call.
  2. **ReadInfo.** Blank path -> `InvalidArgument` (not relabelled). Open with `SourceReadPriority::Viewer` and 64 KiB. Factory, decoder
     from stream with `WICDecodeMetadataCacheOnDemand`, frame 0, `GetSize` -> `to_int_size` (refusal is `InvalidData`), orientation =
     `exif_reader::read_orientation(frame)` (W4-11d, never fails). `ImageInfo::with_orientation(w, h, orientation)`: STORED size;
     W4-01b's `width()/height()` swap for 5..8. No colour, no pixels. Errors -> `relabel_invalid_argument`. Note: C# ReadInfo relabels ANY
     `ArgumentException`, Decode excludes `ArgumentNullException`; Rust has no null, so both are the same function.
  3. **Factory and frame.** `interop::create_factory()`; `create_decoder_from_stream(factory, &stream.istream(), WICDecodeMetadataCacheOnDemand)`;
     `get_frame(decoder, 0)`; `GetSize` -> `to_int_size` (the result is only a guard; `orig_w/orig_h` stay `u32` for the scaler maths).
  4. **Orientation and EXIF (one metadata read).** `root = exif_reader::exif_ifd_root_of(decoder)` (JPEG `/app1/ifd`, TIFF `/ifd`, else
     `None`). If `apply_orientation && source_orientation.is_some()`: orientation = that value AS GIVEN (no normalisation: 9, 0, -1 are kept and
     reported; golden `plain-source9-*`), and `read_frame_metadata(frame, false, root)` only for the EXIF. Else orientation =
     `read_frame_metadata(frame, apply_orientation, root).orientation` (1 when `apply_orientation` is false), EXIF from the same read.
     `transposed = apply_orientation && orientation::is_transposed(orientation)`.
  5. **Downscale decision.** Only when `request.is_downscale_requested()`: `(fw, fh) = request.decode_box().fit_stored(orig_w as i32,
     orig_h as i32, transposed)`; only when `fw < orig_w || fh < orig_h` (as u32) does scaling happen and `downscaled = true`. The box
     applies to the DISPLAYED image (scale first on the stored grid, rotate last).
  6. **Two-stage scale.** Stage 1: `try_get_native_reduced_size(frame, (tw, th), (ow, oh))`; when `Some((nw, nh))`, a scaler with
     `WICBitmapInterpolationModeFant` at `(nw, nh)` directly on the FRAME (so WIC serves it through `IWICBitmapSourceTransform`, DCT 1/2,
     1/4, 1/8, no resampling). Stage 2: always a second scaler to `(tw, th)` on the current source with `HighQualityCubic`; if its
     `Initialize` fails with a `Com`-kind error, `Initialize` the SAME scaler again with `Fant`. Any other error propagates.
  7. **Output format.** `GetPixelFormat` of the CURRENT source (after scaling) -> `opaque = is_opaque_format(..)`. Output layout:
     `Bgr32` (`GUID_WICPixelFormat32bppBGR`) when opaque, else `Pbgra32` (`GUID_WICPixelFormat32bppPBGRA`). Indexed and unknown formats
     count as alpha-capable (golden `format-png-indexed8` -> `Pbgra32`).
  8. **Colour management (after scaling, before the converter).** `read_color_contexts(factory, frame)` (the FRAME, not the scaled
     source); `select_source_color_context` (profile wins; else the first non-sRGB EXIF colour space; sRGB/untagged -> none; a failing
     `GetContextType`/`GetExifColorSpace` is NOT caught in C#: it propagates through `decode_error_from_wic`, a `Com` kind being a
     fallbackable `COMException`); when one is chosen: `ColorTransformChain::build(factory, current, profile, opaque)` (transform format 32bppBGR opaque / 32bppBGRA straight alpha,
     destination `InitializeFromExifColorSpace(1)`, first try the native source format, on a `Com`-kind failure of that `Initialize` normalise
     with a format converter and retry; ANY failure of the build, including `CreateColorContext`/`InitializeFromExifColorSpace` and the
     FIRST `CreateColorTransformer` (outside the inner catch), -> `color_chain_failure`). The chain and the contexts are released at the end
     of the call on every path.
  9. **Format converter.** Always: `CreateFormatConverter` + `Initialize(current, output_guid, WICBitmapDitherTypeNone, None palette, 0.0,
     WICBitmapPaletteTypeCustom)`. Failures propagate with their own mapping (NOT an ICC failure: IMG-04).
  10. **Rotation.** Only when `apply_orientation && orientation > 1` and `map_to_transform_options(orientation) != Rotate0`: a flip-rotator
      with those options on the converter's output. Orientation 9 (or any value outside 2..8) creates no rotator.
  11. **Output size and admission (R16).** `GetSize` of the final source -> `to_int_size`; then `ensure_output_fits(w, h,
      output_byte_length(w, h), memory_info)` BEFORE any allocation; then `stride = w * 4`, `buffer = stride * h` (`checked_mul`, `None` ->
      `Overflow` like C# `checked`: after the guard this can only happen for a zero-height output, whose 0-byte length skips the guard
      while `w * 4` still overflows; WIC never reports it, but keep C#'s order: guard first, then the checked maths). `allocate_and_fill(w, h, layout, |buf| CopyPixels(NULL rect, stride,
      buf.bytes_mut()?), chain.is_active())`. The ONLY `CopyPixels` of the decode writes straight into the `PixelBuffer` (WP-03: one copy).
  12. **Result.** `codec.image_from_pixels(buffer)?` (ownership moves; on error the buffer is already dropped). `DecodedImage::new(platform,
      w, h, buffer_len as i64, DecodedImageOptions { downscaled, orientation, actual_backend: WicDirect, original_width: if transposed
      { orig_h } else { orig_w }, original_height: (swapped likewise), exif, is_degraded_fallback: false })`; a `DecodedImageError` maps to
      `InvalidArgument` (then relabelled to `InvalidData`; cannot happen for WIC sizes >= 1). `estimated_bytes` = the buffer length.
  13. **Pure helpers** are specified on each `pub fn` in the stub (messages byte-identical to C#, see the golden `wic-direct-internals`).
      `ensure_output_fits` reads `memory_info` at most once and NEVER below the threshold or outside the int range (the golden records
      `consulted`).
- Traps checklist (MULTI-AGENT-PLAN section 7 plus unit-specific):
  - T1 (section 7 item 9) **Every C# `catch (X)` is a filter on the .NET exception TYPE that `Marshal.GetExceptionForHR` builds.** The Rust
    test is the kind, never "any Err": `catch (COMException)` = `WicError::exception_kind() == Com` ONLY (E_INVALIDARG is `Argument`,
    E_OUTOFMEMORY `OutOfMemory`, E_NOINTERFACE `InvalidCast`: none of them is caught there). Places: scaler HighQualityCubic retry (6),
    `GetClosestSize` (6), chain first `Initialize` (8), ReadColorContexts (`Argument or Com`), chain build (`Com or InvalidCast or Argument`).
  - T2 (item 3) `u32` sizes: `to_int_size` before ANY `as i32`; `output_byte_length` saturates; the admission check runs before the checked
    stride maths, so a hostile header is `MemoryAdmission` (not fallbackable), never `Overflow` (fallbackable, would hand a bomb to the fallback).
  - T3 **INV-12 mapping.** `decode_error_from_wic` must give the variant whose W4-12b fallback verdict equals C# `IsFallbackable` for the .NET
    type (golden `fallbackable` column in every error row is the oracle). `FileNotFound/DirectoryNotFound/OutOfMemory/MemoryAdmission/Canceled`
    must never come out as `Com`/`InvalidData`.
  - T4 `ArgumentNullException` exclusion (C# line 54) has no Rust counterpart; record `// DIVERGENCE: no null in Rust` at the relabel test.
  - T5 Missing DIRECTORY: C# `DirectoryNotFoundException`; Rust `io::ErrorKind::NotFound` -> W4-01c `From` gives `FileNotFound`. Both are
    not fallbackable, so behaviour matches; the TYPE differs (golden `fail-missing-directory`). Record `// DIVERGENCE:` and assert only

## Open questions
1. **Localized sentences.** C# attaches `Tr.ErrDecoder*` sentences (`invalidDimensions`, `decompressFailed`, `outputTooLarge`,
   `iccTransformFailed`) with `UserFacingError.Localized`. W4-01c's `DecodeError` has no slot for a `pr_l10n::LocalizedText`. Options:
   (A, recommended) W4-01c adds `localized: Option<LocalizedText>` to the variants built by decoders (or one wrapper variant
   `Localized { inner: Box<DecodeError>, text }` whose `message()`/fallback verdict delegate to `inner`), and this unit fills it with
   `pr_l10n` keys; (B) keep English only and mark the four `UserFacingError` facts `Partial` in PARITY. Until decided, the stub's helpers
   return the English error and the localized asserts are `#[ignore = "blocked: W4-11c OQ1"]`.
2. **W4-11d traits on WIC types (resolved in review).** The W4-11a contract assigns the `FrameMetadata` / `DecoderContainer` /
   `MetadataQueryReader` impls for the `windows` types to W4-11d (its own file, including the `windows_core::GUID` ->
   `pr_core::catalog::explorer_types::Guid` conversion). Nothing to add here; if W4-11d lands without them, the lead adds them there, not here.
3. **A stream fault that C# reports as `ArgumentException`.** `WicDirectFaultInjectionTests.*_StreamReportsInvalidArgument_*` throw
   `ArgumentException` from `Stream.Read`; the CCW returns E_INVALIDARG and the decoder relabels it `InvalidData`. A Rust `SourceReader`
   can only return `io::Error`, which W4-11a's `StreamFault::Io` turns into `HRESULT_FROM_WIN32(os code)` or `COR_E_IO` (-> `IOException`,
   not fallbackable). Recommended: W4-11a maps `io::ErrorKind::InvalidInput` without an OS code to `E_INVALIDARG` (what a .NET
   `ArgumentException` crossing the CCW gives), so the Rust twin is "reader returns `InvalidInput` -> `InvalidData`". Alternative: drop the
   two tests as C#-runtime specific (`Different` note).
4. **COM fakes for the fault-injection tests.** C# drives `ReadColorContexts`/`ColorTransformChain`/`TryGetNativeReducedSize` with managed
   fakes of WIC interfaces. Rust can do the same with `#[implement(IWICColorContext)]` etc. (needs the `windows-core` `implement` support W4-11a
   already uses), but `IWICImagingFactory` has 28 methods. Recommended: keep the pure filters (`is_color_metadata_fault`,
   `color_chain_failure`, `native_reduction_is_useful`, `select_source_color_context`) as the ported tests and cover the COM paths with the
   real-WIC goldens; a verifier may still add `#[implement]` fakes for `IWICBitmapFrameDecode` + `IWICBitmapSourceTransform` if a mutant in
   `try_get_native_reduced_size` survives.
5. **Lifetime-balance tests (resolved in review).** W4-11a requires every out object to go through `Com::adopt` (counted), and its
   `create_*` / `get_frame` helpers already return `Com<T>`. The stub's private colour-context list and `ColorTransformChain` fields are now
   `Com<..>` too; `GetColorContexts` gets a temporary `Vec<Option<IWICColorContext>>` of uncounted clones of those contexts. Interfaces obtained
   by `cast()` (`IWICBitmapSource` views of the scaler/converter/rotator/transform) are views of an already-counted object and stay plain.
   The three `WicLifetimeBalanceTests` are therefore ported (native).
6. **`memory_info` has no default.** C# defaults to `MemoryHeadroom.ReadGcMemoryInfo`; the Rust production reader is unowned (W4-07b OQ2). The
   constructor takes it explicitly; the composition root (W4-12a / W8) passes the Windows reader. If the lead prefers C#'s shape, add
   `WicDirectDecoder::with_defaults(codec)` once the reader exists.
7. **Draft mismatch W4-01b vs W4-01c (for the lead).** W4-01c's `ImageDecoder::decode` returns `Arc<dyn DecodedImage>`, but in W4-01b
   `DecodedImage` is the struct and the trait is `DecodedImageView`; `to_pixels` also needs `PixelLease<'_>`. This stub compiles against the
   drafts with `Arc<dyn DecodedImageView>`; whichever name the lead keeps, only the `use` line and the `decode` return type change.
   Second mismatch in the same pair: W4-01c's `PlatformImage` is `Arc<dyn Any + Send + Sync>` (what `image_from_pixels` returns) while
   W4-01b's `DecodedImage::new` takes its own `enum PlatformImage { Pixels(Arc<PixelBuffer>), Opaque(..) }`. Semantics 12 needs ONE type;
   recommended: W4-01b's enum everywhere (the codec returns `PlatformImage::Pixels`, so W4-14 / D2D can reach the buffer without
   `downcast`). Until the lead decides, the porter converts at the call (`PlatformImage::Opaque(arc)`) and notes it.
8. **Pure helpers in a Windows crate.** `as_invalid_data`, `ensure_output_fits`, `output_byte_length` are reused by C#'s WPF decoder and
   would suit the Wave 5 TurboJpeg decoder too. They are WIC-free; the lead may move them to `pr_imaging` (e.g. `decode_guards`) in Wave 5
   without changing their bodies.
