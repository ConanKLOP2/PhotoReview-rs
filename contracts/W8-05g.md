## Design (why the class is not a literal port)
- **State vs references (D-W8-1).** C# keeps five references in fields and mutates `ViewerState` (an `ObservableObject`) from inside the class. Rust has single ownership, so the controller keeps ONLY its own state and every call gets a
  `PointerContext` of borrows. The `ViewerState` updates the controller causes are accumulated (`take_viewer_update`) so the shell can repaint and stop the glide on `zoom_mode_changed`, as the C# event handlers did.
- **Await (D-W8-2).** The C# `YieldToRenderAsync` becomes `PointerStep::AwaitRender`; `resume` is the code after the `await`. This is exactly `viewport::fit::{apply_fit_start, apply_fit_resume}` for Fit. The `ImageSurface::yield_to_render` of 05a is therefore NOT called
  by the controller (O1); the shell owns the yield, posts `resume` at Render priority, and must ALWAYS resume (the counter `zooms_awaiting_layout` is balanced in `resume`).
- **Fire-and-forget tasks.** `FireAndLog` tasks become: `commands.apply_fit()` (a post), and the bitmap-swap re-anchor, whose continuation is parked in `pending_continuation` because it is created inside the `ViewerState::swap_source_size` callback, which cannot return it.
- **Commands.** `NextAsync`, `PreviousAsync`, `ApplyFitAsync` only POST; an implementation must never call the controller synchronously (borrowck forbids it anyway).

## Semantics notes (each is a C# behaviour; line numbers refer to `PointerInputController.cs`)
1. **Wheel entry (77-115).** `StopKinetic` first, always. The touchpad classifier is fed only when `TouchpadSwipeEnabled && !Ctrl` (the `&&` short-circuits, `isTouchpad` is otherwise false). `Route(input, enabled, isTouchpad, CanPan())`:
   `Ignore` returns; `Pan` resets both the wheel interpreter and the swipe navigator, then scrolls; `Navigate` resets the wheel interpreter only, feeds the swipe navigator with `settings.TouchpadSwipeDistancePerImage`, logs, navigates;
   otherwise (mouse wheel or pinch) the swipe navigator is reset and `WheelGestureInterpreter.Handle(delta, ctrl, MouseWheelAction)` decides: `Zoom` goes to `ZoomAtPoint` with `ViewerState.WheelZoom(delta)`, anything else to `NavigateAsync`.
2. **Navigate (118).** `Next` and `Previous` each call the command only when `HasImages()`; `Zoom` and `None` do nothing.
3. **PanByTouchpad (132).** `TouchpadGestureRules.PanOffsetDelta` gives an OFFSET change; `CalculatePanOffsets` wants a POINTER movement, so the call passes `-horizontal`, `-vertical` (a `-0.0` is possible and must be kept). One `ScrollTo`.
4. **Keyboard zoom (153-185).** No images: return before anything. Else `CancelPan`, `StopKinetic`, `ZoomAtPoint(ResolveKeyboardAnchor(), ..)`. `ResolveKeyboardAnchor` = `PointerGestures.ResolveKeyboardZoomAnchor(settings.KeyboardZoomAnchor, surface.PointerPosition, viewportW, viewportH)`:
   the cursor only with `Pointer` mode and a pointer over the viewport, else the viewport centre (the test pins the exact `ToImageElement` argument).
5. **ZoomToImagePoint (203-227).** Order: `version = Next()`; `_zoomsAwaitingLayout++`; `applyZoom()`; when loaded `ScrollAnchorTo` and capture metrics (the scroll is placed in the SAME operation as the zoom, before the render pass); await the render pass;
   `version != Current || !IsLoaded` returns false (no second placement, and the caller's follow-up must not run); `placed != CaptureLayoutMetrics()` (also when `placed` is null) places again; `finally` decrements the counter. The anchor is captured BEFORE the zoom.
6. **CaptureZoomAnchor (364).** At Fit with a known positive source size, the pointer is mapped through the letterboxed (Uniform) element to SOURCE pixels (`CalculateUniformImagePoint`) and normalised by the source size; otherwise the element point is normalised by the element's actual size.
   `ToImageElement` is called once.
7. **ScrollAnchorTo (260).** `UpdateLayout()` first (so the geometry is current), then `CalculateZoomToPointOffsets(anchor, imageOrigin, imageActualSize, viewportPoint, offsets, extent, viewport)`, then ONE `ScrollTo`.
8. **Bitmap swap (244-257).** ADR 0008 amendment R4: keeps the viewport-centre image point in place. Skipped while a zoom awaits its layout (`_zoomsAwaitingLayout > 0`), when not loaded, or when the element has no width or height. The version captured is `Current` (NOT `Next()`): a later
   viewport operation drops it, and it does not supersede anything itself.
9. **Fit width / height (290-361).** No images: nothing. `CancelPan`, `StopKinetic`, anchor (the CALLER's `FitWidthAnchor`, or (0.5, 0.5) for height), `ZoomToImagePoint(anchor, viewportCentre, ApplyFit*)` where `ApplyFit*` first force-updates the viewer's viewport from the surface, then zooms.
   After a pass that was NOT superseded, `CorrectForSideScrollbar` re-runs the SAME Fit once when the OTHER axis overflowed by more than 0.5 DIP (`ExtentWidth > ViewportWidth + 0.5` for width, height for height; an overflow of exactly 0.5 does not count), because the scrollbar WPF shows eats into the viewport the zoom was computed against.
10. **Initial view (318).** `ViewerState.ApplyInitialViewMode` does the zoom (a no-op with `KeepZoomAcrossImages`); only `FitWidth` / `FitHeight` then place the scroll (a pass with no zoom action), with the same scrollbar correction. Fit and the click-zoom level place no scroll.
11. **`CanPan` (542).** `!IsFit && (ExtentWidth > ViewportWidth + 0.5 || ExtentHeight > ViewportHeight + 0.5)`. **`CancelPan` (545)** always calls both surface methods. **`StopKinetic` (630)** unhooks only when hooked and returns whether a glide was active.
12. **`OnCurrentIndexChanged` (66).** Only a CHANGED index stops the glide and resets the wheel interpreter.

## Traps checklist
- **T1 INV-9 style token (version) on every completion.** Every `resume` compares `versions.current()` with the version taken at the start; a superseded pass must not scroll and must not run its `then`. The re-anchor after a swap uses `current()`, not `next_version()`.
- **T2 Counter balance.** `zooms_awaiting_layout` goes up in `zoom_to_image_point` and down in EVERY exit of `resume` (superseded, unloaded, normal). A continuation that is never resumed blocks the swap re-anchor for good: the shell must resume even at window close.
- **T3 Order inside the first pass.** version, counter, zoom, scroll, metrics. Placing the scroll after the render pass brings back the "ghosting" frame the C# comment describes. The test `ZoomAtPoint_PlacesTheScrollBeforeTheRenderPass_..` pins it (the scroll count at the moment `AwaitRender` is returned).
- **T4 Short-circuit.** `TouchpadSwipeEnabled && !Ctrl && classifier.IsTouchpad(..)`: the classifier mutates (`in_gesture`, `last_timestamp`); calling it when disabled or Ctrl changes later results. Use `&&`.
- **T5 `-0.0` and NaN.** The negated touchpad delta keeps `-0.0`; `LayoutMetrics` equality is `double.Equals` (NaN equals NaN, `0.0 == -0.0`): implement it with `f64_same`, never derive `PartialEq`. The 0.5 overflow comparisons are strict `>` and false for NaN.
- **T6 Anchor before zoom.** `capture_zoom_anchor` reads the pre-zoom layout; calling it after `apply_zoom` anchors to the wrong point. `to_image_element` is called exactly once per capture.
- **T7 Fit correction reuse.** The correction re-runs the same `ZoomAction` (FitWidth / FitHeight) with a fresh version and `AfterZoom::Nothing`; it must not chain a third pass.
- **T8 Settings read.** C# reads `_settings()` at each use; within one call it is one object. Do not cache settings across calls (a settings reload changes `KeyboardZoomAnchor` etc. between gestures).
- **T9 UI thread only.** No `Send`/`Sync` requirement; the controller holds no references and no threads.
- **T10 No `unsafe`, no `windows`, no `std::time`.** The only clock is `surface.timestamp()` (05h).
- **T11 Viewer update bookkeeping.** Every `ViewerState` call the controller makes (`wheel_zoom`, `zoom_in`, `zoom_out`, `set_zoom`, `zoom_to_actual_size`, `update_viewport`, `zoom_to_fit_width/height`, `apply_initial_view_mode`) goes through `record_viewer_update`, or the shell never repaints.

## Open questions (each with a recommended default; the stubs follow the default)
- **O1 Yield and frame hooks vs the B1 `ImageSurface`.** `ImageSurface::yield_to_render(continuation: Box<dyn FnOnce()>)` and `hook_render_frame(handler)` assume a closure that can call back into the controller; borrowck forbids that without `Rc<RefCell>`.
  Recommended (used): the controller never calls `yield_to_render`; it registers a NO-OP handler with `hook_render_frame` only to get the `RenderHookId` (balanced hook / unhook) and the shell routes frames to `on_kinetic_frame` (05h).
  Recommended B1 change (lead, optional, no stub depends on it): remove the `handler` parameter of `hook_render_frame` and the whole `yield_to_render` method from `input/surface.rs`, since both are the shell's job now. Until then the stubs compile against the current trait.
- **O2 `ZoomActualSize` is not a command.** See the `PointerCommands` doc. If W8-08a's host method does more than `has_images` + `zoom_to_actual_size`, add it back as a member and call it BEFORE the zoom pass; the baseline does not.
- **O3 `ticks_per_ms` as a constructor argument.** C# reads `Stopwatch.Frequency / 1000.0` statically. Recommended: the shell passes `pr_core::diagnostics::perf::STOPWATCH_FREQUENCY as f64 / 1000.0` (10 000.0), the rate of `perf::timestamp()`; whatever `ImageSurface::timestamp` returns must use the same rate.
- **O4 Settings object per call.** `PointerContext::settings: &AppSettings` (not a getter). A shell that keeps settings behind a lock clones the current `AppSettings` (or holds a read guard) for the call.
- **O5 Plan edges.** Add to `docs/WAVE-8-PLAN.md` when scheduled: 05g needs 05f, 04e, 06a (and not 01b / 01d); 05h needs 05e and 04e as well as 05g and 05f. (The lead owns the plan.)
- **O6 `ViewerState::swap_source_size` callback type.** `&mut dyn FnMut(&ViewerState)` gives the handler only `&ViewerState`; `on_source_size_swapping` therefore takes `&ViewerState`, `&dyn ImageSurface` and `&ViewportOperationVersion` and parks its continuation. No B1 change needed.
