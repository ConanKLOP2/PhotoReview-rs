## Semantics notes
1. **What the executor is.** A thin composition of the REAL `PreviewImageService` and `PreloadScheduler` (no benchmark-only cache), so P50/P95 reflect the app. Its own logic is: how
   the profile is turned into service/scheduler configuration, the preload-hit accounting in `decode`, the cold-decode eviction, the profile window around the scheduler, and teardown.
   Do not re-implement any cache, queue or policy: if a behaviour looks missing, the merged W4-14/W4-15 code already has it.
2. **Constructor wiring (the exact mapping; each line is a possible mutant).**
   - Scratch directory: `scratch_parent.join(new_scratch_directory_name())`, `scratch_parent` default `temp_dir()/PhotoReviewRs-Benchmark-Cache`. Created lazily by the disk store, not by `new`.
   - `is_original = profile.loading_mode == LoadingMode::Original`, evaluated ONCE and captured by value (C# closes over the local). `target_decode_box` is
     `PreviewServiceConfig::width_only(|| profile.target_width())` (height 0). The profile is cloned into the closure; it is NOT re-read from the caller later.
   - `capacity_bytes = perf_options::IMAGE_CACHE_CAPACITY_BYTES` (16 GiB), `disable_disk_cache_override = Some(!profile.disk_cache)`: `Some(..)` ALWAYS, so the diagnostic variable
     `PHOTOREVIEW_RS_DIAG_DISABLE_DISKCACHE` cannot turn the disk cache on or off in a benchmark (C# passes `disableDiskCacheOverride:`). `disk_cache_capacity_bytes` stays the default.
   - `PreloadOptions { worker_count: profile.workers, memory_load_limit: PRELOAD_MEMORY_LOAD_LIMIT (0.90), reserve_bytes: profile.memory_reserve_bytes,
     full_folder_threshold_bytes: profile.full_folder ? service.capacity_bytes() : 0, window: default }`. The threshold `0` for a non-FullFolder profile is a correctness feature
     (a small folder must not escalate to a whole-folder pass): test `executor_full_folder_controls_whole_folder_warming` pins both rows.
   - The scheduler's target is the `WindowedPreloadTarget` (which wraps the service), its entries snapshot is the fixed list of the profile's files (`CatalogEntry::new(file)`), its memory
     probe is `DelegateMemoryProbe(has_headroom)` when given, else the OS probe. Logging: the scheduler gets no log (C# passes none).
   - The environment variable `PHOTOREVIEW_RS_DIAG_PRELOAD_WORKERS` still WINS over `profile.workers` inside `PreloadScheduler::new` (the C# `PHOTOREVIEW_DIAG_PRELOAD_WORKERS` does too).
     Tests must not depend on the process environment (do not set it; the pre-existing scheduler tests use `env_lookup`, which the executor does not expose).
3. **`decode`.** Order is fixed: cancel check, key, then the hit test, then the service call (see the stub doc). The hit rule is `service.try_get_cached_preview(&key).is_some() &&
   scheduler.try_consume_preloaded_key(&key)`: `&&` order matters because the second call has a side effect (it forgets the key). Cancellation is checked only before the work starts.
   `Err(Key(..))` is what C# threw synchronously (`FileNotFoundException` for a missing file). `decode_async` returns the `PreviewHandle` so a caller can overlap several decodes
   (W7-03c's parallel workloads); `decode` is the blocking convenience.
4. **`evict_for_cold_decode`.** RAM first (`evict_cached_path` with the scheduler callback that forgets the preloaded key of that normalized path), then `clear_disk()`. `clear_disk`
   bumps the cache epoch (INV-2) and empties the scratch directory; it does not touch other executors' directories (each has its own).
5. **`warm_preload_around`.** `set_center` BEFORE `preload_around`: the windowed target must already know the new centre when the scheduler asks it about candidates. The kick is not
   awaited; `when_preload_settled` waits for the LAST run (earlier ones are ignored, as in C#).
6. **`WindowedPreloadTarget`.**
   - Index: `ignore_case_key(get_full_path(file))` -> position; a later duplicate (same path up to OrdinalIgnoreCase) overwrites the earlier one. `get_full_path` failing (empty or blank
     path, `\0`) fails construction (golden `window-empty-path-throws`, C# `ArgumentException`).
   - `outside_window` is exactly C#: `false` if `full_folder` or the path is not in the index, else `delta = index - center` in **unchecked 32-bit** arithmetic and `delta > next ||
     -delta > previous` (also unchecked: `-i32::MIN == i32::MIN`). Use `wrapping_sub` / `wrapping_neg` on `i32`; `i64` or checked arithmetic gives a different verdict for
     `center = i32::MIN` (golden `window-center-int-min-wraps`). A profile's `next`/`previous` are NOT validated here (golden `window-negative-sizes-unvalidated`).
   - Two lookups with two different key spellings: `try_get_cached_preview_for_path` looks up the path AS GIVEN (no `get_full_path`), `try_get_cached_preview(&key)` looks up `key.path()`
     (already upper-cased full path). A non-normalized probe is "not in the index" by path but found by key (golden `window-unnormalized-by-path`: the by_path and by_key columns differ).
   - The verdict is `outside || inner.<same call>`: the inner target is NOT asked when the path is outside (short-circuit; test with a counting fake).
   - Every other member forwards to the inner target, including the three that have trait defaults (`active_viewer_decodes`, `cached_preview_bytes`, `has_disk_cached_preview`): a missing override
     silently turns the inner answers into 0 / `None` / `false` and breaks the viewer-busy and whole-folder logic (test with an inner that returns non-default values).
   - `center` is an `AtomicI32` with release store / acquire load (C# `Volatile`).
7. **`BenchmarkProfileScope::apply_logging`.** `get_enabled()` read once; `set_enabled(profile.detailed_logging)` called ALWAYS (even if equal: the golden counts writes); the write counter
   is sampled right after that write. Restore: skipped when a counter exists and changed (someone else wrote, even the same value); otherwise `set_enabled(previous)` (also called when
   `previous == current`). At most once (second dispose/drop does nothing: golden `dispose-twice-*`). Without a counter the restore always runs (golden
   `external-write-without-counter-is-overwritten`). The C# `ArgumentNullException.ThrowIfNull`s have no Rust twin (references and closures cannot be null).
8. **Teardown (`dispose`).** Order and non-blocking contract from the stub doc. Key facts: step 1 `cancel` before waiting; the persist-worker shutdown finishes BEFORE the directory delete
   can start; the directory delete runs on a separate thread and `dispose` returns WITHOUT waiting for the prune (the C# perf fix: a slow prune must not hold up the next profile); the
   scratch directory is removed only after `wait_for_prune` reports "settled"; on timeout it is LEFT and an error is logged; any failure of the delete is logged and swallowed; the
   `TeardownHandle` completes in every case. Messages (English, exact): `Benchmark persist workers failed to shut down cleanly`, `Benchmark disk cache prune did not finish in time; leaving
   scratch directory: {dir}`, `Benchmark scratch directory could not be removed: {dir}`. The log defaults to `FileLog::default_instance()` (adapter), never to a file in the user's data
   folders beyond what the app log already is.
9. **Threads, not tasks (R0003).** No async runtime: every wait is a condvar/handle wait; tests give each wait a timeout (hang guard). The executor is `Send + Sync` (compile-time guard in the stub).
   Never call `decode`/`dispose`/`when_preload_settled` from a UI thread.
10. **Intentional deviations from C# (document in the module doc; not `Different` rows because the observable benchmark output is unchanged):**
    (a) blocking handles instead of `Task`; (b) `dispose` is explicitly idempotent and there is no `Drop`; (c) the scratch parent is `PhotoReviewRs-Benchmark-Cache` (R0002) instead of
    `PhotoReview-Benchmark-Cache`; (d) `decoder: None` is an error (`NoDecoder`) because the WIC decoder lives in `pr_platform_win` and the host must pass it (C# built it here);
    (e) the constructor takes the payload codec too (`PreviewServiceConfig` requires it; C# used a static WIC encoder);
    (f) review-added: `physical_memory_bytes` defaults to 0 = "unknown" (no clamp of the 16 GiB cache budget to 50% of RAM), whereas the C# service reads the real physical RAM itself and the
    whole-folder threshold is the CLAMPED `CapacityBytes`. The production host (CLI / BenchmarkWindow) MUST pass `ram_budget::get_physical_memory_bytes(..)`, else a benchmark on a small machine
    uses a bigger budget than the app (Open question 5);
    (g) `evict_for_cold_decode` could return `Err(PreviewError::SourceBytes)` (C# source-bytes eviction throws); unreachable here because no source-bytes cache is configured.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- 1 (OrdinalIgnoreCase): the index key is `pr_core::text::ignore_case_key`, never `to_lowercase`.
- 3 (arithmetic): the window delta is unchecked `i32` (see note 6); `service.capacity_bytes()` is `i64`.
- 7 (Windows paths): the index uses `get_full_path` (W2-00), the probe by path does not.
- 8 (None vs Some): `has_headroom`/`decoder`/`log`/`scratch_parent` `None` mean "C# default"; `disable_disk_cache_override` is `Some(..)` always.
- 9 (exception => Result): C# `catch (Exception)` around the persist shutdown and around the whole teardown pass are two separate arms with two separate messages; do not merge them. The
  background pass catches EVERYTHING (it is never awaited), `dispose` catches only the persist-shutdown step.
- 10 (iteration order): the index is a `HashMap` but only point lookups leak out; nothing iterates it.

## Open questions (lead decides)
1. Scratch parent name. Recommended and used by this stub: `PhotoReviewRs-Benchmark-Cache` under `std::env::temp_dir()` (R0002: never share a scratch parent with the C# app). Alternative: keep the C#
   name; then a C# benchmark and a Rust benchmark running together share a parent directory (harmless: unique GUID children) but the C# app's temp sweeper could remove Rust directories.
   Proposal id for `docs/PROPOSED-DECISIONS.md`: P-W7-03b-1.
2. Production memory probe. Recommended: `pr-bench` depends on `pr-platform-win` and `choose_memory_probe(None, ..)` returns `WindowsMemoryProbe` (matches the C# default, one line of Cargo
   change). Alternative: `pr-bench` stays free of the Windows crate and the host (CLI / BenchmarkWindow, which already link `pr-platform-win`) passes a `MemoryProbe`; then
   `BenchmarkExecutorOptions.has_headroom` becomes `memory_probe: Arc<dyn MemoryProbe>` and `None` is no longer representable (a signature change, so decide before the porter starts).
3. Unbounded `shutdown_persist_workers()` in `dispose`. C# awaits without a bound; a stuck persist worker would hang the benchmark teardown forever. Recommended: keep parity (unbounded) because a
   timeout would delete the directory under a live writer; alternative `shutdown_persist_workers_timeout(60 s)` and on timeout log and leave the directory. Not a behaviour the C# tests cover.
4. `decoder: None`. The WIC decoder that C# builds by default is in `pr_platform_win` (W4-11c); this stub makes it the host's job (`ExecutorError::Service(NoDecoder)` otherwise). If the lead wants
   the default back, `choose_decoder` would live next to `choose_memory_probe` behind the same Cargo dependency.
5. (review-added) `physical_memory_bytes`. The `0` default silently differs from C# (deviation f). Options: keep and require the host to set it (as stubbed), or make it a mandatory constructor argument.
   Recommended: mandatory-by-doc now, revisit in W7-03c when the CLI exists.
