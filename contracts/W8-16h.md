## Semantics (C# is the spec)
1. **Construction** (C# 74-86): builds `ViewportState::new(ViewportLayoutEngine)`, subscribes `ShellWindowEvent::ClientSizeChanged` (handler holds a `Weak` of the controller: `update_fit_size()` then `invalidate_layout()`), then calls `invalidate_layout()` once, so exactly ONE job is posted at Render priority and nothing is laid out until it runs (extent 0 before). Returned as `Rc` (`Rc::new_cyclic`; the posted job and the window / clock closures hold `Weak`).
2. **`invalidate_layout`** (C# 98-103): returns when `layout_posted` or disposed; else `layout_posted = true`, `poster.post_render(job)` where the job (on the UI thread) does `layout_posted = false`, then, if not disposed, `run_layout()`. Coalescing: any number of calls before the job runs post one job; a call after it ran posts another.
3. **`run_layout`** (C# 123-138): `changed = false`; loop at most `MAX_LAYOUT_ITERATIONS` (8) times: `content = (self.content)()`; `state.set_input(current_input(&content))`; `image_size = (state.image_actual_width(), state.image_actual_height())` taken BEFORE the update; `if !state.update_layout() { break }`; `changed = true`; `if content.is_fit && image_size != (new width, new height)` (IEEE `!=` on the two `f64`s: NaN is always "different", as the C# tuple operator) -> `(self.update_fit_size)()`. After the loop: `!changed` -> return; else `window.invalidate()` then raise `LayoutUpdated`. The fixed-point loop is how the Fit size feeds back into the same layout (`FitSizeHook_FeedsBackIntoTheSameLayout_UntilStable`).
4. **No borrow across the callbacks (D-W8B4V-9).** `content()`, `update_fit_size()`, `window.*`, the `LayoutUpdated` handlers and `poster.post_render` may call back into this controller (`update_fit_size` of the real window calls `ViewerState::update_viewport`, then `invalidate_layout()` / `scroll_*`). The `ViewportState` lives in a `RefCell` borrowed only for single calls (`set_input`, `update_layout`, a getter); the borrow is dropped before each callback. `LayoutUpdated` handlers run on a snapshot.
5. **`current_input`** (C# 111-117): `ViewportInput { client_width, client_height }` from the window's client size DIP (the host twin `SizeD` read field by field; NOT sanitized here: the engine sanitizes), `scroll_bar_thickness`, `scroll_bars` from the options, and the content fields as given.
6. **`viewport_size`** (C# 150-157): the client size passed through `ViewportLayoutMath.SanitizeLength` (finite and `> 0` keeps the value, anything else is 0): the porter writes a private `sanitize_length` (the `layout.rs` one is private) with the same rule; `(-3, NaN)` -> `(0, 0)`.
7. **`is_loaded`** = `window.is_loaded() && !disposed`. **`update_layout`** = `run_layout()` (synchronous). **`update_fit_size`** = the callback. **`yield_to_render(continuation)`** = `poster.post_render(continuation)` (FIFO behind the layout job posted earlier at the same priority, so the continuation sees the applied offsets); not inline, even when nothing is queued. **`scroll_home`** = `state.scroll_home()` then `invalidate_layout()`. **`scroll_to(h, v)`** = `state.scroll_to(h, v)` (stored clamped below 0 only; applied by the next pass) then `invalidate_layout()`.
8. **Getters** read the state's effective values after the latest pass (`horizontal_offset`, `vertical_offset`) and the layout (`viewport_width`, `viewport_height`, `extent_width`, `extent_height`), `image_origin`, `to_image_element`, `image_actual_width/height`. `source_size()` reads `content()` NOW (not the state): `Some(SizeD { bitmap_width, bitmap_height })` only when both are `> 0`.
9. **`drag_threshold`** = `(h / dpi, v / dpi)` with `(h, v) = options.drag_metrics_pixels()` and `dpi = normalized_dpi(window.dpi_scale())`. **`normalized_dpi`**: `(0.25..=16.0).contains(&x)` keeps `x` (both ends inclusive), everything else including NaN is 1.0.
10. **Mouse and cursor**: `capture_mouse` = `window.capture_pointer()`; `release_mouse_capture` releases only when `window.has_pointer_capture()`; `set_pan_cursor(true)` = `ShellCursor::SizeAll`, `false` = `Arrow`.
11. **Frame hooks** (C# 231-250): `hook_render_frame(handler)`: a new `RenderHookId` (a counter), subscribes ONE handler on the frame clock whose body calls the hook handler with `Some(ticks)` where `ticks = (tick.rendering_time_ms * 10_000.0) as i64` (saturating `as` cast; .NET `TimeSpan.FromMilliseconds` ticks), records `(id, FrameHandlerId)`, then `frame_clock.request_frame()`. Hooking the same closure twice is two hooks (two calls per tick). `unhook_render_frame(id)`: removes that hook's clock subscription; an unknown or removed id is a no-op; safe from inside the hook's own delivery (the host clock supports unsubscribing a running handler). The hook closures are `FnMut`: the clock handler holds the closure in a `RefCell<Option<..>>` slot taken out while it runs, so a hook that calls `hook_render_frame` / `unhook_render_frame` does not double-borrow.
12. **`timestamp`** = `(options.timestamp)()` (QPC ticks, default `qpc_now`). **`display_timing`** = `display_clock.get_timing(window.hwnd())`, `None` without a clock. **`pointer_position`**: `cursor_screen_pixel()` None -> None; `p = window.screen_to_client_dip(screen)` (host twin, converted); `Some(p)` only when `0 <= p.x <= viewport_width` and `0 <= p.y <= viewport_height` (inclusive both ends, using the layout viewport that excludes the bars), else `None`.
13. **`dispose`**: idempotent; `disposed = true`, unsubscribe the window event, unsubscribe every hook from the clock and clear the list. After it: `is_loaded()` false, `invalidate_layout()` posts nothing, a job posted earlier does nothing (no window invalidation), a resize no longer calls `update_fit_size`. `Drop` calls it.
14. **No trait impls for `ImageSurface` / `FitSurface` here** (D-W8B4V-16): this type has their members as inherent methods; W8-14c's `ViewportImageSurface` implements the traits over `Rc<ViewportController>` (it also needs `OperationVersion` and `FitViewer`, which are not the controller's).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (INV-9-like re-entrancy): see 4. Tests: a fit callback that calls `invalidate_layout()` and `scroll_to()`; a `LayoutUpdated` handler that calls `update_layout()` (nested pass, the 8-iteration cap must hold across nesting: nested passes are bounded by their own loops; document and test that it terminates).
- T2 (`f64` equality, section 7): `image_size != new_size` is IEEE inequality of `f64` pairs, NOT `PartialEq` of `SizeD` (NaN-aware); keep the C# tuple semantics (a NaN image size triggers `update_fit_size` each iteration until the cap).
- T3 (coalescing): `layout_posted` must be cleared BEFORE running the layout, so an `invalidate_layout()` made by `update_fit_size()` inside the pass posts a new job.
- T4 (time units): `rendering_time_ms * 10_000` is `TimeSpan` ticks (100 ns), not QPC ticks; the scroll bars' repeat timing uses `timestamp()` (QPC); never mix.
- T5 (hook identity): C# removes the LAST hook of a handler; Rust removes exactly the hook of the id; the "unknown handler is ignored" test becomes "unknown id is ignored".
- T6 (DPI): `normalized_dpi` is used by both `drag_threshold` and 16f's `to_dip`; the closed interval `0.25..=16` is tested at both ends.
- T7 (default engine): `ViewportLayoutEngine` has no state; do not add a cache (the C# engine is a static class).
- T8 (weak self): every closure given to the window, the clock or the poster captures a `Weak<Inner>`; a strong `Rc` would keep the controller alive past `dispose`.

## Open questions (recommended default in bold)
1. **`RenderPoster` seam** (D-W8B4V-4) instead of `Rc<dyn UiDispatcher>`: `UiDispatcher::post_with_priority` takes a `Send` action; a job that reaches this `!Send` controller cannot be one. Cross-unit assumption on **W8-13j / W8-13d**: the main window provides the `RenderPoster` implementation (thread-local queue of `Box<dyn FnOnce()>` + a `Send` wake job at `UiPriority::Render` through `Win32UiDispatcher`); ordering between the layout job and `yield_to_render` continuations is FIFO per poster. Alternative: make the controller `Send + Sync` with `Arc<Mutex<..>>` state (rejected: every `Rc` it touches is `!Send`).
2. **`ViewportController::new` returns `Rc<Self>`**: **yes** (closures need a `Weak`); alternative: the caller wraps it (rejected: cannot create the weak before construction).
3. `hook_render_frame` handler delivery with `Some(ticks)` only: **yes** (the trait type allows `None`, the controller never produces it).
4. `source_size` returns the `pr_app` `SizeD`; `viewport_size` a `(f64, f64)` tuple: **as C# members** (the W8-14c adapter converts to the trait's types: `SizeD` for `source_size`, tuple for `FitSurface::viewport_size`).
5. Cross-unit assumption on **W8-14c**: `ViewportImageSurface` calls these inherent members one for one (the member list in the stub doc is complete for `ImageSurface` and `FitSurface`; `capture` / `ViewportSnapshot` is built by 14c from `ViewerState` plus these getters, as in C# `ViewportImageSurface`).
