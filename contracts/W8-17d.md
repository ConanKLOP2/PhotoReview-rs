## Semantics (C# is the spec)
1. **Options** (`options.rs` in both crates): `EnvOptions::from_env`: prefix = `env.var(INSTANCE_PREFIX_VAR)` when `Some` and NOT EMPTY (a whitespace-only value is kept: `InstanceScope` refuses it later and the start-up fails with the box; this is the C# behaviour, `Length > 0`), else `INSTANCE_NAME_PREFIX`; `prefer_warp = env.var(PREFER_WARP_VAR) == Some("1")` (exact: `"true"`, `" 1"`, `""` are false); `warm_graphics = env.var(NO_WARM_VAR) != Some("1")`. `ShellStartupOptions::from_env`: those three, `activate = true`, `install_process_hooks = true`, `start_perf_listener = true`, `smoke_timeout = DEFAULT_SMOKE_TIMEOUT`, every other member `None` / `ShellServicesOptions::default()`. `Default` reads the process environment.
2. **`ui_hop`** (the `await`): `ui_hop(ui, k)` assigns an id from a process-wide `AtomicU64`, stores `Box<dyn FnOnce(Box<dyn Any + Send>)>`-style type-erased `k` in a `thread_local!` registry of THE CALLING THREAD, and returns the sender. `send(value)` marks the sender sent and calls `ui.post(Box::new(move || deliver(id, Ok(value))))`; `Drop` of an unsent sender posts `deliver(id, Err(HopLost))`. `deliver` runs on whatever thread the scheduler runs the job on: it removes the entry for `id` from ITS thread's registry and calls it; no entry (wrong thread, already delivered) does nothing. Never inline, never twice, no lock held while `k` runs. The registry holds the continuation only until delivery (a hop whose job is never run leaks one boxed closure for the life of the thread; acceptable, documented).
3. **`load_settings_and_language`** (the worker body): see the stub doc; the mark names are exactly `settingsFileLoaded` and `languageLoaded`; `after_file_loaded` runs between them and must not block; a poisoned localization mutex is recovered; the guard is dropped before `mark("languageLoaded")`. `store.load(None)` returning `Err` ends the function with `Err(Settings(e))` (the C# `Load()` threw; the only handler registered at that point is the infallible log switch). **`apply_loaded_settings`**: `localization.apply(Some(&settings.ui_language), localizer.clone())` (the service logs the catalog warnings and publishes the localizer and culture), then `mark("settingsLoaded")`. **`logging_enabled`**: `settings.logging_enabled || diag.force_log`. **`startup_log_lines`**: `format!("Startup (shell) args={}", args.join(" | "))` (the RAW arguments, not `launch.arguments`) and `Some(format!("DIAG MODE: {}", diag.describe()))` iff `diag.any_enabled()`. **`repair_notice`**: `repairs = store.last_load_repairs()`; empty -> `None`; else `Some(build_repair_text(&repairs, false, texts))` (reset names joined by `", "` into one line, one line per `Shortcuts.<Name>` entry; already golden-tested in W2-02).
4. **`LocalizerSettingsTexts`**: each member `localizer.format(KEY, &[LocArg::new(name, value)])` with the keys listed in the stub; a missing key returns the key itself (the localizer's own fallback). `action_default_name(n)` passes `n` as the argument `n`.
5. **`build_startup_context`**: `ShellStartupContext { arguments: launch.arguments.clone(), initial_path: launch.initial_path().map(str::to_owned), launch_folder: launch.launch_folder.clone(), settings: StartupTask::spawn("PhotoReview.StartupContextSettings", move || (*settings).clone()), placement: placement.unwrap_or(PrefetchHandle { handle: None }), process_start }` (D-W8B6-22).
6. **Instance negotiation** (`instance.rs`): `try_take_lock(gate, folder)` = `gate.try_acquire(folder)` (no side effects besides the lock). `handoff_decision(forwarded, mode)`: `true` -> `ExitSilently`; `false` -> `PerFolder` -> `ExitWithMessage(FolderAlreadyOpen)`, any other mode -> `ExitWithMessage(AppAlreadyRunningNoResponse)`. Texts: keys `folder.alreadyOpenInOtherInstance`, `app.alreadyRunningNoResponse`, title `app.title` from the localizer the caller passes (`Localizer::current()` after `apply_loaded_settings`).
7. **`create_scope` / `ScopeGate`** (`pr_shell`): see the stub docs. `forward_to_owner` BLOCKS (up to `handoff::DEFAULT_TIMEOUT` = 1.5 s plus the connect): it runs on a worker only. `try_forward` logs `Forward to running instance: {outcome} ({n} path(s))` itself.
8. **Early decode** (`early_decode.rs`): `prepare_early_decode` returns `None` when `predict_decode_box` does; it runs on a worker (it may be slow: Win32 monitor calls). `start_early_decode` runs on a worker AFTER the lock; it sets `startup_prediction` BEFORE it starts the prewarm so the window's `earlyDecodeBoxMatched` mark sees it. A `None` plan does nothing (no mark, no prediction).
9. **`Win32MonitorProbe`**: the bodies follow the stub docs; `DPI_AWARENESS_*` constants are in `pr_app::services::initial_viewport`. `work_areas()` re-uses `Win32MonitorLayout` (`host::main_window::windowing`) rather than duplicating the enumeration. No `unsafe`.
10. **`start_phase_one` / `on_settings_loaded`**: the numbered steps in the stub docs are the spec, in that order. Additional rules: (a) `done` is called EXACTLY once on every path, always on the UI thread. A failure in steps 1-6 of `start_phase_one` calls `done(Err)` synchronously, before `start_phase_one` returns (the caller must hold no `RefCell` borrow while it calls); everything after the settings worker is asynchronous (a hop); (b) every step runs under `catch_step`; (c) a failure after the instance scope was created leaves the scope in the state (the shutdown releases the mutex); (d) `done(Ok(SecondInstanceExit))` is called after the hand-off ended: AFTER the box was shown and closed (modal) when the request was not answered (`ExitWithMessage`), at once (no box) when it was handed over (`ExitSilently`); in both cases the caller quits with 0 and the early decode never started; (e) a `--smoke` run never calls `create_scope`.
11. **Thread model** (R0003): workers: `PhotoReview.SettingsLoad`, `PhotoReview.EarlyDecodePlan`, `PhotoReview.Handoff` (named threads, one each); each closure owns only `Send` data (`Arc` of the store, the localization mutex, the previews, the mark, the log, the sender). The UI thread owns the state. Nothing blocks the UI thread except the modal message box.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (no hang): the settings worker panics or its thread cannot start -> the sender drops -> `Err(HopLost)` -> `StartupError::Worker` -> `done(Err)`. Test: a builder whose `load` panics (a store over a file system that panics) ends in one `done(Err(Worker or Settings))`.
- T2 (exactly-once `done`): `done` is a `FnOnce` moved through the chain; no path may drop it silently (tests assert a counter == 1 for: success, second instance forwarded, second instance unanswered, graph failure, settings failure, handoff failure, smoke).
- T3 (order): marks in this order for a normal start: `servicesBuilt`, `settingsFileLoaded`, `languageLoaded`, `settingsLoaded`, `instanceLock` (C# `ShellStartupTests` order test); `earlyDecodeStarted` only after `instanceLock`.
- T4 (lock hygiene): the early decode never starts for a refused second launch; the scope is created AFTER the settings (the mode comes from them, Q-R18) and BEFORE any other lock.
- T5 (Rc and Send): the state is `!Send`; closures given to workers never capture `Rc`/`RefCell`; the hop continuations (UI side only) capture a `Weak<StartupState>`, not an `Rc`: a hop whose job never runs (dispatcher shut down, worker lost) must not keep the state, the dispatcher and the services alive after `run` returns. `InstanceGate: Send + Sync` (the hand-off worker owns an `Arc` of the gate).
- T6 (env): the tests never mutate the real process environment: `EnvSource` fakes; the golden test maps names, it does not set variables. `ProcessEnv` is exercised by ONE test that only reads an unset, unique variable.
- T7 (named kernel objects): tests that create an `InstanceScope` use a unique prefix per test (`PhotoReviewRsTest` + a GUID without braces) and dispose the scope in a guard.
- T8 (user data): no test touches the real data root; `StartupGraph.config_file` and the placement file point into a `TempRoot`.
- T9 (surrogate-free text): the localized messages are passed through unchanged; no `format!` width on them.
- T10 (UI strings): all box texts come from `Localizer` keys; the only literals are log messages and thread names.

## Safety rules (`// SAFETY:` per `unsafe` block)
`monitor_probe.rs` has none (safe wrappers only). `local_time.rs`: the one call to `GetLocalTime` (or its safe `windows` form): "writes a `SYSTEMTIME` into a live local; no pointer is kept". `pr-app` and `pr-shell` files: no `unsafe`.

## Error mapping
| C# | Rust |
|---|---|
| exception in `StartupCoreAsync` (any) | `Err(StartupError)` or a panic caught by `catch_step` -> `done(Err)` -> 17e `fail_startup` |
| `await settingsLoad` faulted | `StartupLoadError::{Settings, Worker}` -> `StartupError::{Settings, Worker}` |
| `InstanceScope` constructor / `TryAcquire` / `CreateClient` throwing | `InstanceStartError` -> `StartupError::Instance` |
| `TryForwardAsync` returns false | `HandoffDecision::ExitWithMessage(kind)` |
| `TryForwardAsync` throws `OperationCanceledException` | impossible (`CancelToken::none()`); `Err(Canceled)` maps to `Ok(false)` |
| `PrepareEarlyDecodeAsync` exception (not OOM) | `catch_unwind` in `prepare_early_decode`: logged, `None` |
| `EntryPointNotFound` / `DllNotFound` / `ArgumentOutOfRange` of the predictor | already `None` in `predict_decode_box` (R-IV-9) |
| `ShellErrorLog.Configure` | `error_log::configure` (never fails) |
| `DiagOptions.*` | `diag_options()` snapshot (the env names are `PHOTOREVIEW_RS_DIAG_*`, P-16) |

## Open questions (recommended default in bold)
1. **`ShellStartupContext.placement` after the early decode took the single-use handle** (D-W8B6-22): **an empty `PrefetchHandle` (`handle: None`) built inside `pr_app`**. Alternative: amend `context.rs` (17a) so `placement` is `Option<WindowPlacementData>`; nothing reads the field, so the cheap form is taken.
2. **Local time**: **new `local_time.rs` for the perf CSV file name only**; the general log keeps `SystemLocalTime` (UTC) and gets a `Different` row (D-W8B6-38). Alternative: pass UTC parts and accept a wrong file name.
3. **The 09b seam** (D-W8B6-24): **`StartupGraph` struct + `GraphBuilder` closure**; `production_graph_builder` stays `todo!("W8-09b")` until 09b is ported. Alternative: a trait over the registry (rejected: 09b names unknown).
4. **Settings worker as a hop, not a blocking `join`** (D-W8B6-21): **hop** (R0003: nothing waits on the UI thread; the message box of a second instance needs the loop running). Alternative: `StartupTask::join` on the UI thread: simpler, deviates from R0003, and freezes the loop for the duration of the load.
5. **Env names** (D-W8B6-26): **`PHOTOREVIEW_RS_INSTANCE_PREFIX`, `PHOTOREVIEW_RS_WARP`, `PHOTOREVIEW_RS_NOWARM`**. The harness of the C# integration tests sets the C# names; the Rust harness sets the Rust ones.
6. **`production_graph_builder` panics until 09b**: **yes** (the binary is not usable before 09b anyway; the tests use a fake builder). Alternative: return `Err("service graph not wired")` so `main` shows the failure box instead of crashing: **preferred if the porter prefers a safe stub**, but then the `todo!` count in this unit is not zero; the lead decides.
7. **The `DIAG MODE` line** is written with `AppLog::write_forced` even when logging is off (C# `WriteForced`): **kept**.
