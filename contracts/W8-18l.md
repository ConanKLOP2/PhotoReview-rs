## Semantics (C# is the spec)
1. **`kind_for_style`**: exactly the doc of the stub (the C# `switch` with the type mask). `BS_TYPEMASK` values 0 and 1 are push buttons; 2, 3, 5, 6 are check boxes (`BS_CHECKBOX`, `BS_AUTOCHECKBOX`, `BS_3STATE`, `BS_AUTO3STATE`) or push buttons when `BS_PUSHLIKE`; 4 and 9 radio; 7 group; everything else (8 `BS_USERBUTTON`, 10, 11 `BS_OWNERDRAW`, 12..15 split button and command link) `None`; `BS_ICON | BS_BITMAP` first. The constants come from `win32::dialog_chrome` (`BS_*`, `CBS_*`, `PBS_MARQUEE`, `TBS_VERT`, `SS_*`).
2. **Predicates**: `is_full_paint` = kinds 1..=8; `has_flat_border` = 9..=11 or `Progress`; `tracks_hover` = PushButton, CheckBox, RadioButton, ComboBox, Trackbar; `HeaderFiller` and `None` are in none of them. `repaints_after_system_paint`: the lists in the stub doc, any other kind `false`.
3. **`control_message_action`** (the table is the C# `switch`, first match wins; "full" = `is_full_paint`, "hover" = `tracks_hover`, "flat" = `has_flat_border`):

| message | condition | action |
|---|---|---|
| `WM_ERASEBKGND` 0x14 | full | `EraseBackgroundHandled` |
| `WM_PAINT` 0x0F | full | `PaintWindow` |
| `WM_PRINTCLIENT` 0x318 | full | `PrintClient` |
| `WM_MOUSEMOVE` 0x200 | hover | `TrackHover` |
| `WM_MOUSELEAVE` 0x2A3 | hover | `LeaveHover` |
| `WM_NCPAINT` 0x85 | flat | `PaintNonClientBorder` |
| `WM_PRINT` 0x317 | flat and `(lparam as u32) & 2 != 0` | `PrintNonClientBorder` |
| `WM_PAINT` | kind `HeaderFiller` | `PaintHeaderFiller` |
| `WM_PRINTCLIENT` | kind `HeaderFiller` | `PrintHeaderFiller` |
| `WM_UPDATEUISTATE` 0x128 | full | `InvalidateAfterDefault` |
| any | `repaints_after_system_paint(kind, message)` | `RepaintAfterDefault` |
| `WM_NCDESTROY` 0x82 | any | `Destroy` |
| else | | `PassThrough` |

   Consequences to test: a `Progress` handles both `WM_PAINT` (full) and `WM_NCPAINT` (flat); `WM_PRINT` without `PRF_NONCLIENT` is `PassThrough`; a `ComboBox` gets `RepaintAfterDefault` for `WM_SETFOCUS` and `CB_SETCURSEL` but `PassThrough` for `WM_PAINT`'s neighbours such as `WM_NCHITTEST`; `HeaderFiller` ignores `WM_ERASEBKGND`.
4. **`attach(hwnd, kind)`** and **`attach_dialog(dialog)`**: the stub docs (they are the C# line by line). `attach` boxes the `PaintState`, passes `Box::into_raw` as `ref_data` and as the property value; `Destroy` (the `WM_NCDESTROY` arm of `control_proc`) is the only place that frees it (`Box::from_raw`), after `remove_window_subclass` and `remove_prop`.
5. **`control_proc` / `dialog_proc`**: the algorithm in the stub docs. The whole body runs in `pending_panic::guarded` with a "no result" marker; when a panic was captured the message STILL goes to `def_subclass_proc` and its result is returned (C# `catch (Exception) {}` then `DefSubclassProc`, D-W8B5-410). `dialog_proc` reads the `NMHDR` of `WM_NOTIFY` only when `lparam != 0` (typed `NMHDR` read under a SAFETY comment, D-W8B5-311); the notification is corrected only when `nmhdr.code == NM_CUSTOMDRAW (-12)` AND `is_list_view(nmhdr.hwndFrom)` (C# line 302: `*(int*)(lParam + 16) == NmCustomDraw && IsListView(*(nint*)lParam)`, the order matters: the cheap code test first), then `r = def_subclass_proc(..)` and the answer is `controls::adjust_list_view_custom_draw(&mut *(lparam as *mut NMLVCUSTOMDRAW), r)`. Any other `WM_NOTIFY` (other code, other control class, null `lparam`) goes straight to `def_subclass_proc`.
6. **`adjust_custom_draw`**: the stub doc; the drawing-side wrapper is 18m's. `CDRF_NOTIFYITEMDRAW` 32, `CDRF_SKIPDEFAULT` 4, `CDRF_NEWFONT` 2, `CDDS_PREPAINT` 1, `CDDS_ITEM` 0x10000, `CDIS_SELECTED` 1 come from `control_constants`.
7. **Colours**: `color(key)` = `DialogColors::from_key(key).unwrap_or(MISSING_COLOR)` (the C# throws; see D-W8B5-405). The 17 `keys::*` are every key the C# painter names.
8. **`production_painter()`**: `Rc::new(NativeDialogChromePainter)` as `Rc<dyn ChromePainter>`. `default_chrome()` of W8-18h builds `DarkDialogChrome::new(production_painter())` (D-W8B5-410: 18n's porter changes that line, see 18n).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (leaks): the `PaintState` is freed exactly once, at `WM_NCDESTROY`; a failed `set_window_subclass` frees it at once; no GDI object is created in this unit. The heap box is invisible to `GetGuiResources`, so the stub carries a test hook: `PaintState::new(kind)` counts up and `Drop for PaintState` counts down a process-wide `AtomicUsize`, read by `pub fn live_state_count() -> usize` (`#[doc(hidden)]`); the leak test compares it before and after 50 attach / destroy cycles (D-W8B5-419). `PaintState` is `#[non_exhaustive]` so only `new` builds one (a literal elsewhere would unbalance the counter).
- T2 (re-entrancy): `hot` is a `Cell`; no `RefCell` anywhere; the drawing code of 18m sends messages to the same control (`BM_GETSTATE`), which re-enters `control_proc` with the same `&PaintState`.
- T3 (use after free): after `Destroy` frees the state nothing may read `state` (take `kind` into a local BEFORE the match, as the C# `var kind = state->Kind`).
- T4 (panic): see rule 5; the procedures are `extern "system"` and must never unwind (D-W8B3H-4, D-W8B5-207).
- T5 (integer widths): `lparam as u32` for `PRF_NONCLIENT`; `wparam as Hdc` is a reinterpret (`usize` to `isize`); the message plan receives the `lparam` as `isize`.
- T6 (the stub bodies of 18m/18n): in 18l's native tests the windows are never shown and no message loop is pumped, so `WM_PAINT` / `WM_NCPAINT` never reach `todo!()`; `attach`'s `invalidate_rect` only marks the region. Do not call `UpdateWindow`, `RedrawWindow` or `PrintWindow` in 18l.
- T7: no `unwrap` / `expect` / `panic` outside `#[cfg(test)]`; `from_value` returns `None`, `color` returns the magenta.

## Safety rules (`// SAFETY:` per `unsafe` block)
`control_proc` / `dialog_proc` (`state` from `ref_data`: "the address of the `PaintState` boxed by `attach` for this subclass, alive until `WM_NCDESTROY` frees it; read only while the message is processed"), the `Box::from_raw` at `Destroy` ("the box was leaked by `attach` for this window and is freed once here"), the `NMHDR` read of `WM_NOTIFY` ("`lparam` points to a notification structure for the duration of the message"), the `NMLVCUSTOMDRAW` cast ("a list view sends `NM_CUSTOMDRAW` with an `NMLVCUSTOMDRAW`; `is_list_view(hwndFrom)` was checked"), `set_window_subclass` ("`control_proc` stays valid for the process; `ref_data` is the box"). The `dialog_chrome` / `comctl` wrappers used are safe functions.

| C# | Rust |
|---|---|
| `catch (Exception)` in both procedures | `pending_panic::guarded`, the message still goes to `def_subclass_proc`, the panic is resumed by the owner of the native call |
| `DialogColors.FromKey` throws `KeyNotFoundException` | `MISSING_COLOR` |
| `SetWindowSubclass` fails | `attach` frees the state and answers `false` |
| `(ChromePaintKind)state->Kind` | `PaintState::kind` is the enum (no cast) |
