## Semantics notes
Each C# member is named in its doc comment. The rules below fix the points where a literal port would go wrong.

### Texts and the localizer
1. **Every text comes from the `Localizer` argument** (D-W8-4). No English literal is written in the module, except the trophy symbol
   (`BEST_SYMBOL`, a language-neutral marker, as in C#) and `""`. The window calls `Localizer::current()` and passes it in; the module
   never reads the ambient instance. This is what lets the tests run English and Vietnamese side by side (D-10h-3).
2. **Lookup rule** (C# `Lookup`): `localizer.contains(key)` then `localizer.get(key)`; otherwise the fallback (`profile.name` or
   `profile.description`). Use `get` for the plain keys and `format` only where the key has a `{placeholder}`. Do not use the `format` path
   for a key without arguments.
3. **Placeholder keys**: `unit.milliseconds` takes `value`, `bench.error.notImplemented` takes `profileName`, `bench.error.profileSettings`
   takes `profileId`, `bench.error.unexpected` and `bench.result.failedDetail` take `message`, `benchmark.status.progress` is NOT used here.
   Argument names are exactly these, case-sensitive.

### Profile keys and profile texts
4. **`profile_key(id, field)`** (trap T1): `PROFILE_KEY_PREFIX` + the id with each `-` removed and the character after each `-` uppercased,
   then `.` + `field`. Only a `-` turns the next char upper; the flag is cleared after one char. Examples: `fast-sequential`/`name` gives
   `benchmark.profile.fastSequential.name`; `-a` gives `benchmark.profile.A.name`; `a--b` gives `aB`; `a-` gives `benchmark.profile.a.name`
   (the trailing dash has no char after it); `""` gives `benchmark.profile..name`.
   Case mapping (trap T2): iterate `char`s, map with `c.to_uppercase()` only when that yields exactly ONE char, otherwise keep `c`.
   This matches .NET `char.ToUpperInvariant`: `ß` stays `ß` (its Rust full mapping is `SS`), `ÿ` gives `Ÿ`, `é` gives `É`. Non-BMP chars are
   never changed (a surrogate pair is copied as-is and the flag is cleared after it, as the golden `key-astral-after-dash` shows).
   Do NOT use `to_ascii_uppercase` (it leaves `é` unchanged) and do NOT lowercase or trim. The golden decides the dotless `ı`
   (`key-dotless-i`) and the long `ſ` (`key-long-s`): if the golden disagrees with `char::to_uppercase`, stop and report (open question 1).
5. **`profile_name` / `profile_description`**: the catalog text of `profile_key(id, "name" | "description")` when the key exists, else
   `profile.name` / `profile.description`. The key is case-sensitive: `FAST-SEQUENTIAL` has no key and falls back (golden
   `texts-fallback-upper-case-id`).
6. **`BenchmarkProfileItem`** is the same two lookups with `profile.id`. It has no state besides `profile` and no change notification (D-10h-2).

### Messages and enum texts
7. **`progress_message`**: exact, case-sensitive match of `PROGRESS_OK` and `PROGRESS_CORRECTNESS_FAILED` (golden
   `progress-lower-case-passes-through`); any other string, including `""`, passes through unchanged.
8. **`loading_mode_text`**: `Fast` gives `enum.loadingMode.fast`, `Preview` gives `enum.loadingMode.preview`, `Original` gives
   `enum.loadingMode.original`. Write all three arms explicitly (no `_`, no `Debug` fallback; D-10h-4).
9. **`workload_text`**: `FirstFrame` gives `enum.benchmarkWorkload.firstFrame`, `Sequential` gives `...sequential`, `Random` gives `...random`,
   `WarmNext` gives `...warmNext`, `Preload` gives `...preload`, `FileAction` gives `...fileAction`, `Correctness` gives `...correctness`.
   All seven arms explicit.

### Errors
10. **`describe_error(error, localizer)`** (C# `Describe`), arms in THIS order:
    a. `Profile(e)` with `e.problem == NotImplemented`: `bench.error.notImplemented` with `profileName` = `profile_name(p, l)` when
       `pr_bench::profiles::find(&e.profile_id)` finds `p`, else `e.profile_id` as given (no trim, no case folding: `CACHE-RECOVERY` is
       not found).
    b. `Profile(e)` with `e.problem == MissingIdOrMode`: `bench.error.profileIncomplete` (no arguments).
    c. any other `Profile(e)` (`InvalidSettings`): `bench.error.profileSettings` with `profileId` = `e.profile_id`.
    d. `Other(message)`: `bench.error.unexpected` with `message` as given (an empty message stays empty: `Unexpected error: `).
    The English message of the error (`e.message`) is NEVER shown when a translation exists (the golden `describe-not-implemented-*` cases
    check that the catalog text wins).

### Rows
11. **`BenchmarkResultRow::new`** stores the three arguments; `is_best` is `false`. No validation: the row shows whatever it gets.
12. **`best_marker`**: `BEST_SYMBOL` when `is_best`, otherwise `""`. Not the workload or the status.
13. **`count`** = `phase.count()` (the sample count, `i32`).
14. **`milliseconds_text(value, count, l)`** (C# `MillisecondsText`; the row passes `count = phase.count()` and `value` = `p50()`, `p95()`, `p99()` or
    `max()`): when `count == 0` return `bench.noValue` (the value is ignored, `—` in the catalog); otherwise `unit.milliseconds` with
    `value` = `format_milliseconds_f0(value)`. The row methods call it with the phase's own statistic.
15. **`format_milliseconds_f0(value)`** (trap T4, the C# `value.ToString("F0", CurrentCulture)` under invariant culture): NaN gives `NaN`,
    `+inf` gives `Infinity`, `-inf` gives `-Infinity`; every other value gives `format!("{value:.0}")`. The Rust rounding (ties to even on the
    exact binary value, `-0.4` gives `-0`) matches the .NET 10 behaviour recorded in `pr_bench::engine::format_ms`. Do not add a
    grouping separator, a `+` sign or a `%`. Do NOT call `format_ms` (it prints one decimal).
16. **`status_text`** (C# `StatusText`, trap T6): `match status`:
    - `Pass` gives `enum.benchmarkResultStatus.pass`; `Warn` gives `...warn`. The message is ignored.
    - `Fail`: FIRST look at `phase.message`:
      - `None` gives `enum.benchmarkResultStatus.fail` (plain Fail). The `error` is NOT looked at, even when it is `Some`
        (golden `row-fail-no-message-with-error-shows-plain-fail`);
      - `Some(m)` with `m == RESULT_CORRECTNESS_FAILED` (exact) gives `benchmark.result.correctnessFailed` (the error is not looked at);
      - `Some(m)` otherwise gives `bench.result.failedDetail` with `message` = `describe_error(err, l)` when `error` is `Some(err)`, else `m`.
    - any other status (`InsufficientData`) gives `enum.benchmarkResultStatus.insufficientData`.
    `Fail` with `error = Other("io")` and message `Decoder crashed` gives `Failed: Unexpected error: io` (golden
    `row-fail-message-other-error-uses-describe`).
17. **`cell_texts`** (C# `CellTexts`): exactly ten strings in this order: `best_marker()`, `profile_name`, `loading_mode_text`,
    `workload_text`, `count().to_string()` (plain integer, no grouping), `p50_text`, `p95_text`, `p99_text`, `max_text`, `status_text`.
    The count cell does NOT go through `milliseconds_text`.
18. **Statistics**: the row takes the percentiles from `BenchmarkPhaseResult::p50/p95/p99/max` (already golden-verified in W7). Do not
    re-sort the samples in this module.

## Traps (for the porter; each one is covered by a golden case or an F test)
- T1 `profile_key`: dash handling (`-a`, `a--b`, trailing `-`), empty id. Golden `key-*`.
- T2 case mapping: one-char rule for `to_uppercase`; `ß`, `ÿ`, `é`, `ı`, `ſ`, astral. Golden `key-*`.
- T3 lookups are case-sensitive; `contains` before `get`; fallback uses the library English text. Golden `texts-*`.
- T4 `format_milliseconds_f0`: non-finite spellings are invariant (`Infinity`, not `∞`); `-0` for `-0.4`; ties via `{:.0}`. Golden `ms-*`.
- T5 the count cell is a plain integer; the `—` appears only in the four time cells and only when `count == 0`. Golden `row-no-samples`.
- T6 `StatusText` order: Fail with no message ignores the error; correctness message wins over the error; otherwise `describe` replaces the
  message only when an error exists. Golden `row-fail-*`.
- T7 `describe` arm order: NotImplemented first, then MissingIdOrMode, then other profile errors, then Other. Golden `describe-*`.
- T8 a NaN/Infinity sample changes the percentiles; the text goes through T4. Golden `row-nan-sample`, `row-infinite-sample`.
- T9 `RowError::Other` keeps the English technical message; the translated wrapper is added by `describe_error`, never by the caller.

## Decisions (contract-level, recorded so the porter does not revisit them)
- D-10h-1 `RowError` replaces C# `Exception? Error`. `Profile` keeps the whole `BenchmarkProfileError` (problem, profile id, English message); `Other`
  keeps the message text. An `ArgumentNullException` and a `null` error have no Rust form.
- D-10h-2 The C# `INotifyPropertyChanged` of `BenchmarkProfileItem` and `NotifyTextsChanged` are not ported. Views re-read the texts after a
  language change. The presenter reports that through the `ChangeSet` of the view model (D-W8-1, units 08a and W8-10i).
- D-10h-3 The localizer is a parameter (not an ambient global) so the same function can be checked in two languages in one test process.
- D-10h-4 The C# fall-back arms `_ => mode.ToString()` and `_ => workload.ToString()` and their tests (`(LoadingMode)99`, `(BenchmarkWorkload)99`)
  have no Rust counterpart: the enums are closed. Their tests are N/A, not ported.
- D-10h-5 `pr_app` depends on `pr_bench`, and `pr_bench` depends on `pr_platform_win`. This module uses only `pr_bench::{models, engine, profiles}`
  and never names `pr_platform_win` or `windows` (AGENTS.md layering for the pure module).

## Open questions (each has a recommended default; the stub already follows the default)
1. **Case mapping of `ı` (U+0131), `ſ` (U+017F) and `ÿ` (U+00FF) under .NET invariant.** The default is the one-char rule with
   `char::to_uppercase` (`ı` gives `I`, `ſ` gives `S`). If the golden says .NET keeps `ı`, the porter adds a two-entry exception table, which
   is still a pure function. Do not change the rule without the golden.
2. **`row-nan-sample` and `row-infinite-sample`** depend on the W7 percentile of non-finite samples (`BenchmarkStatistics.Percentile`,
   `pr_core::diagnostics::bench_stats`). If the golden fails only on these two cases, report the percentile, not this module.
3. **`RowError` versus passing `BenchmarkError`.** The default is the new two-variant `RowError` (D-10h-1), because `BenchmarkError` covers
   engine failures that the row never shows. The alternative (pass `&BenchmarkError`) changes the signatures of `describe_error` and
   `BenchmarkResultRow::new`; decide before the porter starts, not during the port.
4. **Vietnamese strings in the golden.** The golden is English only (the oracle never switches the ambient Localizer). The Vietnamese assertions
   are F tests (`describe_maps_library_problems_to_catalog_text_in_both_languages`, `profile_texts_follow_the_current_language`) and use
   `vi.json` directly. The lead does not need to regenerate the golden for a catalog change.
