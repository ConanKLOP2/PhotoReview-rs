## Required behavior

- SingleWindow mode keeps one app-wide lock; every folder open proceeds. PerFolder mode claims the target lock before
  switching, retains the previously shown lock while the new open is pending, and forwards to an existing owner. If
  forwarding fails, make one final claim attempt to handle an owner moving away/exiting during the handoff.
- Compose the mutex name from W6-03a and its paired pipe name from W6-03b before claiming ownership or forwarding; the
  resulting pair must match the C# `InstanceKeys.For` contract.
- Track claims by mutex name and pending opens by reference count. `after_open` completes exactly one pending claim;
  shown-folder changes release only claims that are neither current nor pending.
- When a folder being reopened is still in this process's asynchronous release set, wait for those releases and retry
  claiming instead of mistaking the process's own mutex for another instance.
- Release on a background worker because disposing a server joins its accept loop. Stop the server before closing the
  mutex handle so a new owner cannot race the old listener. Dispose each claim independently; one cleanup failure must
  not prevent releasing remaining claims, and failures are logged.
- `StopListening` disposes listeners but retains mutex claims. After disposal, `BeforeOpen` follows C# shutdown behavior
  (proceed) and holds no new locks. Blank prefix and null callback are caller errors.
- Empty or whitespace folder input returns the explicit `FolderOwnershipError::InvalidFolder`, mirroring C#'s argument guard rather than treating it as a remote-owned folder.
- When another instance owns a folder and the forwarded path is invalid (including embedded NUL), return the ordinary
  `OwnedByOtherInstance` outcome without throwing. Do not forward relative, malformed, or invented paths.

## Concurrency, process safety, and tests

- This state machine coordinates independent processes through named mutexes and pipes and multiple in-process folder
  requests through `_gate`, pending counts, and release tasks. Keep all claim/pending transitions under one lock; never
  block synchronously on server disposal while holding that lock. Preserve the UI-thread nonblocking release behavior.
- Integration tests that create mutexes/pipes must use unique prefixes and bounded waits. Fakes should cover client
  outcomes, pending release hooks, and disposal failures. Native tests are ignored with a `native` reason and clean up
  their own named objects; no Recycle Bin or user-file operations are involved.
- Tests must use event/task synchronization, not fixed-delay assertions or sleep polling. Every potentially blocked
  wait has a finite timeout (the C# tests use bounded helpers and explicit wait bounds).
- Mutation expectations: per-mode key selection; claims retained through pending opens; pending reference decrement;
  release exclusion for shown/pending folders; one retry after owner silence; self-release wait; stop-listening vs lock
  retention; server-before-mutex teardown; cleanup continuation after a claim disposal failure; shutdown path behavior.
- Gates: `cargo fmt --all --check`; `cargo clippy -p pr-platform-win --all-targets -- -D warnings`;
  deterministic/fake tests by default and native tests ignored with reason; final integration uses the full workspace gates.
