- Semantics notes:
  1. **Ownership instead of `IDisposable`.** One owner, freed on `Drop`; shared read-only as `Arc<PixelBuffer>` (W4-01b `PlatformImage::Pixels`,
     `PixelLease::Owned`). `dispose(&mut self)` exists for parity with the C# observable state: after it `is_disposed()` is true, `address`,
     `get_row*`, `bytes*`, `try_get_span*` return `Err(Disposed)`, `width/height/stride/layout/byte_count/id` stay readable, a second `dispose` is a
     no-op, and `Drop` after `dispose` frees nothing twice (the `Option<NativePixelMemory>` makes this structural). Mutable access needs `&mut`:
     the C# "writable `Span<byte>` from a shared reference" is `get_row_mut` / `bytes_mut`. No interior mutability, no `unsafe` here.
  2. **`allocate`.** `width < 1` => `WidthOutOfRange`, `height < 1` => `HeightOutOfRange`, `width > i32::MAX / 4` (= 536 870 911) =>
     `WidthOutOfRange`, all BEFORE allocating; then `NativePixelMemory::allocate(width as i64 * 4 * height as i64)` (an `Err(OutOfMemory)` maps to
     `PixelBufferError::OutOfMemory { byte_count }`). `stride = width * 4` (`i32`), `byte_count = stride as i64 * height as i64` (use `i64`
     arithmetic, never `i32 * i32`). `id` = `LAST_ID.fetch_add(1, Ordering::Relaxed) + 1`: first buffer of the process gets 1, strictly
     increasing, unique across threads. Memory is NOT zeroed (decoders overwrite it all); a test must not assert contents of a fresh buffer.
  3. **Rows and spans.** `get_row(y)`: disposed check FIRST, then `0 <= y < height` (`RowOutOfRange { y, height }`, also `i32::MIN/MAX`), then the
     `stride`-byte slice at `y as usize * stride as usize` (use `usize`/`i64` arithmetic; `y * stride` overflows `i32` above 2 GiB).
     `try_get_span`: disposed check first; `Ok(None)` when `byte_count > i32::MAX as i64` (strictly greater: 2 147 483 647 bytes still `Some`,
     `65536 x 8192 x 4 = 2^31` is `None`), else `Ok(Some(&bytes[..byte_count]))`. `bytes()` has no size limit.
  4. **`apply_orientation` entry.** Order: (a) `src.is_disposed()` => `Err { error: Disposed, source: src }` (also for orientation 1: C# throws before
     looking at the value); (b) orientation `< 2 || > 8` => `Ok(src)` with the same `id`, no copy, no allocation; (c) allocate the destination
     (`height x width` when `orientation >= 5`, else `width x height`; same layout); allocation failure => `Err { error, source: src }` with `src`
     untouched and NOT freed; (d) copy; (e) drop `src` (frees it) and return the destination. The destination `id` is new.
  5. **Orientations 2..=4 (`copy_rows`).** 2 mirror horizontally, 3 rotate 180, 4 mirror vertically. Destination row `y` = source row `y` (2) or
     `height-1-y` (3, 4); for 2 and 3 the row is then reversed **per 4-byte pixel** (C# reverses `Span<uint>`). Reversing the bytes would swap
     the B and R channels: golden `orient-*-o2/o3` and `MovesKnownPixel` catch it.
  6. **Orientations 5..=8 (`copy_transposed`).** Source `W x H`, destination `H x W`; destination `(x, y)` (`x < H`, `y < W`) takes the source
     pixel index `origin + x * step_x + y * step_y` with `w = W as i64`, `h = H as i64`:
     5 `(0, w, 1)`; 6 `((h-1)*w, -w, 1)`; 7 `((h-1)*w + w-1, -w, -1)`; 8 `(w-1, w, -1)`; as `(origin, step_x, step_y)`.
     Equivalent closed forms: 5 `src(y, x)`, 6 `src(y, H-1-x)`, 7 `src(W-1-y, H-1-x)`, 8 `src(W-1-y, x)` as `(x_src, y_src)`; the W4-02a
     `map_pixel` table is the cross-check. Iterate in 32x32 destination tiles (`TRANSPOSE_TILE`) for cache locality; order does not change the
     result. Use `i64` for the index (a 20 000 x 20 000 image has 4e8 pixels, `(h-1)*w` needs more than 32 bits only above 46 340 x 46 340, but
     negative steps must not wrap an unsigned type). Copy whole 4-byte pixels (`copy_from_slice`/`u32::from_ne_bytes`, never channel by channel).
     The loop is safe code over `bytes()` / `bytes_mut()`; bounds checks are acceptable (the perf gate is W4-14, measure before reaching for `unsafe`).
  7. **No half-written results.** The destination is fully written before `src` is dropped; there is no early return between (d) and (e).
  8. **`is_fully_opaque`.** Order: disposed check, then `layout != Pbgra32` => `true` (also a `Bgr32` buffer with arbitrary 4th bytes), then per row
     `row[3], row[7], ...` all `== 255`. Return `false` at the first pixel with `A < 255`; premultiplied colour bytes are not examined (golden
     `alpha-colour-bytes-*`). Row widths that are not a multiple of any SIMD width (1, 9, 17, 21) must work: the C# vector loop plus tail is an
     optimisation; a plain `chunks_exact(4)` loop (or a `u32`-mask loop) is the contract. Do not assume the buffer start is aligned beyond `u8`.
  9. **`has_alpha`.** `layout == Pbgra32 && !is_fully_opaque`. Note the C# doc: it means "has a real non-opaque pixel", not "the format can
     carry alpha". Disposed check first (a disposed `Bgr32` buffer is `Err`, not `Ok(false)`).
- Traps checklist: §7 items 3 (`i64` for `byte_count` and pixel indexes, `i32` stride, never overflow), 6 (per-pixel, not per-byte, mirroring;
  channel order B,G,R,X|A is memory order, not "RGBA"), 8 (a disposed source is an error even for the identity orientation), 10 (no ordering
  involved). INV-1: `id` must never repeat in a process; a result of `apply_orientation` must never reuse the source `id` (a stale GPU entry
  keyed by the old id would show the un-rotated pixels).

## Golden package
- `oracle/W4-16a.cs`: commands `pixel-buffer` and `pixel-ops` (dispatch lines in the file header). Public API only. Pattern: byte `i` of the buffer
  (row-major, no padding) is `(i * 131 + seed * 17 + i / 251) mod 256` in 64-bit arithmetic; digests are FNV-1a 64 (`h = 14695981039346656037`,
  `h = (h ^ b) * 1099511628211` wrapping, 16 lowercase hex digits), computed in the test with 5 lines, so no hashing crate is needed.
  Deterministic (D19): no clock, no path, no ids in the output (only `id_positive` / `id_changed`).
- `golden-inputs/pixel-buffer.json` (21 cases): 8 valid geometries (1x1 .. 1000x3, both layouts) each probing rows `-1, 0, h-1, h, i32::MIN,
  i32::MAX`, then span, then dispose; 9 invalid sizes (0, negative, `i32::MIN`, `i32::MAX/4 + 1`, `i32::MAX`); 4 unknown layouts
  (`-1, 2, 255, i32::MIN`). Result: `{throws}` (exception type name) or the geometry block plus `after_dispose` (every accessor throws
  `ObjectDisposedException`, geometry readable, second dispose ok).
- `golden-inputs/pixel-ops.json` (476 cases):
  * `orient` (364): 14 sizes (1x1, 1xN, Nx1, 2x3, 3x2, 31x33, 32x32, 33x31, 64x65, 70x45, 1x40, 40x1, 33x1, 1x33: odd and tile-crossing) x both
    layouts x orientations `0..9, -1, i32::MIN, i32::MAX`. Result: `same_instance`, `source_disposed`, `id_changed`, size, layout, stride,
    `byte_count`, `fnv1a64`, `hex` (images up to 16 pixels). Expected: `same_instance` true and `id_changed` false for orientations outside 2..8.
  * `compose` (20): `[6,8]` and `[6,6,6,6]` and `[5,5]` give `equals_original` true; `[6,6]` and `[3]` on the same seed have equal `fnv1a64`.
  * `alpha` (84): sizes 1x1, 17x3, 64x2, 3x9, 21x5, 8x1, 9x1 (vector width, tail, exact fit); opaque; one pixel with `a = 0` and `254` at the
    first, last, middle, top-right and bottom-left pixel; all zero; Bgr32 with the unused byte 0 and 255 (always opaque); colour bytes 0 and 255.
  * `disposed` (8): `orient-6`, `orient-1`, `is_fully_opaque`, `has_alpha` on a disposed 2x2 buffer of both layouts: `ObjectDisposedException`.
- How the Rust test maps a case: `layout` int => `PixelLayout::from_i32` (an `Err` there is the C# `ArgumentOutOfRangeException` of `allocate`);
  `rows` => `get_row(y)` result length or `dotnet_type_name()`; `orient` => `create_pattern` then `apply_orientation`, `same_instance` is
  `result.id() == src_id`, `source_disposed` is true exactly when the orientation is in 2..=8 (observed via `live_count`), `hex` is
  `bytes()` hex-encoded; `alpha` => build the pattern, overwrite byte 3 of every pixel with `alpha_fill`, bytes 0..2 with `colour_fill` when
  present, then the `alpha_set` pixels; `disposed` => `dispose()` then call, compare `dotnet_type_name()` of the `Err`.

## Open questions
- **`PixelBuffer` mutability.** Recommended (used by the stub): `&self` readers and `&mut self` writers (`get_row_mut`, `bytes_mut`), shared as
  `Arc<PixelBuffer>` once filled. Alternative: a `PixelBufferMut` builder type that freezes into `PixelBuffer`; cleaner types, but W4-01b/W4-01c
  would have to take the builder into account and `PixelLease::Owned` would need both. Lead decides before W4-16b/W4-01c are ported.
- **`dispose` on a type that frees on `Drop`.** Kept only for parity (`IsDisposed`, `ObjectDisposedException` tests, decoders that dispose a
  half-built buffer on a failure path). Alternative: drop `is_disposed` and the `Disposed` variant and make use-after-free unrepresentable;
  fewer branches in hot accessors but W4-01c's contract text mentions a disposed `PixelBuffer`. No behaviour impact on the happy path.
- **Where the pattern/assert helpers live.** `PixelAssert` (create_pattern, clone, equal with first-difference report) is also needed by W4-16b
  (`PixelBufferImageCodecTests`) and the Wave 5 parity tests. Recommended: write them locally in `tests/pixels.rs` now; the lead hoists them to
  `pr-test-support` (needs `pr-imaging` as a dev-dependency there, so a cycle check first) when the second user appears.
- **`address()` returning a raw pointer.** `pr-platform-win` upload code needs the first byte for D2D `CreateBitmap` / WIC `CopyPixels`. The raw
  pointer keeps `unsafe` where the FFI is. Alternative: `bytes()` only and let the FFI layer take `as_ptr()` of the slice; then `address` can go.
