## Semantics (C# is the spec; the doc comment of every stub function is part of it)
1. **Shape (D-W8B5-901).** `SettingsContent` is the C# `SettingsDialog` without its base class and implements `DialogContent`; `SettingsDialog` is `{ native: NativeDialog, content: Rc<SettingsContent> }` (precedent D-W8B5-301, D-W8B3H-18). The pages see the window through `SettingsPageContext` over `host::PageHost`, which holds a `Weak<SettingsContent>`; the content owns the pages: no `Rc` cycle. The content keeps the live `NativeDialog` in `link` from `initialize` to `close::on_closed` only (that one cycle is cut at close, 19m), so a `NativeDialog` dropped without ever being shown leaks nothing.
2. **`SettingsContent::new(args)`** in this order: `physical` seed (`ScratchSeed`) cloned from `args.presenter` BEFORE it moves; `presenter = Rc::new(RefCell::new(SettingsPresenter::new(&args.current, args.presenter)))`; `warnings = options.warnings` or `TaskDialogWarningSink::instance()`; `pages` = `options.pages` or `catalog::create_pages()`, each wrapped in `Rc<RefCell<Box<..>>>`; `pages.len() != PAGES.len()` -> `Err(PageCountMismatch { expected: 7, actual })` (nothing else happened); `Declaration = build_items(&pages, options.version.as_deref())`; the per-page `PageView` vector (`scroll 0`, `content_height 0`, `created false`); `Rc::new_cyclic` for the content so that `PageHost::new(weak)` and `SettingsPageContext::new(Rc::new(host))` can be built inside; then `register_subclass_key()`. No OS call. `SettingsDialog::new` takes `chrome` out (`args.chrome.clone()`), calls `new`, then `NativeDialog::with_chrome(content.clone(), chrome)`.
3. **`build_items(pages, version)`** (pure). Items, in this order and with these styles (`child = DIALOG_STYLE_CHILD`, `tab = WS_TABSTOP`, `text = child | SS_NOPREFIX`): `Static HEADER_ID` (`tr::settings_header()`, `text`); `ListBox NAV_ID` (`""`, `child | tab | LBS_NOTIFY | LBS_NOINTEGRALHEIGHT | LBS_OWNERDRAWFIXED | LBS_HASSTRINGS`, ex `WS_EX_CLIENTEDGE`); `Static VERSION_ID` (`version` or `""`, `text`); `Static PAGE_TITLE_ID` (`""`, `text`); `ScrollBar SCROLL_ID` (`""`, `child | SBS_VERT`); per page `i`: `Static viewport_id(i)` (`""`, `text | WS_CLIPCHILDREN | WS_CLIPSIBLINGS`, ex `WS_EX_CONTROLPARENT`); then Buttons `DEFAULTS_ID` (`tr::settings_restore_defaults`), `RESET_PAGE_ID` (`settings_reset_page`), `EXPORT_ID` (`settings_export_settings`), `IMPORT_ID` (`settings_import_settings`), `CANCEL_ID` (`common_cancel`), `APPLY_ID` (`common_apply`), each `child | tab | BS_PUSHBUTTON`, and `SAVE_ID` (`common_save`, `child | tab | BS_DEFPUSHBUTTON`). The page controls are NOT in this list. Per page, in order: `declare` on a new `SettingsPageBuilder::new(page_id_base(i))` (a page that is already borrowed is impossible here: nothing has run yet); a builder with `error().is_some()` (D-W8B5-704) replaces that page, inside its `RefCell`, with `PendingSettingsPage::new(key)` declared on a fresh builder (the user sees the "not available" note instead of a half-built page; nothing is logged here, a log line is the composition root's job); `combo_items()`, `notes()`, `key_boxes()`, `warning_texts()` are merged into `DeclaredSets`. Group lookup is `SettingsPageBuilder::set_group_visible` (D-W8B5-713).
4. **`DialogContent` routing** is in the stub and final: `title` = `tr::settings_window_title()`; `items` = clone; `resizable` true; `header_control_ids` `[HEADER_ID, PAGE_TITLE_ID]`; `initial_focus_id` `NAV_ID`; `default_button_id` `SAVE_ID`; the other hooks call the member named in their doc (`footer`, `apply`, `page_layout`, `messages`, `nav`, `surface`, `close`). A hook never panics (R0003).
5. **`initialize(dialog)`** (C# `OnInitialized`, the framework lays out once right after it returns): store `link = Some(dialog.clone())` FIRST (pages need the host from the first `load`); for each page: `viewport = get_dlg_item(hwnd, viewport_id(i))` (NOT `item`: the hosts are not registered yet), `dialog.add_child_host(viewport)`, `forward(viewport, true)`, `show_window(viewport, SW_HIDE)`; `forward(item(NAV_ID), false)`; one `ListBoxControl::add(nav, page.title())` per page (a borrowed page is impossible here); `key` = `"Files"` when `options.target == ExternalEditor`, else `SettingsPresenter::initial_page_key()`; `index = max(0, position(key))`; `select_single(nav, index)`; the language subscription (`Localizer::on_current_changed(move || poster.post_language_changed())`, the closure holds an `Arc<WindowPoster>` clone and nothing else); `poster.set_hwnd(dialog.hwnd())`; `attached = true`; `activate_page(index, remember: target != ExternalEditor, layout: false)`; for `ExternalEditor`, `post_local(.., Box::new(|c, d| { c.focus_external_editor(d); }))` (runs after the base set the focus on the navigation list).
6. **`focus_external_editor`**: the FIRST page with key `"Files"`: `ensure_page_created`, `activate_page(i, false, true)` when it is not the showing page, then `page.focus_external_editor()` (its answer); no such page -> `false`.
7. **`ensure_page_created`**: see the doc of the stub (7 numbered steps). Details that are traps: the text of each control is asked from the provider NOW; `WS_CLIPSIBLINGS` is OR-ed into every page control (a dialog template adds it itself, `CreateWindowEx` does not); group boxes are moved to the bottom of the z-order only AFTER all siblings exist (otherwise `WS_CLIPSIBLINGS` clips every sibling away: a blank page); a control that fails to create is skipped, the rest of the page is built; the page is marked created BEFORE its controls exist (a re-entrant call from `load` cannot create it twice); `page.attach` then `page.load` with `loading` set; the working copy of the form (`working_fields()`) is used, so a page created after Defaults/Import shows the new values.
8. **`activate_page`**: see the stub doc. The navigation list is told to select the row only when it is not already selected (`select_single` does not send a notification, so no recursion). `scroll[index] = 0` on every activation (switching pages starts at the top). `layout == false` only from `initialize`.
9. **`cycle_page(forward)`** = `activate_page(next_page_index(max(0, active), page_count, forward), true, true)`.
10. **`handle_dialog_key`** = `classify_dialog_key` then the action (see the stub). `control_down` reads `options.control_key_down` or `get_key_state(VK_CONTROL) < 0`; `shift_down` reads `get_key_state(VK_SHIFT) < 0` (not injectable in C#, so not in the options). The native modal loop calls the hook for EVERY message it pulls (mouse moves, paints, timers), so the inputs are computed lazily as the C# `&&` chain does: a message that is not `WM_KEYDOWN` / `WM_SYSKEYDOWN` answers `false` before any OS call and without calling the `control_key_down` option; `control_down`/`shift_down` only for `WM_KEYDOWN` + Tab; `is_key_box` only for the other key messages. A plain Tab, Tab with `WM_SYSKEYDOWN`, a key-up and any other key are `NotHandled` unless the target is a key box.
11. **Ids.** A page control id is `page_id_base(i) + n` (`n` in `1..=999`); `page_of(id)` is `id / 1000 - 1` for `id >= 1000`, else `-1` (for `id >= 8000` it is `>= page_count`: every caller range-checks, the C# would throw `IndexOutOfRange`). `viewport_id(i) = 110 + i`.
12. **Handle accessors.** Every `SettingsDialog` method is ONE call: `self.content.<member>(&self.native, ..)` (members that need no window call the content only). `settings()` clones `presenter.borrow().settings()`. `saved()` reads `view.saved`. Out-of-range indices answer `0`/`None`/empty, never panic.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T3 (arithmetic): `viewport_id` and `page_id_base` use `wrapping_add`/`wrapping_mul` (C# unchecked, only reachable with absurd indices); `page_of` uses `/` on `i32` as C#.
- T8 (null vs empty): `Options.Version` `None` is an empty version text, `Some("")` the same; `Option` for files/decoder factory; `active_page_key` is `""` before the first activation, not an error.
- T9 (exception to Result): the single `ArgumentException` of the constructor is `SettingsDialogError::PageCountMismatch`; an `Err` from `create_window_ex` for one control is the C# `if (control == 0) continue`.
- T10 (order): the item order is the Tab order and the z-order of the template; merged sets are `BTreeMap`/`BTreeSet`; pages and builders are `Vec`s in navigation order.
- Re-entrancy (D-W8B4I-1): the dialog procedure re-enters on every `SendMessage` a page makes (`set_text` -> `EN_CHANGE` -> `on_command`). `ensure_page_created` and `activate_page` copy what they need out of every `RefCell`, release, then call the OS or a page; a page is reached with `try_borrow_mut` and skipped when it is the one running (D-W8B5-904).
- The `Rc` cycle (D-W8B5-901): `link` is set in `initialize` and taken in `close::on_closed` (19m); a test proves with a `Weak` that the content is freed after a modal close and after a close from outside.
- `forward`/`hook_key_box` get their `ref_data` from `subclass_key`, never a pointer (D-W8B5-908).
- Leak: `register_subclass_key` puts a `Weak` in a `thread_local!` map at `new`; `Drop for SettingsContent` and `on_closed` both call the idempotent `forget_subclass_key`, so a dialog built and dropped without `show_modal` leaves no entry (the `PageCountMismatch` path never registers).

## Safety rules (`// SAFETY:` per `unsafe` block)
`create_window_ex`: "the class is one of the standard control classes of `window_class_name`, no `lpParam`, the parent is the live page container of this dialog". Nothing else in this slice is `unsafe`.

## Error mapping
| C# | Rust |
|---|---|
| `ArgumentException` in the constructor | `Err(SettingsDialogError::PageCountMismatch)` |
| `CreateWindowEx` returns 0 for a page control | skip the item |
| `ShowModal` exceptions | `Err(DialogError)` of the native base (D-W8B5-306) |
| exception in a page hook | a panic: captured by the native dialog procedure (`pending_panic`), the dialog closes as Cancel and `show_modal` resumes it |
| `Options.Version ?? BuildInfo.GetVersion(assembly)` | `options.version` as given; no assembly attribute exists in Rust (the composition root passes `BuildStamp::version()`) |

## Open questions (recommended default in bold)
1. **Store the live handle in the content (`link`)** or add a weak handle to `NativeDialog`: **`link`, cleared in `on_closed`** (D-W8B5-901); a `NativeDialog::downgrade()` in 18h would be cleaner and replaces `link` without touching callers (every method takes `&NativeDialog` already).
2. **`SettingsDialogOptions::physical_memory_bytes`**: **dropped**, it is `args.presenter.physical_memory_bytes` (D-W8B5-903); keeping both would let them disagree.
3. **Default `Version`**: **empty** (D-W8B5-903); the C# default reads an assembly attribute that Rust has not.
4. **Frame refuses a page whose builder failed** (D-W8B5-704): **replace by the pending page**; alternative `Err` from `new` would make one broken page kill Settings.
