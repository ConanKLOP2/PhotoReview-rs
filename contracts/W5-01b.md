- Semantics notes:
  1. **Records are plain data.** Public fields, `Clone`/`PartialEq`/`Eq`/`Hash` (the C# record's value equality, golden `equals` / `hash_equal`), `i32`/`i64`
     exactly as C# (`width == 0` means "unknown until the SOF is parsed", offsets are `long`). C# `with { Width = .. }` is struct update on a clone
     (`EmbeddedPreview { width, ..p.clone() }`); no setters, no builder. Constructors only fill the two C# default parameters
     (`HeaderResolved = false`, `IfdIsExif = false`). `EmbeddedPreview.Index` is not validated; a reader that passes a bogus index gets it back.
  2. **Error model.** `InvalidData` carries the message and an optional `io::Error` (C# `InnerException` of type `IOException`/`ObjectDisposedException`).
     `is_io_failure` is exactly `RawHeaderErrors.IsIoFailure`: inner present. `ArgumentOutOfRange` is the programming-error path (negative offset or count);
     `Canceled` is `OperationCanceledException`, "never wrapped": a reader that sees `ct.is_canceled()` returns it, nothing converts it to `InvalidData`.
     Messages that tests pin are produced by the implementors (W5-12, readers); this unit fixes only the formats of `Display` (see the stub).
  3. **`RawHeaderSource::read` borrow rule.** `&mut self` in, `&[u8]` tied to `&mut self` out. This makes "valid only until the next `Read`" a compile error to violate;
     do NOT add `Cow`, `Vec` or `Arc<[u8]>` returns to dodge it (the whole point is zero copies for single-block reads, the 8 MiB budget, INV-8).
     Callers that keep bytes copy them (`to_vec()` / array conversion) before the next read.
  4. **`InMemoryRawHeaderSource::read` order of checks (identical to C#, golden-pinned):** (a) `offset < 0 || count < 0` -> `ArgumentOutOfRange{param:"offset"}`;
     (b) `offset > length - count` (i64, overflow-free; never `offset + count`) -> `InvalidData` "Attempted to read past end of memory (offset: {o}, count: {c}, length: {n})."
     (message text of the in-memory class; the file-backed one says "stream"); (c) `count > MAX_HEADER_BYTES` -> `InvalidData` "RAW header read of {c} bytes exceeds hard limit of
     {MAX} bytes."; (d) `count == 0` -> empty slice, nothing charged (also at `offset == length`); (e) charge block by block from `offset / 64 KiB` to
     `(offset + count - 1) / 64 KiB`: an untouched block costs `min(64 KiB, length - block * 64 KiB)`; if that exceeds `MAX_HEADER_BYTES - total` ->
     `InvalidData` "RAW header read exceeded hard limit of {MAX} bytes." and the blocks already charged in this call STAY charged (golden); a touched block is free.
     The slice returned is `&bytes[offset..offset + count]` (no copy; `MAX_HEADER_BYTES` and the block size are `i64`/`usize` conversions: no `as` truncation on
     `offset`, use `usize::try_from` after check (b)).
  5. **`RawContainerReader` is object safe and `Send + Sync`**; `read` receives `&mut dyn RawHeaderSource` (C# passes the interface) and `&CancelToken` (`pr_core::sync`).
     A hostile or truncated container is `Err(InvalidData)`, never a panic (hardening tests of W5-02..10 call it with garbage).
  6. **`RawPreviewFallback`** returns `Vec<u8>` for `ReadOnlyMemory<byte>` and `DecodeError` (`pr_imaging::decoder_traits`) for the C# exceptions, so W5-12's
     recoverable-failure test and W5-15/16's LibRaw adapter share one error type. A format the provider does not handle is `DecodeError::not_supported(..)`
     (C# `LibRawPreviewFallback` throws `NotSupportedException` unless the format is ORF).
- Traps checklist: §7 items 3 (offset/count math: i64 with `offset > length - count`, no `offset + count`; block index `/` and `%` on non-negative i64 only),

- `oracle/W5-01b.cs`: commands `raw-contract-records` (constructs `EmbeddedPreview` / `ExifBlock` from argument lists, reports fields, `Equals`, hash equality, `with` copy
  equality, enum names and numeric values) and `raw-header-budget` (real `SourceRawHeaderSource` over a `MemoryStream` of `i % 251`, reports each step; the in-memory Rust source
  must reproduce it, W5-12's file-backed one too). Dispatch lines are in the file header. Needs a `PhotoReview.Imaging.Raw.dll` reference in `OracleCs.csproj` (wiring step).
- `golden-inputs/raw-contract-records.json` (12 cases), `golden-inputs/raw-header-budget.json` (12 cases); outputs in `golden-reference/` after the wiring step runs the oracle.
- Case design (records): defaults vs explicit, a header-resolved copy differs, index/colour-space/offset differences, `i32::MIN` height and `i64::MAX` length, enum values. (budget): zero-length
  source, cache hits and boundary crossing, partial last block charging only its bytes, past-end and zero-count edges, negative arguments (check order), overflow-free huge offsets and
  counts, count over the 8 MiB cap, budget exhaustion mid multi-block read keeping the earlier blocks, a single-block read after the budget is spent, sparse blocks.
- Determinism: no clock, no cwd, no files; a 9 MiB `MemoryStream` is built per case.

## Open questions
1. **Where `RawHeaderErrors.IsIoFailure` lives.** Recommended (used by this stub): the method `RawHeaderError::is_io_failure`, because the error type is defined here and W5-01a would
   otherwise import a type from its sibling and re-export a function. Alternative: W5-01a owns the enum too. Lead decides when merging the two stubs; the variant shape is the only
   thing other units depend on.
2. **`InMemoryRawHeaderSource` in the production crate.** C# keeps it in `TestSupport.Windows`. Rust integration tests (`tests/*.rs`) of W5-02..12 cannot see `#[cfg(test)]` items and
   `pr-test-support` would need a dependency on `pr-imaging-raw` (a dev-dependency cycle risk), so the stub puts it in `contracts.rs` as a small public type with an honest doc comment.
   Alternative: `pr-test-support` hosts it behind a `raw` feature. Cost of the recommendation: ~40 lines of non-production code in the crate.
3. **`SyntheticRawBuilder`** (`tests/PhotoReview.Imaging.Tests/Raw/SyntheticRawBuilder.cs`, builds minimal TIFF/BMFF/RAF byte arrays) is used by about 30 RAW test files. No unit owns it
   in the roster. Recommendation: the lead assigns it to W5-02 (first reader porter) as `crates/pr-imaging-raw/tests/common/mod.rs`, with its C# test
   `SyntheticRawBuilder_RoundTripsMinimalContainers`; W5-01b only needs `InMemoryRawHeaderSource`.
4. **`RawHeaderSource::read` count type.** `i32` mirrors C# `int` (callers cast `(int)` after their own checks, and the negative-count `ArgumentOutOfRange` row of the C# test needs a signed
   count). Alternative `usize` makes the negative-count test unrepresentable and moves the check to every caller's cast. Recommendation: keep `i32`.
5. **`raw-header-budget` golden overlap with W5-12.** W5-12 may want its own golden for the file-backed source. This one is deliberately usable by both (same trait, same trace); W5-12 should
   reuse it and add only failure-injection cases (I/O error, short read, which cannot be expressed as inputs).
