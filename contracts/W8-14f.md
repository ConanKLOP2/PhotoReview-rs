## Semantics (C# is the spec)
1. **`NativePopupMenuHost::show(items, point)`** in this order: `owner = owner_hwnd()`; `owner == 0 || showing || items.is_empty()` -> `Ok(None)` (no OS call: pure-testable). `dpi = user32::get_dpi_for_window(owner)` (0 stays 0 -> 96 in the scaling). `session = OwnerDrawMenuSession::new(owner, dpi, self.log.clone())`; `owner_draw = session.attach()`. `root = user32::create_popup_menu()`: `Err` -> `Ok(None)`. `showing.set(true)` through a guard whose `Drop` clears it; a second guard owns `root` and calls `destroy_menu(root)` on drop (this destroys the submenus; the C# `finally`). `populate(root, items, &mut ids, ..)`; `(x, y) = to_screen_pixels(point, dpi)`; `command = user32::track_popup_menu_ex(root, TPM_RETURNCMD | TPM_RIGHTBUTTON, x, y, owner)`; then the id is computed from `command`; the guards are dropped (the menu is destroyed, `showing` cleared); THEN `pending_panic::rethrow_pending()` runs (a panic captured by the window procedure during the nested loop is resumed by the owner of the native call, D-W8B3H-4, with the menu already cleaned up); finally `Ok(id)` where `id = id_for_command(&ids, command)`.
2. **`populate`** exactly as the C# `Populate`/`AppendItem` above: `created(menu)` hook (a `RefCell` borrow is released before the call); `set_menu_info(menu, MIM_BACKGROUND | MIM_APPLY_TO_SUBMENUS, background_brush)` when owner-draw (`SetMenuInfo` with a `MENUINFO` whose `cbSize` is its size); items as above; the plain (no owner-draw) path uses `mapping::display_text` and `user32::append_menu(menu, flags, id, Some(text))`, the owner-draw path registers an `OwnerDrawItem` per item (`text`, `shortcut_text`, `is_separator`, `is_submenu = flags & MF_POPUP != 0`) and calls the private `append_menu_owner_draw(menu, flags | MF_OWNERDRAW, id_or_sub, item_data)` (an `AppendMenuW` whose `lpNewItem` is the app value `item_data`: the `PCWSTR` carries an integer that the OS never reads as text for `MF_OWNERDRAW`). A failing `append_menu` is ignored (C# `AppendMenuData` result discarded `_ =`; the plain `User32.AppendMenu` wrapper would throw: the Rust wrapper returns `Err`, which is ignored the same way: a half-built menu is better than none). `command_ids(items)` is the pure twin of the id assignment and what the tests use.
3. **`to_screen_pixels(dip, dpi)`**: `scale = if dpi == 0 { 1.0 } else { f64::from(dpi) / 96.0 }`; `((dip.x * scale).round_ties_even() as i32, (dip.y * scale).round_ties_even() as i32)`.
4. **Keyboard and focus.** No `SetForegroundWindow`, no `WM_NULL` post after the menu (C# parity); the owner is the viewer window (`owner_hwnd()`), the menu is `TPM_RIGHTBUTTON` so a right click selects. Escape closes, Down+Enter chooses (system menu behaviour). The popup is modal for THIS thread: the window procedure of the owner still runs for messages sent to it (paint, timers, the frame clock); that is why nothing in `show` holds a borrow.
5. **`MainWindowMenus::register(services, input)`** (C# `RegisterContextMenu`): `controller = Rc::new(ContextMenuController::new(Rc::new(MainWindowMenuActions::new(services.clone(), input)), Rc::new(NativePopupMenuHost::new(Box::new(move || services.owner_hwnd())).with_log(services.log())), Some(services.log())))`; `services.window().add_message_handler(Rc::new(ContextMenuMessageHandler::new(services.window(), controller.clone())))`. The `owner_hwnd` closure returns 0 for a destroyed window (C# `_window.IsDestroyed ? 0 : _window.Hwnd`); the closure holds a `Weak` of the services if they own the window (D-W8B3H-18 rule).
6. **`MainWindowMenuActions`** (C# members): `settings()` = `services.settings().current()`; `has_image` = `vm.has_images()`; `can_copy_path` = `vm.can_copy_current_file_path()`; `can_undo` = `true`; `can_open_in_external_editor` = `vm.can_open_in_external_editor()`; `is_compare_visible` = `vm.compare().is_visible()`; `effective_zoom` = `viewer.borrow().effective_zoom()`; `execute(c)` = `input.input().execute(c)` then `Ok(())` (errors are reported inside `ShellInput`); `fit()` = `input.input().apply_fit()`; `zoom_to_configured_level()` = `input.input().set_click_zoom_level(settings.click_zoom_percent)`; `apply_zoom_preset(p)` = `input.apply_zoom_menu_selection(p)`; `custom_zoom()` = `input.open_click_zoom_custom_dialog()`; `set_zoom_also_sets_click_level(v)` / `set_click_zoom_percent(p)`: `begin_edit` + `commit_edit`, a failure is `log.error("Could not save the 'also set as click zoom level' setting" / "Could not save the click zoom level setting", Some(&e))`; `open_in_external_editor()` = `vm.open_in_external_editor()` (`Err(ExternalEditorBug)` is the failure); `copy_file_name()`, `copy_full_pathname()`, `show_settings()` = the view-model calls through `with_view_model`; `report_action_failed(n, e)` = `input.input_host().report_action_failed(n, e)`; `report_menu_failed(e)` = `menus.report_menu_failed("ContextMenu", e)`; `zoom_action_name()` = `services.zoom_action_name()`.
7. **`report_menu_failed(context, error)`**: `services.report_shell_error(context, error)` (`ShellErrorLog.Report`, W8-17a; the file is written even when the general log is off), `services.log().error(&format!("{context} failed"), Some(error))`, `services.show_menu_failed_status(error)` (sets `StatusText = status.menuFailed({message})`, where the message is the user-facing description of the error). Callable from inside the modal loop; the view-model borrow lasts one call.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (handle leaks): every `HMENU` created is destroyed on every path (success, cancel, `Err`, panic): `destroy_menu(root)` in a guard, and a submenu whose `append_menu` failed is destroyed explicitly (it is not yet owned by `root`). `OwnerDrawMenuSession` is a local dropped last (the subclass is removed after the menu is destroyed). Test: `set_menu_created` + `IsMenu` + GDI/USER counts flat over 20 open/cancel cycles.
- T2 (re-entrancy): see rule 4; `showing` is a `Cell`, the hook list a `RefCell` released before each call.
- T3 (capture and focus): `TrackPopupMenuEx` takes the mouse capture itself; after it returns the window's capture state is whatever the system restored (`WM_CAPTURECHANGED` goes through the input handler, which tolerates it, D-W8B4I-4). The host never calls `SetCapture`/`ReleaseCapture`.
- T4 (panic): see rule 1; a panic must not leave a destroyed-menu-less state or a stuck `showing`.
- T5 (integer ids): command id = `ids.len()` after the push, as `usize`; never 0; the OS returns it as `i32`.
- T6 (owner-draw text): text passed to `OwnerDrawItem` is the raw `item.text` (not `&`-doubled) and the raw shortcut text; the plain path uses `display_text` (doubled `&`, TAB).
- T7 (DPI): `GetDpiForWindow(owner)` of the OWNER at the time of showing; the controller already divided the point by the owner's `dpi_scale`.
- T8: no `unwrap`/`expect`; `OwnerDrawMenuSession::attach` returning `false` (subclass failed) shows the system look, not an error.

## Safety rules (`// SAFETY:` per `unsafe` block)
`set_menu_info`: "pointer to a local `MENUINFO` with `cbSize` set; the OS reads it during the call and copies `hbrBack`"; `append_menu_owner_draw`: "`item_data` is an application value for `MF_OWNERDRAW`, never dereferenced by the OS; `idOrSubmenu` is a command id or a handle the OS validates". The calls of `win32::api::user32` are the 11b safe wrappers.

## Error mapping
| C# | Rust |
|---|---|
| `CreatePopupMenu` returns 0 | `Ok(None)` |
| `AppendMenu` failure (C# wrapper) / `_ = AppendMenuData` | ignored (see rule 2) |
| exception while showing | `Err` to the controller -> `report_menu_failed`; a panic is resumed (rule 1) |
| `InvalidOperationException` of `ContextMenu` before registration | unrepresentable (`MainWindowMenus::context_menu()` exists after `register`) |
| `ShellErrorLog.Report` failure | swallowed by the log (its own contract) |
