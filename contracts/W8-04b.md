## Semantics

### export(code, shipped_dir, user_dir)
1. Checks in this order, all before any file access: `code` blank (empty or whitespace only) -> `BlankArgument("code")`;
   `user_dir` blank -> `BlankArgument("user_dir")`; `!LanguageCatalog::is_valid_code(code)` -> `InvalidCode(code.to_owned())`.
2. Catalogs: `read_catalogs(shipped_dir, code)` then `read_catalogs(user_dir, code)` (user last: it wins and supplies `_meta`).
   Notes: `read_notes(shipped_dir / "en.notes.json")`. Text: `build_json(built_in_english(), code, &catalogs, &notes)`.
3. `create_dir_all(user_dir)`. Path: `user_dir / (code.to_lowercase() + ".todo.json")`.
4. If the path exists and its decoded text differs from the new text (ordinal), copy the OLD BYTES to `free_backup_path(path)`.
   Equal text: no backup, the file is rewritten anyway (same bytes).
5. Write the new text as UTF-8 without BOM. Return the path. `Io` for every failure of steps 3 to 5 (no panic, no `unwrap`).

### read_catalogs(dir, code)
6. `dir` is not a directory -> empty `Vec`. Listing `dir` fails (for example `dir` is a file) -> `Err` (C# does not catch it).
7. Candidates: regular files whose name ends with `.json` ASCII case-insensitively (Windows `*.json` pattern). Order: full path string
   by `cmp_ignore_case` (OrdinalIgnoreCase), stable.
8. Skip a candidate whose name has a `.` in its stem: the stem is the name before the LAST `.` (`xx.draft.json` -> `xx.draft`,
   `en.notes.json`, `xx.todo.json` skipped; `xx.json` -> `xx`). A name without `.` before its extension is kept.
9. Skip a file longer than `MAX_FILE_BYTES` (check the length before reading). Read errors skip that file only.
10. Text: strip one leading UTF-8 BOM, decode with `String::from_utf8_lossy`. `LanguageCatalog::try_parse(text, path, &mut warnings)`:
    `None` -> skip. Keep it only when `eq_ignore_case(catalog.code(), code)`.

### read_notes(path)
11. Missing file, not a regular file, longer than `MAX_FILE_BYTES` (check length before reading), unreadable, unparsable,
    or a root that is not an object -> EMPTY map. Nothing partial is returned (C# parses the whole document first).
12. Each member: skip names starting with `_`; keep only string values; a duplicate name keeps the LAST value (C# property order).
13. Syntax: comments (`//` and `/* */`) and trailing commas are accepted, a UTF-8 BOM is skipped, trailing non-whitespace after the
    root is an error (C# `JsonDocument.Parse` behaviour). See open question 1 for how the parser is obtained.

### build_json_with_help(english, code, translations, notes, help) (build_json passes `help_text()`)
14. `is_english = eq_ignore_case(code, ENGLISH_CODE)`.
15. `meta` = the LAST element of `translations` if any; else `english` when `is_english`; else none.
    `plural` = `meta.plural()` or `PluralRule::OneOther` when there is no meta.
16. `current`: sources are `[english] ++ translations` when `is_english`, else `translations`, in that order. For each source entry whose
    key exists in `english`, `current[key] = text` (the last one wins). Keys unknown to English are dropped.
17. `missing` = English keys (in English order) not in `current`, except when `plural == None` and the key is an `X.one` whose
    `X.other` is in English (unused form). Sorted by UTF-16 code unit order (rule T2).
18. `done` = keys of `current` sorted the same way. `entries` = `missing ++ done` (each with its text: the English text for missing).
19. Output, in this order (exact text, see 20):
    `_meta`: `code` = `meta.code()` or `code.to_lowercase()` when no meta; `name` = `meta.name()` or the RAW `code` argument;
    `nativeName` = `meta.native_name()` or the RAW `code`; `plural` = `"none"` for `PluralRule::None`, else `"one-other"`;
    `authors` = `meta.authors()` or `[]`.
    `_help`: the `help` argument. `_missing`: the missing keys in order. `_notes`: for each entry key in `entries` order, the note
    when `notes` has it (keys not exported are dropped). Then one member per entry (`key: text`) in `entries` order.
20. Format (System.Text.Json indented writer): 2 spaces per level, `"name": value` with one space, one member or element per line,
    empty array `[]` and empty object `{}` on one line, LF newlines, exactly one trailing `\n`, no BOM. The top object is `{` ... `}`.
    String escaping (`UnsafeRelaxedJsonEscaping`): `"` -> `\"`, `\` -> `\\`, `\b \f \n \r \t` as short escapes, other U+0000..U+001F as
    `\u00XX`; all other characters (non-ASCII included) are written raw. The golden cases `build-json-escapes` and
    `build-unicode-passthrough` settle the hex case of `\u00XX` and whether U+007F, U+2028, `<`, `>`, `&`, `'`, `+` are escaped:
    FOLLOW THE GOLDEN where it differs from this line, and record the finding in the PARITY row.

## Traps (docs/MULTI-AGENT-PLAN.md section 7, plus this unit)
- T1 Backup name: append `.bak` to the OS string. `Path::with_extension` would replace `.json` (`xx.todo.bak`), wrong.
- T2 Ordinal sort of keys: `encode_utf16()` comparison, not `String` byte order (differs above U+FFFF). Keys in practice are ASCII; the rule is kept anyway.
- T3 `serde_json::Map` is a sorted map without `preserve_order`: do not build the output with it. Write the text by hand (escape
  each string with the rule of 20) so the key order `_meta, _help, _missing, _notes, entries` holds.
- T4 Notes reader and comments/trailing commas: `serde_json` rejects both (see open question 1). Do not silently accept a different
  language without the note.
- T5 `Path::file_stem(".json")` is `".json"` in Rust (dotfile rule) but `""` in .NET. Use `rfind('.')` on the file name (semantics item 8).
- T6 Case-insensitive comparisons of codes and names: `pr_core::text::{eq_ignore_case, cmp_ignore_case}` only (AGENTS.md). Never
  `to_lowercase()` equality.
- T7 Error mapping: `read_catalogs` listing failure -> `Err` (propagated as `Io`); a single bad file -> skipped; `read_notes`
  swallows every failure into an empty map. Do not merge these three rules.
- T8 Fallback names: `_meta.code` falls back to the LOWERCASED code, `name` and `nativeName` fall back to the RAW code.
- T9 English is the base: for `is_english` the translations override English texts; the meta of an English export with
  translations is the last translation's (not English's).
- T10 Plural: decided by `plural == None` only (not `plural_declared()`); the unused-one filter applies only to `None`.
- T11 Backup numbering: `.bak`, then `.bak2`, `.bak3`, ... (there is no `.bak1`).
- T12 File bytes: UTF-8 without BOM, LF only, one trailing `\n`. The C# `Replace("\r\n", "\n")` is a no-op for the writer output; keep it out.
- T13 Invalid code must not create `user_dir` (check the code before `create_dir_all`).
- T14 Equality check of an existing file: decode its bytes like `ReadAllText` for a UTF-8 BOM (strip it); other BOM kinds (UTF-16/32)
  are not decoded (known divergence, documented in the PARITY row; no golden case).
- T15 `fs::copy` copies bytes exactly (the C# `File.Copy` does too); do not re-encode the old file.
- T16 Output text must not depend on `help_text()` in tests: the tests call `build_json_with_help` with the English help text.
- T17 No `unsafe`, no `windows` crate, no `unwrap`/`expect` outside tests. Errors are values.

## Open questions
1. **Notes parser (lenient JSON).** C# `ReadNotes` uses `CommentHandling.Skip` and `AllowTrailingCommas`. `serde_json` does neither,
   and the pr-l10n parser (`LanguageCatalog::try_parse`) is private to `pr_l10n::catalog`. The keygen reader `read_flat_json` is
   in the build script only (`crates/pr-l10n/build/keygen.rs`). Recommended default: the lead exposes ONE lenient object reader
   (`pr_l10n::catalog` or a new `pr_l10n::json_lenient`, owned by the lead, shared with W8-04a) and this unit calls it. Alternative
   (simpler, but a documented divergence with a `DIVERGENCE:` comment in the PARITY row): strict `serde_json` for the notes file only;
   the shipped `en.notes.json` is strict, so the divergence only shows for hand-edited notes. The golden cases `read-notes-comments-and-trailing-commas`
   and `read-notes-trailing-garbage-empty` decide which of the two is in force; with the strict choice the first one must be
   marked `expect_divergence` in the test and the PARITY row must name it.
2. **Escape policy of `_meta`/values.** Item 20 is the recommended default. If the golden differs (uppercase `\u00XX`, escaped U+007F
   or U+2028), follow the golden and keep the rule in one function (`json_string`) so the change is one edit.
3. **Physical file system type.** The tests use `pr_core::io::PhysicalFileSystem`; confirm the re-export path at port time (the
   struct is declared in `crates/pr-core/src/io/physical.rs`).
4. **Non-UTF-8 and UTF-16 files.** .NET `ReadAllText` detects UTF-16/32 BOMs and replaces invalid UTF-8 bytes with U+FFFD. The
   recommended default handles UTF-8 (with or without BOM) only (T14). No golden case exercises UTF-16. Add one only if the lead asks.
