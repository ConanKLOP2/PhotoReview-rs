- Semantics notes:
  1. **Constructor.** `new(directory, pattern, max_bytes, log, clock)`: `Err(InvalidStoreArgument { param_name: "directory" })` when the directory
     text is empty or all `char::is_whitespace` (same set as .NET `char.IsWhiteSpace`), then the same for `"searchPattern"`. `max_bytes =
     max(0, max_bytes)`. Defaults: `NullLog`, `SystemClock`. Nothing touches the disk. The store is a handle over `Arc<StoreInner>` so the prune
     thread can outlive the caller's borrow; dropping the store while a pass runs is fine (the thread keeps the `Arc`).
  2. **`note_accessed(path)` (F-IMG-3).** `now = clock.utc_now()`. Key = `pr_core::text::path_key(path)` (C# `StringComparer.OrdinalIgnoreCase`).
     If the table has the key and `now.ticks() - last.ticks() < ACCESS_TOUCH_INTERVAL_TICKS`, return (strict `<`: exactly 10 min later touches
     again; a clock that went BACK gives a negative difference and is throttled; golden cases). Else: if `len >= MAX_TOUCH_ENTRIES` clear the
     table; insert `(key, now)`; THEN set the file's last-access time to `now`, ignoring every error (missing file, directory, locked, denied).
     The entry is recorded even when the file is missing (golden `missing-file-is-still-tracked`). Do the table work under one mutex; do the file
     call outside it (R0003: no lock across I/O). Setting the time: open with only `FILE_WRITE_ATTRIBUTES` (0x100) and share Read|Write|Delete
     (`std::os::windows::fs::OpenOptionsExt::{access_mode, share_mode}`, `cfg(windows)`), then `File::set_times(FileTimes::new().set_accessed(t))`
     (.NET `File.SetLastAccessTimeUtc`); a `DateTimeUtc` -> `SystemTime` helper is needed (`UNIX_EPOCH` +/- `(ticks - 621_355_968_000_000_000) * 100`
     ns). No `FILE_FLAG_BACKUP_SEMANTICS` (.NET `File.*` opens with `asDirectory: false`, so a directory path fails the open and is
     ignored: golden `directory-path-does-not-throw`). Non-Windows: `OpenOptions::new().write(true)` fallback (never on CI).
     DIVERGENCE (record as `// DIVERGENCE:`): C# catches only `IOException`/`UnauthorizedAccessException`, so `""`, a NUL in the path or a
     time before 1601 throw `ArgumentException`/`ArgumentOutOfRangeException` out of `NoteAccessed` (after the entry was recorded); Rust
     returns `()` and swallows them. Unreachable from the callers (a cache path they just built).
  3. **`note_written(path)` (IMG-10).** Length: `fs::symlink_metadata(path)`; error or a directory => return (C# `FileInfo.Length` throws
     `FileNotFoundException` for both). `u64 -> i64` saturating. Under the size lock: `noted_during_scan = noted_during_scan.wrapping_add(len)`;
     `if tracked_bytes >= 0 { tracked_bytes = tracked_bytes.wrapping_add(len) }` (C# `long` is unchecked). Never touches `skipped_passes`.
     DIVERGENCE: `new FileInfo("")` / a NUL throws `ArgumentException` out of C# `NoteWritten`; Rust returns quietly (same reason as note 2).
  4. **`run_prune_pass()`** (C# private `RunPrunePass`; exact order):
     ```
     lock size: if tracked >= 0 && tracked <= max_bytes && { skipped += 1; skipped < FULL_SCAN_EVERY } { return Ok(()) }
                skipped = 0; noted_during_scan = 0          // the increment happens ONLY when the first two conditions hold
     full_scan_count += 1                                   // before the scan, so a failing scan still counts (golden)
     remaining = prune_directory(dir, pattern, max_bytes, Some(log))?   // Err: return it, size state stays as set above
     lock size: tracked = if remaining < 0 { -1 } else { remaining.wrapping_add(noted_during_scan) }
     ```
     Writes noted while the scan ran are added on top (may double-count: safe, never under-counts; test
     `RunPrunePass_WritesNotedDuringScan_AreAddedToTheTrackedSize`). Never hold the size lock during `prune_directory` (its log calls
     `note_written` in that test: a held lock deadlocks).
  5. **`prune_directory(dir, pattern, max, log)`.** Not an existing directory (`PhysicalFileSystem.directory_exists(dir)`, W2-14's .NET
     `Directory.Exists`: blank, invalid or a file => false) => `Ok(-1)`, nothing created. Pattern validity as `PhysicalFileSystem::enumerate_files`
     (NUL, a separator or a drive-rooted pattern => `Err(InvalidInput)`; C# `ArgumentException` for NUL/rooted), checked AFTER the existence test
     (golden: a missing folder with any pattern is `-1`). DIVERGENCE: .NET splits a pattern with a separator into sub-folder + pattern; W2-14
     rejects it (unpinned there too; every store pattern is a constant `*.ext`). Paths: C# `new DirectoryInfo(dir)` normalises with
     `Path.GetFullPath`, so each `FileInfo.FullName` (the path given to `try_delete`, hence the `Delete failed: {path}` text) is
     `pr_core::text::dotnet_path::get_full_path(dir)` (trailing separator trimmed) joined with the entry name, NOT `dir.join(name)` and never
     `std::path::absolute` (§7 item 7; differs for a relative, `/`-spelled or `.`-containing `dir`). List that full path with `fs::read_dir`;
     per entry: a `read_dir`/entry error is returned as `Err` (C# enumeration throws); keep the entry when it is NOT a directory by
     attribute (`MetadataExt::file_attributes() & 0x10 == 0` under `cfg(windows)`, so directory symlinks/junctions are excluded and file symlinks
     kept, like `DirectoryInfo.EnumerateFiles`) and its name matches `pr_core::io::physical::matches_win32_expression(pattern, name)`. Length and
     times come from `DirEntry::metadata()` (Windows: the `FindNextFile` data, no open: perf IMG-10/AR16). Sort key `(last_access_time(),
     creation_time())` as raw FILETIME `u64` (`MetadataExt`; same order as C# `DateTime`), `sort_by_key` (stable: equal keys keep listing order,
     golden `full-tie-keeps-listing-order`; never `sort_unstable`). `total` = sum of lengths (`i64`, saturating; DIVERGENCE: LINQ `Sum` is
     `checked` and throws `OverflowException` past `i64::MAX`, unreachable on a real disk). Then in order: `if total <= max
     { break }`; `if try_delete(path, log) { total -= len }`. Return `Ok(total)`. A file that cannot be deleted stays counted (golden). The static
     helper does NOT clamp `max` (golden `negative-quota-static-is-not-clamped-deletes-everything`); only the constructor clamps.
  6. **`schedule_prune` / the loop (INV-2: the store must never wedge).** Two `AtomicBool`s, `SeqCst` (R0003):
     ```
     schedule_prune: if scheduled.swap(true) { pending.store(true); return }  start_loop()
     start_loop:     spawn thread "pr-disk-cache-prune" running:
                       loop { pending.store(false); run pass inside catch_unwind; on Err/panic: log.error("Prune failed: {dir}", err)
                              if !pending.load() { break } }
                       hook (if set) ; scheduled.store(false) ; notify idle condvar
                       if pending.load() && !scheduled.swap(true) { start_loop() }   // exit-window request (race test)
     ```
     `{dir}` is `directory.display()`. A panic in a pass is logged with an error whose `Display` is the panic message
     (`pr_core::abstractions::panic_message`) and does not end the loop early. If `thread::Builder::spawn` fails, run the same body INLINE on the
     caller's thread rather than leave `scheduled` stuck at true (C# `Task.Run` cannot fail; this is the only way to keep "never wedges"); note
     it as a `// DIVERGENCE:` comment. The hook runs on the prune thread after the last pending check and before `scheduled` is cleared; a
     `schedule_prune` from inside it sets `pending` (scheduled is still true) and the tail check starts a second loop (test + golden-free race
     test). Do not hold any lock while calling the hook or the log.
  7. **`wait_for_prune(timeout)`.** Deadline = `Instant::now() + timeout`; wait on the idle condvar while `scheduled || pending` and time is left
     (re-check after every wake-up; spurious wake-ups are fine); return `!scheduled`. No lost wake-up: the waiter reads the flags while holding
     `idle_lock`, and the prune thread takes `idle_lock` around `notify_all` (after its `scheduled.store(false)`); otherwise a notify between the
     waiter's check and its `wait_timeout` costs the whole timeout. A `pending` with `scheduled == false` exists (a) inside the exit window (the
     tail check restarts the loop) and (b) in one rare C# race: a `schedule_prune` that saw `scheduled == true` stores `pending` only after the
     loop's tail check; `pending` then stays set until the next `schedule_prune`, and a waiter waits the full timeout and returns `true`. Keep
     both as C# does (the C# poll behaves the same). No `sleep` polling (AGENTS.md tests rule applies to the code the tests wait on).
  8. **Clear.** `clear_directory()` = `clear_directory_matching(dir, pattern, Some(log))?` then `clear_directory_matching(dir, TEMP_FILE_PATTERN,
     None)?` (no log: a live writer still holds its temp file and deletes it itself; golden `clear-instance-locked-temp-not-logged-...`), then
     under the size lock `tracked = -1; noted_during_scan = 0` (`skipped_passes` untouched). It does NOT touch the prune flags: a pass running
     concurrently may overwrite `tracked` afterwards with its own result (C# has the same benign race; do not "fix" it, it only costs a scan).
     `clear_directory_matching`: missing folder (`directory_exists`) => `Ok(())`; then exactly C# `Directory.EnumerateFiles(dir, pattern)`, which
     is `PhysicalFileSystem.enumerate_files(dir, pattern)` (W2-14, golden `physical-fs-pattern`: files only by attribute, DOS matcher, pattern
     validation => `Err(InvalidInput)` for NUL, golden `clear-static-nul-pattern-throws`). Unlike note 5 the paths are spelled as the CALLER gave
     `dir` (`Path.Join(dir, name)`, W2-14 `join_as_spelled`), not the full path: this is what `Delete failed: {path}` prints. `try_delete` each,
     results ignored. (The W2-14 call lists eagerly; C# deletes during a lazy listing: same effects.)
  9. **`is_cache_entry_failure(&DecodeError)`** (C# `ex is IOException or UnauthorizedAccessException or NotSupportedException or FormatException or
     InvalidDataException or ArgumentException or InvalidOperationException or OverflowException or InvalidCastException or COMException`,
     including subclasses). Over W4-01c's `DecodeError`: TRUE for `Io(_)` (covers `IOException`, `UnauthorizedAccessException`, `EndOfStream`,
     `PathTooLong`), `FileNotFound`, `DirectoryNotFound`, `MemoryAdmission` (an `IOException` subclass: true, surprising but C#), `NotSupported`,
     `MissingCodec` (a `NotSupportedException`), `Format`, `InvalidData`, `InvalidArgument` (`ArgumentNullException`/`OutOfRange` too),
     `InvalidOperation`, `Disposed` (`ObjectDisposedException` derives `InvalidOperationException`), `Overflow`, `InvalidCast`, `Com { .. }` (any
     HRESULT, `E_OUTOFMEMORY` included: the WIC reader maps that one to `OutOfMemory` BEFORE it reaches here). FALSE for `Busy`, `Canceled`,
     `OutOfMemory` (`InsufficientMemoryException` too), `DllNotFound`, `BadImageFormat`, `EntryPointNotFound`, `Other`. Write it as one exhaustive
     `match` with no `_` arm, so a new variant forces a decision. The golden `cache-entry-failure` is keyed by C# type name; the test maps each name
     to a variant with a table in the test file (`TaskCanceledException` => `Canceled`, `PlatformNotSupportedException` => `NotSupported`,
     `NullReferenceException`/`TimeoutException`/`Exception` => `Other`, `EndOfStreamException`/`PathTooLongException`/`IOException`/
     `UnauthorizedAccessException` => `Io(..)` with a matching kind).
  10. **`try_delete(path, log)`.** `PhysicalFileSystem.file_exists(path)` false => `false`, nothing logged (missing, a directory, `""`). Else
      `PhysicalFileSystem.delete(path)` (W2-14: `DeleteFileW`, so a Read-only file FAILS with `PermissionDenied` like .NET `File.Delete`; std's
      `remove_file` clears Read-only and would delete it: never use it here). `Err(e)` => `log.error(&format!("Delete failed: {}",
      path.display()), Some(&e))`, `false`. `Ok` => `!file_exists(path)` (a delete-pending file still exists: `false`, no log). C# catches only
      `IOException`/`UnauthorizedAccessException`; every `io::Error` is one of those here.
  11. **`delete_stale_temp_files(dir, now, max, log)`.** Missing folder (`directory_exists`) => `0`. Lazy listing (C# `Directory.EnumerateFiles`:
      files only by attribute, matcher `"*.tmp"`, paths spelled as the caller gave `dir`, like note 8), stop after `max` matches (`max <= 0` =>
      look at none; C# `Take` counts ENTRIES looked at, fresh ones included: golden `max-files-counts-fresh-files-too`). The lazy listing needs
      W2-14's private `listing_root`/`join_as_spelled` (open question 2); if they are not hoisted, `PhysicalFileSystem.enumerate_files` then
      `take(max)` is acceptable with a `// DIVERGENCE:` (a listing error after some entries then deletes nothing instead of some; only reachable
      when the folder vanishes mid-listing). Per match: last write time from `fs::symlink_metadata` (.NET `File.GetLastWriteTimeUtc` uses
      `GetFileAttributesEx`, which does not follow a link; std falls back to `FindFirstFileW` on a sharing violation, so a temp file a live
      writer holds share-none still stats) (`MetadataExt::last_write_time()` FILETIME); `NotFound`
      => treat as 1601-01-01 (.NET returns `FromFileTimeUtc(0)` for a missing file; `try_delete` then returns false, so it only matters for
      parity of the count); any other error => skip. Delete when `now.ticks() - written.ticks() > STALE_TEMP_FILE_AGE_TICKS` (strictly greater:
      exactly 10 min stays, golden) and `try_delete(path, log)`; count the deletions. A listing error (open or mid-way) => `log.error("Stale temp
      file cleanup failed: {dir}", err)` and return the count so far. Never panics.
  12. **`write_atomically` / `write_pixels_atomically`.** Blank `cache_path` => `Err(DecodeError::InvalidArgument { message })` before anything

## Open questions
1. **Encoder seam.** `PngEncoder` is defined here because `pr-imaging` cannot depend on `pr-platform-win`. W4-08b needs a JPEG twin for
   `PreviewCacheFile`. Recommended: the lead merges both into one `pr_imaging::cache::CacheImageEncoder { encode_png, encode_jpeg(quality) }` in
   `cache/mod.rs` before W4-08b/W4-11e start; this file then re-exports or uses it (signature of the free fns changes only in the trait name).
   Alternative: keep two single-method traits.
2. **Pattern and listing helpers.** `matches_win32_expression` and `PhysicalFileSystem::enumerate_files` are public, but the pattern validation,
   the UTF-16 matcher (names with lone surrogates), `listing_root` (full path, trailing separator trimmed, .NET-style directory open) and
   `join_as_spelled` (`Path.Join` as `Directory.EnumerateFiles` spells it) are private in `pr_core::io::physical`. Recommended: lead hoists
   `pub fn validate_search_pattern(&str) -> io::Result<()>`, `pub fn matches_win32_expression_os(&str, &OsStr) -> bool` and a lazy
   `pub fn enumerate_files_lazy(dir, pattern) -> io::Result<impl Iterator<Item = io::Result<(PathBuf, Metadata)>>>` (spelled paths) into
   `pr_core::io::physical` (W2-14 owner file, small additive change). Alternative: clear uses `enumerate_files` as is, the stale sweep uses it
   with the divergence of note 11, and `prune_directory` builds its own `read_dir` over `get_full_path(dir)` with a copied 3-line pattern check
   (names with lone surrogates then go through `to_string_lossy`, a divergence nobody can hit with cache file names, which are hex + ASCII
   extensions).
3. **Draft type names.** W4-01b names the decoded-image trait `DecodedImageView` and `PlatformImage` an enum; W4-01c's stub refers to
   `dyn DecodedImage` and a `PlatformImage` type alias. This stub follows W4-01b (it owns the types; D28). The lead aligns W4-01c before the
   wiring step.
4. **Spawn failure.** C# `Task.Run` cannot fail; the stub runs the loop inline on the caller's thread if `thread::Builder::spawn` fails (note 6).
   Alternative: clear `scheduled`, log `Prune failed` and drop the request (cheaper for the caller, but a later `schedule_prune` is needed). The
   inline run is recommended: a full scan on a persist worker is rare and harmless; a dropped prune lets the cache exceed its quota.
5. **Uncaught `ArgumentException`s.** .NET throws out of `NoteAccessed` (path `""`/NUL, clock value before 1601) and `NoteWritten` (path
   `""`/NUL); the Rust signatures return `()` and swallow them (notes 2, 3). Unreachable with real cache paths and a real clock; record as
   `// DIVERGENCE:` only. Alternative: `debug_assert!` on a blank path (not recommended: a test-only panic C# does not have either).
