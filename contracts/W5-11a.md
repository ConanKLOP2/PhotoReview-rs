- Semantics notes:
  1. **Routing.** `find_reader` scans the readers in order and returns the first whose `can_read(first_64_bytes, extension)` is true. No sorting, no caching,
     no extension normalisation (the readers do the OrdinalIgnoreCase compare), no padding of a short header (a reader that needs 10 bytes says no to 9; golden
     rows `*-header-N-bytes`). Returns `Option<&dyn RawContainerReader>` borrowed from the registry (C# returns the instance). `find_reader_index` is
     a Rust-only twin of the same scan. Both are `&self`: the registry is immutable after construction and `Send + Sync`.
  2. **Default list.** Order `Cr2, Nef, Arw, Dng, Orf, Rw2, Cr3, Raf` (= `DEFAULT_READER_ORDER`; the oracle reads the real list by reflection and the golden case
     `default-registration-order` compares). Each reader owns exactly one extension, so the order is not observable through `find_reader`; it is pinned anyway
     because W5-12 may add a fallback reader behind them. NRW and PEF are absent on purpose (`RawFormat` has them, no reader does).
  3. **Custom list.** `with_readers` takes the readers verbatim: empty allowed, duplicates allowed. `Vec<Box<dyn RawContainerReader>>` is the storage (trait is
     `Send + Sync`, so no extra bounds); do NOT switch to `Arc` unless the lead changes the trait.
  4. **`ensure_adobe_rgb_profile` order of checks** (matches C#): (a) `has_embedded_icc(&jpeg)` => `Ok(jpeg)` untouched (same allocation, no copy);
     (b) `jpeg.len() < 2 || jpeg[0] != 0xFF || jpeg[1] != 0xD8` => `InvalidData("Adobe RGB preview is not a valid JPEG stream.")` (a one-byte `[FF]` input is
     rejected, `[FF D8]` alone is accepted and gets the segment); (c) `16 + profile.len() > 65535` => `InvalidData("Adobe RGB ICC profile exceeds JPEG APP2 limits.")`;
     (d) build: `FF D8 FF E2 <len be16> "ICC_PROFILE\0" 01 01 <profile> <jpeg[2..]>`, `len = 16 + profile.len()` (= length field 2 + identifier 12 + sequence/count 2 + payload).
     The result length is `jpeg.len() + 2 + 16 + profile.len()` (the C# allocates `4 + 12 + 2` = 18 = `2 + 16`). `with_capacity` once, no reallocation.
     The error is `RawHeaderError::invalid_data(..)` (no inner io error, so `is_io_failure()` is false; W5-12 relies on that to add its localized "corrupt" text).
  5. **`has_embedded_icc` is the C# walk, byte for byte** (see its doc comment in the stub). Traps: the loop guard is `offset + 4 <= len`, so a standalone marker
     that leaves fewer than 4 bytes ends the walk with `false`; the length check is `length < 2 || offset + length > len` where `offset` points at the length bytes
     (a segment ending exactly at the end is valid: golden `app2-length-exactly-fits-the-buffer` and `icc-segment-ends-exactly-at-end`); only marker `E2` with a
     payload of at least 12 bytes and the identifier counts (an `E1` carrying the identifier and an `E2` with 11 bytes do not, goldens); `DA` and `D9` stop the walk;
     markers `D8`, `01`, `D0..=D7` have no length; a non-`FF` byte where a marker must start returns false; fill-byte runs are skipped. Every index is checked before use;
     usize math cannot overflow because `offset <= len` holds at each step and `length <= 0xFFFF`.
  6. **Profile asset.** `include_bytes!("../assets/AdobeCompat-v2.icc")` (path relative to `src/registry.rs`); the file is binary: the porter must not retype or re-encode it
     (the lead copies it; check with `git diff --stat` that it is 374 bytes, and the golden `bundled-profile-identity` fails on any change). Licence note for the ADR trail:
     CC0, same bytes as the C# resource. `.gitattributes` must not apply text normalisation to `*.icc` (check, add `*.icc binary` if missing: lead-owned file).
  7. **No unsafe, no I/O, no logging, no panics.** `unwrap`/`expect`/indexing only where a bound was just proven; the hardening test (every prefix of every golden JPEG) enforces it.
- Traps checklist: §7 items 1 (extension compare lives in the readers, OrdinalIgnoreCase via `pr_core::text`, never `to_lowercase` here), 3 (no `as` casts on lengths: the segment
  length is a checked `u16::try_from`; the `ushort.MaxValue` limit is exactly 65535), 8 (`None` vs empty result: an untagged JPEG is `Ok(new Vec)`, a tagged one `Ok(same Vec)`, never
  `None`), 9 (one error variant `InvalidData`; no `Canceled`, no io), 10 (no `HashMap` anywhere). INV: none owned; INV-8 (bounded header reads) is the source's job, the registry never reads.

## Golden package
- `oracle/W5-11a.cs`: commands `raw-registry-find` (builds the default or a named custom registry, runs `FindReader`, reports the reader name and its index read through
  reflection on the private `_readers` list; case `op:"default-order"` reports the real default order) and `raw-icc-ensure` (calls the internal
  `RawJpegIccProfile.EnsureAdobeRgbProfile` through reflection; reports ok, error type and message, reference equality with the input, result length, first 20 bytes, whether the profile
  and the tail are intact; case `op:"profile"` reports the bundled profile's length and FNV-1a 64). Dispatch lines are in the file header. Needs the `PhotoReview.Imaging.Raw.dll`
  reference in `OracleCs.csproj` (wiring step, same as W5-01b). No InternalsVisibleTo change (the C# repo is never edited): reflection only.
- `golden-inputs/raw-registry-find.json` (49 cases incl. the order case) and `golden-inputs/raw-icc-ensure.json` (44 cases); both generated by `gen-inputs.js` (kept for review).
  Outputs land in `golden-reference/` after the wiring step runs the oracle (not run here).
- Case design (registry): every default reader accepted at its minimum header length and refused one byte below (CR2 10/9, NEF 4/3, CR3 12/11, RAF 16/15), upper/mixed-case
  extensions, the four ORF magics, TIFF big/little endian per reader, RW2 `IIU\0` vs TIFF magic, RAF last-byte mismatch, reserved NRW/PEF, wrong/empty/dotless/trailing-space extension, empty header, 64-byte header,
  and custom registries (empty, duplicate, other order, subset missing the extension).
  (ICC): the rejected inputs of the C# theory rows, injection for untagged/non-ICC APP2/APP1-identifier/after SOS/11-byte payload/near-miss identifiers, truncated and impossible
  lengths (including the exact-fit and one-past boundary), fill/marker truncation, EOI stop, every "already tagged" layout of the mutation-gap file (long segment, RST0/RST7, SOF-length segment,
  second SOI, TEM, empty segment, segment at the very end, identifier-only payload, two ICC segments, MPF then ICC), and one 4 KiB stream to check the tail copy.
- Determinism: no clock, no files, no culture (headers are hex).

## Open questions
1. **`ensure_adobe_rgb_profile` signature.** Recommended (used by the stub): `Vec<u8> -> Result<Vec<u8>, RawHeaderError>` so the "tagged, return as is" path moves the caller's buffer and
   the "same instance" test is a pointer compare. Alternative: `&[u8] -> Result<Cow<'_, [u8]>, _>` (borrowed = tagged); costs one `into_owned()` copy at the W5-12 call site when it needs a `Vec`
   for the decoder. Lead decides when W5-12's stub is written; only that call site changes.
2. **Reader identity in the registry.** `find_reader_index`/`DEFAULT_READER_ORDER` are Rust-only additions so the golden can name readers without adding `name()` to `RawContainerReader`
   (a trait change in W5-01b). Alternative: add `fn format(&self) -> RawFormat` to the trait (useful for W5-12 logging too); then `find_reader_index` can be dropped. Not required for this unit.
3. **Asset location.** `crates/pr-imaging-raw/assets/` is a new directory; `docs/INDEX.md`/`assets/SYNC-MANIFEST.txt` may want a line (the root `assets/` folder holds language data, a different purpose).
   Recommended: keep it inside the crate so `include_bytes!` stays crate-relative and the crate stays publishable as a unit.
4. **Default registry before W5-03..10 land.** The stub's `new()` is `todo!()` and the default-list tests are listed as dependent on all eight readers; a partial default list is NOT acceptable
   (it would change routing silently), hence the `#[ignore]` fallback above instead of a feature-gated shorter list.
