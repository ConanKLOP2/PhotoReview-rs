## Semantics notes
Pseudo-code of the C# `Read` (the porter keeps this call ORDER: it decides which 64 KiB blocks are touched, and the golden pins `bytes_read`):

```
if source.length() < 16                          -> Err(InvalidData("File too short for CR2 container."))
header = try_read_header(source.read(0, 16)?)    -> None, or magic != 42 -> Err(InvalidData("Invalid CR2 TIFF header."))
orientation = 1; exif_w = exif_h = 0; largest_area = 0; largest_w = largest_h = 0; previews = []; exif_blocks = []
visited = {}; current = ifd0_offset as i64; ifd_index = 0
while current > 0 && ifd_index < 64:
    ct.check()?                                   // Canceled; only here
    if !visited.insert(current): break            // cycle
    (entries, next) = read_ifd_entries(source, current, le)?
    (w, h)          = read_image_size(source, entries, le)?
    if ifd_index == 0 && read_tag_value(.., 0x0112)? in 1..=8: orientation = value
    if let Some(p) = read_tag_value(.., 0x8769)? && p > 0:
        if exif_blocks.is_empty(): exif_blocks.push(compute_exif_block(source, le, ifd0_offset)?)
        if exif_w == 0 && let Some((pw, ph)) = try_read_exif_pixel_dimensions(source, p, le)?: exif_w = pw; exif_h = ph
    area = w as i64 * h as i64; if area > largest_area: largest = (area, w, h)
    if ifd_index == 0:
        if let Some((off, len)) = try_read_single_strip(..)? && starts_with_soi(source, off, len)?:
            (sw, sh) = (w, h); reconcile_jpeg_size(source, off, len, &mut sw, &mut sh)?
            previews.push(EmbeddedPreview { index: previews.len(), offset: off, length: len, Jpeg, sw, sh, Unknown, header_resolved: false })
    else if let Some((off, len)) = try_read_jpeg_interchange(..)?:
        (pw, ph) = (w, h); reconcile_jpeg_size(..)?; previews.push(same shape)
    current = next as i64; ifd_index += 1
sensor_w = if exif_w > 0 { exif_w } else { largest_w }; sensor_h = if exif_w > 0 { exif_h } else { largest_h }
if exif_blocks.is_empty(): exif_blocks.push(compute_exif_block(source, le, ifd0_offset)?)
Ok(RawContainerInfo { Cr2, sensor_w, sensor_h, orientation, previews, exif_blocks })
```

1. **`can_read`.** Extension: `pr_core::text::eq_ignore_case(extension, ".cr2")` (`.CR2`, `.Cr2` yes; `cr2`, `.cr2 `, `""`, `.cr3` no). Bytes: at least 10, `[0..4] == 49 49 2A 00`, `[8] == 'C'`, `[9] == 'R'` (upper case). Bytes 4..8 are
   NOT looked at (any IFD0 offset), the big-endian `MM\0*` header is rejected here (but `read` accepts it), only the `2A 00` pair is checked, not "magic == 42" semantics for other values.
   Shorter input (including empty) is `false`, never a panic. Golden: 21 `can-read` cases incl. each of the 6 signature bytes flipped.
2. **Header.** Fewer than 16 source bytes is `InvalidData` even though only 8 are used (the C# reads 16). `try_read_header` accepts `II`/`MM`; `read` then demands magic 42, so `II+\0`, ORF `IIRO` and RW2 `IIU\0` are errors.
   The `CR` marker at 8..9 is NOT validated by `read` (golden `read-no-cr-marker-is-not-checked-by-read`): the caller already sniffed with `can_read`.
3. **IFD chain.** Start offset `ifd0_offset` (u32) widened to i64; `0` means "no IFD" (empty info, still ONE Exif block, no cancel check: golden `canceled-token-with-ifd0-offset-zero-never-checks`).
   At most 64 IFDs (index 0..=63; golden `chain-of-65-ifds-65th-is-ignored`, `chain-of-64-ifds-64th-is-read`); a repeated offset ends the loop (self loop, A<->B, A->B->C->B);
   `next_ifd_offset` is already validated by the navigator (`>= 8 && <= len - 6`, else 0). `read_ifd_entries` returning an empty list is not an error.
4. **Orientation** only from IFD0, only values 1..=8 (`0`, `9`, `255`, `65535` keep 1); IFD1's orientation is ignored even when IFD0 has none; any numeric tag type is accepted (LONG 6 works).
5. **IFD0 strip preview.** Only `ifd_index == 0`. `try_read_single_strip` requires `StripOffsets` AND `StripByteCounts` present with `count == 1` each, `offset > 0`, `length > 0`, `offset <= file_length - length`;
   then `starts_with_soi` (needs `length >= 4` and bytes `FF D8`). A JPEG over several strips is rejected (not "first strip only"). `length` is `i64` and may be up to `u32::MAX`
   (3_000_000_000 against a source reporting 3.5 GB): never narrow it to `i32` (the C# bug fixed in "Read_Cr2StripLengthAboveIntMaxValue"). The preview size is the IFD0 `ImageWidth/Length` as a hint, replaced by the JPEG's own frame size when BOTH are > 0
   and the frame is readable; otherwise it stays as declared (0 when undeclared). IFD0's `0x0201/0x0202` pair is IGNORED (the `else if` hangs off `ifd_index == 0`): golden `ifd0-interchange-tags-are-not-used-for-ifd0`.
6. **IFD1+ previews.** For `ifd_index >= 1`: `try_read_jpeg_interchange` (0x0201 + 0x0202, range inside file, SOI). No de-duplication (unlike ARW): the same JPEG in IFD0's strip and IFD1, or in IFD1 and IFD2, is listed twice.
   `index` = position in the list (0 for the first listed preview, even when it comes from IFD1). `kind = Jpeg`, `color_space = Unknown`, `header_resolved = false`.
7. **Sensor size.** `exif_w > 0` wins (and then `exif_h` is used even if it equals 0 -> impossible, the navigator returns both > 0 or none). Else the largest IFD by `w as i64 * h as i64`, STRICTLY greater (a tie keeps the earlier IFD; an IFD with only a width has area 0 and never wins). IFD sizes
   come clamped to `i32::MAX` by the navigator (`ifd-size-above-int-max-is-clamped`: 2147483647x3). sRAW: IFD0 is the 5184x3456 preview, Exif says 2592x1728, Exif wins.
   The Exif IFD is tried in EVERY IFD that has a pointer while `exif_w == 0` (a width-only first Exif IFD does not block a complete later one: golden `exif-width-only-in-ifd0-then-complete-in-ifd1`); once found, later Exif IFDs are not even read (matters for `bytes_read`).
   The pointer must be `> 0`; the Exif IFD offset is not range checked here.
8. **Exif block.** Exactly one block per result. It is computed (`compute_exif_block(source, le, ifd0_offset)`, always with IFD0's offset, never the offset of the IFD that held the pointer) at the FIRST IFD that has a pointer `> 0`,
   otherwise after the loop. It always starts at 0, `is_tiff_header = true`, `ifd_is_exif = false`. Length rules live in the navigator (`min(file, 128 KiB)`, grown to the IFD/value extent up to 4 MiB, kept at the default when the extent does not fit).
9. **Errors.** Everything the navigator or the source raises propagates with `?` UNCHANGED (never rebuild it as a fresh `InvalidData`: the I/O cause and `is_io_failure()` must survive for W5-12; the golden checks `io_failure`).
   Cancellation: `ct.check()` at the top of each loop iteration only (not before the header checks: a canceled token with a short file or a bad magic still returns `InvalidData`). Nothing else may panic: no `unwrap`, no unchecked slicing or `as` narrowing on
   file-controlled values, no `+` on offsets that can overflow (`i64` math with `checked_*`/`saturating_*`; the C# relies on `long`).
10. **Budget parity.** `bytes_read` of the golden is the production `SourceRawHeaderSource` charge (whole distinct 64 KiB blocks, last block counts the bytes it holds). The Rust support source must charge identically and the reader must touch the same blocks:
    same navigator calls, same order, no extra "peek" reads (e.g. do not read the 16-byte header twice, do not pre-read the strip). The 8 MiB budget cases (`*-exhausting-header-budget`) pin that a JPEG walk running out of budget is swallowed by
    `reconcile_jpeg_size` and keeps the declared size, while the same exhaustion inside `read_ifd_entries` would propagate.

- No network, no clock, no file system in this file; corpus reads happen only in the test file.
