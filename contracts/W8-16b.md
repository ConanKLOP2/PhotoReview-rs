## Semantics (C# is the spec)
### Compare
1. `layout::*` is the C# arithmetic in `f64`, in the C# operation order. Every `Math.Max(0, x)` / `Math.Min` keeps .NET semantics: a NaN operand gives NaN (`f64::max(0.0, NAN)` would give 0). The porter writes private `net_max` / `net_min` helpers (the `pr_app` ones are private). A NaN client therefore yields NaN rectangles; `hit_test` then fails its `> 0` guards (`NaN > 0` is false) and returns `None`, `draw` returns `Ok(0)` (panel width `> 0` false). Test it.
2. `layout::hit_test` uses `RectD::contains` (closed, with the C# formula `p.x - width <= x`), NOT `scrollbar_geometry::inside` (half-open). Consequence: a point exactly on the right edge `x = 1188` of the right border `(604, 12, 584, 776)` is a hit (closed), which the half-open `inside` would reject; the C# test only pins `(1187, 787)`, so the porter adds `x = 1188` as a new test to lock the choice.
3. `draw`: empty panel -> `Ok(0)` and NOTHING is drawn (no `fill_rectangle`). Else `fill_rectangle(panel, canvas())`, then left, then right; `draw_cell`: border empty -> 0 (nothing drawn for that cell); `draw_border(color)` (selected `selected_color()`, else `unselected_color()`) with the exact bar order (top, bottom, left, right); a `None` or disposed buffer -> 0; else `push_clip(content)`, `try_draw(cache, context, pixels, image_rect, interpolation, 1.0, 1)`, `pop_clip()`.
4. Clip balance (try/finally, trap T-compare): the result of `try_draw` is kept, `pop_clip()` ALWAYS runs, then the draw error (if any) wins over a `pop_clip` error. `pop_clip` fails only when unbalanced (a bug), so that branch is `debug_assert`-level and returned as the `Err`.
5. `CompareFrame::from_view_model`: `left = compare.left_image().and_then(|d| d.platform_image().as_pixels()).map(|a| &**a)`, same for right; `left_selected = compare.is_left_selected()`, `right_selected = compare.is_right_selected()`. A `PlatformImage::Opaque` image gives `None` (C# `as PixelBuffer` is null). `CompareFrame` borrows the view model for one frame; it must not be kept.
6. INV-1: the GPU bitmap of each cell is the cache entry of `PixelBuffer::id()`; `draw` never looks at a path. The two ids are kept alive by `UpdateRetained` in 13j (it adds both ids while `compare.is_visible()`); this unit only draws.

### Crossfade
7. **State**: `outgoing: RefCell<Option<Arc<PixelBuffer>>>`, `frame: Cell<RectD>`, `interpolation: Cell<ImageInterpolation>`, `opacity: Cell<f32>`, `start_count: Cell<i32>`, `disposed: Cell<bool>`, `animator: RefCell<Animator>`, `frame_subscription: Cell<Option<FrameHandlerId>>`, the clock and the `invalidate` callback. Shared as `Rc<Inner>`; the clock handler holds a `Weak<Inner>` (a strong `Rc` in the clock would keep the layer alive after the window dropped it).
8. **Animator ownership** (the one structural difference from C#): `Animator::fade_to`/`on_frame` take an `&mut dyn OpacityStore`. The store is a small adapter `Store<'a>(&'a Inner)` whose `opacity(id)` answers `Some(opacity)` only for `ELEMENT_ID` while `outgoing` is `Some` (C# `ResolveTarget`) and whose `set_opacity` writes the cell. No `RefCell` borrow of `animator` may be held while `invalidate` or the clock runs (T3 below).
9. **`start`** (C# 68-87), in this order: `Err(Disposed)` if disposed; `Ok(false)` when `outgoing.is_disposed()`, `duration` converts to `<= 0` animator ticks (`(duration.as_nanos() / 100) as i64`, i.e. under 100 ns), `frame.width <= 0`, `frame.height <= 0` (a NaN size also fails: `!(w > 0)`), or any of `frame.{x,y,width,height}` is not finite (`!f64::is_finite`). Else: `animator.cancel(ELEMENT_ID)` (and unsubscribe if now idle), store `outgoing`/`frame`/`interpolation`, `opacity = 1.0`, `start_count += 1`, `fade_to(store, ELEMENT_ID, 0.0, ticks, QuadraticOut)` -> if `effect.request_frame`: subscribe (once) and `clock.request_frame()`; `Ok(true)`.
10. **Frame tick** (the Animator's `OnFrame` + `StopListeningWhenIdle` + `OnAnimatorChanged`): the handler converts the tick with `to_app_tick`, calls `animator.on_frame(store, &tick)`, unsubscribes when `!animator.is_animating()`, and then, when `effect.changed`: `if opacity <= 0 { release() }`, `invalidate()`. The first tick after `start` is t0 (opacity 1.0); a tick that finishes the fade writes `0.0`, releases the image and the clock subscriber count returns to 0 (test `FadeEnd_...`). `invalidate` runs once per frame in which the opacity changed, never otherwise.
11. **`cancel`** = `animator.cancel`, unsubscribe when idle, `release()` (outgoing = None, opacity = 0). **`release`** never touches the animator.
12. **`draw`** (C# 100-133): `outgoing` None -> `Ok(false)`. Disposed buffer, or (`opacity <= 0` and the animator idle) -> `release()`, `Ok(false)`. `opacity <= 0` and still animating -> `Ok(false)` (do not release: the fade's last frame may still set a value). Else `push_clip(viewport)`, `try_draw(cache, context, &outgoing, frame, interpolation, opacity, 1)`, `pop_clip()` (always, then the error wins). `Ok(true)` when the image was drawn. `Ok(false)` from `try_draw` (disposed buffer; also a NaN/empty frame, impossible after `start`'s guards) -> `cancel()`, `Ok(false)`.
13. **`dispose`**: idempotent; `disposed = true`, unsubscribe, `animator.dispose()`, `release()`. `Drop` calls it. After dispose `start` is `Err(Disposed)`; `draw`, `cancel`, `opacity` still work and report "nothing".
14. **`new`**: `ticks_per_second <= 0` -> `qpc_frequency()` (the unit of `HostFrameTick::timestamp`, D-W8B4V-14). `Animator::new(tps)` fails only for `tps <= 0`, which `qpc_frequency()` (1e9 fallback) excludes; the porter handles the `Err` arm without `unwrap`/`expect` (fall back to `1_000_000_000`).
15. **Duration unit**: the animator's `duration_ticks` are .NET `TimeSpan` ticks (100 ns), NOT the clock's `ticks_per_second`; the animator divides by `1e7` itself. Do not pass QPC ticks.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (INV-1): the cache key is `PixelBuffer::id()`; the crossfade must hold the SAME `Arc<PixelBuffer>` it drew (not a copy), and `outgoing_buffer_id()` must be the id of that buffer so `retain` keeps its bitmap for the whole fade.
- T2 (clip balance): `push_clip`/`pop_clip` are balanced on every path including `Err`; `D2dRenderSurface::end_draw_and_present` reports an unbalanced frame AFTER presenting (12d), so a leak is visible only there. Test with a recording context that counts depth.
- T3 (re-entrancy): `invalidate` (the window's `invalidate`) and `clock.subscribe/unsubscribe/request_frame` may run while a clock tick is being delivered (the host clock supports unsubscribing from inside a handler). Never hold a `RefCell` borrow of `animator`/`outgoing` across those calls: read what is needed, drop the borrow, then call out.
- T4 (restart, not queue): `start` while fading cancels the old tween BEFORE `fade_to`; otherwise the animator's "same target, tween running" rule (`fade_to` is a no-op for an equal target) would keep the OLD fade running with the new image.
- T5 (`f32` opacity): the animator writes `f32`; compare with a tolerance of 1e-4 in tests (the C# asserts `Assert.Equal(expected, actual, 4)`).
- T6 (.NET `Math.Max/Min` NaN): see 1.
- T7 (colour constants): `color_from_rgb` divides each `u8` by 255 in `f32`; `canvas()` must equal `viewport::render_geometry::dark_canvas()`; `selected_color()` is `color_from_rgb(0x32, 0xCD, 0x32, 0xFF)`, `unselected_color()` `color_from_rgb(0x55, 0x55, 0x55, 0xFF)`.
- T8 (frame types): `Animator::on_frame` takes the `pr_app` `FrameTick`; the clock delivers the host twin. `to_app_tick` copies `timestamp`, `rendering_time_ms`, `timing` (D-W8B3H-1). When the layering follow-up replaces the host twins by imports, `to_app_tick` becomes the identity and is deleted.
