## Semantics notes
1. **Routing key.** `crate::formats::is_raw_extension(Some(path))` (W5-01a): the 8 extensions `.cr2 .cr3 .nef .arw .dng .raf .orf .rw2`, `OrdinalIgnoreCase` on `get_extension` (stops at `\` or `/`, NOT `:`). So `C:\folder.cr2\photo.jpg`,
   `a.cr2.`, `a.cr2 ` (trailing space), `a.cr2:stream`, `dir.cr2/`, `.nrw`, `.pef`, `.\u212ar2` (Kelvin sign; no RAW extension contains a k, so it is non-RAW under any folding, a guard only) are NOT RAW and go to `standard`; `.cr2` (a file named just that), `C:file.cr2` and `a:b.cr2` ARE RAW. Never re-implement the check, never
   lower-case the path. A blank path is not RAW.
2. **Order of checks in `route`** (observable through `enabled_calls`, golden `setting-not-read-for-non-raw`, `setting-read-once-per-raw-call`): `is_raw_extension` false -> `standard` WITHOUT calling `is_raw_enabled`; else `is_raw_enabled()` EXACTLY ONCE per call
   (one `decode` or one `read_info` = one read; never cached between calls: golden `toggle-*`); false -> `Err(raw_disabled(path))` with NEITHER decoder touched; true -> `raw`. No other branch: the router never retries, never falls back to `standard` for a RAW path
   (a container error from `raw` is returned as is: INV-12 spirit, "Container errors never fall back to WPF").
3. **The refusal kind.** `DecodeError::not_supported_localized(english, text)` (variant `NotSupported`, NOT `MissingCodec`: the C# type is plain `NotSupportedException`). The router sits in front of the whole RAW stack, so the refusal never reaches `FallbackImageDecoder`;
   the generic fallback whitelist would accept `NotSupported`, which is exactly why the router must be the OUTERMOST wrapper for RAW paths (composition detail for W8, note it in the PARITY row).
4. **English message (log/type control flow), exact:** `RAW support is disabled; cannot decode '{fileName}'.` where `{fileName}` = `pr_core::text::dotnet_path::get_file_name(path)` (`C:\raw dir\photo.NEF` and `C:/x/photo.NEF` -> `photo.NEF`, `\\server\share\a.arw` -> `a.arw`).
   The UI sentence is the `UserText` closure `move || texts.raw_disabled(&name)` evaluated AT DISPLAY TIME (a language switch applies to an error the status bar already holds; never pre-render). `describe()` therefore equals the `en.json` template
   `image.error.rawDisabled` ("RAW support is turned off in Settings, so {fileName} cannot be shown.") with the name substituted, and does not contain the English log text. The two messages differ on purpose: keep both.
5. **`read_info` argument check.** C# `ArgumentException.ThrowIfNullOrWhiteSpace(path)` runs BEFORE routing, so `""`, `" "`, `"\t"`, `"\r\n"`, U+00A0, U+3000, U+0085, U+2028 give `DecodeError::InvalidArgument` even with RAW support off, and the setting is not read
   (golden `blank-*`: `throws: ArgumentException`, `enabled_calls` 0). Whitespace = `chars().all(char::is_whitespace)` (same set as W5-01a; the golden pins it). `decode` has NO such check: a blank path goes to `standard` (it is not RAW) and the
   request is forwarded unchanged. The C# `null` path cannot be expressed (`&str`/`PathBuf`), no Rust twin.
6. **Forwarding.** `decode` passes the SAME `&DecodeRequest` (no clone, no field changed: `apply_orientation`, `bytes`, `priority`, `source_orientation` ride through) to the chosen decoder and returns its `Result` untouched (`Arc<dyn DecodedImageView>` or the inner error).
   `read_info` forwards the same `&str`. `request.path.to_string_lossy()` is the routing key (W4-01b `DecodeRequest.path: PathBuf`).
7. **`as_cancellable()` stays `None`.** The C# class implements only `IImageDecoder`, so `decoder is ICancellableImageDecoder` is false for a router-wrapped decoder and PreviewImageService never takes the token overload there (a native LibRaw decode behind the router
   cannot be cancelled mid-flight in C#). Parity wins: keep the trait default; see Open questions 2.
8. **Thread-safety.** `Send + Sync` (all fields are); no lock, no state of its own, nothing to dispose. The setting closure and the decoders are called concurrently from decode and preload threads.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- 1 OrdinalIgnoreCase (inside `is_raw_extension`, via `eq_ignore_case`); 2 culture: none, do not add `to_lowercase`; 7 path spellings (UNC, `\\?\`, drive-relative, dot in directory, alternate stream, trailing dot/space/NBSP are in the golden);
  8 blank path vs empty path vs null: `read_info` rejects, `decode` forwards; 9 two refusal kinds stay distinct (`NotSupported` here, `MissingCodec` in W4-12c).
- INV ids: INV-12 (decoder wrapping/fallback: the router is a non-cancellable wrapper that never falls back; refusal is `NotSupported`). INV-8 (single-pass reads): the router opens no file, reads no bytes.
- Hardening: total over any `&str` (embedded NUL, 4 KiB names, lone dots); no slicing at a computed index here, no allocation proportional to the input except the file-name copy in the refusal.

## Open questions
1. **`texts` constructor parameter.** C# reads `Tr.ImageErrorRawDisabled` statically; Rust has no static localizer in the pure crates, so the stub adds `Arc<dyn RawRoutingTexts>` (same as `WebpHeicTexts`, W4-12c, D13). Recommended: keep. Alternative: take a ready `Fn(&str) -> String`
   (`UserText` factory); the trait is clearer for the W8 `Localizer` adapter and for tests. The real implementation (`Localizer` backed) is the App wave; this unit uses a test double.
2. **Cancellation parity.** The C# router is not an `ICancellableImageDecoder`, so a RAW decode through the router is never natively cancelled by `PreviewImageService`. Recommended: keep parity (`None`) now; a deliberate improvement (forward to `raw.as_cancellable()` and to `standard.as_cancellable()`)
   is a behaviour change to record in `docs/PROPOSED-DECISIONS.md`, not a port.
3. **Where the router lives.** `pr-imaging-raw` (as the C# namespace `Imaging.Raw`). It depends on `pr-imaging` for the traits (already a dependency). W5-12b composes it over `RawDecoder` in the same crate; the factory closure in W4-12a stays in `pr-imaging` and receives the router from the composition root (W8).
4. **Real-corpus twin.** Skips by early return when the corpus is absent (like W5-03); it adds no coverage beyond the pure rows, only the real file names. If the lead prefers, drop it and keep the golden alone.
