## Semantics notes (C# is the spec)
1. **Everything is `&self`** (interior mutability, D-W8-12a-3): the cache is shared by the compositor, the prefetch jobs and the device-recreated handler. State is ONE `RefCell<State>`; the
   backend call sites (`upload`, `upload_rows`, `release`) run while it is borrowed, which is why `GpuImageBackend` must never call back into the cache (trait doc). The `UploadCompleted`
   handlers and the scheduler call are made AFTER the borrow is released (a handler may call `get_or_upload`: the C# presenter does, to switch to the finished image).
2. **Own LRU, not `BoundedLruCache`.** `pr_core::caching::lru::BoundedLruCache` is thread-safe, evicts the least recent entries when an insert exceeds the capacity and has no notion of entries
   that must not be evicted; the C# cache lets the current image and the retained ids exceed the budget. Use `HashMap<i64, Entry>` + `BTreeMap<u64, i64>` (stamp -> id; smallest stamp = oldest),
   the same technique as `lru.rs`. `touch` assigns a new, larger stamp. (D-W8B3S-3.)
3. **`default_budget_bytes(w, h)`** = `6 * max(1920*1080*4, w as i64 * h as i64 * 4)`, all `i64` (`6 * 8_294_400 = 49_766_400` for any surface up to Full HD; `88_473_600` at 2560x1440). The product
   `w*h*4` of a 16384x16384 surface is 1 073 741 824 and still fits `i32`, but `* 6` does not: do the whole formula in `i64`.
4. **`new`** validates before it builds anything: negative budget -> `NegativeBudget { value }`, `stripe_bytes < 4` -> `StripeBytesTooSmall { value }` (`ArgumentOutOfRangeException.ThrowIfNegative/ThrowIfLessThan`).
   The C# constructor then subscribes `OnDeviceRecreated` to the backend; the Rust one builds the `Rc` with `Rc::new_cyclic`, then subscribes a handler holding a `Weak<Self>` (a handler that
   fires after the cache is gone does nothing). `dispose` (and `Drop`) unsubscribes the stored id.
5. **`get_or_upload(pixels)`**, in this order: cache disposed -> `Err(Disposed { object: CACHE_OBJECT_NAME })`; `pixels.is_disposed()` -> `Err(Disposed { object: PIXEL_BUFFER_OBJECT_NAME })`
   (C# checks the cache first). Then:
   - id cached: if the image is not complete, `upload_rows(entry, pixels, image.pixel_height())` using the buffer passed HERE (not `pending_source`); then `touch`; `protected_id = Some(id)`; return the SAME `Rc`.
     A backend error in `upload_rows` propagates BEFORE the touch and the protected assignment (state unchanged except rows already written).
   - id not cached: `backend.upload(pixels, true)?`; `image.set_uploaded_rows(image.pixel_height())`; `protected_id = Some(id)`; `add(image)`. A failing `upload` leaves `protected_id` as it was.
6. **`add(image)`**: new `Entry` (new `serial`), newest in LRU order, `entries.insert`, `total += gpu_bytes` (use `saturating_add`; C# unchecked `long`), then `evict_over_budget(Some(id))`.
7. **`evict_over_budget(also_keep)`** walks the entries from the oldest and, while `total > budget`, removes each entry whose id is not `protected_id`, not `also_keep` and not in `retained`. The
   `total > budget` test is evaluated before EACH entry (stop as soon as the cache fits). Entries that are skipped stay. Result: the cache may stay over budget when everything left is protected
   (`GetOrUpload_ImageLargerThanBudget_IsKeptAsCurrent`). Implement over a snapshot of ids in ascending stamp order (removal only removes the current entry).
8. **`prefetch(pixels: &Arc<PixelBuffer>)`**: cache disposed -> `Err(Disposed)`; `pixels.is_disposed()` -> `Ok(())` (no-op, NOT an error; asymmetric with `get_or_upload`); cached id -> `touch` only (does not
   set `protected_id`, does not schedule); otherwise `backend.upload(&pixels, false)?`, `add(image)` (which protects ONLY this id during its eviction pass, so an older prefetched image or an older non-current
   image can be evicted by a new prefetch), `pending_source = Some(Arc::clone(pixels))`, `schedule_stripe`. `protected_id` is NOT changed.
9. **`schedule_stripe(entry)`** calls `scheduler.schedule_stripe(StripeToken { pixel_buffer_id, serial })`; it never runs the job inline (D-W8B3S-2). The scheduler implementation posts at
   `UiPriority::Background`; that priority is a property of the host adapter (W8-13d), not testable here.
10. **`run_stripe(token)`** (C# `RunStripe`), in this order, each early exit returns `Ok(())`: cache disposed; no entry for `token.pixel_buffer_id`, or `entry.serial != token.serial` (STALE JOB TRAP, see T1);
    `image.is_released()`; `pending_source` is `None`; `image.is_complete()`. Then "source gone": `source.is_disposed()` or `Arc::strong_count(&source) == 1` (only the cache holds it any more) -> `remove(entry)` and `Ok`
    (no `UploadCompleted`). Otherwise `rows_per_stripe = max(1, stripe_bytes / source.stride())` (integer division; `stride` is `width * 4`), `upload_rows(entry, source, uploaded_rows + rows_per_stripe)`
    (use `i64`/`saturating_add`: `uploaded_rows` is up to the image height), then: not complete -> `schedule_stripe` again; complete -> raise `UploadCompleted(id)` (once, after the LAST stripe, never on removal).
    A backend `Err` is returned to the scheduler (it logs it) with the entry and `uploaded_rows` untouched and NO reschedule (C# lets the exception escape the dispatcher job).
11. **`upload_rows(entry, pixels, end_row)`**: `start = image.uploaded_rows()`, `end = min(end_row, image.pixel_height())`; if `end > start`: `backend.upload_rows(image, pixels, start, end)?` then
    `image.set_uploaded_rows(end)`; afterwards, if the image is complete, `entry.pending_source = None` (drops the `Arc`). The C# order is "write then set"; on a backend error `uploaded_rows` is not advanced.
12. **Source ownership (D-W8-12a-4, Different row).** C# `PixelBuffer.IsDisposed` midway means "the owner gave the image up": the partial image is dropped. In Rust a shared `Arc<PixelBuffer>` cannot be disposed while
    the cache holds a clone, so the observable twin is `Arc::strong_count == 1` ("only the cache still holds it"). Callers keep their `Arc` until `is_fully_uploaded` or until they no longer want the image (the
    presenter's preview cache normally does). The check is a snapshot (another thread may drop its clone a moment later), which is fine: the next stripe sees it. `is_disposed()` is also checked (an owner that called
    `PixelBuffer::dispose()` before wrapping it); that path is defensive.
13. **`remove(entry)`**: out of the order map and `entries`, `total -= gpu_bytes` (`saturating_sub`), `pending_source = None`, `release_image`. **`release_image(image)`**: no-op if `is_released()`; else
    `set_released(true)` THEN `backend.release(&image)` (flag first, like C#).
14. **`clear()`** releases every entry (oldest first; C# iterates a dictionary, no test depends on the order), clears the maps, `total = 0`, `protected_id = None`. **`retained` is NOT cleared** (T6).
    **`retain(ids)`** replaces the set (no union), then `evict_over_budget(None)`; cache disposed -> `Err(Disposed)`.
15. **`set_budget_bytes(v)`**: `v < 0` -> `Err(NegativeBudget { value: v })` and the budget is NOT changed (C# throws before assigning); else assign, `evict_over_budget(None)`. It has NO disposed check (after
    dispose the cache is empty, so it evicts nothing). `total_gpu_bytes`, `count`, `contains` also work after dispose.
16. **`dispose()`**: idempotent; set `disposed`, unsubscribe from the backend, `clear()`. Calls after dispose: `get_or_upload`, `prefetch`, `retain` -> `Err(Disposed)`; `run_stripe` inert.
17. **`UploadCompleted`** is a handler list (`Rc<dyn Fn(i64)>`, `Fn` not `FnMut`) in subscription order; the list is cloned before the call so a handler may (un)subscribe or call the cache. Unknown id = no-op.
18. **`on_device_recreated()`** = `clear()` (the backend raises it inside the surface's `resize`/`end_draw_and_present`; the cache is idle at that moment because both are UI-thread calls).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (stale job): C# captures the `Entry` object in the posted closure, so a job queued before `Clear`/eviction stays inert even if the same `PixelBuffer` id is cached again. Keying the job by id alone resumes the NEW
  entry's upload one stripe early (an extra `UploadCompleted` timing, wrong row counts). The `serial` in `StripeToken` is the fix; test `stale_stripe_after_clear_is_inert_for_a_recached_buffer`.
- T2 (eviction exceptions): three kinds of entry are skipped (`protected_id`, `also_keep`, `retained`); `prefetch` does not become `protected_id`. A porter who "simplifies" to LRU-only breaks `Prefetch_DoesNotEvictCurrentImage`
  and `Retain_Pins...`. Mutation target.
- T3 (touch): `get_or_upload` of a cached id and `prefetch` of a cached id both touch; the touch happens AFTER a successful completion upload (so a failed completion does not refresh the entry).
- T4 (whole-image bytes): `total` counts `gpu_bytes` of a half-uploaded image in full from the moment of `prefetch` (the budget is a reservation).
- T5 (`i64`): budget, totals, `default_budget_bytes` and `gpu_bytes` are `i64`; row counts are `i32`; `stripe_bytes / stride` is `i32` division with `max(1, ..)`; `uploaded_rows + rows_per_stripe` must not overflow.
- T6 (`retained` survives `clear`): C# `Clear` leaves `_retained` alone; only `Retain` replaces it. A device loss must not forget the pinned ids.
- T7 (error order): disposed cache before disposed buffer; `prefetch` of a disposed buffer is `Ok`, `get_or_upload` of one is `Err`.
- T8 (budget setter): negative leaves the budget unchanged AND evicts nothing; a valid value evicts immediately.
- T9 (no borrow across callbacks): never hold the `RefCell` borrow when calling an `UploadCompleted` handler or the scheduler; a handler that calls `get_or_upload` would panic otherwise.
- T10 (`pending_source` lifetime): set to `None` the moment the image is complete (not at the next stripe), or the cache keeps a 24 MP buffer alive for nothing.

## Safety rules
No `unsafe` in this unit and none may be added. Thread affinity: UI thread only, enforced by the types (`Rc`, `RefCell`, no `Send`). `Arc<PixelBuffer>` is the only thing shared with other threads (the buffer is read-only).
The scheduler seam is the one place a thread boundary exists: its implementation posts a `Send` job carrying only a `StripeToken` (plain data).

## Error mapping
`CacheError` is `Copy`. After the layering PR (done by the 12g adapter, not here): `Disposed { object }` -> `RenderError::Disposed { object }`; `NegativeBudget { value }` -> `RenderError::NegativeBudget { value }`;
`StripeBytesTooSmall` is a construction error of the composition root (not part of the `GpuImageCache` trait); `Backend(GfxError { hresult, operation })` -> `RenderError::Device { hresult, operation }`
(field for field, D-W8B3G-2).

## Open questions
1. **Weak vs strong source buffer in `prefetch`.** Recommended (taken, D-W8-12a-4): the cache holds an `Arc` clone until the last stripe and treats `strong_count == 1` as "owner gone". Alternative: `Weak<PixelBuffer>`; rejected because the cache would then
   never be able to finish a prefetch whose owner dropped the buffer one tick early, and `upgrade` races are the same snapshot problem.
2. **Where is `UploadCompleted` consumed?** C# `WP-21` only (the presenter switches to a finished image). Recommended: keep the multi-handler list as written; W8-16c may need only one handler and can ignore the rest.
3. **`CacheError` vs reusing `RenderError` directly.** Recommended (taken): local `CacheError` until the layering PR, then `impl From<CacheError> for RenderError` in 12g. Alternative: wait for the layering PR before porting 12f; rejected, it would serialize the batch.
4. **Reentrancy guard.** The trait doc forbids backend callbacks; recommended: no runtime guard (a nested `borrow_mut` panic is a programming error and would show in the first native test). Alternative: `try_borrow_mut` and `Err`; rejected, noise.
5. **Layering PR timing.** The `CachedImage` impl for `TiledGpuImage<B>` and the adapter (12g) need it. 12f itself does not (its tests implement `CachedImage` on a local fake).
