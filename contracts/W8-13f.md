## Semantics (C# is the spec)
### `process_message` (C# 251-314), in this order
1. **Lifecycle** (13e): `WM_NCCREATE` -> `on_nc_create`; `WM_CREATE` -> `on_create`; `WM_DESTROY` -> `on_destroy`, return 0; `WM_NCDESTROY` -> `def_window_proc`. These return at once: the handlers never see them.
2. **Own state first** (C# 262-278): `WM_SIZE` -> `update_client_size(low_word(lparam), high_word(lparam))`; `WM_DPICHANGED` -> `apply_dpi_change(low_word(wparam as isize), suggested)` then `icons::apply(hwnd, dpi)` (taskbar and title bar icons at the new dpi); `WM_ACTIVATE` -> `update_active(low_word(wparam as isize) != WA_INACTIVE)`. Then fall through to 3 (no return).
3. **Handler chain** (C# 281-287): `for handler in handlers.borrow().clone()` (clone the `Vec<Rc<..>>`, release the borrow, then iterate): `Some(result)` from `try_handle(&WindowMessage { hwnd, msg, wparam, lparam })` returns `result` immediately. Registration order; `insert_message_handler_first` puts one at index 0.
4. **Defaults** (C# 289-315): `WM_SIZE` -> `invalidate()`, 0. `WM_DPICHANGED` -> 0. `WM_GETMINMAXINFO` -> `apply_min_track_size(info)`, 0, where `info` is `Some(&mut MinMaxInfo)` built from `lparam` if `lparam != 0` (and aligned) else `None`. `WM_CLOSE` -> `raise_closing()`, 0. `WM_SETCURSOR` with `low_word(lparam) == HTCLIENT` -> `set_cursor(cursor_handle(cursor))`, 1 (a `WM_SETCURSOR` for another hit-test falls to `def_window_proc`; C# `case ... when`).
   `WM_ERASEBKGND` -> 1. `WM_PAINT` -> `validate_whole_client(hwnd)`, `invalidate()`, 0. Everything else -> `def_window_proc(..)`.
### State updates
5. `update_client_size(w, h)`: store both, then `raise_client_size_changed_if_needed()`. The values are `low_word`/`high_word` of `lParam` (unsigned 16 bit each; a window larger than 65535 px wraps exactly like C#).
6. `raise_client_size_changed_if_needed`: `size = client_size_dip()`; equal (record equality, NaN-safe) to `last_raised_client_size` -> return; else store and raise `ClientSizeChanged`. Used by `WM_SIZE` and by the DPI path.
7. `apply_dpi_change(new_dpi, suggested)` (C# 357-375; DOC ORDER IS THE CONTRACT): `new_dpi > 0` -> `dpi = new_dpi as u32` (0 or negative keeps the old dpi); `suggested = Some(rect)` -> `set_window_pos(hwnd, 0, rect.left, rect.top, rect_width(&rect), rect_height(&rect), SWP_NOZORDER | SWP_NOACTIVATE)` (this provokes a `WM_SIZE` that raises `ClientSizeChanged` when the pixel size changed);
   then `raise_client_size_changed_if_needed()` (same pixel size but different dpi: the DIP size changed, so it still raises, test `SamePixelSize`); then raise `DpiChanged` (the event observer sees the new `dpi_scale` and the already-moved window rect: test `AppliesTheSuggestedRectBeforeRaisingTheEvent`); then `invalidate()`.
8. `update_active(active)`: unchanged -> return; store; raise `Activated` or `Deactivated`. `WA_ACTIVE` (1) and `WA_CLICKACTIVE` (2) both count as active, `WA_INACTIVE` (0) inactive; the three-message test pins "once per change".
9. `apply_min_track_size(info)`: `None` -> nothing. `min_track_size(min_width_dip, min_height_dip, scale, grow)`: `rect = (0, 0, to_pixels(min_w, scale), to_pixels(min_h, scale))`; `grow(rect)` is `adjust_window_rect_ex_for_dpi(&mut rect, WS_OVERLAPPEDWINDOW, false, 0, dpi)` (on `Err` -> `None`, `ptMinTrackSize` untouched); else `(rect_width, rect_height)` of the grown rect, written to `ptMinTrackSize.x/.y`.
10. `raise_closing` (`WM_CLOSE`): `args = CancelEventArgs::default()`; run EVERY `Closing` handler (C# multicast: all handlers run; a handler cannot stop the others; any may set `cancel`); `!args.cancel` -> `destroy_window(hwnd)` (error ignored). A panicking handler propagates through the trampoline guard (resumed by `close`/the loop; the window is NOT destroyed).
11. `low_word(v)` = `(v as u64 & 0xFFFF) as i32`; `high_word(v)` = `((v as u64 >> 16) & 0xFFFF) as i32` (logical shift of the 64-bit pattern). `WM_SIZE`'s `lParam` and `WM_DPICHANGED`'s `wParam` use them.
### The raw-pointer messages (the only `unsafe` of this unit)
12. `WM_DPICHANGED`: `lparam` is a `*const RECT` valid for the call. `suggested = if lparam != 0 && lparam % align_of::<RECT>() == 0 { Some(*(lparam as *const Rect)) } else { None }` (copy out at once; C# `Rect*` null-check, plus the alignment guard because any thread of the process can `PostMessage`/`SendMessage` a crafted value).
    `WM_GETMINMAXINFO`: `lparam` is a `*mut MINMAXINFO`, same guard, `Some(&mut *ptr)` only for the duration of `apply_min_track_size`. A non-system sender with a bad pointer is outside the trust boundary (same process); the guards turn the common mistakes (0, misaligned) into "ignore".

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (DPI change handling): the suggested rect is applied BEFORE `DpiChanged`; `dpi` is stored BEFORE `SetWindowPos` (the `WM_SIZE` it provokes computes DIPs with the new scale); `ClientSizeChanged` may fire twice for one DPI change in C# only if the DIP size differs both times (the equality check de-duplicates): do not add an unconditional raise.
- T2 (own state before handlers): a handler that reads `client_size_dip()` during `WM_SIZE` sees the NEW size (test `Handlers_SeeResizeAfterTheWindowUpdatedItsClientSize`); `is_active` is updated before handlers see `WM_ACTIVATE`.
- T3 (re-entrancy): handlers and events run with no `RefCell` borrow held; a handler may `add_message_handler` (not seen until the next message), `set_title`, `close`, `invalidate`. `process_message` may be entered again from `SetWindowPos` inside `apply_dpi_change` (the `WM_SIZE`/`WM_WINDOWPOSCHANGED` it provokes): state must be consistent before that call (the dpi store comes first).
- T4 (panic guard): a panicking handler returns 0 to the OS and leaves the chain; no default processing follows (C# comment 79). The Rust test checks that `WM_CLOSE` with a panicking `Closing` handler does not destroy the window.
- T5 (WM_QUIT): not produced here.
- T6: `WM_SETCURSOR` returns `1` (TRUE: "processed") only for `HTCLIENT`; returning 1 for every hit-test would freeze the resize cursors on the frame.
- T7: `WM_ERASEBKGND` returns 1, `WM_PAINT` validates then invalidates (the renderer paints on the frame clock, not in `WM_PAINT`); a `WM_PAINT` that is not validated is delivered forever.
- T8: `WA_CLICKACTIVE` (2) is active; compare `!= WA_INACTIVE`, not `== 1`.
- T9: `min_track_size` uses the dpi of the window NOW (after a DPI change), and the minimum in DIP: the C# test sends `WM_DPICHANGED` with 120 and expects `(400 x 1.25, 300 x 1.25)` grown by the frame at 120 dpi.
- T10: `LowWord(wParam)` of `WM_DPICHANGED` is the X dpi; the Y dpi is ignored (equal for square pixels).

## Safety rules (`// SAFETY:` per block)
Two blocks in `process_message`: the `*const Rect` copy for `WM_DPICHANGED` and the `&mut MinMaxInfo` for `WM_GETMINMAXINFO` (pointer non-null, aligned, valid for the duration of the message per the Win32 contract, not stored beyond it). Everything else uses safe wrappers.

## Error mapping
No fallible API in this unit: the C# `ProcessMessage` had no `throw` of its own. A handler or event exception is a panic (T4, D-W8B3H-4). `Win32Exception` cases of the window (`CreateWindowEx`, `SetWindowText`) are 13e's.

## Open questions (recommended default in bold)
1. **Merge 13e and 13f into one PR at scheduling time?** The contract keeps two units (plan P-18); the signatures and file split are identical either way. Recommended: two PRs if two porters are free, one PR otherwise.
2. `DpiChanged` ordering when `SetWindowPos` re-enters `process_message`: **keep the C# order** (store dpi, set pos, raise size, raise dpi, invalidate).
3. Misaligned/zero pointer guard for `WM_DPICHANGED`/`WM_GETMINMAXINFO`: **yes** (cheap, no behaviour change for the OS); alternative: trust `lparam` blindly like C#.
4. `WM_SETCURSOR` when the pointer is over the client area of a CHILD window: not applicable (no children in the shell window; the overlay and scrollbars are drawn, W8-15/W8-16).
5. `WM_DPICHANGED_BEFOREPARENT`/`AFTERPARENT`, `WM_GETDPISCALEDSIZE`: **not handled** (C# does not; the constants exist in `win32::messages` for later).
