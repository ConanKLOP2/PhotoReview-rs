## Semantics notes

### Parsing (`LocTemplate::try_parse`)
Scan the text left to right; `current` is the literal being built, `literals`/`names` are the output lists.
- `{`: if the NEXT char is `{` -> append one `{` to `current`, skip both. Otherwise find the first `}` after this `{` (`text.find('}')` from the next position). No `}` found, or the text between them is not a valid name -> `None`. Valid: push `current` to `literals`, clear it, push the name to `names`, continue after the `}`.
- `}`: if the next char is `}` -> append one `}`, skip both. Otherwise (a single `}`) -> `None`.
- any other char -> append to `current`.
- At the end push `current` to `literals` (so `literals.len() == names.len() + 1`). `text` is stored unchanged.
- Valid name (`is_valid_placeholder_name`): non-empty, first char ASCII letter (`A-Za-z`), all chars ASCII letters or digits. So `{1x}`, `{}`, `{with space}`, `{dot.name}`, `{ñ}`, `{a_b}`, `{ x}` are invalid; `{a1}`, `{ABC}` valid. Do NOT trim.
- The first `}` rule means `{a{b}` is invalid (name `a{b`), `{{{a}}}` is valid (`{` literal, placeholder `a`, `}` literal), `{{}}` valid (literal `{}`), `{x}}` INVALID (placeholder, then a lone `}`), `{{x}` INVALID (literal `{`, `x`, lone `}`), `{{x}}` valid (literal `{x}`).
- Both failure causes (unbalanced brace, bad name) give plain `None`; callers (Localizer, later) write generic warnings. No error detail is added.
- Work on bytes or `char_indices`: braces are ASCII so slicing at them is safe in UTF-8. Surrogate pairs/RTL text are copied through unchanged.
- C# throws `ArgumentNullException` for a null text; a Rust `&str` cannot be null, nothing to port.

### Render
For `i` in `0..names.len()`: append `literals[i]`; then look for the FIRST arg whose `name == names[i]` (exact, case-sensitive, ordinal; `Name` != `name`). If found: `format_value` gives `Some(s)` -> append `s`; `None` (formatter failed, R21) -> append `{name}` back. A failed first match does NOT fall through to a later arg with the same name. If no arg matches -> append `{name}`. After the loop append the last literal. A template with no placeholders returns `literals[0]` (args ignored). A repeated placeholder is formatted at every occurrence. Args that match no placeholder are ignored. Never panic: a panic inside `Lazy` is caught (`std::panic::catch_unwind(AssertUnwindSafe(..))`) and treated like `None`.
Nested render (a `Lazy` closure rendering another template) must work: render with a fresh `String` each call, no shared/thread-local buffer (the C# one was a perf trick, not behaviour).

### Value formatting (`format_value`), C# `FormatValue`
`Null` -> `""`; `Str` verbatim; `Int`/`UInt` -> decimal digits, preceded by `culture.negative_sign` when negative (`i64::MIN` works: use `unsigned_abs`); `F64`/`F32` -> below; `Bool` -> `"True"`/`"False"` (capitalised, invariant); `Char` -> the char; `Lazy(f)` -> `f(culture)` under `catch_unwind` (panic = `None`).
C# mapping of what callers pass: `int/long/short/byte/...` -> `Int`/`UInt`; `double` -> `F64`; `float` -> `F32`; `string` -> `Str`; `null` -> `Null`; any other `IFormattable`/object (dates, enums, `decimal`, custom classes) -> the caller formats it first (`Str`) or uses `Lazy`. Dates are NOT supported by `LocValue` (C# `DateTime.ToString(null, culture)` is the culture's "G" pattern; the Rust app formats dates before passing them).
Digits are always ASCII (`DigitSubstitution` is not applied by .NET `ToString` in any of the probed cultures: ar-SA, fa-IR, ps-AF all give ASCII digits).

### `format_f64` / `format_f32` (.NET Core 3.0+ default `ToString()`)
1. NaN -> `culture.nan_symbol`. +Inf -> `positive_infinity_symbol`; -Inf -> `negative_infinity_symbol`.
2. Otherwise take the SHORTEST digit string that round-trips (use Rust `format!("{:e}", v.abs())` -> `d.ddddde<exp>`; for f32 format the `f32` itself, never widen to f64) giving digits `D` (no trailing zeros, at least 1 digit) and decimal exponent `e` (the value is `D[0].D[1..] x 10^e`). Zero (and -0.0): digits `"0"`, `e = 0`.
3. Sign: `negative_sign` is written when the sign bit is set, INCLUDING `-0.0` (renders `-0`).
4. Choose notation. Let `scale = e + 1`.
   - f64: scientific when `e >= 17` or `e <= -5`; f32: scientific when `e >= 9` or `e <= -5`. Otherwise fixed. (Examples f64: `1e16` -> `10000000000000000`, `1e17` -> `1E+17`, `0.0001` -> `0.0001`, `0.00001` -> `1E-05`; f32: `1e8f` -> `100000000`, `1e9f` -> `1E+09`, `12345678f` -> `12345678`, `123456790f` -> `123456790`.)
   - Fixed: if `scale <= 0` -> `"0"` + decimal separator + `(-scale)` zeros + `D`; else if `D.len() <= scale` -> `D` + zeros up to `scale` digits (no separator); else `D[..scale]` + separator + `D[scale..]`.
   - Scientific: `D[0]`, then (if `D.len() > 1`) separator + `D[1..]`, then `E`, then `positive_sign` for `e >= 0` or `negative_sign` for `e < 0`, then `|e|` zero-padded to AT LEAST 2 digits (`E+17`, `E-05`, `E+308`).
5. The decimal separator and signs come from the culture and may be multi-char strings; never assume one char.
Golden `loc-render` pins ~60 values x 14 cultures. Do not use `f64::to_string()` / `{}` for the digits: Rust never switches to scientific notation.

### transform_literals / append_literal
- `transform_literals(f)`: new literals = `f` applied to each existing literal in order (index 0 first, once each, including empty ones). New `text` = `esc(lit[0])` then for each name `i`: `{name_i}` + `esc(lit[i+1])`, where `esc` doubles braces (`{` -> `{{`, `}` -> `}}`, ordinal). Names unchanged. NOTE the new `text` is rebuilt, the old `text` is not reused.
- `append_literal(suffix)`: literals cloned, `suffix` appended (raw) to the LAST literal; new `text` = old `text` + `esc(suffix)`.
- Both results re-parse (`try_parse(result.text())`) to a template with the same names and the same rendering (the fuzz test asserts this).
- `literal(text)`: `text` stored as given (NOT escaped), one literal, no names. `Literal("{not a placeholder")` renders verbatim and `text()` returns it unchanged.

### UserFacingError (Rust shape chosen by the contract writer; C# attaches a `Func<string>` to `Exception.Data`)
- C# libraries throw `IOException`/`InvalidDataException`/`NotSupportedException`/`FileNotFoundException`/`EndOfStreamException` and callers filter on the TYPE. Rust code returns `io::Error`, and callers filter on `ErrorKind`. So the sentence rides inside the `io::Error` as a boxed [`LocalizedError`] payload: `io::Error::new(kind, LocalizedError{..})`. `kind()` is preserved.
- `localized_io(kind, english, text)`: `io::Error::new(kind, LocalizedError::new(english, Arc::new(text)))`.
- `localize_io(err, text)`: new `io::Error` with `kind = err.kind()` whose payload has `message = err.to_string()` and `source = Some(Box::new(err))`. (C# mutates the same exception; Rust cannot, so the original error is kept as the `source` and the message/kind are copied.) If `err` is ALREADY localized (`is_localized(&err)`), return it unchanged: the C# call sites guard with `!IsLocalized(ex)` before localizing, this makes the helper idempotent instead.
- `is_localized`/`describe` inspect ONLY the error itself: `err.downcast_ref::<LocalizedError>()`, or `err.downcast_ref::<io::Error>()` then `.get_ref()` then `.downcast_ref::<LocalizedError>()`. Do not walk `source()` (C# only reads `exception.Data`, not `InnerException`).
- `describe`: not localized -> `err.to_string()`, except an `io::Error` with `raw_os_error() == Some(code)`: strip the exact suffix `" (os error {code})"` if present (so the UI text equals .NET's `Exception.Message`). Localized -> run the closure inside `catch_unwind(AssertUnwindSafe(..))`; `Ok(s)` -> `s`; panic -> the same message fallback as the not-localized case, computed from the error (for a `LocalizedError` payload: its English `message`).
- The closure is called on every `describe` (not cached): the sentence follows the language current at display time.
- `describe` of a `LocalizedError` built by `localize_io` over an OS error uses `message` (`err.to_string()` of the original): apply the same `(os error N)` strip when the stored original has a raw OS error code (inspect `source`).
- `LocalizedError` must be `Send + Sync + 'static` so `io::Error::new` accepts it (`LocalizedText` is `Arc<dyn Fn() -> String + Send + Sync>`).

### TranslatorModes
- `accent(text)`: for every char `c`: if `c` is one of the 52 ASCII letters, replace it with the char at the same index in the table; otherwise keep `c`. Table (index = position in `abc...zABC...Z`), code points:
  - a-m: `00E1 0180 0107 0111 00E9 0192 011D 0125 00ED 0135 0137 013A 1E3F`
  - n-z: `0144 00F3 1E55 02A0 0155 015B 0165 00FA 1E7D 0175 1E8B 00FD 017A`
  - A-M: `00C1 0181 0106 0110 00C9 0191 011C 0124 00CD 0134 0136 0139 1E3E`
  - N-Z: `0143 00D3 1E54 024A 0154 015A 0164 00DA 1E7C 0174 1E8A 00DD 0179`
  Build the table with `char::from_u32(..)`; do not type the accented letters literally (a localization guard test in C# forbids non-ASCII letters in source; keep the same discipline). Output has exactly as many chars as the input.
- `pseudo_padding(n)`: `n == 0` -> `""`; else `" "` + `"~"` repeated `max(1, ceil(n as f64 * 0.35) as usize)`. KEEP the f64 expression `(n as f64 * 0.35).ceil()`: integer tricks like `(n*35+99)/100` differ where `n*0.35` is just above an integer in floating point (the golden covers n = 0..=300). `n` is the UTF-16 length of the ORIGINAL `t.text()` (so `{{` counts as 2, an astral char like U+1F600 counts as 2): `t.text().encode_utf16().count()`.
- `pseudo_template(t)`: `let mut first = true; t.transform_literals(|lit| { let a = accent(lit); if first { first = false; format!("[{a}") } else { a } }).append_literal(&(pseudo_padding(utf16_len(t.text())) + "]"))`. Consequences: an empty template becomes `[]`; a template starting with a placeholder (`{n} files`) becomes `[{n}` + accent(` files`) + padding + `]` (the first literal is `""`, so `[` comes first).
- `show_key_template(key)`: `LocTemplate::literal(&format!("[{key}]"))`.
- `PSEUDO_CODE` = `"qps-ploc"`.

Also: UTF-16 length for `pseudo_padding`, not `chars().count()`/`len()`.

## Open questions
1. Culture plumbing: the contract uses an explicit `&NumberCulture` argument to `render`. C# uses the ambient `CultureInfo.CurrentCulture` (Windows regional settings, NOT the UI language: `LocalizationService` only sets `CurrentUICulture`). The future Localizer WU (and `pr-platform-win`) must build a `NumberCulture` from the Windows user locale (`GetLocaleInfoEx`) and pass it in. If the lead prefers an ambient thread-local/global current culture, only `render`'s signature changes.
2. `UserFacingError` shape (payload inside `io::Error`) is a design choice; it assumes error-returning code uses `io::Error` for decoders/IO. If R-decisions later introduce a project error enum, `describe` gets one more match arm, nothing else changes.
3. `describe`'s `(os error N)` suffix strip is an addition to keep UI text equal to the .NET message; the suffix is Rust-specific, so this is not a C# behaviour difference visible to the user. Lead may veto.
4. `LocValue` has no `decimal`, date, or enum variants; C# tests using them (`decimal.MinValue`, `DateTime`) are skipped, see the test list.
5. The first-match-wins plus failed-formatter behaviour (no fall-through) comes straight from the C# loop (`found = true; break;` after a failed format); no test pins it, so the golden `loc-render` includes a case for it.
