## Semantics notes
1. **`is_raw_extension`.**
   - `None`, `Some("")` and any all-whitespace string give `false` (`string.IsNullOrWhiteSpace` = every char `char.IsWhiteSpace`;
     for the tested set U+0009..U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000..U+200A, U+2028, U+2029, U+202F, U+205F, U+3000 this
     equals Rust `char::is_whitespace`; use `trim().is_empty()` or `chars().all(char::is_whitespace)`).
   - The path is NOT trimmed otherwise: `" a.cr2"` is `true` (extension is `.cr2`), `"a.cr2 "` is `false` (extension `.cr2 `),
     `"a.cr2\u00a0"` is `false`.
   - Extension = `pr_core::catalog::types::get_extension(path)` (W1-07, already merged, golden `image-file-types`): scans from the end,
     stops at `\` or `/` (not `:`), a trailing dot gives `""`. `.cr2` alone (a dotfile) IS accepted (`Path.GetExtension(".cr2")` is
     `".cr2"`), `"dir.cr2/"` and `"C:\\dir.cr2\\"` are `false`, `"C:file.cr2"` and `"a:b.cr2"` are `true` (colon is not a separator).
   - Match = `pr_core::text::eq_ignore_case(ext, candidate)` against the 8 entries (C# `HashSet` with `OrdinalIgnoreCase`). NOT
     `to_lowercase`/`to_ascii_lowercase`: those differ from `OrdinalIgnoreCase` for non-ASCII (`İ`, `ı`, `ſ`, the Kelvin sign U+212A).
     No allocation needed.
   - Never panics for any input, including embedded NUL and lone-surrogate-free UTF-8 of any length (hardening, golden has NUL cases).
   - Duplicate of W1-07's RAW check (`ImageFileTypes.is_raw`)? C# has both (`Core/Catalog/ImageFileTypes` and `Imaging.Raw/RawFileTypes`), keep both;
     the golden `raw-formats` and `image-file-types` agree on the 8 extensions and a test may assert it (see Tests, item 6).
2. **Constants** are copied from C# exactly (see the stub); `128 << 20` = 134 217 728, `8 << 20` = 8 388 608, `4 << 20` = 4 194 304,
   `128 * 1024` = 131 072, `64 * 1024` = 65 536. They are `i32` like C# (`int`), no `usize`/`u64`, so `long`/`int` arithmetic in the
   readers ports 1:1 (cast to `i64` where C# widens).
3. **`initial_probe_length(source_length)`** = `(int)Math.Min(64L, sourceLength)`: take `min(64, source_length)` IN `i64`, then narrow with `as i32`.
   Narrowing first would turn `2^31` into a negative number (that is the bug the helper and its test exist for). Negative input: returned
   as is when it fits (`-1` gives `-1`), truncated like the unchecked C# cast otherwise (`i64::MIN` gives `0`, `-2147483649` gives
   `2147483647`). The golden pins all of these (17 `probe` cases). Callers pass a non-negative length; do not "fix" the negative cases.
4. **`is_io_failure`** = `matches!(error.cause, Some(RawHeaderCause::Io(_) | RawHeaderCause::Disposed))`. `None` and `Other(_)` are `false`.
   C# classes mapped: `IOException` and every subclass (`FileNotFoundException`, `EndOfStreamException`, `DirectoryNotFoundException`,
   `PathTooLongException`) -> `Io`; `ObjectDisposedException` -> `Disposed`; `InvalidDataException`, `ArgumentException`,
   `UnauthorizedAccessException` (NOT an `IOException`), `InvalidOperationException` -> `Other`; no inner -> `None`. The golden has one
   case per class. A nested `InvalidDataException` inside an `InvalidDataException` is NOT followed (only `InnerException` itself is tested).
5. **`RawContainerInfo`** has no logic. `orientation` is a raw EXIF value, not validated here. Keep the field order of the C# record.
6. **Hardening.** Nothing in this unit allocates from an input length or panics; the limits exist so the readers (W5-02..) can reject
   hostile headers before allocating: `MAX_PREVIEW_BYTES` is a cap checked BEFORE `Vec::with_capacity`, `MAX_HEADER_BYTES` caps the sum of
   header reads, `MAX_IFD_COUNT`/`MAX_ENTRIES_PER_IFD` cap loops, `MAX_JPEG_MARKER_SEGMENTS`/`MAX_JPEG_FILL_BYTES` cap the JPEG walkers.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- 1 OrdinalIgnoreCase: `eq_ignore_case`, not ASCII lowercase (semantics 1).
- 2 Culture: none here (no `ToLower`, no parsing), but do not introduce `to_lowercase`.
- 3 Integer width: `i32`/`i64` as in C#; `initial_probe_length` narrows after `min` (semantics 3).
- 8/9 `Option<&str>` stands for C# `string?`; `None` is the only "null".
- INV ids: none owned. INV-12 (decoder routing) consumes `is_raw_extension` later (FormatRoutingDecoder, `RawSupport` off throws
  NotSupported): not this unit.
- Parsers never panic: `is_raw_extension` is total (no slicing at a computed index other than inside `get_extension`, which is char-boundary safe).

## Open questions
- **Q1 (where do `EmbeddedPreview`/`ExifBlock` live?)** `RawContainerInfo` embeds both, but their C# files are not in this sub-unit's list. The stub defines
  them in `formats.rs` (complete shape, C# defaults `header_resolved = false`, `ifd_is_exif = false` are plain fields: the readers write the literal).
  Recommended: keep them here (they are 20 lines, every reader needs them, no other file is a better home). If another W5 sub-unit's draft also defines
  them, the lead deletes one copy; the type names and fields are identical to the C# records so the merge is mechanical.
- **Q2 (header error type)** C# throws `InvalidDataException` (with `InnerException`) from `IRawHeaderSource.Read` and the readers catch it with a filter. The stub
  models it as `RawHeaderError` + `RawHeaderCause`. The header-source sub-unit (`SourceRawHeaderSource` wraps `IOException` and `ObjectDisposedException`) must
  return exactly this type (or the lead renames it in one place). Recommended: keep as drafted; `Other` exists only for completeness/golden parity and is
  never produced by a Rust reader.
- **Q3 (`internal` members public)** `initial_probe_length`, `MAX_JPEG_MARKER_SEGMENTS`, `MAX_JPEG_FILL_BYTES` are C# `internal` (visible to the test project). Rust makes
  them `pub` so integration tests and sibling modules can use them. Alternative `pub(crate)` would force the tests to be unit tests inside `formats.rs`, which the
  owned-files list does not allow. Recommended: `pub`.
