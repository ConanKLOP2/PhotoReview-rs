## Semantics (C# is the spec)
1. **`new(owner, dpi, log)`**: `font = create_menu_font(dpi)`, `brush = create_solid_brush(owner_draw_style::background())`. `create_menu_font(dpi)`: `dpi != 0` -> `non_client_metrics_for_dpi(dpi)`; `dpi == 0` -> `SystemParametersInfoW(SPI_GETNONCLIENTMETRICS, 504, &mut NONCLIENTMETRICSW, 0)` (private wrapper); `Ok(m)` -> `create_font_indirect(&m.lfMenuFont)`, non-zero is the font; any failure or a 0 font -> `get_stock_object(17)` and a flag `font_is_stock` so `dispose` does not delete it. The `NONCLIENTMETRICSW` field `lfMenuFont` replaces the C# raw offset 224 (a test pins `offset_of!(NONCLIENTMETRICSW, lfMenuFont) == 224`).
2. **`attach()`**: `ref_data = Rc::into_raw(self.inner.clone()) as usize` (one strong count is owned by the registration); `set_window_subclass(owner, subclass_proc, SUBCLASS_ID, ref_data)`; on `false` reclaim the count at once (`Rc::from_raw`) and `attached = false`; on `true` remember `ref_data`. `attach` twice is a no-op returning the current state (C# would leak a handle; unreachable from `NativePopupMenuHost`).
3. **`register(item)`**: push; return `len as isize` (the 1-based `itemData`). Registration happens BEFORE the menu is shown, never during `TrackPopupMenuEx` (the `RefCell` is borrowed only for the push and for the clone in `item_for`).
4. **`subclass_proc(hwnd, message, wparam, lparam, id, ref_data)`**: for `WM_MEASUREITEM`/`WM_DRAWITEM` only: `inner = &*(ref_data as *const SessionInner)` (valid while the registration holds its count); under `catch_unwind(AssertUnwindSafe(..))`: `lparam` as the struct pointer with a null/alignment guard (D-W8B3H-19: a null or misaligned pointer is "not handled"); `CtlType == ODT_MENU` and a known `itemData` -> `measure`/`draw` -> return `1`. A caught panic is swallowed: `log.error("Owner-draw menu failed", ..)` when a log exists, and the message goes to `def_subclass_proc` (the menu then draws its default). Everything else: `def_subclass_proc(hwnd, message, wparam, lparam)`. The procedure never unwinds.
5. **`measure_item`** and the `MEASUREITEMSTRUCT` decode: a separator -> `(scale(48), separator_height)` (the style functions of 14e); else `hdc = get_dc(owner)`, `old = select_object(hdc, font)`, `(w, h) = text_extent(text)` (empty text `(0, 0)`), `sw` = shortcut extent when non-empty, `select_object(hdc, old)`, `release_dc(owner, hdc)` (a guard, so a failure in between still releases), `(item_width(w, sw, dpi), item_height(h, dpi))`. The decode writes `itemWidth`/`itemHeight` as `u32`.
6. **`draw_item(hdc, rect, state, item)`**: exactly the C# `Draw` above: `fill_solid(hdc, rect, if separator { background } else { item_background(state) })`; separator line rect `(rc.left + scale(8), mid, rc.right - scale(8), mid + 1)` in `separator()` colour, `mid = rc.top + (rc.bottom - rc.top) / 2` (integer division), then return; else text, shortcut, check mark, submenu arrow as listed. Colour of the shortcut: `color_ref("Dark.TextSecondary")` only when `enabled`. Per-draw GDI objects (brush, pen) are created and deleted inside the call; `select_object(hdc, old_font)` restores the font; the DC's text colour and background mode are NOT restored (C# parity: the menu's DC is per-item).
7. **`dispose()`**: idempotent. If attached: `remove_window_subclass(owner, subclass_proc, SUBCLASS_ID)`, THEN `drop(Rc::from_raw(ref_data as *const SessionInner))`, `attached = false`; delete the brush; delete the font unless it is the stock font. `Drop` calls it. Order matters: the subclass is removed before the count is released, so a late message cannot see a freed session.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (GDI leaks): every created object (font, brush, pens, per-draw brushes) is deleted on every path; `select_object` always restores the previous object before deleting the current one; a test counts `GetGuiResources(GR_GDIOBJECTS)` before and after 1000 `draw_item` calls and after create/dispose cycles.
- T2 (FFI panic): the subclass procedure is `extern "system"`; a panic must not unwind (it aborts). The whole body is under `catch_unwind`; this is the one place that swallows a panic (D-W8B4I-9): painting is cosmetic and the C# did the same; the alternative (capture and resume with `pending_panic`) is open question 1.
- T3 (raw pointers): `lparam` is a pointer for these two messages only; null/alignment checked; fields are read/written through the typed reference, never by offset; `ref_data` is a pointer produced by `Rc::into_raw` of THIS type, nothing else is ever stored with `SUBCLASS_ID`.
- T4 (subclass lifetime): removal before release; `attach` and `dispose` on the thread that created the owner window (`SetWindowSubclass` requirement); a subclass left behind after the owner is destroyed is harmless but the count would leak, hence `Drop`.
- T5 (stock font): `DEFAULT_GUI_FONT` must not be deleted by us (the C# `DeleteObject` on a stock object is a documented no-op, the Rust code skips it to keep the invariant explicit).
- T6 (DPI): `dpi` is the owner's DPI when the session was created; sizes are computed from it, not from the monitor under the cursor; a DPI change while the menu is open is out of scope (the menu is modal).
- T7 (integers): `rect` arithmetic is `i32` with the C# formulas (`(bottom - top) / 2` truncating); colours are `COLORREF` `u32`.
- T8 (text): `draw_text` clears `DT_MODIFYSTRING` (11d); the item text is NOT `&`-doubled here (`DT_NOPREFIX`), unlike the plain-menu path.
- T9 (threading): `Rc` core, `!Send`; everything on the UI thread of the owner window.

## Safety rules (`// SAFETY:` per `unsafe` block)
(a) `subclass_proc`: `ref_data` deref ("the registration holds a strong count of this `SessionInner` until `remove_window_subclass`"), the `MEASUREITEMSTRUCT`/`DRAWITEMSTRUCT` deref ("valid for the duration of the message per the Win32 contract; non-null and aligned checked"), `def_subclass_proc` ("called from a subclass procedure with its own parameters"); (b) `Rc::into_raw`/`from_raw` pair around `set_window_subclass`/`remove_window_subclass`; (c) `set_window_subclass` call ("`subclass_proc` stays valid until removal; `ref_data` as above"); (d) `MoveToEx`/`LineTo`/`SystemParametersInfoW` private wrappers ("handle values; a null previous-point pointer", "pointer to a local `NONCLIENTMETRICSW` with `cbSize` set"); (e) `from_raw_parts` is not used.

## Error mapping
| C# | Rust |
|---|---|
| `SetWindowSubclass` returns false | `attach()` returns `false`; the menu keeps the system look (no error) |
| exception in `Measure`/`Draw` | a caught panic: logged, message goes to `DefSubclassProc` |
| `CreateFontIndirect` / `SystemParametersInfo` failure | stock `DEFAULT_GUI_FONT` |
| `GetDC` returns 0 | the measure answers with zero text extents (the C# wrapper did not check either) |

## Open questions (recommended default in bold)
1. **A paint panic**: **swallow and log** (C# parity, the menu is cosmetic); alternative: capture with `pending_panic` and resume in `NativePopupMenuHost::show` after `TrackPopupMenuEx` (D-W8B3H-4 style), which would surface a drawing bug instead of hiding it; it would be a stricter behaviour than C# and needs no Different row (it is not observable in a correct build).
2. **`draw_item`/`measure_item` public**: **yes**, they are the test seam that makes the painting testable without a popup window; the `lparam` decode stays private.
3. **Restoring the DC text colour and background mode**: **no** (C# parity); the menu resets them per item.
4. **The system's black submenu arrow**: not fixable (C# comment); the Rust port draws the same light arrow and accepts the black overdraw.
5. **`SystemParametersInfoW` wrapper in this file** vs an addition to 11d: **private here** (one caller); if 11d gains `system_parameters_info`, use it.
