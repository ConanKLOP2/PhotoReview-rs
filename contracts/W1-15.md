## Semantics notes

### `percentile` (C# `BenchmarkStatistics.Percentile`)
There is NO rounding anywhere in this function (no `Math.Round`, so no banker's-rounding question). The definition is the INCLUSIVE linear-interpolation percentile (Excel `PERCENTILE.INC`, numpy `linear`), not nearest-rank (nearest-rank is `PerfStats.NearestRank`, a different unit).
1. `values.is_empty()` -> `Ok(0.0)`. This happens BEFORE the percentile check: `percentile(&[], 7.0)` and `percentile(&[], f64::NAN)` are `Ok(0.0)`.
2. `if !(percentile >= 0.0 && percentile <= 1.0)` -> `Err(PercentileOutOfRange)`. Keep the negated form: NaN, `+inf`, `-inf`, `1.0000000000000002`, `-1e-300` all fail it; `-0.0` and `5e-324` pass. (Clippy's `neg_cmp_op_on_partial_ord` may warn: write `if !(0.0..=1.0).contains(&percentile)`, which is the same for every f64 including NaN and -0.0.)
3. `ordered` = copy of `values`, sorted ascending with a STABLE sort using this comparison (the one `Comparer<double>.Default` / `double.CompareTo` uses): `a < b` Less; `a > b` Greater; `a == b` Equal (so `-0.0` and `0.0` are EQUAL and keep their input order); otherwise (at least one NaN): NaN sorts before every number and NaN equals NaN. Use `Vec::sort_by` (stable) with a hand-written comparator. Do NOT use `partial_cmp().unwrap()` (panics on NaN) and do NOT use `f64::total_cmp` (it orders `-0.0 < 0.0` and splits NaN by sign), the golden pins both.
4. `position = (ordered.len() - 1) as f64 * percentile` (IEEE multiplication, nothing fused). `lower = position.floor() as usize`, `upper = position.ceil() as usize` (both indices; `-0.0` gives 0). Never use integer or decimal arithmetic for the position: `0.7 * 10` is `7.000000000000001`, which makes `lower != upper` and adds a tiny interpolation term (golden: n=11, p=0.7 gives `8`; n=101, p=0.57 gives `57.99999999999999`).
5. Result: `lower == upper` -> `ordered[lower]`, else `ordered[lower] + (ordered[upper] - ordered[lower]) * (position - lower as f64)`, evaluated exactly in this order. Infinities and NaN propagate by IEEE rules (`[-inf, inf]` at 0.5 is NaN; `[f64::MAX, -f64::MAX]` at 0.5 is `+inf`).
6. The input slice is not modified.

### `DiagOptions::from_lookup` (C# `ReadFromEnvironment`)
`get(name)` is called with the five `*_VAR` names; `None` and an empty string behave the same in every case below.
- `pre_read`, `disable_disk_cache`, `force_log`: `true` only when the value is EXACTLY `"1"` (ordinal). `"0"`, `"true"`, `"TRUE"`, `"yes"`, `" 1"`, `"1 "`, `"11"`, `"01"`, `""`, fullwidth `"１"` are all `false`.
- `preload_workers`: C# `int.TryParse(raw, NumberStyles.Integer, CultureInfo.InvariantCulture, out v) && v is >= 0 and <= 16`; anything else is `None`. Reproduce `NumberStyles.Integer` exactly:
  1. skip leading whitespace, where whitespace here is ONLY `\t \n \v \f \r` and space (U+0009..U+000D, U+0020), NOT NBSP or other Unicode spaces;
  2. one optional sign, `+` or `-`, directly followed by the digits (`"+ 5"` fails);
  3. one or more ASCII digits `0-9` (leading zeros fine: `"05"`, `"005"`, `"-0"` -> 0; Arabic-Indic and fullwidth digits fail);
  4. skip trailing whitespace (same set), then only NUL characters (`'\0'`) may follow (.NET quirk: a trailing NUL is accepted; it cannot occur in a real environment variable but a lookup closure can return it);
  5. the number must fit `i32` (`"2147483648"`, `"-2147483649"`, `"9223372036854775808"` fail), then the 0..=16 range check.
  Examples: `" 5 "`, `"+5"`, `"\t5\n"`, `"\v7\f"`, `"12\r\n"`, `"+16"` give `Some`; `"17"`, `"-1"`, `"abc"`, `"2.5"`, `"1e1"`, `"16.0"`, `"5x"`, `"5 5"`, `"0x5"`, `"1,5"`, `"1_0"`, `"+-1"`, `"+"`, `" "`, NBSP-padded give `None`. Do not use `str::parse::<i32>` directly (it rejects whitespace and accepts nothing else) and do not use `trim()` (Unicode whitespace).
- `instance_label`: the RAW value (no trimming) unless it is empty or every char is whitespace by `char::is_whitespace` (the C# `string.IsNullOrWhiteSpace`, which IS Unicode-aware: `" "`, `"\t"`, `"   "`), then `None`. `"  padded  "` stays `"  padded  "`.
- Culture: none. Digits and signs are ASCII; nothing depends on the user's locale (RV-S02).

### `any_enabled`, `describe`
- `any_enabled` = `pre_read || preload_workers.is_some() || disable_disk_cache || force_log || instance_label.is_some()`. `PRELOAD_WORKERS=0` alone counts as enabled.
- `describe`: when nothing is active the exact text `(none)`. Otherwise the active parts joined with `;` and no spaces, in this fixed order: `PREREAD=1`, `PRELOAD_WORKERS=<n>` (plain decimal), `DISABLE_DISKCACHE=1`, `FORCE_LOG=1`, `INSTANCE_LABEL=<raw label>`. The label is not escaped (`a;b` stays `a;b`).

### `from_environment`, `current`, cache
- `from_environment()` = `from_lookup(|n| std::env::var_os(n).map(|v| v.to_string_lossy().into_owned()))`.
- `DiagOptionsCache::get_or_load(load)`: lock; if the slot is empty call `load()` and store `Arc::new(result)`; return a clone of the stored `Arc`. The loader runs at most once until `reset()`. Recover a poisoned mutex with `unwrap_or_else(PoisonError::into_inner)`; never `unwrap()`. Do not call `load` while another thread could deadlock on the same lock (it is called under the lock: fine, the loader only reads variables).
- `DiagOptions::current()` = `PROCESS_CACHE.get_or_load(DiagOptions::from_environment)`; `reset_for_tests()` = `PROCESS_CACHE.reset()`.

## Traps checklist
§7 items 4 (no rounding: do not "round" the percentile), 2 (invariant parsing: `NumberStyles.Integer`, ASCII only), 8 (`None` vs empty: label `""` is `None`, but `"  padded  "` is kept raw), 3 (n/a overflow: `(n-1)` as f64; index casts are safe because `0 <= position <= n-1`), 10 (`describe` order is fixed).
