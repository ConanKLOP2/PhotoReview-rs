- Semantics notes:
  1. **Value rules.** valid = `1..=8`. `normalize` keeps a valid value, else 1 (including 0, negatives, 9, 65535, `i32::MIN/MAX`).
     `is_transposed` = `5..=8` only: it does NOT normalize first, and 9 or 0 are `false`. Both take `i32` (C# `int`); do not narrow to `u8`.
  2. **Read order (`read_from_wic`).** Ask `EXIF_ORIENTATION_QUERY` ("/app1/ifd/{ushort=274}"). If the integer answer is valid, return it
     WITHOUT asking the second query. Otherwise (absent, out of range) ask `WINDOWS_ORIENTATION_QUERY` ("System.Photo.Orientation") and
     return it when valid. Anything else is 1. The query strings are persisted nowhere but must be byte-equal (they are WIC property paths).
  3. **Failure seam.** C# wraps both queries in one `try`/`catch (Exception) when not OutOfMemoryException` and returns 1. Rust: the caller's
     closure returns `Err(QueryFailed)` for any failure (including a corrupt-metadata exception mapped by W4-11d); `Err` from the FIRST query
     returns 1 immediately and the second is not asked (golden `exif-throws-gives-1-windows-not-asked`); `Err` from the SECOND gives 1
     (golden `exif-invalid-windows-throws`). There is no panic-catching: a panic is a bug and propagates (like OOM in C#).
  4. **Integer reduction is the caller's.** C# `ReadFromWic` takes the raw managed object and calls `ExifQueryInterpreter.AsInteger` itself
     (byte, short, ushort, int, uint, and the first element of an array; strings and `long` are NOT integers). Rust moves that step to the
     closure so this unit does not depend on W4-04b: the W4-11d reader returns `exif_query::as_integer(value)`. The goldens still cover every
     shape, because the oracle goes through the real C# `AsInteger`; the Rust test feeds the `expected` integer implied by the case (a table in
     the test maps the `type` of the case to the `as_integer` result, `string` and `long` and empty array to `None`).
  5. **Transform table.** Mirrors apply BEFORE the rotation (WPF `TransformGroup` order): 1 identity; 2 flip_h; 3 rot 180; 4 flip_v;
     5 flip_h then rot 270; 6 rot 90; 7 flip_h then rot 90; 8 rot 270; any other value identity. Rotation is clockwise in a y-down plane.
     `map_pixel` is the closed form of the same table; tests assert both agree (apply the flips, then rotate the point, compare).
  6. **`map_pixel`/`oriented_size`.** Pure arithmetic on `u32`; precondition `x < width && y < height` (debug_assert, no error type: the only
     caller is a pixel loop and the test). Use `width - 1 - x` forms; no overflow possible under the precondition. Invalid orientation is
     identity (same as `create_transform`), so `oriented_size(9, w, h) == (w, h)`.
- Traps checklist: §7 items 3 (the `w - 1 - x` forms are safe only under the precondition: do not "simplify" to signed math that
  can go negative), 9 (the one `catch` is one `Err` branch, both queries), plus INV-1 note above (normalize before keys).

## Golden package
- `oracle/W4-02a.cs`: commands `orientation-values` (Normalize + IsTransposed + the two query strings), `orientation-read-wic` (call order
  and result through reflection on `internal ReadFromWic`), `orientation-pixels` (a Bgr32 buffer of unique ids through the REAL
  `PixelOps.ApplyOrientation`; this is the pixel truth for the transform table because WPF types cannot run in the oracle).
  Dispatch lines are in the file header. WIRING NEEDS: a reference to `PhotoReview.Imaging.dll` in `OracleCs.csproj` and the copy step in
  `tools/oracle.ps1` (today only Core/PerfAnalysis/Localization.Generator are referenced). Do not run the oracle in the draft.
- `golden-inputs/{orientation-values,orientation-read-wic,orientation-pixels}.json`, outputs in `golden-reference/`.
- Case design: values 1..8 and every invalid class (zero, negative, just above, `ushort` max, `int` extremes); read order: EXIF valid wins,
  EXIF 0/9 falls through, both absent, every managed integer shape (byte, short, ushort, int, uint, array, empty array), non-integers
  (string, long), a throwing query on each side; pixels: all 8 orientations on 3x2 (the C# test image) plus 2x3, 1x1, 4x1, 1x4, 5x3 so a
  width/height mix-up or off-by-one in the mirror cannot hide, and the identity cases (0, 1, 9, -1, `int::MAX`) with `same_instance`.

## Open questions
- Return type of the closure: this stub uses `Result<Option<i64>, QueryFailed>` (integer already reduced). Alternative is a
  `QueryValue` enum in `exif_query` (W4-04b) and calling `as_integer` inside `read_from_wic`, which is closer to the C# signature but
  couples the two units and their merge order. Recommended: the stub as written; W4-11d does the one-line composition. Lead decides
  before W4-04b is cut, since that decides who owns the "array uses first element" test.
- `create_transform` representation: a plain record of two bools plus degrees (stub) vs a 3x3 matrix. The record is enough for the only
  consumers (a pixel loop and tests); a Direct2D presenter (W7) can derive a matrix from it. Recommended: the record.
