## Semantics (see the verbatim source below; the Rust shape is `ActionProfilesContent`)
- The dialog edits a **copy** (`ExternalEditor` is `Clone`); the original list is never touched. `outcome()` returns copies and `effective_default_id()` (the stored id if some editor has it, else the first editor's id, else `""`).
- `on_initialized`: `fill_list`; with editors, select the default's index (0 when it cannot be found).
- Selection change = `save_current` (writes name `trim`, path `trim`, arguments **untrimmed** of the open row, then `refresh_list`) then show the newly selected row; `open` is the index of the row whose fields are in the boxes (`-1` = none).
- Add: `save_current`, pick an executable (cancel/blank or a full list: nothing), new editor named `suggest_name(path)` or `name_from_path(path)`, first editor of an empty list becomes the default, select the last row. Remove: `open = -1` BEFORE removal, the default moves to the first remaining editor (`""` when none), select `min(index, last)` or clear the three boxes. Set default: `save_current`, then `default_id = selected id`. Browse: initial folder = parent of the current path only when that path is an existing file.
- Apply (`on_ok`): `save_current`; the first editor with a blank path is selected and the warning `dialog.externalEditor.exeMissing {path = ""}` is shown with title `externalEditors.title`; the dialog stays open (`false`).
- Layout arithmetic is the C# one (preferred `(dx(470), dy(190))`, minimum `(max(dx(380), button row + 2*margin), dy(170))`, left column `clamp(w/3, dx(100), dx(170))`); the porter writes the exact `Place` order from the verbatim source into `layout_plan` and tests it with a fake `DialogMeasure`.

## Traps
- Never hold a `RefCell` borrow across a modal call (file dialog, warning): read the controls BEFORE `borrow_mut`, write AFTER (same rule as `ActionProfilesContent`, D-W8B4I-1).
- `ExternalEditorsEdit` lives in this file, not in `pr-core` (a `pr-core` type would leak a Win32 dialog result into the core).
- The id constants are the C# numbers (100..118 with gaps) because tests and the paint test address controls by id.
- UI-thread only, synchronous; no `async`, no background thread, no panic on a bad path (`std::fs` calls only for `File.Exists`/`GetDirectoryName`, errors swallowed as in C#).
