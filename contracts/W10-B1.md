## Public API

The compiling API is the exact surface in `crates/pr-bench/src/compare.rs`: `Summary`, `DatasetIdentity`, `PhaseRow`, `DiagnosticMetric`, `Thresholds`, `Verdict` (including `Skipped`), `ProfileComparison`, `CompareReport`, `CompareError`, `compare(&Summary, &Summary, &Thresholds) -> Result<CompareReport, CompareError>`, and `compare_repeats(&[Summary], &[Summary], &Thresholds) -> Result<CompareReport, CompareError>`. `compare_repeats` requires equal lengths and `len >= minimum_repeats`, pairs by index, and uses medians of per-repeat statistics. `compare` requires `minimum_repeats == 1`. Both stubs return typed errors; comparison is not implemented.

CLI contract only: `pr-bench --bench-compare <csharp-summary.json> <rust-summary.json> [--thresholds <file>] [--out <dir>]`. The PowerShell driver runs the C# executable and Rust executable sequentially and invokes this mode. Do not edit `cli/mod.rs` in this contract.

Lead integration (2026-10-29): each summary argument also accepts a repeat directory. Only immediate regular `*.json` files are read, sorted by filename and paired by index; use identical zero-padded repeat names on both sides. Defaults still require three pairs; a single file pair is incomparable unless a threshold file explicitly sets `minimumRepeats` to 1. Threshold JSON is an object with optional `ratioTolerance`, `absoluteFloorMs`, and `minimumRepeats`; omitted keys keep defaults, unknown/duplicate keys and invalid values are usage errors (exit 2). No new Cargo dependency is used.

`--out` defaults to `docs/drafts/bench-parity`. It receives sibling `YYYY-MM-DD-<machine>-bench-compare.md` and `.json` files using the existing report renderer; Markdown is also printed to stdout. Input/parse/repeat errors produce an Incomparable report (exit 3); output I/O failure returns 3 with a diagnostic. Usage/threshold errors return 2 before writing a report. Reusing the same output directory on the same date replaces that report pair; the driver requires a new output root to preserve prior evidence.

Driver: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/bench-compare.ps1 -BaselineExe <absolute-csharp-exe> -CandidateExe <absolute-rust-exe> -Folder <fixture> -Out <new-directory> [-Profiles all|actions|<comma-separated-ids>] [-Repeats 3] [-Scenario fresh-process|warm] [-Thresholds <file>] [-TimeoutSeconds 600]`. `all`/`actions` use batch output overrides; explicit profiles occupy the third `--benchmark` argument. Each child is bounded and completes before the next starts; measured pairs alternate executable order. Warm runs add one unmeasured batch per executable. Fresh-process does not claim disk-cold state; operator cache control remains outside this script. Separate stdout/stderr logs, invocation/hashes/environment record, numbered baseline/candidate summaries, and a report directory are retained. The script propagates comparison exit codes 0/1/2/3; execution or REPORT failures return 3. `UnwiredBackend` remains a precondition blocking real Rust measurements.

## Semantics

### Invocation and repeat protocol

The operator supplies absolute paths for the C# `PhotoReview.Benchmark.Cli.exe` and Rust `pr-bench.exe`; executable selection is explicit to avoid PATH ambiguity. The comparison script receives one fixture folder, a profile selection, an output root, and repeat count. For each repeat it runs C# to completion, checks exit code and `REPORT:` summary path, then runs Rust to completion; never run them concurrently. Pin the same machine, folder, profile IDs, adapter, power/display state, and app build configuration. Use separate output directories because the reports share the basename `summary.json`.

Run cold and warm conditions as separate named scenarios. Cold means a fresh process and the same documented cache-clearing procedure before each side; do not claim OS disk cache is cold unless independently controlled. Warm means one untimed warm-up batch per executable followed by measured batches. Alternate executable order across repeat pairs (C# then Rust, Rust then C#) only after each process has exited. Require at least 3 paired repeats. Compare the median across repeat-level p50, p95, and max values; do not pool raw samples across repeats.

Use identical mode arguments: `--benchmark <folder> <comma-separated-profile-ids>`, `--benchmark-all <folder> [output-directory]`, or `--benchmark-actions <folder> [output-directory]`. For `--benchmark`, its third argument is the profile list, not output override; place output override only in batch modes. The Rust mode must implement the same argument semantics before use. Rust-only switches use the `PHOTOREVIEW_RS_*` namespace and must be declared in the run record. Never read or write the C# app's journal, sessions, cache, or log; follow R0002.

### Schema and fields

Gate 0 is byte-format parity per Phase 2: check JSON key set/order, CRLF, and number-token grammar of non-timing fields first. Timing values differ by definition; equivalent token grammar means .NET `R` shortest-round-trip form (no exponent for the ranges seen). A format mismatch is `Incomparable`, exit 3.

Three classes govern comparison:

1. **EXACT** (mismatch means Incomparable): schema/key set and order; `Dataset`; `ProfileId` set and order; `Workload`; `Status`; `Count`/sample count; `ImagesPerSample`; correctness flags and messages. `Metrics` presence/shape/key set is part of schema validation.
2. **TIMING** (thresholded): Samples-derived `P50`, `P95`, `P99`, `Max`, `P95PerImage`, `P50PerImage`.
3. **DIAGNOSTIC** (report C#, Rust, delta; never fails the gate): every `ReviewMetricsSnapshot` field: `CacheHits`, `CacheMisses`, `SourceBytesRead`, `SourceReads`, `DecodeMilliseconds`, `PresentedImages`, `PresentMilliseconds`, `PreloadHits`, `InflightJoins`, `DiskCacheHits`, `UiAssignMilliseconds`, `DecoderFallbacks`, `SourceOpenCount`, `TopSourceOpens`, `StatCount`, `SessionWriteCount`, `CrossThreadPresentCount`, `PresentHistogram`. Runtime values may legitimately differ due to timing and scheduling.

Compare `Dataset` exactly: `Folder`, ordered `Files`, `UnsupportedExtensions`, `FileLimit`, and supported/unsupported counts. `Reports` phase rows correspond one-to-one with outcomes.

Null, NaN, infinity, absent percentile, empty samples, invalid status, or zero samples in a timing profile is incomparable; never coerce to zero. `Fail` on either side is exit 3/incomparable, not a speed result. A status mismatch is incomparable. A profile marked not implemented in the C# registry is skipped only when both outputs omit it identically; otherwise profile-set mismatch is incomparable. Correctness-only profiles are compared for exact status, sample count, and correctness fields, but latency is informational and cannot fail the performance gate.

### THRESHOLDS (proposal D-W10BENCH-1)

Require at least three paired repeats. Pair by index; B and R are medians of repeat-level statistic values. For each statistic, `allowed = max(ratio_tolerance * |B|, absolute_floor_ms)` and `d = R - B`; defaults are 5% and 1 ms, reusing C# PerfComparer. R0001's 8.5 ms and 10 ms are context references.

| Condition (same function per statistic) | Verdict |
|---|---|
| `d < -allowed` | Improvement |
| `-allowed <= d <= 0` | Pass |
| `0 < d <= allowed` | WithinNoise |
| `d > allowed` and paired difference exceeds `allowed` in a strict majority of pairs | Regression |
| `d > allowed` but strict-majority condition is false | WithinNoise; note `unstable` |
| Symmetrically not implemented | Skipped |
| Exact/schema mismatch, invalid timing, failed status, or too few repeats | Incomparable |

Equal-or-better means all exact checks pass and no comparable performance profile has a p95 Regression. p50, max, p99, and per-image use the same function; p50/max Regression is a warning note and does not change exit code. Correctness-only profiles use exact correctness/status/count checks; timing is diagnostic. Not-implemented is Skipped only when absent on both sides.

The rule avoids claiming sub-millisecond noise as regression and gives Phase 7 a testable p95 gate. W8-12j's 10 ms trigger remains separate.

Harness exit codes: 0 = no p95 Regression on a comparable performance profile (p50/max Regressions are warnings and keep exit 0); 1 = at least one p95 Regression of a comparable performance profile; 2 = usage/threshold-file error; 3 = environment or not comparable (schema, data, status, repeats, or execution failure).

## Traps

- Current `main.rs` wires `UnwiredBackend`; the harness cannot produce a valid Rust benchmark until engine-backed backend wiring exists. This is a dependency/precondition, not completed work.
- The C# batch caps at 64 top-level supported images. Require identical ordered file manifests and profile lists.
- C# report times are wall-clock measures of the prepared runner's timed step; keep setup and scratch-copy work out, following R2-F-14.
- C# PerfComparer uses robust intervals and context-noise downgrades for repeated probe results. This contract's simple summary gate must not claim that it reproduces the CI interval estimator.
- Report `StartedUtc`, `RunId`, and `Machine` for traceability, not exact parity.
