## Semantics (C# is the spec)
1. **`ctl_color_kind`**: `0x0136` -> `DialogBackground`; `0x0135`, `0x0132`, `0x0137` -> `Button`; `0x0138` -> `ReadOnlyEdit` when `control_is_edit` else `Static`; `0x0133`, `0x0134` -> `Input`; anything else `None`. Use the named constants of `dialog_native` (`WM_CTLCOLORDLG` ...), not literals.
2. **`on_ctl_color`**: `kind = ctl_color_kind(message, message == WM_CTLCOLORSTATIC && is_edit(lparam))` (`is_edit` is 18j's `NativeDialog::is_edit`); `None` -> `None`. Per kind the calls of the C# section, in that order (text colour then background colour), with `hdc = wparam as Hdc` and the brushes from `DrawState` (`0` when not created: the answer is then `Some(0)`, the OS uses the default). `static_text_color` comes from `content.static_text_color(self, get_dlg_ctrl_id(lparam))` with no borrow held. The returned `Lresult` IS the brush handle (`brush as isize`).
3. **`create_brushes`**: `window_brush = create_solid_brush(DialogColors::window())`, `input_brush = create_solid_brush(DialogColors::input())`. Called once by `initialize_dialog`.
4. **`draw_owner_item`**: the C# section; `lparam == 0` -> `false`; the typed read `&*(lparam as *const DRAWITEMSTRUCT)` with the layout assertions (`size_of == 64`, `offset_of!(CtlID) == 4`, `itemID == 8`, `hwndItem == 24`); `item_id = draw.itemID as i32`; `controls::basic::ListBoxControl::draw_item(draw, &item.text, item.badge.as_deref(), font, dx(4), subtitle.as_deref(), badge_color)`; the hooks run BEFORE `draw_item` and with no borrow held; answer `true`.
5. **`on_set_cursor`**: `content.wait_cursor()` -> `load_system_cursor(IDC_WAIT)`; `Ok(c)` -> `set_cursor(c)` (an `Err` leaves the cursor and still answers 1, as the C# which ignored the null cursor); `set_window_long_ptr(hwnd, DWLP_MSGRESULT, 1)`; `1`. Else `0`.
6. **`on_close_request`**: `content.can_close_by_user()` -> `end_modal(ID_CANCEL)`; always `1`.
7. **`delete_and_clear`**: a non-zero handle -> `delete_object(handle)` (result ignored), then `0`.
8. **`cleanup`**: the ten steps of the stub doc, in that order, each tolerant of "already gone": every `is_window` test uses the stored handle; `remove_window_subclass` is only called for windows that still exist (D-W8B5-314: it must run BEFORE the cookie is freed because the subclass `ref_data` is the cookie); `destroy_window` error ignored; the cookie is freed with `free_cookie(self_cookie.replace(0))` AFTER `DestroyWindow` and BEFORE the `closed` callback; `on_closed` under `guarded` (a captured panic is resumed by the `show_*` caller). The collections are drained under a short borrow and iterated after it. `cleanup` may be called from inside the dialog procedure (modeless `end_modal`) and from `Drop` of the `CleanupGuard` during unwinding.
9. **After `cleanup`**: `hwnd() == 0`, `is_closed()`, the owner enabled again, the content released once the last handle is dropped (the cookie was the only extra strong reference).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T3 (arithmetic): `wparam as Hdc` is a reinterpret of the DC handle; `itemID as i32` turns the `UINT` `0xFFFF_FFFF` into `-1` (empty list / below the last row).
- T8 (null vs empty): `item_id < 0` -> `ListItemText::default()` (empty text, no badge) and NO subtitle or badge-colour hook call.
- T9 (exception to Result): the `try/catch` around `OnClosed` is `guarded`; nothing else catches.
- T10 (order): in `cleanup`, `on_closed` BEFORE the subclasses; the owner is enabled BEFORE the window is destroyed; `DWLP_USER` is zeroed BEFORE `DestroyWindow`; GDI objects deleted AFTER the window (a control may still select the font while it is being destroyed); the cookie is freed AFTER the window; the callback is LAST. In `on_ctl_color`: text colour, then background colour, then the brush.
- Handles (R0003): the four GDI handles are deleted exactly once (`delete_and_clear`); a second `cleanup` does nothing; the tip buffer and the cookie cannot be freed twice.
- Re-entrancy: `cleanup` runs hooks (`on_closed`) and the `closed` callback with no `RefCell` borrowed; the callback may drop the last handle.

## Safety rules (`// SAFETY:` per `unsafe` block)
`draw_owner_item` (typed read of `lparam`, valid for `WM_DRAWITEM`), `on_set_cursor` and `on_close_request` (`set_window_long_ptr(DWLP_MSGRESULT)`), `cleanup` (`set_window_long_ptr(DWLP_USER, 0)`: the slot the dialog procedure reads; `free_cookie(cookie)`: the cookie came from `make_cookie` and is freed once because the cell is swapped to `0` first), `remove_window_subclass` is safe in this crate. Test code that sends messages with pointers has its own `// SAFETY:` per block.
