## Semantics
- Where the DLLs must sit differs by test (checked 2026-10-23): the production loaders `crates/pr-libraw/src/native.rs` (`library_path_next_to(current_exe())`) and `crates/pr-turbojpeg/src/native.rs` (`default_library_path()`) load only from the folder of the running executable; for `cargo test` that is the test executable's folder (`target/<profile>/deps`). The tests `pr-libraw/tests/{availability,native}.rs` and `pr-turbojpeg/tests/availability.rs` say the DLL must be "next to the test executable"; only `pr-turbojpeg/tests/decoder_native.rs`, the in-crate native test module of `pr-turbojpeg/src/native.rs` and `pr-libraw/tests/decoder_native.rs` (for `turbojpeg.dll`) read `<repo>/native/x64/`. Staging into `native/x64/` alone therefore does not satisfy the "next to the test executable" tests; how to place the second copy is open (see `docs/drafts/w10-review.md`, decision N-1).
- `.gitignore` ignores `/native/x64/*.dll`. Keep C# baseline pins authoritative.
- Preferred source is C# checkout `native/x64/` after hash verification. Alternative is a verified local package/cache or explicit future fetch using pinned scripts. Any network download needs explicit owner consent. This contract downloads nothing.
- Later PowerShell staging proposal: accept explicit C# checkout path; verify source DLL against pinned SHA-256; verify package zip before extraction if used; copy only verified DLLs into Rust `native/x64/`; hash destination again; fail on missing pin, mismatch, unexpected architecture, or partial copy. Do not search PATH or use unverified binaries.
- Absent/mismatched DLL: ordinary tests remain ignored by default. Explicitly selected LibRaw native tests may return/skip unless strict mode is on (`PHOTOREVIEW_RS_RAW_CORPUS_STRICT=1` for `availability.rs`/`native.rs`, `PHOTOREVIEW_RAW_CORPUS_STRICT=1` for `decoder_native.rs`; see W10-N3); TurboJPEG tests may fail when DLL absent. A skipped test is not native verification.
