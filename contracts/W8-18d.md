## Semantics (C# is the spec)
1. **`build`**: exactly the byte layout above, little endian. `count > 65535` -> `Err(TooManyControls)` before any byte is produced. `title`/`text` are written as `str::encode_utf16()` units (a surrogate pair is two units, as C# `char`). `id as u16` (`-1` -> `0xFFFF`, `65536` -> `0`, no panic). Padding is relative to the START of the returned buffer: the OS wrapper copies it into a 4-aligned buffer, so the offsets match. Never panics, no `unwrap`.
2. **`class_name`**, **`window_class_name`**: the table above; the strings are the constants of `win32::control_constants` (`WC_LISTVIEW` = `SysListView32`, `PROGRESS_CLASS` = `msctls_progress32`, `TRACKBAR_CLASS` = `msctls_trackbar32`).
3. **`DialogColors`**: the accessors take the key from `pr_app::overlay::palette::get(key)` and convert with `to_color_ref`. `to_color_ref(r, g, b)` computes `r * 255.0_f32` in single precision, widens to `f64`, `round_ties_even()`, `as u32` (a saturating cast: C# `(uint)` of a negative double is unspecified, the inputs are always 0..1); `r | g << 8 | b << 16`. Accessors whose key is missing (impossible: a test guards all six) return `0`.
4. **`theme_for`**: `Some("")` for the eight classes above, `None` for Static. `theme_for_control` ignores the handle.
5. **`DarkDialogChrome::apply`**: in this order `os.apply_title_bar(dialog)`, `painter.attach_dialog(dialog)`, then `apply_controls`'s work; **`apply_controls`**: per control in the given order, (a) `set_theme(hwnd, theme, Some(theme))` when `theme_for_control` is `Some`, (b) `painter.attach_control(hwnd, class)`, (c) the parts: ComboBox -> `os.combo_list_window(hwnd)`; non-zero -> `set_theme(list, "", Some(""))`; ListView -> `os.list_view_header(hwnd)`; non-zero -> `set_theme(header, "", Some(""))` then `painter.attach_header_filler(header)`. Results of the painter calls are ignored. Nothing panics when the OS answers `0`/`false`.
6. **`DarkDialogChrome::new(painter)`**: `set_theme` = `dialog_native::uxtheme::set_window_theme(hwnd, Some(app), ids)` with the `Err` ignored (the C# `catch` of a missing export); `os` = `Win32ChromeOs`. `Win32ChromeOs::apply_title_bar` = `host::main_window::windowing::apply_title_bar(dialog, None)`; `combo_list_window` = `chrome::combo_list_window`; `list_view_header` = `unsafe { send_message(hwnd, LVM_GETHEADER, 0, 0) }` with `// SAFETY: LVM_GETHEADER carries no pointer`. `chrome::combo_list_window(0)` = `0`, else `comctl::user32::get_combo_box_info(combo)` -> `hwndList` or `0`.
7. **Oracle golden** `dialog-template` (kinds `build`, `class_name`, `theme_for`, `color_ref`, `from_key`, `named_colors`, `constants`; the Rust test compares hex of the whole buffer, so alignment and padding are proven against C#).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T3 (arithmetic): `id as u16`, `count` check with `u16::MAX`, no `usize` overflow when summing sizes (use `Vec::with_capacity` of a saturating estimate or none).
- T4 (rounding): `round_ties_even`, never `f32::round`/`f64::round`; the product is single precision first (`r * 255.0_f32`), the golden has rows at the .5 boundaries (0.5 -> 127.5 -> 128 even, 0.49803922).
- T8 (null vs empty): `""` is the only representable form; one terminator for title and text.
- T9 (exception to Result): the single C# `throw` of `Build` is `Err`; `FromKey`'s `KeyNotFoundException` is `None`; the `catch (DllNotFound|EntryPointNotFound)` of `Apply` is "ignore the `Err` of `set_window_theme`".
- T10 (order): items are written in the given order; the chrome handles controls in the given order (the recorder sees it).
- Handles (R0003): the chrome is UI-thread only (`Rc`, `!Send`); `apply` may be re-entered by nothing (it calls into `SetWindowTheme`, which sends theme messages, not application messages).

## Safety rules (`// SAFETY:` per `unsafe` block)
Only `Win32ChromeOs::list_view_header` has an `unsafe` block (`send_message`): "`LVM_GETHEADER` takes no pointer arguments". Everything else uses safe wrappers of `win32`.

## Error mapping
| C# | Rust |
|---|---|
| `ArgumentException` (too many controls) | `Err(TemplateError::TooManyControls)` |
| `ArgumentNullException(items)` | unrepresentable (`&[DialogItem]`) |
| `ArgumentOutOfRangeException` in `WindowClassName` | unrepresentable (total match) |
| `KeyNotFoundException` in `FromKey` | `None` |
| `DllNotFoundException` / `EntryPointNotFoundException` in `Apply` | `set_window_theme` `Err` ignored; the classic look stays |
