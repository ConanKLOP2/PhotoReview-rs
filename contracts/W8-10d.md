- Semantics notes (from the C# source read at the baseline):
  1. **Working copy.** `new` stores `current.clone()`. C# clones through the config.json JSON contract so every property survives; a derived `Clone` copies every field,
     which has the same result. `load_fields` never writes to the working copy (the RAM clamp is display only).
  2. **`load_fields` order.** Start `SettingsFormState::default()`, run `load` of every row of `bindings()` in table order, then compute the RAM range from the TEXT the rows
     wrote (`preload_forward_text`, `preload_backward_text`) and store `ram_cache_percent = clamp(image_cache_ram_percent, min, max) as f64`.
  3. **`ram_cache_range`.** Each preload box is parsed on its own with `try_int` (invariant culture; only U+0009-U+000D and U+0020 are whitespace; sign and ASCII digits only;
     overflow refused; range-checked); a refused or `None` box uses the SAVED count clamped into that box's range. The window minimum comes from
     `pr_imaging::ram_budget::minimum_cache_percent(physical, PreloadWindow::new(forward, backward))`, the maximum is `MAX_IMAGE_CACHE_RAM_PERCENT` (90). Do not duplicate the formula.
  4. **`try_save` is a staged pipeline, not atomic.** Order (also in the stub doc): shortcut pre-checks (mandatory then optional) -> every field row in table order (a refusal stops
     the pass, rows already applied STAY written: test `Save_FirstRefusalWins_AndEarlierRowsAreWritten`) -> `validate_shortcuts` -> action destination problem -> language ->
     store write -> live language switch. The preload counts and the auto-hide group are all-or-nothing only because their ROWS validate the group before writing (10b).
  5. **Two different shortcut messages.** A bad key name or a duplicate among MANDATORY shortcuts, or a junk non-empty OPTIONAL shortcut, gives
     `dialog.settingsInvalid.shortcuts`. An optional shortcut equal to a mandatory one passes those pre-checks and is refused later by the shared validator with
     `core.settings.shortcutDuplicate` (its own text). A test pins `NotEqual(shortcuts message)`.
  6. **Canonicalization happens inside the Shortcuts row (10b), not here.** `Save_ShortcutsAreCanonicalized` checks the working copy after `try_save`.
  7. **Store save.** `SettingsStore::save` takes the settings by value and returns the stored `Arc<AppSettings>`; the presenter then replaces its working copy with a clone of
     it (C# `Persist` mutated the same object: canonical shortcuts, `ConfigVersion`). A `SettingsSaveError` of any kind is `SaveFailed` with the error text.
  8. **Language.** With a localization service: `ui_language = to_setting(selected, current)`; after a successful save, `switch` runs only when `requested_language()` differs
     (case-insensitively) from the saved language. Without a service the language row is left alone.
  9. **Live preview.** `duplicate_shortcut_warning` builds a probe `AppSettings` from the typed boxes (NOT canonicalized) and the parsed actions, and runs the validator. The
     parse is cached by the exact text, also after a failure.
  10. **Pages.** `remember_page` stores any text; `initial_page_key` accepts it only if it is one of the seven keys. The memory is process-wide (a `Mutex<String>`, initial `"General"`);
      the test restores it in a `finally`-style guard.
  11. **Defaults.** 65 assignments (counted with grep on lines 293-326), then `load_fields()`. The language and the actions are NOT reset.
- Traps checklist:
  - **T1 Not atomic.** Do not copy the settings, apply, and commit on success. The C# test requires `InitialViewMode` already written when a later row refuses.
  - **T2 Int parsing.** NBSP (U+00A0), full-width digits, group separators, `+` alone, empty string and `None` all fall back. `str::trim` is wrong; use `try_int`.
  - **T3 Fallback per box.** A bad forward box must not change the backward box's value (and vice versa), and a bad box uses the SAVED value clamped to its range.
  - **T4 Math.Clamp order.** `v < min` -> `min`, then `v > max` -> `max`; `i32::clamp` would panic only if `min > max` (cannot happen here: `min <= 90`).
  - **T5 `Math.Round` is ties-to-even** (`toolbar_opacity_value_text`): `f64::round_ties_even`; `.5` rounds to the even integer. (Rust `round()` is wrong.)
  - **T6 `ToString("0.0")` in the current culture** (`format_gb`): one decimal, culture decimal separator, `"?"` when RAM is unknown. Use `viewport::types::format_fixed` for the
    half-away-from-zero rounding of .NET custom formats and substitute `ctx.numbers.decimal_separator`.
  - **T7 Case.** `requested_language` vs `ui_language`: `OrdinalIgnoreCase` (`pr_core::text::eq_ignore_case`), not `eq_ignore_ascii_case`. Shortcut distinctness: `pr_core::text::ignore_case_key`.
  - **T8 Thread.** UI thread only (the dialog's). `switch` publishes the new `Localizer` and must be on the UI thread. The store write blocks, like C#.
  - **T9 The localization mutex.** Lock `SharedLocalization` only around `switch`/`requested_language`/`discover_languages`; never call into the view while holding it.
  - **T10 Texts from `ctx`, never from `Localizer::current()`.** (The only exception is in 10e `reload_translations`.) D-W8-4: no literals except the log lines
    (`AppLog` messages are English diagnostics in C# too).
  - **T11 `ApplyDefaults` list.** It must not touch `ui_language`, `actions`, `config_version`, or any property not in the 65. A test asserts `UiLanguage == "vi"` and the action list survive.
  - **T12 `Settings` aliasing.** Tests that hold `presenter.settings()` across a `try_save` must re-read it (see note 7).
