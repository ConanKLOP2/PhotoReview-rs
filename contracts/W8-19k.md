## Semantics (C# is the spec; the doc comment of every stub function is part of it)
1. **Working form (`state.rs`).** `working_fields()` clones the presenter's `load_fields()` and keeps ONE action JSON: the stored `actions_json` when set (it overrides the freshly loaded value), else the loaded value which then becomes the stored one (so the first call fixes it). `actions_json()` is the stored value or the loaded one (stored on first read). `refresh_actions_json_from_pages()` = `collect_all().actions_json`, stored and returned. `collect_all()` = `working_fields()` then, per CREATED page in order, `page.collect(&mut state)`. `load_all(state)` stores `state.actions_json`, then loads every created page with `loading` set (the guard restores on every path), then `relayout_active_page` only when `active >= 0`. `set_actions_json(json, source_key)` stores `json`, builds `state = collect_all()` with `state.actions_json = json`, loads every created page whose `key()` differs from `source_key`, then `relayout_active_page`. A page that is already borrowed is skipped by all four (D-W8B5-904): this can only be the caller; no page's `collect` writes `actions_json`, so `collect_all` is unaffected, and the caller of `set_actions_json` is excluded by key anyway.
2. **Loading guard.** `LoadingGuard::new` stores `loading = true` and remembers the previous value; `Drop` restores that value (nesting-safe, panic-safe). While `loading` is `true`, `apply::handle_command` swallows page notifications (19l) and `activate_page`/`ensure_page_created` use the same guard around `page.load`.
3. **Control accessors (`dirty.rs`).** Each is the one-line C# body on `dialog.item(id)` (absent control: no-op, neutral answer). `set_control_text` doubles `&` only for a button (`NativeDialog::is_button(item(id))`). `set_combo_items` clears, adds, selects `combo_selection(len, selected)`. `set_slider_range` reads the position first, reconfigures `(min, max, 1, 1, slider_page_size)`, then writes `clamp(position, min, max)` back (`max`/`min` form). `set_control_tooltip_fn` = `set_item_tooltips(id, |_| Some(text()))` (the text is asked again on every show); `set_control_tooltip_text` = `set_tooltip(id, text)`. `set_control_visible`: ask each page builder `set_group_visible(id, visible)` in order, each through `try_borrow_mut` (`layout_page` holds a shared borrow while it places controls: a borrowed builder is skipped instead of panicking); the first `true` ends it (a group has its own flag); otherwise `hidden` gains or loses `id`; then `relayout_active_page`. `is_control_visible(id)`: a group's own flag, else `!hidden.contains(id)`; needs no window. `focus_control`: absent -> nothing; else `ensure_visible(id)` (19m) then `set_focus`. `relayout_active_page`: `active >= 0` -> `dialog.run_layout()`.
4. **Key capture (`keybox.rs`).** `key_box_text(vk, extended)` is `SettingsPresenter::capture_shortcut(key, key.name())` with `key = from_virtual_key(vk, extended)`; `None` for Tab, Esc, the modifiers, IME and dead-char markers (reserved keys). The golden `key_capture` rows pin it for `vk` 0..=255, both extended values. `resolve_virtual_key(wparam, imm)`: `vk = (wparam & 0xFFFF) as i32`; `vk == 229` (`VK_PROCESSKEY`) -> `real = imm()` and `real != 0` -> `real as i32`, else 229 (on Windows 11 the OS answers 229 itself with no key processed, which stays 229 and maps to a reserved key: nothing is written); `imm` is NOT called for any other key. `capture_key(hwnd, wparam, lparam)`: `id = get_dlg_ctrl_id(hwnd)`; `id == 0` or not a key box id -> `false`; text `None` -> `false` (the key stays with the dialog: Tab moves focus, Esc cancels); else `set_item_text(id, text)` (the OS sends `EN_CHANGE` synchronously and the page sees one edit, D-W8B5-805), `send_message(hwnd, EM_SETSEL, 0, -1)`, `true`.
5. **Key box subclass.** `hook_key_box(box)`: `box == 0` -> nothing; `imm_associate_context(box, 0)` (no IME context: a Telex IME can neither compose into the box nor swallow the key); `set_window_subclass(box, key_box_proc, KEY_BOX_SUBCLASS_ID, subclass_key)`. `key_box_proc` runs under `pending_panic::guarded(...)`: `WM_KEYDOWN`/`WM_SYSKEYDOWN` -> `from_subclass_key(ref_data)`; when it exists and `capture_key` answers `true` -> `0`; `is_swallowed_message(message)` -> `0` (the eleven messages of the doc: no text ever reaches the box except through `capture_key`; `WM_COPY` is NOT swallowed); `WM_NCDESTROY` -> `remove_window_subclass(hwnd, key_box_proc, id)`, then on to `def_subclass_proc`. The body must not borrow a page. `key_box_colors(hdc)` sets `DialogColors::text_strong()` / `DialogColors::input()` and answers the brush of `input()` (created lazily; `close::on_closed` deletes it).
6. **`PageHost` (`host.rs`).** One delegation per trait method, as the stub docs list. `upgrade()` fails or `with_native` answers `None` (window not shown yet or closed): the neutral values of `SettingsPageContext::detached()` (D-W8B5-705) and writes do nothing; `presenter()` answers the detached context's presenter (a thread-local) so the caller never panics; `ui_post()` answers a poster that drops. `open_url`: `options.open_url` else `default_open_url`; `start_explorer`: `options.start_explorer` else `SettingsPresenter::try_start_explorer`; `show_action_profiles`: the option or `Err(ActionProfilesUnavailable)`. `current_shortcut_texts()` = `collect_all().shortcut_texts` (a Shortcuts page that was never shown contributes the loaded texts). `warn` -> `apply::warn` (19l). `set_actions_json(json, source_key)` -> `state::set_actions_json`.
7. **`default_open_url(url)`.** Empty or whitespace-only `url` -> `Err("empty url")`-style text (no OS call). Else `ShellExecuteExW(&mut SHELLEXECUTEINFOW { cbSize, fMask = SEE_MASK_FLAG_NO_UI | SEE_MASK_FLAG_DDEWAIT, hwnd = 0, lpVerb = "open", lpFile = url, nShow = SW_SHOWNORMAL, .. })`; an `Err` -> `Err(format!("ShellExecute failed ({code})"))` with the Win32 error. Why not `ShellExecuteW`: .NET `Process.Start(UseShellExecute)` sets `SEE_MASK_FLAG_NO_UI` (no `ErrorDialog`), so a bad URL is an exception; plain `ShellExecuteW` pops the shell's own error message box on the UI thread. `SEE_MASK_NOCLOSEPROCESS` is NOT set (it would hand back an `hProcess` that must be closed: a handle leak). The strings are NUL-terminated UTF-16 locals that outlive the call; the call runs on the UI thread (STA), as the C# did. (D-W8-4: the error text is a developer message, not UI text: the page shows its own localized failure.)
8. **Borrow protocol (D-W8B5-904).** No method of this slice holds a `RefCell` borrow across a call that can re-enter: the presenter is borrowed for `load_fields()` only; the page list is iterated by index with a fresh `pages[i].try_borrow_mut()` per page; `hidden`/`placed` are never held across `relayout`.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T8 (null vs empty): `actions_json` `None` (not read yet) vs `Some("")` (an empty JSON the user typed through `set`) are different; `set_actions_json("")` stores the empty text (golden case `actions_json_default`).
- T9 (exception to Result): `ShellExecuteExW` failure is `Err(text)`; the C# `Process.Start` exception is the same branch; `imm_get_virtual_key` failure is `0`.
- T10 (order): `collect_all` and `load_all` iterate pages in navigation order; `set_control_visible` asks builders in navigation order.
- Re-entrancy: `capture_key` -> `set_item_text` -> `EN_CHANGE` -> dialog procedure -> `on_command` -> the page (not borrowed at that moment: the key arrives from the message loop, not from the page).
- `key_box_proc`, `forward_proc` (19l) and every other callback look the content up by registry key (D-W8B5-908): a lookup that fails passes the message on, never dereferences.
- Panic policy: `key_box_proc` runs under `pending_panic::guarded` (the message still goes to `def_subclass_proc` after a panic); nothing in `host.rs` panics (the weak upgrade, the borrows and the indices are all checked).
- R0003: no `unwrap`/`expect`/indexing; `ShellExecuteExW` is the only new `unsafe` call besides the subclass procedure and the three comctl wrappers.

## Safety rules (`// SAFETY:` per `unsafe` block)
`key_box_proc`: "installed by `hook_key_box` for a window of this thread; `ref_data` is a registry key, not a pointer; the arguments are those of the window message; `def_subclass_proc` is called with them unchanged". `default_open_url`: "`SHELLEXECUTEINFOW` is a live local with `cbSize` set; the NUL-terminated UTF-16 buffers outlive the call; null `lpParameters`/`lpDirectory` are allowed; no `hProcess` is requested". `set_window_subclass` / `remove_window_subclass` / `def_subclass_proc` (the `unsafe fn`s of `win32::comctl`): "`key_box_proc` is a plain `extern \"system\" fn` with the `SubclassProc` signature; the id and the registry key identify this content; removed on `WM_NCDESTROY`; `def_subclass_proc` gets the unchanged arguments". `send_message(EM_SETSEL)`: "integer-only message to a handle the OS validates".
