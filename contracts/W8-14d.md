## Semantics (C# is the spec)
1. **`has_files(data)`**: a `FORMATETC { cfFormat: CF_HDROP, ptd: null, dwAspect: DVASPECT_CONTENT, lindex: -1, tymed: TYMED_HGLOBAL }` and `data.QueryGetData(&format) == S_OK` (0 only; `S_FALSE` and `DV_E_FORMATETC` are `false`).
2. **`files(data)`**: `data.GetData(&format)`: `Err` gives `vec![]`. On `Ok(mut medium)`: always `release_stg_medium(&mut medium)` last (a drop guard, so every early return releases it). `medium.tymed != TYMED_HGLOBAL` or a null `hGlobal` gives `vec![]`. `global_lock(handle)` (`Err` gives `vec![]`); the bytes are `from_raw_parts(ptr, GlobalSize(handle))`; `parse_drop_files(bytes)`; `global_unlock(handle)` always (guard). The size bound is new (C# walked pointers with no bound); a medium that lies about its size cannot make the parser read past the allocation the OS reports.
3. **`parse_drop_files(block)`** (C# `Parse`): `offset = u32::from_le_bytes(block[0..4])`, `wide = i32::from_le_bytes(block[16..20]) != 0`; a block shorter than 20 bytes gives `vec![]`; the list is `block[offset..]` (`offset > len` gives `vec![]`). Wide: read `u16` units to the first NUL, an empty item ends the list, an unpaired trailing byte or an item without NUL before the end stops the list (items before it are kept); decode with `String::from_utf16_lossy`. ANSI: items are NUL-terminated bytes decoded with the system ANSI code page (`MultiByteToWideChar(CP_ACP, ..)`), same stop rules. Order is the data-object order. Duplicates are kept.
4. **Effects.** `DragEnter(data, key_state, pt, effect)`: `drag_has_files.set(data.is_some() && safe_has_files(data))`; write `*effect = DROPEFFECT_COPY` if so else `DROPEFFECT_NONE`; `Ok(())`. `DragOver`: write by `drag_has_files`. `DragLeave`: clear. `Drop`: clear the flag, write `DROPEFFECT_NONE` FIRST; read the files (`callbacks.files` or `files(data)`; a reader `Err` -> `on_failure(&e)` and `Ok(())` with the effect still None; no data object = no files); empty -> `Ok(())`; else write `DROPEFFECT_COPY` and call `open_path(&files[0])`; an `Err` from it -> `on_failure(&e)`. The answer is ALWAYS `Ok(())` (`S_OK`): a failure is reported through the callback, never as an HRESULT (the drag source must not show a failure). The key state, the point and the allowed-effects mask are ignored (C# parity; see open question 3).
5. **`safe_has_files`**: `callbacks.has_files` or `has_files(data)`; an `Err` is `false` (C# `catch COMException | InvalidOperationException`).
6. **Registration.** `register(hwnd)`: there is no argument check (as in C#): the OS fails `RegisterDragDrop(0)` with an error HRESULT, which becomes `Refused`. Already registered gives `Err(AlreadyRegistered)`. Else `ole32::ole_initialize()` (the result is ignored on purpose), then `ole32::register_drag_drop(hwnd, &self.object)`: `Err(h)` gives `Err(Refused(h))`; `Ok` stores the handle. `dispose()`: `hwnd != 0` -> `ole32::revoke_drag_drop(hwnd)` (the result is ignored), `hwnd = 0`; idempotent; `Drop` calls it. No `ole_uninitialize` anywhere (D-W8B4I-12 repeats the C# comment as a rule).
7. **COM object lifetime.** `DropTargetObject` is a windows-rs `#[implement]` object: `.into()` gives an `IDropTarget` that owns one reference; `RegisterDragDrop` `AddRef`s another and holds it until `RevokeDragDrop`; the callbacks (closures that capture `Rc`s of the main window) live as long as the object lives, so the object MUST be revoked before the owner of the captured state is dropped (T1). The object is created and used on the STA thread of the window only.
8. **Panic boundary (D-W8B3H-4, D-W8B4I-9).** Each `IDropTarget_Impl` method body runs under `host::pending_panic::guarded(Err(E_FAIL.into()), AssertUnwindSafe(|| ..))`: a panic in a callback is captured, the method answers `E_FAIL`, and the message loop resumes the panic with `rethrow_pending()` after `DispatchMessage` returns (the OLE call arrives from a message dispatched to this thread). Never let a panic unwind through the generated vtable function (Rust aborts).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (COM lifetime / drag-drop object): revoke BEFORE the HWND dies and before the callbacks' state is dropped; `Drop` = `dispose`; the registration holds a COM reference, so dropping the Rust handle alone does not free the object; the test `dispose_revokes_and_releases_the_callbacks` counts the callbacks' drop with a sentinel.
- T2 (HGLOBAL): lock and unlock balance on every path; the size comes from `GlobalSize`; the medium is released exactly once even when the parse stops early; `release_stg_medium` is `unsafe` (its `# Safety` says "filled by `GetData`, released once").
- T3 (DROPFILES layout): `pFiles` at 0, `pt` at 4 (8 bytes), `fNC` at 12, `fWide` at 16, header 20 bytes; the test builds blocks by hand.
- T4 (effects by pointer): `pdweffect` is `*mut`; the answer is WRITTEN through it (the recorder test of W8-11e guards the slot shape); a null pointer is ignored, not dereferenced.
- T5 (S_OK always): `Drop` never returns an error HRESULT for an open failure.
- T6 (threading): all calls on the registering STA thread; do not move the object across threads (`DropTargetObject` is `!Send` by its `Cell`/closures).
- T7 (`OleInitialize`): result ignored; never `OleUninitialize`.
- T8 (strings): `from_utf16_lossy` / ACP decode never panic; a path with an unpaired surrogate becomes U+FFFD (C# `new string(char*)` would keep the surrogate): documented difference, no row (paths from Explorer are valid).

## Safety rules (`// SAFETY:` per `unsafe` block)
(a) each `*mut DROPEFFECT` write: "non-null checked; the caller (OLE) passes a live DWORD for the effect for the duration of the call"; (b) `from_raw_parts` over the locked block: "the block is locked (`global_lock`) and `GlobalSize` bytes long; unlocked after the slice is dropped"; (c) the union access `medium.u.hGlobal`: "`tymed == TYMED_HGLOBAL` checked"; (d) `GetData`/`QueryGetData` COM calls on a live `IDataObject` owned by the caller for the duration of the call; (e) `release_stg_medium(&mut medium)`: "filled by `GetData`, released once"; (f) `MultiByteToWideChar` with exact buffer lengths from a first sizing call.

## Open questions (recommended default in bold)
1. **The effect ignores the source's allowed effects and the key state** (C# parity, a source that allows only Move would be told Copy and the drop would still run): **keep C#**; alternative: `*effect = incoming & DROPEFFECT_COPY` and honour Ctrl/Shift, a Different row.
2. **ANSI decode through `MultiByteToWideChar(CP_ACP)`** (needs `Win32_Globalization`): **yes**; alternative `String::from_utf8_lossy` (wrong for non-ASCII ANSI, the format is legacy and Explorer sends wide), which would be a Different row.
3. **`open_path` inline in the OLE callback** (see W8-14c Q3): **inline**, the callback decides.
4. **One COM object per target** vs one shared object: **per target** (the callbacks differ per window; a window can have only one target).
5. **`Win32_Globalization` vs `windows-sys`**: **the `windows` feature** (D36: only `pr-platform-win` depends on `windows`).
