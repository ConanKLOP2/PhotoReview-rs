- Decisions (D-W8-1 and D-W8-2 are settled here for the whole main view model):
  - **D-08a-1 One `ChangeSet` for the main window.** Every mutator returns `ChangeSet { main: MainChanges, viewer: ViewerChanges, overlay: InfoOverlayChanges,
    compare: CompareChanges, presenter: PresenterChanges, image_changing: Option<ImageChangingEventArgs>, catalog_changed: bool }`. `MainChanges` is a `u32`
    bit set over `MainProperty` (the 21 properties the C# code raises, verified from the `OnPropertyChanged` / `SetProperty` calls). It is NOT the
    `ViewerChanges` style: the view model also forwards the sub-models' sets and two C# events (`ImageChanging`, `CatalogChanged`). Order and repeat count of
    the C# notifications are not kept. `ChangeSet::merge` is the only combination operator.
  - **D-08a-2 The presentation bridge and the shared viewer.** The presenter owns its `IPresentationSink`; the sink callbacks of
    `composition::contracts::MainViewModelSinkCallbacks` cannot reach the view model. C# `NotifyCurrentImageChanged` must run synchronously inside the presenter
    call, BEFORE `apply_initial_view_mode` and `on_preview_presented` (W8-07h note 7). The callbacks therefore get a clone of `PresentationBridge`, which holds the
    shared `ViewerHandle` (`Rc<RefCell<ViewerState>>`, UI thread) and the state `_lastNotifiedImagePath`. It runs the viewer part inline, remembers the zoom for the
    sink's `take_viewer_zoom_change`, and collects the viewer changes, `image_changing` and a "navigation state is dirty" flag, which the view model drains
    after every presenter call (`finish_presenter_call`). This is the ONE sanctioned shared-state exception to D-W8-1; the RULE is "never hold a `borrow_mut` across a
    call into the presenter or a coordinator".
  - **D-08a-3 Construction.** C# AR14 built the three controllers inside the constructor because they needed the view model as their sink. With recorder sinks (D-08e-1)
    there is no cycle, so the composition root (W8-09b) builds `FolderLoadCoordinator`, `ImagePresenter`, `FileActionController`, `SiblingFolderNavigator`,
    `DuplicateCleanupController` and the `FileActionGate`, and passes them in `MainViewModelDeps`. `compare` lives inside the presenter. `hashService`, `thumbnailCache`,
    `naturalComparer`, `uiScheduler` and `sessionStore` are not needed by the view model; `sessionStore` was only used by the unreachable `PersistSession` fallback.
    The closures `() => Settings` and `RememberMoveCopyFolder` become `SettingsSource` (a shared handle: store + override cell) and the free function
    `remember_move_copy_folder`.
  - **D-08a-4 Events and the pump.** What C# resumed with `await` returns as a `MainEvent` through one `CompletionInbox<MainEvent>`. `MainWorkerPort<E>` adapts it to the
    `WorkerPort<E>` of each coordinator (`E` wrapped by `MainEvent::FolderLoad` / `FileAction` / `Duplicate`). `pump()` applies the inbox, then the presenter's pump, then the
    owed continuations; the shell's wake function posts it. `is_idle()` replaces the C# test seams (`FolderLoadTask`, `CompareToggleTask`, `SettingsRefreshTask`,
    `ReadabilityProbeTask`).
  - **D-08a-5 Hoisted helpers.** `persist_session` (C# 976) and `presented_path_of_current_entry` (C# 944) are in `state.rs`, not in 08d, because 08a, 08b and 08e use them.
    Their bodies are tiny; 08d does not re-implement them.
  - **D-08a-6 Pull model for the C# `ViewerState` hooks.** Lines 117 to 129 of C# (`ZoomModeChanged -> SetViewerZoom`, `PropertyChanged(DisplayZoomPercent) -> InfoOverlay.Refresh`) are
    `apply_viewer_update` for changes the view model makes, and the bridge's pull channel for changes made inside a presenter call.

- Semantics notes:
  1. **Constructor** (C# 55 to 138). Stores the collaborators; then `viewer.set_scaling_quality(settings.scaling_quality_or_default())`, `viewer.set_zoom_step(keyboard_zoom_step_percent / 100.0)`, and
     `presenter.set_viewer_zoom(viewer.effective_zoom())` (the returned `PresenterChanges` is dropped). Calls no sink, reads no file, starts no work. `FolderTitle` starts as `app.title`.
     The C# subscription to `ZoomDetail.RawDecodeIndicatorChanged` (which cached the flag and raised `StatusText` and `StatusNeedsAttention`) becomes the presenter's `RAW_DECODE_INDICATOR`
     bit; the flag is read live from `presenter.zoom_detail().is_raw_decode_indicator_visible()`.
  2. **`StatusText` getter.** Non-empty event text wins; else, with the RAW indicator visible and `!presenter.status_needs_attention()`, `status::decoding_raw`; else the presenter's text.
     The setter reports `StatusText` only when the stored event text differs (ordinal), and never `StatusNeedsAttention`.
  3. **`StatusNeedsAttention`.** RAW indicator, or event text non-empty, or presenter attention, or skipped entries (`||`, any one alone suffices).
  4. **Skipped entries.** `set_skipped_entries` always reports the four properties (also for an equal list); `SkippedWarningText` is empty without entries else the plural text `main.skipped.warning`.
     `IsStatusPanelVisible` = file-info visible (`InfoOverlayViewModel::is_file_info_visible(&settings)`), or `is_exif_line_visible()` (08e), or skipped entries.
  5. **`NotifyCurrentImageChanged`** is `PresentationBridge::on_set_current_image` (doc in the stub): order ImageChanging, new-image test (OrdinalIgnoreCase; two `None` are equal), force-HQ reset, swap
     versus set-source-size, then the dirty flag. A refresh of the SAME path is not a new image.
  6. **`Settings`.** `SettingsSource::current()` = override or store. `set_settings` installs the override and refreshes the overlay. `begin_edit` / `commit_edit` replace the C# in-place mutation
     of the live settings object (used by 08c `toggle_info_overlay` and 08e `remember_move_copy_folder`).
  7. **`current_has_compare_pair`** is `&mut self` (the presenter caches its compare index per `structural_version`). A path error (C# exception) is logged and gives false.
  8. **Capture badge.** `CapturePairBadge`: empty without a group; `main.capturePair.badge.raw` when the presented path equals the RAW path (OrdinalIgnoreCase), else `.jpeg`.
     `CapturePairBadgeToolTip`: bound text with the TRIMMED key when the configured text is not blank and valid for `key_names().is_valid_key_name(configured)` (validated untrimmed), else the unbound text.
  9. **`prewarm_initial_image`** reads the STORE settings (`store_current`), not the override, as C# `_settingsStore.Current`.
- Traps checklist (MULTI-AGENT-PLAN section 7; the items below are specific):
  - **T1 UI thread.** Everything here is UI-thread only; `MainViewModel` is not `Send`. Only `MainEvent` and `CompletionInbox` cross threads (`MainEvent: Send`).
  - **T2 Borrow discipline.** A `ViewerHandle::borrow_mut` held across `with_presenter` or a coordinator call panics inside the bridge. Write `let update = self.viewer.borrow_mut().zoom_in();` (the temporary ends at the `;`).
  - **T3 Split borrows.** `catalog`, `presenter`, `current_session` and `sink` are separate fields precisely so that `PresenterEnv { catalog: &mut self.catalog, session: self.current_session.as_mut(), .. }` and
    `FolderLoadCx { catalog: &mut self.catalog, sink: &mut self.sink }` compile. Never route them through a `&mut self` helper while the other is borrowed.
  - **T4 INV-9.** A `MainEvent` for a load, action or search that a newer one replaced is dropped by the coordinator (its `load_id` / `ticket` / generation), never by the view model; the view model does not cache
    generation numbers except `folder_load_epoch` (08b/08c).
  - **T5 Case-insensitive paths.** Path identity uses `pr_core::text::eq_ignore_case` (OrdinalIgnoreCase, W2-01); never `to_lowercase`.
  - **T6 Change-set exactness.** A property is in the set only when C# raised it. `set_status_text` must not report `StatusNeedsAttention`; `set_skipped_entries` reports its four always.
  - **T7 Text.** All user text comes from the catalog (D-W8-4): keys `app.title`, `main.skipped.warning`, `main.capturePair.*`, `main.folderInfo.*`. No literals except in tests.
  - **T8 No async, no wall clock.** Tests wait with `is_idle()` / `CompletionInbox::wait_ready` as a hang guard, never with sleeps (AGENTS.md).
  - **T9 Debug.** Every `pub` type derives or implements `Debug` (`missing_debug_implementations`): done in the stub (manual impls for the types holding closures or trait objects).

## Open questions (each has a recommended default; the stubs follow it)
- **O1 B1 changes owned by W8-07h (the lead applies them): ** `IPresentationSink::set_current_image(image: Option<PlatformImage>, is_file_change, &ImageChange<'_>)` and `take_viewer_zoom_change`, and the closure type of
  `composition::contracts::MainViewModelSinkCallbacks::set_current_image`. This unit assumes them: the callback calls `PresentationBridge::on_set_current_image(&change, is_file_change)`; the host sink's
  `take_viewer_zoom_change` calls `bridge.take_viewer_zoom_change()`; the `apply_initial_view_mode` callback calls `bridge.apply_initial_view(viewport, &settings)`; `set_status_text` calls `bridge.on_set_status_text()`.
- **O2 `WorkerLane` mapping.** `MainWorkerPort` ignores the lane and runs each job on a `BackgroundRunner` thread. The lane threads (R0003) are W8-09b / the platform layer; a lane-aware port can replace `MainWorkerPort`
  without changing the view model. Flag: `folder_load::state::WorkerPort` and `zoom_detail::{BackgroundRunner, CompletionInbox}` overlap in purpose (not resolved here).
- **O3 Local time.** No UTC to local conversion exists in `pr_core::time`; `FormatContextSource::to_local_time` is the seam (used by the title bar and the EXIF line, 08d/08e). The platform layer implements it
  (`TimeZoneInfo.Local`); tests pass the identity or a fixed offset.
