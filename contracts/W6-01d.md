# W6-01d: Explorer native view query and ordered item reading

- Color: 🔴 | Porter: **sonnet** (`unsafe` COM vtable calls, PIDL/BSTR ownership, cancellation) | C# spec baseline: `d92d6aae`
- Rust crate: `pr-platform-win`
- C# source (baseline): `src/PhotoReview.Platform.Windows/Explorer/ExplorerOrderService.cs`, limited to `QueryShell`, `TryReadNativeView`, `TryReadViewOrderBatched`, `ReadSortColumns`, `ReadGroupState`, and native-view result helpers.
- C# tests (baseline): `tests/PhotoReview.Integration.Tests/ExplorerNativeViewTests.cs`; fake COM objects/vtables cover native call behavior. `ExplorerOrderServiceTests.cs` supplies the opt-in live Explorer smoke set (W6-01c).
- Split rationale: these methods are inside the same 509-line C# service as scheduling. They are an independently testable synchronous query slice behind W6-01c's query delegate. Preserve a clear module/API boundary so the provider does not own raw PIDL or vtable mechanics.

## Scope and behavior

On the STA pump, find the matching shell window, ask its top-level browser service for `IShellBrowser`, query the active view and `IFolderView2`, and report unavailable/failure statuses with the baseline reason codes. Read count, ordered paths, sort columns and grouping. Prefer `IFolderView::Items(SVGIO_ALLVIEW | SVGIO_FLAG_VIEWORDER)` batched enumeration (at most 512 PIDLs per call) when it yields exactly the expected item count; otherwise use the baseline per-item `GetItem`/`IShellItem.GetDisplayName` fallback. Cancellation is checked between batches and items. Preserve progress counts, batch yields, status distinctions, and the exact behavior for failed/unknown sort/group metadata.

Every acquired COM reference, child/combined PIDL, and allocated name must be released on every exit path. A failed sort query is one Unknown column, while a successful zero-column query is an empty list. A failed group query is Unknown, not None. Do not guess a different strategy when the native enumerator is partial or fails; match the test oracle.

## Fake/native safeguards, hang guard, mutation expectations

- Keep the default tests on the existing fake shell/vtable harness; do not call a user's Explorer windows from unit tests. Any real-shell probe is a separately ignored `native` test, read-only, and bounded by the provider timeout and CI job timeout.
- No test may create/delete shell items or touch the Recycle Bin. For owned temporary fixtures, use unique temp directories and guaranteed cleanup.
- Time-box `cargo-mutants` to this unit. Mutations to read-order flags, count/fallback logic, sort/group failure distinction, cancellation checks, and release/free paths must be caught. Use leak/ownership assertions in fakes; record mutants requiring native OS instrumentation as unverified instead of running unsafe cleanup against user state.
