## Semantics notes (C# is the spec)
1. **State.** `generation` starts 0 and changes only in `recreate`. Size is `max(1, v)`, DPI scale `> 0 ? v : 1` (NaN gives 1). `max_frame_latency` is `clamp_frame_latency(value)` (1..=16). `is_warp` is set by `create_device`
   (true when WARP was used, either asked for or as the fallback). `max_bitmap_size` comes from the new context (16384 on feature level 11, 4096 on 9.3).
2. **`create_for_window`.** `hwnd == 0` is `InvalidArgument { param: "hwnd", message: "A window handle is required." }` BEFORE any COM call. Client size: `GetClientRect` (right - left, bottom - top); if the call fails the size stays 1x1.
   DPI: `GetDpiForWindow` (0 gives scale 1, else `dpi / 96.0`). Then `create_all`. The window is NOT required to be visible (the tests use a hidden `STATIC` window).
3. **`create_offscreen`.** Width below 1 is `ArgumentOutOfRange { param: "pixelWidth" }`, else height below 1 is `ArgumentOutOfRange { param: "pixelHeight" }`; both before any COM call. No swap chain, no wait handle, latency 1,
   `adapter_description` empty, `has_swap_chain` false. `prefer_warp: false` tries the hardware device first (keep-alive and performance tests).
4. **`create_device` order** (C# 257 to 288): `d3d11::create_device_with_fallback(prefer_warp)` (hardware with `BGRA_SUPPORT`, ANY failure falls back to WARP, a WARP failure is the error), `d2d::create_factory(0)` (single threaded),
   `d3d11::dxgi_device`, `d2d::create_device_and_context`, `max_bitmap_size`, `d2d::create_solid_color_brush(opaque white)`. The optional adapter override (D-W8B3R-6): when `prefer_warp` is false and `PHOTOREVIEW_RS_GPU_ADAPTER` parses
   ([`parse_adapter_index`]), `d3d11::create_device_on_adapter(index, DEFAULT_DEVICE_FLAGS)` is tried FIRST; its failure falls through to the normal path. The C# has no such switch.
5. **`create_swap_chain`** (window only): `dxgi::create_window_swap_chain(d3d, hwnd, width, height, max_frame_latency)` gives the swap chain, the waitable handle (owned, closed with the swap chain) and the adapter; `adapter_description` is
   `AdapterInfo::display()` or empty. The swap chain values are the production values fixed in `gfx` (D-W8B3G-3: FLIP_DISCARD, 2 buffers, STRETCH, IGNORE, waitable flag).
6. **`create_all`** is `create_device`, `create_swap_chain` when `hwnd != 0`, then `create_target` (12c). On any error the half-built state is dropped (C# left it for finalization).
7. **`end_draw`** (C# 177 to 182): `d2d::end_draw_hresult(context)` is the real HRESULT, then the `end_draw_fault` hook (if set) maps it. The hook runs for success too (the tests turn a success into `D2DERR_RECREATE_TARGET`). `classify_end_draw`
   checks `is_device_lost` FIRST, then `< 0` is `Failed`, else `Continue` (S_FALSE and other positive codes continue to Present).
8. **`present`** (C# 184 to 194): no swap chain returns 0 and does NOT call the hook; otherwise `dxgi::present_raw(swap_chain, sync_interval)` (flags 0), then the `present_fault` hook. The surface classifies with `dxgi::classify_present`.
9. **`recreate`**: `release_all`, `generation += 1`, `create_all`. Same hwnd, size and DPI; `live_bitmap_count` and both hooks survive. Bitmaps handed out before (cache tiles) stay valid COM objects of the OLD device until their holders drop them
   (`release_bitmap`, 12c); they are never drawn again because `TiledGpuImage::is_drawable(generation)` fails.
10. **`dispose`** is idempotent; after it every object getter (`context`, `brush`, `target`, `d3d_device`) is `Err(Disposed { object: "PhotoReview.Shell.Rendering.DeviceResources" })`, `end_draw` is `Err(Disposed)`, `present` returns 0 (no swap chain),
    `recreate` is `Err(Disposed)`. The numeric getters keep their last values.
11. **Errors.** A failing `gfx` call is `RenderFault::Device(GfxError { hresult, operation })` via `From`; the operation names are the `gfx` ones. `RenderFault` maps field by field to `RenderError` (`Device(e)` to `Device { hresult: e.hresult, operation: e.operation }`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (COM release order, D-W8B3G-7): `release_all` must keep the C# order: target and sync probe, wait handle, brush, context, device, factory, then `clear_state_and_flush(d3d)` WHILE THE SWAP CHAIN IS STILL ALIVE, then the swap chain, then the D3D device.
  The C# comment (lines 422 to 426) says that flushing after the swap chain is gone hangs forever on a CI runner (WARP + DWM). Rust struct field order alone does not give this: `release_all` takes each field out of `state` explicitly (`take()`), in this order.
- T2 (wait handle ownership): `gfx::dxgi::WindowSwapChain::frame_latency_waitable` is `Owned<HANDLE>`; it is closed when the swap chain is dropped. Do NOT `CloseHandle` it a second time. `frame_latency_wait_handle()` returns the raw value and 0 when there is no swap chain.
- T3 (thread affinity): the D2D factory is single threaded; the type is `!Send`. A keep-warm thread (12h) creates its OWN `DeviceResources` on its own thread and never shares it.
- T4 (integers, item 3): sizes are `i32` clamped to `>= 1`; casting to `u32` for the `gfx` calls is safe only after the clamp. Do not cast an unclamped value.
- T5 (hook semantics): the hooks see the REAL HRESULT and return the HRESULT to use; the surface must call `end_draw` / `present` of this type (never `gfx` directly) so the tests can inject faults.
- T6 (fallbacks): hardware failure falls back to WARP silently (no GPU, RDP, CI); do not turn it into an error, and set `is_warp` from the device actually used.
- T7 (nulls): `AdapterDescription` is `""` (not `None`) when unknown; `frame_latency_wait_handle` is `0` offscreen.
- T8 (exceptions to Result, item 9): the three C# throw sites (`ArgumentException` hwnd, `ArgumentOutOfRange` width and height, `ObjectDisposed`) are separate variants; do not merge `pixelWidth` and `pixelHeight`.
- T9 (UI-thread rule not enforced by the compiler): `windows` 0.62.2 marks the interfaces `Send`; the `PhantomData<*const ()>` field is what makes `DeviceResources` `!Send`. A test (`static_assertions`-style `fn assert_not_send`) is NOT possible without a new crate; a doc test with `compile_fail` is used instead.

## Safety rules (every `unsafe` block gets `// SAFETY:`)
- Expected `unsafe` is small, because `gfx` owns the FFI: `GetClientRect` / `GetDpiForWindow` calls with a window handle the caller supplied (SAFETY: both accept any handle value and fail cleanly for an invalid one; the out parameter is a local `RECT`).
  The `HWND` is built with `gfx::com::hwnd(raw)`.
- No raw pointer is stored. COM interfaces are owned values (`Drop` releases). `state` is borrowed mutably only inside one method call and never across a call into `gfx` that can re-enter this type (no callbacks exist), so `RefCell` cannot double-borrow.
- `Rc<DeviceResources>` clones live on the UI thread only.

## Error mapping to `RenderError`
`RenderFault` has the variants of `RenderError` that this layer can raise; the `pr_app` adapter (after the layering PR, D-W8B3R-1) converts `Disposed`, `InvalidOperation`, `InvalidArgument`, `ArgumentOutOfRange` unchanged and
`Device(GfxError { hresult, operation })` to `Device { hresult, operation }`. A device loss is never an `Err` of `end_draw` / `present` / the surface `resize`; those return the HRESULT and the surface recreates (W8-12d).
