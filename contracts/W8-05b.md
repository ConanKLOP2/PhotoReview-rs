## Public API (stub, do NOT change signatures)
  ```rust
  pub const KEY_ID_NAMES: &[(&str, u8)];                       // 202 rows, C# declaration order, aliases included
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
  pub struct KeyId(u8);                                       // private field; raw WPF value 0..=172
  impl KeyId {
      pub const NONE: KeyId = KeyId(0); /* ... 202 associated consts, one per declared C# name ... */
      pub const fn value(self) -> i32;                        // C# (int)key
      pub fn from_value(value: i32) -> Option<KeyId>;         // Enum.IsDefined((KeyId)value)
      pub fn name(self) -> &'static str;                      // Enum.GetName, canonical name
      pub fn from_name(name: &str) -> Option<KeyId>;          // Enum.TryParse(name, false) + IsDefined, names only
      pub fn from_name_ignore_case(name: &str) -> Option<KeyId>; // same with ignoreCase: true
  }
  ```
  Const naming rule (generated, do not rename): insert `_` before each uppercase letter that follows a lowercase letter or a digit,
  then uppercase. Examples: `Return` -> `RETURN`, `NumPad0` -> `NUM_PAD0`, `OemOpenBrackets` -> `OEM_OPEN_BRACKETS`, `LWin` -> `LWIN`,
  `Oem102` -> `OEM102`, `D0` -> `D0`, `Pa1` -> `PA1`, `DbeSbcsChar` -> `DBE_SBCS_CHAR`. The stub already contains all 202 consts.
  `KeyId` is a newtype, not a Rust `enum`: a Rust enum cannot hold two variants with one discriminant, and aliases must be equal values.

## Semantics notes
1. **Table.** `KEY_ID_NAMES` is the C# declaration list in order (202 rows, the stub is generated from the C# file; the porter does not retype it).
   The golden `declared` cases pin the order. Rust twin test compares index by index.
2. **Values.** `value()` is the raw number (`(int)key`). `from_value(v)` is `Some` exactly for 0..=172 (golden `from_value`, inputs
   -2147483648, -1, 0, 1, 6, 8, 171, 172, 173, 255, 2147483647).
3. **Aliases are one key.** `KeyId::ENTER == KeyId::RETURN` (equal raw values, derived `Eq`). Each alias const carries a doc line
   "Declared alias of `X`" in the stub. Do not add a second value for an alias.
4. **`name()` = `Enum.GetName`.** For 173 values there is one canonical name. .NET does not promise which alias `GetName` returns when
   several names share a value; the baseline runtime's answer is what the golden `canonical` cases record (declaration-first for
   example would give `Return`, `Capital`, `Prior`, `Next`, `Snapshot`, `Oem1`; the golden decides). The porter adds a private
   `const CANONICAL_NAMES: [&str; 173]` in `key_id.rs`, one entry per value 0..=172, copied from the golden `canonical` cases, and
   `name()` indexes it. Do not compute it by searching `KEY_ID_NAMES` unless the golden matches the first-declared rule.
5. **`from_name` is names only, exact and ordinal.** Matching is case-sensitive (`"tab"` is `None`, `"Tab"` is `Some(TAB)`).
   Surrounding whitespace is ignored as `Enum.TryParse` does: the Rust code uses `str::trim()`. The golden probes contain ASCII spaces, tab,
   CR, LF, NBSP (U+00A0) and ideographic space (U+3000); if one of them disagrees with `str::trim()`, the golden wins and the difference goes
   into the PARITY note. NUL is not trimmed (`"Tab\u0000"` is `None`). Empty and whitespace-only strings are `None`.
   Numbers (`"6"`, `"-6"`) and comma lists (`"Tab,Back"` is `Some(3)`, tokens are OR-combined then `Enum.IsDefined` applies; the golden decides) are NOT probed by the golden and `from_name` returns
   `None` for numbers. C# `Enum.TryParse("6")` gives 6: that is the caller's job (`ShortcutKeyName` rejects numbers, `KeyIdMapping.TryParse`
   handles them). This is a documented boundary, not a Different row (open question 4).
6. **`from_name_ignore_case`** uses `pr_core::text::eq_ignore_case` (OrdinalIgnoreCase) on each table name. Never `to_lowercase`,
   never `eq_ignore_ascii_case`. Two non-trivial probes are in the golden: `cap\u0131tal` (dotless i U+0131) and `CAP\u0130TAL` (dotted I
   U+0130), `\u017fpace` (long s), and `\u212a` (Kelvin sign for `K`): the `pr_core` table folds none of them to ASCII, so `None` is the
   expected answer, and the golden confirms it. Plain `k` matches `K`.
7. **Lookup shape.** A linear scan over `KEY_ID_NAMES` (202 entries, called on the input path, not per frame) returns the value of the first
   matching row. Same-named rows do not exist (checked when the table was generated), so the first match is the only match.
8. **No clock, no I/O, no `unsafe`, no `windows` crate.** No allocation is needed; the functions take `&str` (C# `string?` null is not
   representable: callers map `None` themselves).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- Item 1: `OrdinalIgnoreCase` through `pr_core::text::eq_ignore_case`, never `to_lowercase` (semantic note 6).
- Item 8: `Enum.TryParse(null)` and `Enum.TryParse("")` are both "not found" in C#; `from_name("")` is `None` here.
- Item 10: `KEY_ID_NAMES` is a `&[...]` slice, iterated in order; never a `HashMap` for the lookup, so the first-match rule is stable.
- Item 9 (exception to Result): none. `Enum.TryParse` never throws on a string; the Rust functions return `Option`.
- Enum-with-discriminants trap: a Rust `enum` would not compile with 29 aliases. Do not "simplify" the newtype into an enum.
- Name trap: the consts are SCREAMING_SNAKE. `LWIN` (not `L_WIN`) is the name `ShortcutKeyName.IsReserved` will use (W8-04c, W8-05d).
- Value trap: `NoName = 169` and `DeadCharProcessed = 172` are real WPF values (the 172 is the table maximum); `CapsLock` and `Capital` are both 8.
- Trim trap: the `"\u00a0F1"` probe is valid in .NET `Enum.TryParse` only if .NET trims NBSP; the golden answers it, do not assume.
