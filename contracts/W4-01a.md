- Semantics notes:
  1. **Why `&dyn FileSystem` and `KeyOptions`.** C# `new FileInfo(path)` stats the real disk; the Rust key takes the `FileSystem` seam
     (`get_file_stat`) so cache tests run on `FakeFileSystem`. C# default arguments (`orientationApplied = true`, `backend = Wpf`,
     `sourceKind = 0`) become `KeyOptions::default()`. The four C# `Create` overloads map 1:1: string+width => `create_width_only`;
     string+box => `create`; `FileInfo` => `create_from_stat(full_name, stat, ...)`; `CatalogEntry` => `create_for_entry`.
  2. **Path normalization.** key path = `to_upper_invariant(get_full_path(x))` with `x` = the caller's path (stat overload: `full_name`). Use
     `pr_core::text::dotnet_path::get_full_path` and `pr_core::session::store::SessionStore::to_upper_invariant` (maps `U+017F` to `S`, leaves
     `U+0131 ı` and `ß` unchanged; do NOT use `str::to_uppercase`, which turns `ı` into `I` and `ß` into `SS`). It is the same helper
     `SessionStore::session_key` uses; if the lead hoists it to `pr_core::text` first, import from there. The result is NOT a valid on-disk
     spelling, only an ordinal identity; `matches_current_source` still stats it (Windows file systems are case-insensitive).
     Spellings from the property test (`C:/Pics/A.jpg`, `c:\pics\a.JPG`, `C:\Pics\.\A.jpg`, `C:\Pics\Sub\..\A.jpg`) all give `C:\PICS\A.JPG`.
  3. **Stat once.** `create` does `get_full_path` then exactly ONE `fs.get_file_stat`; `create_from_stat` does none. `None` from `get_file_stat`
     (missing, directory, unreadable) => `CacheKeyError::SourceNoLongerExists { full_name }` where `full_name` is the full path before
     upper-casing. `length` = `stat.length` saturated to `i64::MAX` (C# `long`); ticks = `stat.last_write_utc.ticks()`.
     `get_full_path` failures => `CacheKeyError::InvalidPath(err)` (`ArgumentException` for empty / spaces-only / NUL; `PathTooLongException`).
  4. **Entry fast path.** `create_for_entry`: when BOTH `entry.length` and `entry.last_write_utc` are `Some`, build from them with no stat
     and NO existence check (a missing file yields a key). Otherwise (either is `None`) call `create` with `entry.path()` (stats the disk and may
     return `SourceNoLongerExists`). `entry.length` is `i64`; ticks come from `DateTimeUtc::ticks()`; negative lengths are kept as is.
  5. **Original mode.** The constructor forces `target_width = target_height = 0` when `is_original`, whatever box was passed; a preview key keeps
     the box exactly as given, including negative sides (no clamping; golden `box-negative-preview-kept`). `target_box()` is built from the
     two stored sides. `create_original` and `create_original_with_kind` copy path, length, ticks, orientation and backend from the source,
     set `is_original = true`, box 0 x 0, and (second form only) replace `source_kind`; neither touches the file system. An already-Original
     source gives an equal key (golden `original-of-already-original`).
  6. **Equality and hash.** Derived over all 9 fields (path compared ordinally: it is already upper-cased). `source_kind` is any `u8`; `backend`
     is the `DecoderBackend` enum (`Wpf=0, WicDirect=1, TurboJpeg=2, LibRaw=3`). A key that differs only in `backend` or `source_kind` or
     `orientation_applied` is a different key (INV-12).
  7. **Persistence hand-off (byte-identical rule).** The key has no text form. `PreviewImageService.GetDiskCachePath` (W4-14c) builds the cache
     file name by hashing `preview-v5-box|{Path}|{Length}|{LastWriteUtcTicks}|{IsOriginal}|{W}x{H}|{OrientationApplied}|{Backend}` and appends
     `|kind{N}` when `SourceKind != 0`, where `{IsOriginal}`/`{OrientationApplied}` print `True`/`False` and `{Backend}` prints the enum NAME.
     That is W4-14c's job; this unit only guarantees the getters return exactly the values C# held (path upper-cased, ticks, `u8` kind).
     Do NOT add a `Display` or hashing helper here.
  8. **Error text.** `Display` of `SourceNoLongerExists` is the English `"Image source no longer exists"` (the C# exception message). The UI sentence
     is catalog key `err.io.sourceNoLongerExists` with `{path}` = `full_name`; the caller (pr-l10n side, W4-14) produces it with
     `pr_l10n::template::localized_io`. This crate does NOT depend on pr-l10n. `From<CacheKeyError> for io::Error` exists for callers that
     propagate through `io::Result` (kind `NotFound` for the missing source, as C# `FileNotFoundException` is an `IOException`).
  9. **`matches_current_source`.** `fs.get_file_stat(Path::new(self.path()))`: `Some(stat)` with equal length (as `i64`, saturated) and equal
     ticks => true; `None` or any mismatch => false. No panic path; C#'s `catch (IOException)` / `catch (UnauthorizedAccessException)` are the
     `None` branch of the seam.
- Traps checklist: §7 items 1 (path identity is ordinal after upper-casing: no `to_lowercase`), 2 (`ToUpperInvariant`, never the user's culture),

## Open questions
- **Where `to_upper_invariant` lives.** It is an associated fn of `SessionStore` (pr-core). Recommended (used by the stub): import it from
  there; the lead may hoist it to `pr_core::text` before W4-14c/W4-09 also need it (they hash the same upper-cased path). Alternative: a private
  copy here (duplicates the `ſ` special case). No behaviour impact.
- **One error enum.** W4-01b plans "exceptions become one error enum". Recommended: keep `CacheKeyError` in `cache_key.rs` (two variants, no
  dependency on the other unit) and let the lead re-export or convert (`From`) when the shared enum lands. Alternative: move both variants into
  W4-01b's enum now (couples the two units' merge order).
- **`FileInfo.FullName` with a trailing separator.** `new FileInfo(@"C:\a\b.jpg\")` keeps the separator in `FullName` and so in the key path;
  `PhysicalFileSystem::get_file_stat` trims one separator before stating (W2-14 contract), which matches `FileInfo.Exists`. No golden case:
  production callers never pass one. If a porter finds a difference, add the case to the golden first.
