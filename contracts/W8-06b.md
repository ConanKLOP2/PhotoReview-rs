## Semantics (each one is a C# behaviour a golden or a test checks)
1. **InfoOverlayAutoHidePolicy.must_stay_visible** = `!enabled || !folder || attention || compare || !active`.
   **evaluate**: `hidden = !must_stay && idle`; `opacity = hidden ? 0.0 : 1.0`; `is_hit_test_visible = !hidden`.
   **delay_ms** = `info_overlay_auto_hide_delay_ms` clamped to `[0, 10000]`, never the toolbar value.
2. **ToolbarAutoHidePolicy.must_stay_visible** = `!enabled || !folder || popup || focus`. **is_shown** = `must_stay || mouse_inside`.
   **delay_ms** = `toolbar_auto_hide_delay_ms` clamped to `[0, 10000]`. **target_opacity(p)** = `p.clamp(20, 100) as f64 / 100.0`
   (integer clamp first, then the division in f64). **is_inside_hot_zone**: closed box inflated by `margin`:
   `x >= left - margin && x <= left + width + margin && y >= top - margin && y <= top + height + margin`.
3. **FadeTargetGate.try_change(t)**: `false` when `self.target == Some(t)` in IEEE `==` (so `0.0` and `-0.0` are equal, `NaN` never);
   otherwise store `Some(t)` and return `true`. The first call always returns `true`.
4. **ImageTransitionDecision.should_transition(prev, new, compare)**: `false` if `compare`; `false` if `new` is `None`; `false` if `prev`
   is `None`; otherwise `!eq_ignore_case(prev, new)`. `Some("")` is a value (not `None`).
5. **InfoOverlayViewModel: settings, view inputs and folder.** The C# `Func<>` seams become the `settings` and `inputs` arguments of every
   call (state is a pure function of the arguments). Read-only accessors evaluate live from the arguments: `FontSize` is the stored
   `info_overlay_font_size` (NOT clamped here), `ExifFontSize = FontSize - 1.0`, `IsFileInfoVisible = show_info_overlay && show_file_info`,
   `IsFolderInfoVisible = show_info_overlay && show_folder_info && folder.is_some()`, `IsZoomIndicatorVisible = show_zoom_indicator && has_image`,
   `ZoomIndicatorText = format!("{}%", zoom_percent)` (plain decimal, `-5%` for negatives).
6. **set_folder(folder)**: (a) bump `request` and clear `pending_folder` (always, even if the folder is unchanged); (b) store `folder`,
   with `None` when the input is `None` or only whitespace (`trim().is_empty()`); (c) clear `siblings_folder` and `siblings`; (d) `refresh`.
7. **refresh(settings, inputs)**: first the six notifications `IsFileInfoVisible, IsFolderInfoVisible, FontSize, ExifFontSize,
   IsZoomIndicatorVisible, ZoomIndicatorText` are added to `changes` (ALWAYS, whatever the value). Then:
   - (a) folder `None` or folder block disabled: bump `request`, clear `pending_folder`, set text to `""`;
   - (b) `siblings_folder == Some(folder)` (exact `==`, C# `Ordinal`): text = `format(folder, siblings)`;
   - (c) otherwise: text = `current(display_name(folder)) + PART_SEPARATOR + pending()`; if `pending_folder != Some(folder)`, bump
     `request`, set `pending_folder = Some(folder)` and return `search = Some(SiblingSearch { folder, request })`. A search already pending
     for the same folder is NOT started again and the request number is NOT bumped.
   The text is written BEFORE the search is returned. `FolderInfoText` is added to `changes` only when the new text differs from the old one.
8. **format(folder, siblings)**: parts in order: `previous(key, display_name(prev))` if `siblings.previous` is `Some` and the previous key is
   non-blank; `current(display_name(folder))`; `next(key, display_name(next))` if `siblings.next` is `Some` and the next key is non-blank.
   Key text = the shortcut trimmed (`str::trim`, same Unicode set as `string.Trim()`); a blank shortcut counts as absent. Parts are joined with
   `PART_SEPARATOR`.
9. **complete_search(search, outcome)**: (a) `Cancelled`: no change, return an empty refresh; (b) `search.request != self.request`: stale,
   return an empty refresh; (c) otherwise: `pending_folder = None`, `siblings = Found(s)` or the default for `Failed`, `siblings_folder =
   Some(search.folder)`, then `refresh(settings, inputs)` (which takes the formatted branch, so no new search).
10. **display_name(folder)**: remove ONE trailing `\` or `/` unless the path is a root (`C:\`, `\`, `/`, a path whose only separators are
    the leading root); take the text after the last `\` or `/`; if that text is empty, return the INPUT unchanged. Do not use `std::path`
    (its separator rules depend on the host OS).
11. **InfoOverlayChanges** holds the `InfoOverlayProperty` values as bits; `iter` yields them in enum order, which is the C# raise order.

## Traps (MULTI-AGENT-PLAN section 7 items 1, 3, 4, 8, 9, 10 apply; the items below are specific to this unit)
- **T1 NaN in the fade gate.** C# `_target == target` is IEEE `==` on `double?`: a `NaN` never equals a stored value, so every `NaN` starts
  a fade. Do not compare with `to_bits`, `total_cmp` or a derived struct equality that treats NaN as equal. `Option<f64> == Some(t)` in Rust
  already has the IEEE behaviour: use it.
- **T2 Two string comparisons.** `siblings_folder == folder` is C# `StringComparison.Ordinal`: exact `==`, case-sensitive.
  `ImageTransitionDecision` is `OrdinalIgnoreCase`: `pr_core::text::eq_ignore_case`, never `to_lowercase`. The golden covers both
  (`C:\photos\A.JPG` against `a.jpg` is the same file for transitions, a different folder key for siblings).
- **T3 Integer clamp, then divide.** `TargetOpacity` clamps the INT percent to `[20, 100]` and divides by `100.0`. `(p as f64).clamp(...)`
  before the division gives the same value, but write it the C# way (integer `clamp`, then `as f64 / 100.0`).
- **T4 Hot zone arithmetic.** Use the same operand order (`left + width + margin`, computed left to right). A NaN operand makes the
  comparison false, so the result is `false`; never use `f64::clamp` or `min`/`max` on these coordinates (their NaN handling differs).
- **T5 `IsNullOrWhiteSpace` and `Trim`.** .NET `Char.IsWhiteSpace` and Rust `char::is_whitespace` agree on the characters that matter here
  (`str::trim` and `trim().is_empty()` use the Unicode `White_Space` property, the same set as .NET's Zs, Zl, Zp plus the control whitespace).
  The golden holds `"   "` and `" PageUp "` cases. Do not write `trim_matches(' ')`.
- **T6 Null versus empty.** `None` means C# `null`; `Some("")` is a real value. For the folder, `""` and `"  "` both become `None`
  (`IsNullOrWhiteSpace`), but for the transition decision `""` is a path (it compares unequal to `"a.jpg"`).
- **T7 display_name.** One trailing separator is removed, not all of them (`C:\photos\trip\` gives `trip`; `C:\photos\\` gives the whole
  input because the trimmed text ends in a separator and the name is empty). A drive root is not trimmed (`C:\` gives `C:\`).
- **T8 Notification order and "changed".** The six notifications are always added and come first. `FolderInfoText` comes last and only
  when the text changed. The golden `raise order` cases check this sequence.
- **T9 Request counter.** Every cancel bumps `request`, including the cancel that happens on every hidden `refresh` even when no search
  is pending. A result for an older request is dropped. The same folder re-requested after a hide gets a new request number.
- **T10 Failed versus Cancelled.** `Failed` = any finder error: the folder is shown with NO siblings (never the placeholder). `Cancelled`
  changes nothing. The Rust type makes this explicit; do not map both to "no siblings".
- **T11 Placeholder before the request.** The text is set to the placeholder before the `SiblingSearch` is returned, so a caller that
  completes the search on the same thread cannot see a late placeholder overwrite the answer.
- **T12 Live reads.** `set_settings` and `set_view` in the golden change no notification; the accessors read the NEW values at once
  (C# property getters poll the settings). Pass the current `settings` and `inputs` on every call.
