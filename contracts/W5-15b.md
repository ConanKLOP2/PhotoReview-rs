## Semantics notes
1. **Outcome invariant.** `reason` is `Some(non-empty)` exactly when `available` is false. Every reason below has a fixed prefix, so even an empty exception message yields a non-empty reason.
2. **`probe_with`** (C# `RunProbeCore`): `try_load()` is `None` => `ProbeOutcome::unavailable("Could not load {dll_name} (missing, incompatible architecture, or dependent runtime unavailable).")`, no `free`, no `probe_loaded`. Otherwise run `probe_loaded(&handle)` and return its result; `free(handle)` runs exactly once on EVERY exit including panic unwinding (C# `try/finally`): hold the handle in a private guard struct (`Option<H>` + `Option<F>`, `Drop` calls `free`). No `catch_unwind` in production code. The probe loads the library once to test it and frees that handle; the P/Invoke imports resolve it again independently (as in C#): do not hand the handle to the decoder.
3. **`probe_loaded_library`** (C# `ProbeLoadedLibrary`), strictly in this order:
   1. `missing = required_exports().filter(!lib.has_export(name))`, every name probed, in the sorted order. Non-empty => `"{display_name} does not export the required LibRaw entry point(s): {missing joined by \", \"} (wrong or stale library)."` (nothing else is called).
   2. `lib.version()`: `Err(e)` => `"{display_name} loaded but failed to initialize: {e}"`. `Ok(v)`: `check_version(v.as_deref(), display_name)` `Some(problem)` => that text is the reason; `init_and_close` is NOT called (a wrong library must never be initialised).
   3. `lib.init_and_close()`: `Err(e)` => `"{display_name} loaded but failed to initialize: {e}"`; `Ok(false)` => `"libraw_init returned a null decoder handle."` (C# returns before `close` since there is nothing to close); `Ok(true)` => `ProbeOutcome::ok()`.
   C# catches only `DllNotFound`/`BadImageFormat`/`EntryPointNotFound`/`InvalidOperation` inside steps 2-3; anything else reaches `GuardProbe`. In Rust an `Err` from the trait is the whole caught class, a panic is the uncaught class.
4. **`check_version`** (C# `CheckVersion`): `try_parse_version` fails => `"{display_name} reported an unreadable LibRaw version '{version}'."` with the version text (`None` prints as an empty string, so `''`). Parsed but `major != 0 || minor != 22` => `"{display_name} is LibRaw {version} but this build requires 0.22.x (run tools/fetch-libraw.ps1)."` The "0.22" in the text is `{REQUIRED_MAJOR}.{REQUIRED_MINOR}`; keep the literal `.x (run tools/fetch-libraw.ps1)` suffix. Patch and suffix play no role here, so `0.22.0`, `0.22.9-Release` pass.
5. **`try_parse_version` / `check_exact_version` quirks** (C# `Split('.')` + `int.TryParse(.., NumberStyles.None, InvariantCulture)`):
   - Split on `'.'` keeps empty parts: `"0..2"` => parts `["0", "", "2"]` => minor fails. `""` and `"0"` have fewer than two parts => fail.
   - `NumberStyles.None` = ASCII digits only: no sign (`+0`, `-1`), no surrounding whitespace (`" 0.22.2"`, `"0. 22.2"` fail), no non-ASCII digits (Arabic-Indic `\u0662` fails), leading zeros fine (`"00.22.2"`, `"0.022.2"` pass). Overflow of `i32` fails (`"0.2147483648"`, `"2147483648.0"`). Rust `str::parse::<i32>` accepts a leading `+`: check `bytes().all(is_ascii_digit)` and non-empty FIRST.
   - Only the first two parts matter to `try_parse_version`; the third is untouched (`"0.21.4-Release"` => `(0, 21)`), but `"0.22-Release"` fails because the minor part is `"22-Release"`.
   - .NET `int.TryParse` tolerates TRAILING `'\0'` characters after the digits even with `NumberStyles.None` (`Number.TrailingZeros`), so `"0.22\0"` should give `(0, 22)` and `"0.22.2\0"` exact true, while an inner NUL (`"0\0.22.2"`) fails. Golden versions 44..46 (`0.22\0`, `0\0.22.2`, `0.22.2\0`) settle it: the oracle output wins. Real LibRaw returns a C string, so this only matters for the golden.
   - `check_exact_version`: needs `try_parse_version` ok with `(0, 22)`, AND `split('.')` with at least 3 parts (`"0.22"` false, `"0.22."` true count but empty patch => false), patch = the leading run of ASCII digits of part 3 (`char.IsAsciiDigit`), empty run or `i32` overflow => false, value must equal 2. `"0.22.2-Release"`, `"0.22.2abc"`, `"0.22.02"`, `"0.22.2.5"`, `"0.22.2\n"` are TRUE; `"0.22.+2"` false.
6. **`compute_exact_version`**: `probe()` first; `Ok(false)` => false and `version` NOT called; `Ok(true)` => `check_exact_version(version()?.as_deref())`. Any `Err` => false (C# comment: a `Lazy` must not cache a throwing exception). Panics propagate. `is_exact_pinned_version` caches the result for the process: `OnceLock<bool>`, closure `compute_exact_version(|| Ok(probe().available), || Ok(native::version_string()))` (W5-15a's `version_string()` returns `Option<String>`, NOT a `Result`; the closure supplies the `Ok`).
7. **`required_exports`**: `native::ENTRY_POINTS` (23 names, includes `libraw_version`) + `"libraw_version"`, de-duplicated, sorted by ordinal comparison (`Vec::sort_unstable` + `dedup` on `&str` is ordinal; every name is ASCII), cached in a `OnceLock<Vec<&'static str>>`. The missing-export list in semantics 3 therefore comes out sorted.
8. **Caching** (`probe`): `static PROBE: ProbeCache`; first call runs `guard_probe(native::LIBRARY_NAME, || Ok(probe_with(..)))`, later calls (any thread) return the same `&'static ProbeOutcome`. The answer never changes later in the process even if the DLL appears or disappears (documented C# behaviour; the Settings UI and the composition rely on it).
9. **`guard_probe`**: `Ok(o)` => `o`; `Err(e)` => `"{dll_name} probe failed: {e}"` (C# `$"{LibraryName} probe failed: {ex.Message}"`). Panics propagate. The `dll_name` parameter replaces `LibRawNativeMethods.LibraryName` so the seam needs no `native` import.
10. **Never panics, never errors out of `probe`** when the DLL is absent (CI): `available == false` with a reason. This is the "degrade like the C# availability probes" rule (`RawCorpus.RequireNative`).
11. **No `unsafe` in the logic**, only the two adapter blocks of item 13 (FFI/unsafe is only allowed in the three decoder crates); no Windows-only dependency, so every fake-based test runs on any host.
13. **Real wiring (W5-15a API as drafted)**: `native::LibraryHandle` is RAII (`Drop` = `FreeLibrary`), so `probe()` is `guard_probe(LIBRARY_NAME, || Ok(probe_with(LIBRARY_NAME, || LibraryHandle::load_next_to_exe(LIBRARY_NAME).ok(), drop, |h| probe_loaded_library(&HandleLibrary(h), LIBRARY_NAME))))` (`drop` is the `free` step; the guard struct of item 2 still calls it exactly once). W5-15a has NO `impl LoadedLibrary`, so the adapter is owned HERE: a private `struct HandleLibrary<'a>(&'a native::LibraryHandle)` in `availability.rs`: `has_export` => `LibraryHandle::has_export`; `version` => `unsafe { call_version() }` where `None` (not exported) => `Err("libraw_version is not exported")`; `init_and_close` => `unsafe { call_init_close() }` where `None` => `Err("libraw_init/libraw_close is not exported")`. Each `unsafe` block has a SAFETY comment (every export was verified by `probe_loaded_library` step 1 before these run; `init_and_close` only runs after the version check). They sit in `pr-libraw`, one of the three crates allowed FFI/unsafe. If the lead prefers zero `unsafe` here, W5-15a must add `impl LoadedLibrary for LibraryHandle` instead (lead decision). The kernel32 test uses `LibraryHandle::load_system("kernel32.dll")`.
12. **Loading policy** (C# `[assembly: DefaultDllImportSearchPaths(AssemblyDirectory)]`, comment: a planted `libraw.dll` in the working directory or on PATH must not be loaded): enforced by W5-15a's `LibraryHandle::load_next_to_exe`; this file must not load libraries itself.

## Traps checklist (MULTI-AGENT-PLAN section 7)
- Free exactly once on all paths, zero times when the load failed (tests check both counts, plus the panic path).
- Version parsing: `NumberStyles.None` (no `+`/`-`/whitespace/non-ASCII digits, overflow false, leading zeros ok); `Split('.')` keeps empty parts; culture invariant by construction (ASCII only).
- A rejected library is never initialised (`init_and_close` not called after a version problem) and `libraw_version` is only called after ALL exports resolved.
- `check_exact_version` is stricter than `check_version` on purpose: only 0.22.2 may receive the raw struct write (`IParams`/white-balance offsets); other 0.22.x load and decode but skip the write. Do not unify the two.
- `probe` is the single source of truth for registration; do not log from the probe (C# does not; the composition root logs the reason).
- Test-only seams are `pub` (C# `internal` + `InternalsVisibleTo`); document it and keep the real `probe()` separate from `probe_with`.
- Do not use `HashSet` for the export list (output order must be sorted: trap 10).

## Open questions
1. **Seam shape**: C# uses a raw `IntPtr` and `NativeLibrary.TryGetExport`; Rust introduces `LoadedLibrary` (a trait with three methods) so the probe has no `unsafe`. If W5-15a prefers free functions over a handle type, adapt `probe()`'s closure only; `probe_loaded_library`'s signature can then become `(has_export, version, init_and_close, display_name)` closures. Lead decides when W5-15a is contracted.
2. **Export list injection**: `probe_loaded_library` reads the global `required_exports()`, which depends on W5-15a. For tests that must run before W5-15a merges the porter may add a `pub fn probe_loaded_library_with(exports: &[&str], ..)` and have the public one delegate (same behaviour, no signature change of the listed items).
3. **`probe()` return shape**: `&'static ProbeOutcome` instead of `bool` + out param (same as W5-13b so the App composition treats both backends alike).
4. **Exception classes**: the `catch (... when ex is DllNotFound or BadImage or EntryPointNotFound or InvalidOperation)` filter cannot be mirrored (Rust has one error type); documented in semantics 3. No behaviour difference is observable because every non-fatal exception ends as `available == false` either way, only the reason prefix (`loaded but failed to initialize` vs `probe failed`) differs: a native wrapper that returns `Err` from `version`/`init_and_close` always gets the first one.
