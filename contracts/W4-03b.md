## Semantics notes
1. **Never fails.** Every function returns `Option`; no `Result`, no panic. The C# outer `try/catch (ArgumentException | IndexOutOfRange | Overflow |
   DecoderFallback)` is "defensive only"; the Rust port does NOT use `catch_unwind` and instead indexes with `get(..)` / checked arithmetic so a panic
   is impossible. (Trap §7.9: that single `catch` has no Rust branch; the tests `corrupted_input_never_panics` and the golden `threw:false` guard it.)
2. **`find_exif_tiff_block` (the marker walk).**
   - `len < 4` or not `FF D8` => empty. `offset = 2`; loop while `offset + 4 <= len`.
   - `jpeg[offset] != 0xFF` => empty (NOT resync). `marker = jpeg[offset+1]`.
   - `marker == 0xFF` => fill byte, `offset += 1`, continue. `marker == 0x00` => empty (stuffed byte: corrupt header area).
   - `marker` in `{0xD8, 0x01, 0xD0..=0xD7}` => standalone, `offset += 2`, continue.
   - `marker` in `{0xDA, 0xD9}` => empty (EXIF must precede the scan).
   - otherwise `length = BE u16 at offset+2`; `length < 2` or `offset + 2 + length > len` => empty (a truncated final segment is NOT parsed).
     `payload = jpeg[offset+4 .. offset+2+length]` (`length - 2` bytes).
   - `marker == 0xE1 && payload.len() >= 6 && payload[..6] == b"Exif\0\0"` => return `payload[6..]` (the FIRST Exif-headed APP1 wins even when its TIFF part is
     empty or garbage; later APP1 segments are never examined). Else `offset += 2 + length`.
   - Use `usize` arithmetic with `checked_add`/`get`; `offset + 2 + length` cannot overflow on `usize` but keep it explicit.
3. **Header check (both `try_parse_tiff` and `try_read_orientation`).** `len >= 8`. Byte order: `II` little, `MM` big; one matching letter is not enough
   (`IM`, `MI` rejected). Magic = `tiff::read_u16(block, 2, little)`. `try_read_orientation` and `try_parse_jpeg` accept ONLY 42. `try_parse_tiff_block*`
   additionally accept 0x4F52 (`RO`, ORF "IIRO"/"MMOR") and 0x5352 (`SR`, "IIRS"). 0x002B (BigTIFF), 0x4F53 and anything else => `None`.
4. **IFD bounds.** `ifd_offset < 8 || ifd_offset > len - 2` => nothing read (an IFD0 offset inside the header, e.g. 0, 2, 4, 7, is rejected, 8 and 16 are
   accepted). `count = min(u16 at start, MAX_IFD_ENTRIES (256), (len - start - 2) / 12)`. Entry `i` is at `start + 2 + i*12`. Bytes after the counted
   entries (the next-IFD pointer and beyond) are never read as entries. The 257th entry is ignored even when the block has room.
5. **Per entry:** `tag/type/count` are read at `entry`, `entry+2`, `entry+4` (`read_u16/u16/u32`); `tiff::try_get_value_span(block, entry, type, count,
   little)` returning `None` => that entry is skipped (`continue`), the loop goes on. The value slice covers every element, so scalars read the first
   element.
6. **IFD0 vs Exif IFD (`is_exif_ifd`).** In IFD0 only Make 0x010F, Model 0x0110, DateTime 0x0132 (ASCII via `tiff::read_ascii(value, type)`) and the
   Exif pointer 0x8769 are looked at. In the Exif IFD only ExposureTime 0x829A, FNumber 0x829D (rational), ISO 0x8827 (`tiff::read_unsigned`),
   DateTimeOriginal 0x9003, DateTimeDigitized 0x9004, LensModel 0xA434 (ASCII), FocalLength 0x920A (rational). A 0x8769 entry INSIDE the Exif IFD is
   ignored (no recursion: a self-pointing sub-IFD terminates). Exactly one follow: IFD0, then at most one Exif IFD.
7. **First readable wins (`??=`).** A field is set only while it is `None` and the new read is `Some`. A duplicate tag whose first value reads as `None`
   (empty text starting with NUL, wrong type such as a BYTE-typed Make, SRATIONAL with a non-positive part, rational/ISO of the wrong type) does NOT block a
   later duplicate (golden `jpeg-duplicate-make-empty-first-then-value`). A first value that is readable but later dropped by `ExifSummary::create` (ISO 0)
   still wins over a later valid duplicate (golden `jpeg-duplicate-iso-zero-first-wins-then-dropped`).
8. **Exif pointer.** First 0x8769 entry whose `read_unsigned` is `Some(p)` with `8 <= p <= u32::MAX` wins; one below 8 or unreadable (or a negative SLONG)
   is skipped and a later one is taken; a first in-range pointer that points nowhere (`0xFFFFFFFF`) is still THE pointer (the later valid one is not
   consulted; goldens `exif-pointer-*`). Pointer 8 = IFD0 itself: it is read once more in Exif mode (its ISO etc. count), never again.
9. **Date choice happens on raw text, before parsing.** `date = date_original.or(date_digitized).or(date_time)` over the `Some` strings, then
   `ExifSummary::create` parses ONE string. So a present-but-invalid DateTimeOriginal (`"0000:00:00 00:00:00"`, `"   "`) hides a valid DateTime and yields no
   date (goldens `date-garbage-original-hides-valid-datetime`, `date-blank-original-hides-valid-datetime`); an EMPTY original (value starts with NUL,
   `read_ascii` => `None`) falls through (`date-empty-original-falls-through`). Do not "improve" this.
10. **`ifd_is_exif == true`** (CR3 CMT2): IFD0 is read ONCE with `is_exif_ifd = true`; Make/Model/DateTime are not read, the 0x8769 pointer is not
    followed. `try_parse_tiff_block` is `with(false)`.
11. **Empty input.** `try_parse_tiff_block*(&[])` and `try_parse_jpeg` over an empty/no-EXIF JPEG => `None` (C# `TryParseGuarded` empty check). A block shorter
    than 8 bytes => `None`.
12. **Orientation.** `try_read_orientation` scans IFD0 only (same bounds as 4) and decides on the FIRST entry with tag 0x0112: if its value span is
    unreadable => `None` (does not continue to a later duplicate); if `read_unsigned` is `Some(1..=8)` => that value, else `None` (so `0`, `9`, negative
    SSHORT, RATIONAL type, count 0, all `None`; a BYTE or LONG 1..8 is accepted). Golden `orientation-tiff-duplicate-0-then-6-first-wins` => `None`.
    Note the contrast with note 7: orientation is first-ENTRY-wins, the summary fields are first-READABLE-wins.
13. **Text.** `tiff::read_ascii` caps at 256 bytes and decodes UTF-8 with replacement (C# `Encoding.UTF8.GetString`); Rust `String::from_utf8_lossy`
    must give the same string for invalid bytes (golden `jpeg-make-invalid-utf8` decides; if it differs, the fix belongs to W4-03a). Sanitising
    (control chars to space, trim, 64-char cap) is `ExifSummary::create`'s job, not this file's.

## Traps checklist (§7 items 3, 8, 9, 10; INV ids: none; this unit has no INV, it feeds INV-2 only through the disk-cache EXIF bytes of W4-04a/W4-08b)
- §7.3 integer arithmetic: all offsets are untrusted `u32`; convert to `usize` only after the `<= len - 2` check; `entry + 8 + total` style sums stay in
  `tiff::try_get_value_span` (W4-03a). In this file the only sums are `start + 2 + i * 12` (bounded by `available * 12`) and the marker walk.
- §7.8 `None` vs empty: `find_exif_tiff_block` returns an empty slice (not `Option`) like C# `default`; `try_parse_*` treat empty as `None`.
- §7.9 exception filter has no Rust branch (note 1).
- §7.10 no hash maps; field precedence is order-dependent (notes 7, 8, 9).
- Hostile input: `MAX_IFD_ENTRIES` (256) and the one-level rule are the DoS guards; the contract tests keep a golden for index 255 (read) and 256 (not read).
- `u32 > len - 2` comparison: do it in `u64` (or after `usize::try_from`), never `as usize` first on a 32-bit target.

## Open questions
1. **Sibling signatures are assumed.** W4-03a and W4-04a are written in parallel; the surface above is this contract's assumption. If W4-03a uses
   `i32` offsets (C# `int`) or `u8` array elements differently, only `read_ifd` and `try_read_orientation` call sites change; the lead reconciles in
   the wiring step (D28: the wired stubs outrank this prose).
2. **Orientation type.** `try_read_orientation*` return `Option<u8>` (always 1..=8). W4-02a may define an `ExifOrientation` enum; if so, wrap with its
   `from_exif_value` at the call site in the decoder, not here (keeps this file free of a W4-02a dependency).
3. **`pr-imaging` dev-dependencies.** The test needs `serde_json` and `pr-test-support`; `crates/pr-imaging/Cargo.toml` is lead-owned (D15-style).
4. **`find_exif_tiff_block` visibility.** It is `pub` here (C# `internal`) because W5 TurboJPEG/RAW tests compare their combined header scan against it
   (C# `CombinedHeaderScanTests` does that through `InternalsVisibleTo`). If the lead prefers `pub(crate)`, W5 loses that cross-check.
5. **Invalid UTF-8 text.** Whether `String::from_utf8_lossy` equals .NET `UTF8.GetString` for every invalid sequence is decided by the golden
   `jpeg-make-invalid-utf8` (one case only); add more cases if W4-03a finds a divergence.
