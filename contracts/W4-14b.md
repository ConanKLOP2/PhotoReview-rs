- Semantics notes:
  1. **Mapping of the C# tasks (R0003).** Every `Task`-returning entry point returns a `PreviewHandle` AT ONCE. Whatever C# decides
     synchronously before its first `await` is decided before the call returns: the cancellation check, the RAM hit (`Ready`), and the
     in-flight `GetOrAdd` with its metric (`record_cache_miss` for the creator, `record_inflight_join` for a joiner): tests assert
     `inflight_joins` right after the calls and `has_inflight_preview` right after `get_viewer_preview` with a long delay. The creator's work
     runs on a spawned thread (`DecodeThreadKind::Preview` for `get_preview`, `Viewer` for `get_viewer_preview`, `Original` for
     `decode_original`); callers block only in `wait`. Never `wait` on the UI thread.
  2. **In-flight table.** `in_flight: Mutex<HashMap<(ImageCacheKey, epoch), Arc<LoadCell>>>`; the lock is held only for fetch-or-insert and
     for remove (never across a spawn, a decode or a wait). Creator = the caller whose freshly made cell was inserted (C#
     `ReferenceEquals(lazy, candidate)`, decided under the lock, not by a flag set inside a closure). The epoch is read BEFORE the lookup
     (C# `cacheEpoch` local) and travels with the job: the publish and the persist hand-off compare against it.
  3. **Completion order.** The load thread computes the outcome inside `catch_unwind` (a panic -> `Err(Panicked(text))`), then REMOVES the
     table entry if it still maps to this very cell (`Arc::ptr_eq`; C# `TryRemove(KeyValuePair)`), THEN completes the cell. Waiters therefore
     never observe a finished load that is still registered (tests assert `has_inflight_preview == false` right after `wait`). A dropped
     handle changes nothing: the load still completes, publishes, and removes itself (C# an un-awaited task still runs its `finally`).
  4. **Joiner rules (`PreviewHandle::wait`, C# `GetPreviewCoreAsync` loop + the two `catch ... when` filters):** after the cell completes:
     `Ok` -> return it. `Err(e)` and this caller is the CREATOR -> return `Err(e)` (the creator surfaces Busy and cancellations; the
     PreloadScheduler handles Busy). `Err(e)` for a JOINER: if `e.is_canceled() && !own_token.is_canceled()` -> retry; if `e.is_busy()` ->
     retry (whatever its own token); otherwise return `Err(e)`. A retry is a fresh `get_preview_attempt` with the same path, key, viewer flag,
     start delay and token (it re-checks the token first, then the RAM cache, then joins or creates). A joiner retries as often as needed (C#
     `while (true)`). `JoinEnd` perf is emitted once per joined attempt when perf was on at join time (`perf::ms(start)`).
  5. **Viewer lane (`run_viewer_load`, C# `DecodeForViewerAsync`).** (a) `start_delay > 0` -> `wait_cancellable(delay, token)`; (b)
     `viewer_slots.acquire(token)` (a token already cancelled never takes a free slot); (c) `token.check()` -> the LAST drop point; (d)
     `active_viewer_decodes += 1`, `decode_and_cache(.., Viewer)`, `-= 1` (only if (d) ran); (e) the permit drops (slot returned) on every
     path. Cancellation at (a)-(c) is `Err(Canceled)` and the decoder is never called. A started decode is never interrupted; its result is
     published like any other (test `StartedViewerDecode_IsKeptAfterSupersede`). `wait_cancellable`/`acquire` wake on a release at once and
     re-check the token every `CANCEL_POLL_SLICE` (10 ms): `CancelToken` has no wake-up (Open questions 2).
  6. **`decode_and_cache` (C# `DecodeAndCache`), in this order:**
     1. `key.source_kind() == RAW_FULL_DECODE` -> `Err(RawFullDecodeKey)` before anything else (no stopwatch, no source open, no metrics).
     2. Perf: `enabled = PhotoReviewPerf::log().is_enabled()`, nav = `PhotoReviewPerf::nav_context()` (set by the load thread from the job),
        `path_id = perf::path_id(path)` only when enabled. Stopwatch (`Instant`) starts here.
     3. `cache_path = disk_cache_path_for(key)` (14c; `None` when the disk cache is off: the key is not even hashed, L02).
     4. If `cache_path` is `Some` and `disk_entry_exists`: `try_read_disk_entry(path)` (14c, records the disk hit, touches the entry,
        emits `DiskCacheRead`). `Err(e)` with `e.is_cache_entry_failure()` -> `try_delete(cache_path, Some(log))` (W4-09; best effort)
        then `source_read = true` and step 5. `Err(e)` that is NOT a cache-entry failure (W4-08b `OutOfMemory`, `Canceled`) -> `Err(DiskEntry(Arc::new(e)))` (C#: the exception
        escapes; the entry is kept and the source is not decoded). (A prune may delete the file between the
        exists check and the read: that is a cache-entry failure like any other read error, never an escaping error.)
        Else (no path, no file): `source_read = true`, step 5.
     5. `decode_from_source(path, key.length(), key.backend(), target_box, priority)`; `Err` propagates (nothing published, no metrics
        beyond what `decode_from_source` recorded: the source open).
     6. INV-1 verify: perf start; `key.matches_current_source(fs)` false -> `Err(SourceChanged { path: path.to_owned(), phase: Decode })`
        (nothing published, not seeded, not persisted, no `record_source_read`); else perf `Verify` (only on success, like C#).
     7. `degraded = image.is_degraded_fallback()`; if not degraded: `publish_if_current(key, image, cache_epoch)` (14a).
     8. `has_known_original(image)` -> `original_dimensions.set(create_original(key), (original_width, original_height))` (also for a
        degraded image and for a disk hit; NOT epoch-checked, like C#).
     9. `cache_path.is_some() && source_read && !degraded && image.downscaled()` -> `queue_persist(image, cache_path, cache_epoch)` (14c).
     10. `source_read` -> `record_source_read(source_bytes_read(&image, key), elapsed_ms, true)` (elapsed = whole method, `as_millis` as
        `i64`). A disk hit records no source read.
  7. **`decode_from_source`.** `is_raw = is_raw_path(path)`. Pre-read: `!is_raw && cache.can_cache(source_length)` ->
     `cache.get_or_read_with_priority(Path::new(path), priority)` (`Err` -> `Err(SourceBytes)`); else `!is_raw && diag.pre_read` ->
     `diag_pre_read` (`Err` -> `Err(Io)`). Then `metrics.record_source_open(path)` (AFTER the pre-read, once per source decode, also when
     the decode then fails). Then `request = DecodeRequest::with_box(path, target_box)`, `.with_bytes(b)` when pre-read, `.with_priority(p)`
     (apply orientation stays true, no source orientation); `get_decoder(backend).decode(&request)` (`Err` -> `Err(Decode(Arc))`); perf
     `Decode(nav, path_id, ms, target_box.width, downscaled, !target_box.is_unbounded() && !downscaled)`. The diagnostic pre-read allocates
     the reported stream length (seek to end, back to start) and reads until full or a 0-byte read: a file that shrank in between keeps
     trailing zero bytes (C# quirk, keep it); perf `SourceRead` with that length.
  8. **Original decode (`decode_original` + `run_original_decode`).** On the caller's thread: token check (`Ready(Err(Canceled))`); key as
     in the stub doc; RAM hit -> `Ready(Ok)` (an Original-mode preview already cached is reused; NO metrics). Else spawn ONE `Original`
     thread: `original_gate.acquire(token)` (`Err(Canceled)`), `token.check()`, then: no override (RAW full decode off) ->
     `decode_from_source(path, key.length(), key.backend(), UNBOUNDED, Viewer)` (pre-read rules apply); override that is cancellable
     (`as_cancellable()`) -> `decode_cancellable(&DecodeRequest::with_box(path, UNBOUNDED), token)`; otherwise
     `decode(&DecodeRequest::with_box(path, UNBOUNDED))` (no bytes, default priority, NO `record_source_open` for the override paths: C#
     calls the decoder directly). Then INV-1 verify (`SourceChanged { Decode }`), seed `original_dimensions` under `key` (the kind-2 key for
     a RAW full decode, so a later `try_get_known_original_dimensions(preview key)` does NOT see it: golden `decode-original-raw-full-decoder`),
     `record_source_read(bytes, ms, key.source_kind() != RAW_FULL_DECODE)`. Never `publish`, never persist. The permit drops after the
     decode. The handle has no retry context (not de-duplicated).
  9. **`get_original_dimensions`** runs on the CALLER's thread (blocking; the caller is a worker lane). Order in the stub doc; `read_info`
     `Err` -> `Err(Decode)` and nothing is stored; the stat for the verify happens AFTER `read_info` (C#). Lookups/stores use
     `create_original(current_key)` (kind kept from the current key).
  10. **`get_decoder`**: no factory -> `decoder.clone()`; with a factory: lock, look up, unlock; on a miss call `factory.create(backend)`
     outside the lock, then insert-if-absent and return the stored one (C# `GetOrAdd` may build twice; the factory itself is build-once).
  11. **`preload(path, token)`**: `token.is_canceled()` -> `Ready(Err(Canceled))`; else `get_preview_path(path)` WITHOUT the token.
  12. **Perf context.** `PhotoReviewPerf::nav_context()` is thread-local in Rust (C# `AsyncLocal` flowing through `Task.Run`). Capture it in
     `LoadJob.perf_nav` on the creating thread and set it first thing on the load / original thread; a joiner's `JoinStart`/`JoinEnd` use the
     joiner's own nav.

## Open questions
1. **Handle vs blocking API.** Chosen: handle + spawned thread (keeps the C# synchronous join decision and lets the App fire a viewer
   request and keep the UI thread free). Alternative: blocking `fn get_preview(..) -> PreviewResult` on the caller's lane; simpler, but the
   C# tests that check "joined/in-flight right after the call" would need hooks, and two viewer slots would need two viewer lanes in the
   App. Recommended: keep the handle (W4-10b `ThumbnailCache` drafted the same pattern).
2. **Waitable cancellation.** `pr_core::sync::CancelToken` has no wake-up, so the start delay and the gates poll their token every 10 ms
   while blocked (a release wakes them at once). Proposal for the lead: add a condvar-backed `CancelToken::wait_timeout(&self, d) -> bool`
   (cancel notifies) to `pr-core`; the porter then replaces the slice loop without API change. Not needed for correctness.
3. **Diagnostic pre-read of a > 2 GiB file.** C# `new byte[stream.Length]` throws `OutOfMemoryException`/`OverflowException` (caught nowhere
   here: the decode fails). Rust: refuse lengths above `i32::MAX` (the .NET array limit 0x7FFFFFC7, `cache::source_bytes::ARRAY_MAX_LENGTH`)
   with `Err(Io(InvalidData))` instead of trying to allocate. Diagnostic-only path; recommended as written.
4. **Decode thread per request.** One OS thread per preview decode (`StdThreadSpawner`) is the C# `Task.Run` cost profile (the pool grows the
   same way); the preload scheduler (W4-15) bounds concurrency. If W4-15 measures thread churn, the App installs a pooled spawner for
   `DecodeThreadKind::Preview` (rayon is planned in R0003): no API change.
