## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T7 (Windows paths): `initial_folder` returns the folder with backslashes; a UNC or `\\?\` file works the same through `metadata`; a UNC file directly under a share root gives `\\server\share\` (Rust `parent`) where .NET gives `\\server\share` (benign: the dialog takes either); a path with invalid characters is simply not a file (`None`), never a panic.
- T8 (null vs empty): `Some("")` from `initial_folder` of a bare name is passed on as `Some("")` (C# parity, the file dialog treats it as no folder); `pick_open_file` returning `Ok(Some(""))` does not write the field.
- T9 (exception to Result): the C# `catch (Exception ex) when (ex is not OutOfMemoryException)` of `PickOpenFile` is the `Err(Hresult)` branch; the `catch` of `InitialFolder` (`ArgumentException`, `PathTooLongException`, `NotSupportedException`, `IOException`) is `metadata` failing.
- T10 (order): declaration order = Tab order = ids; `load` order; radios index 0 = Fast, 1 = Power-loss safe.
- D-W8-4: the executable filter text is `tr::dialog_file_filter_executable()`; the page never writes `"Executable"` or `".exe"` itself.
- R0003: no `unwrap`/`expect`/indexing (`chunks_exact`, `first()`), nothing panics when the context is detached.
