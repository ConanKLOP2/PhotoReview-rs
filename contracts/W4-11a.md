- Semantics notes:
  1. **Why so little of the C# file survives.** The `windows` crate is generated from the Windows metadata: it has every interface, IID,
     vtable (in `wincodec.h` order), enum and GUID the C# file declares by hand. The C# vtable-order and IID facts are therefore TESTED
     (golden `wic-interop-constants` against `windows` IIDs and `_Vtbl` field offsets), not re-declared. Name differences to map in the
     test: C# `IComStream` = `IStream`; C# `IWICColorContext.GetContextType` = `windows` `GetType`; C# `StatStgNative` = `STATSTG`.
  2. **`Com<T>` = `WicCom`.** `wrap(raw, name)`: null -> `Err(Com { E_FAIL })` (C# `Marshal.GetExceptionForHR(E_FAIL, -1)`, a
     `COMException`); else take the reference (`IUnknown::from_raw`), `cast::<T>()` (QueryInterface), and the taken reference is released
     on EVERY path (drop the `IUnknown`), so a success holds exactly the QI reference and a failure holds none. A QI failure is ALWAYS
     `NoInterface { name }` whatever its HRESULT (C# uses `is`, never a throwing cast, to avoid the stale `IErrorInfo`). Increment the
     thread counter only after success; `Drop` releases and decrements. `query::<U>()` = C# `obj is U`: `Some` (counted) or `None`, never
     an error. `adopt`: for methods the `windows` crate already wrapped: `Ok(t)` counted; `Err(e)` -> `from_windows(&e)`.
     `adopt_optional`: `Err` with code 0 -> `Ok(None)`, other `Err` stays an error, `Ok` -> `Some`.
  3. **The `windows` crate null trap.** For an out-interface method that returns S_OK with a null pointer, the crate returns
     `Err(Error::empty())` whose `code()` is `HRESULT(0)`. C# turns that into `E_FAIL` (`WicCom.Wrap`) or `null` (`WrapOrNull`, only
     `GetThumbnail`). `WicError::from_windows` maps code 0 to `E_FAIL`; NEVER let a code-0 error out of this module as a "success"
     error. All 10 helpers go through `adopt` / `adopt_optional`. W4-11b..e must use `Com::adopt` for any other out-object method they call.
  4. **Factory and COM apartment.** `create_factory`: first `ensure_com_initialized()?`, then `WICCreateImagingFactory_Proxy(0x0236,
     &mut raw)` (declared with `#[link(name = "windowscodecs", kind = "raw-dylib")]`; the `windows` crate does not export it).
     `check_factory_result(hr.0, !raw.is_null())`; on `Err` release `raw` if non-null (C#: "a failing HRESULT that still returned a
     pointer must not leak it"); on success `Com::wrap(raw, "IWICImagingFactory")`. Do NOT use `CoCreateInstance(CLSID_WICImagingFactory)`.
     Why the apartment step: every C# WIC call runs on a CLR thread that the CLR has already put in the MTA (pool threads) or an STA (UI);
     a bare Rust thread (every `cargo test` thread, `std::thread`, rayon) is in no apartment. The proxy itself works there, but codec,
     colour-context and metadata-handler instantiation inside WIC can fail with `CO_E_NOTINITIALIZED` (W4-11b, W4-11c T7 and W4-11e OQ1
     all route this to here). `ensure_com_initialized`: once per thread (thread-local guard): `CoInitializeEx(None,
     COINIT_MULTITHREADED)`; `S_OK`/`S_FALSE` -> remember it and `CoUninitialize` in the guard's `Drop` at thread exit (balanced, like the
     CLR); `RPC_E_CHANGED_MODE` -> `Ok`, the thread is already STA, nothing to undo, never `CoUninitialize` it; any other failure ->
     `Err(Com { hr })` and the next call retries. Every WIC call chain starts with `create_factory`, so W4-11b..e need no apartment code.
     One factory per call chain, as C# (no global cache: a factory is not `Send`).
  5. **Counter.** `thread_local!` `Cell<i32>`. `Com` is `!Send + !Sync` (`PhantomData<*const ()>`) so a drop always decrements the counter
     of the thread that incremented it. Not `Clone`.
  6. **HRESULT -> exception type.** `exception_kind_for_hresult(hr)`: `None` for `hr >= 0`; else the CoreCLR mapping
     (`Marshal.GetExceptionForHR`, `rexcep.h`: several HRESULTs per exception type, e.g. `E_OUTOFMEMORY` and `STG_E_INSUFFICIENTMEMORY`
     -> `OutOfMemory`, `0x80070002`/`STG_E_FILENOTFOUND` -> `FileNotFound`); unknown failing codes -> `Com`. Build it as a `match` on
     the HRESULT (u32 patterns), filled from the golden; every golden row must match. `is_*` helpers follow the golden's `base_types`
     (`ArgumentOutOfRange` is an `Argument`, `ObjectDisposed` an `InvalidOperation`, `PlatformNotSupported` a `NotSupported`, `FileNotFound`
     etc. an `Io`). The fallback decision itself is W4-12b; the conversion `WicError -> DecodeError` is W4-11c (it depends on both crates).
  7. **`ComStream` = `ManagedIStream`.** One `Mutex<StreamState>` inside the COM object (`ComObject<ComStreamObject>`); the `ComStream`
     handle and the `IStream` WIC holds share it. Per call (golden `wic-managed-istream` is the authority):
     - `Read(pv, cb, pcbRead)`: disposed -> `COR_E_OBJECTDISPOSED`; `cb > i32::MAX` -> `COR_E_ARGUMENTOUTOFRANGE` (C# `int cb` is negative,
       `new Span<byte>(pv, cb)` throws; `pv` is not touched); one `backend.read(&mut pv[..cb])`; `*pcbRead = n` if not null; S_OK even for
       a short read or 0 at the end (never S_FALSE). `cb == 0` -> S_OK, 0.
     - `Write(pv, cb, pcbWritten)`: disposed -> `COR_E_OBJECTDISPOSED`; `cb > i32::MAX` -> `COR_E_ARGUMENTOUTOFRANGE` (before the read-only
       check, as C#); `write_all(pv[..cb])`; `*pcbWritten = cb` if not null. Read-only backend -> `COR_E_NOTSUPPORTED`. Writing after a
       seek past the end zero-fills the gap (MemoryStream; `Cursor<Vec<u8>>` does too).
     - `Seek(move, origin, pNew)`: disposed first; `seek_from` (origin 0/1/2, else `E_INVALIDARG`; `Start` with negative move ->
       `SeekBeforeBegin`); backend `InvalidInput` or OS error 131 (`ERROR_NEGATIVE_SEEK`) -> `SeekBeforeBegin` (`COR_E_IO`), position
       unchanged; `*pNew` written ONLY on success (on failure the caller's memory is untouched: the golden shows the sentinel).
     - `SetSize(n)`: disposed first; `n > i64::MAX` -> `COR_E_ARGUMENTOUTOFRANGE`; read-only -> `COR_E_NOTSUPPORTED`; `Cursor<Vec<u8>>`:
       resize (zeros when growing, also after an earlier shrink) and clamp the position to the new length (MemoryStream.SetLength).
     - `CopyTo`, `Clone`: `COR_E_NOTSUPPORTED` always (also after dispose); the Rust shims write no out pointer (the golden does not
       record them: the C# CCW stub may zero `*ppstm`; nobody reads it after a failure).
     - `Commit`: `flush()` if not disposed; S_OK after dispose. `Revert`, `LockRegion`, `UnlockRegion`: S_OK always.
     - `Stat(p, flag)`: disposed first; `STATSTG { r#type: 2, cbSize: len, everything else 0, pwcsName null }`, flag ignored. Zero all 80
       bytes first (`ptr::write_bytes(p, 0, 1)`), then write the fields: bytes 12..16 are padding and the golden's `stat_bytes` pins them
       (a plain struct write leaves padding undefined).
     - Backend `io::Error` -> fault, one rule for every op: `ErrorKind::Unsupported` -> `NotSupported` (C# `NotSupportedException` of a
       read-only `MemoryStream`); in `Seek` only, `InvalidInput` or OS error 131 -> `SeekBeforeBegin`; else `StreamFault::Io(e)`, whose
       HRESULT is `hresult_from_win32(raw_os_error)` if it has one (.NET `FileStream` errors carry `HRESULT_FROM_WIN32` as `HResult`),
       else `E_INVALIDARG` for `InvalidInput` (what a .NET `ArgumentException` crossing the CCW gives; W4-11c OQ3 relies on it), else
       `COR_E_IO` (C# `IOException.HResult`). Record every failure in `last_fault` (Rust addition, see Open questions).
     - Build the `Err` of the `IStream_Impl` shims with `windows_core::Error::from_hresult(HRESULT(code))`. Never `Error::new(code, msg)`
       (it originates a thread error object) and never `Error::from(HRESULT)` / `HRESULT::ok()` (they call `GetErrorInfo` and take the
       thread's error object).
     - `File` backend: `set_len` also moves the position to the new length when it was beyond it (.NET `FileStream.SetLength`; Rust
       `File::set_len` does not); `flush` is `Write::flush`, never `sync_all` (C# `Flush()`, not `Flush(true)`).
     - The COM methods must never panic (a panic in an `extern "system"` shim aborts): lock with `unwrap_or_else(PoisonError::into_inner)`,
       no `unwrap`, no slice indexing that can fail (`cb` from WIC is trusted like C# `new Span<byte>(pv, cb)`; null `pv` with `cb > 0` ->
       `E_POINTER`, a Rust-only guard, not in the golden).
     - `ComStream` `Drop` = `dispose()` (C# `using`). `dispose` is idempotent (second call `None`).
  8. **`ManagedIStream` share mode.** C# passes a `FileStream` opened with share `ReadWrite | Delete` (by W4-11c, not here):
     `ComStream::from_file` takes any `File`; W4-11c opens it with `OpenOptionsExt::share_mode(7)`.
  9. **Enums.** Use the `windows` newtypes (`WICDecodeMetadataCacheOnDemand` = 0 etc.); the golden pins the C# numeric values (C# `uint`,
     `windows` `i32`: compare as `u32`). `WICBitmapTransformOptions` is a flags enum in both.
  10. **`GetMetadataByName`** (C# `[PreserveSig]`): nothing to port; the `windows` method returns `Result<()>`, a missing tag is
      `Err` with code `WINCODEC_ERR_PROPERTYNOTFOUND` and costs no exception in Rust. W4-11d tests that code (W4-02a only receives the values through its query function).
- Traps checklist: §7 items 3 (`cb`/`n` are `u32` vs C# `int`; `SetSize` `u64` vs C# `long`: values above `i64::MAX` are C# negative ->
  ArgumentOutOfRange), 8 (null out pointers are legal for Read/Write/Seek: write only when non-null; null out OBJECT is E_FAIL except
  the thumbnail), 9 (each C# exception type becomes its own `StreamFault` / `DotnetExceptionKind`, never collapsed). COM traps: a
  reference taken by `from_raw` must be released on the failure path (the WP-12 leak class, `WicLifetimeBalanceTests`); never
  `mem::forget` a `Com`; never read `windows_core::Error::message()` for parity (it may hold the thread's stale `IErrorInfo`); `Error::empty()`
  is code 0 (note 3). INV-12: a wrong `exception_kind_for_hresult` row silently changes whether a decode falls back to the other backend.
  `windows` side effect: every failed `windows` call (including the QI inside `cast`) builds its `Error` with `GetErrorInfo`, which TAKES
  the thread's `IErrorInfo`; C# `GetExceptionForHR(hr, -1)` leaves it. Harmless (nothing reads it), but the stale-`IErrorInfo` twins must
  not assert that the stale object is still set afterwards; they clear it with `SetErrorInfo(0, None)` as C# does.

- `oracle/W4-11a.cs`: commands `wic-interop-constants`, `wic-hresult-exception`, `wic-managed-istream` (dispatch lines in the file header).
  Needs a `PhotoReview.Imaging` reference in `OracleCs.csproj` (as W4-02a); reaches the internal types by reflection. No WIC object is
  created, so the outputs do not depend on the machine's codecs.
  - `wic-interop-constants`: `guids` (all 18 `WicGuids` fields, declaration order), `enums` (members and values of the 6 enums, `[Flags]`),
    `interfaces` (IID, base interfaces, `first_slot`, methods in vtable order with `preserve_sig`), `statstg` (pointer size, size, offset
    of every field), `sdk` (`WINCODEC_SDK_VERSION1`, entry point name). Rust test: `guids::ALL` equals the list; each IID equals
    `<windows type as Interface>::IID`; for each interface method `i`, `offset_of!(<I>_Vtbl, <Method>) == (first_slot + i) * 8`
    (map the three renamed items of note 1; inherited methods are nested: C# `IComStream.Read` is `offset_of!(IStream_Vtbl,
    base__.Read)`); `offset_of!` of every `STATSTG` field equals the C# offsets (C# `type` = `r#type`).
  - `wic-hresult-exception`: per HRESULT the .NET type `Marshal.GetExceptionForHR(hr, -1)` creates (null for success), its `HResult` and
    `base_types`. Rust: `exception_kind_for_hresult(hr).map(type_name) == type`, and each `is_*` helper equals "`base_types` contains X".
  - `wic-managed-istream`: scripts run through the REAL `IStream` vtable of a `ManagedIStream` CCW over a `MemoryStream` (`growable` =
    `new MemoryStream()` filled with the data = Rust `ComStream::writable_memory()` + write + seek; `readonly` = `new MemoryStream(byte[],
    false)` = `ComStream::from_bytes`). Per op: `hr`, `out_u32`/`out_u64` (the out value, or the 0xCD.. sentinel when not written),
    `buffer` (reads, unread bytes are 0xEE), `stat_bytes` (80-byte `STATSTG` hex, only on success), `position`/`length` of the backing
    stream, `content` after write/set_size, all recorded after EVERY op. Rust runs the same ops through `ComStream::istream()` with raw
    pointers and the same sentinels; after each op it reads position (`seek(0, 1)`), length (`stat().cbSize`) and content (`seek(0, 0)`,
    `read` of `length` bytes, `seek(position, 0)`) through the safe `ComStream` methods (no side effect on success); after a `dispose` op
    it keeps the returned backend and reads it directly (downcast through `into_any`; a second `dispose` op returns `None`). `cb` is an
    `i32` in the golden: pass `cb as u32` (the `-1` rows become `u32::MAX`) and allocate `max(cb, 1)` bytes.
- `golden-inputs/{wic-interop-constants,wic-hresult-exception,wic-managed-istream}.json`. Case design: every WIC/IO/COM/CLR HRESULT the C#
  can meet (all `WINCODEC_ERR_*`, common Win32 file errors, STG_E_*, COR_E_*, odd ones: NTSTATUS, customer bit, 0x80000000, -1); every
  ManagedIStream test of C# plus seek origin errors, seek before start from each origin, seek past end then read/write, shrink then grow,
  `SetSize(-1)`, `Read`/`Write` with `cb = -1`, every op after dispose, `Stat` flag 0 and 1.

## Open questions
- **COM apartment (decided in review; lead may revert).** `ensure_com_initialized` and its call at the top of `create_factory` (note 4)
  were added because W4-11b, W4-11c (T7) and W4-11e (OQ1) all route apartment setup to this unit. Alternative: each thread entry point
  (W4-08b/W4-09/W4-14/W4-15 workers) initialises COM itself; more places to forget, same behaviour.
- **`InvalidInput` -> `E_INVALIDARG` (decided in review, W4-11c OQ3).** Lets W4-11c port the two `*_StreamReportsInvalidArgument_*` tests.
  On the parity paths neither `MemoryStream` nor `FileStream` throws `ArgumentException` from Read/Write, so no golden row changes.
- **`exception_kind_for_hresult` doc examples are not authoritative.** E.g. CoreCLR may map `E_POINTER` to `AccessViolationException`
  rather than `NullReferenceException` (both are defined on 0x80004003 in `rexcep.h`); the golden decides, add the variant if needed.
- **`windows` crate vs hand-written vtables.** Recommended (used by the stub, P-22): `windows` 0.62.2 + `windows-core` (MIT/Apache, by
  Microsoft, generated from metadata; removes ~400 lines of hand-declared vtables and their slot-order risk). Cost: two crates in the
  workspace (~compile time), and the null-out-object trap (note 3). Alternative: hand-declared `#[repr(C)]` vtables like the C# file, no
  dependency; more `unsafe`, the vtable tests become the only guard. Lead decides; P-22 already proposes `windows`.
- **`take_last_fault` (Rust addition).** In C#, an exception thrown inside `ManagedIStream` crosses the CCW as its HResult and sets the
  thread `IErrorInfo`; what the C# caller then sees after WIC wraps the failure (e.g. `WINCODEC_ERR_STREAMREAD`) depends on WIC and on
  .NET's `IErrorInfo` restore. Not covered by any C# test. Recommended: W4-11c keeps reporting the WIC HRESULT (C#-compatible type
  classification) and only uses `take_last_fault` to enrich the log message. Alternative: drop the method. Lead decides; harmless either way.
- **Golden runner detail.** The oracle calls the CCW entry points through `Marshal.GetDelegateForFunctionPointer`. If the runtime refuses that
  for `[UnmanagedCallersOnly]` targets on the wiring machine, switch to `delegate* unmanaged` with `AllowUnsafeBlocks` (results must not change).
- **`MemoryStream` limits not mirrored.** C# `MemoryStream` refuses positions/lengths above `int.MaxValue` (ArgumentOutOfRange); the
  `Cursor<Vec<u8>>` backend does not. Only the cache encoders use memory streams and their outputs are far below 2 GB; not in the golden.
