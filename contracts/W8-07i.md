- Semantics notes (line numbers are `ImagePresenter.cs`):
  1. **Range and override checks (237 to 241), before any state change.** `index < 0 || index >= catalog.count()`: `Ok` with no change (no token taken, `last_present_started_from_ram` untouched, no sink call, no preload notification). Then `path_override` not belonging to entry `index`
     (`catalog.index_of(po) != index`): `Err(PresentError::PathNotInEntry)`.
  2. **Order inside `begin_present` (242 to 296)** is pinned by tests (see the stub doc, 8 steps). Notably: `catalog.set_current(index)` is synchronous and before the first wait; the previous viewer-decode token is cancelled when the new one is installed;
     `zoom_detail.reset()` and `preload.notify_navigation(index)` run BEFORE the stat; `compare.select(None)`, `current_photo_info = None` and `info_while_original_shown = None` run before the stat so the info line never describes the previous image.
  3. **The stat (298 to 326).** One stat on the stat worker, cancellable by the viewer token. `!is_navigation_current(token)` drops the event. `Missing` -> 07k's removal (`remove_missing_catalog_item(path, token)`), `Error` -> keep the entry, clear the image and the compare view model, error status WITH attention. The catalog is
     never touched on `Error` and never touched by a stale event.
  4. **R7-1 (328 to 349).** The key describes the file as it is now: when `path_override.is_none()` and the catalog entry does not `matches` the stat, evict the entry's cached path (only if the entry had both length and mtime) and `update_metadata` BEFORE the key is built. For a capture-member
     override, or an entry that left the catalog, the key comes from `CatalogEntry::new(path)` + `with_metadata(stat)` and the catalog is NOT touched (test `CaptureMemberOverride_*`).
  5. **RAM lookup (351 to 377).** `last_present_started_from_ram = ram.is_some()`; `has_inflight` only when not RAM; the preload hit is consumed and counted ONLY on a RAM hit; `current_photo_info` is set from the RAM image or `None`; `settings` are snapshotted here; the initial status is `ready` (RAM) or `loading` (attention).
  6. **The race (379 to 464).** The viewer preview starts first, with the preload controller's `get_viewer_decode_delay()` and the navigation's token; the thumbnail is requested only in Preview mode, not RAM, not already in flight. The first event decides: a thumbnail result is shown as a placeholder (sized from the
     known original dimensions if any), the status becomes `loading_full_res` (attention), `apply_initial_view_mode()` is called; a preview result first makes a later thumbnail event a no-op. A thumbnail error other than a cancellation is logged and treated as "no thumbnail".
  7. **Present the preview (466 to 512).** `record_cache_hit` for a RAM image; token check; AR16 rebase of the index; info; `update_current_image(.., Some(path))`; `record_ui_assign`; `on_presented(path)` then the hook; then the kick: deferred (flag consumed NOW, event on the scheduler, run only if still current) or immediate.
  8. **The tail** (`after_preview_presented`) belongs to W8-07j; this unit's last statement is the call to it.
- Traps checklist (MULTI-AGENT-PLAN section 7 items 1, 3, 4, 8, 10 apply; specific items below):
  - **T1 INV-1 / INV-9 on every continuation.** `on_initial_stat`, `on_thumbnail`, `on_preview` and `on_deferred_kick_due` check `is_navigation_current(token)` before touching the sink, the catalog (except where C# touches it first, see T2) or the cache. A superseded present must leave
    `current_image`, the status, the catalog, `last_present_started_from_ram` of the NEW present and the sink untouched.
  - **T2 where C# mutates before the check.** Only `last_present_started_from_ram = false` and `catalog.set_current` (both in `begin_present`) are unconditional; everything after an `await` is guarded.
  - **T3 token capture (APP-P01).** The navigation owns a CLONE of the viewer-decode `CancelToken`; the shared field is replaced by the next present. Never `unwrap()` the shared field in a continuation.
  - **T4 stat worker cancellation.** The stat job must be skipped without touching the disk when the viewer token is already cancelled (a burst behind a slow stat): use `NavigationStatWorker::run(.., &viewer_cancel)`. Test: the file system fake records the paths it was asked.
  - **T5 no UI-thread I/O.** No `std::fs` call, no `FileSystem` call, no `PreviewHandle::wait`, no `ThumbnailRequest::wait` on the UI thread. `catalog.*`, `preview_service.try_get_cached_preview`, `has_inflight_preview`, `get_current_cache_key_for_entry` (no I/O when the entry has metadata), `get_viewer_preview` (starts a decode) are UI-thread calls.
  - **T6 `last_present_started_from_ram` timing.** Reset at the start of every accepted present (also a stale-NotFound retry), set once after the stat; a superseded older present must not flip it back (its event is dropped before the line).
  - **T7 deferred kick.** The flag is consumed when the event is POSTED, not when it runs; without a scheduler the flag is NOT consumed (the test `DeferFlagWithoutScheduler_KicksSynchronously` leaves it set: keep the C# condition `DeferNextPreloadKick && _uiScheduler is not null`).
    The kick event is posted BEFORE the later post-frame yield of 07j (the gated test releases yield 0 = kick, yield 1 = frame).
  - **T8 AR16.** Re-read `catalog.current_index()` after the wait and compare with `catalog.index_of(path)`; `-1 == -1` must NOT count as current (`current >= 0` first). `preload_around(-1)` must never happen.
  - **T9 the crossfade flag.** `update_current_image` passes `Some(path)` for the thumbnail and the preview, `None` for a zoom swap; the second call of one navigation sees `presented_file_path == path` and reports `false` (test `ThumbnailReplacedByPreview_*`).
  - **T10 thread names and priority.** The viewer decode lane's priority is the service's concern (W4-14b); the presenter only passes the delay and the token.
  - **T11 `PreviewError::Canceled` after supersede** is not an error to report: a `Preview` event with `Err(e)` for a non-current token is dropped silently (the fail path of 07j logs `ShowImage superseded`/`failed (stale ..)` only when the navigation record still exists).

## Open questions (each has a recommended default; the stub follows it)
- **O1 Performance marks.** `PhotoReviewPerf` calls (about 12) are kept 1:1 behind the `perf` flag; no test pins them. Default: port them (they feed the perf CSV analyser `pr-perf`). Alternative: drop and log a `Different` row. Default taken.
- **O2 `CatalogEntry::new` is fallible** (blank path). The path comes from the catalog, so it cannot be blank; use `?`-free handling: a blank path takes the generic failure branch. No test.
- **O3 Thread per wait.** A held-down arrow key creates one short-lived worker per navigation for the preview wait (cancelled decodes finish at once). Default: `BackgroundRunner` per wait. Alternative: one long-lived wait thread with a channel. Measure before changing (review speed first).
- **O4 `ThumbnailCache::get` returns `Err` synchronously** (`BlankPath`, `Disposed`) where C# throws synchronously inside the `try`: default is `fail(PresentFailure::Thumbnail(e))` (a `Disposed` cache after shutdown then shows an error for the image being presented, like C#).
