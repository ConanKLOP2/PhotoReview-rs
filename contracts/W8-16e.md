## Semantics notes (C# is the spec; line numbers are of the C# files)

### Helpers (traps T1 to T3)
1. **`cs_min` / `cs_max` (T1).** C# `Math.Min`/`Math.Max` return NaN when either argument is NaN, and order `-0.0` below `+0.0`
   (`Math.Max(0.0, -0.0)` is `+0.0`, `Math.Min(0.0, -0.0)` is `-0.0`). Rust `f64::min`/`f64::max` return the non-NaN operand. Every C# `Math.Min`/`Math.Max` in
   `ScrollBarGeometry.cs` (about 14 call sites in `Compute`, `BuildBox`, `Travel`, `OffsetForThumbStart`) must use the helpers. Implement max as
   `if a.is_nan() || b.is_nan() { f64::NAN } else if a > b { a } else if b > a { b } else if a.is_sign_negative() { b } else { a }` (equal values: the `+0.0` wins);
   min is the mirror (`a < b`, `b < a`, and for equal values the `-0.0` wins). The helpers are private; the golden cases with `"-0"` inputs exercise them through the public API.
2. **`sanitize` (T2, line 250).** `value.is_finite() && value > 0.0 ? value : 0.0`. The result for NaN, negatives, `-0.0` and infinities is `+0.0`. It is applied to
   `client.width/height`, `metrics.thickness` and the viewport length, and NOT to the margins, the min thumb length, the offsets or the max offset.
3. **Arithmetic order (T3).** Keep the C# expression order; `a * b / c` is `(a * b) / c`; `bar.width - (2.0 * margin)`; `travel * clamped_offset / range`. The golden compares
   doubles bit for bit (shortest round-trip text parses back to the same `f64`). No fused multiply-add, no `mul_add`, no reordering, no `f32`.

### `compute` (lines 119 to 148)
4. Steps, in order (all `f64`, `+0.0` literals):
   `width = sanitize(client.width)`, `height = sanitize(client.height)`, `thickness = sanitize(metrics.thickness)`; `hv = layout.horizontal_bar_visible`,
   `vv = layout.vertical_bar_visible`; `bt_x = cs_min(thickness, width)`, `bt_y = cs_min(thickness, height)`.
   `vertical_bar = if vv { RectD { x: cs_max(0.0, width - thickness), y: 0.0, width: bt_x, height: cs_max(0.0, height - (if hv { thickness } else { 0.0 })) } } else { RectD::default() }`;
   `horizontal_bar = if hv { RectD { x: 0.0, y: cs_max(0.0, height - thickness), width: cs_max(0.0, width - (if vv { thickness } else { 0.0 })), height: bt_y } } else { default }`.
   `vertical = if vv { build_box(Vertical, vertical_bar, layout.max_vertical_offset, vertical_offset, layout.viewport_height, metrics) } else { ScrollBarBox::hidden(Vertical) }`,
   `horizontal` likewise with `max_horizontal_offset`, `horizontal_offset`, `viewport_width`. `both = vv && hv`;
   `corner = if both { RectD { x: cs_max(0.0, width - thickness), y: cs_max(0.0, height - thickness), width: bt_x, height: bt_y } } else { default }`; result `{vertical, horizontal, corner, has_corner: both}`.
   The bars use `layout`'s visibility flags and offsets only: the policy (Auto/Overlay/Hidden) is already folded into the layout by the engine. `extent_width/height` and `image_rect` are never read.
5. **`build_box` (lines 150 to 182).** `vertical = axis == Vertical`.
   `track` = vertical: `RectD { x: bar.x + across, y: bar.y + along, width: cs_max(0.0, bar.width - 2.0*across), height: cs_max(0.0, bar.height - 2.0*along) }`;
   horizontal: `RectD { x: bar.x + along, y: bar.y + across, width: cs_max(0.0, bar.width - 2.0*along), height: cs_max(0.0, bar.height - 2.0*across) }`
   (`along = metrics.track_margin_along`, `across = metrics.track_margin_across`). `track_length` = track height (vertical) or width.
   `range = cs_max(0.0, max_offset)`; `clamped = cs_min(range, cs_max(0.0, if offset.is_nan() { 0.0 } else { offset }))`.
   `viewport = sanitize(viewport_length)`; `total = range + viewport`; `thumb = if total > 0.0 { track_length * viewport / total } else { track_length }`;
   `thumb = cs_min(cs_max(0.0, thumb), track_length)`; `thumb = cs_max(metrics.min_thumb_length, thumb)`;
   `thumb_visible = track_length > metrics.min_thumb_length || (track_length >= thumb && track_length > 0.0)`.
   If `!thumb_visible`: `ScrollBarBox { axis, visible: true, bar, track, thumb: default, thumb_visible: false, max_offset: range, offset: clamped, viewport_length: viewport }`.
   Else `thumb = cs_min(thumb, track_length)`; `travel = track_length - thumb`;
   `start = (if vertical { track.y } else { track.x }) + (if range > 0.0 { travel * clamped / range } else { 0.0 })`;
   thumb rectangle: vertical `RectD { x: track.x, y: start, width: track.width, height: thumb }`, horizontal `RectD { x: start, y: track.y, width: thumb, height: track.height }`;
   box `{axis, true, bar, track, thumb, true, range, clamped, viewport}`. Note the box stores `range` (= `cs_max(0.0, max_offset)`, which stays NaN for a NaN input, see 6) and the sanitised `viewport`, not the raw inputs.
   The C# `extent` parameter of `BuildBox` is unused (compiler would not warn on a private method parameter): drop it.
6. **NaN traps (T4).** A NaN `max_offset` makes `range` NaN (`Math.Max` propagates), `clamped` NaN, `total` NaN, so `total > 0` is false and the thumb is the whole
   track (`thumb = track_length`), `thumb_visible` follows the second clause, `start = track + (range > 0 ? .. : 0)` = track start (NaN > 0 is false). The box carries `max_offset = NaN`,
   `offset = NaN`. A NaN `min_thumb_length` makes `cs_max(NaN, thumb)` NaN, so `thumb_visible` is `track_length > NaN || (track_length >= NaN && ..)` = false. Do not "fix" any of this;
   the golden has the cases (`metrics: NaN min thumb`, `direct: NaN max offset`).
7. **Thumb visibility edge (T5).** `track_length == min_thumb_length` (exactly 8) is visible through the second clause; `7.99` is hidden; `0` is hidden even with `min_thumb_length = 0`
   (`0 > 0` false, `0 > 0` false). Golden cases `direct: track exactly as long as the minimum thumb (8)`, `... just below ... (7.99)`.

### Hit testing and offsets
8. **`offset_for_thumb_start` (lines 188 to 198).** `travel = b.travel()`; `if !(travel > 0.0) || !(b.max_offset > 0.0) { return 0.0 }` (written with `!` so NaN returns 0; do NOT rewrite as
   `travel <= 0.0 || ..`); `ratio = (thumb_start - b.track_start()) / travel`; `cs_min(b.max_offset, cs_max(0.0, ratio * b.max_offset))`. A NaN `thumb_start` gives NaN (no guard in C#).
   `travel()` = `cs_max(0.0, track_length - thumb_length)` with the box's own `thumb` rectangle (a hidden thumb has length 0 so travel equals the track length).
9. **`hit_test` (lines 201 to 236).** `if layout.has_corner && inside(layout.corner, point) { return Corner }`; `part = hit_box(&layout.vertical, point)`; `if part != None { part } else { hit_box(&layout.horizontal, point) }`.
   `hit_box`: `if !b.visible || !inside(b.bar, point) { None }`; `if b.thumb_visible && inside(b.thumb, point) { Thumb }`; `if inside(b.track, point) { if !b.thumb_visible { Background } else if b.along(point) < b.thumb_start() { TrackBefore } else { TrackAfter } }`; else `Background`.
   A visible thumb of zero width (golden `hit: thumb_visible true with a thumb of zero width`) falls through to the track and compares `along < thumb_start`.
10. **`axis_at` (lines 239 to 247).** Vertical when `layout.vertical.visible && inside(layout.vertical.bar, point)`, else horizontal under the same rule on the horizontal bar, else `None`.
    The C# doc comment says "including the corner: vertical" but the corner square is outside the vertical bar rectangle (the bar is `height - thickness` tall when both show), so a corner point gives
    `None` unless a hand-built vertical bar covers it (golden `hit: the corner has priority ...` has `axis` values for both situations). The code, not the comment, is the spec.
11. **`inside` (line 253).** `rect.width > 0.0 && rect.height > 0.0 && p.x >= rect.x && p.x < rect.x + rect.width && p.y >= rect.y && p.y < rect.y + rect.height` (half-open; right edge by the sum in
    floating point, never by subtraction as `RectD::contains` does). NaN anywhere gives `false`. Do not call `RectD::contains`.
12. **Defaults (T6).** `ScrollBarMetrics::default()` is `{10, 2, 1, 8, 4}` (the C# `record struct` has an explicit parameterless constructor so `new()` is NOT zeros; `default(ScrollBarMetrics)`,
    which is not reachable in Rust, would be zeros). `ScrollBarBox::hidden(axis)` and `ScrollBarLayout::none()` are all-zero boxes with `visible = false`, `thumb_visible = false`, axes `Vertical`/`Horizontal`.
13. **No state, no clock, no I/O** in `scrollbar_geometry.rs`; no `unsafe`, no `windows` crate.

### Native (`ScrollBarNative.cs`)
14. **`repeat_timing_for` (line 67).** `(delay + 1) * 250` and `((31 - speed) * (400 - 33) / 31) + 33`, C# `int` unchecked. Rust: `keyboard_delay.wrapping_add(1).wrapping_mul(250)` and
    `(31i32.wrapping_sub(keyboard_speed).wrapping_mul(367) / 31).wrapping_add(33)` (`400 - 33` is the constant 367; the division truncates toward zero in both languages; the divisor is 31 so the
    `i32::MIN / -1` overflow cannot happen). The 4 C# rows: `(0,31) -> (250,33)`, `(1,31) -> (500,33)`, `(3,0) -> (1000,400)`, `(2,15) -> (750,222)`. Out-of-range inputs are formula output, not errors
    (golden `out of range: ...`, includes wrapping rows).
15. **`repeat_timing` (lines 49 to 64).** `delay = 0; speed = 31;` call `SystemParametersInfoW(SPI_GETKEYBOARDDELAY = 0x0016, 0, &mut delay, 0)`; if the call fails or `!(0..=3).contains(&delay)` then `delay = 0`.
    Call `SystemParametersInfoW(SPI_GETKEYBOARDSPEED = 0x000A, 0, &mut speed, 0)`; if it fails or `!(0..=31).contains(&speed)` then `speed = 31`. Return `repeat_timing_for(delay, speed)`. (The `pvParam`
    is a pointer to an `i32`/`UINT`; note SPI_GETKEYBOARDDELAY writes an `INT`.) The two failure fallbacks are the defaults, so a failing OS call yields `(250, 33)`.
16. **`track_mouse_leave` (lines 39 to 43).** Build `TRACKMOUSEEVENT { cbSize: size_of::<TRACKMOUSEEVENT>() as u32, dwFlags: TME_LEAVE (0x2), hwndTrack: HWND(hwnd as _), dwHoverTime: 0 }`, call `TrackMouseEvent`, ignore the
    result (`let _ =`). One `unsafe` block with a `// SAFETY:` comment (pointer to a local struct that outlives the call; an invalid HWND makes the call fail, which is ignored). No error type, no logging.
17. Constants: `WM_MOUSE_LEAVE = 0x02A3`, `WM_CANCEL_MODE = 0x001F` (golden `constants` case checks both against the C# constants). If W8-11a already declares them in `pr_platform_win::win32`, re-export instead of redefining and keep these names.
