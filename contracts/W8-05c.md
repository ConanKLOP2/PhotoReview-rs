## Semantics (C# is the spec; line numbers are C# lines)
1. **`FromVirtualKey`** (26-36): if the code is outside `0..=255` (C# `(uint)virtualKey >= (uint)Length`), return `None` (value 0).
   If `is_extended`: code `0x11` gives `RightCtrl` (119), code `0x12` gives `RightAlt` (121). Otherwise the row of
   `VIRTUAL_KEY_TO_KEY` for the code, or `None` when no row. Result for `0x10`, `0x11`, `0x12` without the flag: `LeftShift` (116),
   `LeftCtrl` (118), `LeftAlt` (120).
2. **`ToVirtualKey`** (39-43): row of `KEY_TO_VIRTUAL_KEY` for the value, or `0` when the value is outside `0..=172` or has no row.
   The four values with no row: `None` (0), `LineFeed` (4), `System` (156), `DeadCharProcessed` (172).
3. **`TryParse`** (49-57): (a) `canonicalize(Some(name))`; (b) reject if empty, if it contains `','`, if the first character is a digit
   (`char.IsDigit`), or if it is `'-'` or `'+'`; (c) exact, case-sensitive lookup in `KEY_NAMES`; the result is that row's value; a
   value outside the enum cannot occur (names are defined). Failure returns `None`.
4. **Name table**: 202 rows including aliases. The alias pairs live in `pr_core` (`ALIAS_PAIRS`, 29 pairs), so `"Return"` becomes `"Enter"` in
   step (a); aliases that are not in `ALIAS_PAIRS` (for example `"LineFeed"`, `"System"`) are plain names of `KEY_NAMES`.

## Traps (write these into the tests; each one is a mutant the verifier will try)
1. **Out-of-range codes do not panic.** `-1`, `256`, `i32::MIN` and `i32::MAX` give `None`. A port that does `virtual_key as usize`
   wraps to a huge index and panics; use a range check on the `i32`.
2. **`is_extended` changes only `0x11` and `0x12`.** `0x10` with the flag stays `LeftShift`. `FromVirtualKey` never gives `RightShift`
   (116 is LeftShift only). `RightShift` (117) comes from `0xA1` (a row of the table) or from the scan code in the caller.
3. **`LeftShift` has two codes, the reverse table has one.** `ToVirtualKey(LeftShift)` = `0xA0` (160), not `0x10`. The same for
   `LeftCtrl` (`0xA2`) and `LeftAlt` (`0xA4`). A port that builds the reverse table from the forward table gives `0x10`: a mutant.
4. **Aliases share values.** `Return` and `Enter` are both 6, `ToVirtualKey(Enter)` = `0x0D`. `Next`, `PageDown` are 20 (`0x22`);
   `Prior`, `PageUp` are 19 (`0x21`). A port with one row per name (not per value) is wrong for the reverse table.
5. **No code means 0, including values out of range.** `ToVirtualKey` of `None`, `LineFeed`, `System`, `DeadCharProcessed`, `-2`,
   `173`, `1000`, `i32::MIN` is `0`. A port that panics on index 173 (the C# array length is `DeadCharProcessed + 1`) fails.
6. **`TryParse("None")` is true.** `Enum.TryParse` accepts every field name, so `None`, `LineFeed`, `System` and `DeadCharProcessed`
   parse to their value (`Some(KeyId(0))` for `"None"`). Do not "fix" this: the C# code accepts them, and the golden pins it.
7. **Digits and sign are rejected before the lookup, but the lookup alone would reject them too.** No field name starts with a digit,
   `+` or `-`, or contains a comma, so these pre-checks are behaviour-neutral. Keep them, with a comment saying so. A mutant that removes
   them is an equivalent mutant (not a survivor to fix in the tests).
8. **Case:** `Enum.TryParse(ignoreCase: false)` is exact. `"enter"` works only because `canonicalize` repairs the casing through the alias
   map (`"Enter"` is a canonical name). `"a"` is rejected (`"A"` is the name), `"pageup"` works (canonical `PageUp`), `"NumPad 1"` is rejected
   (inner space), `"Num9"` is rejected. A mutant that makes the lookup case-insensitive passes `"a"` and must fail test 7.
9. **Trim:** C# `Trim()` trims `char.IsWhiteSpace`. The golden rows `"\tEnter\t"`, `"\u000BTab"`, `"\u000CTab"`, `"\u0085Tab"`,
   `"\u00A0F1"` must give the same as the oracle. `"\u001CTab"` is a probe for the difference between .NET and Rust `trim()`: the golden
   decides. If the oracle and Rust disagree there, do NOT special-case the code: record a `DIVERGENCE` comment and a `Different` PARITY
   row (open question 6).
10. **Non-ASCII never matches an alias.** `"\u212A"` (Kelvin sign), `"\u0131"` (dotless i), `"\uFF21"` (fullwidth A) are not `"K"`, `"I"`,
    `"A"`. `canonicalize` is ASCII-only already (W1-04); the port must call it, not `eq_ignore_case` on the whole string.
11. **Exact `i32` arithmetic.** Do not cast the key value to `u8`/`u16`: the golden includes `-2`, `177`, `1000`, `i32::MAX`, `i32::MIN`.
12. **Pure, no allocation outside `try_parse`:** the VK lookups return values without `String` or `Vec`. `try_parse` allocates through
    `canonicalize` only (no extra copy of the table).

## Open questions
1. **`KeyId` representation (blocks W8-05b and this unit).** Recommended: `pub struct KeyId(pub i32)` (value-carrying newtype, the shape
   in the placeholder). A Rust enum cannot hold the alias rows (`Return` and `Enter` both 6, Rust rejects duplicate discriminants) nor
   the out-of-range values the C# tests cast (`(KeyId)(-2)`, `(KeyId)int.MinValue`). Alternatives: (a) a `#[repr(i32)]` enum with
   canonical variants only and a separate alias table: loses `(KeyId)value` for aliases and makes out-of-range values awkward; (b) an
   enum with an `Unknown(i32)` variant: the aliases stay out of the type, but out-of-range values then need a second case everywhere.
   The lead confirms the newtype or another choice before W8-05b starts; if it is not the newtype, this contract changes its
   signatures and tests in step.
2. **Name table owner.** Recommended: `KEY_NAMES` lives here (the plan lists "names" in this unit's Rust column) and W8-05b provides only the
   type. If W8-05b also writes the names, delete `KEY_NAMES` here and use 05b's table (same 202 rows and order).
3. **PARITY ID.** `C-06` is the duplicates row (W2-07). Recommended: `K-43` (the next free K row, K-42 is the last). Lead confirms.
4. **WPF cross-check (App.Tests tests 1 and 3).** These compare with `KeyInterop` (WPF), which the Rust port cannot run. Recommended: skip them
   here; the golden pins the C# table, and the table itself was verified by the C# test on Windows at `d92d6aae`. Record it in the PARITY row.
5. **`TryParse_AgreesWithShortcutKeyName` (test 8).** Needs `services::shortcut_key_name` (W8-04c, `Services/ShortcutKeyName.cs`).
   Recommended: port it in W8-04c's test file once both merged, not here (no circular dependency between 04c and 05c).
6. **`U+001C` trim.** Trap 9. Rust `str::trim` does not trim U+001C; .NET `char.IsWhiteSpace` may not either. The golden decides. If they
   differ, the port keeps Rust `trim()` and records a `DIVERGENCE` comment and a `Different` PARITY row; the lead decides whether an ADR is needed.
7. **Porter model.** Haiku as the plan says. The data is generated, the logic is a lookup and one name check. Escalate to Sonnet only if
   the first red-green cycle fails on traps 1 to 4 (the P-34 cap still holds).
