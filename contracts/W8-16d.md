## Semantics (C# is the spec)
### Prefetcher
1. **`plan`** (C# 75-90): `step = if direction < 0 { -1 } else { 1 }`; first `ahead` indexes `index + step * i` (i = 1..=ahead), then `behind` indexes `index - step * i`; every index outside `0..count` is dropped (no wrap-around). Inputs near `i32::MAX` must not overflow (use `checked_add`/`i64`, T3). Example: `plan(10, 5, 1, 2, 1) = [6, 7, 4]`; `plan(10, 0, -1, 2, 1) = [1]`.
2. **`navigated(index, count)`**: `index < 0 || count <= 0` -> clear planned, `last_index = -1`, `generation += 1`, return (NO `PlanChanged`, NO host call). Else: when `last_index >= 0 && index != last_index` the direction is `+1` if `index > last_index` else `-1` (an equal index or the first call keeps the old direction); `last_index = index`; `generation += 1`; run one pass now; then call `host.schedule_retry(Duration::from_millis(d), RetryRequest { generation, index, count })` for each delay of `RETRY_DELAYS_MS` in order.
3. **Pass** (C# 123-151): candidates = `plan(count, index, direction, AHEAD, BEHIND)` mapped through `host.path_at` (None dropped, order kept); no paths -> nothing (no host call); else `host.start_lookup(LookupRequest { generation, paths })`. A pass reads the CURRENT `direction` (a retry after a direction flip uses the new one, as C#). The pass NEVER calls the cache.
4. **`run_retry(request)`** (the host calls it on the UI thread after the delay): runs a pass with `request.index/count` only when `request.generation == self.generation`; a stale retry starts no lookup (`RetryPassesOfAnOlderNavigation_DoNotEvenStartABackgroundLookup`).
5. **`apply_lookup(generation, found)`** (the host calls it on the UI thread when the background lookup finished; C# `Apply` inside the `PostToUi` closure): `generation != self.generation` -> `Ok(())`, nothing changes (`Prefetcher_LateLookupResultOfAnOlderNavigation_IsNotApplied`). Else `planned.clear()`; for each `Some(pixels)` that is not disposed: `planned.insert(id)`; when `!cache.contains(id)`: `cache.prefetch(&pixels)?` and `prefetch_calls += 1`; then raise `PlanChanged` (snapshot of handlers, no borrow held). The first `prefetch` error stops the pass and is returned: `planned` keeps the ids added so far, `PlanChanged` is NOT raised (the C# exception left the posted action; the host logs it).
6. **Threading** (D-W8B4V-5). The prefetcher owns no thread, timer or queue. The host (W8-13j) fulfils `start_lookup` by running `lookup_cached(paths)` on a worker (it stats files; `PreviewImageService::try_get_cached_preview` per path, `PlatformImage::as_pixels`, I/O and "disposed" errors give `None`), then posting `apply_lookup` to the UI thread at `UiPriority::Background` and skipping it when the window is gone; it fulfils `schedule_retry` with its UI timer. Only plain `Send` data crosses (`LookupRequest`, `Vec<Option<Arc<PixelBuffer>>>`).
7. **GPU keys and stripes** (INV-1): the planned ids are `PixelBuffer::id()`s that 13j passes to `GpuImageCache::retain` (together with the composer's and the compare ids) so the LRU keeps them; `cache.prefetch` uploads in 2 MB stripes at Background priority (12f) and is a no-op when the id is already cached. `contains` is true for a PARTIALLY uploaded entry too, so a second pass does not start a second upload.

### KeepWarm
8. **`from_environment(get)`** (C# 29-43): enabled variable present -> `value = raw.trim()`; disabled iff `value == "0"` or equals (ASCII case-insensitively) `off` / `false` / `no`; any other value, including empty, keeps it enabled; absent = enabled. `window_ms` / `interval_ms`: `get(name)` parsed as .NET `int.TryParse(NumberStyles.Integer, InvariantCulture)`: optional leading/trailing white space (`\t\n\v\f\r` and space), one optional `+`/`-`, ASCII digits, must fit `i32`; failure or absent gives the default; success is clamped to the range (`3000` -> 3000, `10` -> 250, `999999` -> 60 000). Use `str::parse::<i32>()` after trimming exactly those characters (it accepts `+`/`-` and rejects empty / overflow like .NET).
9. **`KeepWarmController`**: `is_interaction` is the 13-message set of the stub doc (`WM_KEYDOWN`, `WM_SYSKEYDOWN`, `WM_MOUSEMOVE`, `WM_LBUTTONDOWN`, `WM_RBUTTONDOWN`, `WM_MBUTTONDOWN`, `WM_XBUTTONDOWN`, `WM_MOUSEWHEEL`, `WM_MOUSEHWHEEL`, `WM_ACTIVATE`, `WM_TOUCH`, `WM_POINTERUPDATE`, `WM_POINTERDOWN`); `try_handle` calls `note_interaction` for those and returns `None` ALWAYS (it must never change input behaviour). `note_interaction`: `!enabled || !is_window_active()` -> return WITHOUT consuming the throttle; `now = timestamp()`; when an extension exists and `now - last_activation < ticks_from_ms(THROTTLE_MS)` -> return; else `last_activation = now`, `has_activation = true`, `activations += 1`, `activate(now + ticks_from_ms(window_ms))`. `warm_at_launch`: `!enabled` -> return; `launch_warmups += 1`; `activate(timestamp() + ticks_from_ms(window_ms))`; it touches neither `activations` nor the throttle.
10. **Interplay with `GpuKeepAlive` (12h)**: `activate(until)` only EXTENDS the window (`fetch_max`), so a launch warm-up, an interaction and the throttle can never shorten each other; the thread starts at the first activation, sleeps on an event outside the window, and `dispose` joins it (3 s) and drops the work on its own thread. The controller's `timestamp` and the keep-alive's `TickClock` must be the SAME clock (the registration passes one `TickClock` to both; default `monotonic_ticks`), in nanoseconds (D-W8B3S-8): `window_ms * ticks_per_second / 1000` is `ticks_from_ms`.
11. **`register_keep_warm`** (C# `RegisterKeepWarm`, 20-32), in this order: `frame_log` = `FrameLog::from_environment(|_| path, qpc_frequency())` when `registration.frame_log_path` is non-empty, else `FrameLog::from_environment(env reader, qpc_frequency())` (`PHOTOREVIEW_RS_FRAME_LOG`); `options = registration.keep_warm` or `KeepWarmOptions::from_environment(&|n| std::env::var(n).ok())` (read ONCE here); `!options.enabled || (prefer_warp && work.is_none())` -> return a setup with `keep_alive = None`, `controller = None` (the frame log is still returned): no thread, no device, no handler (`WarpSurface_..._CreatesNoKeepAlive`); else `GpuKeepAlive::new(options.interval_ms, work.unwrap_or_else(|| Box::new(open_offscreen_hardware_work)), KeepAliveOptions { timestamp: registration.timestamp.clone(), below_normal_priority: true })` in an `Arc`, the controller (`is_window_active` = a closure over a `Weak` of the window, `false` when the window is gone; `activate` = a closure over the `Arc<GpuKeepAlive>`), and `window.insert_message_handler_first(controller)`.
12. **`KeepWarmSetup::dispose`** (C# `DisposeKeepWarm`): `keep_alive.take().dispose()` (joins) and `frame_log.take()` closed; idempotent. 13g/13h call it FIRST in `release_renderer` (before the viewing and the surface). The `FrameLog::record(&mut self, ..)` call of every frame (13i) goes through `setup.frame_log.as_mut()`.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (INV-1): the prefetcher never touches a path after the lookup; only `PixelBuffer::id()` reaches the cache and `planned_ids`.
- T2 (generation): both `run_retry` and `apply_lookup` compare `generation` for equality; `navigated` bumps it on EVERY call (also with the same index) and on the clearing call.
- T3 (arithmetic, section 7 item 3): `index + step * i` and the `ticks_from_ms` products use `checked`/`saturating` (a huge `window_ms` is already clamped, but `from_environment` is also used with injected getters in tests).
- T4 (culture, section 7 item 2): the numbers are parsed with the invariant rules only (no `,` decimals, no Unicode digits, no grouping); `trim` differs between `str::trim` (Unicode White_Space) for the enabled flag (C# `string.Trim()`, same set) and the .NET number-style whitespace (ASCII set) for the integers: keep both as specified.
- T5 (never claim a message): `try_handle` returns `None` for EVERY message, interaction or not; a test sends all 17 table messages and asserts `None`.
- T6 (reference cycle): the controller lives in the window's handler list, so it must not hold the window strongly: `is_window_active` captures a `Weak` (D-W8B4V-7). A test drops the window and checks the controller reports inactive and the window is freed.
- T7 (re-entrancy): `PlanChanged` handlers call `GpuImageCache::retain`; they run with no prefetcher borrow held. `apply_lookup` may be called while a host callback of the SAME navigation is on the stack (a fake host that applies synchronously): no `RefCell` double borrow.
- T8 (clock mixing): never use QPC / `host::frame_clock::base::qpc_now` in `keep_warm.rs`.
