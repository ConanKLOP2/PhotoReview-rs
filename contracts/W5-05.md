- Semantics notes (each names the C# lines so the verifier can diff; "nav" = `crate::tiff_nav`):
  1. **`can_read`.** `extension` equals `.orf` under OrdinalIgnoreCase (`.ORF`, `.Orf` yes; `orf`, `.orf `, `.orfx`, `.nef`, `""` no) else `false`; then `len < 4` => `false`;
     then true for exactly the first four bytes `49 49 52 4F` (IIRO), `49 49 52 53` (IIRS), `4D 4D 4F 52` (MMOR), `49 49 2A 00` (II*\0). Plain big-endian TIFF `4D 4D 00 2A`,
     `MMSR`, BigTIFF are `false` even though `read` would parse the first two (golden `can-read-*`, 33 cases).
  2. **`read` header.** `source.length() < 16` => `invalid_data("File too short for ORF container.")`. Read 16 bytes at 0, `tiff::try_read_header` (needs `II` or `MM`, both letters).
     `None`, or `magic` not in `{42, 0x4F52, 0x5352}` => `invalid_data("Invalid ORF header.")`. Magic is read in the file byte order, so `MMOR` gives 0x4F52 and `MMSR`
     0x5352 (big-endian `MM` + 42 is also accepted; `II` + `OR` swapped is not). Copy the three header fields before the next `read` (borrowed slice).
  3. **IFD walk.** `current = i64::from(ifd0_offset)`, `ifd_index = 0`. Loop `while current > 0 && ifd_index < limits::MAX_IFD_COUNT` (`ifd_index: i32`): `token.check()?` first; `visited.insert(current)` false => `break`
     (a `HashSet<i64>`, never iterated); `let ifd = nav::read_ifd_entries(source, current, le)?` (`ifd.entries`, `ifd.next_ifd_offset`); process; `current = i64::from(ifd.next_ifd_offset)`; `ifd_index += 1`. An IFD that
     `read_ifd_entries` rejects (offset < 8, beyond the file, count 0) returns no entries and next 0, so the walk ends without an error. Previews of IFDs 0..=63 only (golden:
     chains of 64, 65, 66 IFDs all give 64 previews).
  4. **Per entry (in entry order; the LAST duplicate wins, which is observable).** Locals per IFD: `jpeg_offset: Option<i64>`, `jpeg_length: Option<i64>`, `ifd_width/ifd_height: i32 = 0`.
     - `0x0112`: only when `ifd_index == 0`: `nav::read_tag_unsigned`; `Some(v)` with `1 <= v <= 8` sets `orientation = v as i32`; anything else (None, 0, 9, 65535) keeps the previous value
       (a second entry in range overrides, golden `orientation-second-entry-*`). Orientation of IFD1+ is ignored.
     - `0x0100` / `0x0101`: `if let Some(v) = read_tag_unsigned(..)?` then `ifd_width = nav::clamp_to_int(Some(v))`. A readable zero RESETS the value to 0 (`size-duplicate-width-zero-last-resets`);
       an unreadable entry (None) leaves the previous value (`size-duplicate-width-unreadable-last-keeps-first`). SLONG/SSHORT negatives clamp to 0. LONG `0xFFFFFFFF` => `i32::MAX`
       (no wrap to negative; `i64` arithmetic, never `as i32` on the raw value).
     - `0x0201` / `0x0202`: `jpeg_offset = read_tag_unsigned(..)?` and `jpeg_length = ...` are plain assignments of the `Option`: a later unreadable duplicate sets it back to `None`
       (`preview-duplicate-offset-tag-unreadable-last-clears`). Do NOT write `if let Some(..) = ..`.
     - `0x8769` (ExifIFD pointer): `read_tag_unsigned(..)?` is `Some(p)` with `p > 0` => `nav::read_ifd_entries(source, p, le)?` (the next pointer is discarded); for every entry with tag `0x927C`
       and `count > 4`, `maker_note_offset = Some(i64::from(value_or_offset))`. No visited set for the Exif IFD (an ExifIFD pointer back to IFD0 terminates because IFD0's own entries are
       re-read once; cost is bounded by 64 IFDs x 4096 entries).
     - `0x927C` directly in the IFD: `count > 4` => `maker_note_offset = Some(i64::from(value_or_offset))` (count 4 means the 4 value bytes ARE the data; count 0..4 never an offset). The last
       `0x927C` seen in any IFD, in entry order across `0x8769` expansions, wins (goldens `note-pointer-*`).
     - everything else ignored.
  5. **After the entries of an IFD.** `ifd_index == 0 && ifd_width > 0 && ifd_height > 0` => sensor size = `(ifd_width, ifd_height)` (IFD1+ never sets it; a zero in either IFD0 dimension leaves
     `(0, 0)`, even when the width is 4080). `jpeg_offset > 0 && jpeg_length > 0 && nav::starts_with_soi(source, off, len)?` => `preview_w/h = ifd_width/ifd_height`,
     `nav::reconcile_jpeg_size(source, off, len, &mut pw, &mut ph, read_frame)?` with the `read_frame` closure of "Assumed shared API" (only acts when both are declared: the JPEG frame header wins; a header-budget failure keeps the declared size),
     push `EmbeddedPreview { index: previews.len() as i32, offset, length, kind: Jpeg, width: pw, height: ph, color_space: Unknown, header_resolved: false }`. NO de-duplication in the
     IFD loop: the same JPEG in two IFDs is listed twice (`previews-same-jpeg-in-two-ifds-is-listed-twice`), unlike MakerNote previews.
  6. **MakerNote.** After the loop: `maker_note_offset` is `Some(n)` with `n > 0 && n < source.length() - 16` (strict: a note starting 17 bytes before the end is parsed, 16 is skipped;
     golden `note-with-{18,17,16,15,1}-bytes-before-the-end-of-file`) => `parse_olympus_maker_note(source, n, le, &mut previews)?`.
     In it: `available = min(32, length - note_offset)` (>= 17 here; keep the C# `< 16` early return anyway); copy those bytes out. Signature dispatch in THIS order:
     `"OM SYSTEM\0"` (10 bytes) => `note_le = bytes[12] == b'I' && bytes[13] == b'I'`, `ifd_start = n + 16`, `base = n`; `"OLYMPUS\0"` (8 bytes) => `note_le = bytes[8]=='I' && bytes[9]=='I'`,
     `ifd_start = n + 12`, `base = n`; `"OLYMP\0"` (6 bytes) => legacy: `note_le = file byte order`, `ifd_start = n + 8`, `base = 0`; else plain: `ifd_start = n`, file byte order, `base = 0`.
     Marks other than exactly `II` (`MI`, `IM`, `MM`, `XX`) mean BIG-endian, whatever the file's order. Then `entries = nav::read_ifd_entries(source, ifd_start, note_le)?.entries`:
     every entry with `tag == 0x0100 && count > 4` => `add_preview(source, base + value_or_offset, i64::from(count), previews)?` (all of them, in order);
     then the FIRST `0x2020` entry (`nav::try_get_entry`) points (`base + value_or_offset`) at the CameraSettings IFD, read with `note_le`; `nav::read_tag_value` for `0x0101` (PreviewImageStart) and
     `0x0102` (PreviewImageLength): both `Some` => `add_preview(source, base + start, length, previews)?`. Missing either, or no `0x2020` => nothing.
     `add_preview` ignores the candidate unless `nav::is_range_in_file(offset, length, len) && length >= 4 && read(offset, 2) == [0xFF, 0xD8] && no listed preview has the same offset`
     (the short-circuit order matters: the 2-byte read must not happen for an out-of-range candidate); it pushes width/height 0, `Unknown`, `header_resolved = false`.
     Sums are `i64` of a `u32`-range value and a file offset, so they cannot overflow; a negative SLONG start makes `is_range_in_file` false.
  7. **Exif block.** `exif_blocks = vec![nav::compute_exif_block(source, le, i64::from(ifd0_offset))?]` AFTER the MakerNote step (so the header budget is spent in the C# order).
  8. **Result.** `RawContainerInfo { format: Orf, sensor_width: decoded_width(sensor_width), sensor_height, orientation, previews, exif_blocks }`. `decoded_width(4080) == 4056`, every other value
     unchanged (4079, 4081 untouched; height never changed). Pinned by `OrfDisplayedSizeTests`; the corpus sizes are E-P3 4056x3040, E-M1 4640x3472, OM-1 5220x3912.
  9. **Errors are values.** Every C# `InvalidDataException` thrown by the header source or the navigator becomes `Err(RawHeaderError)` and propagates with `?` (the only places that swallow one are inside
     `nav::reconcile_jpeg_size` and `nav::compute_exif_block`, W5-02). Cancellation is `Err` of the cancellation variant, checked once per IFD iteration only. No `unwrap`/`expect`/indexing that can
     fail: use `get()` or slice patterns on the copied note header.

module `pr_test_support::tiff_bytes` (no RAW types, so no crate cycle): `TiffBytes::new(little: bool, size: usize)`, `.header(ifd0: u32, signature: &[u8])` (empty = `II*\0` / `MM\0*`), `.put(pos, &[u8])`, `.u16(pos, v)`,
`.u32(pos, v)`, `.ifd(pos, next, &[Entry])` (a SHORT of count 1 is left-justified in the value field), `.to_vec()`, and `Entry`, `short(tag, v)`, `long(tag, v)`, `at(tag, ty, count, offset)`; plus `create_minimal_jpeg(w, h)`
(byte-for-byte `SyntheticRawBuilder.CreateMinimalJpeg`: SOI, APP0 JFIF, DQT, SOF0, DHT, SOS, 6 data bytes, EOI = 163 bytes), `build_tiff(little, jpeg, orientation, magic)`, and `raw_corpus::{directory(), try_get_file(name), files(exts),
is_strict()}` (`tests/fixtures/raw-corpus`, env `PHOTOREVIEW_RS_RAW_CORPUS_STRICT`). `InMemoryRawHeaderSource` ships in `pr-imaging-raw` (W5-01), because `pr-test-support` cannot depend on it. The existing private `TiffBytes` inside
`crates/pr-imaging/src/tiff.rs` tests is the starting point. If the lead has not landed these when W5-05 is ported, the porter stops with a BLOCKED note instead of inventing a private copy (three units would diverge).

## Golden package
- `oracle/W5-05.cs`: command `orf-container` (ops `can-read`, `read`, `corpus`). Runs `OrfContainerReader` over a real temp file through `SourceRawHeaderSource(FileStream)` (so the 64 KiB block cache and the 8 MiB budget
  are the production ones). Dispatch line, csproj reference to `PhotoReview.Imaging.Raw.dll` and the `oracle.ps1` build step for `src\PhotoReview.Imaging.Raw` are in the file header. Needs nothing from other oracle files.
- `golden-inputs/orf-container.json` (233 cases, generated by `golden-inputs/gen-orf-container.mjs`, which mirrors `TiffBytes` and is for reviewers only). Case design: every `CanRead` signature, each single signature byte flipped,
  extension casing; every accepted and rejected magic in both byte orders; IFD0 offsets 0/4/7/beyond/`FFFFFFFF`; sizes by type (BYTE/SHORT/LONG/SLONG/SSHORT/RATIONAL, out-of-line, zero count, unknown type), clamping, the 4080/4079/4081
  rule, height untouched, duplicate width entries (last wins / zero resets / unreadable keeps); orientation 0/1/6/8/9/65535, duplicates, IFD1; IFD chain of 64/65/66, self and mutual cycles, next pointer below 8 / beyond file / six-byte room;
  4095/4096/4097 entries (cap and dropped chain); preview pointer to padding / beyond / length 3, 4 / offset 0 / not SOI / single tag / duplicates incl. unreadable-clears / stored as SHORT / SLONG negative; declared size vs frame; the
  budget-exhausting JPEG (140 APP segments, 9 MB); MakerNote count 0/1/3/4/5/8, offsets 0/7/8/beyond/`FFFFFFFF`, 18..1 bytes before the end, tag/count of the thumbnail entry, duplicates, signatures `OLYMPUS`/`OM SYSTEM`/legacy
  `OLYMP`/none/wrong terminator in both file orders, note marks `II`/`MI`/`IM`/`MM`/`XX`, CameraSettings start/length missing, length 3 vs 4, first-entry-wins, ordering of thumbnail vs settings vs IFD previews, the last-wins rule for
  `0x927C` between IFD0 and the Exif IFD; EXIF block growth to 128 KiB+, exactly at / one over the 4 MiB cap, small file, IFD0 offset 0, big endian. Three `corpus` cases (E-P3, E-M1, OM-1: sizes, orientation, previews incl. the offset-52224 JPEGs).
- `golden-reference/`: produced by the wiring step (`tools/oracle.ps1 -Command orf-container`, after `fetch-raw-samples` so the corpus cases have `present: true`); this draft did NOT run the oracle.
- Rust golden test contract: node `{hex}` or `{len, patches[{at, hex, times?}]}` (zero-filled buffer, patches applied in order, `times` repeats the hex); `can-read` runs the first `min(64, len)` bytes with `ext`; `read` runs
  `OrfContainerReader::read` on `InMemoryRawHeaderSource` and compares `ok`, `error` (`"InvalidDataException"` <=> the invalid-data `RawHeaderError`; any other error kind or a panic is a failure), `message` (only when the golden value is not
  null), `format` (`"Orf"`), `sensor_width/height`, `orientation`, and the arrays field by field (`kind` `"Jpeg"`, `color_space` `"Unknown"`, `header_resolved` false); `corpus` cases are skipped when `present` is false or the file is
  missing (panic in strict mode). The 9 MB budget case allocates 9 MB: fine.

## Open questions
1. **Shared API names (W5-01a/b, W5-02a, W5-11).** The drafts written in parallel agree on `RawHeaderError`, `read(&mut self, .., count: i32)`, `&mut dyn RawHeaderSource`, `TiffEntry.field_type`,
   `try_get_entry -> Option<TiffEntry>` (W5-04's compile-check shim says `Option<&TiffEntry>`: both work with `if let Some(e) = ..`), `reconcile_jpeg_size` with a `read_frame` closure. They still differ on: the
   module path of the navigator (`crate::tiff_nav` in W5-02a, `readers::tiff_navigator` in W5-04's shim), the `read_ifd_entries` result (`IfdRead` vs a tuple), the reader error type (W5-04 invents
   `RawReadError`, W5-01b has `RawHeaderError::Canceled`; this draft follows W5-01b), the `limits` path and integer type (`MAX_IFD_COUNT: i32` here), and `read_tag_unsigned_array`'s `max_items`.
   Recommended: the lead reconciles on W5-01b / W5-02a (the owners of the shared definitions) before any porter starts; the change in this unit is one `use` block plus call sites.
2. **Where the shared test builders live** (`TiffBytes`, `create_minimal_jpeg`, `raw_corpus`). Recommended: `pr_test_support` (pure bytes, usable from `pr-imaging`, `pr-imaging-raw` and later crates). Alternative: `crates/pr-imaging-raw/tests/common/mod.rs`
   (each test file says `mod common;`; W5-03..W5-09 copy it). The lead decides once for all of Wave 5.
3. **Corpus provisioning.** The C# fetch script `tools/fetch-raw-samples.ps1` + `tools/raw-samples.txt` (CC0 files from raw.pixls.us, SHA-256 pinned) have no Rust twin; `tests/fixtures/raw-corpus/` is not in `.gitignore`. Recommended: sync
   both scripts with `tools/sync-from-csharp.ps1` (never hand-edit), add `tests/fixtures/raw-corpus/` to `.gitignore`, name the strict switch `PHOTOREVIEW_RS_RAW_CORPUS_STRICT` (R0002 prefix) and set it only in the CI job that fetched the corpus.
   Without the corpus the 3 `corpus` golden cases and the corpus tests are skipped; the synthetic coverage above is complete on its own.
4. **JPEG frame check in the corpus preview test.** C# decodes the preview with WPF `BitmapFrame.Create`. Recommended: SOI/EOI bytes plus `try_read_jpeg_frame` (W5-11) width/height > 0, no decoder. A WIC decode would be `#[ignore = "native"]`
   and belongs to W5-12.
5. **Unreachable C# branch.** `ParseOlympusMakerNote`'s `available < 16` return cannot fire (the caller guarantees `note_offset < length - 16`). Kept in the stub text for a 1:1 diff; the porter may keep it as a dead guard or drop it (mutation
   survivor is documented as equivalent).
