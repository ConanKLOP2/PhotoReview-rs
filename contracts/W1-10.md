## Semantics notes

### AppVersion::try_parse (C# `AppVersion.TryParse`) — apply the steps in EXACTLY this order
1. `None`, `""`, or a string of only Unicode whitespace → `None`. (`char::is_whitespace` has the same set as C# `char.IsWhiteSpace`; NUL is NOT whitespace.)
2. `s = text.trim()` (Unicode whitespace, both ends).
3. If the first char is `v` or `V`, drop it (one char only). `"v"` therefore becomes `""` and fails at step 7 (one part, not three). `"vv1.2.3"` fails at step 8 (part `"v1"`).
4. Cut at the FIRST `+` (build metadata): everything from the `+` on is discarded. Done BEFORE the `-` search, so `"1.2.3+x-y"` is a release 1.2.3 (the `-` was inside the discarded metadata).
5. Find the FIRST `-`. If found: if it is the last char (`"2.0.93-"`) → `None`; else `is_prerelease = true` and cut everything from the `-` on (`"2.1.0-beta.1"` → `"2.1.0"`). A leading `-` (`"-1.0.0"`) leaves `s = ""`.. → fails at step 7.
6. Not a pre-release reason: nothing else (the text after `-` is never validated; `"1.2.3-!!!"` is a valid pre-release).
7. `s.split('.')` must give EXACTLY 3 parts (`"2.0"`, `"2.0.93.1"` → `None`). Rust `split('.')` on `""` yields one empty part, like C#.
8. Each part: non-empty, every char an ASCII digit (`0-9` only; NOT `char::is_numeric`, NOT `+`/`-`/space/NUL), and it must fit `i32` (`NumberStyles.None` + invariant: `"2147483647"` OK, `"2147483648"` and `"99999999999"` → `None`). Leading zeros are fine (`"01"` → 1). Use `part.parse::<i32>()` only AFTER the all-ASCII-digit check (Rust's parse would accept a leading `+`).
9. Result `AppVersion{major,minor,patch,is_prerelease}`. On any failure C# leaves `default` (0.0.0, false); Rust returns `None`.
Trap: `"1.2.3\0"` must be rejected (the NUL is not a digit). Whitespace inside (`"1. 2.3"`) is rejected.

### Ordering (`Ord::cmp`)
Compare `major`, then `minor`, then `patch` numerically (as `i32`); if all equal, the release sorts ABOVE the pre-release: `other.is_prerelease.cmp(&self.is_prerelease)` (note the swapped operands; `false < true`). Build metadata and pre-release label text are not kept, so `2.1.0-beta.1` == `2.1.0-rc.2` in ordering and in `==`. Pre-release of a higher number still wins: `2.0.94-rc.1 > 2.0.93`.

### Display
`format!("{}.{}.{}", major, minor, patch)`; the pre-release flag is not printed (`"v2.1.0-beta.2+abc"` → `"2.1.0"`). Plain integer formatting is culture-free.

### validate_update_url (C# `UpdateUrlPolicy.Validate`)
Returns the normalized absolute URL (the string `System.Uri.AbsoluteUri` would produce) when the URL is `https://github.com/ConanKLOP2/PhotoReview` or below it. Otherwise `None`. There is no `System.Uri` in Rust and no `url` crate may be added: implement this subset by hand. Every rule below was verified against .NET 10 (`Uri.TryCreate(s, UriKind.Absolute)`); the golden file pins them. Do NOT "improve" on them.

Let `s = url.trim()` (None/whitespace-only → `None`).

**1. Scheme and separators.** `s` must start with `https` (ASCII case-insensitive), then `:`, then exactly TWO separator chars, each `/` or `\` (so `https:\\github.com/...` and `https:/\github.com/...` are valid), and the next char must NOT be `/` or `\` (`https:///github.com` → `None`). One slash or none (`https:/github.com`, `https:github.com`) → `None`. Any other scheme (`http`, `ftp`, `file`, `javascript`, `ms-settings`) or no scheme → `None`. Output scheme is always lowercase `https`.

**2. Authority** = the text after the separators up to the first `/`, `?` or `#` (a `\` is NOT a terminator: any `\` inside the authority → `None`; `https://github.com\ConanKLOP2\PhotoReview` → `None`). An authority containing `?`-start, e.g. `https://github.com?/x`, ends at `?`, giving path `/` → rejected by the path check.
- userinfo: if the authority contains `@`: more than one `@` → `None`; text before the `@` must be EMPTY, otherwise `None` (`user:pw@`, `github.com@evil.example`, `:@`, `us er@` all → `None`). An empty userinfo (`https://@github.com/...`) is ACCEPTED and the output keeps the `@` right after `//` (`https://@github.com/ConanKLOP2/PhotoReview`).
- port: after the last `:` of the host part. Empty (`github.com:`) is fine. Otherwise it must be only ASCII digits whose numeric value is 443 (`:443`, `:0443`, `:00000000000443` are accepted; `:8443`, `:65536`, `:abc`, `:+443`, `:443:443` → `None`). The port is never printed.
- host: the rest must equal `github.com` ASCII-case-insensitively (`GitHub.Com` ok; `github.com.`, `xn--github.com`, `github.com.evil.example`, any non-ASCII char incl. fullwidth/ideographic-dot lookalikes, `[::1]`, empty → `None`). Printed lowercase.
- `https://github.com` with nothing after the authority has path `/` (rejected by step 5).

**3. Path** = from the first `/` after the authority up to the first `?` or `#` (if there is no `/`, the path is `/`). Transform char by char:
  a. `\` → `/`.
  b. `%` followed by two hex digits (either case), byte value `b`:
     - `b` is an ASCII unreserved char (`A-Z a-z 0-9 - . _ ~`) → emit that char (`%41` → `A`, `%7E` → `~`, `%2e` → `.`).
     - `b < 0x80` otherwise (`%2F`, `%20`, `%00`, `%7f`, `%5c`, `%22`, `%7C`...) → emit the 3 chars VERBATIM, hex-digit case unchanged (`%2f` stays `%2f`).
     - `b >= 0x80`: take the maximal run of consecutive `%XX` escapes with `b >= 0x80` starting here; if the bytes up to the first complete UTF-8 sequence are valid UTF-8, emit each byte of that sequence as `%` + UPPERCASE hex (`%c3%a9` → `%C3%A9`); if the sequence is invalid or incomplete (`%e9`, `%c3`, `%c3%28`, `%C0%AE`) emit the escapes verbatim (case unchanged). (Valid or not, any character that is later reported is ASCII-only, so only the exact bytes matter for the golden comparison.)
  c. `%` NOT followed by two hex digits → emit `%25` (the `%` only; the following chars are processed normally: `%zz` → `%25zz`, `%E0%A4%A` → `%E0%A4%25A`).
  d. Any other ASCII char in `0x00..=0x20`, `0x7F`, and `" < > ^ \` { | }` → `%` + 2 UPPERCASE hex digits (`a b` → `a%20b`, tab → `%09`, newline → `%0A`, NUL → `%00`, `"` → `%22`, `^` → `%5E`, `|` → `%7C`). Kept literally: letters, digits and `! $ & ' ( ) * + , ; = : @ [ ] - . _ ~ /`.
  e. Non-ASCII char → its UTF-8 bytes, each as `%XX` uppercase (`é` → `%C3%A9`, U+200B → `%E2%80%8B`, an emoji → 4 escapes).
  f. Remove dot segments on the resulting string, segment = text between `/`: a segment `.` is dropped; a segment `..` is dropped together with the previous segment (at the root nothing more is popped: `/../x` → `/x`); `...` and `..;` are ordinary segments. If the path ENDS with a `.` or `..` segment the result ends with `/` (`/a/b/..` → `/a/`, `/a/b/.` → `/a/b/`). Empty segments are kept (`//` stays `//`). Because step (b) already decoded `%2e`, `%2E%2e`, `.%2e` count as dot segments (`/ConanKLOP2/PhotoReview/%2e%2e/Evil` → `/ConanKLOP2/Evil`), while `%2F`, `%5c` stay encoded and do not create segments (`..%2FEvil` is one ordinary segment).

**4. Query and fragment.** The first `?` (before any `#`) starts the query; the first `#` starts the fragment (a second `#` or `?` inside stays literal: `#a#b`). If `?` is present (even empty: `PhotoReview?`) the output has `?` + query; if `#` is present (even empty) the output has `#` + fragment. Escaping: same rules (b), (c), (e) as the path, and rule (d) with the same char set EXCEPT that `\` is escaped as `%5C` (not turned into `/`). No dot-segment processing. Order in output: path, then `?query`, then `#fragment`.

**5. Allow-list test** on the normalized path (it is now pure ASCII, so `str::eq_ignore_ascii_case` equals OrdinalIgnoreCase): path equals `/ConanKLOP2/PhotoReview` or starts with `/ConanKLOP2/PhotoReview/`, both ASCII-case-insensitive. So `/ConanKLOP2/PhotoReview.`, `/ConanKLOP2/PhotoReviewEvil`, `/ConanKLOP2/PhotoReview%20/x` fail; `/ConanKLOP2/PhotoReview/` and `/conanklop2/photoreview/releases/latest` pass. The check happens AFTER dot-segment removal and decoding, so `/ConanKLOP2/PhotoReview/../Evil/x` fails and `/ConanKLOP2/x/../PhotoReview` passes (normalized to `/ConanKLOP2/PhotoReview`).

**6. Result** = `"https://"` + (`"@"` if an empty userinfo was present) + `"github.com"` + normalized path + (`"?"` + query) + (`"#"` + fragment). Path case is preserved exactly as typed (only host is lowercased): `https://GITHUB.com/conanklop2/photoreview/releases/latest` → `https://github.com/conanklop2/photoreview/releases/latest`.

Anything not covered above that .NET might still accept is out of scope: reject (`None`) rather than guess, and report it under `behaviour_doubts`.
