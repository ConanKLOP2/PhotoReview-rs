## Scope and decisions (D-01d-1 to D-01d-6 settle what the plan left open; the lead may reverse any of them before the contract PR)

- **D-01d-1 Trait seams, not concrete types.** The C# `FitViewController` takes `ViewerState` (W8-06a), `ViewportOperationVersion`
  (W8-05a) and the WPF surface. W8-06a depends on this unit (plan row 06a: `01a, 01d`), so a concrete dependency would be a cycle.
  This unit defines the traits `FitSurface`, `FitViewer` (`reset_fit`) and `OperationVersion` (`next`, `current`); the owners implement them.
- **D-01d-2 `ZoomDetailRefreshResult` is defined in `viewport::fit`** (type owner: this unit). It is a 5-variant enum with the C# values
  (0..4). W8-07g (`coordinators::zoom_detail`) imports it from here. **Lead: add the edge W8-07g depends on W8-01d** (the plan lists 07g
  as `01a, 06d, pr_imaging::service` only). `ViewRefreshOutcome` (a record that holds it) lives here too.
- **D-01d-3 `ViewerStretchMode` is NOT defined in this unit.** The plan row lists `ViewModels/ViewerStretchMode 11` under 01d, but
  `ViewportSnapshot` (W8-01a, `viewport::types`) and `ViewportContracts` need the enum before 01d merges. Its Rust home is
  `viewport::types::ViewerStretchMode` (W8-01a). Lead: correct the 01d row in the plan; the 11 lines are ported by 01a.
- **D-01d-4 Stability rule is a parameter.** `ViewportConvergence.IsStableViewport` (C# `MainWindowConvergence.cs`, W8-04e as
  `misc::viewport_convergence::is_stable_viewport`) is passed as a `fn` pointer (`StabilityRule`). No compile dependency on 04e for
  the stub or the port. The tests use the real 04e function (test-only dependency).
- **D-01d-5 Continuation state, no controller field.** The C# `async` method keeps its locals across the render yield. In Rust the state
  is the `FitContinuation` value, returned in `FitStep::AwaitRender` and handed back to `apply_fit_resume`. A single `Option<PendingFit>`
  field would lose the state of a superseded Fit, and C# still runs that Fit's `Capture` once after the yield (test
  `a_zoom_while_the_fit_waits_supersedes_it` pins it). Hence: free functions, no struct.
- **D-01d-6 Yield is the shell's job.** `IFitSurface.YieldToRenderAsync` is removed from the trait. `FitStep::AwaitRender` says "the
  shell must let the queue run down to Render priority, then call `apply_fit_resume` with this continuation" (W8-13d
  `UiDispatcher::post`, D-W8-2). The driver calls `apply_fit_resume` exactly once per `AwaitRender` and never after `Finished`.
  The test harness simulates the yield by logging `Yield` and calling resume.

## Semantics (from the C# code; the stub doc comments repeat the order)

### Fit: `apply_fit_start` (C# `ApplyFitAsync` up to the first `await`)
1. `cancel_pan()` (once, first).
2. `version = versions.next()` (the one version this Fit owns).
3. `(w, h) = surface.viewport_size()`; `viewer.reset_fit(w, h)` (called even when the surface is not loaded).
4. Pass 0 starts with the check of section "loop check" below, then `update_layout()`, `update_fit_size()`, and returns
   `AwaitRender(FitContinuation { version, pass: 0, last: None })`.

### Fit: `apply_fit_resume` (C# code after `await surface.YieldToRenderAsync()`)
1. `current = surface.capture()`. **No version or loaded check before the capture.** C# captures even when superseded.
2. If `last` is `Some(l)` and `stable(&l, &current)`: break, go to step 5. (The first capture of a Fit never ends the loop.)
3. Else `last = Some(current)`; `pass += 1`.
4. If `pass < 3`: loop check (below), then `update_layout()`, `update_fit_size()`, return `AwaitRender` with the new pass.
   If `pass == 3`: fall through to step 5.
5. Final section: loop check (below) without the layout; then `update_layout()` (**not** `update_fit_size()`) and `scroll_home()`.
   Return `Finished`.

**Loop check** (C# `if (version != viewportVersion.Current || !surface.IsLoaded) return;`): if `versions.current() != version` or
`!surface.is_loaded()`, return `Finished` at once, without any layout, scroll, or capture.

Consequences the golden trace tests encode:
- Pass count is at most 3, captures at most 3, final layouts = passes + 1 (the final `update_layout`).
- A superseded Fit: its waiting continuation still captures once (step 1), then stops at the loop check (step 4). No scroll home.
- Two Fits: only the newest one reaches `scroll_home`.
- Not loaded at start: `cancel_pan`, `reset_fit`, then `Finished`. Nothing else.

### Zoom menu rules
- `PRESET_PERCENTS` is the menu order, exactly `[50, 70, 100, 150, 200, 300, 400]`. The C# `ZoomPresets` (MainWindow) is the same list.
- `calculate_click_level_from_effective_zoom(z)`: `None` for `None`; `None` when `z` is not finite (NaN, +inf, -inf). Otherwise
  `r = (z * 100.0).round()` (Rust `f64::round` rounds half away from zero, like `MidpointRounding.AwayFromZero`), `as i32` (saturating), then clamp
  to `[MIN_CLICK_ZOOM_PERCENT, MAX_CLICK_ZOOM_PERCENT]`.
  Checked values: 1.0 -> 100; 1.499 -> 150; 1.501 -> 150; 2.505 -> 251 (`2.505 * 100.0` rounds to exactly 250.5 in f64, so the
  half-away rule gives 251); 0.125 -> 13 (12.5 away from zero); 0.004 -> 10; 0.01 -> 10; 50.0 -> 800; 1e308 -> 800; -5.0 -> 10.

## Traps (docs/MULTI-AGENT-PLAN.md section 7, items 3, 4, 9 and this unit)
1. **Order inside `apply_fit_start`**: `cancel_pan` before `next()`, `next()` before the viewport-size read, `reset_fit` before the
   first loaded check. A test asserts the trace order.
2. **No version check before the capture in resume** (decision D-01d-5). Adding one makes the superseded-zoom test fail (Capture count 0
   instead of 1).
3. **`break` goes to the final section, it does not return.** The final section calls `update_layout` and `scroll_home` (not
   `update_fit_size`), and does its own loop check.
4. **The first capture never ends the loop**: stability is checked only when `last` is `Some`. The test `first_capture_never_ends_the_loop`
   pins it (with an always-true rule the Fit still makes a second pass).
5. **Argument order of the stability rule is `(last, current)`**, as C# `IsStableViewport(lastSnapshot, currentSnapshot)`. A test records it.
6. **Rounding**: multiply by 100 in f64 first, then round half away from zero. Not `round_ties_even` (0.125 -> 12, 2.505 -> 250), not
   division by 0.01 (other results), not `as i32` before rounding.
7. **Non-finite input**: check `is_finite()` before any arithmetic and return `None`. Do not `unwrap` a `try_from`: a finite `z` can make
   `z * 100.0` infinite (`f64::MAX`), and the saturating `as i32` then clamps to MAX, the same as .NET 9+ (the C# result is 800 too).
8. **Clamp bounds come from `pr_core`** (`MIN_CLICK_ZOOM_PERCENT`, `MAX_CLICK_ZOOM_PERCENT`), never hard-coded 10 and 800.
9. **Plain data**: `ViewRefreshOutcome` and `ZoomDetailRefreshResult` have no logic. Discriminants must equal the C# values (0..4): the
   golden for the refresh result (none in this unit) would compare by value.
10. **No `unsafe`, no `windows` crate in this unit** (pure module, `pr_app` rule).

## Open questions (each with the recommended default; the lead may confirm or change)
1. **`ViewportSnapshot` derives.** `FitContinuation` derives `PartialEq`, so 01a must derive `PartialEq` on `ViewportSnapshot`. Default: yes
   (C# records are value types). If 01a rejects it, drop `PartialEq` from `FitContinuation` and from `FitStep`.
2. **Where `ZoomDetailRefreshResult` lives.** Default: `viewport::fit` (D-01d-2). Alternative: move it to `viewport::types` (01a).
   Either way 07g imports it; the edge must be recorded.
3. **Duplicate click-level function.** C# has `MainWindowHelpers.CalculateClickLevelFromEffectiveZoom` and `ZoomMenuRules.CalculateClickLevelFromEffectiveZoom`
   (identical). Default: one Rust function here; W8-02a and W8-14e use it. Nothing else to port from `MainWindowHelpers` (the WPF file is retired).
4. **Yield driver.** The shell calls `apply_fit_resume` through `UiDispatcher::post` at Render priority (D-01d-6). Default: the shell
   keeps the continuation in the closure it posts (no shared slot). If the shell needs cancellation on window close, it drops the
   continuation; `apply_fit_resume` is then never called (equivalent to C# `IsLoaded` false, which the loop check already covers).
5. **`capture` takes `&self`.** Default: yes (C# `CaptureViewportSnapshot` is read-only). The WPF-era adapter needed no mutation either.
