## Semantics notes
1. **`decode` (C# `Decode(DecodeRequest)`).** Caller bytes (`request.bytes == Some`) are decoded in place (`&bytes[..]`, no copy). Otherwise `load_file`
   (2-3) yields a `Vec<u8>` and the file is already closed (INV-8). Run `decode_bytes`. On `Err(e)`: when `request.bytes.is_none()` AND
   `FallbackImageDecoder::is_fallbackable(&e)` -> `e.attach_source_bytes(Arc::from(vec))` (the ONE copy of the file, only on this failure path, trap T6);
   never attach for caller bytes or a non-fallbackable error (the buffer must not ride on it). `Ok(image)` -> `Arc::new(image)`.
2. **`load_file`.** In this order: (a) path blank (`path.as_os_str().is_empty()` or every char `char::is_whitespace`, C# `IsNullOrWhiteSpace`) ->
   `InvalidArgument { NO_SOURCE }` + `no_source()`; (b) `!file_exists(path)` -> `FileNotFound { IMAGE_NOT_FOUND }` + `image_not_found(path)` (path as
   `to_string_lossy`, captured by value in the closure); (c) one private `open_shared(path)` helper used by every open of this file: `OpenOptions::new().read(true)` plus, under
   `#[cfg(windows)]`, `std::os::windows::fs::OpenOptionsExt::custom_flags(FILE_FLAG_SEQUENTIAL_SCAN = 0x0800_0000)` (C# `FileOptions.SequentialScan`,
   INV-8 / I-20; std only, no Windows crate). std's default share mode on Windows is read|write|delete = C# `FileShare.ReadWrite | FileShare.Delete`:
   do not change it. NO `BufReader` (C# `bufferSize: 64 KiB` is FileStream-internal; a Rust buffer would add reads and break the read counts); an open error of kind `NotFound` (vanished, or a missing directory) -> the SAME localized `FileNotFound` as (b); any other
   open error -> `DecodeError::Io(e)` (not localized); (d) `length = metadata.len()` (u64 -> i64, saturate); (e) `source_fits(length, memory_info)` false ->
   `NotSupported { "JPEG source is too large for the available memory: {length} bytes." }` + `output_too_large(0, 0, length)` (fallbackable: WIC streams it);
   (f) `read_all_bytes(&mut file, length)`, errors per 3. Drop the file before returning. `request.priority` is IGNORED (C# `LoadBytes`
   opens a plain `FileStream`; no lane/throttle at the baseline) and `request.path` is not read at all when `request.bytes` is `Some`.
3. **Bounded whole-file read.** `read_all_bytes`: `length > MAX_SOURCE_BYTES` -> `TooLarge` before any read (decoder maps to `NotSupported { "JPEG source is
   too large to read into memory: {length} bytes." }` + `output_too_large(0, 0, length)`); else `Vec::try_reserve_exact(length)` (failure -> `OutOfMemory`, decoder
   maps to `DecodeError::OutOfMemory`, NOT fallbackable, as C# `OutOfMemoryException`), `resize(length, 0)`, then a fill loop of `read(&mut buf[filled..])` until
   full or `Ok(0)`; `Interrupted` is retried; `truncate(filled)`. No `read_to_end` (it issues a probe read; `ReadAllBytes_ExactLength_OneRead` counts calls).
   `source_fits`: `length < GUARD_THRESHOLD_BYTES` -> true with ZERO `memory_info` reads; else one read and `memory_headroom::has_headroom(length, total, load)`.
4. **`decode_bytes`, before any native call** (C# order; each step is observable through which error wins): (a) `len < 3 || [0] != FF || [1] != D8 || [2] != FF`
   -> `NotSupported { NOT_JPEG_PREFIX + label }`, `label` = the path text, or `messages::MEMORY_BUFFER` when the path is empty; user text
   `not_jpeg(path or texts.memory_buffer())`, both evaluated inside the closure; (b) `scan_header(bytes, true, true)`; `has_icc` -> `NotSupported { ICC_FALLBACK }`
   + `icc_fallback()` (no decompressor created, no buffer allocated: `IccProfile_FallsBackWithoutAllocating`); (c) `orientation = 1`; when
   `request.apply_orientation`: `request.source_orientation` AS GIVEN (no normalisation: 9, 0, -1 are kept) else `parse(exif_tiff)` (empty -> 1;
   `exif_parser::try_read_orientation(..).map_or(1, i32::from)`); (d) `exif = exif_parser::try_parse_tiff_block(exif_tiff)` ALWAYS (also when orientation is
   not applied, also for an empty slice: returns `None`); (e) `transposed = apply_orientation && orientation::is_transposed(orientation)`.
5. **Native header.** Every `Decompressor` call is `?`-propagated first (an `Err` is the C# exception escaping the P/Invoke: e.g.
   `EntryPointNotFound` stays fallbackable, `Disposed`/`InvalidArgument` do not; NEVER map an `Err` to a return code), then its `Ok(code)` is
   interpreted. `decompressors.create()?` (errors propagate unchanged), `configure_strict_decoding` (`set(ScanLimit, 500)?` code ignored, an
   `Err` still propagates as in C#; `set(StopOnWarning, 1)? != 0` -> `InvalidOperation { STRICT_FAILED_PREFIX + (native or UNKNOWN_CONFIGURATION_ERROR) }` + `strict_mode_failed(native or no_detail())`, NOT fallbackable),
   `decompress_header(bytes) != 0` -> `InvalidData { HEADER_FAILED_PREFIX + (native or HEADER_PARSE_ERROR) }` + `header_failed(native or no_detail())`;
   `w = get(JpegWidth)`, `h = get(JpegHeight)`; `w <= 0 || h <= 0` -> `InvalidData { INVALID_DIMENSIONS_PREFIX + "{w}x{h}" }` + `invalid_dimensions(w, h)`.
   The native text is read with `error_message()` right after the failing call, before any other call on that decompressor.
6. **Scale decision.** `target = (w, h)`, `factor = ONE`. When `request.is_downscale_requested()`: `target = request.decode_box().fit_stored(w, h, transposed)` (the
   box is in DISPLAYED pixels); when `target.0 < w || target.1 < h` -> `factor = select_scaling_factor(w, h, target.0, target.1)`. Then ALWAYS call
   `set_scaling_factor(factor)`; a non-zero result resets `factor = ONE` (target unchanged: the decode runs at full size and fine-scales).
   `select_scaling_factor`: first factor of `SUPPORTED_SCALING_FACTORS` with `scaled_size(w) >= tw && scaled_size(h) >= th`, else `ONE`;
   `scaled_size(s, f) = (s as i64 * num + denom - 1) / denom`.
7. **Output buffer and guard.** `calculate_output_buffer(w, h, factor)` exactly as its doc (`i64` math, saturating stride/length); `Err(o)` -> `InvalidData {
   "TurboJPEG output dimensions are too large: {o.width}x{o.height} ({o.buffer_length} bytes)." }` + `output_too_large(o.width, o.height, o.buffer_length)`, WITHOUT
   reading `memory_info` (`Decode_ImpossibleOutputSize_*`: the source panics/fails if consulted; in Rust the fake source records calls). Then
   `output_fits(buffer_length, memory_info)`: below 128 MiB no read; at exactly 128 MiB one read (`8192 x 4096 x 4`); false -> `MemoryAdmission {
   "TurboJPEG output dimensions are too large for the available memory: {sw}x{sh} ({len} bytes)." }` + `output_too_large(sw, sh, len)` (NOT fallbackable, INV-12).
   The guard uses the SCALED size (`Decode_DownscaleOfAHugeDeclaredSize_*`: 20000^2 with box 2000 -> 1/8 -> 2500^2 fits 1 GiB).
8. **Decode and finish.** `PixelBuffer::allocate(sw, sh, Bgr32)`: `OutOfMemory` -> `DecodeError::OutOfMemory { message: e.to_string() }` (C# raw
   `OutOfMemoryException`, not fallbackable, not localized); any other `PixelBufferError` (unreachable after semantics 7) -> `InvalidArgument
   { e.to_string() }`. There is NO `From<PixelBufferError> for DecodeError`: map `buffer.bytes_mut()` explicitly (`Disposed` -> `DecodeError::Disposed`,
   unreachable). `decompress8(bytes, dst, buffer.stride(), Bgrx)?` (an `Err` drops the buffer by scope); `!= 0` -> drop the buffer FIRST, then
   `InvalidData { DECOMPRESS_FAILED_PREFIX + (native or DECOMPRESSION_ERROR) }` + `decompress_failed(native or no_detail())`. The decompressor may be dropped as
   soon as `decompress8` returned (not observable). Plan: `fine_scale = downscale && (sw > tw || sh > th)`; `orient = apply && orientation > 1`; `original =
   transposed ? (h, w) : (w, h)`; `downscaled = downscale && (sw < w || tw < w || th < h)`. `finish_with_codec`: fine scale -> drop the source buffer
   immediately after `resize` returned Ok; `apply_orientation(buffer, orientation)` when `orient` (2..=8 rotate; >8 returns the same buffer); `FineScaleError::OutOfMemory`
   or `ApplyOrientationError { error: OutOfMemory, source }` (drop `source`) -> the 7 `MemoryAdmission` with `plan.scaled_width/height/buffer_length`;
   `FineScaleError::Failed(e)` -> `e`; any other `ApplyOrientationError` -> `DecodeError::Disposed`/`InvalidArgument` by kind; then
   `estimated = buffer.byte_count()`, `(pw, ph) = (buffer.width(), buffer.height())`, `codec.image_from_pixels(buffer)?` (the codec owns the buffer from here: an
   error drops it), `DecodedImage::new(image, pw, ph, estimated, DecodedImageOptions { downscaled, orientation: plan.orientation, actual_backend: TurboJpeg,
   original_width, original_height, exif, is_degraded_fallback: false })` (an `Err` -> `InvalidArgument { e.to_string() }`; unreachable). Exactly one
   `NativePixelMemory` is alive after a successful decode (the returned one) and none after any failure.
9. **`try_read_segment`** (the C# loop, byte for byte; `usize` indices, `checked_add` where a sum could exceed `usize`): `while offset + 2 <= len`:
   `jpeg[offset] != FF` -> `End(false)`; skip fill: `while offset + 1 < len && jpeg[offset + 1] == FF { offset += 1 }`; `offset + 2 > len` -> `End(true)`;
   `marker = jpeg[offset + 1]`; `00` or `FF` -> `End(false)`; `D9` -> `End(false)`; `01`, `D8`, `D0..=D7` -> `offset += 2; continue`; `DA` -> `End(offset + 4 >
   len || offset + 2 + be16(offset + 2) > len)` (the SOS header itself must be complete, RV-I03); `offset + 4 > len` -> `End(true)`; `length = be16(offset + 2)`;
   `length < 2` -> `End(false)`; `offset + 2 + length > len` -> `End(true)`; `payload = jpeg[offset + 4 .. offset + 2 + length]`, `offset += 2 + length`,
   `Segment`. Loop exit (`offset + 2 > len`) -> `End(true)` ("ran out at a segment boundary": `FF D8` alone needs more data). `header_needs_more_data`: `len < 4` or
   no `FF D8` -> false; else walk from 2 until `End(n)` -> `n`.
10. **`scan_header` / `read_exif_orientation`.** As the stub docs. The ICC test comes first and the EXIF test is in the `else` branch of the same segment
    (an `E2` can never be the Exif segment, an `E1` never ICC). `exif_tiff` is `&payload[6..]` of the first Exif-headed `E1` (possibly empty, which still ends the EXIF
    search). Stop rule after each segment, including the very first one when nothing is wanted.
11. **Header-area reads.** `read_header_area`: open with the 2c `open_shared` helper (errors as `SourceReadError::Io`; the caller maps with `DecodeError::from`, so `NotFound` becomes an
    unlocalized `FileNotFound`, C# raw `FileNotFoundException`), `length` from metadata, buffer `min(length, HEADER_READ_CHUNK)` via `try_reserve_exact`, fill loop,
    truncate on a short read, then `grow_header_area(.., HEADER_READ_CAP)`. `grow_header_area`: `limit = min(length, cap, MAX_SOURCE_BYTES)`; loop condition in the C#
    order `len < length && len < limit && header_needs_more_data(&buf)`; new size `min(limit, 2 * len)` (`i64` math; a `len` of 0..3 never loops because
    `header_needs_more_data` is false below 4 bytes, so no infinite loop); copy, read the new tail with the fill loop; a short tail returns the bytes that exist
    immediately. `extend_header_area`: second open of the file (C# does reopen: 2 opens per failed first parse; keep it), `seek(Start(initial.len()))`, cap 64 MiB.
12. **`read_info(path)`.** (a) `path.trim()`-blank per 2a -> `InvalidArgument { messages::BLANK_PATH }` (not localized); (b) `!file_exists` -> localized
    `FileNotFound` (as 2b); (c) `header = read_header_area(path)` (errors: `Io` -> `DecodeError::from(io)`, `OutOfMemory` -> `OutOfMemory`); (d) signature check on
    `header` -> `NotSupported { NOT_JPEG_PREFIX + path }` + `not_jpeg(path)` (a 2-byte file is `NotSupported`, a 3-byte `FF D8 FF` is `InvalidData` later); (e)
    `orientation = read_exif_orientation(&header)` (from the FIRST buffer, even if the extended read sees more; keep this, C# parity); (f) `try_read_dimensions(&header)`
    `Found` -> `ImageInfo::with_orientation(w, h, orientation)` (STORED size; `width()/height()` swap for 5..=8); (g) else `full = extend_header_area(path, header.clone())`
    (the porter may avoid the clone by passing ownership and comparing lengths first); when `full.len() > header.len()` and `try_read_dimensions(&full)` is `Found` ->
    that; (h) else `try_read_dimensions(&full)` AGAIN for its `native_error` (a third fresh decompressor, C# parity) -> `InvalidData { INFO_FAILED_PREFIX + (native or
    HEADER_PARSE_ERROR) }` + `info_failed(native or no_detail())`. `try_read_dimensions`: fresh decompressor, strict mode (errors propagate), `decompress_header(..)? != 0` ->
    `Failed { error_message() }`; `get(..)?`; sides `> 0` -> `Found`, else `Failed { None }`. ReadInfo has NO output-size guard (`huge-65500` reports 65500x65500).
13. **`NativeDecompressors` / `NativeDecompressor`.** `create`: `library: None` -> `crate::native::create_decompressor()`, `Some(lib)` ->
    `lib.create_decompressor()`; `Err(NativeError)` -> `DecodeError::from` (W5-13a: `tj3Init` NULL -> `InvalidOperation { native::INIT_FAILED_MESSAGE }`,
    library not loadable -> `DllNotFound`/`BadImageFormat`, missing export -> `EntryPointNotFound`); `Ok(handle)` -> `Box::new(NativeDecompressor(handle))`.
    `NativeDecompressor` owns the W5-13a `TurboJpegHandle` (`Drop` = `tj3Destroy` via the handle's own `Drop`); each trait method calls exactly
    one handle method and maps `Err` with `DecodeError::from`. NO second destination-size check: W5-13a's `decompress8` already re-reads the
    header and refuses a too-small `dst`/`pitch` with `Err(InvalidArgument)` before any native call (W5-13a semantics 8, its OQ5); the decoder
    propagates that `Err` (not fallbackable; unreachable from the C# sequence). No `unsafe` in this file.
14. **Threads and panics.** `TurboJpegDecoder` holds only `Arc`s of `Send + Sync` seams: share one instance. No `unwrap`/`expect`/unchecked index on input-derived
    values; every parser path returns a value or an `Err` for ANY byte input (hardening tests). A panicking `TurboJpegTexts` closure is already contained by
    `DecodeError::describe`.
15. **Divergences (record as `// DIVERGENCE:` in the tests and in the PARITY notes).** D-1: a request path cannot be null in Rust; an EMPTY path is treated as C#
    `null` (label "memory buffer"), where C# `""` would print an empty label. D-2: no `ArgumentNullException` for a null codec. D-3: C# `UnauthorizedAccessException`
    (not an `IOException`) and Rust `Io(PermissionDenied)` (an `is_io_exception` true) differ in that predicate; both are non-fallbackable, same verdict. D-4: the file
    bytes are copied once into an `Arc<[u8]>` when attached to a fallbackable failure (C# shares the array); success paths do not copy.

## Traps checklist
- T1 **Fine scaler.** C# calls `WicPixelScaler.Resize` (owner decision "b"), NOT `PixelAreaResampler` (W5-14a's note "the decoder calls area_resampler::resize" is
  outdated at d92d6aae). The decoder takes a `FineScaler`; production wires the WIC adapter; the area resampler may be used only by tests that do not compare pixels.
- T2 §7.3 arithmetic: `scaled_size`, `calculate_output_buffer`, `grow_header_area` sizes in `i64`; `offset + 2 + length` cannot overflow `usize` but write it so it
  obviously cannot (`len - offset` comparisons or `checked_add`).
- T3 §7.8 null vs empty: `Option<String>` native error text; `None` -> `HEADER_PARSE_ERROR`/`DECOMPRESSION_ERROR`/`UNKNOWN_CONFIGURATION_ERROR` in the log text but
  `no_detail()` in the user text (two different fallbacks, both tested: `Assert.DoesNotContain("no detail")` cases have a native text).
- T4 §7.9 exception arms: `NotSupported` (signature, ICC, source too large: fallbackable) vs `InvalidData` (native header/scan, dimensions, impossible size:
  fallbackable) vs `MemoryAdmission` (guard: NOT fallbackable) vs `InvalidOperation` (strict mode: NOT) vs `OutOfMemory` (allocation: NOT) vs `FileNotFound` (NOT).
  The golden `fallbackable` field pins every row.
- T5 The orientation applied to pixels is the raw value; the REPORTED orientation is `plan.orientation` (1 when not applied, else the raw value, also 9 or -1).
- T6 Do not keep a second copy of the source on success; `Arc::from(vec)` only inside the fallbackable-error branch.
- T7 INV-8: the file handle is closed before `decode_bytes` starts (scope it in `load_file`); `FileHandlesReleasedImmediatelyAfterDecode` renames the file right
  after `decode` returns.
- T8 INV-12: `MemoryAdmission`/`OutOfMemory`/`FileNotFound`/`InvalidOperation` never carry source bytes.
- T9 Memory budget reads: `output_fits` and `source_fits` read the source at most ONCE and never below the threshold (tests count calls).
- T10 The 4th byte of a pixel: TurboJPEG BGRX writes `0xFF`; after the WIC fine scale it is unspecified. Goldens hash B,G,R only; `x_bytes_all_ff` is checked only
  for non-fine-scale rows.
- T11 `read_info` orientation comes from the first 64 KiB+ buffer only, dimensions may come from the extended one (C# parity, `lead-com-20` read-info row).

## Open questions
1. **Seams vs C# shape.** Recommended (stub): the decoder takes 5 `Arc` seams (`codec`, `scaler`, `memory_info`, `decompressors`, `texts`). Alternative: a builder
   with defaults (`native()`), which needs `pr-turbojpeg` to know the production memory probe (in `pr-platform-win`) and the catalog texts: rejected (D13/D41 and
   no `pr-platform-win` dependency outside dev).
2. **FineScaler adapter home.** Recommended: a 15-line `pub fn fine_scaler() -> Arc<dyn FineScaler>`-style adapter in the composition root (W8), mapping
   `ScaleError::InsufficientMemory` and `Pixels(OutOfMemory)` to `FineScaleError::OutOfMemory` and every other `ScaleError` to `Failed(DecodeError)` by its
   `dotnet_kind()` (Com -> `Com { hresult }`, Disposed -> `Disposed`, width/height -> `InvalidArgument`). Alternative: in `pr-platform-win` next to `wic::scaler`
   (then `pr-platform-win` depends on `pr-turbojpeg`, a new edge). The test support has its own copy for the native tests.
3. **`Decompressor` location.** Recommended: in `decoder.rs` (this unit owns the decision points; W5-13a only provides the handle). Alternative: W5-13a defines the trait in
   `native.rs`; then the stub's trait moves there unchanged and `NativeDecompressors` becomes W5-13a's.
4. **Number formatting in `output_too_large`.** `EnglishTurboJpegTexts` prints plain invariant digits; if the C# `Tr.ErrDecoderOutputTooLarge(long, long, long)` renders
   `{bytes}` with group separators, the golden `user_text` shows it and the English implementation (and the catalog-backed one) must follow (W1-11 `LocTemplate`
   rules). Check at the first golden run.
5. **`TurboJpegSyntheticFormatTests`** (grayscale/CMYK/YCCK/odd subsampling flavours compressed by `tj3Compress8`). CONFLICT with W5-13a OQ4, which
   already ships `create_compressor`/`compress8` as test support. Recommended (revised at review): use W5-13a's `compress8` and port both tests natively
   (no extra oracle command, no fixtures; the C# test itself compresses at run time). Alternative: a follow-up oracle command `turbojpeg-synthetic-fixtures`
   writing those JPEGs plus a decode golden, `compress8` dropped from W5-13a; until then the two tests are `#[ignore = "blocked: W5-14b OQ5"]` placeholders.
6. **Fixture size.** `tests/fixtures/turbojpeg/` is about 19 files, the largest `parity-640x480.jpg` (~60-90 KB); total well under 1 MB (D39 precedent 235 KB). The
   orientations 2..8 are produced by `set_orientation` instead of 70 more files.
