## Semantics (C# is the spec)
1. **Order of effects** (the contract of this unit): `set_current_image(image, is_file_change, change)` calls `callbacks.set_current_image(image.clone(), is_file_change, change)` FIRST (the view model updates the viewer state and records `ImageChanging` for a file change), then `hub.set_current_image(image, is_file_change)` (the main window re-reads the layout). `set_status_text`, `apply_initial_view_mode`, `on_presented` forward to their callbacks only (the hub is not involved). `trace_presented` forwards to `hub.add_trace`. `take_viewer_zoom_change` forwards to `callbacks.take_viewer_zoom_change` (NOT in the C# sink: the C# view model raised the zoom through a re-entrant event; the Rust presenter pulls it right after `set_current_image` / `apply_initial_view_mode`, W8-07h note 7, W8-08a O1). Nothing is forwarded to the hub that the view model has not seen first.
2. **`ShellPresentationHub::set_current_image`**: `current_image = image`, `current_image_presented = false`, `image_change_count += 1` (wrapping, C# `int++` unchecked), then raise `ImageChanged(image.as_ref(), is_file_change)` to a snapshot of the handlers, in subscription order, with no state borrow held (a handler may call `current_image()` and `subscribe_image_changed`).
3. **`add_trace(token, kind, assigned)`**: when `current_image_presented` -> `emit(token, kind, assigned)` now. Else, when 16 marks already wait, remove the OLDEST (index 0), then push the new one: the queue never exceeds `MAX_PENDING_TRACES` (a minimised window never draws). `kind` is copied (`String`).
4. **`note_frame_presented(contained_image)`**: `!contained_image` -> return (a canvas-only frame changes nothing). Else `current_image_presented = true`; an empty queue -> return; else take the whole queue, clear it, emit each mark in insertion order. A second call with an empty queue emits nothing (no re-emit).
5. **`emit(token, kind, assigned)`**: `!perf.is_enabled()` -> return; else, in THIS order (the perf analysis `pr_perf::nav` reads `RenderedFrame` after `Presented`): `perf.rendered(token, perf.ms_since(assigned))`, `perf.presented(token, kind)`, `perf.rendered_frame(token, perf.ms_since(assigned))`. `ms_since` is read once per call, as C# calls `PhotoReviewPerf.Ms(assignedTimestamp)` twice; the two values differ by microseconds and `RenderedFrame` is the frame-accurate proxy.
6. **C-18**: `RenderedFrame` of a mark is the `note_frame_presented(true)` that follows the image; 13j computes `contained_image = frame.main_drawn && ptr_eq(composer.current(), hub.current_image())` or `compare_images > 0` (window-level rule, C# `ShellMainWindow.Viewing.cs` 251-260; not this unit) and 13i passes it to `note_frame_presented` after each present.
7. **Not ported**: the C# cross-thread marshalling of `InvokeUi` and the `ReviewMetrics.RecordCrossThreadPresent()` counter (D-W8B4V-10): the sink and hub hold `Rc`s, so they are `!Send` and a call from another thread does not compile; the dispatcher and metrics constructor arguments are dropped. `CrossThreadPresentCount` stays 0 (the value ADR 0005 expects).
8. **Factory**: `create(callbacks)` returns `Box<dyn IPresentationSink>` over a clone of the shared hub `Rc`. The `pr_shell` `PresentationSinkFactory` trait is implemented in the composition root (W8-17c) as a thin adapter that converts `pr_shell`'s `MainViewModelSinkCallbacks` into [`SinkCallbacks`] (adding `take_viewer_zoom_change` from `PresentationBridge::take_viewer_zoom_change`) and calls `create` (D-W8B4V-11). W8-09a's text ("W8-16i implements the factory trait") is superseded.
9. **`PlatformImage` clone**: cheap (`Arc`), so the sink hands one clone to the view model and moves the original to the hub.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (order, ADR 0005 / C-16): view model before hub, every time; a test with a shared `Vec<String>` log pins it (`viewmodel:True` before `surface:True`).
- T2 (re-entrancy, D-W8B4X-11): the `ImageChanged` handler of the window (13j `on_hub_image_changed`) only QUEUES the image and posts a safety-net drain; it does not run `composer.set_incoming`, `invalidate_layout` or `window.invalidate` (those run in `drain_pending_images`, after the view-model borrow ended). It may call `hub.current_image()` and `hub.subscribe_image_changed`; no `RefCell` borrow of the hub is held during the raise (T-repeat of D-W8B4V-9). A handler that unsubscribes itself must not break the iteration.
- T3 (unbounded growth): the pending-trace list is capped at 16 after the push (assert `pending_trace_count() <= 16` with 100 marks, and that the oldest ones are the dropped ones).
- T4 (flag reset): `set_current_image` clears `current_image_presented` for EVERY new image, so the mark of image N+1 waits for its own frame (`NewImage_ResetsThePresentedFlag...`).
- T5 (disabled perf log): with `is_enabled() == false` nothing is emitted but the marks are still consumed from the queue (the C# `Emit` returns early after the dequeue).
- T6 (no `unsafe`, no thread): the unit has no thread-safety code; do not add `Send` impls to "make the sink usable from workers" (the presenter owns the sink on the UI thread).
