## Public API

P0 measurement driver is blocking for production p95 and W8-12j decisions: either (a) run `PhotoReviewRs.exe` with `PHOTOREVIEW_RS_FRAME_LOG` and the W8-20b `pr-platform-win::ui_driver::post_key(hwnd, virtual_key, down)` poster, or (b) update `r0001-spike` to use the production surface as W8-12j requires. W8-20b specifies the PostMessage key poster, but its bodies are still `todo!()` on origin/master (3a0d144), so it is not implemented. P0(a) also needs a 250 ms timer loop around the poster, a small bin/tool **to be added by a later unit**. Posted `WM_KEYDOWN` bypasses the OS input queue and IME: valid for frame timing, invalid for IME checks. Hand-pressing Right-arrow at a steady rhythm is not an acceptable substitute for the 250 ms matrix, so P0 remains blocking until one automated route works. Until P0, the spike-only adapter/run subset is indicative and cannot start or cancel W8-12j.

## Semantics

### Preconditions and setup

1. P0 must hold for production results. W8-12d, W8-12e, and W8-12h must be merged.
2. Record CPU, GPUs, default/active adapter and identification method, driver versions, RAM, Windows, power plan, AC state, app build, and display topology.
3. Test the internal panel at 150% DPI, then a second monitor at a different DPI; move the foreground window between them. Keep display on; disable screen saver/sleep.
4. Generate 40 JPEGs at 6000x4000 (24 MP): `cargo run -p pr-shell --features ui-spike --bin r0001-spike -- --generate <dir> 40 6000x4000`. Record actual count and size; earlier R0001 fixtures were about 8 MB each, not a guaranteed generated size.
5. `r0001-spike` supports Left/Right/wheel/drag/F/1/Esc and has no text box, does not use production keep-warm, and uses the spike swap chain. IME checks are a separate qualitative check in the running production app: type real Vietnamese Telex/VNI and Japanese or Chinese IME text into the first reachable single-line Edit control (settings builder `Edit(label, ..)` in `crates/pr-platform-win/src/dialogs/settings/builder/inputs.rs`; otherwise benchmark dialog `FOLDER_ID`/`LIMIT_ID` in `crates/pr-platform-win/src/dialogs/benchmark/layout.rs`). Check composition display, candidate-window position, no hang, and no lost key. The settings builder code merged in #161, but the dialog composition/open path has `todo!()` stubs; defer only if no such dialog is reachable in the running build. Posted `WM_KEYDOWN` is not valid for this IME check. A frame log may be observed during typing only if an automated timing loop can run at the same time; no keep-warm loop is required for this qualitative IME check.

### Commands and switches

Spike-only command: `cargo run -p pr-shell --features ui-spike --bin r0001-spike -- <folder> --measure 100 --interval-ms 250`. `PHOTOREVIEW_RS_SPIKE_ADAPTER` is read in `crates/pr-platform-win/src/spike_ui.rs`: a number selects the DXGI adapter index, `warp` selects WARP, anything else selects default hardware. It affects only the old spike.

Production-only variables are in `crates/pr-platform-win/src/shell_viewing`: `PHOTOREVIEW_RS_GPU_KEEPWARM=0` (also `off`, `false`, `no`; `_MS` and `_INTERVAL_MS` tune keep-warm) and `PHOTOREVIEW_RS_FRAME_LOG=<file path>`. The spike does not use either. Frame log appends CRLF lines: `F gap=<F1 ms> frame=<F2 ms> endDraw=<F2 ms> present=<F2 ms>`; empty/unset disables it. Run 100 switches 250 ms apart. Record p50/p95/max and frames above 50 ms; retain the first-switch outlier in primary numbers and optionally show an excluded diagnostic row.

### Decision rule: start or cancel W8-12j

For each measured physical adapter A, M(A) is median of its three keep-warm-ON production p95 values; note any rendering-path frame above 50 ms.

| Case | Action |
|---|---|
| Any M(A) >10 ms | START W8-12j; note disagreements. A good adapter never masks the active adapter. |
| All measured M(A) <8.5 ms and no rendering-path frame >50 ms | CANCEL; R0001 Accepted; close W8-12j as “not needed” in `task_on_progress.md`. |
| All M(A) <=10 ms and at least one is in [8.5, 10], or all are <8.5 but any rendering-path frame >50 ms | Run three more for each affected adapter (6 total); use six-run median. >10: START. <8.5 and no >50 ms frame: CANCEL/Accepted. Otherwise DO NOT START (D-W8B3S-11), leave R0001 Proposed and record values. |
| Only one adapter available | Apply cases above; state other unavailable. Provisional and R0001 stays Proposed until second adapter measured, unless machine has only one GPU, then final. |
| Single run >10 ms but initial M(A) <=10 ms | Record outlier; it does not decide by itself. |

The lead records the result in R0001 Measured and Reading and updates `task_on_progress.md`.

## Traps

| Condition | Action |
|---|---|
| Laptop on battery / wrong plan | Pause, connect AC, restore plan, rerun affected condition; retain aborted log. |
| Adapter missing | Mark unavailable; do not infer its performance. |
| Run aborted, app loses foreground, display sleeps | Preserve log as invalid; rerun condition from run 1 if later samples may be affected. |

Do not use spike results to claim production parity or decide W8-12j.
