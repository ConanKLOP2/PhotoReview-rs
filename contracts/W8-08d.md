- Semantics notes:
  1. **Which settings are read.** The "previous" and "new" values of the dialog comparison come from the STORE (`settings.store_current()`), not the override; the viewer quality, zoom step and later UI reads come from `settings()` (override-aware). Option settings are compared by their
     `*_or_default()` values (`loading_mode_or_default`, `decoder_backend_or_default`, `image_sort_mode_or_default`): comparing the raw `Option`s would report a change when the saved file merely gained an explicit default.
  2. **Reload versus re-present** (stub doc steps 4 and 5; C-20): `reload_folder` needs a non-empty session folder; RAW pair mode counts only when RAW support is on AFTER the change. A reload starts `start_settings_reload` and does NOT present separately (the open presents).
     A mere loading-mode / backend / RAW-full-decode change re-presents the current image after `presenter.reset_zoom_detail()` ("drop an armed target / held full decode made under the old setting"), keeping the shown capture member and the compare state (`PresentedPathOfCurrentEntry`,
     `include_capture_group_in_compare = compare.is_visible()`).
  3. **Backend change**: RAM clear immediately (`preview_service.clear_cache()`), disk clear on a worker (R2-F-16: never on the UI thread), preloaded keys cleared; with a reload the RAM clear and key clear are done again before the open (as C#).
  4. **Settings reload waits for the gate.** `start_settings_reload` returns at once when `file_action_gate` is free (the open starts in the same call, "completes synchronously"). Otherwise a waiter is registered (`when_released`, the waiter sends `MainEvent::GateReleased`), and
     `continue_settings_reload` re-checks `is_held` (the C# `while` loop). The folder and the start path are read AFTER the wait (the action may have moved the current photo or the user opened another folder). Each waiting reload opens once.
  5. **`close_session`**: `is_closed = true` first, then `folder_coordinator.dispose()` (an `order_gate_released` update resumes the parked commands), a pending open is finished as superseded (08b note 5), then `session_writer.dispose()`. The writer's own bounded wait (2 s) is inside `SessionWriter::dispose` (W2-13).
  6. **Title.** `update_folder_title(None)` uses the session folder (`""` when none). Blank folder: `ApplyInstanceLabel(app.title)`. Otherwise `main.title.withFolder` or, when `logging_enabled`, `main.title.withFolderLogging`, with `{folder}` = the content from `build_title_bar_content`, then the label.
     `build_title_bar_content` reads only memory (no disk, AGENTS.md rule 1): catalog entry length / last write, `presenter.current_photo_info()`; an empty result falls back to the folder's last segment. The label prefix is `"[label] "` exactly (one space), only for a non-empty label.
  7. **Folder line.** `set_folder_text` never parses `FolderText` back; `refresh_localized_text` re-renders it from `folder_text_folder` / `folder_text_count` / `explorer_order_applied`.
- Traps checklist:
  - **T1 Store versus override** (note 1): reading the override for the "previous" snapshot would hide a dialog change made while an override is installed.
  - **T2 Dialog is modal and synchronous**: no other call can happen during it; the snapshot must be taken BEFORE `show_settings_at` and the comparison AFTER.
  - **T3 Provisional override**: a changed dialog clears it (`SettingsSource::clear_provisional_override`) BEFORE the new values are read.
  - **T4 Order of effects** in `show_settings_at`: title, overlay, viewer quality and zoom step, EXIF line, tooltip; then the cache and preload steps; then the reload or re-present. `preload.cancel()` precedes every clear.
  - **T5 No disk I/O on the UI thread** for the preview disk clear; the file-action gate waiter must not run user code under the gate's lock (it only sends an event).
  - **T6 Closed window**: `continue_settings_reload` stops when `is_closed`; `represent_current_after_settings` needs a valid index at call time.
  - **T7 Text**: `app.title`, `main.title.withFolder`, `main.title.withFolderLogging`, `main.folderText.imageCount{,Explorer}` (plural group, `count`), no literals (D-W8-4). The "LOG" marker belongs to the catalog text.
  - **T8 Case-insensitive paths** in `choose_reload_path` (`eq_ignore_case`).
