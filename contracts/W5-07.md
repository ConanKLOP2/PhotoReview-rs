## Algorithm (exact step order; the order is observable through `previews` order and `bytes_charged`)
`can_read(first_64, ext)`: `eq_ignore_case(ext, ".arw")` (pr_core::text, OrdinalIgnoreCase) AND `first_64.len() >= 4` AND `first_64[..4] == [0x49,0x49,0x2A,0x00]`. Nothing else (a
big-endian `MM\0*` file and magic 43 are rejected; the extension has no trimming: `".arw "` and `"arw"` are false).

`read(source, ct)`:
1. `source.length() < 16` => `RawError::invalid_data("File too short for ARW container.")` (exact text, golden `reader_message`).
2. `header = source.read(0, 16)?`; `pr_imaging::tiff::try_read_header(header)` is `None` OR `magic != 42` => `invalid_data("Invalid ARW TIFF header.")`. `II` AND `MM` both pass step 2 (only `can_read` is
   little-endian only), so a big-endian file handed to `read` directly IS parsed big-endian (golden `read-big-endian-file-parsed-directly`). Copy `little_endian`/`ifd0_offset` out of the header before the next `read`
   (the slice dies at the next call). `ifd0_offset` is `u32`; widen with `i64::from`.
3. State: `orientation = 1`, `previews = Vec::new()`, `pending: VecDeque<i64>` with `ifd0_offset` pushed, `visited: HashSet<i64>` (order never observed, a HashSet is fine), `maker_note_offset: Option<i64> = None`,
   `if_count = 0usize`, `largest_area: i64 = 0`, `sensor_w/h = 0`, `crop_w/h = 0`, `exif_pixel_w/h = 0` (all `i32`).
4. `while !pending.is_empty() && ifd_count < MAX_IFD_COUNT (64)`:
   a. `ct.check()?` (=> `RawError::Canceled`). This runs at the top of EVERY iteration, also for an item that is about to be skipped (golden `cancel-ifd0-offset-zero-still-checked-at-loop-top`).
   b. `ifd_offset = pending.pop_front()`; `if ifd_offset <= 0 || !visited.insert(ifd_offset) { continue }`. Skipped items do NOT increment `ifd_count`.
   c. `(entries, next_ifd) = nav::read_ifd_entries(source, ifd_offset, little_endian)?`; `is_ifd0 = ifd_count == 0`; `ifd_count += 1`.
   d. `(width, height) = nav::read_image_size(source, &entries, le)?`.
   e. `if is_ifd0` and `nav::read_tag_value(source, &entries, 0x0112, le)?` is `Some(o)` with `1..=8` => `orientation = o as i32`. Only IFD0; IFD1/SubIFD orientations are ignored.
   f. If `try_get_entry(&entries, 0x014A)` (SubIFDs): `for sub in nav::read_tag_unsigned_array(source, &entry, le, 64)? { pending.push_back(sub) }` (the `64` is the C# default `maxItems`).
   g. If `try_get_entry(&entries, 0x8769)` AND `nav::read_tag_unsigned(source, &entry, le)?` is `Some(exif_offset)` with `exif_offset > 0`:
      - `(exif_entries, _) = read_ifd_entries(source, exif_offset, le)?`; for each exif entry with `tag == 0x927C && count > 4`: `maker_note_offset.get_or_insert(i64::from(entry.value_or_offset))`.
        QUIRK (`??=`): the FIRST such entry in the whole file latches, even with offset 0 (later notes are then never looked at; golden `note-first-latched-offset-zero-hides-later-valid-note`);
        an entry with `count <= 4` does not latch.
      - `if exif_pixel_w == 0` and `nav::try_read_exif_pixel_dimensions(source, exif_offset, le)?` is `Some((w, h))` => store both. So the FIRST complete Exif size in any IFD wins; a width-only Exif IFD
        does not count and does not block a later complete one (golden `sensor-exif-width-only-first-then-complete-later`, `sensor-exif-second-complete-is-ignored`).
      - Do not reuse `exif_entries` for the pixel size: the navigator reads again (cheap: header budget is charged per 64 KiB block once).
   h. `is_preview = nav::try_read_jpeg_interchange(source, &entries, le)?` is `Some((jpeg_offset, jpeg_length))`. If so: `(pw, ph) = (width, height)`;
      `nav::reconcile_jpeg_size(source, jpeg_offset, jpeg_length, &mut pw, &mut ph)?` (swallows an exhausted budget, propagates an I/O failure); `add_preview(&mut previews, jpeg_offset, jpeg_length, pw, ph)`.
   i. `area = i64::from(width) * i64::from(height)`; `if !is_preview && area > largest_area { largest_area = area; sensor_w = width; sensor_h = height; (crop_w, crop_h) =
      nav::try_read_default_crop_size(source, &entries, le)?.unwrap_or((0, 0)); }`. The crop is assigned UNCONDITIONALLY inside the branch: a later, larger raw IFD without crop resets the crop to 0
      (C# `out` parameters; golden `subifd-later-larger-raw-ifd-without-crop-resets-crop`). Equal area keeps the FIRST IFD (strict `>`).
   j. `if next_ifd > 0 { pending.push_back(i64::from(next_ifd)) }`. Order of the queue is therefore: SubIFDs of this IFD first, THEN its next IFD. Preview order = processing order.
5. `(sensor_w, sensor_h) = nav::choose_active_sensor_size(sensor_w, sensor_h, crop_w, crop_h, exif_pixel_w, exif_pixel_h)` (crop, else Exif size, else raw size; a candidate larger than the raw IFD in either direction is ignored).
6. `if let Some(note) = maker_note_offset && note > 0 { parse_sony_maker_note_preview(source, note, le, &mut previews)? }` (offset 0 skips).
7. `exif_blocks = vec![nav::compute_exif_block(source, le, i64::from(ifd0_offset))?]` (uses the HEADER's IFD0 offset, even if that offset was invalid or skipped).
8. `Ok(RawContainerInfo { format: RawFormat::Arw, sensor_width, sensor_height, orientation, previews, exif_blocks })`.

`add_preview`: `if previews.iter().any(|p| p.offset == offset) { return }` (offset-only dedupe: the same offset with another length is the same preview); else push `EmbeddedPreview { index: previews.len() as i32 (before the push),
offset, length, kind: Jpeg, width, height, color_space: Unknown, header_resolved: false }`.

`parse_sony_maker_note_preview(source, note_offset, le, previews)` (all early exits return `Ok(())`, in this order, because each skipped read changes `bytes_charged`):
1. `note_offset < 8 || note_offset > source.length() - 14` => return.
2. `ifd_start = note_offset`; `if source.read(note_offset, 9)? == b"SONY DSC "` (case sensitive, 9 bytes, a shorter slice is "not equal") => `ifd_start = note_offset + 12`.
3. `(entries, _) = read_ifd_entries(source, ifd_start, le)?`; the entry with tag `0x2001` missing OR `count <= 4` => return.
4. `start = i64::from(entry.value_or_offset)`, `length = i64::from(entry.count)`; `!is_range_in_file(start, length, source.length()) || length < 4` => return WITHOUT reading;
   then `source.read(start, 2)?` must be exactly `[0xFF, 0xD8]`, else return. `add_preview(previews, start, length, 0, 0)` (size 0x0: `PreviewSelector` resolves it lazily, W5-11).

## Semantics notes / traps
1. **Errors.** The only errors are the two reader texts above, `Canceled`, and whatever `source.read` / the navigator return (budget exhausted `InvalidData`, I/O). Never swallow a source error in this file
   except through the navigator functions documented to do so (`reconcile_jpeg_size`, `compute_exif_block`). Never `unwrap`/index: every slice access is `get`/`first_chunk`/`==` on a possibly short slice.
2. **Short slices.** `RawHeaderSource::read` of a production source returns exactly `count` bytes or `Err`, but test doubles (C# `FuzzTrackingHeaderSource`) return fewer. Write
   `source.read(n, 9)? == SONY_DSC_PREFIX` as `slice.starts_with(..)`/`slice == &prefix[..]` with the length check implied, and `matches!(slice, [0xFF, 0xD8])`.
3. **Arithmetic (§7 item 3).** Offsets are `i64`; `u32` fields widen with `i64::from`; `width*height` is `i64::from(w) * i64::from(h)` (no overflow); `source.length() - 14` cannot underflow because `length >= 16` was checked,
   but use `saturating_sub` anyway so a refactor cannot panic. `index as i32` of `previews.len()` is bounded by 64 + 1.
4. **Order (§7 item 10).** `previews` is a `Vec` in processing order (IFD0 jpeg, SubIFD jpegs in pointer order, then the next IFD's, ..., MakerNote last). No `HashMap` anywhere that leaks into output.
5. **`bytes_charged` is pinned by the golden.** Reads happen exactly as in the step list: header (16 bytes), then navigator reads. Do not add a "prefetch", a second header read, or a read the C# code skips.
6. **No narrowing of lengths.** `source.length()` is `i64` and stays `i64`; sizes stored in `EmbeddedPreview`/`RawContainerInfo` are the navigator's clamped `i32`.
7. **INV ids.** No journal/cache invariant is owned here. The container info feeds `SourceKind = 1` (RAW preview) of the cache key (INV-1) through W5-11/12: a wrong preview offset/size here shows a stale or wrong image
   there, so the preview list (offsets, lengths, sizes, order) is the contract. I-13: "Container errors never fall back to WPF" is enforced by W5-12; this reader only has to fail with `InvalidData`.
8. **Hostile input (hardening tests).** At most 64 IFDs, repeated IFD offsets read once, 4096 entries per IFD (navigator), previews and note ranges checked against the file length with `is_range_in_file` (offset > 0, length > 0, no overflow),
   SOI verified before a preview is listed. No allocation proportional to an untrusted count in this file.

## Open questions
1. **W5-01/W5-02 API shape.** This stub assumes: types and traits at the crate root of `pr_imaging_raw`, `limits::MAX_IFD_COUNT`, `tiff::navigator::*` as free functions taking `&mut dyn RawHeaderSource` and returning `Result<_, RawError>`,
   `RawHeaderSource::read(&mut self, i64, usize) -> Result<&[u8], RawError>`, `RawContainerReader::read(&self, &mut dyn RawHeaderSource, &CancelToken)`. Recommended: keep (dyn keeps the W5-11 registry a `Vec<Box<dyn RawContainerReader>>`). If W5-01 chooses a generic
   `S: RawHeaderSource`, only `arw.rs` signatures change. D28 applies.
2. **Where does the JPEG frame walker live?** C# `TiffHeaderNavigator.ReconcileJpegSize` calls `PreviewSelector.TryReadJpegFrame` (W5-11 in the plan). Recommended: W5-02 owns the frame walker it needs (`JpegMarkerProbe` already walks markers) and W5-11 re-uses it, so the six TIFF readers
   do not wait for W5-11. If the lead leaves it in W5-11, W5-03..08 must list W5-11 as a dependency (P-28), which serialises the whole wave.
3. **Shared helpers and ownership.** Every TIFF reader unit needs the same `InMemoryRawHeaderSource`, `TiffBytes`, spec builder, corpus helper and `mutate`. Recommended: W5-01 creates `tests/common/mod.rs` before the reader units start, and each reader unit's own test file `mod common;`.
   Alternative (not recommended): each unit copies them, six diverging copies.
4. **Corpus.** The C# corpus is gitignored and fetched by a PowerShell tool; the Rust repo has none yet. Recommended: sync `tools/fetch-raw-samples.ps1` + `raw-samples.txt` with `tools/sync-from-csharp.ps1` at the next baseline move, gitignore the folder, and keep the corpus tests
   data-gated (early return, strict env fails). The 3 pinned ARW sizes are also asserted from the golden, so a machine without the corpus still checks the synthetic 178 cases.
5. **Dropped timing assert.** The C# fuzz test asserts a p95 parse time. AGENTS.md forbids timing asserts; the Rust twin relies on the bounded loops (64 IFDs, 4096 entries, header budget) and the cargo job timeout.
6. **Cancellation granularity.** C# checks the token at the top of every loop iteration only. Kept as is; no check inside the navigator. A future change (check in the navigator for long JPEG walks) belongs to a different unit and needs a Different row.
