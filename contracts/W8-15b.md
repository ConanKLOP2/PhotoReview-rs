Time units (decision, O6): every duration is a .NET `TimeSpan` tick count (`i64`, 100 ns), so `duration.TotalSeconds` is `ticks as f64 / 1e7`,
bit-identical to C#. A `std::time::Duration` would give different f64 bits from `as_secs_f64`. Timestamps are in the caller's units (`ticks_per_second`).

## Semantics (C# is the spec)
1. **Tween start.** `start` is the timestamp of the FIRST frame after `fade_to`, not the time of the call (C# `tween.Start ??= now`). Golden `Tween starts at the first frame`.
2. **`fade_to` order** (C# `FadeTo`): (a) disposed check first; (b) target NaN -> 0, else clamp to 0..=1; (c) element missing -> remove its tween, return;
   (d) running tween with the same target -> return (no change, no request, the duration is ignored); (e) remove any tween for this element;
   (f) `duration_ticks <= 0` or element opacity already equal to target -> set opacity (when different: `changed`), return; (g) otherwise new tween
   from the CURRENT opacity, `request_frame = true`.
3. **`on_frame`.** Per tween, in order: element missing -> tween ends (no write). Else `start` is set on the first frame; `elapsed = max(0, (now - start) / tps)`
   where `now - start` is a WRAPPING i64 subtraction and `/ tps` is f64; `progress = min(1, elapsed / duration_seconds)`; the value is exactly `target` when
   `progress >= 1`, else `from + (target - from) * ease(easing, progress)`. Write only when the value differs from the current opacity (f32 `!=`).
   Tweens with `progress >= 1` are removed after the loop. `changed` is set once if any write happened. `request_frame` is never set by `on_frame`.
4. **Bit-exact interpolation.** C# types: `From`, `Target` are `float`. `Target - From` is a FLOAT subtraction; `* Ease(...)` is a double multiply;
   `From + ...` is a double add; the result is cast `(float)`. Rust: `let d = target - from;` (f32), `let v = from as f64 + (d as f64) * ease(e, p);`,
   `v as f32`. Do not compute everything in f64 (golden `Fade end lands exactly...` and the 0.02 to 0.1 case would differ by one ulp).
5. **Ease.** `Linear` = `t`. `QuadraticOut` = `1 - ((1 - t) * (1 - t))`, in that operation order (f64).
6. **Stop listening.** C# subscribes only while a tween exists. For the host this is `is_animating()`: the host subscribes when it turns true and
   unsubscribes when it turns false (C# `StopListeningWhenIdle`). `dispose` clears all tweens without writing.
7. **Frame delay start.** `secs = delay_ticks as f64 / 1e7`; `ticks = (secs.max(0.0) * ticks_per_second as f64).ceil() as i64` (saturating cast = C#
   `(long)Math.Ceiling`); `deadline = now_timestamp.wrapping_add(ticks)`. A running timer keeps running and takes the new deadline (measured from
   `now_timestamp`, not from the old deadline). Always `request_frame` (the host's job). `newly_running` is true only when it was not running.
8. **Frame delay fire.** `on_frame` does nothing when not running or when `tick.timestamp < deadline`. Otherwise it stops and returns `true`
   (C# `Stop(); _elapsed();`). A restart from the elapsed action is a new `start` call after the stop.
9. **Palette.** `TABLE` is the C# table verbatim (35 rows). `from_argb`: `a = argb >> 24`, `r = (argb >> 16) & 0xFF`, `g = (argb >> 8) & 0xFF`,
   `b = argb & 0xFF`; each channel `c as f32 / 255.0_f32` (single division; C# `int / 255f`). `get`: exact ordinal match (C# `StringComparer.Ordinal`),
   no trim, no case folding.
10. **No clock, no I/O, no logging** in any of the three files. Nothing is `static mut`; the palette has no state.

## Traps (write these as tests; each has a golden case or a `// new:` test)
- **T1 Wrong progress units.** `TimeSpan` ticks (100 ns) and the timestamp units (`ticks_per_second`) are different. Golden `Realistic 60 Hz frame sequence`
  (`ticks_per_second = 1_000_000`, `duration_ticks = 1_500_000`) pins it.
- **T2 Tween removal before the equality check.** C# removes the old tween (step e) before testing `element.Opacity == target` (step f). A running
  tween whose target differs but whose current opacity already equals the new target is removed and nothing is written (golden `Zero duration
  cancels a running tween`, and `Non-zero duration to the current opacity` cover the neighbours).
- **T3 NaN before clamp.** `f32::clamp(NaN, 0.0, 1.0)` returns NaN, which would then write NaN. Test NaN first (golden `NaN` target).
- **T4 Restored element.** A tween whose element is removed and then restored before the next frame continues from its stored `from`
  (golden `Element restored before the next frame`: the first tick writes `from` = 1.0, not the restored 0.8).
- **T5 Changed only on a real change.** Zero duration to the same value fires no `changed` (golden), but the tween is still removed.
- **T6 Wrapping subtraction.** `now - start` must not panic in debug builds (`i64::MIN - i64::MAX` overflows). Use `wrapping_sub` (C# unchecked). New test `wrapping_subtraction...`.
- **T7 Deadline restart.** A second `start` while running uses the new `now_timestamp` (golden `Start while running replaces the deadline`).
- **T8 Ordinal palette keys.** `"dark.overlay"` and `"Dark.Overlay "` are unknown (golden `get` cases). No `to_lowercase`.
- **T9 Palette division.** `c as f32 / 255.0` in f32. Dividing in f64 and casting can differ in the last bit for some channel values (golden `from_argb` compares
  bits through the f32 values).
- **T10 Disposed before missing.** `fade_to` on a disposed animator returns `Disposed` even when the element is missing (step a comes first).
