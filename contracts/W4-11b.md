- Semantics notes:
  1. **Type mapping.** C# `Func<IReadOnlyList<DecoderEntry>>` throwing becomes `FnOnce() -> io::Result<Vec<DecoderEntry>>`;
     `Func<Guid,bool>` becomes `FnOnce(&Guid) -> io::Result<bool>`. Any `Err` is what C# catches as `Exception` (all but
     `OutOfMemoryException`, which has no Rust analogue). `Guid` is `pr_core::catalog::explorer_types::Guid` (.NET `ToByteArray()` order, so the
     constants in the stub are NOT the textual order; the test `container_guids_match_wincodec_h` pins them against the textual GUIDs).
  2. **`heif` is derived.** `heif() == heif_container && hevc_decoder`. It is a method, not a stored field, so a hand-built
     `WicCodecSupport { webp: true, heif_container: true, hevc_decoder: false, .. }` can never claim HEIC.
  3. **`probe` order and exact text.** (a) call `enumerate_decoders`; on `Err(e)` return `none("WIC decoder enumeration failed: " + e)` and do
     NOT call the video seam (golden `enumeration-throws-hevc-seam-not-called`: `hevcAskedFor` null). (b) `webp` / `heif_container` = any entry
     whose `container_format` equals the constant (exact 16-byte equality). (c) ALWAYS call `has_video_decoder(&MEDIA_SUBTYPE_HEVC)` exactly
     once, even when no HEIF container was listed (golden `hevc-probe-asked-even-without-heif`). `Ok(b)`: `hevc = b`, text `found` / `not found`;
     `Err(e)`: `hevc = false`, text `"probe failed: " + e`. (d) `detail` is exactly
     `WIC decoders: {count}; WebP decoder: {found|not found}; HEIF decoder: {found|not found}; HEVC video decoder: {hevc_text}`
     (`count` is the number of entries including duplicates and non-WebP/HEIF ones). `e` is `io::Error`'s `Display`; an empty message keeps
     `"probe failed: "` including the trailing space (golden `hevc-throws-empty-message`).
     The `e` text of a native failure differs between .NET (`Exception.Message`) and Rust; only the seam-injected messages are pinned by goldens.
  4. **`current()`** is `OnceLock::get_or_init`, the equivalent of `Lazy<..>(ExecutionAndPublication)`: one probe per process, concurrent first
     callers block on it, never re-probed (a codec installed while running is seen after a restart). It must not be called from startup code.
  5. **`native::enumerate_decoders`** (steps in the stub doc comment). Details that matter: `WICCreateImagingFactory_Proxy` result `< 0` or a null
     factory is `Err` (a null factory with a non-negative result is `E_FAIL` 0x80004005, as C#); `CreateComponentEnumerator` flags are
     `WIC_DECODER_COMPONENT`, `WIC_COMPONENT_ENUMERATE_DEFAULT`; the loop runs while `Next(1, ..) == S_OK (0)` and `fetched == 1`
     (`S_FALSE` ends it). For each item QueryInterface for `IWICBitmapCodecInfo` (IID `E87A44C4-B76E-4C47-8B09-298EB12A2714`); failure to get
     it skips the item. A COM error from `GetContainerFormat` skips that item only (C# `catch (COMException)`), never aborts the walk.
     Every item pointer returned by `Next` is `Release`d exactly once; the factory and enumerator are released on every path (RAII guards).
     Also: the SDK version passed to the factory is `WINCODEC_SDK_VERSION1 = 0x0236` (W4-11a's constant, `WicInterop.cs:496`); a `Next` result
     other than `S_OK` (0) (`S_FALSE`, or a negative HRESULT) just ends the walk with what was collected (never an `Err`); a failure of
     `CreateComponentEnumerator` is an `Err` (C# lets the exception out of `finally`-protected code). Apartment: the C# runs on CLR threads
     that already have COM initialised; a bare Rust thread (and every `cargo test` thread) does not, and `CoCreateInstance` inside the WIC
     proxy then fails with `CO_E_NOTINITIALIZED`. The native seam therefore must ensure COM is initialised on the calling thread (use W4-11a's
     COM guard if it has one, else `CoInitializeEx(MTA)`; `RPC_E_CHANGED_MODE` on an STA thread (UI) means 'already initialised, continue'
     and must not be paired with `CoUninitialize`). Documented divergence: C# `catch (COMException)` does not catch HRESULTs the CLR maps to
     other exception types (`E_INVALIDARG`, `E_NOTIMPL`, ...), which would abort the walk; Rust skips the item on any failed HRESULT
     (strictly more robust, unobservable in goldens).
  6. **String reads** (`ReadString`): call the getter with `(0, null)` to get the length (in chars, NUL included); a length of `0` or `> 4096`
     gives `""`; otherwise allocate `length` UTF-16 units, call again, decode, `trim_end_matches('\0')`; any COM error gives `""`.
  7. **`has_media_foundation_decoder`.** `MFTEnumEx` (mfplat.dll) with `MFT_ENUM_FLAGS`; the C# does NOT call `MFStartup` first, and
     the contract keeps that (parity); if the first real-machine run shows `MFTEnumEx` failing with `MF_E_PLATFORM_NOT_INITIALIZED`, open a
     question rather than adding `MFStartup` silently (it changes process state). `count > 0` is the answer; release each non-null
     `IMFActivate`, then `CoTaskMemFree` the array (a null array is skipped). A negative HRESULT is `Err`.
  8. **No `windows` crate in pr-core.** The pure part (`probe`, `WicCodecSupport`) has no Windows dependency by construction; only `native`
     is `unsafe`. See Open question 1 about where the pure part lives long term.

## Golden package
- `oracle/W4-11b.cs`: command `wic-codec-probe` (dispatch line in the file header). Calls the internal `Probe` by reflection with
  expression-tree delegates (the internal `DecoderEntry` type is built with `Activator`). Reports `webp`, `heifContainer`, `hevcDecoder`, `heif`,
  `detail`, the GUID the video seam was asked for (`hevcAskedFor`, null when not called) and `supports` for the three formats. A final row named
  `constants` reports the three GUIDs textually. Not differential for the native seams (machine dependent): those are the `ignore` test.
- `golden-inputs/wic-codec-probe.json`, outputs in `golden-reference/` after the wiring step. Each Rust case builds `DecoderEntry` values from
  `guid` (textual GUID parsed in the test into .NET byte order: first group little-endian 4 bytes, second and third little-endian 2 bytes,
  then the remaining 8 bytes as written), with `enumerate: "throws:<msg>"` => `Err(io::Error::other(msg))` and
  `hevc: "found" | "missing" | "throws:<msg>"`.
- Case design: empty list with and without HEVC (an HEVC decoder alone is not HEIC), each container alone, both together, duplicates counted in
  `detail`, a GUID differing in the last digit (exact compare), enumeration failure with and without a message, HEVC probe failure keeping the
  other two flags, non-ASCII failure text (UTF-8 passthrough, no escaping), and the video seam being asked even without a HEIF container.
