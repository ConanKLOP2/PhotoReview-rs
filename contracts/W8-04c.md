## Decisions

- **D-04c-1 Traits for the C# interfaces, no `Send`/`Sync`.** `ClipboardService`, `PresentationObserver` and `ZoomPromptService` are
  UI-thread seams (the Win32 clipboard and zoom prompt belong to the owner window's thread). Only `PrewarmPreviews` (used from the
  prewarm thread) and the `KeyNameValidator` impl (pr-core trait, `Send + Sync`) cross threads.
- **D-04c-2 Unit values for C# singletons.** `UnavailableClipboardService.Instance` and `NullPresentationObserver.Instance` become
  `Copy` unit structs; there is no shared instance and no `static`.
- **D-04c-3 `PreviewStateContext` closures are `Arc<dyn Fn + Send + Sync>` public fields.** They mirror the C# settable `Func`
  properties (struct-literal syntax) and can be cloned into the preview service's own closures (same pattern as
  `PreviewServiceConfig::target_decode_width`).
- **D-04c-4 Prewarm: one short-lived thread per launch.** C# `Task.Run` becomes `std::thread::spawn`; the stat runs on that thread
  (Q-R29). `PrewarmTask::wait` joins it. Alternative (route the stat through `pr_core::io::navigation_stat`, W2-15) is open question Q2.
- **D-04c-5 Predictor split.** The geometry and the decode-box rule are pure. Every Win32 call goes through `MonitorProbe`; the real probe
  is in `pr-platform-win::shell_startup` (W8-17), with its own native twin test. `pr-app` keeps `unsafe`-free (AGENTS.md).
- **D-04c-6 `RenderFrameTrace` returns steps, not callbacks.** `start`/`cancel`/`on_frame_tick` return `Vec<FrameTraceStep>` in the
  order C# performs them (`Subscribe`/`Unsubscribe`, `FirstFrame`, `SecondFrame`). The host (W8-13a frame clock) executes them after
  the call returns; the C# reentrancy (a first-frame callback calling `Start`) becomes "perform the steps, then call `start` again".
- **D-04c-7 `ViewportSizeSource` setters take `&self`.** The source is shared between the window and the composition root. Packed
  values use `AtomicI64` (lock-free reads from preload workers); the viewport accessor is an `RwLock` (replaced once, after the window's
  first layout).
- **D-04c-8 `WpfKeyNameValidator` is replaced, not ported.** `KeyIdNameValidator` implements the pr-core `KeyNameValidator` trait by
  `try_parse(Some(s)).is_some()`. The composition root (W8-09a) registers it.

## Semantics

Each rule is checked by a test (Test plan). C# line references are to `d92d6aae`.

### contracts (R-CT)
- **R-CT-1** `try_set_text` returns `bool` and never panics for an unavailable clipboard (C# "never throws for that").
- **R-CT-2** `UnavailableClipboardService::try_set_text` is always `false` (C# `TrySetText(text) => false`), for every text including `""`.
- **R-CT-3** `NullPresentationObserver::on_presented` does nothing for any path, including `""`.
- **R-CT-4** `ZoomPromptService::prompt_custom_zoom` returns `None` on cancel (C# null) and the chosen percentage otherwise; the trait is
  the only zoom-prompt seam (C-13).

### preview_state (R-PS)
- **R-PS-1** `new()` (and `Default`): `is_original_loading_mode()` is `false`, `target_decode_box()` is `DecodeBox::UNBOUNDED`, `current_backend()`
  is `DecoderBackend::Wpf`.
- **R-PS-2** The default backend is the C# default (`Wpf`), not a Rust choice. The Rust app always replaces it in the composition root
  (W8-09b); a headless test must not rely on the default being WIC.
- **R-PS-3** Clones share the closures (`Arc`): replacing a field's closure on one clone is not visible on the other (fields are
  moved values); the closures themselves observe the live state they capture.

### prewarm (R-PW)
- **R-PW-0** C# `ArgumentNullException.ThrowIfNull(settings)` runs first. Rust takes `&AppSettings`, so there is no null case; the order
  of the remaining checks is unchanged.
- **R-PW-1** `previews` `None` gives `None`; nothing is started, the fake records zero calls.
- **R-PW-2** `path` `None`, empty, or only whitespace (`char::is_whitespace`, .NET `IsNullOrWhiteSpace`) gives `None`.
- **R-PW-3** Support check on the RAW rule: `pr_core::catalog::types::is_supported_with(path, false, settings.webp_heic_support_enabled)`
  (C# `rawEnabled: false`). Unsupported names and every RAW extension give `None`; WebP is supported only when the setting is on.
- **R-PW-4** The full path is computed with `pr_core::text::dotnet_path::get_full_path` (C# `Path.GetFullPath`, never
  `std::path::absolute`, trap 7). On `Err` nothing is started (R-PW-6).
- **R-PW-5** The thread: (a) computes `current_cache_key(full_path, target_box)` (`target_box` `None` = the service's own box, read on the
  thread, C# evaluation order); (b) on `Err` it returns silently; (c) otherwise `start_viewer_preview(full_path, &key)` and waits on the
  returned `PreviewHandle` (its result is dropped; the C# fault is observed and ignored). The start thread never blocks the caller.
- **R-PW-6 Different:** C# lets `GetFullPath` throw (an `ArgumentException` for a path with NUL) out of the launch code. Rust returns `None`
  (the prewarm is an optimisation; the presenter's own request still decodes). Recorded as a `// DIVERGENCE:` comment and a Different row.

### render_frame_trace (R-RF)
- **R-RF-1** `start` cancels the pending trace first (its `Unsubscribe` is the first step), then allocates a new id and returns `Subscribe(new)`.
- **R-RF-2** After `start`, exactly one trace is pending, whatever the number of earlier starts (C# RV-A17: 5 starts with no tick keep one
  subscription; the host's list has one id).
- **R-RF-3** `cancel` returns `[Unsubscribe(pending)]` and clears the pending trace; with nothing pending it returns `[]`.
- **R-RF-4** `on_frame_tick(id)` for an id that is not the pending one returns `[]` and changes nothing (superseded or cancelled handler).
- **R-RF-5** Tick 1 of the pending trace returns `[FirstFrame { token, kind, assigned_timestamp }]`, the trace stays pending. Tick 2 returns
  `[Unsubscribe(id), SecondFrame { token, assigned_timestamp }]` and clears the pending trace (C# calls `Cancel()` before `onSecondFrame`).
- **R-RF-6** Ids are never reused within one trace object; the counter wraps (`wrapping_add`) only after 2^64 starts, which cannot happen.

### shortcut_key_name (R-SK)
- **R-SK-1** `try_parse(name)`: (1) trim; (2) if non-empty, `canonicalize(trimmed)` (`pr_core::settings::shortcuts::canonicalize`, which
  trims again and repairs aliases); (3) refuse if empty, contains `,`, starts with an ASCII digit, or starts with `-` or `+`; (4) find the
  first `KeyId` in `KeyId::ALL` whose `name()` is `eq_ignore_case` with the text (`pr_core::text::eq_ignore_case`, never `to_lowercase`);
  (5) refuse when `is_reserved`. The digit check is redundant for the outcome (no key name starts with a digit) but kept as written, so the
  numeric refusal does not depend on the name table.
- **R-SK-2** `is_reserved(k)` is true for exactly: `None`, `Escape`, `Tab`, `ImeProcessed`, `DeadCharProcessed`, `System`, `LeftCtrl`,
  `RightCtrl`, `LeftAlt`, `RightAlt`, `LeftShift`, `RightShift`, `LWin`, `RWin` (14 keys).
- **R-SK-3** Aliases (`Return`, `Prior`, `next`, `Capital`, ...) parse to a key with the same WPF value as their canonical name; the table
  is `ALIAS_PAIRS` (29 pairs).
- **R-SK-4** Numbers are refused in every form (`999`, `-1`, `+44`, `0x41`); `KeyId` has explicit numeric values, so a number must never reach
  a value lookup (the Rust lookup is by name only, which makes this structural).
- **R-SK-5** `KeyIdNameValidator::is_valid_key_name(s)` equals `try_parse(Some(s)).is_some()`.

### viewport_size_source (R-VS)
- **R-VS-1** Defaults: `viewport_size()` is `(0.0, 0.0)`; `target_decode_box()` is `DecodeBox::UNBOUNDED` (packed `0`, the C# default);
  `startup_prediction()` is `None` (packed `-1`).
- **R-VS-2** Width and height are published in one atomic store and read in one atomic load (`AtomicI64`, `Acquire`/`Release`). No
  reader sees a width from one box and a height from another.
- **R-VS-3** Packing exactly as C#: `(i64::from(width) << 32) | i64::from(height as u32)`; unpacking `(packed >> 32) as i32` (arithmetic
  shift) and `packed as i32` (low 32 bits). Negative heights round-trip (`(0,-5)` gives `(0,-5)`).
- **R-VS-4** `set_startup_prediction(None)` stores `-1`; `startup_prediction()` returns `None` for any negative packed value, so a box
  whose packed form is negative (negative width) reads back as `None` (C# parity; the predictor never produces one, trap T-9).
- **R-VS-5** `set_viewport_size_fn` replaces the accessor (write lock); `viewport_size()` calls the current one (read lock) and returns its
  `(f64, f64)` unchanged (no clamping, no NaN handling: C# has none).

### initial_viewport (R-IV)
- **R-IV-1** `PixelRect::width` = `right - left` and `height` = `bottom - top`, wrapping (trap T-3).
- **R-IV-2** `predict_client_size`, maximized: `caption = -frame_insets.top - frame_insets.right` (the C# formula literally, `right`, not
  `bottom`); result `(work_area.width(), work_area.height() - caption)`. `normal_bounds` is ignored.
- **R-IV-3** Normal: `(normal_bounds.width() - frame_insets.width(), normal_bounds.height() - frame_insets.height())`.
- **R-IV-4** Result `Some((w, h))` only when `w > 0 && h > 0`; otherwise `None`. Works on the same arithmetic for maximized and normal.
- **R-IV-5** `predict_decode_box` follows the C# method body step by step: see the doc comment on the stub. `on_screen` uses `probe.work_areas()` (the
  C# `Win32MonitorLayout.WorkAreas()` list); a normal rect counts as visible when `WindowPlacementVisibility.IsVisible` (W8-03a) accepts
  it against those areas.
- **R-IV-6** Default size: `scale = dpi as f64 / 96.0`; `(round_ties_even(default_width_dip * scale) as i32, round_ties_even(default_height_dip * scale) as i32)`
  (C# `Math.Round` is banker's rounding, trap T-4). Placed at `(0, 0)`.
- **R-IV-7** `WS_OVERLAPPED_WINDOW = 0x00CF_0000` is the style passed to the probe's `frame_insets` (the probe is the only caller of the
  Win32 call).
- **R-IV-8** Arithmetic on `PixelRect` values is wrapping (C# `int` unchecked); no panic in debug builds (trap T-3).
- **R-IV-9** Errors: a probe `None` in the monitor, work-area, or insets steps gives `None` (C# returns null). The three exceptions the C#
  `catch` names (`EntryPointNotFoundException`, `DllNotFoundException`, `ArgumentOutOfRangeException`) are the probe's business: a
  probe reports them as `None`. `calculate_target_decode_box` returning `Err(InvalidPreviewArgument)` gives `None` in Rust; C# lets that
  exception escape (open question Q4).

## Traps (docs/MULTI-AGENT-PLAN.md section 7 applies)

- **T-1 (trap 1, OrdinalIgnoreCase).** Key names compare with `pr_core::text::eq_ignore_case`, never `to_lowercase()` or an ASCII-only
  compare. The Kelvin sign (`\u{212A}`) must not match `K`; the dotless `\u{131}` follows the generated .NET table (Q9), not an assumption.
- **T-2 (trap 8, empty versus none).** `try_parse(None)`, `try_parse(Some(""))` and `try_parse(Some("   "))` are all refused, through
  different steps; the test checks each input.
- **T-3 (trap 3, `int` wraps).** `PixelRect::width`/`height` and the packed-box shift use wrapping or bit operations. A debug build must not
  panic on `i32::MIN`-style inputs (test with `i32::MIN` left, `i32::MAX` right).
- **T-4 (trap 4, rounding).** `round_ties_even`, not `f64::round`: `0.5` gives `0`, `1.5` gives `2`, `2.5` gives `2`. Test: `scale = 1.0`
  (dpi 96), default width `2.5` gives width `2`.
- **T-5 (trap 9, exceptions).** The C# `catch` is a filter for three types only; a Rust port maps the probe's failures to `None` and leaves
  the other failure paths as `Err`/`None` as listed in R-IV-9. Do not merge them into a catch-all.
- **T-6 (trap 10, order).** `RenderFrameTrace` steps are ordered (Unsubscribe before Subscribe on `start`; Unsubscribe before SecondFrame on
  tick 2). A test asserts the exact `Vec`, not a set.
- **T-7 (trap 7, paths).** `Path.GetFullPath` is `pr_core::text::dotnet_path::get_full_path`; `std::path::absolute` differs for drive-relative
  and `\\?\` paths.
- **T-8 (names).** The `KeyId` names are the WPF `Key` names (`Return`, `Prior`, `Next`, `Capital`); the enum variant names must match the
  golden fixture exactly (checked by the fixture test). No JSON is read by production code.
- **T-9 (sentinel).** The startup prediction uses `-1` as "none". A box whose packed value is `-1` (`(-1, -1)`) is indistinguishable from
  none, as in C#. The predictor never yields negative sizes, so this is unreachable; recorded, not fixed.
- **T-10 (threads).** `prewarm::start` must not compute the key on the calling thread (C# Q-R29). The test fake records
  `std::thread::current().id()` in `current_cache_key`; the test asserts it differs from the test thread. No timing, no sleep, no barrier
  (a barrier could hang a broken `start`).
- **T-11 (UI-thread traits).** `ClipboardService`, `PresentationObserver` and `ZoomPromptService` have no `Send` bound. Do not add one to
  make a fake convenient: the fake uses `Cell`/`RefCell`.

## Open questions

- **Q1 `KeyId` shape (W8-05b).** The stub needs `KeyId::ALL`, `name()` and `wpf_value()`. Recommendation: 05b exposes exactly these three.
  Alternative: 04c owns its own name table (a duplicate of 05b's), rejected because it would drift. Changing the shape changes only
  `try_parse` and the golden test.
- **Q2 Prewarm thread (D-04c-4).** Recommendation: one `std::thread` per launch (one-shot, about 1 ms to start). Alternative: route the stat
  through `pr_core::io::navigation_stat` (W2-15) and the decode through the service's own spawner. Rejected for now: the stat worker is a
  single FIFO thread shared with navigation, which would delay the launch decode behind other stats.
- **Q3 `RenderFrameTrace` steps (D-04c-6).** Recommendation: steps (no reentrancy). Alternative: callbacks as `Box<dyn FnMut>` with a shared
  `RefCell`; rejected (the host's tick loop would re-enter the trace while it is borrowed).
- **Q4 Policy errors in the predictor.** `calculate_target_decode_box` returns `Err` for a non-finite or non-positive argument. C# lets the
  exception escape the launch code. Recommendation: `None` (no prediction; the presenter's own request still decodes), recorded as a
  `Different` row. Alternative: propagate `Err` to the caller; rejected because the caller is the launch path, which must never fail for an
  advisory prediction.
- **Q5 `ViewportSizeSource` accessor cell.** `RwLock` (recommended: the window replaces it once; reads are rare). Alternative: `OnceLock`, which
  forbids the replacement that the C# property allows.
- **Q6 Plan edges.** Add `05b` and `03a` to the W8-04c row (see Depends on); `01a` can be dropped. The lead decides.
- **Q7 Native twin placement.** The `PredictDecodeBox` native test lives in `pr-platform-win/tests/`, next to the real probe (W8-17).
  Recommendation: keep it there, because the plan keeps `pr-app` free of the `windows` crate. Alternative: a native test in `pr-app`
  through a dev-dependency on `pr-platform-win`; rejected for that reason.
- **Q8 `KeyIdNameValidator` name.** The retired C# name is `WpfKeyNameValidator`; the Rust name says what it uses. Recommendation: keep.
  Alternative: `ShortcutKeyNameValidator`.
- **Q9 .NET name folding for non-ASCII key names.** `Enum.TryParse(..., ignoreCase: true)` is assumed to fold like `OrdinalIgnoreCase`
  (the generated table of `pr_core::text`, PARITY X-ordinal-ignore-case). If the C# baseline folds differently for the dotless `\u{131}`
  or the long s, the `try_parse` body changes only in the name comparison. Recommendation: confirm once with an oracle run of
  `ShortcutKeyName.TryParse` for the 6 non-ASCII probes (outside this unit; the lead decides). Until then the test asserts consistency with
  `eq_ignore_case`, not a fixed answer.
