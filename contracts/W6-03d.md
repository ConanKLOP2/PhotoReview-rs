## Required behavior

- Constructor rejects a null pipe name. Encode before connecting; encoding errors become `Rejected`.
- Trim requests to the first `MaxPaths` in order before encoding. Write the complete framed request, then read a bounded
  response until newline/deadline. A reply whose first line is exactly `OK` is `Delivered`; any other reply is `Rejected`.
- If connection fails because no server exists, return `NoInstance`. Once request bytes may have reached the server, a
  timeout, EOF, or pipe failure yields `Unknown`, because the owner may have accepted the request. Caller cancellation
  propagates distinctly and must not be converted into `Unknown`.
- `allow_server_foreground` is best effort: when enabled, obtain the server PID from the connected pipe and request
  foreground permission; missing DLL/entry point or invalid operation is ignored while forwarding still succeeds.
- Preserve the Core trait's outcome semantics; do not move UI or process-exit policy into this adapter.

## Concurrency and safety

- Native tests use unique pipe names and bounded deadlines, and dispose their client/server handles. Avoid fixed-delay
  polling; use synchronization signals with explicit timeouts. Never connect to the production pipe.
- No filesystem mutation or Recycle Bin behavior belongs here. Paths are payload strings validated by the shared Core
  protocol and server; native tests use synthetic paths and an injected server-side existence check.
- Mutation expectations: trim count/order; encode-before-connect; timeout classification before/after write; explicit
  cancellation; reply parsing; `NoInstance` vs `Unknown`; foreground best-effort failure handling.
- Gates: `cargo fmt --all --check`; `cargo clippy -p pr-platform-win --all-targets -- -D warnings`;
  pure tests by default and native tests ignored with a reason. Final integration uses workspace gates.
