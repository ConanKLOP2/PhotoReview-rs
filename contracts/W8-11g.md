## Semantics notes (C# is the spec; the R0001 spike supplies proven calls and measured facts)

### Device creation (`d3d11.rs`)
1. `create_device(kind, flags)` is `D3D11CreateDevice(None, D3D_DRIVER_TYPE_HARDWARE | _WARP, HMODULE::default(), flags, Some(&FEATURE_LEVELS), D3D11_SDK_VERSION, Some(&mut device), Some(&mut level),
   None)` (the shape the spike uses). Success without a device object is `Err(E_FAIL)`. `CreatedDevice::is_warp` is `kind == Warp`.
2. `create_device_with_fallback(prefer_warp)`: `prefer_warp == false`: try Hardware with `DEFAULT_DEVICE_FLAGS`; success returns it (`is_warp == false`). `prefer_warp == true`, or ANY hardware failure (no GPU, RDP, driver
   error): create WARP with `DEFAULT_DEVICE_FLAGS`; a WARP failure is the error returned, with operation `"D3D11CreateDevice(WARP)"` (C# `ComInterop.Check`). The hardware error is dropped (C# did the same).
3. `create_device_on_adapter(index, flags)` (D-W8B3G-8, no C# twin): `CreateDXGIFactory1::<IDXGIFactory1>()`, `EnumAdapters1(index)` (an index past the last adapter is `Err` with `DXGI_ERROR_NOT_FOUND`,
   0x887A0002), cast to `IDXGIAdapter`, `D3D11CreateDevice(Some(&adapter), D3D_DRIVER_TYPE_UNKNOWN, ..)`. `is_warp` is false. The environment variable that selects the index is W8-12b's, not read here.
4. `clear_state_and_flush(device)`: `GetImmediateContext()`; on failure return silently (C# null check); else `ClearState()` then `Flush()`. `flush(device)`: `Flush()` only.
5. `device_removed_reason(device)`: `0` when `GetDeviceRemovedReason()` is `Ok`, else the error's HRESULT.

### Swap chain (`dxgi.rs`)
6. `window_swap_chain_desc(w, h)` (pure) returns exactly: `Width = w`, `Height = h`, `Format = DXGI_FORMAT_B8G8R8A8_UNORM`, `Stereo = false`, `SampleDesc = { Count: 1, Quality: 0 }`,
   `BufferUsage = DXGI_USAGE_RENDER_TARGET_OUTPUT`, `BufferCount = 2`, `Scaling = DXGI_SCALING_STRETCH`, `SwapEffect = DXGI_SWAP_EFFECT_FLIP_DISCARD`, `AlphaMode = DXGI_ALPHA_MODE_IGNORE`,
   `Flags = DXGI_SWAP_CHAIN_FLAG_FRAME_LATENCY_WAITABLE_OBJECT.0 as u32` (0x40). The caller guarantees `w, h >= 1` (`DeviceResources` ctor `Math.Max(1, ..)`): a zero size would make DXGI take the window
   size, a different behaviour.
7. `create_window_swap_chain(device, hwnd, w, h, max_frame_latency)`: reject a null `hwnd` with `Err(GfxError { E_INVALIDARG })` BEFORE touching the device (C# `CreateForWindow` throws for `hwnd == 0`).
   Then, in this order (C# lines 292-331): `dxgi_device(device)`, `GetAdapter()`, `adapter_info(&adapter)` (diagnostics, never fatal), `adapter.GetParent::<IDXGIFactory2>()` (the factory that
   owns the device's adapter, NOT a fresh `CreateDXGIFactory2`), `CreateSwapChainForHwnd(device, hwnd, &desc, None, None)`, drop adapter and factory, `cast::<IDXGISwapChain2>()`,
   `SetMaximumFrameLatency(max_frame_latency)`, `GetFrameLatencyWaitableObject()` wrapped in `Owned`. A null waitable handle after a successful `SetMaximumFrameLatency` is `Err(E_FAIL)` (C# stored 0
   and `FrameLatencyWaitHandle` was then 0; with the flag set the SDK promises a handle, so this is a defensive improvement, D-W8B3G-3 note). The caller passes a value from `clamp_frame_latency`.
8. `clamp_frame_latency(v)` is `v.clamp(1, 16) as u32` (C# `Math.Clamp(maxFrameLatency, 1, 16)`): negatives and 0 give 1, 17 and `i32::MAX` give 16.
9. `resize_buffers(sc, w, h)` is `ResizeBuffers(0, w, h, DXGI_FORMAT_UNKNOWN, SWAP_CHAIN_FLAGS)`; buffer count 0 and format UNKNOWN keep the current ones; the SAME flags as at creation are mandatory.
   Failure keeps the HRESULT in `GfxError` so `is_device_lost` works (C# `Resize` returned the HRESULT and `D2DRenderSurface.Resize` tested `DeviceLoss.IsDeviceLost(hr)`).
10. `present_raw(sc, sync_interval)` is `Present(sync_interval, DXGI_PRESENT(0))` and returns `hr.0`. `classify_present(hr)`: `hr == DXGI_STATUS_OCCLUDED` -> `Occluded` (tested FIRST); else
    `is_device_lost(hr)` -> `DeviceLost(hr)`; else `hr < 0` -> `Failed(hr)`; else `Presented` (so S_FALSE and other status codes are `Presented`). The mapping to `PresentResult` and the sync interval rule (0 when
    tearing or immediate-present, else 1) are W8-12d's.
11. `back_buffer(sc)` is `GetBuffer::<IDXGISurface>(0)`. In a flip-model swap chain index 0 is always the current back buffer.
12. `adapter_info(adapter)`: `GetDesc()`; `description` is the UTF-16 `Description` up to the first NUL, converted lossily; `vendor_id` is `VendorId`; a failing call is `None`. `display()` is
    `"{description} (vendor 0x{vendor_id:X4})"` (`0x0001` for vendor 1, `0x1414` for the WARP "Microsoft Basic Render Driver").

### R0001 facts that bind this unit (docs/adr/R0001-ui-framework.md, measured 2026-10-18, Core i7-9750H, Intel UHD 630 + RTX 2080 Max-Q)
13. The spike's `create_dxgi` is the proven call sequence: `D3D11CreateDevice(BGRA)` -> `cast::<IDXGIDevice>()` -> `GetAdapter()` -> `GetParent::<IDXGIFactory2>()` -> `CreateSwapChainForHwnd`, and

14. The open gate: windowed p95 shows 300 to 510 ms stalls INSIDE `ID2D1DeviceContext::EndDraw` (not in `Present`) in 9 to 29 % of frames; they vanish with WARP and without a swap chain, and appear on both

    description from the same module. An attended re-measure before W8-12d decides whether 12j runs.

## Safety rules (every `unsafe` block gets a `// SAFETY:` comment; `undocumented_unsafe_blocks` is on)
- Every windows-rs COM method used here is `unsafe fn`. The SAFETY text states: the receiver is a live owned interface passed by reference; out pointers are locals (`Option<ID3D11Device>`,
  `D3D_FEATURE_LEVEL`) that outlive the call; `HWND` is validated non-null and belongs to the calling thread's window (the caller guarantees it is a live window; a stale handle only makes
  `CreateSwapChainForHwnd` fail).
- Thread affinity: a device, its immediate context and swap chain are used only on the thread that owns them (the UI thread; the keep-warm thread for its own offscreen device). Calling
  `clear_state_and_flush`/`flush` from another thread while the owner draws is forbidden (the immediate context is not re-entrant for the caller's draw sequence). The compiler does NOT enforce this:
  windows 0.62 marks `ID3D11Device`, `IDXGISwapChain1`, `ID2D1Factory1` and `IDWriteFactory` as `Send`, so `CreatedDevice` is `Send`. `WindowSwapChain` is `!Send` only because `Owned<HANDLE>` is (raw pointer).
  The owning types of W8-12b/12c/12d must be `!Send` themselves (a `PhantomData<*const ()>` field), see D-W8B3G-9 rule on affinity.
- COM lifetimes: `create_window_swap_chain` holds the adapter and factory only inside the function; the returned struct owns the swap chain and the waitable handle. Dropping `WindowSwapChain` closes the
  handle and releases the swap chain; field order is `swap_chain`, then `frame_latency_waitable`, then `adapter` (info only). The CALLER must still run `clear_state_and_flush` BEFORE dropping a live swap chain
  (trap T1), because only the caller knows the Direct2D target is gone.
- `Owned::new(handle)` only on the non-null handle returned by `GetFrameLatencyWaitableObject`.
- `unsafe_op_in_unsafe_fn = deny`: all public functions of this unit are safe.

## Error mapping
- Every `Err` is a `GfxError` with `operation` from this list: `"D3D11CreateDevice(Hardware)"`, `"D3D11CreateDevice(WARP)"`, `"D3D11CreateDevice(adapter)"`, `"CreateDXGIFactory1"`, `"IDXGIFactory1::EnumAdapters1"`,
  `"QueryInterface IDXGIDevice"`, `"IDXGIDevice::GetAdapter"`, `"IDXGIObject::GetParent(IDXGIFactory2)"`, `"IDXGIFactory2::CreateSwapChainForHwnd"`, `"QueryInterface IDXGISwapChain2"`,
  `"IDXGISwapChain2::SetMaximumFrameLatency"`, `"IDXGISwapChain2::GetFrameLatencyWaitableObject"`, `"IDXGISwapChain::ResizeBuffers"`, `"IDXGISwapChain::GetBuffer"`, `"IDXGISwapChain2::GetMaximumFrameLatency"`,
  `"CreateDXGIFactory2"`.
- Device loss: `resize_buffers` and `present_raw`/`classify_present` expose the loss HRESULTs untouched (`D2DERR_RECREATE_TARGET`, `DXGI_ERROR_DEVICE_REMOVED`, `DXGI_ERROR_DEVICE_RESET`); the recreate flow
  (drop all, new generation, rebuild) is W8-12b/12c. `device_removed_reason` is the diagnostic: nonzero means the next call will fail.
- `present_raw` returns the number, never an `Err`: a failed `Present` is a normal frame result in the renderer.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (flip-model teardown and resize, measured in WP-13b and again on CI): before `ResizeBuffers`, the back buffer must have NO outstanding reference: `SetTarget(None)`, drop the target bitmap and every
  `IDXGISurface` obtained from `back_buffer`, THEN `clear_state_and_flush`, THEN `resize_buffers`. At teardown call `clear_state_and_flush` while the swap chain is STILL alive and release the swap chain after it
  (`DeviceResources.ReleaseAll` lines 420-433): releasing the swap chain first left the destruction and queued presents to the `Flush`, which hung forever on the CI runner (WARP + DWM) and in
  `ShellMainWindow` shutdown (comment at `ShellMainWindow.cs` line 359). A hang in this area is not a flaky test, it is this trap.
- T2 (`ResizeBuffers` flags): pass `SWAP_CHAIN_FLAGS` every time; passing 0 on a waitable swap chain fails with `DXGI_ERROR_INVALID_CALL`. The spike passed 0 only because it created the swap chain with flags 0.
- T3 (factory identity): get the factory from `adapter.GetParent()` of the device's own adapter; do not create a new factory (device and swap chain must share the adapter).
- T4 (`Present` is an HRESULT, not a `Result`): in windows-rs `IDXGISwapChain::Present` returns `HRESULT`; calling `.ok()` would turn `DXGI_STATUS_OCCLUDED` into success and lose it. Use `present_raw`.
- T5 (occluded first): `DXGI_STATUS_OCCLUDED` (0x087A0001) is positive; any `hr < 0` test must come after it, and `S_FALSE` is `Presented`.
- T6 (waitable handle): created only with the 0x40 flag; it must be closed (W8-11f T4); it is not a COM object. The latency is set BEFORE the handle is fetched (C# order).
- T7 (HRESULT literal signs): compare `i32` with `i32` (`0x887A0005u32 as i32`), never with an unsigned literal.
- T8 (zero size): never create or resize to 0; clamp with `max(1)` in the caller.
- T9 (`GetDeviceRemovedReason` is an Err in windows-rs): map back to the HRESULT; do not treat `Err` as "call failed".
- T10 (hardware failure is not an error): `create_device_with_fallback(false)` must not return the hardware error when WARP works (RDP, VM and CI have no GPU).
