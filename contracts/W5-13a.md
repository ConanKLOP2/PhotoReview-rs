- Semantics (exact):
  1. **Values.** `TjInit` 0..2, `TjParam` 0..22, `TjPixelFormat` 0..11 exactly as the C# enums (golden `enum-*`). `bytes_per_pixel`:
     Rgb/Bgr 3, Gray 1, the other nine 4 (libjpeg-turbo `tjPixelSize`).
  2. **`TjScalingFactor`.** Equality and hash need both fields, no normalisation (`1/8 != 2/16`, golden). `Display` = `"{num}/{denom}"`
     with Rust's default integer formatting (matches C# invariant `ToString` for every `int`, incl. `-2147483648`). `scaled(d)` =
     `(d as i64 * num as i64 + denom as i64 - 1) / denom as i64` (`/` truncates toward zero like C#; with the factors in use the
     operands are non-negative), `None` when `denom <= 0`. It must reproduce the `width`/`height` of every `output-buffer` golden row
     (rows with an `exception` carry `"{w}x{h}"` in the message: parse and compare those too).
  3. **Loading (C# `DefaultDllImportSearchPaths(AssemblyDirectory)`).** `default_library_path()` = `current_exe()?.parent()?.join(DLL_NAME)`;
     no environment variable, no cwd, no `PATH`. `load(path)`: non-absolute -> `InvalidArgument("TurboJPEG library path must be
     absolute: {path}")`; else `LoadLibraryExW(wide(path), NULL, LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_DEFAULT_DIRS)`.
     NULL -> `GetLastError` (`std::io::Error::last_os_error()`): 193 -> `BadImageFormat`, anything else (2, 3, 126, ...) -> `DllNotFound`;
     message `"Unable to load DLL 'turbojpeg.dll' or one of its dependencies: {io error text}"` (the .NET wording; free text, logged
     only through the W5-13b probe reason). Then `GetProcAddress` for `tj3Init`, `tj3Destroy`, `tj3DecompressHeader`, `tj3Get`,
     `tj3Set`, `tj3SetScalingFactor`, `tj3Decompress8`, `tj3GetErrorStr`, `tj3Compress8`, `tj3Free` (NUL-terminated ASCII names); a
     NULL result leaves that `Symbols` field `None` (no error at load). `#[cfg(not(windows))]`: always `DllNotFound` (the crate must
     still compile everywhere; CI is Windows).
  4. **Lazy per-export failure (C# P/Invoke binds each entry point on first call).** A `None` export makes only the call that needs it
     fail, with `EntryPointNotFound("Unable to find an entry point named '{name}' in DLL 'turbojpeg.dll'.")`. `error_message` treats a
     missing `tj3GetErrorStr` as `None`.
  5. **`shared()`.** `static SHARED: OnceLock<Result<Arc<_>, NativeError>>`, initialised with `load(default_library_path())`
     (`None` path -> `DllNotFound("Unable to load DLL 'turbojpeg.dll': the application folder is unknown.")`). Cached forever, success
     or failure; the `Arc` in the static is never dropped, so the shared module is never unloaded (DllImport parity). Concurrent first
     calls load once (`OnceLock::get_or_init`).
  6. **Handle lifetime (C# `SafeHandleZeroOrMinusOneIsInvalid`).** `is_invalid` = raw is 0 or -1. `close()`: if already closed ->
     `Ok(())` and nothing runs; else set `closed = true` FIRST, then if `owns && !is_invalid` call the seam or the bound library's
     `tj3Destroy(raw as *mut c_void)` exactly once and return the seam's result. `Binding::Shared` resolves `shared()` only at that
     point (a valid owned handle whose library cannot be loaded returns that `Err`, handle stays closed). `set_handle_as_invalid()`
     sets `closed = true` without releasing. `raw_value()` keeps the raw value after close (C# `DangerousGetHandle`, golden `raw_after`).
     `Drop`: `let _ = self.close();` (never panics, never double-destroys). Handles from `TurboJpegLibrary::create_*` hold an `Arc` of
     that library (`Binding::Library`), so the module outlives every handle.
  7. **Call guard order (every `tj3*` method).** (a) closed -> `Err(Disposed(HANDLE_CLOSED_MESSAGE))`; (b) invalid raw value ->
     `Err(InvalidArgument(HANDLE_INVALID_MESSAGE))` (DIVERGENCE, trap T6); (c) resolve the library (`Binding`); (d) the export
     (`EntryPointNotFound`); (e) method-specific checks; (f) the native call, its `c_int` return as `Ok(code)` unchanged. (a) and (b)
     run before (c), so the pure tests need no DLL. `error_message` returns `None` instead of each `Err`.
  8. **`decompress8` soundness guard.** libjpeg-turbo re-reads the header from `jpeg` and writes `scaled_h` rows of `pitch` bytes into
     `dst`; nothing on the Rust side can trust an earlier `decompress_header` (another slice, or the same memory mutated since). So,
     after 7(a..d): `pitch <= 0` -> `InvalidArgument`; call `tj3DecompressHeader(jpeg)` on THIS slice (non-zero -> return `Ok(code)`,
     native error string left in place); `w = scaled(tj3Get(JpegWidth))`, `h = scaled(tj3Get(JpegHeight))` with the remembered factor
     (`self.scaling`, `ONE` until a `set_scaling_factor` returned 0; libjpeg-turbo 3.0 keeps the factor across header calls); refuse
     when `w <= 0 || h <= 0`, `i64::from(pitch) < w * bytes_per_pixel` or `i64::try_from(dst.len()).unwrap_or(i64::MAX) <
     i64::from(pitch) * h` (`InvalidArgument`,
     message naming the required and actual sizes) BEFORE the native decode. The extra header parse is a few microseconds and invisible
     to callers (golden: every `pixels_sha256` must match through the guarded path). C#'s caller sizes its buffer from the same
     arithmetic, so the guard never fires in production.
  9. **Other calls.** `decompress_header(jpeg)`: `tj3DecompressHeader(raw, jpeg.as_ptr(), jpeg.len())`; an empty slice passes its
     (dangling, non-null) pointer with size 0, libjpeg-turbo rejects size 0 before reading (C# passes NULL from `fixed` on an empty
     array; same error text, golden `strict-wic-direct-empty`). `get`/`set`/`set_scaling_factor`: pass-through (`TjScalingFactor` BY
     VALUE, never by pointer). `error_message`: copy `CStr::from_ptr(p).to_string_lossy().into_owned()` immediately (the string is
     owned by libjpeg-turbo and overwritten by the next call). `compress8` (test support): guard `width, pitch, height > 0`,
     `pitch >= width * bpp`, `src.len() >= pitch * height`; `jpeg_buf = null_mut()`, `jpeg_size = 0`, call; on non-zero return
     `Err(InvalidOperation("tj3Compress8 failed: {error_message or 'no detail'}"))`; on success copy `jpeg_size` bytes from `jpeg_buf`;
     `tj3Free(jpeg_buf)` on every path where it is non-null (missing `tj3Free` -> leak, never `free()` from Rust's allocator).
  10. **What W5-14b will call (shape this API for it, do not port it here):** `create_decompressor()?`, `set(ScanLimit, 500)` ignoring
      the code, `set(StopOnWarning, 1)` (non-zero -> its own error with `error_message()`), `decompress_header(&bytes)?`,
      `get(JpegWidth)?`/`get(JpegHeight)?`, `set_scaling_factor(f)?` (non-zero -> `ONE`), `decompress8(&bytes, pixels.bytes_mut()?,
      pixels.stride(), TjPixelFormat::Bgrx)?`, `error_message()` on each failure, then the handle drops. One fresh handle per decode and
      per `TryReadDimensions` (a failed parse leaves a handle unusable for another buffer; C# comment).
  11. **`unsafe`.** Only in this file; one `// SAFETY:` per block naming the invariant (pointer from a live slice for the whole call,
      length from the same slice, handle non-null and not destroyed, export signature matches `turbojpeg.h` 3.0, string copied before
      the next call). The `fn` pointer types are `unsafe extern "C"` (x64: cdecl = the C ABI). No callback crosses the boundary, so no
      unwinding can enter C. `transmute` of a `GetProcAddress` result into the `Option<fn>` type is the one pattern allowed for symbols
      (`std::mem::transmute::<*mut c_void, Tj3Init>` after a NULL check; SAFETY names the header signature).
- Traps checklist: §7 items 3 (`i64` arithmetic in `scaled` and the guard; `usize` -> `i64` conversions with `try_from`, never `as`
  truncation on a length), 8 (`None` vs empty: `error_message` NULL vs `""`), 9 (each C# exception type is its own `NativeError`
  variant, never merged: INV-12 depends on it). Unit-specific:
  - T1 **DLL search hijack:** never call `LoadLibraryW`/`LoadLibraryExW` with a bare name or flags 0; the absolute path + the two
    `LOAD_LIBRARY_SEARCH_*` flags is the C# AssemblyDirectory guarantee. A test asserts a relative path is refused.
  - T2 **Struct by value:** `tj3SetScalingFactor` takes `tjscalingfactor` by value (8 bytes, one register on x64). Declaring it as a
    pointer compiles and corrupts silently; the golden `scale-*` rows catch it.
  - T3 **`size_t`:** `jpegSize` is `usize`, `pitch`/`pixelFormat` are `c_int`. `c_ulong` is 32-bit on Windows: wrong.
  - T4 **Lazy binding:** resolving all exports eagerly and failing `load` on a missing one would make W5-13b report "Could not load"
    where C# reports "loaded but failed to initialize" (and a missing `tj3Compress8` must never disable decoding).
  - T5 **Double destroy / use after destroy:** `closed` is set before the destroy call, so a panicking or failing seam cannot cause a
    second destroy; `Drop` after `close` is a no-op. All calls check `closed` first.
  - T6 **Invalid raw values (DIVERGENCE, record `// DIVERGENCE:` in the test):** C# would marshal 0/-1 into the native call (libjpeg-turbo
    answers NULL with "Invalid handle"; -1 would crash). Rust refuses both before the library is touched. Unreachable from production
    (C# never builds such a handle outside tests).
  - T7 **Rust-only guards are not behaviour changes:** `InvalidArgument` from `decompress8`/`compress8`/`load` maps to
    `DecodeError::InvalidArgument` (C# `ArgumentException`, not fallbackable); the C#-shaped call sequence never triggers them.
  - T8 **Error string lifetime:** `tj3GetErrorStr` returns a pointer into the instance (or a thread-local for NULL); copy before any
    other call on the handle.
  - T9 **Thread safety:** a `tjhandle` must not be used concurrently. `&mut self` on every call; the type is `Send`, not `Sync`. Do not
    add `unsafe impl Sync`. `TurboJpegLibrary` is `Send + Sync` automatically (only `usize`, `PathBuf` and `fn` pointers): no
    `unsafe impl` needed; if a field change breaks that, fix the field, not the impl.
  - T10 **Golden pixel hashes depend on the DLL build:** compare `pixels_sha256` only when the loaded DLL's SHA-256 equals the row's
    `turbojpeg_dll_sha256` (pinned `E9BDEC69...583D`); otherwise compare everything except the hash and print one line (D39 pattern).
  - T11 **Tables-only stream in the guard:** libjpeg-turbo 3.0 `tj3DecompressHeader` returns 0 for a tables-only (abbreviated)
    datastream WITHOUT updating `jpegWidth`/`jpegHeight`, so the guard's `tj3Get` sees -1 (fresh handle) or the previous image's size.
    -1 -> refused by `w <= 0` (`InvalidArgument`, where the native decode would have failed with its own text); a stale size is
    harmless because `tj3Decompress8` re-reads the header with `require_image = TRUE` and errors before writing. Unreachable from
    the C# sequence (its own header call already yields -1 dims and W5-14b throws "Invalid image dimensions"). Do not "fix" it by
    caching the first header's dimensions: that would reopen the different-slice hole of Semantics 8.
  - T12 **Hash in the golden:** C# `GetHashCode` (`HashCode.Combine`) is seeded per process; only `hash_equal == true` for equal
    factors is meaningful. The Rust golden test checks `DefaultHasher` equality only on rows with `equals == true` and ignores
    `hash_equal` on unequal rows.
  - INV ids: INV-12 (exception type -> fallback classification), INV-8 does NOT apply (no file handle here; W5-14b reads the file).

## Open questions
1. **Run-time loading mechanism.** Recommended (used by the stub): hand-declared `kernel32` `LoadLibraryExW`/`GetProcAddress`/
   `FreeLibrary` in a private `#[cfg(windows)] mod win32` inside `pr-turbojpeg` (no new crate, ~10 lines, same pattern W5-15a/LibRaw
   can copy). Alternatives: (b) the `libloading` crate (lead adds to the workspace; its `Library::load_with_flags` exposes the same
   flags; one more dependency to audit); (c) the `windows` crate with `Win32_System_LibraryLoader` (D36 keeps `windows` in
   `pr-platform-win`; would widen it to a decoder crate). Static/import-library linking is rejected: the app must start and fall back
   to WIC when the DLL is missing (AR01).
2. **Fetching the DLL for Rust tests and the app.** Recommended: the lead syncs `native/turbojpeg.sha256` and a Rust-side
   `tools/fetch-native.ps1` (same nuget package `libjpeg-turbo-native-windows/3.0.0`, same pin, writes `native/x64/turbojpeg.dll`),
   CI runs it before `--include-ignored`; packaging (Wave 8) copies the DLL next to `PhotoReviewRs.exe`. Not decided here: whether a
   `build.rs` should copy it next to test binaries (rejected in this draft: writing outside `OUT_DIR` from a build script).
3. **Cached failure in `shared()`.** C# re-attempts the P/Invoke load on every call when the DLL is missing (only the probe result is
   cached). Caching the failure is invisible because W5-14b is registered only after a successful probe; if the lead prefers exact
   retry semantics, `shared()` caches success only (one `Mutex<Option<Arc<_>>>`), no API change.
4. **`compress8` in production code.** It is test support for W5-14b's `TurboJpegSyntheticFormatTests` (C# declares its own
   `[DllImport]`s in the test). Keeping it in `native.rs` avoids a second FFI site in a test file (AGENTS.md: unsafe only in the
   decoder crates). Alternative: move it behind a `test-support` cargo feature. CONFLICT to resolve at wiring: W5-14b open
   question 5 recommends NO `tj3Compress8` binding in Rust (an oracle command writes the synthetic JPEGs instead) and parks its two
   synthetic tests as `#[ignore = "blocked: W5-14b OQ5"]`. If the lead takes W5-14b's route, `compress8`/`create_compressor`/
   `COMPRESSOR_INIT_FAILED_MESSAGE` and the `compress8`/`free` symbols are dropped here together with the
   `compress8_round_trips_through_decompress8` test (the decode golden already covers `decompress8`); no other API changes.
5. **Small-destination contract with W5-14b.** W5-14b's `NativeDecompressors` adapter (its Semantics 13) expects to return `-1`
   when `dst` is too small; this unit returns `Err(InvalidArgument)` from `decompress8` instead. The adapter must not add a second
   check: it maps `Err(InvalidArgument)` to its own failure path (or the lead aligns W5-14b's text to "propagate the `Err`").
   Either way the C# call sequence never triggers it (T7).
