## Semantics (C# line numbers at d92d6aae)
1. **Construction** (l. 91-145). `worker_count = parse_diag_workers(env(PRELOAD_WORKERS_VAR)) ?? options.worker_count`: the variable
   WINS over the option and over the convenience override (the convenience constructor computes `override ?? env ?? 8`, then the main
   constructor reads the variable again). Slots `max(1, worker_count)` (never touched when 0). The first lifetime exists and is tracked
   from the start (`tracked_lifetime_counts() == (1, 0)`). `viewer_busy_worker_limit(cpus)` once. Nothing is started.
2. **Gate.** One `Mutex<GateState>` = C# `_preloadCtsGate` (C# `lock` is REENTRANT, Rust's mutex is not: never call a hook, the target,
   the probe, the log, the timer factory's callback or a snapshot callback that could re-enter the scheduler while holding it; the two
   allowed calls under the gate are `snapshot_entries()` (C# does it, l. 319; the callback must not call the scheduler) and
   `timers.create_timer` (must not call back synchronously)). Poison is recovered with `PoisonError::into_inner`. Warmed keys have their
   own mutex (C# `_preloadedKeysGate`); the two are never nested.
3. **`preload_around` / `PreloadAroundCore`** (l. 244-324), in order: 0 workers => completed handle (no pace, no version, no lifetime);
   real kick => `pace.record(center)`; `snapshot_version()` OUTSIDE the gate (`None` callback = 0). Then under the gate: disposed =>
   completed; a resume kick whose generation is stale or whose lifetime is cancelled => completed; retire the re-check (`reset_checks` only
   for a real kick); count `resumes_for_tests` for a resume kick; RV-I13: a different snapshot version while the newest run of the CURRENT
   lifetime is still running => cancel that lifetime (and its waiting jobs) and wake; a cancelled current lifetime => prune finished
   lifetimes, create and track a new one; `preload_center = center`; `priority_version += 1`; JOIN when the newest run is unfinished,
   belongs to the current lifetime and is not exiting => wake, return a clone of its handle (`same_run`); else start a run: drop finished
   lifetime runs, `run_id += 1`, `run_exiting = false`, remember the snapshot version, take `snapshot_entries()?`, create the handle,
   track `(lifetime, handle)`, release the gate and run the prefix (semantics 5). Any `Err` from a callback (and a panic in the kick) =>
   Error `MSG_KICK_FAILED` with the error, completed handle; state already changed under the gate stays changed (as in C#).
4. **Run loop** (l. 475-688), with `queue: RunQueue` (W4-15a):
   ```
   while !lifetime.is_canceled():
       seen_wake = events.wake_seq()                       # BEFORE the version read (a later navigation must wake the wait)
       version = priority_version; shape = current_shape(); center = preload_center   # in this order (PassInputs doc)
       queue.refresh(ctx, PassInputs { version, center, shape })?
       limit = policy::worker_limit(workers, target.active_viewer_decodes(), metrics.decode_milliseconds_ewma(), viewer_busy_limit)
       while running.len() < limit:
           match queue.next(ctx, on_caller, &lifetime.token)?:
               Exhausted | FillLimitStop | Paused => break
               Canceled => goto drain
               LeaveCallerThread => hand off (semantics 5), continue
               Skipped => continue
               Dispatch(c) => dispatch (semantics 6); if c.batch_yield: progress line if log.enabled(); hand off / yield_now; cancel check
       if !paused && running.is_empty() && queue.calibration_changed(sizes): continue
       if paused || running.is_empty():
           if !try_exit_run(run_id, queue.seen_version(), paused, token): continue
           before_scheduler_exit hook; break
       match events.wait(run_id, seen_wake): Woken => continue; Finished(f) => remove f; apply f (semantics 6)
   drain: wait until every running worker reported (ignore wakes)
   ```
   `try_exit_run` (l. 350-366) under the gate: not paused, not cancelled and the live version differs from `seen_version` => `false`
   (take another pass: RV-I12). Otherwise, when `run_id` is still the newest run: `run_exiting = true` and, if paused, not cancelled and not
   disposed, arm the re-check (semantics 8); return `true`. Errors: a `QueueError`, a `WorkerEnd::Faulted`, a panic inside the loop
   (catch_unwind around each step, R0003) => `mark_run_exiting(run_id)`, Error `MSG_SCHEDULER_FAILED` with the error, drain, complete. A
   cancelled lifetime ends silently after the drain. The handle completes only after the drain (IsIdle/Dispose never see a run finished
   while one of its workers still holds a slot). The run's `RunEvents` queue is removed at the end.
5. **Caller-thread prefix (Q-R26, ADR 0005).** `preload_around` runs the loop on the CALLING thread (the UI thread in the app: only cache
   lookups and dispatches, never a decode) until the first hand-off point, then moves the run (queue + running set) to a new named thread
   `pr-preload-run` and returns. Hand-off points: H1 `QueueStep::LeaveCallerThread` (first candidate outside the window); H2 a dispatch
   with `batch_yield` (C# `Task.Delay(1)`; on the run thread H2 is only a cancellation check + `thread::yield_now()`, never a sleep);
   H3 the loop must wait for a worker or a wake; H4 a drain with workers still running. A run that ends before any hand-off completes on
   the caller (the returned handle is already complete, like C#'s synchronously completed task). Divergence accepted (no test sees it):
   C# continues on the caller when a worker already finished before its `WhenAny`; Rust always hands off at H3.
6. **Dispatch and the worker** (`PreloadOneAsync`, l. 775-890). Rules W1-W8:
   - W1: at most `max(1, worker_count)` items hold a slot at once, shared by EVERY lifetime of this scheduler (a draining old run and a new
     run share them).
   - W2: slot waiters are served FIFO.
   - W3: when a lifetime is cancelled (`cancel`, `dispose`, RV-I13 retire) its waiting items end `Canceled` at once, without a slot.
   - W4: if a slot is free at dispatch (and nobody waits), the two short-circuit checks run INLINE on the dispatching thread: `target.
     try_get_cached_preview(key)` => `Cached` (perf `skipped`); `!is_still_wanted(index, center, current_shape())` => `Superseded` (perf
     `superseded`); the slot is released and `queue.on_finished` is applied at once with no running entry (C# `IsCompletedSuccessfully`).
     Otherwise the item (holding or waiting for a slot) goes to a pool thread, which runs the same two checks when it gets the slot.
   - W5: prefetch and `target.preload` run on a pool thread (`pr-preload-<n>`), never on the dispatching thread. The `dispatched_on` seam
     is called with the path on the dispatching thread.
   - W6: no lock is held while calling the target, the probe, the log, the prefetch or a hook.
   - W7: every item reports exactly once (drop guard + `catch_unwind`), so a run can never hang on a lost report.
   - W8: the perf navigation context (`PhotoReviewPerf::set_nav_context(-1)`, thread-local) is set on the pool thread for the item and
     restored after; the queue wait for perf is measured from dispatch.
   Item body after the checks: `raw = is_raw_path(path)`; if `!raw && prefetch.is_some() && !target.has_disk_cached_preview(&key)` =>
   `prefetch(path, token)`; `target.preload(path, token)`; `fresh = target.get_current_cache_key_for_path(path)` (INV-1: the identity the
   decode stored, may differ from `key`); `hit = target.try_get_cached_preview(&fresh)`; on hit: warmed keys - when `fresh.target_box()`
   differs from the stored box, clear the set and store the new box (RV-I15), then insert `fresh`; `cached_preview_bytes(&fresh)` =>
   `sizes.record(fresh.target_box(), bytes)`; `busy_backoff.record_success(path)`; outcome `Cached`, else `Failed`. Perf item kind:
   `decoded` when `metrics.snapshot().source_reads` grew, else `hit`/`miss` (snapshot only when tracing). Error arms, one per C# catch, in
   C# order: `Busy` => `busy_backoff.note_busy(path, &key) == 1` ? Info `format_deferred_busy` : debugger-only line (not the log); then
   the `busy_noted` hook; outcome `Busy`. `DecodeError::is_io_exception()` (incl. `Io`, `FileNotFound`, `DirectoryNotFound`,
   `MemoryAdmission`; `PermissionDenied` is C# UnauthorizedAccess, same text) => Error `format_preload_failed` with the error.
   `Canceled` while the lifetime token is NOT cancelled (RV-I14) => Warn `format_foreign_cancel(path, err.to_string())`, `Failed`;
   `Canceled` while it IS cancelled => the item ends `Canceled` (the run drains). `MissingCodec` => `Failed`, no log. Anything else
   (incl. a `KeyError` from the fresh key and a panic inside prefetch/preload/fresh key) => Error `format_preload_failed`, `Failed`. A
   panic in the two short-circuit checks => `WorkerEnd::Faulted` (C# a faulted task: the run fails).
7. **Applying a report**: `Done(outcome)` => `queue.on_finished(path, outcome)`; `Canceled` => end of the loop (cancelled lifetime) then
   drain; `Faulted` => semantics 4 error path.
8. **Memory re-check** (l. 368-473). Arm (under the gate, only from `try_exit_run` of the newest, paused, live run, or from a `NotYet`):
   drop the old timer; budget spent (`resume_checks >= 8`) => nothing; else `delay = resume_check_delay(resume_checks)`, `resume_checks
   += 1`, `generation = ++resume_generation`, `timers.create_timer(delay, callback(generation))` where the callback holds a `Weak` of
   the shared state. Retire (`cancel_resume_check_locked`): `resume_generation += 1`, drop the timer, reset the budget only when asked
   (every real kick, navigation, `cancel`, `dispose`; NOT a resume kick). Callback (`on_resume_check`, never panics out: everything is
   caught and logged as Error `MSG_RECHECK_FAILED`): under the gate, disposed or stale generation => return; drop the timer. Outside the
   gate: `evaluate_resume` (W4-15a). `Resume` => Info `format_resumed_log(center)` (when enabled), `preload_around_core(center,
   Some(generation))` and store its handle in `resumed_run_for_tests` (a completed handle when superseded). `CacheFull` => Info
   `format_stays_paused_log(cache_bytes)`, nothing armed. `NotYet` => under the gate, if still current and not disposed, arm again. The `CacheFull` line re-reads
   `target.cache_bytes()` (C# reads `CacheBytes` a second time for the text). An `Err` from `preload_around_core` (snapshot callback)
   or a panic anywhere in the callback is logged as Error `MSG_RECHECK_FAILED` with the error, NOT `MSG_KICK_FAILED` (C# calls
   `PreloadAroundCore` directly, outside `PreloadAroundAsync`'s catch).
9. **`dispose`** (l. 913-958): idempotent. Under the gate: `disposed = true`, cancel the current lifetime, retire the re-check (reset),
   copy the tracked lifetime runs. Then wake, cancel waiting items of every tracked lifetime (W3), wait for all copied runs up to the
   drain timeout (default 3 s, `set_dispose_drain_timeout`). In time: stop and join the pool. Timed out: Warn `MSG_DRAIN_TIMEOUT`, start a
   `pr-preload-late-dispose` thread that waits for the copied runs and then stops the pool, expose its completion as
   `late_disposal_for_tests`, return at once. After `dispose`, `preload_around` / `notify_navigation` / `cancel` are no-ops
   (`preload_around` returns a completed handle; `notify_navigation` still records the pace first, as C# does before its gate
   check). The warmed-key methods (`try_consume_preloaded_key`, `remove_preloaded_keys_for_path`, `clear_preloaded_keys`),
   `is_idle`, `worker_count` and `get_viewer_decode_delay` have NO disposed check in C# and keep working (golden case
   `dispose-then-everything-is-a-no-op` consumes a key after dispose). `Drop` calls `dispose`. Never called from a pool or run thread by the scheduler itself.
10. **Wake-ups** (C# `_wake`): `notify_navigation`, every kick that joins, `cancel`, `dispose` and the RV-I13 retire bump
    `events.wake()`; a run that waits on workers wakes to re-prioritize (`Navigation_WakesWaitingScheduler`). A worker report is preferred
    over a pending wake (C# `WhenAny` lists the workers first).
11. **`notify_navigation`** (l. 208-222): 0 workers => nothing (not even the pace). `pace.record(index)`; under the gate, not disposed:
    centre, version + 1, retire the re-check (reset); wake; `if current_shape().lead > 0 { preload_around(index) }` (handle dropped).
    `get_viewer_decode_delay`: 0 workers => zero, else `pace.get_viewer_start_delay(metrics.decode_milliseconds_ewma())`.
12. **`cancel`** (l. 157-168): under the gate, not disposed: cancel the current lifetime, retire the re-check (reset); then wake, W3 for
    that lifetime, perf `preload_cancel("cancel")` when tracing. `clear_preloaded_keys` also clears the busy back-off.
    `remove_preloaded_keys_for_path` compares ORDINALLY with `key.path()` (already upper-invariant). `try_consume_preloaded_key` removes.
13. **Lifetime bookkeeping** (`prune_finished_lifetimes`, l. 329-341): drop completed runs; drop every lifetime that is not current and has
    no unfinished run. `ManyNavigations_KeepTrackingBounded` and `Lifetimes_AreBoundedIncludingTheFirst` pin it.

## Traps checklist
§7 items 3 (`priority_version` is an `i64` with wrapping increments, D3), 8 (`Option` callbacks: `None` snapshot version = 0), 9 (one
arm per C# catch; `is_io_exception` vs `PermissionDenied` vs `Canceled`-with/without-own-cancel), 10 (warmed keys are a set; nothing
ordered leaks). Specific:
- **INV-1**: warmed keys hold the FRESH key re-read after the decode, never the candidate key; a box change drops the whole set (RV-I15).
- **INV-2**: `clear_preloaded_keys` must be callable while runs are in flight; a worker finishing after the clear may add its fresh key
  again (C# does the same; the set only feeds the preload-hit metric).
- **Reentrancy**: C# `lock` is reentrant and the C# prefix runs UNDER the gate; Rust releases the gate before the prefix. Every hook
  (`before_scheduler_exit`, `busy_noted`, `dispatched_on`) may call back into the scheduler (`NavigationDuringSchedulerExit_IsPreloaded`
  calls `preload_around` from the exit hook): no lock may be held when they run.
- **No sleeps**: production waits are condition variables (events, pool, timers, handles). Tests use gates and `wait_timeout(10 s)` as
  hang guards only (AGENTS.md).
- **Panics are the C# "fake throws"**: tests that make the probe or the target throw in C# panic in Rust; the scheduler catches them at
  the C# catch sites only (kick, loop, item body, timer callback) with `catch_unwind(AssertUnwindSafe(..))`; a panic message becomes the
  logged error (`Box<dyn Error>` wrapper).
- **Threads are named** (`pr-preload-run`, `pr-preload-<n>`, `pr-preload-recheck`, `pr-preload-late-dispose`) and none outlives
  `dispose` except as described in semantics 9. A disposed scheduler must not resurrect a lifetime, a run or a timer.
- The timer callback and run threads hold the shared state; dropping the last `PreloadScheduler` disposes first, so no thread keeps the
  target alive forever (timer callbacks hold a `Weak`).

## Open questions
1. **Thread model.** Recommended and assumed by the stub: caller-thread prefix + one `pr-preload-run` thread per run + a fixed pool of
   `max(1, workers)` threads (semantics 5/6). It keeps the Q-R26 tests (window lookups on the caller, decodes started before the caller
   moves on) and bounds threads. Alternative: run the whole loop on the run thread (simpler; `preload_around` returns before ANY
   candidate is queued, the caller-thread tests become `Different` and first-preload latency grows by one thread start). Lead decides
   before the porter starts.
2. **Timer seam location.** `OneShotTimerFactory` lives in `pr_imaging::preload::timer`. If W4-14 (or later units) needs a one-shot
   timer too, hoist it to `pr_core::time` (lead-owned move, no behaviour change).
3. **`RunHandle` vs `pr_core::session::writer::Completion`.** Same primitive (flag + condvar) minus `same_run`. Recommended: lead hoists
   `Completion` to `pr_core::sync`, adds `ptr_eq`, and `RunHandle` becomes a newtype over it. Not blocking.
4. **`MSG_FAILED_DURING_DISPOSAL`** has no reachable Rust path (a run thread never "faults": its panics are caught and logged as
   `MSG_SCHEDULER_FAILED`). Recommended: keep the constant for parity, no code path; note it in PARITY I-11.
5. **Snapshot callback under the gate** (semantics 2/3). C# calls `_snapshotEntries()` under its reentrant lock; Rust keeps the call
   under the gate (so a joining kick never pays for a snapshot copy) and documents that the callback must not call the scheduler.
   Alternative: take the snapshot before the gate on every kick (one O(n) copy per navigation). Recommended: as stubbed.
