- Semantics notes (line numbers are `ImagePresenter.cs`, `CVM` = `CompareViewModel.cs`):
  1. **Branch decision (514 to 526).** `pair = get_compare_pair(path, request.include_capture_group_in_compare || compare.is_visible())`. While compare is open EVERY presentation compares the capture pair (Next / Previous / undo), otherwise navigation would drop the pair yet leave compare visible. Compare runs only
     when `pair.is_some() && request.allow_compare`; otherwise the single-image branch (`allow_compare == false` with a pair clears the compare view model).
  2. **Compare branch (528 to 567 + CVM 166 to 255).** In this order: `current_photo_info = None`, `update_current_image(None, 0, 0, None)`; token check (a stale token ends the present); `compare.set_left_path`, `set_right_path`, `select(Some(path))` (the PRESENTED path, `initialSelectedPath: path`, so the right
     member can be selected when it is the override), `set_visible(true)`, `set_left_image(None)`, `set_right_image(None)`; BOTH previews requested before either is awaited (two jobs); when both are in: the LEFT error wins if both failed; success: token check (stale: the present ends), `set_left_image`, `set_right_image`;
     sizes (only when `settings.compare_size_enabled`; ONE job stats both files through `compare_file_size`; the injected-size overload is not used by the presenter) then token check, `status::compare_size_suffix(bytes)` for each `Some`; `set_left_size_text`, `set_right_size_text`; hashes: `hash_text = status::compare_hash_text(None)`; when
     `settings.compare_hash_enabled` and exactly one member is RAW (`is_raw_path`) -> `compare_hash_text(Some(false))` without reading any file; when enabled and both or neither are RAW -> two hash jobs, then token check, then `compare_hash_unknown` if either failed (non-cancellation) else
     `compare_hash_text(Some(eq_ignore_case(l, r)))`; `set_hash_text`; `set_status_text(status::compare(&CompareStatus { index, count, left_name, left_size, right_name, right_size, hash_text }))` with ZERO-based `index` (the formatter prints it 1-based) and `count = catalog.count()`; then `update_status(compare.status_text(), false)`; step 7.
  3. **Compare errors (545 to 560).** A preview error that is NOT a cancellation, while the navigation is current: the compare view model is cleared, the CURRENT image is shown alone with its photo info, `apply_initial_view_mode()` (+ zoom sync), the zoom target is armed (`on_preview_presented`, so zooming after a failed compare works), and the status names the PARTNER
     (`partner = if eq_ignore_case(pair.left, path) { pair.right } else { pair.left }`) with attention. The catalog is NOT touched (the current image is fine) and the stale-file path below is NOT taken. The present ends WITHOUT step 7 (no session save, no `record_presented`). A cancellation, or any error while not current, goes to `fail`.
  4. **Single-image branch (568 to 625).** `compare.clear(ctx)`; `apply_initial_view_mode()` then the zoom sync; `zoom_detail.on_preview_presented(token, path, current_key, image)` (apply its effects); with a UI scheduler: `post` a `FrameYielded { PostFrame }` and wait (the frame containing the new image renders before the bookkeeping), then token check;
     without a scheduler continue at once. Original dimensions: in Original loading mode `(image.pixel_width(), image.pixel_height())` and no lookup; otherwise a KNOWN value (`try_get_known_original_dimensions`) is used on the spot (no worker hop), else `try_get_original_dimensions` runs on a worker;
     an expected failure is `None` (status without dimensions), an unexpected one goes to `fail`. Token check. The refresh stat (`submit_stat(.., Refresh, none-cancel)`): `!Found` -> RV-A04 status (dimensions of the initial size), catalog untouched, NOT attention; `Found` -> catalog metadata updated only for non-override presents when the entry's length or mtime differs from the NEW stat (the compare is
     with the `initial_entry` metadata taken after the R7-1 refresh), status with the NEW length.
  5. **Step 7 (627 to 645).** Token check; session update only when BOTH a live session (`env.session`) and a session store exist: `current_path = Some(path)`, `updated_utc = utc now`, then the writer's `update` (debounced; flushed on folder change and shutdown by other units) if a writer exists, else the store's `save`. Then `metrics.record_presented(ms)`. The navigation record is dropped.
  6. **Catch clauses (646 to 711), in order.** (1) cancellation while NOT current: log, nothing else. (2) current and not-found (`FileNotFound` / `DirectoryNotFound`): the file system decides, not the (possibly stale, joined) failure: a recheck stat on the stat worker; found and `retries >= 3`: error status with attention, entry KEPT; found: re-present the same entry with `retries + 1` and the ORIGINAL
     previous navigation path; not found or unreadable (`Missing` or `Error`): `remove_missing_catalog_item`. (3) current, anything else: generic failure with the `previousNavigationPath` / `sameEntryAsShown` logic. (4) not current: log only.
  7. **Expected dimension failures** are exactly the list of `photo_info::is_expected_dimension_failure`; the status for them is `ready(..)` (no `WxH`) and `StatusNeedsAttention` is false.
- Traps checklist (MULTI-AGENT-PLAN section 7 items 1, 3, 4, 8, 10 apply; specific items below):
  - **T1 INV-1 after every wait.** Token check after: the frame yield, the dimensions, the refresh stat, both compare previews, the sizes, the hashes, the recheck stat. After a stale check the continuation returns WITHOUT sink calls, status, catalog or session writes (test `TokenSuperseded_*`, `SupersededWhileStatPending_*`).
  - **T2 concurrency of the two previews.** Both compare previews are requested BEFORE either result is looked at; a second request after the first finished would serialize two decodes (the C# comment says: load both images in parallel).
  - **T3 JPEG+RAW never hashes.** Exactly-one-RAW skips both hashes (`hash_text = different`) so a 40 MB RAW is not read for nothing; both-RAW or no-RAW hashes both.
  - **T4 cancellation is not "unknown".** `FileHashError::Canceled` is a `PresentFailure::HashCanceled`, only other hash errors become "unknown" (logged `Compare hash failed path=..`).
  - **T5 compare partner failure keeps the catalog.** Do NOT call `remove_missing_catalog_item` on this path, and do NOT run step 7.
  - **T6 stale-NotFound bound.** `MaxStaleNotFoundRetries = 3`: the decoder in `MutationGaps` is called exactly 4 times (first + 3 retries). `Missing` or `Error` of the recheck both go to `remove_missing_catalog_item` (C# only tests `== Found`).
  - **T7 `previousNavigationPath` restore.** In the generic failure, `current_navigation_path` is restored to the previous path only when that path is NOT equal to `path` (ordinal ignore case) AND the failed entry is the same entry as the one on screen; then the image is NOT cleared. A failed DIFFERENT entry clears image and compare (Delete / Move must not act on an unseen file).
  - **T8 session save mutates the live `SessionState`** (`current_path`, `updated_utc`) before the writer / store call; the writer copies it (`update` records a COPY), the store serializes it.
  - **T9 status flags.** `StatusNeedsAttention`: true for loading, errors; false for ready / with-dimensions / compare. The RV-A04 status is not attention.
  - **T10 culture.** `CompareSizeSuffix` uses the N0 group separator of the display culture; hash comparison is ordinal ignore case; all text through `status::*` (D-W8-4).
  - **T11 no catalog access from workers.** The compare jobs and the dimension job get strings and `Arc` services only; `ReviewCatalog` stays on the UI thread.
  - **T12 `fail` must put no event handler in a bad state.** After any `fail` the navigation is either ended (`None`) or in `AwaitRecheckStat`; never left in a phase whose event will not come.

## Open questions (each has a recommended default; the stub follows it)
- **O1 Who orchestrates the compare load.** C# `CompareViewModel.LoadAsync` runs the four steps with injected async callbacks. Default (used): the presenter drives the steps (stages `Previews`, `Sizes`, `Hashes`) and calls only the view model's SETTERS, because an `async fn` / future callback API (the 06c draft) is forbidden by D-W8-2 and the
  presenter must interleave the token checks. Alternative: W8-06c exposes pure step functions (`plan_hash(pair, enabled) -> HashPlan`, `size_suffixes(..)`, `format_status(..)`) and 07j calls them; the stage machine stays. If 06c ships `load_async`, it is dead code for the presenter (keep it only if 06c's own tests need it). The 06c reviewer and the lead must reconcile; the observable order above is the contract.
- **O2 `compare_file_size` duplicates `CompareViewModel.TryGetFileSize`.** Default: the copy in `compare_pair.rs` (it needs `AppLog` and `PhysicalFileSystem`, both already available). Delete one when 06c lands.
- **O3 `get_current_cache_key_for_entry` failure.** See W8-07h O3. The stub routes it to `fail` with `PresentFailure::CacheKey`.
- **O4 Left error wins.** C# `Task.WhenAll` rethrows the first exception of the task list. Default: left before right. The test `ComparePartnerBusyTwiceInARow` has only one failing side, so either order passes; keep the documented order.
- **O5 Log text.** The `ShowImage ...` / `Compare ...` log lines are English diagnostics, ported verbatim (the APP-P01 test greps `ShowImage failed` and `ObjectDisposedException`).
