- Semantics notes (each from the C# read at the baseline):
  1. **Start guards.** A run in progress ignores `run_selected` and `quick_check` (checked first, also for an empty selection). An empty selection reports `benchmark.status.noProfileSelected` and never
     goes busy. Quick check ignores the selection: `fast-sequential`, 10 iterations, the profile's own warm-up count.
  2. **Run start.** In this order: image limit parsed ONCE; `run_id` incremented; running; token created (before the scan, so Cancel/Close can interrupt a slow scan); `set_running(true)`; rows
     cleared; `set_progress(0)`.
  3. **Scan.** Worker. `DirectoryNotFound` before `Io` (status `folderMissing` vs `cannotReadFolder`); empty list => `noImages`; unexpected error => `bench.status.failed` with `bench.error.unexpected`.
     RAW files are never listed. The token is polled every 256 files and once after the loop.
  4. **Profiles.** For each profile in order: the factory runs on the UI thread OUTSIDE per-profile handling (its failure ends the run as failed and leaves the rows untouched); the session runs
     on a worker with the run's CAPTURED token; the session is disposed on every path; a returned report is kept even when Cancel was requested meanwhile (only a cancellation error counts as
     cancelled); another error is a Fail row + `profileFailed` status + the next profile. The factory is called for the next profile even after `close()`; the session then ends through the cancel path.
  5. **Saving.** Only when at least one report exists: `done` status with `completed = reports`, `total = profiles`, the summary path. All profiles failed: nothing saved, `last_report` stays, the last
     failure status remains.
  6. **Finalization** always: not running, `set_running(false)`, `close()`. Order of view calls in a normal two-profile run: `[true, false]` for `set_running`.
  7. **Progress.** Applied only while running and for the live `run_id`; a stale or late message (after cancel, from an earlier run) changes neither the bar nor the status. `total == 0` => 0.0. The
     status shows the profile index/count of THIS run and the translated engine message (`progress_message`).
  8. **Best marker.** Per workload group, the winner of `rank(..)` (Fail and InsufficientData excluded); all other markers cleared first; `refresh_rows` after every recompute (so at least once per
     added row, test `Refreshes >= 3`).
  9. **CSV.** RFC 4180 quoting, `\r\n` after every line including the last; cells exactly as displayed (`cell_texts`).
  10. **Open report / folder.** `open_report` only for an existing FILE; `open_result_folder` falls back to the temp path.
  11. **Report store.** `<root>/<yyyyMMdd-HHmmss>/` + one JSON per report + `summary.json` (array); an empty report is `report-<run_id>.json`; the test expects `fast-sequential-run-fast-sequential.json`.
- Traps checklist:
  - **T1 Captured token.** `close()` empties the slot and cancels it, but the running loop keeps its own clone; re-reading the slot per profile is the NRE-as-bogus-Fail-row bug the C# comment names.
  - **T2 Stale progress.** The guard is `is_running && run_id == current`; a `run_id` check alone passes progress of a finished run if `is_running` was reused. Test both late-progress cases.
  - **T3 `DirectoryNotFound` before `Io`** (subtype order) and `Canceled` before both in the scan outcome.
  - **T4 Kept report after cancel.** Do not test the token after `run` returns `Ok`.
  - **T5 No Fail row for a cancelled profile.** `Canceled` outcome => status only.
  - **T6 View call order** is observable: `set_running(true)` BEFORE the rows are cleared and BEFORE `set_progress(0)`; `set_running(false)` after the final status.
  - **T7 Enumeration order.** Keep the OS order; do not sort; the limit takes the FIRST n. Directories are skipped; a file without extension is not supported (`is_supported`).
  - **T8 Image limit.** `try_int(text, 1, i32::MAX)`: `" 12"` is 12 (leading whitespace allowed), `"+5"` is 5, `"0"`, `"-1"`, `"x"`, `""`, `None` are all 0.
  - **T9 Ranking input.** Rank over the rows' phases WITH the registry images-per-sample lookup (`workload_runner::registry_images_per_sample`), as the C# default does.
  - **T10 Threads.** `BenchmarkPresenter`, the view and all `on_*` calls are UI-thread only; the four jobs, the session trait, the factory and the scan/save closures are `Send`/`Sync`.
  - **T11 No sleeps.** Fake sessions block on a channel or spin on `cancel.is_canceled()` with `std::thread::yield_now()` under a 20 s wall-clock bound (C# `Bound`); no `sleep`.
  - **T12 Recycle Bin.** No test uses the real bin: sessions are fakes; the production session test (if any) runs with `bench_recycle_bin::create_with(false, ..)`; the report-store test uses a `TempRoot`.
  - **T13 Production session `Send`.** `LoggingScope` is not `Send`; it is applied inside `run` (see the stub), never stored in the session.

## Open questions (each has a recommended default; the stub follows it)
- **O1 Step machine instead of `async`.** Recommended (used): run / scan / profile / save are four `Send` jobs, results fed back through `on_*_finished` (D-W8-2). The host (W8-18s) posts with `UiScheduler::post`.
  Alternative: one worker thread running the whole loop and posting UI actions; rejected because the factory and the row updates must stay on the UI thread (C# does both after `await`s).
- **O2 Session dispose on the worker.** The job disposes the session right after `run`, before the UI adds the rows (C# disposes after). Not observable (tests only check "disposed at the end").
- **O3 Report folder name.** C# `PhotoReview-Benchmark-Reports`. Recommended (used): `PhotoReviewRs-Benchmark-Reports` so the Rust window never writes into the C# app's report folder (R0002). The Rust CLI
  (`pr_bench::cli::arguments`) still prints the C# name because its golden pins it; if the owner wants one name, change this constant only.
- **O4 `summary.json` bytes.** C# serializes `IReadOnlyList<BenchmarkReport>` with a source-generated context (indented, default names). `pr_bench` has no array serializer; recommended: concatenate each
  report's `to_json` indented by two spaces inside `[`..`]` joined by `,\r\n`; the C# test checks only "array of 2 + contains a newline". No oracle compares these bytes (W7 pinned the report JSON, not the array).
- **O5 Pictures folder.** `initial_folder(initial, pictures_folder)` takes the folder as an argument (the Known Folder lookup is a `windows` call, W8-18r).
- **O6 Production session deps.** The `PreviewPayloadCodec`, platform codec, decoder factory and real recycle bin come from the composition root (W8-09b / W8-17c); this unit only defines `BenchmarkSessionDeps`.
- **O7 Changes to B1 stubs:** none.
