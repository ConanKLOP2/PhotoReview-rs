## Semantics (C# is the spec)
1. **`ClickCounter::register`** exactly as C# 28-44. `elapsed = time.wrapping_sub(self.time)` (the C# `unchecked`), so a `GetMessageTime` wrap-around (49.7 days) still counts as consecutive (test `TickCountWrap_...`). `slop_width / 2` is integer division (truncates toward zero; the slop is positive). `(x - x0).abs()`: the inputs are 16-bit client coordinates, so the `i32` difference cannot overflow (the C# `Math.Abs(int.MinValue)` throw is unreachable).
2. **`modifiers_from_key_states`** maps `< 0` to the flag: Control (`VK_CONTROL`), Alt (`VK_MENU`), Shift (`VK_SHIFT`), Windows when EITHER `VK_LWIN` or `VK_RWIN` is down. `read_modifiers` calls `settings_native::get_key_state` five times (C# order: Control, Alt, Shift, LWin, RWin; the second Windows read only when the first is not down) and passes the results.
3. **Clock domain.** `message_time()` is `GetMessageTime` and `tick_count()` is `GetTickCount64() as u32 as i32`: the same clock (ms since boot, 32-bit wrapping). They are mixed in ONE classifier (`TouchpadWheelClassifier` gets the message time of vertical wheels and the tick count of horizontal ones), so a different clock for `tick_count` would break the 250 ms gesture gap (D-W8B4I-15). `double_click_time_ms()` is `GetDoubleClickTime() as i32`.
4. **`cursor_screen_pixel`** is `comctl::user32::get_cursor_pos` mapped to `PointD`; `None` when the call fails (on a hidden desktop it fails: the test expects `None`, never `(0, 0)`).
5. **`drag_metrics_pixels(dpi)`** is `(get_system_metrics_for_dpi(SM_CXDRAG, dpi), ..(SM_CYDRAG, dpi))`; `double_click_size_pixels` the same with `SM_CXDOUBLECLK/SM_CYDOUBLECLK` (all four constants are in `win32::messages`).
6. **Words.** `signed_low_word(v)` = `((v as usize) & 0xFFFF) as u16 as i16 as i32`; `signed_high_word(v)` = `(((v as usize) >> 16) & 0xFFFF) as u16 as i16 as i32`; `low_word` unsigned. `wparam` (a `usize`) is passed as `wparam as isize`. The Rust wheel path uses `wheel_message::delta(wparam as i64)` and `wheel_message::screen_point(lparam as i64)` instead of `InputNative.WheelDelta` and the two words (same bits).
7. **`dpi_of(scale)`** = `((scale * 96.0).round_ties_even() as i32).max(1) as u32` (Rust `as` maps NaN to 0, C# x64 gives `int.MinValue`; both end at 1).
8. **`current_wheel_device`**: `get_current_input_message_source()` (11b) is `Some(source)` with `source.deviceType.0 == 0x10` gives `Touchpad`, `Some` otherwise or `None` gives `Unknown`. Valid only while the wheel message is being dispatched: `ShellInput` reads it inside the handler's call, never later (D-W8B4I-15).
9. **`KeyboardMessageHandler::try_handle`**: `WM_KEYDOWN | WM_SYSKEYDOWN`: `vk = resolve_virtual_key(wparam as i32, lparam)`; `key = key_mapping::from_virtual_key(vk, is_extended_key(lparam))`; `handled = port.handle_key_down(key, msg == WM_SYSKEYDOWN, is_key_repeat(lparam), port.message_time())`; `last_key_handled.set(handled)`; `handled_virtual_key.set(if handled { wparam as i32 } else { -1 })`; `handled.then_some(0)`. `WM_KEYUP | WM_SYSKEYUP`: `Some(0)` and reset to -1 only when `handled_virtual_key == wparam as i32`, else `None`. `WM_CHAR | WM_SYSCHAR`: `last_key_handled.get().then_some(0)`. Anything else `None`. NOTE the value stored is the RAW `wparam` (`VK_SHIFT`), not the resolved `VK_RSHIFT`, because the key-up message carries the raw one.
10. **`PointerMessageHandler::try_handle`**: as the C# table above; `Some(0)` only for a handled left/middle/right press. `wparam as i32` for `(int)message.WParam` then `& MK_LBUTTON`.
11. **`WheelMessageHandler::try_handle`**: only the two wheel messages; `handled.then_some(0)`.
12. **`ShellInputEnvironment::default()`** builds the real closures; a test replaces single members with struct-update syntax (`ShellInputEnvironment { message_time: Box::new(|| 1000), ..Default::default() }`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (re-entrancy, D-W8B3H-6): handlers are `&self` and can be re-entered (a command run by the key handler can `close()` the window, which sends messages back through the same chain). The only state, `last_key_handled` and `handled_virtual_key`, are `Cell`s; the port call is made with NO cell borrowed (a `Cell` has no borrow, but do not hold a `Ref` of anything else).
- T2 (integers): coordinates are `i16` sign-extended; `lparam` is `isize` (negative `lparam` with `(-1, -1)` for the keyboard `WM_CONTEXTMENU` is 14e's, here a `0xFFFF` low word must read -1). Never `as i32` the whole `lparam` first on 64-bit and then mask: mask first.
- T3 (wrap): `elapsed` uses `wrapping_sub`; `time` values are `GetMessageTime` which wraps at 2^32 ms.
- T4 (key repeat): bit 30 is "previous key state"; a held key repeats `WM_KEYDOWN` with the bit set; the first press has it clear. `ShellInput` drops auto-repeat for file actions (R2-F-06).
- T5 (Shift sides): `WM_KEYDOWN` ALWAYS carries `VK_SHIFT`, never `VK_LSHIFT`/`VK_RSHIFT`; only the scan code tells them apart. Windows may also send `VK_LSHIFT` for a synthetic key; `resolve_virtual_key` only rewrites `VK_SHIFT`.
- T6 (swallow rule): a handled key down swallows its key up and its `WM_CHAR`/`WM_SYSCHAR` (no beep, no stray character); an unhandled `Alt+F4` must reach `DefWindowProc` (it posts `SC_CLOSE`), `Alt+Space` opens the system menu.
- T7 (device hint): `current_wheel_device` is only meaningful during the dispatch of the message; never cache it.
- T8: no `unwrap()`/`expect()` anywhere in production code; every conversion is `as` between integers or `try_from` with a documented fallback.

## Safety rules (`// SAFETY:` per `unsafe` block)
`message_time` (`GetMessageTime`), `double_click_time_ms` (`GetDoubleClickTime`), `tick_count` (`GetTickCount64`): "no arguments, reads process-global state". These three are the only new `unsafe` blocks; the rest goes through the safe wrappers of 11b/11c/11e.

## Error mapping
No errors: every function is infallible. `cursor_screen_pixel` and `current_wheel_device` turn an OS failure into `None`/`Unknown`, as C#. `ArgumentNullException` for a null `ShellInput` is unrepresentable (`Rc` is non-null).
