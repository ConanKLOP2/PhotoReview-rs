## Semantics (C# is the spec; the Rust shape is in D-W8B4I-1/-3/-4/-5)
1. **Core and borrows (D-W8B4I-1).** `InputCore` keeps the pure controllers in ONE `RefCell<InputState>` (`pointer`, `router`, `versions`, `clicks`). A pure call is made as: `let settings = (deps.settings)(); let mut viewer = deps.viewer.borrow_mut(); let mut surface = deps.surface.borrow_mut(); let mut commands = ShellPointerCommands::default(); let step = state.pointer.xxx(&mut PointerContext { surface: &mut *surface, viewer: &mut *viewer, settings: &settings, versions: &mut state.versions, commands: &mut commands, log: &*deps.log }, ..);` then ALL borrows are dropped, THEN the recorded effects run (`commands.take()`: `next`, `previous`, `apply_fit` in call order), then `pointer.take_viewer_update()` (a `zoom_mode_changed` stops the glide, C# `OnZoomModeChanged`), then `post_pointer_step(step)`. Nothing that can re-enter (host calls, `window.*`, posting) happens while a borrow is held. `ShellPointerCommands` implements `PointerCommands`: `has_images` reads the host (it is the one query allowed inside the call: `host.has_images()` is a `&self` read that borrows the view model, never the input state or the viewer; the host's view-model borrow and the viewer `borrow_mut` are different cells, and `ViewerHandle` must not be touched by `has_images`: documented requirement on the host impl), `next`/`previous`/`apply_fit` only push to a `Vec` (D-W8-2 "posts the request").
2. **Constructor.** `PointerInputController::new(ticks_per_ms)`; `ShortcutRouter::from_settings(&settings.shortcuts, &settings.actions)` and remember the settings `Arc`; `surface.set_frame_router(Some(router))` where the router is a `Weak<InputCore>` upgrade calling `on_render_frame(ticks)` (D-W8B4I-5); `window.subscribe(ShellWindowEvent::Deactivated, ..)` calling `stop_kinetic` through a `Weak`; then the three handlers (14a) over the ports, `add_message_handler` in the order keyboard, pointer, wheel. A `Weak` is used in every callback so the window never keeps the input alive (T8 of 13e).
3. **`handle_key_down`**, in this exact order (C# 183-237):
   1. `modifiers = environment.modifiers()`.
   2. `arrow_consumed = modifiers == NONE && !host.is_compare_visible() && pointer.try_pan_by_arrow(ctx, key, is_repeat)` (short-circuit: the controller is not called when a modifier is held or the compare view is visible).
   3. if `!arrow_consumed`: `pointer.stop_kinetic(surface)` (every other key stops the glide unconditionally; a consumed arrow decides about the glide itself).
   4. if `PhotoReviewPerf::log().is_enabled()`: `key_input(0, key.name(), f64::from(tick_count().wrapping_sub(message_time)))` (C# `unchecked(TickCount() - messageTime)`).
   5. `arrow_consumed` -> `true`.
   6. `key == ESCAPE && escape_interceptor()` (the Tools popup closes first, R7-6) -> `true`.
   7. `key == ESCAPE && host.cancel_duplicate_check()` (Q-R25) -> `true`.
   8. `(key == SPACE || key == ENTER) && activation_key_owned()` -> `false` (a focused button or compare cell owns them).
   9. `command = router.try_resolve(if sys { KeyId::SYSTEM } else { key }, if sys { key } else { KeyId::NONE }, modifiers, RouteState { is_fullscreen: host.is_fullscreen(), has_image: host.has_images(), has_compare_pair: host.current_has_compare_pair(), is_compare_visible: host.is_compare_visible(), has_capture_pair: host.current_has_capture_pair() })` (the struct is built field by field: `RouteState::new` has the C# defaults of the optional flags, all five are passed here).
   10. `None` -> `false`. Some: unless `is_repeat && command.kind.ignores_auto_repeat()` run `execute_guarded(command)`; the key is swallowed (`true`) even when the repeat was dropped (R2-F-06).
   Before 9, the settings changed check: if `(deps.settings)()` is a different `Arc` than the last one the router was built from (`Arc::ptr_eq`), `router.rebuild(..)` (D-W8B4I-7: the `SettingsStore::subscribe_changed` handler is `Send + Sync` and cannot reach this `Rc` core, so the table is rebuilt lazily; `rebuild_shortcuts` stays for eager use).
4. **`execute(command)`** (C# `ExecuteAsync`): `ZoomActualSize` -> `pointer.zoom_actual_size(ctx)`; `ToggleFit` -> `apply_fit()`; `ZoomIn` / `ZoomOut` / `ClickZoom` -> `zoom_in` / `zoom_out` / `toggle_click_zoom`; `FitWidth` | `FitWidth2` -> `fit_width(ctx, window_helpers::fit_width_anchor_for(&settings, command.kind == FitWidth2))`; `FitHeight` -> `fit_height`; anything else -> `host.execute(command)` AFTER every borrow was released. Each pure call yields a `PointerStep`; `AwaitRender(c)` is posted (rule 8). `execute_guarded` wraps: an `Err` from the host (or a `Result` of a viewport command that cannot fail does not exist) is `log.error("Command {kind:?} failed", Some(&e))` then `host.report_action_failed(&format!("{kind:?}"), &e)` (C# `command.Type.ToString()`; the Rust name is the variant name, equal to the C# enum name). Commands from the key path and the menu path run synchronously, right after the handler decided: C# ran them inline until the first `await`, which is the same turn.
5. **`handle_pointer_down(button, px, py)`** (C# 298-326): `time = environment.message_time()`; `(sw, sh) = environment.double_click_size_pixels(dpi_of(window.dpi_scale()))`; `click_count = clicks.register(button, px, py, time, environment.double_click_time_ms(), sw, sh)`; `pointer.on_window_preview_mouse_down(surface)` (the window-level tunnel runs for EVERY button, also over the overlay and while comparing); `point = client_dip(px, py)`; `is_over_overlay(point) || host.is_compare_visible()` -> `false`. Then by button: **Left** and `is_over_image(point)` -> `pointer.on_image_press(ctx, Left, click_count, point, time)`; **Middle** and `is_inside_viewport(point)`: when `click_count == 1 && host.has_images()` and `resolve_middle_click(settings.middle_click_action_or_default())` is `Some(cmd)` -> `execute_guarded(cmd)`; the press is ALWAYS handled (`true`) inside the viewport (C# comment: `ImageScroll_PreviewMouseDown: e.Handled = true`); anything else `false`. Right and extra buttons only pass the tunnel (they stop a glide, nothing more).
6. **`handle_pointer_move(px, py, left)`**: `point = client_dip`; `last_pointer_position = Some(point)`; raise `PointerActivity` (handlers are cloned out of the list first, no borrow held while they run); `is_over_overlay(point) && !window.has_pointer_capture()` -> return; if `window.has_pointer_capture() || (is_over_image(point) && !host.is_compare_visible())` -> `pointer.on_image_move(ctx, left, point, message_time)` (the return value is not used). **`handle_left_button_up`**: `has_pointer_capture() || (is_over_image && !is_over_overlay && !is_compare_visible)` -> `on_image_release(ctx, point, message_time)`; the returned `PointerRelease.step` is posted; `handled` is ignored (the handler answers `None`). **`handle_capture_lost`**: see rule 9.
7. **Wheel.** `handle_vertical_wheel(delta, ctrl, client)`: `is_over_overlay(client) || host.is_compare_visible()` -> `false`; else `WheelInput::new(delta, false, ctrl, message_time).with_hint(environment.wheel_device())` -> `pointer.on_wheel(ctx, input, client)` -> post the step; `true` (always swallowed). `handle_horizontal_wheel`: `!window.is_loaded() || host.is_compare_visible() || !is_inside_viewport(client)` -> `false`; raise `PointerActivity`; the timestamp is `environment.tick_count()` (NOT the message time, WM_MOUSEHWHEEL has none in the WPF version); `true`. The device hint is read INSIDE the call (valid only during the dispatch). A controller `Err` does not exist (pure); the C# `RunGuarded` for the wheel reduces to the post of the step (a panic is not caught, R0003).
8. **Continuations (D-W8B4I-3).** `post_pointer_step(AwaitRender(c))`: `deps.dispatcher.post_with_priority(Box::new(move || with_input(id, |core| core.resume(c))), UiPriority::Render)`. The action is `Send` (`c` is plain data) and finds the `!Send` core through a UI-thread registry (`thread_local! { static INPUTS: RefCell<HashMap<u64, Weak<InputCore>>> }`, id from a process counter, entry removed by `dispose` and on `Drop`); a missing core drops the continuation silently (the window closed; `resume` itself would only balance the awaiting-layout counter of a controller that is gone). `resume(c)`: `pointer.resume(ctx, c)` with fresh borrows; a returned `AwaitRender` is posted again. `apply_fit()`: `apply_fit_start(&mut *surface, &mut ViewerFitAdapter(viewer), &mut VersionAdapter(&mut state.versions), &mut || pointer.cancel_pan(..), stable)` where `ViewerFitAdapter` takes `viewer.borrow_mut()` ONLY inside `reset_fit` (a held guard would collide with the surface's `update_fit_size`, which writes the viewer: T1), `VersionAdapter` maps `ViewportOperationVersion` (`i64`) to `viewport::fit::OperationVersion` (`u64`, W8-05g note), and `stable = misc::viewport_convergence::is_stable_viewport`; a `FitStep::AwaitRender` is posted the same way with `apply_fit_resume`. The pointer controller's `cancel_pan` closure and the fit driver run under the same single `state` borrow: the closure must not borrow `state` again (pass the controller and the versions from the destructured guard).
9. **Capture re-entrancy (D-W8B4I-4).** `surface.release_mouse_capture()` calls `ReleaseCapture`, which sends `WM_CAPTURECHANGED` to this very window SYNCHRONOUSLY, i.e. `PointerMessageHandler` -> `handle_capture_lost` while a pure call (`cancel_pan` inside `on_image_release`, `stop`, Fit) still holds the state borrow. `in_pointer_call` is set for the whole span of a pure call; `handle_capture_lost` with the flag set only sets `capture_lost_while_busy` (the outer call is already cancelling the pan: the nested C# `OnLostCapture` was a second, idempotent `cancel_pan`); after the outer call released its borrows the flag is cleared and, when it was set, `pointer.on_lost_capture(surface)` runs once more (same observable state; `cancel_pan` is idempotent). A `WM_CAPTURECHANGED` with the flag clear (another application took the capture) runs `on_lost_capture` at once. `try_borrow_mut` is used instead of `borrow_mut` on the state in this one path so a missed flag can never panic.
10. **Frames.** `on_render_frame(ticks)` (the surface's router): if `pointer.is_kinetic_hooked()` -> `pointer.on_kinetic_frame(ctx, ticks)` then effects as in rule 1; else nothing. `ticks` is `Some(trunc(rendering_time_ms * 10_000))` made by the viewport controller (16h) (`TimeSpan` ticks, W8-05h O5).
11. **`dispose`**: idempotent; `window.unsubscribe(deactivated)`, `surface.set_frame_router(None)`, `pointer.on_window_closed(surface)`, remove from the registry. Never touches the window if it is already destroyed beyond calling `unsubscribe`.
12. **Other members**: `note_current_index_changed(i)` -> `pointer.on_current_index_changed(surface, i)`; `apply_initial_view()` -> `apply_initial_view(ctx, settings.initial_view_mode, settings.click_zoom_percent)` + post; `set_click_zoom_level(p)` -> `set_click_zoom_level(ctx, p)` + post; `stop_kinetic()`; `on_zoom_mode_changed()` -> `stop_kinetic`; `client_dip(px, py)` = `(px / scale, py / scale)` with `scale = window.dpi_scale()` (division, not multiplication by the inverse: the same double result as C#).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (RefCell vs re-entrancy): see rule 1 and 9. Test: a fake window whose `release_pointer` immediately dispatches `WM_CAPTURECHANGED` through the handler chain; `on_image_release` must not panic and the final state must equal the non-re-entrant run.
- T2 (viewer borrow): `PointerContext::viewer` is a `&mut ViewerState` from `viewer.borrow_mut()`; the surface and the host must not touch the `ViewerHandle` during that call. Fit uses the adapter instead (rule 8). A test calls Fit and a wheel zoom with a surface that reads the viewer in `capture()`/`update_fit_size()`; a double borrow is a `BorrowMutError` panic, so the test fails loudly.
- T3 (click counting): the counter is fed by EVERY button press including those that are then rejected (overlay, compare), because C# registers before it routes; a rejected press still counts toward a later double click (C# order).
- T4 (key repeat / swallow): the router sees repeats; only the command execution is dropped for `ignores_auto_repeat` kinds; navigation and zoom keep repeating. The matching `WM_KEYUP`/`WM_CHAR` swallow is 14a.
- T5 (wheel classification): the device hint and the timestamps are handed to `pr_app` (`WheelInput`) unchanged; this unit does not classify. Vertical uses the message time, horizontal the tick count; both are the same clock (D-W8B4I-15).
- T6 (capture and focus): `Left` press over the image captures through the controller (`capture_mouse`); the unit never calls `SetFocus`/`SetForegroundWindow`; a press over the overlay or the compare view does not capture. `Deactivated` stops a glide but does not end a pan (C#).
- T7 (coordinates): pixels from 14a are signed; `client_dip` must keep the sign (a drag outside the window is negative). Wheel client points come from `window.screen_to_client_dip` (rounds the screen pixel with ties-to-even, divides by the scale).
- T8 (`Weak` callbacks): the window events, the frame router and the registry hold `Weak`; `dispose` + `Drop` leave no subscription (a test counts window subscribers).
- T9 (no async): nothing awaits; a continuation is data. A continuation posted before `dispose` and run after it is dropped, not resumed on a dead core.
- T10 (error mapping): `host.execute` `Err` is reported once; the unit never panics on a host error.

## Safety rules
No `unsafe` in this unit (everything is `Rc`/`RefCell`/traits); the OS reads are 14a's. The module-level doc states it.

## Error mapping
| C# | Rust |
|---|---|
| `Task` faulted with an exception (not cancel, not OOM) | `Err(Box<dyn Error>)` from `ShellInputHost::execute`: `log.error` + `report_action_failed(name, &e)` |
| `OperationCanceledException` | no twin (commands are synchronous); test `ACommandThatIsCancelled_...` retired |
| `ArgumentNullException` of the constructor | unrepresentable |
