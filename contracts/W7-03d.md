## Design: why a backend trait
`Program.cs` calls `BenchmarkProfiles`, `BenchmarkImageExecutor`, `BenchmarkProfileScope`, `BenchmarkWorkloadRunner.RunProfileAsync` and the report/summary JSON writers directly.
Those are W7-01/02/03a-c and are being contracted in parallel; the CLI only needs a few plain values from them. `BenchmarkBackend` (stateful: it accumulates the C# `reports` and
`outcomes` lists in call order) carries exactly those, so this unit compiles and is fully testable with a fake backend, and the lead wires the real one afterwards. The enum fields of
`ProfileInfo` are the .NET member NAMES because string interpolation prints names (`Fast`, `WarmNext`). `ToolError.type_name` is the .NET exception type NAME because the C# code
branches on exception type (`IsExpectedToolFailure`) and prints `ex.GetType().Name` into the failed phase message.

## Semantics notes
1. **Dispatch (`classify`)**: the `if` chain of Program.cs, first match wins (arity matters, modes are case sensitive):
   1. `len == 1 && a0 == "--benchmark-list-profiles"` -> ListProfiles.
   2. `len >= 2 && a0 in {"--benchmark", "--benchmark-all", "--benchmark-actions"}` -> Benchmark / BenchmarkAll / BenchmarkActions.
   3. `len in {2, 4} && a0 == "--ui-next-probe" && (len == 2 || a2 == "--cache-dir")` -> UiNextProbe.
   4. `len >= 1 && a0 in {"compare", "--perf-compare"}` -> Compare. 5. `len >= 1 && a0 == "--perf-export"` -> PerfExport. 6. `len >= 1 && a0 == "--startup-probe"` -> StartupProbe.
   7. `len >= 1 && a0 == "--perf-session"` -> PerfSession. 8. `len in {2, 3} && a0 == "--preload-bench"` -> PreloadBench. 9. `len >= 2 && a0 == "--perf-analyze"` -> PerfAnalyze.
   10. `len in 3..=5 && a0 == "--io-decode-split"` -> IoDecodeSplit. 11. `len >= 2 && a0 == "--decoder-bench" && a1 == "--raw"` -> DecoderBenchRaw (before 12).
   12. `len in 3..=6 && a0 == "--decoder-bench"` -> DecoderBench. 13. `len == 2 && a0 == "--explorer-probe"` -> ExplorerProbe. 14. `len >= 2 && a0 == "--raw-survey"` -> RawSurvey.
   15. else Unknown: usage to STDERR, exit 2 (`--benchmark` alone, `--benchmark-list-profiles x`, `--decoder-bench x` with len 2, `--ui-next-probe x y` are all Unknown).
   Modes other than 1, 2, 15 go to `backend.run_other_mode(mode, args, out, err)` and its return value is the exit code. Its default prints `PhotoReview.Benchmark.Cli: mode not available in this build` (exit 2).
2. **Console**: `Console.WriteLine` writes `\r\n`. START, DONE, progress and REPORT lines go to STDOUT, FAIL and error lines to STDERR. Error line: `PhotoReview.Benchmark.Cli: {message}`.
   Usage (stderr, exit 2): first line `PhotoReview.Benchmark.Cli: unknown or missing mode. Supported modes:`, then 16 lines, each `"  " + text`, texts copied verbatim from the
   array at the end of Program.cs (golden `no-args` pins every character). Write errors on the console are ignored.
3. **`--benchmark-list-profiles`**: for each `catalog.all()` profile one line
   `{id}\t{name}\t{workload}\tmode={loading_mode}\tworkers={workers}\titerations={iterations}\tcorrectnessOnly={True|False}\t{description}`. `bool` prints `True`/`False` in .NET.
4. **`--benchmark*` block**: `folder = args[1]`; `reject_surplus_benchmark_arguments(args)` then `resolve_profiles(args[0], args)`; an `ArgumentException` from either prints the error line and returns
   2 (so an unknown profile is reported BEFORE a missing folder; golden `benchmark-unknown-profile-wins-over-missing-folder`); `resolve_output` follows; `run_cli_benchmarks`; an `Err` that
   `is_expected_tool_failure(type_name)` prints the error line and returns 2; any other `Err` prints `Unhandled exception. {type_name}: {message}` to stderr and returns `UNHANDLED_EXIT_CODE`
   (the .NET stack trace is not reproduced: Open question 7).
5. **`run_cli_benchmarks`** (order is observable, pinned by the process golden): directory-exists check (`DirectoryNotFoundException(folder)`, message = the folder text as given);
   `resolve_report_directory` (guard before anything is created); `create_directory(report_dir)` (so a later "no supported images" error leaves the folder behind; creating over an existing FILE
   is an `IOException`, golden `benchmark-all-output-exists-as-file`); top-level `enumerate_files(folder, "*")` (hidden and system files included, subfolders not entered); `plan_dataset`;
   manifest with `get_full_path(folder)`; then per profile as documented on `run_cli_benchmarks`. Report file name `{profile.id}-{run_id}.json` (id as in the catalog, canonical case), summary
   `summary.json`, joined to the report directory with `\`. Files are written with `write_report_file` (UTF-8, no BOM, text as returned by the backend). `REPORT: {summary path}` is the last line.
   A failure inside the per-profile block that happens AFTER `run_profile` returned (report write, `report_json`) still leaves that report and outcome in the backend lists and adds a second, failed
   one: this duplicate is C# behaviour, keep it (test with a fake backend whose `report_json` fails once).
6. **`plan_dataset`**: sort by `get_file_name(path)` with `pr_core::text::cmp_ignore_case`, then by the whole path ordinal (`str::cmp`); both stable. A path is supported when
   `catalog::types::extension_in(SUPPORTED_EXTENSIONS, get_extension(path))` (RAW, WebP/HEIC are NOT supported here, `.jpg ` with a trailing space is not). Unsupported extension key =
   `"<none>"` when `get_extension(path)` is empty (`"README"`, `"b."`; an extension is never white space only because it starts with the dot, so `"b. "` and `"c.\u00a0"` keep their own
   keys `". "` and `".\u00a0"`, golden `blank-extension-keeps-its-own-key`), else the extension lower-cased with `.ToLowerInvariant()`; counted, ordered by key ordinal (UTF-16 code unit order, NOT `str::cmp` on UTF-8 for astral characters: compare
   `encode_utf16()` sequences). Files = the first 64 supported ones with `get_full_path` applied. None supported -> `InvalidOperationException("Benchmark folder contains no supported images")`.
7. **`ToLowerInvariant` is not `str::to_lowercase`**: map char by char with `char::to_lowercase`, keep the char when the mapping is not a single char (U+0130 stays `İ`), and apply no
   final-sigma rule (`ΑΣ` -> `ασ`). Goldens `turkish-and-unicode-case`, `greek-final-sigma-and-sharp-s`.
8. **Parsing** (`arguments.rs`). White space is `char::is_whitespace` (identical to .NET `char.IsWhiteSpace`, verified: U+001C..U+001F, U+180E, U+200B, U+FEFF are NOT white space).
   `split_list` = `Split(',', RemoveEmptyEntries | TrimEntries)`. Integers are `NumberStyles.None`: ASCII digits only, no sign, no space, no separator, value `<= i32::MAX`, leading zeros fine,
   and ANY number of trailing U+0000 is accepted (`"5\0"` parses, `"\05"`, `"5\01"`, `"5 \0"` do not). Doubles are `NumberStyles.Float`: leading/trailing white space of only U+0009..U+000D and U+0020
   (NBSP and U+2003 are rejected), sign, digits with optional `.` (`.5`, `5.`), optional exponent, then trailing U+0000 allowed (`"2.5 \0"`, `"1e1\0"` ok, `" 5\0 "` not); `Infinity`/`NaN` (any case) and
   overflow (`1e999`, `1.7976931348623159e308`) are rejected as non-finite, underflow to 0 (`1e-400`) as not `> 0`; `4.9e-324` is accepted. Error messages are in the doc comments and pinned by the goldens.
   `parse_defined_enum`: see its doc (quirks pinned by goldens `enum-*`, `nul-enum-*`, `enum-list-*`).
9. **ToolPathGuard**: all comparisons go through `real()` = `trim_ending_directory_separator(fs.resolve_real_path(path))`, case-insensitive (`pr_core::text`), prefix = root + `\` (a sibling whose name
   merely starts the same is allowed). A junction/symlink to the photo folder is therefore refused whether it is the output or the photo side (goldens `*-junction-*`; need
   `PhysicalFileSystem::resolve_real_path`, W2-14). `ensure_output_file` uses the DIRECTORY of the full path. Messages: see doc comments (pinned, `{root}` in goldens is the temp root).
   `write_report_file`: sibling temp `{full}.{guid8}.tmp` then `std::fs::rename` over the leaf (Windows `MoveFileEx` with replace, the leaf link itself is replaced, never written through);
   a missing target directory is `DirectoryNotFoundException: Could not find a part of the path '{temp path}'.` (the temp path, not the target: C# writes the temp file first; the golden
   scrubs `.{8 hex}.tmp` to `.{tmp}.tmp`).
10. **`resolve_report_directory`**: `output_override` of length > 0 (even `" "`) -> `get_full_path` (blank -> `ArgumentException("The path is empty. (Parameter 'path')")`, NUL ->
    `ArgumentException("Null character in path. (Parameter 'path')")`, too long -> `PathTooLongException`); `None` or `Some("")` -> `{temp_path}PhotoReview-Benchmark-Reports\{yyyyMMdd-HHmmss}-{guid[..6]}`
    (guid = `new_guid_n`, lower-case hex). Guard afterwards. Nothing is created.
    `resolve_output` (not the report directory) turns a BLANK third argument into `None` (`IsNullOrWhiteSpace`), so `--benchmark-all f " "` uses the default folder; only a direct
    `resolve_report_directory(Some(" "))` call reaches the `ArgumentException`.
11. **DONE line numbers**: `format!("{:.1}")`-style invariant text via `pr_perf::rules::fmt_fixed(v, 1)` (exact decimal expansion, half-to-even on exact ties, `NaN`/`Infinity` spelled .NET style; verified
    with .NET 10: `0.25` -> `0.2`, `0.75` -> `0.8`, `-0.04` -> `-0.0`). C# uses the CURRENT culture here (`vi-VN` prints `12,3`): Open question 2.
12. **I/O errors as .NET exceptions** (`ToolError::from_io`): message formats are in its doc comment; they are what the process golden shows for `benchmark-all-output-exists-as-file`
    (read the exact text there).

13. **Failures before the C# `try`**: `new BenchmarkImageExecutor(...)`, `CreateSeededRandom` and `BenchmarkProfileScope.ApplyLogging` run OUTSIDE the `try` of the profile loop, so in C# an
    exception there aborts the whole batch (no failed report, no `summary.json`; expected types exit 2, others crash). `BenchmarkBackend::run_profile` folds them into one `Err`, which the Rust CLI
    treats as a per-profile failure (failed report, FAIL line, batch continues). Accepted as a `Different` row (Open question 11): these constructors do not fail in practice.

## Open questions (the lead decides; the recommendation is what the stub and goldens assume)
1. **Backend seam instead of direct model types.** Recommended (used): `BenchmarkBackend`. Alternative: depend on W7-01/W7-03 types directly, which blocks this unit until they merge and ties the CLI
   tests to the engine. After the decision the lead writes `EngineBackend` (about 120 lines: catalog adapter, `run_profile` = executor + seeded random + logging scope + runner, JSON through `report.to_json`).
2. **Number culture of the DONE line.** C# `{p50:F1}` uses the current culture, so on this user's vi-VN machine the C# CLI prints `12,3ms`. Options: (a) invariant dot (recommended: the output is also scanned
   by scripts, AGENTS.md says machine-read text is invariant, no Win32 in `pr-bench`), record a `Different` row; (b) read the Windows user locale decimal separator (D10 deferred a `NumberCulture` lookup to
   W8) and print what C# prints; (c) invariant now, (b) later. Cost of (b): a platform helper plus golden cases per culture.
3. **Scope of "the CLI" in the plan row.** W7-03 says "CLI with output in the same format as `PhotoReview.Benchmark.Cli`", but the C# project holds 11 more tools (`--decoder-bench`, `--io-decode-split`,
   `--raw-survey`, `--perf-session`, `--startup-probe`, `--ui-next-probe`, `compare`/`--perf-export`, `--preload-bench`, `--explorer-probe`, `--perf-analyze`) of which `--perf-session` needs the WPF window and
   the Win32 UI host (App wave W8). Recommended: this unit = dispatch + `--benchmark*` + list-profiles + usage + shared argument/guard code; add W7-03e (`--perf-analyze` + `NavSamplesCsv`, small, `pr_perf::analyze`
   exists) and W7-03f (`--perf-compare`/`--perf-export`, pure) later; the decoder/IO/RAW survey tools and the WPF-bound ones wait for W8 or are dropped by decision. Until then they print "not available" and exit 2.
4. **Progress output ordering.** C# reports progress through `Progress<T>` (no synchronization context in a console app), i.e. on the thread pool: lines can arrive after the following DONE line and interleave.
   Rust prints each line synchronously in order. Accepted unless you want the nondeterminism reproduced (it cannot be tested).
5. **Sync backend.** `run_profile` is synchronous; if W7-03c's runner is `async`, `EngineBackend` drives it with a small single-thread executor. No async runtime enters `pr-bench` through this unit.
6. **App data folder protection.** C# refuses a `--cache-dir` that overlaps `%LOCALAPPDATA%\PhotoReview`. Rust protects BOTH `...\PhotoReviewRs` and `...\PhotoReview` (R0002). `ensure_cache_directory` receives the
   list from its caller; the goldens use `csharp_app_data_folder()` for `@`.
7. **Unhandled exceptions.** A failure outside `is_expected_tool_failure` crashes the .NET process (exit code `0xE0434352`, stack trace on stderr). Rust prints one line and returns the same exit code; stderr
   text is not compared. In Rust a backend `panic!` is exit 101 (a bug, not a mode).
8. **Console encoding.** C# writes with the console/OEM code page when redirected; Rust writes UTF-8. Only matters for non-ASCII folder names in messages; accepted, `Different` row.
9. **Default report folder name** stays `%TEMP%\PhotoReview-Benchmark-Reports\...` (the oracle and C# tool share it; it is a temp output folder, not app data).
