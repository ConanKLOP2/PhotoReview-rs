- Semantics notes:
  1. **Identity and file name (PERSISTED, D-06; golden `preview-disk-cache-path`).** `preview-v5-box|{path}|{length}|{ticks}|{is_original}|
     {w}x{h}|{orientation_applied}|{backend}` with `key.path()` (already upper-cased), decimal `i64`/`i32` (invariant: ASCII `-`),
     `True`/`False`, the backend's .NET NAME (`LenientEnum::name`); then `|kind{n}` (decimal `u8`) only when `source_kind != STANDARD`.
     Hash = SHA-256 over the UTF-8 bytes (Rust strings are UTF-8 already; a path with an unpaired surrogate cannot occur in a `String`, see
     Open questions 2), hex UPPER case (`Convert.ToHexString`), + `.pv4`. `disk_cache_path` = `directory.join(file_name)` (`Path.Combine`:
     a trailing separator is not doubled; `"D:"` gives `D:<hash>.pv4`; a `/` directory keeps its slashes and gets one `\`; golden pins all).
     The C# and Rust apps share the format, not the directory (R0002): equal names make cache files exchangeable for tests and tools.
  2. **Disabled disk cache** (`disable_disk_cache`, resolved by 14a): `disk_cache_path_for` is `None` (no hashing), `has_disk_cached_preview`
     is `false` (no existence check), no startup cleanup is scheduled (`wait_startup_cleanup` is `true` at once), nothing is ever queued (the
     decode path has no path). The 2 workers are still started (C# does) and simply idle. `clear_disk` still bumps the epoch and clears the
     directory (C# does not look at the switch there).
  3. **Disk hit** (`try_read_disk_entry`, called by 14b only when `disk_entry_exists`): `preview_file::read(path, payload_codec)` ->
     `preview_file::to_decoded_image(entry, platform_codec)` (the header's ACTUAL backend, orientation, original size and EXIF are the image's;
     `downscaled = true`), wrap in `Arc` -> `record_disk_cache_hit()`, `disk_store.note_accessed(path)` (W4-09 throttles), perf
     `DiskCacheRead(nav, path_id, ms, file_bytes)` when enabled. Return the `PreviewCacheError` unchanged on failure (14b decides). A hit
     never rewrites the entry (no persist: `source_read` stays false).
  4. **Queueing** (`queue_persist`): `cache_epoch != current_epoch()` -> return; else `persist.try_push(request)` (full or completed queue ->
     dropped, no log: C# `DropWrite` + ignored `TryWrite`). Requests hold the `Arc` image: at most 16 queued + 2 in flight stay alive outside
     the RAM budget (R06, pinned by `PersistQueueBound_IsPinnedAt18`).
  5. **Worker loop** (`run_persist_worker`; `persist_one` per request, C# `RunPersistWorkerAsync`):
     1. `request.epoch != current_epoch()` -> skip (no I/O, no log).
     2. `lease = platform_codec.to_pixels(image.platform_image())`: `Err(DecodeError::InvalidArgument{..})` -> skip silently (a foreign
        platform image is simply not persisted); any other `Err`, or a lease without pixels -> `Err(Pixels)` (logged).
     3. `is_fully_opaque(pixels)`: `Ok(false)` -> skip (IMG-01/Q-R7: JPEG would flatten transparency); `Err` -> `Err(Opacity)`.
     4. `claim_persist_path(path, epoch)` and hold a guard whose `Drop` calls `release_persist_path(path)` (C# `finally`; it must also run on a
        write error and on a panic).
     5. `preview_file::write_atomically(pixels, image.actual_backend(), image.orientation(), image.original_width(),
        image.original_height(), path, true, image.exif(), payload_codec, &CancelToken::none())` (C# passes no token); `Err` -> release (guard)
        and `Err(Write)`.
     6. Run the after-write test hook if set (clone the `Arc` out of its mutex first; never call it under a lock).
     7. `request.epoch != current_epoch()` -> `delete_stale_persist_file(path, epoch)` (BEFORE the release: this writer is still counted, so a
        newer claim is visible), release, return `Ok` WITHOUT `note_written`/`schedule_prune`.
     8. Release (guard drop), then `disk_store.note_written(path)` and `disk_store.schedule_prune()` (W4-09 coalesces).
     9. The lease drops at the end of the request (an owned lease frees its buffer).
     The loop wraps `persist_one` in `catch_unwind(AssertUnwindSafe(..))`: `Err(f)` and a panic both become ONE
     `log.error("Preview disk cache write failed: {path}", Some(&error))` (path via `Path::display`) and the loop continues: the two workers
     are never restarted, a dead worker would silently stop all persistence. On exit the worker decrements `live_workers` and notifies.
  6. **Owner table (C1 fix).** Key = `pr_core::text::path_key(path)` (OrdinalIgnoreCase, C# `StringComparer.OrdinalIgnoreCase`). Claim:
     `(max(old.0, epoch), old.1 + 1)` with a missing entry as `(0, 0)` (note: `max` with 0 means a NEGATIVE epoch (after wrapping) would be
     stored as 0, exactly like C#). Release: missing -> nothing; `writers <= 1` -> remove; else `(epoch, writers - 1)`. Delete-stale: under the
     table mutex, `entry.0 > epoch` -> keep the file; else `try_delete(path, None)` (W4-09; NO log, like C#). The delete runs under the mutex
     ON PURPOSE (check-and-delete must be atomic against a newer worker's claim); only the two persist workers take this mutex and the delete
     is one file: a documented exception to the R0003 "no lock across I/O" rule (C# does the same under `lock`).
  7. **Startup cleanup** (`start_background`, C# `ScheduleLegacyCacheCleanup` fire-and-forget): only when the disk cache is enabled; one
     `StartupCleanup` thread: `cleanup_legacy_cache_files(dir, log)` then `delete_stale_temp_files(dir, clock.utc_now(),
     LEGACY_CLEANUP_MAX_FILES, Some(log))` (W4-09: `*.tmp` older than 10 min), then set `startup_cleanup_done` and notify. Never blocks the
     constructor. A spawn failure of this thread or of a worker fails the constructor (`PreviewServiceBuildError::Spawn`, 14a).
  8. **Legacy cleanup** (`cleanup_legacy_cache_files`): not an existing directory -> return (nothing created, nothing logged). For each of
     `LEGACY_PATTERNS` in order: list the directory's FILES (not directories, non-recursive) whose NAME matches the pattern with
     `pr_core::io::physical::matches_win32_expression` (.NET `Directory.EnumerateFiles` semantics; `*.png` does not match `x.png.meta` nor
     `x.pv4`), take the first `LEGACY_CLEANUP_MAX_FILES` in listing order, `try_delete(path, Some(log))` each (W4-09 logs `Delete failed:`).
     A listing error -> `log.error("Legacy preview cache cleanup failed: {directory}", Some(&err))` and stop the whole pass.
  9. **`clear_disk`** (C# `ClearDisk`): gate { epoch wrapping += 1 } (14a's gate and atomic); then `disk_store.clear_directory()` (W4-09:
     `*.pv4` with per-file logging, then `*.tmp` silently, then forgets its tracked size); on `Ok` run the legacy cleanup (an explicit user
     action: no wait for the once-per-process pass); on `Err(e)` -> `log.error("Preview disk cache clear failed: {directory}", Some(&e))`
     and skip the legacy cleanup (C#: the exception leaves the `try` before it). Never panics, never returns an error. Does NOT clear the RAM
     cache or the original dimensions and does not raise `CacheCleared` (Clear Cache in the App calls `clear_cache` too, C-05).
  10. **`shutdown_persist_workers`** = `persist.complete()` then wait on `changed` until `live_workers == 0` (the timeout variant returns
     `false` when the deadline passes). Workers drain the remaining queue before exiting (C# `ReadAllAsync` after `TryComplete`), still
     applying the epoch check per item. Idempotent. Never called by the App (the C# production singleton never shuts down).
  11. **`has_disk_cached_preview(key)`** = `!disable_disk_cache && disk_entry_exists(&disk_cache_path(dir, key))`; `disk_entry_exists` is a
     regular-file check (`std::fs::metadata(p).map(|m| m.is_file())`, any error = false; C# `File.Exists`).
  12. **`wait_for_prune`** delegates to `disk_store.wait_for_prune(timeout)`.

## Open questions
1. **SHA-256.** Private copies exist in `pr_core::session::store` and `pr_core::diagnostics::perf`; W4-10b raised the same question (its OQ1).
   Recommended: the lead hoists one `pub fn sha256(&[u8]) -> [u8; 32]` into `pr_core::text` (or a small `pr_core::hash`) in the wiring PR;
   no new crate (D18 allows `sha2`, but the in-tree one is already verified against the RFC vectors).
2. **Unpaired surrogates.** C# `Encoding.UTF8.GetBytes` replaces a lone surrogate in a path with `EF BF BD`; a Rust `String` cannot hold one
   (W4-01a builds the key path from a `String`), so such a path never reaches here. No action; the golden has no such case.
3. **ACL tests without the `windows` crate.** `icacls` from the test is the proposal (same approach as W2-05's `attrib`). Alternative: keep
   them as C#-only. Recommended: port them `#[ignore]`d; CI on `windows-latest` may run them.
4. **`PixelLease` lifetime.** The worker borrows the pixels from the image's platform image for the duration of the write; W4-01c's
   `to_pixels(&self, &PlatformImage) -> Result<PixelLease, _>` elides the lifetime to `&self`. The stand-in in `deps.rs` ties the lease to the
   platform image (`to_pixels<'a>(&self, &'a PlatformImage) -> PixelLease<'a>`), which is what a borrowing lease needs. The lead aligns W4-01c
   at wiring.
