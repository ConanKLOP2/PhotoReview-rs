## Encoding and line breaks
Both files: UTF-8 WITHOUT BOM (`File.WriteAllText(path, text)`), written with `std::fs::write`. Line breaks are `"\r\n"` (C# `AppendLine` and the indented `Utf8JsonWriter` both use `Environment.NewLine`; verified CRLF with .NET 10 on Windows). The Markdown ends with a CRLF; the JSON has NO trailing newline.

## Small helpers (private)
- `escape(s)`: `s.replace('|', "\\|")` first, then `\r` -> `' '`, then `\n` -> `' '` (the pipe replacement does not touch the others).
- `ms(v: f64)` (C# `Ms`): NaN -> `N/A` else `fmt_fixed(v, 1)` (infinities print `Infinity`/`-Infinity`). Option version: `None` -> `N/A`.
- `pct(v)`: NaN -> `N/A` else `fmt_fixed(v * 100.0, 1) + "%"` (`Infinity%`, `-0.0%` are possible).
- `GroupKey` text = `key.to_string()` (W1-17); every place below says "KEY" for `escape(&key.to_string())`.
- Integers print as plain decimal. Counts are `i32`, `dropped_rows` is `i64`.
- **Sorting rules** (they decide the golden output): all sorts are STABLE (`slice::sort_by`, never `sort_unstable*`). Comparing `f64` like .NET `Comparer<double>.Default`: NaN is LESS than every number (and equal to NaN), `-0.0 == 0.0`. `f64::total_cmp` is WRONG (it puts positive NaN last); write `fn cmp_dotnet(a, b) -> Ordering` (`a.is_nan()` / `b.is_nan()` first, else `partial_cmp`). "Descending" = `cmp_dotnet(b, a)`, still stable (equal elements keep their original order).
- `percentile_or_nan(sorted_ascending, p)` = NaN if empty else `crate::stats::nearest_rank`.

Notes on the details:
- The dispatcher paragraph is ONE line; the dash in `starts — D06` is U+2014 (EM DASH), copy it from the golden. The heading is `## Dispatcher (>16ms)`.
- `pop(list, p)` = `percentile_or_nan(list, p)`; `qw` = `queue_wait_ms` of ALL preload items, sorted ascending; `dec` = `ms` of the items whose `kind == "decoded"`, sorted ascending (sorted with `cmp_dotnet`: golden has a NaN).
- Top 5 names: group `dispatcher_long_ops` by `name` (ordinal equality, groups in first-appearance order; the empty name is a group); for each group `total` = sum of its `ms` left to right and `count`; sort groups by `total` DESCENDING (stable, `cmp_dotnet`); take the first 5; render each `{escape(name)}×{count} ({fmt_fixed(total,1)}ms)` (the `×` is U+00D7); join with `"; "`; no groups -> empty string (the cell is `|  |`).
- The sum in the "total ms" column is `ops.iter().fold(0.0, |a, d| a + d.ms)`.
- Empty sections still print heading, blank line, header row, separator row and the blank line after; only the data rows are missing (golden `no-groups`).
- The table rows of one group are NOT sorted otherwise: groups come in `result.groups` order.
- The Startup table prints `fmt_fixed` (not `ms`): NaN would print `NaN`, `-0.0` prints `-0.0`.

### `startup_phases(summary)`
Walk `summary.startup_runs` in order, each run's entries in its insertion order; group the values by phase name (ordinal equality; groups in first-appearance order). For each group: `sorted` = values ascending (`cmp_dotnet`), `mid = n/2`, `median = sorted[mid]` for odd `n`, else `(sorted[mid-1] + sorted[mid]) / 2.0`; `min = sorted[0]`, `max = sorted[n-1]`, `count = n`. Finally a STABLE sort of the phases ascending by `median` (`cmp_dotnet`; equal medians keep first-appearance order).

## summary.json — exact schema and layout
Root object, members in this order; every member name is exactly as written (camelCase), written with `json_string_literal`:
```
csvFileCount: int
groups: [ { scenario: str, mode: str, cond: str, preloadWorkers: int|null,
            count: int, incomplete: int, lowSampleWarning: bool, droppedRows: int64,
            firstVisualMs: {p50, p95, max}, finalVisualMs: {p50, p95, max}, renderedFrameMs: {p50, p95, max},
            hitRate: dbl,
            kindCounts: { <kind>: int, ... },                 // insertion order, NOT sorted
            slowestDecilePhaseShare: { <phase>: dbl, ... },   // insertion order
            preload: { workers: int|null, items: int, pausedCount: int, cancelCount: int },
            dispatcherLongOpCount: int, dispatcherLongOpsBeforeStartCount: int,
            gcTimePercent: dbl|null, frameTimeP95Ms: dbl|null,
            folder: [ { gen: int64, t1CatalogReadyMs: dbl|null, t2Ms: dbl|null, t3Phase: str, t3Ms: dbl|null } ],   // original order, NOT sorted
            startup: [ { phase: str, median: dbl, min: dbl, max: dbl, count: int } ],                                // startup_phases order
            rules: [ { rule: str, triggered: bool|null, evidence: str, note: str|null } ] } ]
```
- `scenario`/`mode`/`cond` are the raw key parts (not `escape`d). `preloadWorkers` = `key.preload_workers`; `preload.workers` = `summary.preload_workers`.
- Every `f64`/`Option<f64>` is written with `crate::analyze::nan_as_null_double_json(v)` (finite -> .NET number text via `fmt_double`, else `null`); `None` -> `null`. So `-0.0` -> `-0`, `1e-5` -> `1E-05`, `10.0` -> `10`.
- Layout (identical to `System.Text.Json` with `WriteIndented = true`): two spaces per level; an object is `{` NL, members each on its own line as `<indent>"name": value`, separated by `,` at the end of the line, NL, closing `}` at the parent's indent; same for arrays (`[` NL, items, `]`); an EMPTY object is `{}` and an empty array `[]` (golden: `"groups": []`, empty `kindCounts`). One space after each colon, none before. NL = `\r\n`. No trailing newline after the final `}`.
- Strings, property names and dictionary keys: `json_string_literal` rules below. `bool` -> `true`/`false`.
Build it by assembling a small value tree (`enum` of Null/Bool/Int/Raw-number-text/Str/Array/Object with ordered members) and one recursive printer, or with a writer that tracks depth and "first member" flags. Either is fine as long as the bytes match.

### `json_string_literal(s)`
`"` + escaped chars + `"`. Per char `c`:
- `"` -> `"`; `&` -> `&`; `'` -> `'`; `+` -> `+`; `<` -> `<`; `>` -> `>`; `` ` `` -> ```; `\` -> `\\`; U+007F -> `\u007F`;
- U+0008 `\b`, U+0009 `\t`, U+000A `\n`, U+000C `\f`, U+000D `\r`; every other control char below U+0020 (incl. U+000B, U+0000) -> `\u00XX`;
- every other ASCII char is written as is (including `/`, space, `|`, `=`, `%`, `~`);
- every non-ASCII char -> one `\uXXXX` per UTF-16 code unit (`c.encode_utf16(&mut buf)`): `é` -> `é`, `日` -> `日`, U+1F600 -> `😀`, U+2028 -> ` `, U+FEFF -> `﻿`, U+0080 -> `\u0080`.
Hex digits are UPPER case, always four digits. The 48 golden `json_string` cases cover every ASCII char class and several non-ASCII ones.

## Golden `perf-report` (how to compare)
`report` case input fields: `name`, `csv_file_count`, `groups` (array of group specs). Build `AnalysisResult { groups, csv_file_count, ..Default::default() }` with a test helper `group_from_spec(&Value) -> GroupResult`:
