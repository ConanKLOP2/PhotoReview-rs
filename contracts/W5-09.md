## Semantics notes (the algorithm; every line has a golden case)
RAF layout: bytes 0..16 magic `"FUJIFILMCCD-RAW "` (trailing space), then version/camera text, zeros, and a big-endian pointer table:
u32 at 84 = JPEG offset, 88 = JPEG length, 92 = CFA header offset, 96 = CFA header length. The pointer table ends at 100.

1. **`can_read(first_64, ext)`**: `eq_ignore_case(ext, ".raf")` FIRST (so a wrong extension is false before the bytes are looked at); then
   `first_64.len() >= 16 && first_64[..16] == MAGIC`. Only 16 bytes are examined (a 20-byte or 64-byte slice makes no difference). No trimming of `ext`:
   `".raf "`, `" .raf"`, `"raf"`, `".raf."`, `""` are false. Use `pr_core::text::eq_ignore_case`, not `to_lowercase` (T1); golden covers `.RAF/.Raf/.rAF`,
   a dotless-i and a Kelvin-sign extension (both false).
2. **`read`, step 1, header.** `source.length() < 92` -> `InvalidData("File too short for RAF container.")` (checked BEFORE the magic: 91 zero bytes give
   "too short", not "Invalid magic"). Then `h = source.read(0, 92)?`; `h[..16] != MAGIC` -> `InvalidData("Invalid RAF magic header.")` (case-sensitive; the trailing
   space matters). `jpeg_offset = u32::from_be_bytes(h[84..88])`, `jpeg_length = u32::from_be_bytes(h[88..92])`; COPY them out before the next `read`
   (the slice borrows `source`; `read` takes `&mut self`). Messages are exact: golden `error.message` is compared for `origin == "reader"`.
3. **Step 2, preview range.** Widen both to `i64` first (C# widens `uint` to `long`; never add in `u32`/`i32`). `range_valid` is the short-circuit AND of, in this order:
   `jpeg_offset >= 100` and `jpeg_length >= 2` and `jpeg_offset + jpeg_length <= source.length()` and `source.read(jpeg_offset, 2)? == [0xFF, 0xD8]`.
   The SOI read happens only when the first three hold (it is a real read: it charges the budget block and its `?` propagates a source error).
   When valid: one `EmbeddedPreview::new(0, jpeg_offset, jpeg_length, Jpeg, 0, 0, Unknown)` (`header_resolved` false), one
   `ExifBlock::new(jpeg_offset, exif_length, false)` with `exif_length = min(jpeg_length, 131072)` (`DEFAULT_EXIF_BLOCK_BYTES`), and
   `orientation = try_read_orientation_from_jpeg(source.read(jpeg_offset, exif_length as i32)?).map_or(1, i32::from)`
   (RAF has no orientation of its own; `None` -> 1, so an invalid value 0/9/255/65535 or a missing Exif gives 1; an Exif beyond the first 131072 bytes
   is not seen -> 1; a JPEG shorter than its Exif is cut at `jpeg_length`). When not valid: no preview, no EXIF block, orientation 1, and the container is KEPT
   (no error): the CFA size is still read and the no-preview LibRaw fallback can decode the file.
   Boundaries pinned by golden: offset 100 / length 2 valid, offset 99 or length 1 invalid, `offset + length == file length` valid, `+1` invalid,
   `offset == u32::MAX`, `length == u32::MAX`, `length == 0x7FFFFFFF` invalid. The preview length is the whole `jpeg_length` (may be 2 GB-ish only
   when the file is that big; it never exceeds the file), the EXIF block length is capped.
4. **Step 3, sensor size** = `read_cfa_size(source)?`, ALWAYS executed (also when the preview range is invalid). `h2 = source.read(92, 8)?` is unconditional:
   a source of 92..=99 bytes passes the "too short" check and then FAILS here with the source's own past-end `InvalidData` (golden `valid-magic-92/95/99-bytes`: `error.origin == "source"`,
   only the kind is compared; do not add a special case, do not turn it into a size of 0x0). `cfa_offset = u32 be h2[0..4]`, `cfa_length = u32 be h2[4..8]` (as `i64`).
   Skip (size `(0, 0)`, NO error) when `cfa_offset == 0 || cfa_length < 4 || cfa_offset + cfa_length > source.length()`. Otherwise
   `cfa = source.read(cfa_offset, min(cfa_length, 65536) as i32)?` (copy it if you keep it across a call; `parse_cfa_records` takes `&[u8]` so no copy is needed).
   `cfa_offset` may overlap the header (1 or 92 are accepted; golden `cfa-offset-1-*`, `cfa-offset-at-pointer-table-92`).
5. **`parse_cfa_records(cfa)`** (`cfa.len() < 4` -> all zero). `count = u32 be cfa[0..4]`; `position = 4`; loop `i in 0..min(count, 256)` while `position + 4 <= cfa.len()`:
   `tag = u16 be`, `size = u16 be as usize`, `data = position + 4`; `data + size > cfa.len()` -> break (the record is dropped; earlier records stay);
   `size >= 4 && tag in {0x0100, 0x0111, 0x0121}`: `height = u16 at data`, `width = u16 at data + 2` (HEIGHT FIRST); for tag `0x0121` only, `width == 4284` becomes `4287`
   (LibRaw `parse_fuji`; `4285`, or `4284` under tag 0x0100/0x0111, are NOT widened); stored (as `(width, height)`) only when `width > 0 && height > 0`; a later valid record of the same tag
   overwrites an earlier one, a later invalid one does not. `position = data + size` ALWAYS (unknown tag, `size < 4`, `size > 4` all advance). The walk is bounded by 256 records and by
   the 65536 read window: golden `cfa-64k-cap-*` (a record whose data ends exactly at byte 65536 of the header is read, one byte more is dropped, a header starting at 65536 ends the walk) and
   `cfa-256-records-cap-*` (the 256th record is read, the 257th ignored, also with `count = 300`). `count = u32::MAX` is fine (min with 256). Use `checked_`/`usize` arithmetic: nothing here can overflow
   on 64-bit but write it so a 32-bit build would not either.
6. **`choose_sensor_size`**: `fits(s) = s.0 > 0 && (full.0 == 0 || (s.0 <= full.0 && s.1 <= full.1))`; result `cropped` if it fits, else `image_size` if it fits, else `full`
   (all `(0, 0)` stays `(0, 0)`). Quirks: no full record -> any valid cropped/image size fits (golden `cfa-cropped-without-full-always-fits` = 9000x9000); the 0x0121 widening happens BEFORE
   the fit test (4284 -> 4287 is then rejected by a full record 4000 wide, accepted by one 4300 wide); cropped and image size are compared against `full` only, never against each other;
   the result is never the embedded JPEG size.
7. **Cancellation.** The C# reader never looks at its `CancellationToken`. Rust: do not touch `ct` (the stub names it `ct`; once the body exists clippy needs `_ct`, rename the parameter then: names are not part of the trait contract). A token that is already cancelled
   still reads normally (golden `cancelled-token-still-reads`); the reader never returns `RawHeaderError::Canceled`.
8. **Errors and I/O.** Every `source.read(..)?` error propagates unchanged (`InvalidData`, including the I/O flag of a disk failure: it must stay an I/O failure for `is_io_failure`; `ArgumentOutOfRange` cannot
   happen because every offset/count is non-negative). Nothing is swallowed, nothing is wrapped.
9. **Read pattern and budget** (golden `bytes_charged` = C# `SourceRawHeaderSource.TotalBytesRead`, Rust `InMemoryRawHeaderSource::total_bytes_read()`, both charge 64 KiB blocks once): `read(0,92)`;
   if the range is valid `read(jpeg_offset, 2)` then `read(jpeg_offset, exif_length)`; then `read(92, 8)`; then, if the CFA range is plausible, `read(cfa_offset, min(cfa_length, 65536))`. Do not add reads,
   do not read the whole file, do not read the JPEG beyond `exif_length`. The worst case touches about 7 blocks, far under the 8 MiB budget, so `bytes_charged` cases are about WHICH blocks, e.g.
   `jpeg-length-2000000-far-cfa-block` charges 230 708 bytes (3 blocks of the JPEG window + the last block with the CFA).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- 1 OrdinalIgnoreCase: extension compare via `pr_core::text::eq_ignore_case` (semantics 1).
- 2 Culture: none; do not introduce `to_lowercase`.
- 3 Integer width (the main trap of this unit): `jpegOffset`/`jpegLength`/`cfaOffset`/`cfaLength` are `uint` widened to `long` before every add/compare; `Math.Min(uint, int)` is the `long` overload;
  sizes are `ushort` read into `int`; `width += 3` cannot overflow. Rust: `i64` for file positions, `u32` only for the raw fields, `usize` for indexes into the CFA slice; never `as i32` on a file field before the compare.
- 8 Null/empty: none (`Option<u8>` orientation `None` -> 1, an `Err` is not `None`).
- 9 Exception to Result: the C# method has no `catch`; do not add one. `InvalidDataException` from the source is the only error and it propagates.
- Hostile input: no panic for any bytes (index with `get(..)`/checked slicing in the pure functions, `read` already bounds-checks), no loop longer than 256 iterations, no allocation sized from a file field
  (the only allocation is the source's own bounded read).
- Borrow: `RawHeaderSource::read` returns a slice borrowed from `source` (`&mut`); fields needed later are copied to locals (`u32`s, `[u8; 2]`) before the next `read`.

## Open questions
1. **Corpus provisioning in the Rust repo.** There is no `tests/fixtures/raw-corpus` and no Rust `fetch-raw-samples` yet; C# has `RawCorpus` (strict env `PHOTOREVIEW_RAW_CORPUS_STRICT`). Recommended: lead ports `RawCorpus` into
   `pr-test-support` once for all W5 reader units (`corpus_dir()`, `try_get_first(pattern, name_contains)`, `is_strict()`), and this unit's corpus tests use it; until then the tests carry a 10-line local copy. Corpus tests stay `#[ignore]` so a
   plain `cargo test` never needs the download.
2. **`RawHeaderError` shape.** W5-01a's draft has a struct `RawHeaderError { message, cause }`, W5-01b's draft an enum `{ InvalidData { message, io }, ArgumentOutOfRange, Canceled }`. This unit follows W5-01b (it owns the traits).
   The two spots that touch the shape are `RawHeaderError::invalid_data(..)` (constructor) and matching `InvalidData { message, .. }` in tests; trivial to adapt.
3. **`pub` helpers.** `read_cfa_size`, `parse_cfa_records`, `choose_sensor_size`, `CfaSizes` are `pub` (not in C#) so the integration test file can reach them (cross-crate/test visibility lesson of Wave 4). If the lead prefers a smaller surface,
   they can become `pub(crate)` with the pure-function tests moved to a `#[cfg(test)] mod` inside `raf.rs` (then the porter owns that module too).
4. **Behaviour kept on purpose that looks like a bug:** a RAF of 92..=99 bytes is an error from the CFA pointer read (not "too short", not an empty container) because the C# does `source.Read(92, 8)` unconditionally. Pinned by golden; do not "fix".
