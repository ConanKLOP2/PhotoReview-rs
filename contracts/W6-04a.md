## Required behavior

1. Zero HWND or no monitor returns DWM timing directly and does not start the worker. A resolved monitor returns only
   an estimate published for that monitor; return `None` before `MIN_SAMPLES`, and after monitor changes/idle reset
   until fresh samples exist.
2. Start one worker on demand. It follows the latest requested monitor, closes the old adapter before opening a new
   one, resets estimator/publication when the monitor changes, waits for vblanks, feeds monotonic QPC timestamps, and
   publishes current `VBlankEstimator` timing. The caller never blocks for sample collection.
3. Adapter-open failure, nonzero vblank wait, and missing native wait entry/library fail only the affected monitor,
   log the C#-specified warning, close any opened adapter, and use DWM for that monitor until
   `RetryFailedAfterMs = 8000`; retry at the source comparison boundary. Other monitors remain immediately eligible.
   Unexpected worker exceptions log an error then mark the affected monitor for DWM fallback. No selected monitor means
   forget the dead worker without poisoning monitor zero.
4. Stop after `IdleStopMs = 1500` with the C# strict comparison boundary; clear stale publication and close the adapter.
   The next request starts a fresh worker. Use monotonic frequency-equivalent ticks and an injected timestamp for tests.
5. Preserve publication with monitor identity so an estimate for one display cannot answer a request for another.

## Concurrency and verification

- Fake driver waits must synchronize through explicit channels/semaphores and expose opened/waiting/closed signals.
  Teardown releases any blocked fake before joining. Timeouts are finite hang guards only; no fixed-delay assertions or
  polling.
- Do not hold the state lock across a blocking vblank wait. Keep lock order and publication transitions source-traced
  against C#; test monitor switch, idle restart, failure/retry, and disposal paths for adapter leaks.
- Mutations expected to be killed: monitor identity check, sample threshold, one-worker behavior, close-before-open,
  estimator reset, failure/retry interval and strict boundary, per-monitor failure isolation, idle boundary/publication
  clearing, and adapter close on all worker exits.
- Gates: `cargo fmt --all --check`; `cargo clippy -p pr-platform-win --all-targets -- -D warnings`;
  `cargo test -p pr-platform-win --locked`; final integration also runs workspace gates. These tests require no live
  monitor or D3DKMT operation.
