## Semantics notes
1. **Sequence of `probe_with`** (exactly the C#):
   1. `let Some(handle) = try_load() else { return unavailable("Could not load {dll_name} (not found or incompatible with the current process architecture).") }`. `free` and `create_decompressor` are NOT called.
   2. Otherwise guard the handle so `free(handle)` runs exactly once on EVERY exit (C# `finally`): normal return, `Err`, and panic unwinding. Implement with a small private guard struct holding `Option<H>` + `Option<F>` whose `Drop` calls `free`.
   3. `match create_decompressor()`: `Ok(d)` => drop `d` NOW (C# `using var decompressor`; dispose happens before `free`, the decompressor must not outlive the library), result `ok()`. `Err(e)` => `unavailable("{dll_name} loaded but failed to initialize: {e}")`.
   4. Drop order matters: the decompressor value is dropped inside the `match` arm / a nested block, the library guard is dropped last.
2. **Reason text**: exact strings above, built with `format!` (invariant by construction). `e` is `Display` of the error (`ex.Message`); do not add `Debug`, a type name or a source chain (C# prints only the message). An empty error message still yields a non-empty reason because of the prefix.
3. **Panics**: C# `catch (Exception ex) when (ex is not OutOfMemoryException)` swallows every exception except OOM. In Rust the init failure is a `Result::Err`; a panic stands for the "fatal" class (OOM twin) and is NOT caught (propagates), but the guard still frees the library. Do not use `catch_unwind` in production code.
4. **Caching** (`probe`): a `static PROBE: ProbeCache`; the first call runs the real probe, later calls (any thread) return the same `&'static ProbeOutcome`. The answer never changes later in the process, even if the DLL appears or disappears (documented C# behaviour; the Settings UI relies on it). Known divergence: a C# `Lazy` also caches an escaping exception (OOM) and rethrows it on every `Value` access, whereas `OnceLock::get_or_init` stays uninitialised after a panic and the next caller re-runs the probe. Irrelevant in practice (the OOM twin is fatal); documented, no test.
5. **Real wiring (`probe`)** depends on W5-13a. VERIFIED against the W5-13a draft stub (`contracts/drafts-w5/W5-13a/crates/pr-turbojpeg/src/native.rs`): it exports NO `try_load_library`/`free_library`; the real names are `native::DLL_NAME` (`"turbojpeg.dll"`), `native::default_library_path() -> Option<PathBuf>`, `native::TurboJpegLibrary::load(&Path) -> Result<Arc<TurboJpegLibrary>, NativeError>` (frees the module in `Drop`), `native::create_decompressor() -> Result<TurboJpegHandle, NativeError>` (goes through the process-wide `TurboJpegLibrary::shared()`, `TurboJpegHandle::drop` = `tj3Destroy`), `NativeError: Display + Error + Send + Sync` (Display = the C# `ex.Message`). So the closures in `probe()` are:
   - `try_load = || native::default_library_path().and_then(|p| native::TurboJpegLibrary::load(&p).ok())` (handle type `H = Arc<TurboJpegLibrary>`; `None` path or load error => "Could not load ..."; the load error text is NOT part of the C# reason, drop it),
   - `free = drop` (`|lib| drop(lib)`; `FreeLibrary` runs in `TurboJpegLibrary::drop`, so the probe's own reference is released last, exactly once),
   - `create_decompressor = || native::create_decompressor().map_err(|e| Box::new(e) as Box<dyn Error + Send + Sync>)`.
   `create_decompressor()` resolves the library through `shared()` independently of the probe's own handle: this matches the C# (the probe loads once with `NativeLibrary.TryLoad` to test it and frees that handle; the P/Invoke stub resolves it again). Keep it: do not add a `&H` parameter to the seam. Consequence: when `shared()` has already cached a failure it is the same failure as the probe's load, so the two never disagree within one process. If W5-13a's final names differ, adapt only these three closures and report the mismatch.
   Loading must be from the application directory only (C# `[assembly: DefaultDllImportSearchPaths(AssemblyDirectory)]` in `Native/TurboJpegNative.cs`; `NativeLibrary.TryLoad(name, assembly, null, ...)` honours it): a planted `turbojpeg.dll` in the working dir or PATH must NOT be loaded. That is W5-13a's job (`default_library_path` = `current_exe().parent()` + `LoadLibraryExW` with `LOAD_LIBRARY_SEARCH_DEFAULT_DIRS`); this file must not load libraries by itself.
6. **Never panics, never errors out of `probe`** when the DLL is absent (CI): the result is `available == false` with a reason. This is the "degrade like the C# availability probes" rule.
7. **No `unsafe`** in this file (FFI/unsafe is only allowed in the three decoder crates, and here it lives in `native`); no Windows-only dependency, so the fake-based tests run everywhere.

## Traps checklist (MULTI-AGENT-PLAN section 7)
- Free exactly once on all paths; zero times when load failed (tests check both counts).
- Dispose the decompressor before freeing the library (drop order).
- Do not swallow panics; do not log from the probe (C# does not log; the composition root logs the reason).
- `Probe` is the single source of truth for registration: `reason` non-empty iff unavailable (`Availability_ProbeIsTotal`).
- Test-only seams are `pub` (C# `internal` + `InternalsVisibleTo`); document it and keep the real `probe()` separate.

## Open questions
1. **Handle type of the seam**: C# passes `nint` and a delegate with `out`. Rust uses a generic `H` (fakes use `usize` such as `0x1234`; the real wiring uses `Arc<TurboJpegLibrary>`, see semantics 5); `probe_with`'s signature stays.
2. **`probe()` return shape**: `&'static ProbeOutcome` instead of `bool` + out param. If the App wave prefers `fn() -> (bool, Option<&'static str>)` a one-line adapter is enough; lead decides when W8 composition is contracted.
3. **Seam visibility**: `probe_with` is `pub` so the integration test file can inject fakes. Alternative `pub(crate)` + in-file `#[cfg(test)]` module; then `tests/availability.rs` leaves the owned list. Recommended: keep `pub`.
4. **`catch_unwind`**: not used (semantics 3). FFI wrappers in W5-13a return `Result`, so a panic there is a bug, not an environment condition.
