- Semantics (each item names the C# line it mirrors, so the verifier can diff):
  1. **`try_read_header`**: `len < 8` => `None`. Bytes 0 and 1 must BOTH be `I` or BOTH `M` (case sensitive; `IM`, `MI`, `ii` => `None`).
     `magic` = u16 at 2, `ifd0_offset` = u32 at 4, both in the file's byte order. The magic is NOT checked (42, 43, `0x4F52` ORF and `0x55` RW2
     all return `Some`); the offset is NOT range checked. On `None` the C# out values are `true, 0, 0`: nothing may depend on them.
  2. **`type_size`**: 1, 2, 6, 7 => 1; 3, 8 => 2; 4, 9, 11, 13 => 4; 5, 10, 12 => 8; everything else (0, 14, 15, 16, 17, 65535) => 0.
     13 (IFD) is 4 on purpose (TiffSubIfdTypeTests); 16 (BigTIFF LONG8) stays 0.
  3. **`read_u16` / `read_u32`**: `0` when `offset < 0` or `offset > len - width`. The comparison MUST be done in `i64` (or `checked_*`): with
     `len < width` the C# expression `len - 2` is negative and `0 > -1` is true => 0; in `usize` it would underflow/panic. `offset = i32::MAX`,
     `i32::MAX - 1`, `i32::MAX - 3` and `i32::MIN` are golden cases. Both byte orders.
  4. **`try_get_value_span`** (the only non-trivial function; follow the C# order exactly):
     1. `entry_offset < 0 || entry_offset > len - 12` => `None` (i64 arithmetic; the whole 12-byte entry must be inside the block. Without
        this check a truncated entry would read its offset field as 0 and return bytes from the file header: RV-I08, golden
        `span-entry-truncated-before-offset-field`).
     2. `size = type_size(field_type)`; `size == 0 || count == 0` => `None`.
     3. `total = size as i64 * count as i64` (`count` is `u32`: up to 8 * 4 294 967 295 fits in `i64`; do NOT use `usize` on a 32-bit target).
     4. `total <= 4` => inline: needs `entry_offset + 8 + total <= len` else `None`; the slice is `tiff[entry_offset+8 ..][..total]`. The
        offset field is never read in this case. A RATIONAL x 1 is 8 bytes, so it is out of line.
     5. Otherwise `offset = read_u32(tiff, entry_offset + 8, little_endian)`; `offset >= len` => `None` (so `offset == len` is rejected and
        `offset == 0` is accepted: it reads from the TIFF header, golden `span-offset-zero-reads-header`).
     6. `available = len - offset`; `total = min(total, if field_type == 2 { 256 } else { 4096 })`. The cap is by TYPE NUMBER, so BYTE (1)
        and UNDEFINED (7) and every numeric type get 4096, only ASCII (2) gets 256.
     7. Types 2 and 7: `total > available` => `None` (a text/blob running past the end is rejected, never shortened). Note the cap is applied
        FIRST: ASCII count 1000 at `len - 200` gives `total = 256 > 200` => `None` (golden `span-ascii-capped-then-past-end`).
     8. Every other type: `total = min(total, available / size * size)` (integer division: whole elements only).
     9. `total < size` => `None`; else return `tiff[offset..offset+total]`.
  5. **`read_ascii`**: type must be 2 or 7 else `None`; clamp the slice to 256 bytes (UNDEFINED spans carry up to 4096); cut at the first `0`
     byte; an empty result (including a leading NUL) => `None`; decode as UTF-8. The clamp happens BEFORE the NUL search, so a NUL at index 256
     is never seen and a 2-byte character split by the clamp becomes one replacement character (golden `ascii-clamp-splits-multibyte`).
  6. **`read_unsigned`**: type 1 needs 1 byte; 3 needs 2 (u16); 4 and 13 need 4 (u32); 8 needs 2 and returns the value as `i16` sign-extended;
     9 needs 4 and returns `i32` sign-extended; every other type (0, 2, 5, 6, 7, 10, 11, 12, 16) => `None` even when bytes are present.
     A longer slice is fine: only the first element is read. Result is `i64` (C# `long?`), never negative for 1, 3, 4, 13.
  7. **`read_rational`**: `value.len() < 8` => `None`. Type 5: `Some(numerator, denominator)` as read, zero allowed (denominator 0 is kept;
     `ExifRational::value` handles it). Type 10: both words reinterpreted as `i32`; `None` unless both are `> 0`; then `Some` of the same
     bits as `u32`. Every other type => `None`. Only the first rational of an array is read.
- Traps checklist:
  - Integer width: `i32` offsets, `u32` counts, `i64` intermediate. Using `usize` for `entry_offset` or `u32` for `count * size` is the whole
    bug class this port can have; the 212 goldens include `i32::MIN`, `i32::MAX` and `count = 4 294 967 295` for each reason.
  - Return a SLICE of the input (`Option<&[u8]>`): no copy. The lifetime is the input's, not `'static`.
  - UTF-8 decode (INV: byte-identical results across implementations): `String::from_utf8_lossy` and .NET `Encoding.UTF8.GetString` both
    replace each maximal invalid subpart with one U+FFFD (the WHATWG / Unicode "best practice"). Goldens `ascii-invalid-ff-fe`,
    `ascii-truncated-3byte-then-ascii`, `ascii-lone-surrogate-encoded`, `ascii-overlong-c0-80`, `ascii-above-10ffff`, `ascii-continuation-only`
    verify this per case. A leading BOM (`EF BB BF`) is KEPT as U+FEFF by both. If one case differs, record it as `// DIVERGENCE:` in the test
    and stop: do not hand-write a decoder (open question 2).
  - Latin-1 bytes (`Caf\xE9`) are NOT decoded as Latin-1: UTF-8 only, `Caf\u{FFFD}`.
  - No `unwrap`/index panics on any input: every slice index goes through the checks above; the fuzz test is the proof.
  - No logging, no clock, no I/O, no global state: all functions are pure and `Send + Sync` by construction.
  - D5/D19: no accepted divergences. No path or time values in the golden.

## Open questions
1. **Where `ExifRational` lives.** C# declares it in `ExifSummary.cs` (W4-04a). `read_rational` returns it, so W4-03a cannot compile without
   it, and W4-04a depends on the persisted summary format (not on this unit's order). Recommended and used by this stub: define it HERE in
   `pr_imaging::tiff` and have W4-04a `pub use crate::tiff::ExifRational;` in `exif_summary.rs` (the C# name stays reachable from both
   paths). Alternative: a `pr_imaging::exif_types` leaf both import. The lead must tell the W4-04a author before either contract is wired;
   if W4-04a's draft already declares the struct, delete one of the two and keep the field names `numerator`/`denominator` and
   `Debug, Clone, Copy, PartialEq, Eq, Hash` derives (C# record struct gives structural equality and hashing).
2. **UTF-8 replacement parity.** Both decoders follow the Unicode maximal-subpart rule, but the golden is the authority: if the oracle run
   shows a differing `ascii-*` case, the porter records the case as a divergence and the lead decides between a 30-line hand decoder and
   accepting it (the strings only reach the photo information line, never a cache key or a file).
3. **`i32` vs `usize` in the public API.** Keeping `i32` mirrors C# and the callers' arithmetic (`ifd0 + 2 + 12 * i`), at the cost of
   `as i32` casts in W4-03b. Alternative: take `i64`. Recommended: keep `i32`; the goldens fix the behaviour either way.
4. **`TryReadHeader` shape.** The C# `out` triple is returned as `Option<TiffHeader>`. The `out littleEndian` default `true` on failure is
   dropped (no caller reads it; verified in `ExifParser`, `TiffHeaderNavigator` and the readers by `git grep TryReadHeader d92d6aae`).
