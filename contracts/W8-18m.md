## Semantics (C# is the spec)
1. **`push_button_draw`** (rules in the stub doc). Key table: `back_key` = `!enabled` -> `Dark.Button`; `pressed || latched` -> `Dark.ButtonPressed`; `hot` -> `Dark.ButtonHover`; else `Dark.Button`. `border_key` = `!enabled` -> `Dark.Border`; `is_default` -> `Dark.TextSoft`; `focused` -> `Dark.Accent`; else `Dark.BorderStrong`. `text_key` = `enabled` -> `Dark.TextStrong`, else `Dark.TextMuted`. Worked examples (checked by the porter, they are hand-computed from the C#): `width 100, height 24, scale 1.0, all false except enabled`: `back_key = Dark.Button`, `border_key = Dark.BorderStrong`, `radius 6`, `text_rect = (4, 0, 96, 24)`, `text_flags = 0x8025` (`DT_CENTER 1 | DT_VCENTER 4 | DT_SINGLELINE 0x20 | DT_END_ELLIPSIS 0x8000`), `focus_rect None`. `pressed + focused + is_default + enabled`, same size: `back_key = Dark.ButtonPressed`, `border_key = Dark.TextSoft` (default wins over focused), `text_rect = (5, 1, 97, 25)`, `focus_rect = Some((3, 3, 97, 21))`. `scale 1.5, width 100, height 24`: `radius 9`, `text_rect = (6, 0, 94, 24)`, focus rectangle inset `S(3) = 4` (`round_ties_even(4.5) = 4`). Disabled: `back_key = Dark.Button` even when `hot` or `pressed`; `border_key = Dark.Border`; no focus rectangle even when `focused`. Multiline: `text_flags = DT_CENTER | DT_VCENTER | DT_WORDBREAK = 0x15`; `hide_accel` adds `DT_HIDEPREFIX 0x100000`.
2. **`draw_push_button`**: decode as the stub doc: `style = get_window_long_ptr(hwnd, GWL_STYLE) as u32`; `enabled = is_window_enabled`; `state = send_message(hwnd, BM_GETSTATE) as u32`; `pressed = state & BST_PUSHED`, `focused = state & BST_FOCUS`; `is_default = style & BS_TYPEMASK == 1`; `latched = style & BS_PUSHLIKE != 0 && send_message(hwnd, BM_GETCHECK) == BST_CHECKED`. Order of GDI calls: pen, brush, select both, `round_rect`, select back, delete both; text; focus rectangle.
3. **`paint_to`** (double buffering): the stub doc. The memory DC and bitmap are owned by a small guard struct so every exit (including a panic in `draw`) selects the old bitmap back and deletes the bitmap and the DC. `paint_window` owns its `BeginPaint` session the same way (`end_paint` in the guard's `Drop`, so a panic in `paint_to` cannot leave the window unpainted-and-unvalidated; the C# `finally`). When the compatible DC or bitmap cannot be created the control is drawn straight onto `hdc`.
4. **`draw`**: scale from `get_dpi_for_window`; the font of the control is selected into the DC only when `WM_GETFONT` answers non-zero and the old font is selected back on every path (a guard). The background fill is `DialogColors::window()`.
5. **`fill` / `frame`**: an empty rectangle draws nothing; each `fill` creates a solid brush, calls `fill_rect`, deletes the brush (a guard, never leaks on an early return).
6. **`adjust_list_view_custom_draw`**: reads `nm.nmcd.dwDrawStage`, `nm.nmcd.dwItemSpec`, `nm.nmcd.hdr.hwndFrom`; `selected` = `(send_message(hwndFrom, LVM_GETITEMSTATE, row, LVIS_SELECTED) as u32 & LVIS_SELECTED) != 0` (0 = `hwndFrom == 0` is simply "not selected"); `geometry::adjust_custom_draw(stage, result, || selected)`; applies the adjustment (`uItemState &= !CDIS_SELECTED`, `clrText`, `clrTextBk` as `COLORREF`) and returns `adjustment.result`. Typed fields of the `windows` struct, never byte offsets (D-W8B5-311, the layout assertions of D-W8B5-212 stay in the tests of 18g).
7. **`repaint_now`**: dead or invisible window -> nothing; the DC from `get_dc` is released on every path.
8. **`window_text`**: empty text is `""`; the `get_window_text` wrapper already returns a `String`.
9. **`text_width` / `text_height`**: failure of `get_text_extent_point32` is `0`; `text_height` measures `"Ag"`.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (GDI leaks): pens, brushes, the memory DC and the bitmap are deleted on every path; guards, not `finally` by hand; the test counts `GetGuiResources(GR_GDIOBJECTS)` over 50 paints (baseline after one warm-up paint).
- T2 (re-entrancy): `draw` sends `BM_GETSTATE`, `BM_GETCHECK`, `WM_QUERYUISTATE`, `WM_GETFONT` to the same control, which re-enters `control_proc`; nothing in this unit may hold a `RefCell` borrow (there is none) or the state across such a send except the `&PaintState` (`hot` is a `Cell`).
- T3 (coordinates): the control draws into a DC whose origin is its client top-left; `PaintTo` uses a bitmap of the CLIENT size and `bit_blt(hdc, 0, 0, w, h, memory, 0, 0, SRCCOPY)`.
- T4 (arithmetic): `S()` rounds half to even (`geometry::scaled`); `text_rect` is built with plain `i32` additions (no overflow at dialog sizes).
- T5 (text): `draw_text` copies the rectangle (the C# passes by value; the OS may change the rectangle for `DT_CALCRECT`/`DT_MODIFYSTRING`, which are not used); the `draw_text` wrapper strips `DT_MODIFYSTRING` already.
- T6 (unsafe): only `send_message` is unsafe; each call passes plain integers or a pointer to a local, with a `// SAFETY:` comment.
- T7: no `unwrap` / `expect` / `panic` outside tests.

## Safety rules (`// SAFETY:` per `unsafe` block)
`send_message` calls with integer parameters of the button / trackbar / list view messages ("a plain message with value parameters; the OS validates the window"); `LVM_GETITEMSTATE` ("`wparam` is the row, `lparam` the state mask: values only"). No pointer messages in this unit.

## Error mapping
| C# | Rust |
|---|---|
| `GetClientRect` returns false | `paint_to` returns without drawing |
| `CreateCompatibleDC` / bitmap returns 0 | direct drawing onto `hdc` |
| `BeginPaint` returns 0 | `paint_window` still calls `end_paint` for a session only when one was returned |
| exceptions in drawing | `pending_panic` through `control_proc` (18l) |
