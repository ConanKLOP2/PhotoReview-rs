## Semantics (C# is the spec)
### `present` (C# 26-121) in the exact order
1. `disposed || surface is None || window.is_destroyed()` -> return. `(w, h) = window.client_size_pixels()`; `w <= 0 || h <= 0` -> return (minimised: nothing to draw; the frame after restore draws).
2. `awaiting_first_image = !first_image_drawn`. `mode = pacer.mode_for(viewer.is_fullscreen(), awaiting_first_image)` (windowed -> `Immediate`, full screen -> `VSync`, the first image always `Immediate`).
3. Unless awaiting the first image: if `surface.frame_latency_wait_handle() != 0` and `pacer.should_defer(surface.wait_for_next_frame(0)?)` -> `window.invalidate()`; return (the swap chain has no new frame yet; never block; `MAX_DEFERRED_FRAMES = 3` bounds the deferral). A `wait_for_next_frame` `Err` is logged `"Frame failed"` and the frame dropped (C# would let the exception escape into the UI thread; the Rust choice is documented, no test pins it).
4. Timestamps with `pr_core::diagnostics::perf::timestamp()` (10 MHz, `STOPWATCH_FREQUENCY`): `frame_start = timestamp()`. Resize step, WITHOUT holding the surface borrow across foreign calls: `if surface.pixel_width() != w || surface.pixel_height() != h || surface.dpi_scale() != window.dpi_scale() { surface.resize(w, h, window.dpi_scale()) }` (the dpi comparison catches a monitor change with the same pixel size, WP-25; compare as `f64` equality like C#). Then `composer.try_promote_pending()` (a finished upgrade becomes the main image BEFORE layout so this frame measures the new bitmap), then `if viewport.is_layout_posted() { viewport.update_layout() }` (same-frame layout, like WPF `UpdateLayout`). Layout runs BEFORE `BeginDraw`, so the scroll bars drawn in this frame come from this frame's layout (scroll-bar sync, D-W8B4M-8).
5. Draw segment (the surface is borrowed mutably for exactly this segment): `surface.set_immediate_present(mode == Immediate)`; `context = surface.begin_draw_context()?`; `context.clear(canvas_color())`; `draw_content(context)` (image layer 13j, then scroll bars); then every feature's `draw_overlay(context)` in registration order (the HUD, same frame, over the bars); `present_start = timestamp()`; `result = surface.end_draw_and_present()?`; `present_ticks = timestamp() - present_start`. `end_draw_and_present` is ALWAYS called once `begin_draw_context` succeeded (C# `finally`). A panic inside the draw leaves the frame open and unwinds (R0003; the C# `finally` ran `EndDraw` for exceptions, Rust has no exceptions here; the process-level crash handler of 17e is the owner of that case).
6. Any `Err(RenderFault)` of resize/begin/end (all variants: `Device`, `InvalidOperation`, `Disposed`; the C# `catch (COMException or InvalidOperationException or ObjectDisposedException)`) -> `Log::error("Frame failed", fault)`; return WITHOUT `on_frame_presented` (the unbalanced-stack error of `end_draw_and_present` is raised after the present, as in C#: a presented frame is then not counted).
7. `pacer.observe_present(mode, present_ms)` (a `true` return logs once: "Present(1) blocked the UI thread; the shell now presents without waiting for vblank (WP-21)."). `end_draw_ms`, `present_ms` from `surface.last_end_draw()` / `last_present()` as ms. If `FrameStats::is_slow(end_draw_ms, present_ms)`: `stats.record_slow(frame_ms, draw_ms, end_draw_ms, present_ms, note)` with `note = format!("mode={mode:?} result={result:?} img={w}x{h} fade={active}")` (`w x h` of the composer's current image, empty when none; built ONLY for slow frames: the hot path allocates nothing). `stats.record(frame_end - frame_start, present_ticks)`. `frame_log.record(frame_start, frame_end, end_draw_ms, present_ms)` when enabled (opened by 16d with the same tick unit; at landing the two fields `keep_warm`/`frame_log` of the window become one `RefCell<Option<KeepWarmSetup>>` and this call is `setup.frame_log.as_mut()`, as 16d's contract says).
8. `result` is `DeviceRecreated` or `Failed` -> `window.invalidate()` (the cache cleared itself on the device event; the image uploads again from its `PixelBuffer` at the next frame); `Failed` -> return. `Presented`, `DeviceRecreated`, `Occluded` -> `on_frame_presented()` (an occluded frame was drawn and submitted: it still counts so the cloak is lifted and the startup marks advance; when the window is uncovered `WM_PAINT` -> `invalidate` redraws).
### `on_frame_presented` (C# 130-159)
`image_drawn = take(image_drawn_in_frame)`; if it was set: `first_image = !first_image_drawn; first_image_drawn = true`. `hub.note_frame_presented(image_drawn)` (BEFORE the marks). First frame of any kind: `first_present_done = true`; mark `firstPresent`; `cloak.note_first_present()`; raise `FirstPresented`. If `first_image`: when `options.activate` -> `keep_warm.warm_at_launch()` (perf gate 3: the first key press is not the first work the idle GPU sees); raise `FirstImagePresented`. Events use `EventList::raise` (snapshot, no borrow held, a subscriber may unsubscribe).
### `render_now`, `render_frame`
Both are `present()`. `render_frame` is the `Render` event handler (one call per `invalidate` burst, at the next frame tick, 13e). `render_now` is for the first canvas frame (so the window shows something at once) and the first image (13j).
### Scroll-bar glue
`register_scroll_bars` must run before input (13g). `on_window_closed_for_scroll_bars`: unsubscribe the `Closed` subscription (id in `closed_subscription`), `bars.dispose()` (the bars stay in the field, as C#; `draw_scroll_bars` after that draws nothing because the bars are disposed). `draw_scroll_bars(context) = bars.map(|b| b.draw(context))`. `scroll_bars()` before registration is `Err(FeatureNotRegistered { feature: "Scroll bars" })`.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7 and window-specific)
- T1 (surface borrow): the draw segment holds `surface.borrow_mut()`. Everything called inside it (image layer, bars, overlay hooks, `DrawContext`) must not touch `has_surface`, `with_surface` or `attach_renderer` (use `try_borrow`, which returns "none/busy"). A test calls `with_surface` from a feature's `draw_overlay` and expects `None`, not a panic.
- T2 (re-entrancy): `present` is never called from inside the window procedure for `WM_PAINT` (13f makes `WM_PAINT` validate + invalidate); it runs from the frame clock handler or from `render_now` in a posted or direct call. `render_now` from inside `present` (a hook calling it) returns at once through a `Cell<bool>` guard (C# had none; a nested `BeginDraw` would be an `InvalidOperation` anyway).
- T3 (ticks): `perf::timestamp()` for frame times (10 MHz) and `FrameStats::new(STOPWATCH_FREQUENCY)`; the keep-alive thread's nanosecond ticks (D-W8B3S-8) are a different clock and never mixed. `Duration` -> ms: `as_secs_f64() * 1000.0`.
- T4 (sizes): `client_size_pixels()` is `i32`; the surface compares `i32`; the dpi comparison is `f64 !=` on values that both derive from `dpi / 96.0` (never from different dpi sources).
- T5 (device loss mid-frame): `DeviceRecreated` handlers run synchronously inside `end_draw_and_present` (the cache clears, 12g); the window must not hold the `cache` borrow across the call. `present` holds only the surface borrow; the cache handler borrows the cache cell separately.
- T6 (first-image flag): `image_drawn_in_frame` is set by 13j's `draw_presentation` inside the draw segment and consumed in `on_frame_presented` after `end_draw_and_present`; a frame that returns early (Err, Failed) leaves the flag set for the next successful frame (C# same).
- T7 (`Occluded`): not an error and not retried; do not `invalidate` for it.
- T8 (scroll-bar sync): bars read the viewport layout of the same frame (layout runs in step 4); a resize between `invalidate_layout` and `present` is covered because `ClientSizeChanged` posts a layout pass and `present` runs `update_layout` first.

## Safety rules
No `unsafe` in this unit (the surface and context are safe Rust types; the OS calls are behind `D2dRenderSurface`).

## Error mapping
| C# | Rust |
|---|---|
| `catch (COMException or InvalidOperationException or ObjectDisposedException)` in `Present` | any `RenderFault` -> `Log::error("Frame failed", ..)`, frame dropped |
| `ArgumentNullException`/`InvalidOperationException("Scroll bars are not registered.")` | `MainWindowError::FeatureNotRegistered { feature: "Scroll bars" }` |
| an exception from a `FirstPresented` subscriber | propagates (panic, R0003) |
