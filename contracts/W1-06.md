- Semantics notes (from the contract writer; all verified against the C# oracle with a throw-away implementation):
  1. **Algorithm** (`compare_natural(x, y)`): build `kx = build_natural_key(x)`, `ky = ...(y)`;
     `c = cmp_ignore_case(kx, ky)` -> if not Equal return it; else `c = cmp_ignore_case(x, y)` -> if not Equal return it;
     else return `x.cmp(y)` (ordinal). `cmp_ignore_case` is `pr_core::text::cmp_ignore_case` (OrdinalIgnoreCase), NEVER
     `to_lowercase()`. The C# result is `int`; Rust returns `Ordering` (the golden stores the sign).
  2. **Null handling** (trait impl only): `(None, None)` Equal, `(None, Some)` Less, `(Some, None)` Greater.
  3. **Key** (`build_natural_key`): scan the chars; a maximal run of `is_dotnet_digit` chars becomes
     `format!("{:010}", digits_after_trimming)` + the trimmed digits + `'\0'`, where trimming removes leading **ASCII '0'
     only** (not other zero digits like `'٠'`), and `digits_after_trimming` is the number of chars left (0 for an all-zero
     run, then no digit chars but still the prefix and the `'\0'`). Every non-digit char is pushed as `lower_invariant(c)`.
     Empty name -> empty key. Examples (from the oracle): `"a2"` -> `"a00000000012\0"`, `"007.jpg"` -> `"00000000017\0.jpg"`,
     `"0"` -> `"0000000000\0"`, `"a0b00c"` -> `"a0000000000\0b0000000000\0c"`, `"١٢٣"` -> `"0000000003١٢٣\0"`.
  4. **Digits are not numbers.** Non-ASCII Nd digits (Arabic-Indic, fullwidth, Devanagari ...) count as digits (they form a run
     and add to the run length) but are copied unchanged, so `"١٢"` vs `"12"` is decided by the code points, not by value.
     Digit test is `.NET char.IsDigit` on one UTF-16 unit: `DECIMAL_DIGIT_RANGES` (BMP only). A char above U+FFFF (e.g.
     U+1D7CE MATHEMATICAL BOLD DIGIT ZERO, `"a𝟎"`) is NOT a digit. Do not use `char::is_numeric` or `is_ascii_digit`.
  5. **Lower-casing** (`lower_invariant`): ASCII -> `to_ascii_lowercase`; code point > U+FFFF -> unchanged; one of
     `NOT_LOWERED_BY_DOTNET` -> unchanged; else simple lower-case: `c.to_lowercase()` if it yields exactly one char, otherwise `c`
     (so `'İ'` U+0130, whose Rust lower-case is two chars, stays `'İ'`; `'ǅ'` -> `'ǆ'`; `'K'` KELVIN SIGN -> `'k'`; `'ß'`, `'ı'`, `'ſ'` unchanged).
  6. **Why three steps**: the key ignores leading zeros, so `"a01"` and `"A1"` have equal keys; the second step (case-insensitive
     original text) orders them (`"a01" < "A1"`: `'0' < '1'`), the third step (ordinal) orders `"A1" < "a1"` (upper case first).
     Equal result only for identical strings. After lower-casing, comparing keys case-insensitively means the effective char order
     is *upper-case* order: `'_'` (0x5F) sorts AFTER every letter, `'['` and `` '`' `` too, `'~'` after all (golden pairs `["_a","a"]`...).
  7. **Ordinal tie-break** `x.cmp(y)`: UTF-8 byte order equals code-point order, which equals the C# UTF-16 order whenever the two strings
     already compared OrdinalIgnoreCase-equal. The golden pairs with U+E000 vs U+1F600 prove the OrdinalIgnoreCase step orders by code point
     (`"\u{E000}" < "😀"`), which is what `cmp_ignore_case` does.
  8. **Overflow:** none. Digit runs of any length are never parsed to numbers, only counted (a 5000-digit run gives prefix `0000005000`).
     The prefix is `LENGTH_PREFIX_WIDTH` wide; a run longer than 10^10 chars cannot occur.
  9. **Culture:** the result never depends on locale (tests run Turkish culture in C#; Rust has no culture). Keep it that way.
  10. **Performance:** this is a hot path (every folder sort). Allocating two `String`s per `compare` is acceptable for this WU; the
      later `ImageSortService` WU precomputes keys with `build_natural_key`. Do not add caches or `unsafe`.
