## Semantics
1. `followed` counts redirects **already followed before this response**, not responses seen. At `followed == 49`, one more redirect can be followed (the 50th). At `followed >= 50`, return the next redirect response (the 51st) as plain 3xx. The C# checker then returns BadResponse at `UpdateChecker.cs:43`. **Recommended default, believed but not verified in a .NET 10 loopback probe:** redirects are 301, 302, 303, 307, 308; 300, 304, 305, 306 and other statuses are returned as-is. Missing/unusable Location is returned as-is. HTTPS-to-HTTP downgrade returns the original 3xx response rather than a transport error; the checker returns BadResponse at line 43. Clear Authorization before any followed redirect, including cross-origin; the app's minimal request currently has none. Rules are applied in the following priority order (a `*` means either value; `R` = 301/302/303/307/308):

   | status | from_https | to_https | has_location | followed | decision |
   |---|---|---|---|---|---|
   | not R, including 300/304/305/306 | * | * | * | * | `ReturnResponse` |
   | R | * | * | false | * | `ReturnResponse` |
   | R | * | * | true | >= 50 | `ReturnResponse` (51st redirect response) |
   | R | true | false | true | 0..49 | `ReturnResponse` (downgrade) |
   | R | true | true | true | 0..49 | `Follow` |
   | R | false | false | true | 0..49 | `Follow` |
   | R | false | true | true | 0..49 | `Follow` |

   `has_location` means the transport validated a usable target URI before calling this function. The declared `to_https` value is ignored when `has_location == false`.
2. `proxy_source` is **only for an HTTPS URL**, which is the sole URL sent by the checker; H1 returns an HTTP downgrade without opening it. Interpret each boolean as a usable, nonempty setting. **Recommended default, believed but not verified for every environment edge:** `HTTPS_PROXY` wins, then `ALL_PROXY`, then current-user settings, then direct. This is the complete boolean truth table; `NO_PROXY` and PAC bypass evaluation occur after source selection and need separate probes.

   | has_https_proxy | has_all_proxy | has_user_proxy | result |
   |---|---|---|---|
   | false | false | false | `Direct` |
   | false | false | true | `UserSettings` |
   | false | true | false | `AllEnvironment` |
   | false | true | true | `AllEnvironment` |
   | true | false | false | `HttpsEnvironment` |
   | true | false | true | `HttpsEnvironment` |
   | true | true | false | `HttpsEnvironment` |
   | true | true | true | `HttpsEnvironment` |

3. `remaining_timeout` computes a monotonic whole-exchange deadline. The function returns `None` at zero remaining time; the caller checks its cancellation token first if both conditions are observed. Boundary table:

   | total | elapsed | result |
   |---|---|---|
   | > 0 | < total | `Some(total - elapsed)` |
   | > 0 | == total | `None` |
   | > 0 | > total | `None` |
   | == 0 | any nonnegative value | `None` |

   Use the same total across redirects and body reads; do not reset it for a new WinHTTP request handle.
4. Translate only Windows errors with proven semantic equivalence to `NameResolutionError`, `ConnectionError`, `ProxyTunnelError`, `SecureConnectionError`, `HttpProtocolError`, `InvalidResponse`, `ResponseEnded` or `ConfigurationLimitExceeded`. The remaining C# `Classify` BadResponse members (`UserAuthenticationError`, `VersionNegotiationError`, `ExtendedConnectNotSupported`; `UpdateChecker.cs` 79-81) have no known WinHTTP source and stay reachable only through the merged checker. Unknown codes map to `Unknown` and thus Offline by the merged checker; a table must justify every non-Unknown mapping.

Pure oracle proposal: command `w10-http-policy`, C# file `tools/oracle-cs/Commands/W10-H1.cs`, input `tests/golden-inputs/w10-http-policy.json`. Cases: default `HttpClientHandler` properties (redirect, maximum, decompression), redirect HTTPS→HTTP and redirect count 49/50/51 using a fake `HttpMessageHandler` where applicable, all `HttpRequestError` classifications, and timeout subtraction boundaries. A fake handler cannot expose SocketsHttpHandler's actual redirect/proxy logic; use loopback socket tests for those and mark oracle fields unavailable where necessary. **The oracle is proposed only and was not written or run.**

## Traps
- `WinHttpSetTimeouts` gives per-phase bounds, not the linked token's total ten seconds. A redirect resets neither the deadline nor the caller token.
- `NO_PROXY` and WinINet bypass syntax differ; do not feed one list directly into the other without tests.
- The transport validates the Location URI and passes `has_location` and the target scheme; malformed URI handling must be matched to the .NET local probe.
