## Semantics
1. **The target is blocking (R0003).** C# `Task PreloadAsync` becomes `fn preload(&self, path, &CancelToken) -> Result<(), DecodeError>`
   that returns when the decode is done; W4-15b calls it on a worker thread only. Every other target method is cheap and may run on
   the UI thread. `GetCurrentCacheKey` throws in C#; here `Result<ImageCacheKey, KeyError>` keeps the scheduler's one catch arm
   (`IOException or UnauthorizedAccessException`, i.e. every `io::Error`) apart from everything else (`KeyError::Other`, which ends the
   run). `From<CacheKeyError>`: `SourceNoLongerExists` and `InvalidPath(TooLong)` are I/O, `InvalidPath(Argument)` is Other.
2. **`parse_diag_workers`** = .NET `int.TryParse(s, NumberStyles.Integer, CurrentCulture)` + range `0..=16`. Golden section
   `parse-diag-workers` (39 cases: white set U+0009-U+000D and U+0020 only, NBSP/fullwidth/Arabic-Indic digits rejected, trailing NULs
   accepted, `-0` = 0, `"2147483648"` = None). D4: the variable read by W4-15b is `PHOTOREVIEW_RS_DIAG_PRELOAD_WORKERS`.
3. **`in_preload_window` vs `is_still_wanted` differ on purpose.** The window test normalizes the direction to +-1 (`direction < 0 ? -1 :
   1`); `IsStillWanted` multiplies by the raw direction. Both use unchecked `int` arithmetic (`wrapping_sub`, `wrapping_mul`,
   `wrapping_add`, `wrapping_neg`); golden cases `difference-wraps*`, `lead-plus-forward-wraps`, `int-min-ahead-negation-wraps`.
   `ahead == 0` is never in the window and never wanted.
4. **Worker limit** (per pass): `active_viewer_decodes > 0` => (`decode_ms_ewma > 200.0` ? 1 : `min(workers, max(2, cpus / 3))`), else
   `workers`. Exactly 200.0 is not slow.
5. **`resume_check_delay(k)`** = `2 s * 2^min(k, 16)` capped at 30 s, computed as .NET does (`TimeSpan * double`: ticks * factor,
   rounded to a whole tick); negative `k` gives fractions (1 s, 0.5 s, 0.25 s). Golden section `resume-check-delay` reports ticks.
6. **`evaluate_resume`** reads in this order and stops early: threshold > 0 and `fill_limit_reached(cache_bytes, threshold)` =>
   `CacheFull` (`cache_bytes` is NOT read when the threshold is <= 0: golden `cache_bytes_reads`); `active_viewer_decodes() > 0` =>
   `NotYet` without probing; probe `has_headroom(max(0, limit - 0.05), reserve)` => `Resume` / `NotYet`. Golden section
   `resume-verdict` records each probe call's `(max, reserve)`.
7. **`fill_limit_reached`** is a DOUBLE comparison (`long >= long * double`): `(cache as f64) >= (threshold as f64) * 0.9`. Do not
   compute it in integers (`cache * 10 >= threshold * 9` differs near `i64::MAX`: golden `max-threshold-*`). Inclusive (`900_000_000`
   of `1_000_000_000` stops).
8. **Headroom cache** (IMG-03): re-probe when never probed, when a decode was queued since the last probe, or when `now - tick > 50`
   (strictly). The run loop sets `decode_queued_since_check` on every dispatch, so a burst never queues past the limit on a stale answer;
   a pass over cached images probes at most once per 50 ms.
9. **`RunQueue::refresh`** (order rebuild) - see the doc comment for the exact order. The order is rebuilt only when the version,
   the shape or the calibration flag changed (C# `Order_IsRebuiltOnlyOnChange`: the centre entry is keyed once per rebuild, by
   `current_box`). `busy_backoff.begin_pass()` runs once per rebuild, BEFORE the box lookup. The calibration flag compared is
   `sizes.mean_bytes(seen_box).is_some()` at the OLD box; after the rebuild `seen_calibrated` is `measured.is_some()` at the NEW box.
   `entries.len()` is passed to `build_preload_order` as `i32` (saturating; a catalog never exceeds `i32::MAX`). The policy line is
   written only when `log.enabled()`; it uses `format_policy_log` (golden section `policy-log`; `.NET bool` => `True`/`False`).
10. **`RunQueue::next`** - see the doc comment for the ten ordered checks. Order matters and is tested:
    cancellation is checked after the candidate is consumed; the caller-thread window test comes BEFORE the headroom probe (C# yields
    before probing); the headroom probe comes before the fill limit, the queued check, the key lookup, the cache lookup and the
    back-off; a cached candidate calls `busy_backoff.record_success(path)` (its busy history no longer applies); a dispatch adds the
    path to `queued` by `pr_core::text::ignore_case_key` (C# `OrdinalIgnoreCase` set). `FillLimitStop` and `Paused` do not reset the
    order; the C# `break` leaves the enumerator where it is.
11. **Pause line**: the memory snapshot is fetched ONLY when the log or the perf trace will use it (C#: `GlobalMemoryStatusEx` is a
    syscall). Perf event: `PhotoReviewPerf::log().preload_paused(load_percent as i32, (available_bytes / (1024 * 1024)) as i64)`, or
    `(-1, -1)` without a snapshot.
12. **`format_f0_invariant`**: .NET Core 3.0+ formats the exact binary value and rounds HALF AWAY FROM ZERO at the requested digit
    (`2.5` => `"3"`, `0.5` => `"1"`, `-0.4` => `"-0"`, `0.49999999999999994` => `"0"`). Rust `format!("{:.0}")` rounds half to even:
    do not use it on ties. Golden section `f0` (17 cases) is the authority. Values above 2^53 print all integer digits (`1e20` =>
    `"100000000000000000000"`).
13. **Log texts** are byte-identical to the C# interpolations (golden sections `policy-log`, `paused-log`, `progress-log`): a missing
    snapshot prints nothing after `availableBytes=` / `loadPercent=`; integers use the invariant form (`-1`, no separators).
14. **`DelegateMemoryProbe`**: `has_headroom(max, _)` calls the delegate with `max`; snapshot is always `(50, 16 GiB)`.

## Traps checklist
§7 items 3 (unchecked `int`/`long`: `wrapping_*` in the window tests; `fill_limit_reached` in `f64`), 4 (.NET "F0" rounding,
`TimeSpan * double` rounding), 8 (`Option<f64>` measured vs `"none"`; `Option<MemorySnapshot>` printing empty), 9 (the key catch arm
covers only I/O; one arm per C# catch), 10 (none: no map order leaks). Specific:
- **INV-1**: the key built here from the scan metadata is only a CANDIDATE key; the identity stored after the decode is re-read by the
  worker (W4-15b semantics 6). Do not add the dispatch key to the warmed-key set here.
- **INV-2**: `queued` is per run; nothing here survives a cache clear (W4-15b clears warmed keys and the busy back-off).
- `Shape::INITIAL` is `(1, 0)`, not `(0, 0)`: a first refresh with shape `(1, 0)` and version `-1` still rebuilds (version differs).
- `seen_version` starts at `-1`; the live version starts at 0 and is incremented before any run starts, so the first refresh always
  rebuilds.
- `current_box` catches only `KeyError::Io` (C# `IOException or UnauthorizedAccessException`); `Other` propagates.
- Lock-free: `RunQueue` never takes the scheduler's locks and never calls `log`/`target`/`probe` while holding anything; it is only
  ever used by one thread at a time (`&mut self`).
