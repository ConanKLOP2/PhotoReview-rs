## Semantics notes
Every behaviour marked **[golden]** is pinned by an oracle case; anything else is a hand-written test.

### Rules (`contracts.rs`) [golden `window-placement-rules`]
1. `normalize_show_command(x) = if x == 3 { 3 } else { 1 }` for every `i32` (0, 1, 2, 7, negatives, `i32::MIN`, `i32::MAX` all give 1). R2-F-26: a minimized/hidden command from a damaged file must not reopen a hidden window.
2. `resolve_show_command(x, restore)`: `Some(Maximized)` -> 3; `Some(Normal)` and `Some(Minimized)` -> 1 (whatever `x` is); `None` -> `normalize_show_command(x)`. R7-10. (C# also has a `_ => Normalize` arm for an undefined enum value such as `(WindowShowState)7`;
   a Rust enum cannot hold it, `WindowShowState::from_i32(7)` is `None`, so that arm has no Rust twin: `// DIVERGENCE: unrepresentable`.)
3. `plan_state_before_show(x)` = `Maximized` iff `normalize_show_command(x) == 3`, else `Normal` (never `Minimized`).
4. `WindowShowState::name()` is the C# `ToString()` text; `from_i32(0..=2)` gives the variants, anything else `None`. `WindowPlacementData` fields are in C# constructor order; the golden uses these snake_case names.

### `ScreenRect` / `MonitorLayout` (`monitor_layout.rs`)
5. `width() = right.wrapping_sub(left)`, `height() = bottom.wrapping_sub(top)` (C# `Right - Left` in an unchecked context; a debug build `-` would panic on `i32::MAX - i32::MIN`). No normalization: an inverted rect has a negative width.
6. `FixedMonitorLayout`: `monitor_of` is `1` for every window; `try_get_work` is `works.first().copied()`; `work_areas` is a clone of the list. (C# `FixedLayout.TryGetWork` indexes `works[0]` and throws on an empty list: the Rust `None` is a deliberate,
   unobservable difference.)

### Visibility (`visibility.rs`) [golden `window-placement-visibility`]
7. Algorithm, with `w = wrapping` everywhere (verified against all 37 cases by a scratch reimplementation before the contract was written; the golden decides if it ever disagrees):
   ```
   if right <= left || bottom <= top { return false }                                   // plain comparisons, no arithmetic
   a = (x: left,  y: top,  w: right.wrapping_sub(left),  h: bottom.wrapping_sub(top))     // Rectangle.FromLTRB
   for each work area k:  b = (x: k.left, y: k.top, w: k.width(), h: k.height())          // Rectangle.FromLTRB(w.Left, w.Top, w.Right, w.Bottom) in the store
       x1 = max(a.x, b.x);  x2 = min(a.x.wrapping_add(a.w), b.x.wrapping_add(b.w))
       y1 = max(a.y, b.y);  y2 = min(a.y.wrapping_add(a.h), b.y.wrapping_add(b.h))
       if x2 >= x1 && y2 >= y1 { iw = x2.wrapping_sub(x1); ih = y2.wrapping_sub(y1); if iw >= 80 && ih >= 80 { return true } }   // Rectangle.Intersect, then Width/Height >= MinVisibleSide
   false
   ```
   The wrapping is observable and golden-pinned: `(i32::MIN, 0, i32::MAX, 100)` against `(0,0,1920,1040)` is visible, `(i32::MIN, i32::MIN, i32::MAX, i32::MAX)` against itself is NOT (the intersection width wraps to -1). Never use `i64`, `checked_*` or saturating maths.
8. The parts of a placement that lie in two different work areas are NOT added: `(1880,100,1960,500)` over two side-by-side 1920-wide monitors is not visible (40 px on each) [golden `straddles-two-monitors-40px-each-not-enough`]. An empty or inverted work area never matches. No work areas: `false`.
9. `JsonWindowPlacementStore::is_visible(data)` = `is_visible(data.normal_left, data.normal_top, data.normal_right, data.normal_bottom, &layout.work_areas())`. Only the NORMAL rect matters; `show_command` does not (a Maximized window saved with an off-screen Normal rect is invisible here but still reopens Maximized, see 14).

### Reader (`placement_store.rs`: `deserialize`, `read_raw`) [golden `window-placement-json`]
The C# reader is `JsonSerializer.Deserialize` with `[JsonSourceGenerationOptions(IncludeFields = true, WriteIndented = true)]`: **default** reader options. It is NOT the lenient dialect of `config.json`
(`pr_core::settings::app_settings::json::parse` allows comments, trailing commas and numbers in strings). The ground truth was observed with a scratch run of the baseline sources over the
golden inputs (not committed, the lead's real run regenerates it); the rules below are what it showed.
10. **Build the reader on `pr_core::settings::app_settings::json::parse`** (depth limit 64, duplicate names kept in file order, BOM/NBSP/form feed/leading zeros/text after the root/empty text rejected, `JsonText = None` for a lone surrogate escape),
    wrapped as follows, in this order:
    a. `strict_precheck(text)`: walk the text once, skipping JSON strings (a backslash consumes the next char). Outside strings: any `/` (a comment) -> `Err(Json)`; a `,` followed by optional JSON whitespace (space, tab, CR, LF) and then `}` or `]`
       (a trailing comma) -> `Err(Json)`. (`json::parse` would accept both; System.Text.Json with default options does not.)
    b. `json::parse(text)`; its `Err` -> `Err(Json)`.
    c. Root `JsonValue::Null` -> `Ok(None)`. Root `Object` -> continue. Any other root (array, number, string, bool) -> `Err(Json)`.
    d. Walk the root entries IN ORDER (do not use `JsonValue::property`, which only sees the last duplicate). An entry whose NAME is `None` (lone surrogate) -> `Err(Json)` (a typed object cannot match such a name), but only for the root and for the three
       position objects below; names inside the VALUE of an unknown property are never inspected (golden `lone-surrogate-escape-in-name-inside-unknown-object` is accepted).
       Names match ORDINALLY and case-sensitively against `Length`, `Flags`, `ShowCommand`, `MinPosition`, `MaxPosition`, `NormalPosition`; everything else (including `length`, `LENGTH`) is ignored.
    e. Int property (`Length`, `Flags`, `ShowCommand`, and `X`/`Y`/`Left`/`Top`/`Right`/`Bottom` inside a position): the value must be `JsonValue::Number` and `json::to_i32` must accept it (integer token only, `-0` is 0, `1.0`, `1e2`, `5E0`, `1e400`, `2147483648`,
       `-2147483649` rejected). A `String` (`"5"`), `Bool`, `Null`, `Array` or `Object` -> `Err(Json)` (do NOT use the string-tolerant branch of `to_i32`).
    f. Position property (`MinPosition`, `MaxPosition`, `NormalPosition`): the value must be an `Object` (a `Null`, array, number or string -> `Err(Json)`); read its entries the same way (own defaults 0, unknown names ignored, lone-surrogate name -> `Err`).
       A repeated position property REPLACES the whole earlier value (it is NOT merged: golden `duplicate-struct-property-replaces-not-merges` gives `normal_right = 3` and `normal_left = 0`).
    g. EVERY occurrence of a typed property is converted, in order: `{"Length":"x","Length":2}` and `{"Length":2,"Length":"x"}` both fail; `{"Length":1,"Length":2}` gives 2 (last valid wins).
    h. Defaults: all fields 0 except `show_command = 3` (`SHOW_MAXIMIZED`) when no `ShowCommand` occurs (`{}` and a file that only has `NormalPosition`). An explicit `"ShowCommand": 0` stays 0 (the reader does not normalize; callers apply the rules).
11. `-0` reads as 0 (System.Text.Json); a plain `serde_json` integer parse would not (D5). `json::to_i32` already handles it.
12. `read_raw(fs, path)`: `Ok(None)` when `!fs.file_exists(Path::new(path))` (missing path, or a DIRECTORY: C# `File.Exists`) [golden `read-raw-missing-file-is-null`, `read-raw-directory-is-null`]; else `fs.read_all_text(..)` (an `io::Error` -> `Err(Io)`) and `deserialize`.
    BOMs: UTF-8, UTF-16 LE and BE all decode (`FileSystem::read_all_text` of `PhysicalFileSystem` uses `decode_text_like_dotnet`) [golden `read-raw-file-*`]. A file that is only a BOM, empty, or whitespace is `Err(Json)` (not `Ok(None)`); the text `null` is `Ok(None)`.
    `// DIVERGENCE:` invalid UTF-8 bytes: C# substitutes U+FFFD and may still parse; `PhysicalFileSystem::read_all_text` is lossy (U+FFFD) the same way, so there is no divergence on disk (only `FakeFileSystem` reports `InvalidData`). Verified against C# d92d6aae. No golden case (the placement file is machine-written).
13. `read(path)`: `read_raw` then filter: any `Err` -> `None` (all four C# exception classes), `Ok(None)` -> `None`, `Ok(Some(d))` -> `Some(d)` only when `is_visible(&d)`. No logging in this unit (the caller that needs the reason calls `read_raw`).

### Prefetch (`placement_store.rs`)
14. `prefetch(path)`: create `Arc<OnceLock<Option<WindowPlacementData>>>`, store `PrefetchSlot { path, outcome }` in the `Mutex` (replacing any earlier slot) BEFORE returning, spawn a named thread (`std::thread::Builder`, name `window-placement-prefetch`)
    that runs `read_raw` and, ONLY when it returned `Ok` (including `Ok(None)`), calls `outcome.set(value)`; the thread returns the same `Option` (an `Err` gives `None`). A failed `Builder::spawn` gives a `PrefetchHandle { handle: None }`: `join` answers `None`, the slot never completes, `take_prefetched` finds nothing and the caller reads the file itself.
    The result is UNFILTERED by visibility: a Maximized window saved with an off-screen Normal rect must still reopen Maximized (golden-independent test `Prefetch_IsUnfilteredAndTakenOnceForTheSamePath`).
15. `take_prefetched(path)`: lock; no slot, or the slot's path is not `eq_ignore_case(path)` (`pr_core::text::eq_ignore_case`, OrdinalIgnoreCase, never `to_lowercase`) -> `None` and the slot is LEFT in place. Same path (`path.to_uppercase()` matches) -> `take()` the slot (consumed) and return
    `outcome.get().cloned().flatten()`: a finished successful read gives its value, a read that has NOT finished or FAILED gives `None` (never blocks; C# `TryGet` is non-blocking although its comment says "blocking"). A second call gives `None`.
16. `PrefetchHandle::join` joins the thread; a panicked thread gives `None`. Do not `unwrap`/`expect` anything on the path (AGENTS.md: no panics on user-data paths).

### Writer (`placement_store.rs`: `serialize`, `save`, `write_atomically`) [golden `window-placement-json`, kind `serialize`]
17. `serialize` writes, byte for byte (C# `WriteIndented`, `Environment.NewLine` on Windows):
    `{` CRLF, `  "Length": 44,` CRLF, `  "Flags": 2,` CRLF, `  "ShowCommand": 3,` CRLF, `  "MinPosition": {` CRLF, `    "X": -1,` CRLF, `    "Y": -2` CRLF, `  },` CRLF, `  "MaxPosition": {` ... `  },` CRLF, `  "NormalPosition": {` CRLF, four lines
    `Left`, `Top`, `Right`, `Bottom` (commas on all but the last) CRLF, `  }` CRLF, `}` with NO trailing newline. Integers are plain decimal (`-2147483648` ok). Use `\r\n` explicitly, not `\n` (D9: byte-identical wins; the C# test normalizes only for portability).
    Hand-write it with `format!`; do not add a serde derive (property names and order are the on-disk format, N-3).
18. `save(path, data)`: `get_directory_name(path)` (`pr_core::text::dotnet_path`): `None` (blank or a root) or `Some("")` (a bare file name) -> `Err(io::ErrorKind::InvalidInput)` (C# `Directory.CreateDirectory(Path.GetDirectoryName(path)!)` throws `ArgumentNullException`/`ArgumentException`).
    Otherwise `fs.create_directory(dir)?` then `write_atomically(fs, path, &serialize(data))`.
19. `write_atomically` = `fs.write_all_text_atomic(Path::new(path), content, false)`: that is the C# algorithm already ported in `PhysicalFileSystem` (temp name `<path>.<guid N>.tmp` so two windows saving one file never share a temp name, `File.Move(overwrite)`, temp deleted
    on ANY failure including the write itself, original error re-thrown). Do not re-implement it, and do not use the legacy shared `<path>.tmp` name. The injectable `writeText` hook of C# is replaced by `FakeFileSystem::fail`/`HookFileSystem` in the tests.
20. R0002: this module has no path constants. The composition root passes `AppPaths::window_placement_file` (already `%LOCALAPPDATA%\PhotoReviewRs\window-placement.json`, per-folder mode variants are the caller's business). There is no import of the C# app's file.

## Traps (docs/MULTI-AGENT-PLAN.md section 7)
- Item 3 (`int` is `i32`, unchecked arithmetic): notes 5 and 7; every `-`/`+` on rect coordinates is `wrapping_*`.
- Item 1 (OrdinalIgnoreCase): the prefetch path compare (note 15) uses `pr_core::text::eq_ignore_case`.
- Item 6 (JSON): names case-sensitive, missing -> default (ShowCommand 3), unknown skipped, last duplicate wins BUT every duplicate must convert, duplicate struct replaces, strict dialect (notes 10-11). Do not use `serde_json::from_str` into a derived struct: it rejects
  duplicate fields, accepts `1.0` for ints in some modes, reads `-0` as a float, has a 128 depth limit, and cannot represent the lone-surrogate rules.
- Item 9 (exception -> `Result`): C# catches `IOException | UnauthorizedAccessException | JsonException | NotSupportedException` in `Read` and `Prefetch` and nothing in `ReadRaw`/`Save`: `read_raw`/`save` return `Err`, `read`/`prefetch` swallow it (notes 13, 14).
- Item 8 (null vs empty): `Ok(None)` (missing file, `null` document) is NOT `Err` (damaged); empty or whitespace text is `Err`.
- Item 10 (order): `work_areas` order is the enumeration order and is not sorted anywhere.
- Data safety: `save` replaces the user's file atomically through a unique temp name and never leaves the temp behind; the unit never deletes anything else. No Recycle Bin code. A corrupt or off-screen placement file is IGNORED, never deleted or "repaired" by this unit.
- Concurrency: the prefetch slot is the only shared state (`Mutex` + `OnceLock`); `take_prefetched` must not hold the lock while reading the cell for long (it only clones a small `Copy` struct). No `static` state (C# keeps the state in the instance, "the app holds one shared instance").

## Test-double caveat (verified in `pr-test-support`)
`FakeFileSystem::write_all_text_atomic` inserts the file in one step: it never creates a `<path>.<guid>.tmp`, and its `read_all_text` decodes UTF-8 only (a UTF-8 BOM is stripped, UTF-16 yields `InvalidData`). Consequences: `Save_CreatesDirectory_LeavesNoTempFile` and
`WriteAtomically_TempWriteFailsMidway_LeavesNoTempFile` on the fake are weak (they pass for any implementation that delegates to `write_all_text_atomic` and propagates the error); the real guards for "unique temp name, temp removed on failure" are the `PhysicalFileSystem` twins above.
`FakeFileSystem::fail(FsOp::WriteAtomic, ..)` is the failure injector for the error-propagation test.

## Open questions
1. **Owner of `Win32MonitorLayout`** (native `EnumDisplayMonitors`/`GetMonitorInfoW`/`MonitorFromWindow`). Recommended: W8-13k (real `WindowOps`) in `pr_platform_win`, with `FixedMonitorLayout` for every pure test. Alternative: W8-11b (`win32::api`) so 13k only consumes it. Not blocking 03a/03b.
2. **Prefetch thread vs "the existing worker pool" (D-W8-2).** `pr_core` has no general worker pool; a plain named `std::thread` per prefetch (one per app start) is the smallest faithful port of `Task.Run`. Alternative: a `UiDispatcher`/pool trait from W8-13d, which does not exist yet. Recommended: the thread.
3. **Strict-JSON wrapper vs a new `json::parse_strict` in `app_settings.rs`.** The recommendation (note 10) keeps this unit inside its owned files by pre-checking comments and trailing commas and then reusing `json::parse`. If the lead prefers one strict entry point, add `parse_strict` to `app_settings::json` (lead-owned, W2-01) and delete the precheck here; the golden is unaffected.
4. **`FullscreenControl` method shape.** C# `IFullscreenController` is `Enter(nint, WindowShowState)` / `Exit(nint)` plus two getters; W8-03b's `FullscreenController` also has `EnterNeedsMaximizedState`/`ExitNeedsStateRestore`, which are NOT on the interface and stay on the struct. If 03b prefers `&self` with interior mutability, change the trait before 03b starts.
5. **Invalid UTF-8 placement file** (`// DIVERGENCE`, note 12): Rust reports an I/O error where C# may still parse. Accepted (machine-written file, one unreadable run falls back to the default window placement either way).
