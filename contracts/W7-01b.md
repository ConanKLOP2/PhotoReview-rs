   Row 30 is built with the full constructor, not `P(...)`: `disk_cache = false`, `detailed_logging = false`, **`warmup_count = 0`, `iterations = 3`,

   The `P` helper's argument order is `(id, name, desc, mode, workers, next, previous, full, workload)`: do not swap `next`/`previous` (rows 3, 7, 11, 18 are
   easy to flip) or `workers`/`next`. The golden `registry` case compares all 15 fields of all 30 rows.
2. **`disk_cache` is `false` for every built-in profile** (`P` passes a literal `false`; `BenchmarkImageExecutorTeardownTests` overrides it with `with`). Do not
   derive it from `full_folder`.
3. **`find`**: `OrdinalIgnoreCase` via `pr_core::text::eq_ignore_case` (never `to_lowercase`/`eq_ignore_ascii_case`): `FAST-SEQUENTIAL` matches,
   `fast-sequent\u0131al` (dotless i), `fast-sequent\u0130al` (dotted capital I), `\u017fsd-throughput` (long s) and `rapid-\u212aey-press` (Kelvin sign) are
   decided by the generated .NET ordinal table, the golden holds the answers. No trimming (`" fast-sequential"` is `None`), `""` is `None`. First match wins; the
   returned reference is the registry's own element (`std::ptr::eq` with `&all()[i]`, golden `same_instance_twice`).
4. **`is_not_implemented`** is `workload == Correctness && id in {"explorer-reindex", "cache-recovery"}`. C# writes
   `profile.Workload == Correctness && profile.Id is "explorer-reindex" or "cache-recovery"`; the pattern `is A or B` binds tighter than `&&`, so it is
   `Correctness && (A || B)`. Do not transcribe it as `(Correctness && A) || B`: the golden `not_implemented` cases (`cache-recovery` with workload `Sequential`
   must be `false`) fail then. The id comparison is ordinal and case-sensitive (`CACHE-RECOVERY` + Correctness is `false`). It judges the argument it is given, so a
   modified copy is judged by its own fields.
5. **`runnable`** = `all()` filtered by `!correctness_only && !is_not_implemented(p)`: 30 - `original-correctness` - `cache-recovery` - `explorer-reindex` = 27 profiles,
   same order, includes `recommended-auto`, the 4 `action-*` profiles and `random-navigation`. Build it once (`OnceLock<Vec<BenchmarkProfile>>`, clones);
   `runnable()` need not return the same instances as `all()` (nothing compares identity across the two lists; C# does, but no caller relies on it).
6. **Statics**: `static ALL: OnceLock<Vec<BenchmarkProfile>>`. No `lazy_static`/`once_cell` crates (std `OnceLock`). No mutation after construction.
   The 2 GiB reserve is `pr_core::settings::perf_options::MEMORY_RESERVE_BYTES` (C# `PerformanceOptions.MemoryReserveBytes`), not a second literal.

### Metrics
7. **Scalars**: `current.x - baseline.x` with `wrapping_sub` (C# default `unchecked` `long` arithmetic; the golden `int64-wraps-like-unchecked-csharp` has
   `i64::MIN - 1`). A debug-build `-` would panic. No clamping: negative deltas stay negative (`negative-deltas-are-kept`). The 15 scalar fields are
   `cache_hits, cache_misses, source_bytes_read, source_reads, decode_milliseconds, presented_images, present_milliseconds, preload_hits, inflight_joins,
   disk_cache_hits, ui_assign_milliseconds, source_open_count, stat_count, session_write_count, cross_thread_present_count`. Every field of
   `ReviewMetricsSnapshot` is set (build the result with a full struct literal, no `..Default::default()`, so a new field breaks the build).
8. **`decoder_fallbacks`**: iterate the CURRENT list in its order; `delta = count.wrapping_sub(baseline count for that backend, 0 when absent)`; push only when
   `delta > 0`. Baseline-only backends are ignored. The result keeps the current order (not value order: golden `fallbacks-keep-current-order-not-value-order`).
   A backend repeated inside one list is out of contract (C# dictionaries cannot hold it); take the first baseline entry and do not special-case.
9. **`top_source_opens`**: build a map from the BASELINE entries keyed by `ignore_case_key(path)` -> count; a second baseline entry with the same key returns
   `Err(DuplicateSourceOpenPath(path))` (C# `ToDictionary(.., OrdinalIgnoreCase)` throws `ArgumentException`; this happens even when `current` is empty and
   BEFORE the result is built). Then for each CURRENT entry (all of them: current is NOT truncated to 10) compute `count.wrapping_sub(map.get(key) or 0)`, keep
   entries with `> 0`, and stable-sort by `count` descending, then `cmp_ignore_case(path)` ascending (`sort_by`, never `sort_unstable_by`). The path text of a
   kept entry is the CURRENT spelling. Two current entries that differ only in case both subtract the SAME baseline count (golden
   `opens-current-case-variants-share-one-baseline-count`) and, if still tied, keep input order (`opens-ties-same-path-other-case-keep-input-order`).
   The tie order is OrdinalIgnoreCase, i.e. compare ordinal-UPPERCASED code points: `aB` sorts before `a_1` (`B` 66 < `_` 95) although lowercase compare would flip them
   (golden `opens-ties-ordered-by-path-ignore-case-not-ordinal`). Use `pr_core::text::cmp_ignore_case`; never `to_lowercase`.
10. **`present_histogram`**: baseline map keyed by label, ORDINAL (case-sensitive: `HashMap<&str, i64>`); a repeated baseline label returns
    `Err(DuplicatePresentBucketLabel(label))`; labels differing only in case do not collide. Result = current buckets in current order, each
    `count.wrapping_sub(baseline or 0)`; NOTHING is filtered (zero and negative stay). The duplicate check order is: source opens first, then buckets
    (matters only for which error a doubly broken baseline reports; the golden covers one at a time).
11. **Why `Result`**: C# throws `ArgumentException` from `ToDictionary` (and `ArgumentNullException` for null arguments, which Rust references cannot be). The
    engine's snapshots come from `ReviewMetrics::snapshot()`, whose keys are unique, so W7-03 can treat `Err` as unreachable (`expect` is NOT allowed on
    user-data paths but this is internal metrics: map it to a failed phase with the error text, like any other engine error). Do not turn it into a panic or a
    silent fallback inside `since`.
12. **No clock, no I/O, no logging** in either file.
- Traps checklist (docs/MULTI-AGENT-PLAN.md §7): item 1 (OrdinalIgnoreCase through `pr_core::text`), item 3 (`long` is `i64`, wrapping arithmetic), item 10
  (stable ordering; no `HashMap` iteration order may leak: iterate the `Vec`s, use maps only for lookups), plus the operator-precedence trap in note 4.

## Open questions
1. **`BenchmarkProfile` field names (W7-01a).** This stub assumes the snake_case mirror of the C# record shown above. If 01a's contract differs (for example
   `loading_mode` named `mode`), only the table code and tests of this unit change. Lead: pick one when merging 01a/01b contracts.
2. **`since` returns `Result`** (recommended) because C# can throw from `ToDictionary` on a duplicate baseline key. Alternative: return the snapshot and panic or
   ignore duplicates (last wins), which diverges from C# on a case that real snapshots never produce. Kept as `Result` so the golden can pin the C# behaviour.
3. **`runnable()` instances.** C# `Runnable` holds the same objects as `All`; here it is a second `Vec` of clones (profiles are small plain data). Alternative:
   `Vec<&'static BenchmarkProfile>`, which changes the signature W7-03's CLI would consume. Not worth it unless 01a makes `BenchmarkProfile` non-`Clone`.
4. **`BenchmarkProfileExtensions.TargetWidth`** (`preview-light` 960, `preview-balanced` 1600, `preview-quality` 2400, `preview-high-quality` 3200,
   `original-correctness` 0, else 1920) keys off profile ids but lives in `BenchmarkModels.cs`: assigned to W7-01a. Its golden needs this registry; 01a's tests
   may call `profiles::all()` once this unit is merged.
