- Semantics notes (read the C# next to them; every number below is a boundary the C# mutation tests pin):
  1. **Source borrow discipline.** `RawHeaderSource::read(&mut self, offset: i64, count: i32) -> Result<&[u8], RawHeaderError>` returns a slice that is
     valid only until the next `read` (same as the C# span). Read `let len = source.length();` ONCE at the top (a live slice blocks `length()`),
     decode everything you need from the slice into locals/`Vec`, and only then call `read` again. The C# call sequence must be kept exactly,
     because the golden `fail_after` cases and the 64 KiB-block budget accounting of the real source depend on it:
     `read_ifd_entries` = count read (2 bytes), entries read (`clamped * 12` bytes, issued even when it is 0 bytes), next-pointer read (4 bytes);
     `read_tag_unsigned` = at most one read, none for an inline value; `read_tag_unsigned_array` = at most one read; `has_square_default_scale` =
     one 16-byte read; `starts_with_soi` = one 2-byte read, none when the range check fails.
  2. **`read_ifd_entries`** (arithmetic in `i64`):
     - Guard: `ifd_offset < 8 || ifd_offset > len - 2` => empty result, `next_ifd_offset = 0`. Then read 2 bytes; fewer than 2 => empty.
     - `entry_count = read_u16(..)` (a `u16`), `clamped = min(entry_count, MAX_ENTRIES_PER_IFD = 4096)`, `bytes_needed = clamped * 12`.
       If `ifd_offset + 2 + bytes_needed > len`: `clamped = (len - ifd_offset - 2) / 12`; `clamped <= 0` => return empty (next 0); else recompute
       `bytes_needed`. Whole entries only: 5 stray bytes after 3 entries are ignored.
     - Entries: loop `i in 0..clamped`, `off = i * 12`, stop if `off + 12 > span.len()`. `tag`/`type` via `u16`, `count`/`value` via `u32` in the file's
       byte order (`pr_imaging::tiff::read_u16/read_u32` take an `i32` offset: `off` is at most 4095 * 12 + 8, safe).
     - Next pointer: ONLY when `entry_count <= 4096` (compare the DECLARED count, not `clamped`): a count of 4097 reads 4096 entries and ends the chain
       (golden `ifd-count-4097-ends-chain`, `ifd-count-65535-ends-chain`). `pos = ifd_offset + 2 + entry_count * 12`; when `pos + 4 <= len` read 4 bytes
       (a short read => no pointer); `next` is reported only when `next >= 8 && next <= len - 6` (room for an empty IFD: count + pointer = 6 bytes),
       else `0`. Boundary rows: with `len = 26`, pointer 20 is kept, 21 is `0`, 7 is `0`, 8 is kept.
     - An IFD with 0 entries still reads its next pointer (golden `ifd-zero-entries-reads-next`).
  3. **`read_tag_unsigned`**: `size = type_size(field_type)`; `size == 0 || count == 0` => `Ok(None)`. `i64::from(size) * i64::from(count) <= 4` (a
     `u32` count times a size does not fit `u32`: widen first; C# gets `long` from `int * uint`) => the value is INLINE: build the 4 bytes of
     `value_or_offset` in the file's byte order (`to_le_bytes` / `to_be_bytes`) and `read_unsigned(&buf, type, le)` (first element). Otherwise out of
     line: `offset = i64::from(value_or_offset)`; `offset + size > len` => `Ok(None)` (offset 0 is legal and reads the header; `offset = len - size`
     is the last legal one: golden `unsigned-out-of-line-offset-28/29`); read `size` bytes, `read_unsigned`. Types without an unsigned reading
     (RATIONAL 5, ASCII 2, SBYTE 6, UNDEFINED 7, SRATIONAL 10, FLOAT 11, DOUBLE 12) give `Ok(None)` after the read (IFD 13 reads as LONG; sizes come from
     `pr_imaging::tiff::type_size`: 1/2/6/7 = 1, 3/8 = 2, 4/9/11/13 = 4, 5/10/12 = 8, else 0, so BigTIFF 16 and 255 are unknown => `Ok(None)`); signed types 8 and 9 give negative
     numbers (SSHORT/SLONG are sign-extended by `read_unsigned`), which every caller then rejects through `is_range_in_file` or `> 0` tests.
  4. **`read_tag_unsigned_array`**: `size == 0 || count == 0` => empty, `max_items <= 0` => empty. `n = min(count, max_items as u32)` computed in
     `u32` (never narrow `count` to `i32`: `0xFFFF_FFFF` goes negative; this is the C# regression `CountAboveInt32Max`). `total = size * count` in `i64`
     (UNCLAMPED count, as C#): `total <= 4` => inline buffer (4 bytes in file order), items at `i * size`; each item through `read_array_item`.
     Out of line: `offset + n * size > len` => empty (`n * size` in `i64`; C# computes it in `int`, which wraps for `max_items` near `i32::MAX` with
     a huge count and then throws `ArgumentOutOfRange`; no caller passes more than 64, so the Rust port simply never overflows. Document with
     `// DIVERGENCE:` and keep the Rust-only test), else one read of `n * size` bytes and the same item loop (the `(i + 1) * size > span.len()` break
     is dead code but keep it). `read` takes an `i32` count: convert `n * size` with `i32::try_from(..)` and return `Ok(Vec::new())` when it does not
     fit (only reachable with a file over 2 GiB and an absurd `max_items`; same `// DIVERGENCE:` comment). Items: RATIONAL (5): needs 8 bytes, `den == 0` => skipped (NOT added, so the list gets shorter), else
     `(f64::from(num) / f64::from(den)).round()` cast to `i64` (`f64::round` is half away from zero = `MidpointRounding.AwayFromZero`; do NOT use
     banker's rounding, trap §7 item 4; goldens `array-rational-rounds-*`, `array-rational-half-away-*`: 5/2 = 3, 31041/10 = 3104). Any other type:
     `read_unsigned` of the item; `None` items are skipped (SRATIONAL, FLOAT, ASCII give an empty list).
  5. **`compute_exif_block`**: result is always `ExifBlock::new(0, length, true)` (`ifd_is_exif: false`; the golden `exif-block` compares all four fields).
     `length = min(len, DEFAULT_EXIF_BLOCK_BYTES = 128 KiB)`. Inside a closure that returns `Result`: `needed = exif_summary_extent(ifd0_offset, IFD0_TAGS)`;
     when the 0x8769 pointer it reported is `> 0`: `needed = max(needed, exif_summary_extent(pointer, EXIF_TAGS))`; then, ONLY when
     `needed <= min(len, MAX_EXIF_BLOCK_BYTES = 4 MiB)`, `length = max(length, needed)` (a block clamped below `needed` still cannot hold the structure,
     so it keeps the default; golden `exifblock-extent-exactly-4mib` grows, `...-one-past-4mib` does not). Error handling is the point of this function:
     an `Err(e)` from ANY read inside the closure with `!e.is_io_failure()` keeps the DEFAULT `length` even when the first extent had succeeded (apply
     `length` only after the whole closure returned `Ok`; golden `exifblock-fail-data-after-ifd0-ok-keeps-default`); an I/O failure propagates
     (`exifblock-fail-io-*`). Do not swallow with `.ok()` and do not map every error to the default (trap §7 item 9).
     `exif_summary_extent(ifd, wanted)`: `entries = read_ifd_entries(ifd)`; none => `0` and pointer `0`; `end = ifd + 2 + entries.len() * 12 + 4`
     (entries actually returned, not the declared count); for each entry: tag `0x8769` records `exif_pointer = value_or_offset` (even though it is not in
     the Exif list, and also while scanning the Exif IFD, where the result is discarded); tags not in `wanted` are skipped; `bytes = i64::from(type_size) *
     i64::from(count)`; `bytes > 4` => `end = max(end, i64::from(value_or_offset) + bytes)` (an inline value must NOT stretch the block:
     `exifblock-four-byte-inline-make`; type size 0 adds nothing). IFD0 tags: `0x010F 0x0110 0x0132 0x8769`; Exif tags:
     `0x829A 0x829D 0x8827 0x9003 0x9004 0x920A 0xA434` (copy the two lists as `const` arrays; a mutant that drops one is killed by a test per tag).
  6. **`is_range_in_file`**: `offset > 0 && length > 0 && offset <= file_length - length`. Use `file_length.saturating_sub(length)` (length is `> 0` at that
     point, so C# cannot overflow; `saturating_sub` is only the panic-proof spelling). Offset 0 is never a payload start.
  7. **`try_read_single_strip`**: both tags 0x0111 and 0x0117 must exist (FIRST entry of each), both `count == 1` (checked BEFORE any read), then both values
     through `read_tag_unsigned` (offset first, then length; either `None` => `None`, and a `None` offset means the length value is NOT read: C# `||`
     short-circuit, it changes the read sequence seen by the `fail_after` goldens), then `is_range_in_file(strip, bytes, len)`.
  8. **`try_read_exif_pixel_dimensions`**: `read_ifd_entries(offset)`; for each entry `if tag == 0xA002 && value in 1..=i32::MAX {width = value} else if
     tag == 0xA003 && value in 1..=i32::MAX {height = value}` (the C# `else if` is evaluated per entry; an invalid 0xA002 does not touch a previous valid one;
     the last valid duplicate wins). Both found => `Some`, otherwise `None` (a width-only IFD must not leak a half-set size).
  9. **`try_read_default_crop_size`**: entry 0xC620; `read_tag_unsigned_array(.., max_items = 2)`; `len < 2` or either value `<= 0` or `> i32::MAX` => `None`.
     RATIONAL crops are rounded (note 4); LONG, SHORT inline and RATIONAL out of line all work (goldens `crop-*`).
  10. **`has_square_default_scale`**: entry 0xC61E absent => `true`. Present: `field_type != 5 || count < 2 || value_or_offset < 8 || value_or_offset > len - 16`
      => `false` (an unreadable DefaultScale is NOT square), one 16-byte read, a returned slice shorter than 16 bytes => `false` (cannot happen with a conforming source); any of the four words `== 0` => `false`; else
      `u64(hn) * u64(vd) == u64(vn) * u64(hd)` (cross product in `u64`, golden `scale-ratio-4294967295-...`). `count == 3` is accepted.
  11. **`choose_active_sensor_size`**: `fits(w, h) = w > 0 && h > 0 && (raw_w <= 0 || raw_h <= 0 || (w <= raw_w && h <= raw_h))`; crop first, then Exif,
      else the raw size unchanged (even when it is `(0, 0)` or negative). Pure; the 12 + 24 table rows pin each `<=`.
  12. **`reconcile_jpeg_size`**: returns immediately (no read, `read_frame` NOT called) unless `*width > 0 && *height > 0`. Otherwise
      `match read_frame(source, offset, length)`: `Ok(Some((w, h)))` => assign both; `Ok(None)` => untouched; `Err(e) if !e.is_io_failure()` => untouched,
      `Ok(())`; `Err(e)` (I/O failure) => `Err(e)`. The extra `read_frame` parameter is the one deliberate signature change from C# (open question 1):
      it keeps W5-02a free of W5-11 (the `RawContainerReaderRegistry` in W5-11 lists the readers that call this function). Readers pass
      `|s, o, l| Ok(preview_selector::try_read_jpeg_frame(s, o, l)?.map(|f| (f.width, f.height)))` (or whatever W5-11 exposes).
  13. **Small ones.** `read_tag_value`: first entry with the tag, `read_tag_unsigned`. `read_image_size`: tags 0x0100/0x0101 through `read_tag_value`
      + `clamp_to_int`; a signed negative gives 0. `clamp_to_int(v)`: `Some(x) if x > 0 => min(x, i32::MAX as i64) as i32`, else 0 (`as` after `min` is
      safe; clippy `cast_possible_truncation` is pedantic, not enabled). `try_read_jpeg_interchange`: 0x0201 (offset) then 0x0202 (length), both
      `read_tag_value` (`None` => `None`), `is_range_in_file` AND `starts_with_soi` (in that order: a bad range reads nothing, golden
      `interchange-fail-not-reached-bad-range`). `starts_with_soi`: `length >= 4 && is_range_in_file(offset, length, len)`, then the 2 bytes are exactly
      `[0xFF, 0xD8]`. `try_get_entry`: first match, returns a copy.
  14. **Errors vs the 8 MiB header budget.** All reads go through the budgeted source, so this file never needs its own limits beyond the constants
      above. Every `?` on a `read` is intentional (C# lets `InvalidDataException` escape everywhere except `compute_exif_block`,
      `reconcile_jpeg_size`). Do not add a `catch`-equivalent anywhere else.

## Open questions
1. **`reconcile_jpeg_size` takes the frame walker as a parameter** (recommended, used by the stub). Alternative: keep the C# signature and call
   `crate::preview_selector::try_read_jpeg_frame` directly; then W5-02a depends on W5-11, W5-11 (registry) depends on W5-03..W5-08, and those depend on
   W5-02a: a unit-level cycle that P-28 scheduling cannot start. The other contract writers (W5-03..W5-08) must call it with a closure.
2. **Where do the shared TEST builders live?** (`TiffBytes`, `create_minimal_jpeg`, `build_tiff`, the fuzz `mutants`; `InMemoryRawHeaderSource` is settled:
   production crate, W5-01b.) The W5 drafts disagree: `crates/pr-imaging-raw/tests/common/mod.rs` owned by W5-02 (W5-01b Q3, W5-04, W5-06, W5-07), a lead-owned
   `tests/support/` (W5-03), or `pr_test_support` (W5-05). W5-02a's tests are written as `mod common;` + `use common::TiffBytes` (rename in one line). If the lead
   hands W5-02a the owner role, its Owned files grow by `tests/common/{mod.rs,tiff_bytes.rs,synthetic.rs,fuzz.rs}` and its C# twin `SyntheticRawBuilder_RoundTripsMinimalContainers`
   joins the test list; W4 precedent: `crates/pr-imaging/tests/common`.
3. **`read` takes `&mut self`.** Chosen because the returned slice borrows the source's shared buffer (C# span lifetime). If W5-01 prefers `&self` + interior
   mutability this changes only the parameter types (see the table above).
4. **Rust-only strictness** in `read_tag_unsigned_array` for `max_items` near `i32::MAX` (C# would overflow `int` and throw `ArgumentOutOfRange`, a bug no caller reaches).
   Recommended: do not reproduce, record as `// DIVERGENCE:` plus the Rust-only test. No ADR needed (unreachable, D5 precedent).
5. **Doc drift:** `MULTI-AGENT-PLAN.md` section 3 still lists W5-02 as one unit (`TiffHeaderNavigator` + `JpegMarkerProbe`); the lead updates the row to W5-02a / W5-02b at wiring.
