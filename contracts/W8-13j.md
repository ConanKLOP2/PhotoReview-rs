## Semantics (C# is the spec)
### Image arrives (C# 96-139; the ORDER is behaviour)
1. The view model's call returns a `ChangeSet` with `image_changing: Some(args)` when the presenter replaced the bitmap for ANOTHER file. `apply_changes` (13h) calls `on_image_changing(args.is_file_change)` FIRST, synchronously, before any image is handled, so the last presented frame is still the composer's `last_drawn` and can freeze for the fade: nothing (disposed, no composer, `!is_file_change`) -> return; `settings.image_transition == ImageTransition::None` -> return; else `composer.begin_crossfade(Duration::from_millis(clamp(settings.image_transition_ms, MIN_IMAGE_TRANSITION_MS, MAX_IMAGE_TRANSITION_MS)))` (the `i32` constants 40 and 400 of `pr_core::settings::app_settings`); an `Err` is logged.
2. The hub's `ImageChanged` handler ran inside the view-model call (the sink replay) and queued a `PendingImage { buffer: image.as_pixels().cloned(), is_file_change }` (`on_hub_image_changed`; an opaque platform image is `None`, as C# `image as PixelBuffer`). It also posted a Render-priority safety-net job running `drain_pending_images`.
3. `apply_changes` calls `drain_pending_images()`: for each queued item, FIFO, `handle_image_changed(buffer, is_file_change)`:
   - no composer -> `image = buffer`; else `replace = composer.set_incoming(buffer, is_file_change, DEFER_UPLOAD_BYTES)` (`Err` logged, counts `false`); `replace` -> `image = composer.current()`; then `update_retained()`;
   - `viewport.invalidate_layout()`; `window.invalidate()`;
   - `image.is_some() && !disposed && !first_image_drawn` -> `render_now()` IN THIS CALL (the first-image mark must not wait for a frame tick; test `FirstImage_IsDrawnInTheSameTurn...`).
   Why the queue (D-W8B4M-7): the hub calls the handler while `MainViewModel` is mutably borrowed (the sink replay is inside `pump`/a command); `render_now` reads the view model (`compare`, `viewer`) and would panic with `BorrowError`. The queue moves the work to the first point where no borrow is held, still in the same UI turn.
### Composer and prefetcher lifetime
`attach_viewing` (from `attach_renderer`, 13g): needs the cache; builds `PresentationComposer::new(cache.clone() as Rc<dyn PrefetchStatus>, frame_clock, invalidate = window.invalidate, schedule_on_ui = poster.post_after, ComposerOptions::default())` and `PresentationPrefetcher::new(cache.clone() as Rc<dyn PrefetchCache>, Rc::new(MainWindowPrefetchHost { window: weak }))`, then `attach_viewing_with`: store, subscribe `CurrentChanged`/`PlanChanged` with `Weak` closures (ids kept), and `composer.set(image.clone())` when `image` is some and not disposed (a bitmap that arrived before the renderer existed). `dispose_viewing` (called from `release_renderer`, 13h): drop the cache-cleared subscription, unsubscribe both, `composer.dispose()`, drop both, clear the pending queue; idempotent.
`on_composer_current_changed`: `image = composer.current()`; `viewport.invalidate_layout()`; `update_retained()`. `on_compare_changed`: not disposed -> `update_retained()`; `window.invalidate()`. `on_navigation_changed`: not disposed, prefetcher present -> `prefetcher.navigated(vm.current_index(), vm.total_files() as i32)`. `on_prefetch_plan_changed`: `update_retained()`.
### Retain and clear (INV-1/INV-2)
`update_retained`: needs cache AND composer; `ids = BTreeSet::new()`; `composer.collect_retained_ids(&mut ids)`; add `prefetcher.planned_ids()`; if `vm.compare().is_visible()`: add `left.id()` and `right.id()` of the compare images that are `PlatformImage::Pixels` and not disposed (short borrow, ids copied out); `cache.retain(&ids.into_iter().collect::<Vec<_>>())` (an `Err` logged). GPU bitmaps are keyed by `PixelBuffer::id()`, never by path.
`clear_gpu_cache` (posted at default priority by the cache-cleared listener, which runs on whatever thread called `clear_cache` and is `Send + Sync`: it only calls `post_to_window(dispatcher, id, UiPriority::Normal, clear_gpu_cache)`): not disposed -> `gpu_cache_clear_count += 1`; `cache.clear()`; `composer.cancel_crossfade()`; `window.invalidate()`. The current image is still in RAM (its `PixelBuffer`) and uploads again at the next frame, without a flash because that frame draws the same image; an old crossfade layer (whose buffer left the RAM cache) stops.
### Drawing (C# 229-261) and compare hit-testing
`draw_presentation(context)`: no composer -> return. `viewer = vm.viewer().borrow()` (copy `effective_scaling_quality()`, `scaling_quality()`); `origin = viewport.image_origin()`; `destination = RectD { x: origin.x, y: origin.y, width: viewport.image_actual_width(), height: viewport.image_actual_height() }`; `compare = vm.compare()` (short borrow; copy visibility, the two images' pixel `Arc`s, the two selection flags); `viewport = window.client_size_dip()` converted to `pr_app`'s `SizeD`; `dpi_scale = window.dpi_scale()`. `frame = composer.draw(context, &inputs)`; an `Err` is logged and the frame goes on (the C# exception was a `COMException` caught by `Present`; in Rust the composer reports the error after it popped its clips, so the frame can still end). Then: `frame.main_drawn && Arc::ptr_eq(composer.current(), hub.current_image() pixels)` -> `image_drawn_in_frame = true`; else `frame.compare_images > 0` -> `true` ("the frame contains the image the presenter just assigned": during an upgrade upload the frame has the OLD image and does not count for the new image's mark).
`try_select_compare_at(point)`: disposed or compare not visible -> `false`; `CompareLayout::hit_test(client_size_dip, point)` (16b, DIP, origin top-left): `Left` -> select the left cell, `Right` -> the right, `true`; anything else (margin outside the panel) `false`. The selection is a view-model mutation: it goes through `update_view_model` so its `ChangeSet` (compare) fans out. **Gap**: `MainViewModel` has no public selector (`compare_mut_for_tests` is test-only); Open question 4.
### The prefetch host (C# 288-335), thread rules
`path_at`, `start_lookup`, `schedule_retry` are called on the UI thread by the prefetcher (16d reshaped C#'s `RunBackground`/`PostToUi` into requests the host runs). `path_at(i)`: `Some(vm.borrow().catalog().path_at(i as usize).to_owned())` when `0 <= i < catalog.len()` (`ReviewCatalog::path_at(usize) -> &str` panics outside the range, so the range test comes first), else `None`. `start_lookup(request)`: clone `vm.preview_service()` (an `Arc`), move `request` and the `Arc` to a worker thread (a plain `std::thread::spawn` named `prefetch-lookup`, or the `BackgroundRunner` of the composition root; never the UI thread); per path `service.try_get_cached_preview_path(path)` (ANY key error is a quiet miss, `None`, the Rust service already folds the C# `catch (IOException or UnauthorizedAccessException or ObjectDisposedException)`), result `Vec<Option<Arc<PixelBuffer>>>` from `PlatformImage::as_pixels`; then `post_to_window(dispatcher, id, UiPriority::Background, ..)` of a `Send` job that moves the `Vec` and calls `prefetcher.apply_lookup(generation, &found)` on the UI thread, skipped when the window is gone or disposed (`with_window`). The job must carry `Arc<PixelBuffer>` (it is `Send + Sync`), never an `Rc`. `schedule_retry(delay, request)`: `poster.post_after(delay, UiPriority::Background, job)` where the job runs `prefetcher.run_retry(request)` if the window is alive.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7 and window-specific)
- T1 (view-model borrow): `on_hub_image_changed` MUST NOT touch the view model, the viewer or the surface (it runs inside a view-model call). A test calls it while the view model is `borrow_mut`ed and expects no panic and a queued item.
- T2 (order): `image_changing` before the image; images FIFO; `update_retained` AFTER `set_incoming` (the pending upgrade id must be in the retained set before the cache can evict it); `render_now` last. A test with a recording composer asserts the call order `begin_crossfade, set_incoming, current, collect_retained_ids, retain, render`.
- T3 (cross-thread): the `CacheCleared` listener and the lookup worker are the only code off the UI thread; they hold only `Send` data (`MainWindowId`, `Arc<PreviewImageService>`, `Vec<Option<Arc<PixelBuffer>>>`). A compile-time check (`fn assert_send<T: Send>()`) on the posted closures.
- T4 (disposed): after `dispose` the handlers return early and the posted jobs find no window (`with_window` is `None`): no `PixelBuffer`, composer or cache is touched after `release_renderer`.
- T5 (INV-1): never key anything by path; `retain` takes `PixelBuffer::id()` values. INV-2: after `CacheCleared` the GPU cache is cleared on the UI thread; the count is observable.
- T6 (disposed buffers): `PixelBuffer::is_disposed()` is checked before use (compare images, existing `image`); a disposed image counts as no image.
- T7 (numbers): `defer_upload_bytes` and the byte counts are `i64`; the transition duration is `u64` ms after clamping with the `AppSettings` bounds; `total_files()` -> `i32` with `try_from(..).unwrap_or(i32::MAX)`.
- T8 (re-entrancy): `render_now` can call `present`, which can raise `DeviceRecreated` handlers -> `cache.clear` and `composer.cancel_crossfade`; none borrows `composer`/`prefetcher` cells for the duration of the call (clone the `Rc` out first).
