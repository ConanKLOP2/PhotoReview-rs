- Semantics notes:
  1. **Integer types.** All byte values are C# `long` => `i64`; percents are `int` => `i32`; `IMemoryProbe.HasHeadroom(double, long)` =>
     `MemoryProbe::has_headroom(f64, i64)`. C# is in the default UNCHECKED context: every `+ - *` below wraps. Use `wrapping_add/sub/mul` exactly where
     the C# expression is (golden `min-window-bytes-wrap`, `min-percent-window-wrap-1g`, `bytes-percent-2147483647-*`). The only checked block is
     `checked(width * 2)` / `checked(height * 2)` and the final `checked((long)Math.Ceiling(total))` (cannot overflow after the `>= long.MaxValue` early return).
  2. **Shares use `f64`.** `(long)(physicalBytes * 0.5)` and `* 0.2`: convert the i64 to `f64` first (loses low bits above 2^53), multiply, `as i64`
     (saturating, same as .NET 9+ `(long)double`). Do NOT use integer `/ 2` or `/ 5`: results differ for odd or huge sizes
     (golden `clamp-physical-odd-physical-trunc`, `-double-rounding-large`, `clamp-source-*`).
  3. **`clamp_to_physical_memory`**: `physical <= 0` => the request unchanged (even negative requests); else `min(requested, limit)`.
     **`clamp_source_bytes_to_physical_memory`**: `physical <= 0` => request; else `min(clamp_to_physical_memory(req, phys), (phys as f64 * 0.2) as i64)`.
     **`clamp_preview_to_physical_memory`**: `clamped = clamp_to_physical_memory(req, phys)`; `physical <= 0` => `clamped`; else
     `remaining = max(0, clamp_to_physical_memory(i64::MAX, phys) - max(0, source))`; `min(clamped, remaining)`. Order of operations as written.
  4. **`minimum_preview_window_bytes`** = `(image_count as i64) * 3840 * 2160 * 4` left to right (i64 wrapping). `image_count` wraps (`i32`);
     a negative window gives a negative size (no guard in C#).
  5. **`minimum_cache_percent`**: `physical <= 0` => `MIN_IMAGE_CACHE_RAM_PERCENT` (1). Else `percent = (min_bytes * 100 + physical - 1) / physical`
     (wrapping mul/add/sub, then i64 division which truncates toward zero as in C#), result `percent.clamp(1, 90) as i32`. `Math.Clamp(long,long,long)`
     is used: write it as `percent.max(1).min(90)` on i64 BEFORE the `as i32` (an i64 outside i32 must not wrap into range).
  6. **`clamp_cache_percent`** = `requested.clamp(minimum_cache_percent(..), 90)`. The minimum is always <= 90, so `i32::clamp` cannot panic; keep it
     as `max(min).min(max)` anyway if the porter prefers no panic path.
  7. **`bytes_for_percent`**: `physical <= 0 || percent <= 0` => 0; else `physical / 100 * percent + physical % 100 * percent / 100` with `percent`
     widened to i64 and **wrapping** multiplications (percent is NOT clamped here: `i32::MAX` percent on a big RAM wraps in C#; golden pins it).
  8. **`preview_bytes_for_percent`**: `physical <= 0` => `Err(ArgumentOutOfRange{"physicalBytes"})` (ThrowIfNegativeOrZero), else
     `budget = bytes_for_percent(clamp_cache_percent(..), physical)`; `max(1, budget - max(0, source))` (wrapping sub).
  9. **`source_bytes_for_percent`**: `physical <= 0` => request unchanged; `budget` as above; `room = max(0, budget - minimum_preview_window_bytes(window))`;
     `min(clamp_source_bytes_to_physical_memory(req, phys), room)`.
  10. **`estimate_folder_preview_bytes`** (bytes returned as `i64`, `i64::MAX` is the "never preload the folder" sentinel):
      - `bounded = box.width > 0 && box.height > 0`; `box_bound = if bounded { width as f64 * height as f64 * 4.0 } else { 0.0 }` (f64 product, no i32/i64 product).
      - **Measured branch** when `measured` is `Some(v)` with `v > 0.0` (NaN, 0, negative => ignored, falls to the entry loop). `calibrated = v * 1.25`;
        `if bounded && v <= box_bound { calibrated = calibrated.min(box_bound) }`; `all = (entries.len() as f64 * calibrated).ceil()`;
        `if all >= i64::MAX as f64 { i64::MAX } else { all as i64 }` (NaN from `0 * inf` casts to 0, as .NET; keep the explicit `as`). The entries are NOT visited.
      - **Entry loop** (f64 accumulator `total`): `width/height = entry.width/height.unwrap_or(0)`; `is_raw = is_raw_path(entry.path())`.
        (a) `width > 0 && height > 0 && (bounded || is_raw)`: if `is_raw`, `width = width.checked_mul(2).expect(..)` and same for height (panic = C#
        `OverflowException`); `scale = min(1.0, min(if box.width > 0 { box.width as f64 / width as f64 } else { 1.0 }, same for height))`;
        `estimate = (width as f64 * scale).ceil() * (height as f64 * scale).ceil() * 4.0` (left to right).
        (b) else if `bounded`: `estimate = box_bound`.
        (c) else if `is_raw`: `length = entry.length.unwrap_or(0)`; `length <= 0` => **return `i64::MAX` immediately** (even after other entries);
        `estimate = length as f64 * 6.0`.
        (d) else: `estimate = length.unwrap_or(0).max(0) as f64 * 10.0`.
        After each entry `total += estimate; if total >= i64::MAX as f64 { return i64::MAX }`. Result `total.ceil() as i64`.
      - Note `i64::MAX as f64` is `2^63`; `(long)total` of a value just below it is exact enough: do not try to be cleverer than the C# comparison.
  11. **`should_preload_whole_folder_estimate`**: `estimated < 0` => `Err(ArgumentOutOfRange{"estimatedBytes"})`; else
      `estimated <= capacity && probe.has_headroom(maximum_load, reserve_bytes)`. Short-circuit: the probe is NOT called when the estimate exceeds capacity
      (a counting fake can observe this; the C# `&&` has the same property).
  12. **`FolderEstimateCache`**: hit when ALL hold: stored `entries` is `Some` and `Arc::ptr_eq` with the argument (C# `ReferenceEquals`; an equal but
      distinct snapshot is a MISS), box equal, `measured == stored measured` (`Option<f64>` `==`: `Some(NaN)` never matches, so a NaN calibration recomputes
      every call, as in C#). On a miss compute via `estimate_folder_preview_bytes(&entries, ..)`, store, `compute_count += 1`. Initial state: no entries,
      box `0x0`, measured `None`; the first call is always a miss even for an empty snapshot (entries `None`).
  13. **`get_physical_memory_bytes`**: C# is `GC.GetGCMemoryInfo().TotalAvailableMemoryBytes`. Rust has no GC; the unit only defines the seam and returns
      `source.total_available_memory_bytes()`. The Windows value (physical RAM, honouring a job-object memory limit) is implemented by W4-07b/`pr-platform-win`
      (see Open questions).
- Traps checklist (docs/MULTI-AGENT-PLAN.md §7): item 3 (numeric conversions: `(long)double`, `int`/`long` widening, wrapping), item 4 (floating
  point order, `ceil`), item 7 (inclusive vs exclusive comparisons: `>=` on the long-max test, `<=` on capacity), item 10 (no unordered collections),
  item 11 (default arguments: C# `measuredMeanPreviewBytes = null` is `Option::None`). Specific traps:
  1. **`i64::MAX as f64`** is exactly `9223372036854775808.0`; `all >= that` is the saturation test. A sum equal to 2^63 is `i64::MAX`, below it is cast.
  2. **Widening before multiplying.** `entries.len() as f64 * calibrated`; `width as f64 * height as f64 * 4.0`: never multiply two `i32` first (overflow;
     golden `jpeg-huge-dims-*`).
  3. **`Math.Ceiling(w * scale) * Math.Ceiling(h * scale) * 4`** is `(ceil * ceil) * 4` in f64; do not reassociate.
  4. **RAW dimension overflow panics** (C# `OverflowException`): the only panic in the unit; golden cases `raw-width-times-two-overflows`,
     `raw-height-times-two-overflows`, `raw-width-max-int-overflows`; `raw-width-just-fits-doubled` (1073741823) must NOT panic. In the Rust test
     use `std::panic::catch_unwind` per case (or `#[should_panic(expected = "overflow")]` for the three named tests); the golden-driven test
     treats a panic as `{error: "OverflowException"}`.
  5. **RAW detection** is by extension through `is_raw_path` (case-insensitive via the merged `pr-core` function); an entry whose path has no extension
     is not RAW. Paths such as `a/b.PNG` are non-RAW.
  6. **Unknown length is not zero for RAW only.** Non-RAW without a length contributes 0 in an unbounded box (golden `jpeg-no-dims-unbounded-no-length-zero`).
  7. **Sentinel return inside the loop** skips the remaining entries (cheaper and observable only through the result).
  8. **Negative `percent` in `bytes_for_percent`** returns 0 (guard `percent <= 0`), but `clamp_cache_percent` raises a negative request to the minimum.
  9. **`measured` just above the box bound** is not capped (16-bit images, golden `measured-above-box-bound-16bit`); exactly at the bound is
     capped (`<=`), but `1.25 * bound` then `min(bound)` returns the bound.
  10. **Allocation tests.** The C# per-entry allocation assertions use `GC.GetAllocatedBytesForCurrentThread`. In Rust the requirement is structural:
      `estimate_folder_preview_bytes` must not allocate per entry (`is_raw_path` takes `&str`; do not `to_lowercase`, `format!` or `PathBuf::from`
      inside the loop) and, with a measured mean, must not touch the entries at all.
  11. **JSON 64-bit values.** Goldens carry `i64` values above 2^53 (`2^62`, `i64::MAX`); parse them as `i64` (`serde_json` `as_i64()`), never via `f64`.

## Open questions
1. **Physical memory source.** C# `GC.GetGCMemoryInfo().TotalAvailableMemoryBytes` has no portable Rust twin and `pr-core` may not take Windows deps.
   Recommended and used by this stub: `trait PhysicalMemorySource` here; the Windows implementation (`GlobalMemoryStatusEx.ullTotalPhys`, capped by a
   job-object limit if set) lives next to the W4-07b OS query in `pr-platform-win` and the composition root injects it. If W4-07b already defines a
   snapshot type with total physical bytes, reuse it and drop this trait (one-line change in this file).
2. **Snapshot identity type.** `FolderEstimateCache` needs "same catalog snapshot" (C# reference equality). The stub uses `Arc<[CatalogEntry]>`
   with `Arc::ptr_eq`. If the W4-15 scheduler's catalog snapshot type is different (e.g. a versioned `Arc<Snapshot>`), W4-15 changes this one signature
   (the cache is `pub(crate)`, so nothing outside `pr-imaging` is affected).
3. **Overflow as panic versus `Result`.** The `checked(width * 2)` case is unreachable with real catalog data (a RAW sensor above 1 billion pixels per
   axis); the stub keeps the C# "throws" meaning with a documented panic instead of widening the return type of a hot-path function. If the lead prefers
   `Result<i64, EstimateOverflow>`, the golden's `OverflowException` cases map to `Err`.
4. **`ArgumentNullException` cases** (`entries == null`, `memoryProbe == null`) disappear by construction (references cannot be null); no twin test.
