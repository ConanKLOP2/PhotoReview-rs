## Semantics (C# is the spec; the doc comment of every stub function is part of it)
1. **`classify_command(id, notification)`** (pure): `NAV_ID` with `LBN_SELCHANGE` (1) -> `NavSelection`; `APPLY_ID` / `DEFAULTS_ID` / `RESET_PAGE_ID` / `EXPORT_ID` / `IMPORT_ID` with `BN_CLICKED` (0) -> the matching variant; everything else (including the same ids with another notification, `SAVE_ID`, `CANCEL_ID`) -> `Other`.
2. **`handle_command`**: the variant's action and `true`; for `Other`: `loading` -> `true` (the notification was caused by loading values); else `index = page_of(id)` in `0..page_count`: `pages[index].try_borrow_mut()`; `Ok(mut page)` -> `page.on_command(id, notification as u32)`; `Err` -> `true` (an echo of the running page's own write: the page already knows, D-W8B5-805); out of range -> `false`. The page borrow ends before the function returns and is never held across `warn`.
3. **`try_save_all`** = `plan_for(presenter.try_save(&collect_all(), ctx))`. The presenter is borrowed mutably for the `try_save` call only (the language switch inside it posts `WM_APP_LANGUAGE`, it does not call back). `Warn` -> `warn(title, message)` (modal, no borrow held), then `focus_field(focus)` when `focus != None`, `false`. `Saved` -> `saved = true`, `true`. `saved` is never reset to `false`.
4. **`plan_for`** (pure): `Invalid` -> `Warn { title: tr::dialog_settings_invalid_title(), message: result.message or "", focus: result.focus }`; `SaveFailed` -> `Warn { title: tr::dialog_settings_save_failed_title(), message, focus: None }` (the C# does not move the focus after a failed write); `Saved` -> `Saved`.
5. **`focus_field`** and **`locate_focus`**: targets are asked page by page in navigation order (a borrowed page answers `None`); the FIRST page with `Some(id)` wins; `activate_page(i, true, true)` (creates the controls) THEN `focus_control(id)`. Fields with no page, and `SettingsFocusField::None`, do nothing.
6. **`reset_active_page`**: `active < 0` -> nothing; else the scratch presenter (`ScratchSeed`: same RAM size, texts and shell integration; no store, no localization, no checker) over a clone of the working settings, `defaults = apply_defaults()`, then `page.load(&defaults)` for the SHOWING page only, with `loading` set; then `relayout_active_page`. The real presenter is not touched.
7. **Export**: no `files` -> nothing. `files.pick_save_file(hwnd, tr::dialog_export_settings_title(), FileFilterText::parse(tr::dialog_file_filter_json()), Some("json"), Some("PhotoReview-settings.json"), Some(dir))` where `dir = SettingsPresenter::settings_file_dialog_directory()` as a string. `Ok(None)` and `Err(_)` (the Rust file dialog reports a failure as `Err(Hresult)`; the C# would have thrown out of the button handler; a failed dialog is treated as cancelled, D-W8B5-906) -> nothing. `Ok(Some(path))` -> `presenter.borrow().export_settings_to(Path::new(path), ctx)`; `Some(error)` -> `warn(tr::dialog_settings_invalid_title(), error)`.
8. **Import**: `files.pick_open_file(hwnd, tr::dialog_import_settings_title(), filters, Some(dir))`; `Ok(Some(path))` -> `import_settings_from(path)`. `import_settings_from`: the presenter call `presenter.borrow_mut().import_settings_from(path, refresh, ctx)` where `refresh` is `&mut |p: &SettingsPresenter| { recorded = Some(p.load_fields()); Ok(()) }` (D-W8B5-906: the pages' `load` borrow the presenter through their context, which would panic inside the presenter's `&mut self` call). After the call, if a state was recorded, `load_all(&state)` runs ONCE with the last recorded state (the presenter's failure arm refreshes twice, with the imported settings and then with the previous ones; only the last matters for the final screen). Then `result.error` -> `warn(tr::dialog_settings_invalid_title(), error)`; else `result.repairs_notice` -> `warn(tr::dialog_import_settings_title(), notice)`.
9. **`warn`** = `warnings.show_warning(dialog.hwnd(), title, message)`. Modal; callers hold no `RefCell` borrow. Window-less (hwnd `0`) it still calls the sink (tests and the oracle rely on it).
10. **`WindowPoster`**: `new()` -> hwnd `0`, empty queue. `set_hwnd(h)`: stores `h`; `0` also clears the queue. `post(action)`: `hwnd == 0` -> dropped; else pushed (FIFO) and `post_message(hwnd, WM_APP_QUEUE, 0, 0)`; a failed post leaves the action queued. `drain()`: takes everything under the mutex (`std::mem::take`) and returns it; the mutex is NOT held while an action runs. `post_language_changed()`: `hwnd != 0` -> `post_message(hwnd, WM_APP_LANGUAGE, 0, 0)`. Safe from any thread; a poisoned mutex is recovered with `PoisonError::into_inner`.
11. **`handle_window_message`**: `WM_MOUSEWHEEL` -> `scroll_by_wheel(dialog, wheel_delta(wparam))`, `Some(0)`; `WM_APP_QUEUE` -> first the UI-local queue (pop one at a time under a short borrow, run it with `(self, dialog)`), then every `ContextUiAction` of `poster.drain()` called with `&self.context`; `Some(0)`; `WM_APP_LANGUAGE` -> `refresh_localized_texts`, `Some(0)`; else `None`. An action may post more work: it is queued for the next `WM_APP_QUEUE`, never run in the same drain.
12. **`wheel_delta`** (pure): `((wparam >> 16) & 0xFFFF) as u16 as i16 as i32`. **`is_forwarded`** (pure): see the stub; the "forward everything" kind forwards `WM_COMMAND` (0x111), `WM_NOTIFY` (0x4E), `WM_DRAWITEM` (0x2B), `WM_MEASUREITEM` (0x2C), `WM_HSCROLL` (0x114), `WM_VSCROLL` (0x115) and `0x0132..=0x0138`; both kinds forward `WM_MOUSEWHEEL` unless a combobox is dropped.
13. **`forward_proc`**: see the stub. The forwarded `send_message` carries the original `wparam`/`lparam` (pointers to notification structures owned by the sender for the duration of the call). `hwnd != dialog hwnd` is checked so the dialog never forwards to itself. A `WM_CTLCOLORSTATIC` from a key box answers the brush of `key_box_colors`.
14. **`refresh_localized_texts`**: the stub lists the order. The guard `in_language_refresh` is restored on every path. Combo item lists are re-asked from their `TextFn`s and the selection survives (`max(0, selected)`); a page that is not created yet is localized when it is created (its combos are filled with the then-current texts). Ends with `dialog.run_layout()` (every text may have changed its wrapped height).
15. **Language subscription** (made in `initialize`, 19j): a closure holding an `Arc<WindowPoster>` posts `WM_APP_LANGUAGE`; the language change may come from any thread, the refresh always runs on the UI thread.
16. **Subclass kinds.** `forward(control, true)` (`FORWARD_ALL_SUBCLASS_ID`) is for the page containers only; `forward(control, false)` (`WHEEL_SUBCLASS_ID`) for the navigation list (a direct child of the dialog: its `WM_COMMAND` needs no forwarding) and the page comboboxes.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T8 (null vs empty): `message` of a result is `Option`; an `Invalid` with `None` shows an empty message (the C# `?? string.Empty`); `Files == None` is silent, not an error.
- T9 (exception to Result): three C# exception paths become values: a file dialog failure (`Err(Hresult)` -> cancelled), `export_settings_to` failure (`Some(text)` -> warning), `import_settings_from` failure (`result.error` -> warning). `pick_*` never panics.
- T10 (order): pages are asked in navigation order; the queue is FIFO; `warn` happens BEFORE the focus moves.
- Borrow protocol (D-W8B5-904/906): the presenter is borrowed for exactly one call at a time; `try_save`'s result is a value; `import`'s refresh is deferred; no borrow is held across `warn`, `pick_*`, `load_all`, `activate_page`.
- Re-entrancy: `warn` runs a nested loop in which the window procedure of this dialog keeps running (paint, timers, `WM_APP_QUEUE`); `try_save_all` therefore reads nothing after `warn` that a nested message could have changed except through the same accessors.
- Cross-thread: only `WindowPoster` (and the `Arc` poster in the subscription closure) is shared; the content and the pages stay on the UI thread. The queue drops its actions when the window closes.
- INV-9 spirit: an update-check answer that arrives after Cancel is dropped (the poster has no window).
- R0003: no `unwrap`/`expect`/indexing; `forward_proc` and `key_box_proc` never unwind (`pending_panic::guarded`).

## Safety rules (`// SAFETY:` per `unsafe` block)
`forward_proc`: "a SUBCLASSPROC installed by `forward` on a window of this thread; `ref_data` is a registry key, not a pointer; the arguments are those of the window message and are passed on unchanged". `send_message` in `forward_proc`: "forwards a message that the child sent to its parent; `lparam` is a pointer or handle valid for the duration of this call because the sender is blocked in its own `SendMessage`". `set_window_subclass`: "the procedure is a plain `extern \"system\" fn`; the id and registry key identify the content; removed on `WM_NCDESTROY`" (`remove_window_subclass` and `def_subclass_proc`, also `unsafe fn`s of `win32::comctl`: "called from the procedure with its own arguments"). `post_message(hwnd, WM_APP_QUEUE | WM_APP_LANGUAGE, 0, 0)` in `WindowPoster::{post, post_language_changed}` and `post_local`: "integer-only message (no pointer in `wparam`/`lparam`) to a handle the OS validates; a stale handle makes the post fail, which is ignored".

## Error mapping
| C# | Rust |
|---|---|
| `Files.PickSaveFile` / `PickOpenFile` throw | `Err(Hresult)` treated as a cancelled pick |
| `ExportSettingsTo` returns an error text | `Some(text)` -> `warn(invalid title, text)` |
| `ImportSettingsFrom` returns `Error` / `RepairsNotice` | `warn(invalid title, error)` / `warn(import title, notice)` |
| `TrySave` `SaveFailed` | `Warn` with the save-failed title, no focus change |
| `ConcurrentQueue.Enqueue` + `PostMessage` | `WindowPoster::post` |
| `catch (Exception) { }` in `ForwardProc` | `pending_panic::guarded`: captured, resumed by the owner of the native call |
| `_loading` flag | `LoadingGuard` (19k) |
| `Localizer.CurrentChanged += handler` | `Localizer::on_current_changed(closure)`; dropped in `close::on_closed` |

## Open questions (recommended default in bold)
1. **A failed file dialog (`Err(Hresult)`)**: **cancelled pick** (nothing happens); alternative: warn with the HRESULT. The C# let the exception escape the button handler (the window procedure's catch ends the dialog), which Rust must not do (R0003).
2. **Deferred import refresh** (D-W8B5-906): **yes**; the observable end state equals the C#; the intermediate `load` with the imported values before a failure is not reproduced.
3. **Where `forward` is called**: **declared here, called by 19j** (`initialize`, `ensure_page_created`); the stub signature fixes it.
4. **`SettingsUiPost::post` failure to wake the window**: **action stays queued**, the next wake (or the window closing) handles it; alternative: drop. A failed `PostMessage` to a live window is practically only a full message queue.
