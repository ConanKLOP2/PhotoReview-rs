## Semantics (C# is the spec)
1. **`attach`** in C# order (the stub doc lists it). Concretely: `tooltips = DeferredTooltips::new(factory, &*poster)` where the default factory is `|| NativeTooltipHost::new(window.hwnd()).map(|h| Rc::new(h) as Rc<dyn OverlayTooltips>)`; `menus` is passed in (the adapter from the 14f popup host or `None`); the overlay options get the pieces named in the stub; `overlay.update(view_model.overlay_model())` BEFORE the handler is inserted; the `OverlayMessageHandler` gets the same `Rc<DeferredTooltips>` as the overlay (one instance: the overlay syncs, the handler relays); then the window's `Activated`/`Deactivated` subscriptions (their ids are kept for `dispose`), the settings subscription, the localizer subscription.
2. **Cross-thread handlers.** `SettingsStore::subscribe_changed` takes `Fn(&Arc<AppSettings>) -> io::Result<()> + Send + Sync` and `pr_l10n::localizer::on_current_changed` takes `Fn() + Send + Sync`: neither may touch the `Rc` world. The settings handler stores the settings in `OverlayPending::settings` (latest wins) and calls `wake.wake()`, returns `Ok(())`; the language handler sets `language_changed` and wakes. `run_pending()` (UI thread) drains: settings first (`view_model.set_settings(s)`, `overlay.settings_changed()`, `mark_model_dirty()`), then the language flag (`on_language_changed()`). A test saves settings from another thread and checks that nothing runs until `run_pending`.
3. **`mark_model_dirty` / `refresh_model`**: `refresh_posted` coalesces: while a refresh is pending a second call does nothing; the job (`LocalPoster::post(UiPriority::Render, ..)`, holding a `Weak`) clears the flag FIRST, then updates when not disposed. Many changes in one dispatcher turn give one `overlay.update` with the model read at that time.
4. **`on_view_model_changed(changes)`**: nothing when disposed; navigation (`changes.main.contains(MainProperty::CurrentIndex) || contains(MainProperty::CurrentImage)`) -> `overlay.note_activity()` first; `mark_model_dirty()` when `!changes.main.is_empty() || !changes.overlay.is_empty() || !changes.compare.is_empty()` (the three C# `PropertyChanged` sources; viewer-only changes do not touch the overlay, matching C#, which did not listen to the viewer). C# subscribed per source; the main window now forwards one `ChangeSet` per call.
5. **Language**: `on_language_changed`: disposed -> nothing; `view_model.refresh_localized_text()` BEFORE `overlay.apply_localization(&Localizer::current())` BEFORE `overlay.update(view_model.overlay_model())` (the model must carry the new texts, e.g. "N images").
6. **`client_origin_dip`**: `(x / dpi, y / dpi)` with `dpi = if dpi_scale <= 0 { 1 } else { dpi_scale }`; used for the Tools menu anchor so the anchor is in SCREEN DIP of the CURRENT window DPI (the integration test moves the window to 200 % with a synthetic `WM_DPICHANGED` and expects half of the pixel origin).
7. **`ViewModelOverlayCommands`**: `open_folder` -> `pick_and_open_folder`, the six one-to-one names, `fit` -> the closure, `remove_duplicates(numbered)` -> same. Failures: none caught here (Q5 of W8-15i); the implementer of `OverlayViewModel` reports through `report_action_failed`.
8. **`on_command_failed`** (menu errors reach it through the overlay's `on_menu_failed` as `"ToolsMenu"`): ignored when disposed, else `view_model.report_action_failed(name, message)`. In C# the post to the UI thread was needed because a task continuation could run elsewhere; every Rust call site is the UI thread.
9. **`dispose`** (C# 116-142): idempotent. Drop the `Localizer` subscription (its `Drop` unsubscribes), `settings_store.unsubscribe_changed(id)`, unsubscribe the two window events, `overlay.dispose()` (which also disposes the shared tooltips), set `disposed`. The posted `refresh_model` job later finds `disposed` and does nothing. The message handler remains in the window's chain with a disposed overlay: it answers `None` for everything (no leak of messages). The C# `Interlocked.Exchange(ref _overlay, null)` becomes the owner's `Option::take`.
10. **Order of destruction** (owner, 13h): `MainWindowOverlay::dispose` -> drop the `Rc<MainWindowOverlay>` -> drop the text renderer last (layout leases were released by `overlay.dispose`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (z order of overlay vs image): `draw_overlay` after the image layer in the same frame (item 3 of the cross-unit list); the overlay never calls `Present`.
- T2 (hit testing with DPI / message routing to the overlay window): the handler is inserted first; mouse `lParam` pixels are divided by `window.dpi_scale()` at the moment of the message (the DPI can change between two messages); the origin helper uses the same scale. A test changes the fake window's DPI between two messages.
- T3 (threads): the two `Send + Sync` closures capture only `Arc<OverlayPending>` and `Arc<dyn UiWake>`; nothing `Rc` crosses. `UiWake::wake` may be called while the settings store holds its handler snapshot: it must not re-enter the store.
- T4 (re-entrancy): `run_pending` can run while the overlay is inside a modal menu (`show_tools_menu`); `overlay.settings_changed()` is then called re-entrantly: safe by the no-borrow rule (W8-15h item 2).
- T5 (coalescing): the `refresh_posted` flag is cleared BEFORE the update so a change made inside `update` (a render request) can post again.
- T6 (language event leak): the `Localizer` subscription is process-global; dropping `MainWindowOverlay` without `dispose` still unsubscribes (the subscription's `Drop`), and a test counts wake calls after drop.
- T7 (settings handler error): the closure always returns `Ok(())` (an `Err` would skip the remaining handlers, `SettingsStore` contract).
- T8 (nested `Option`): `attach` twice on the same owner is a programming error of the owner (C# threw `InvalidOperationException`); no run-time check here.
- T9 (no `async`): `FitAsync` is a closure; C# `Task` returns vanish.

## Safety rules
None: no `unsafe` in `main_window.rs` (the `ClientToScreen` call lives in 15f `native.rs`). The `impl OverlayWindowPort for ShellWindow` is a call to a safe inherent method.

## Error mapping
| C# | Rust |
|---|---|
| `AttachOverlay` twice -> `InvalidOperationException`; after dispose -> `ObjectDisposedException` | owner's `Option` / not representable |
| `new NativeTooltipHost(Hwnd)` throws | `DeferredTooltips` swallows (15g): no tooltips |
| `SettingsStore.Changed` handler exceptions | handler returns `Ok(())` always |
| `OnOverlayCommandFailed` off the UI thread | not reachable |
| `Localizer.CurrentChanged` raised on any thread | `UiWake` hand-over |
