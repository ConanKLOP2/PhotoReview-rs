## Semantics (C# is the spec; line numbers are C# lines)
1. **Compute order** (26-44): sanitize client width and height (`SanitizeLength`), `ImageElement.From` (143-147), `Measure` (166-175),
   `ResolveBars` (79-111) with the sanitized thickness, `Arrange` (181-192), then `max_horizontal_offset = scrollable_length(desired.width,
   viewport_width)` and the same for vertical. The extent reported is the DESIRED (clamped) size, not the slot.
2. **`SanitizeLength`** (133): finite and `> 0` keeps the value; NaN, negative, infinite, zero and `-0.0` all become literal `+0.0`.
3. **`SanitizeExplicit`** (149, `Width`/`Height`): finite and `>= 0` keeps the value (`-0.0` passes because `-0.0 >= 0` is true, and it is kept
   as `-0.0`); otherwise NaN, which means auto.
4. **`SanitizeMax`** (151, `MaxWidth`/`MaxHeight`): NaN or `< 0` becomes `+inf`; `0` is a real bound (`max_width_zero_is_a_valid_bound`).
5. **`MaxW` / `MinW`** (154-160): `MaxW = max(min(width or +inf when NaN, max_width), 0)`; `MinW = max(min(MaxW, width or 0 when NaN), 0)`.
   `MinH`/`MaxH` the same with height.
6. **`Measure`** (166-175): box = `stretch_to_box(MaxW, MaxH)` (the MAX, not the explicit size); `unclipped = max(box, MinW)`;
   `desired = min(unclipped, MaxW)`. Returns `desired` and `unclipped`.
7. **`ResolveBars`** (79-111):
   - `Overlay`: flags `greater_than(extent, client)`, viewport = client (no thickness).
   - `Hidden`: `(false, false)`, viewport = client.
   - `Auto` (falls through the switch): pass 1 flags from `greater_than(extent, client)`. If and only if exactly one flag is set (`h != v`):
     when `!h`, `h = greater_than(extent_width, barred(client_width, thickness, true))`; else `v = greater_than(extent_height, barred(client_height, thickness, true))`.
     Then `viewport_width = barred(client_width, thickness, v)` and `viewport_height = barred(client_height, thickness, h)` with the FINAL flags.
8. **`ArrangeOverride` slot** (183-184): `slot = max(desired, viewport)` on each axis.
9. **`ArrangeLength`** (194-201): `length = slot`; `if length < unclipped: length = unclipped`; `effective_max = max(unclipped, max)`;
   `if effective_max < length: length = effective_max`. Called with `MaxW`/`MaxH` as max.
10. **Arrange rectangle** (185-191): `render = stretch_to_box(arrange_width, arrange_height)`; `x = alignment_offset(slot_w, min(render_w, MaxW))`;
    `y = alignment_offset(slot_h, min(render_h, MaxH))`; size = `render`. The ink used for alignment is the render size clamped by `MaxW`/`MaxH`.
11. **`AlignmentOffset`** (204): `ink > client ? 0 : (client - ink) * 0.5`. Image bigger than the slot is pinned to 0 (left/top), otherwise centred.
12. **`StretchToBox`** (207-222): `scale_x = 1`, `scale_y = 1`; if at least one side is constrained (`!= +inf`): `scale_x = is_zero(natural_w) ? 0 : box_w / natural_w`,
    same for y. An unconstrained side copies the other side's scale. If both are constrained and `uniform`: both = `min(scale_x, scale_y)`.
    Result `(natural_w * scale_x, natural_h * scale_y)`. (`Uniform` also means "ViewerStretchMode.Uniform"; `None` is Fill.)
13. **`ClampOffset`** (51-52, `CoerceOffset` 64-70): per axis: NaN gives 0; `if offset > extent - viewport: offset = extent - viewport`; then
    `if offset < 0: offset = 0`. Upper clamp first, lower clamp second (the order matters when `extent < viewport`).
14. **`ImageElement.From` natural size** (146-147): `natural = sanitize_length(bitmap)`. No bitmap means 0 x 0.
15. **`IsZero`** (130): `|value| < 10 * WPF_DOUBLE_EPSILON` (strict). `StretchToBox` uses it on the natural size, not `== 0`.
16. **`GreaterThan`** (118): `value1 > value2 && !are_close(value1, value2)`. Overflow decisions use this, never plain `>`.
17. **`AreClose`** (121-127): equal (including two infinities of the same sign) is close; otherwise
    `eps = (|a| + |b| + 10) * WPF_DOUBLE_EPSILON` and close iff `-eps < a - b && eps > a - b` (both edges open).

## Traps (write these into the tests; each one is a mutant the verifier will try)
1. **`Math.Max`/`Math.Min` are NOT `f64::max`/`f64::min`.** .NET Core 3.0+ propagates NaN and orders `+0` above `-0`; Rust ignores NaN and may
   return either zero. `-0.0` reaches these calls: `width = "-0"` gives `Min(-0.0, MaxWidth)` and then `Max(..., 0)` must yield `+0.0`
   (bits `0000000000000000`), and `extent` bits must match the oracle. Use `net_max`/`net_min` for every C# `Math.Max`/`Math.Min`. The golden
   cases `width -0` (grid elements 11) pin this. A mutant that swaps in `f64::max` must fail a test.
2. **Third pass is conditional** (`h != v`, and only the bar that was off is recomputed). A mutant that always re-runs both passes, or
   recomputes the bar that was already on, fails the three `third_pass_*` tests (14 to 16).
3. **Viewport uses FINAL flags** (108-109). Pass-1 flags for the viewport give a 10 px error in `zoomed_*` tests.
4. **`>` versus `GreaterThan`**: `1000 + 1e-13` is not an overflow (`overflow_uses_wpf_double_util`); `1000.001` is one. The
   `DoubleUtil_AreClose_BothEdges` test pins the strict edges at `2^52 - 4` / `2^52 - 6`.
5. **Alignment uses the clamped ink** (`min(render, MaxW)`, 189-190), not the render size. Example: test 21
   `max_smaller_than_an_explicit_size_clamps_the_element` (explicit 500x400, max 250x100).
6. **Uniform only applies when both sides are constrained** (217-219). Fill (`None`) keeps independent scales.
7. **`SanitizeExplicit` keeps `-0.0`** (`-0.0 >= 0` is true), `SanitizeLength` does not (`-0.0 > 0` is false, returns `+0.0`). Both bits are pinned.
8. **`SanitizeMax` keeps `0`**: `MaxWidth = 0` is valid and bounds the element to zero (`max_width_zero_is_a_valid_bound`). A mutant that treats
   `0` as "unbounded" fails test 33.
9. **NaN in client and thickness**: sanitized to `+0.0` before any arithmetic; `ResolveBars` never sees NaN. `thickness` NaN with a
   valid client gives viewport = client (thickness 0).
10. **`ClampOffset` order**: `NaN` first, upper bound second, lower bound third. A negative `extent - viewport` (content smaller than the
    viewport) therefore gives 0 (test 27).
11. **Bit-exact output**: the golden compares `f64::to_bits`, not a tolerance. Floating-point operation order must match C# exactly
    (`box_w / natural_w` then `natural_w * scale_x`; `(client - ink) * 0.5`). Do not reorder into `natural_w * (box_w / natural_w)` or
    `(client - ink) / 2`: both can differ in the last bit.
12. **No allocation, no clock, no I/O** (C# "Thuần, không cấp phát"): no `Vec`, no `Box`, no `String` in the port.
