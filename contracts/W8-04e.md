## Semantics (C# is the spec; numbers are the C# values)

### A. `viewport_convergence` (pure)
1. `EPSILON = 0.5` DIP. `IsStableViewport(before, after)`: first `validate_measurements(after)`; invalid -> `false`. Then all of:
   `|vw_before - vw_after| < 0.5`, `|vh_before - vh_after| < 0.5`, `|ew_before - ew_after| < 0.5`, `|eh_before - eh_after| < 0.5`,
   horizontal scroll bar visible equal, vertical scroll bar visible equal. Strict `<`. Only `after` is validated; a NaN in `before` makes the
   comparison false.
2. Zoom, stretch, offsets and the actual and max image sizes are NOT compared.
3. `ValidateMeasurements(s)`, first failing group wins, exact reason strings:
   (a) viewport width and height both `> 0` and finite, else `"Viewport not ready"`;
   (b) horizontal and vertical offset both `>= 0` and finite, else `"Offsets invalid"`;
   (c) max image width and height both `>= 0` and finite, else `"MaxImage not set"`;
   (d) actual image width and height both `>= 0` and finite, else `"ActualImage invalid"`.
   Valid -> `(true, None)`.

### B. `window_helpers` (pure)
4. `ClampOffset(value, extent, viewport)`: `room = extent - viewport`; `maximum = max(0, room)` when `room` is finite, else `0`; a non-finite
   `value` becomes `0`; result = `clamp(value, 0, maximum)`. The result is always finite and in `[0, maximum]`.
5. `CalculateUniformImagePoint(element, source, pointer)`: if any of element width/height, source width/height is not `> 0` and finite, or the
   pointer is not finite, return `(0, 0)` (not the centre). Otherwise `scale = min(ew/sw, eh/sh)`, rendered size `s * scale`, left/top =
   `(e - rendered) / 2`, result `x = clampToSource((px - left)/scale, sw)`, `y` likewise. `clampToSource(v, max)`: NaN -> `0`, else
   clamp to `[0, max]` (a denormal element size can make `v` infinite or NaN).
6. `NormalizeImagePoint(point, size)`: if `size.width > 0`, `size.height > 0`, both finite, and `point.x / width` and `point.y / height` finite,
   return `(x/width, y/height)` (NOT clamped); else `(0.5, 0.5)`.
7. `CalculateOffsetsFromAnchorDelta(current, before, after, newExtent, viewport)`: `h = clampOffset(current.x + after.x - before.x, newExtent.width,
   viewport.width)`, `v` likewise with y/height. The sum order is `current + after - before`.
8. `CalculateZoomToPointOffsets(anchor, image, cursor, current, extent, viewport)` = semantic 7 with `before = cursor` and
   `after = (image.x + anchor.x * image.width, image.y + anchor.y * image.height)`. The image rect is where the element sits after the new
   layout at the CURRENT offsets.
9. `CalculateFitWidthAnchorPoint(anchor)`: `TopThird -> (0.5, 1/3)`, `BottomThird -> (0.5, 2/3)`, everything else `(0.5, 0.5)`.
10. `FitWidthAnchorFor(settings, second)`: `second == true` -> `settings.fit_width_anchor2_or_default()` (C# `FitWidthAnchor2`, default
    `BottomThird` when undefined); otherwise `settings.fit_width_anchor`. Never `KeyboardZoomAnchor`.
11. `CalculatePanOffsets(current, delta, extent, viewport)`: `h = clampOffset(current.x - delta.x, extent.width, viewport.width)`, `v` likewise.
    The pointer moves by `delta`, so the offset moves by `-delta` (the caller passes the offset change negated, C# `PointerInputController`).
12. `IsBeyondDragThreshold(dx, dy, minH, minV)`: `|dx| >= minH || |dy| >= minV`. Inclusive. NaN is false.
13. Value equality of `ZoomViewportOffsets` and `ZoomImagePoint`: C# `record struct` uses `EqualityComparer<double>.Default`, so NaN equals NaN.
    Use `f64_same` (W8-01a), not `==`.

### C. `file_hash` (I/O, concurrency)
14. Hash: SHA-256 of the file bytes, returned as UPPER-case hex, 64 characters (C# `Convert.ToHexString`). The same bytes always give the same
    string whichever path (whole-file or streamed) computed them.
15. Key: `ignore_case_key(full_path)` for the cache and the in-flight map (C# `OrdinalIgnoreCase`). `full_path` is `get_full_path(path)`.
    The stored `HashEntry.path` is that full path. Two spellings that differ only in case share one entry (the RAW test uses `shot.NEF`).
16. Cache weight = `UTF-16 length of the path * 2 + 64` (C# `entry.Path.Length * 2L + 64`). Not `path.len()` (UTF-8 bytes). Capacity 16 MiB.
17. `get(path, cancel)` order: (a) `get_full_path` (Err -> `Path`); (b) `try_get_file_stat(full)`: `Ok(None)` or `Err` -> `Io` (C# `FileInfo.Length`
    throws); (c) cache hit with `length == stat.length && last_write_utc == stat.last_write_utc` -> return the cached hash, no read; (d)
    `cancel.check()`; (e) join or start the shared computation for the key with the stat's length and last write time and the generation read now.
18. Shared computation: one `InFlight` per key with its own `CancelToken`, a waiter count and a result slot. The worker runs
    `compute_and_cache`; when it finishes it removes its entry from the in-flight map BY IDENTITY (`Arc::ptr_eq`), sets the result and wakes all.
19. Waiter loop (C# `GetAsync` while loop): (a) if the caller's token is cancelled, decrement the count; when it reaches 0 cancel the entry's token;
    return `Canceled`. (b) If the result is `Err(Canceled)` and the caller is not cancelled, the entry was cancelled by previous waiters: remove it
    (identity), decrement, and loop to start a fresh computation. (c) Otherwise decrement and return the result. A waiter never returns another
    caller's `Canceled`.
20. `compute_and_cache(path, length, lastWrite, generation, cancel)`:
    - Whole-file path when the source-bytes cache is present, `can_cache(length_as_i64)` is true (`try_from`, an overflow is "not cacheable"),
      and `!is_raw_path(path)`: `bytes = get_or_read(path)` (map `SourceBytesError` -> `Source`), `hash = sha256(bytes)`. Then `complete_if_unchanged`.
      The token is checked after the read (decision D-04e-2, Q5): C# does not observe it here, but nobody can receive the result after the
      last waiter left, so the difference is not visible to any caller.
    - Otherwise streamed: `reader.open_source(path, SourceReadPriority::Preload, HASH_STREAM_BUFFER_BYTES)`; read in 1 MiB chunks; `cancel.check()`
      before each chunk; update the incremental SHA-256; then `complete_if_unchanged`. The C# priority does not exist; `PhysicalSourceReader`
      ignores it (Q9).
21. `complete_if_unchanged(path, length, lastWrite, generation, hash)`: re-stat (`try_get_file_stat`; `None` or `Err` -> `Io`). If the new length or last
    write time differs from the captured ones -> `ChangedWhileHashing { path, user_text }` (text built lazily from `texts`; nothing cached).
    Otherwise: if `generation == current generation`, publish `HashEntry`; return the hash in both cases.
22. `clear()`: generation += 1, then empty the cache. An in-flight computation returns its hash and does not publish it.
23. Errors are `Clone`: a shared computation's error is handed to every waiter that receives it. `is_localized()` is true for `ChangedWhileHashing`
    and for `Source(e)` with `e.is_localized()`. `describe()` is the localized sentence when there is one, else the English `Display`.
24. Streamed read: through `SourceReader` (INV-8: shared read, delete allowed, sequential scan). Never `std::fs::File::open` with a custom
    share mode (the pr-app pure rule: no `windows` crate, and the reader seam is what tests fake).
25. Threading: `get` blocks. Never call it on the UI thread (D-W8-2). A computation runs on a worker thread. The C# `ContinueWith` cleanup
    is the worker's last step (step 18).

## Traps (docs/MULTI-AGENT-PLAN.md section 7 applies; these are specific to this unit)
1. **`f64::clamp` panics** when `min > max` or a bound is NaN (C# `Math.Clamp` returns NaN instead). Every clamp here uses a finite, `>= 0` bound
   (`maximum` in `clamp_offset`, `max` in `clamp_to_source` after the `> 0` guard). Keep the C# NaN guards in front of each clamp.
2. C# `Math.Clamp(+Infinity, 0, max)` is `max`; the NaN guard in `clampToSource` exists because `Infinity - Infinity` and `0 * Infinity` are NaN.
3. `normalize_image_point`: finiteness is checked on `point.x / width` and `point.y / height`, not on `point.x`. A tiny width makes the quotient infinite
   while `x` is finite.
4. `calculate_uniform_image_point` early return is `(0, 0)`, not the centre. A test expects the corner.
5. `calculate_zoom_to_point_offsets` argument order: `before = cursor`, `after = image point`. Flipping them gives the wrong sign; the first
   `ZoomToPoint` test catches it.
6. `calculate_pan_offsets` subtracts the delta (`current - delta`). Adding it is the classic sign bug in this file.
7. `is_beyond_drag_threshold` is inclusive `>=`, per axis, OR. A `>` mutation fails the Theory row at exactly the threshold.
8. `fit_width_anchor2_or_default()`, not `.fit_width_anchor2.unwrap()`, and never `KeyboardZoomAnchor`.
9. `validate_measurements` order: a zero viewport height fails group (a) even when the actual image width is also invalid (`-5`). The first
   failing group wins; the Theory row `ReportsTheFirstInvalidGroup` pins this, so the groups must be checked in the order (a), (b), (c), (d).
10. `is_stable_viewport` validates `after` only. A NaN `before` is not an error here; it just fails the comparison.
11. `FileHashService` cache key is ORDINAL-IGNORE-CASE (`ignore_case_key`), not the raw path. Weight in UTF-16 units (traps 16 above).
12. The RAW check is `is_raw_path` (ignore-case extension). `shot.NEF` must stream, not use the byte cache (test row 2).
13. `can_cache` takes `i64`. Convert the file length with `i64::try_from`; never `as i64`.
14. The generation is read BEFORE the computation starts and compared AFTER the read. A `clear()` between the two means "return, do not publish".
    Changed-while-hashing is checked before the generation.
15. Identity removal: `in_flight.remove(key)` by key can remove a NEWER entry for the same path; compare with `Arc::ptr_eq` (C# `TryRemove(KeyValuePair)`).
16. **Lock order / re-entrancy**: `clear()` runs inside the byte cache's before-publish hook in the test `ClearRunsWhileTheHashIsInFlight`. Never hold
    the in-flight map lock or an `InFlight` state lock while calling `SourceBytesCache`, `FileSystem`, `SourceReader` or `clear`.
17. Test seams are one-shot. Inside a hook do NOT call `set_before_publish_for_tests(None)` (it takes the seam lock while the byte cache holds its
    gate). Use an `AtomicBool` in the hook, as the C# one-shot intends.
18. The stat is taken before the cache check. A deleted file that has a cache entry is an `Io` error (C# `FileInfo.Length` throws), not a cached hash.
19. `DateTimeUtc` compares ticks. The physical stat must keep 100 ns precision; the test "length-equal mtime change" depends on it.
20. Tests that build `SourceBytesCache` pass an explicit physical-memory value large enough that 1 MiB is not clamped to 20 % of RAM
    (`clamp_source_bytes_to_physical_memory`). Otherwise `can_cache` in the test changes meaning.
21. No `unwrap`/`expect` in production paths: `new` returns `Result<_, InvalidCapacity>` (cannot fail for the constant; not unwrapped).
22. The hash cache weight constant `64` and `2` come from C# `(Path.Length * 2L) + 64`. Keep both.
23. `get_full_path` returns `String` (pr-core `dotnet_path`), not `PathBuf`; convert once.
24. `FileHashError::Path` wraps `PathError` (`Argument` and `TooLong`). Do not flatten it into `Io`.
25. Hex is upper case. A lower-case digest breaks duplicate equality with C#-written caches (none today, but the golden of later units compares it).
26. The streamed hash must equal the whole-file hash for the same bytes (both branches use the same incremental SHA-256). Test row
    `get_streams_file_larger_than_source_bytes_cache_without_whole_read` compares with `sha256(bytes)` from the test.
