## Semantics notes

`ShortcutMappings`
* Fields are key NAMES (WPF `Key` enum names as text: `"Right"`, `"D1"`, `"F11"`, `"Add"`). Core does not check they are real keys. Empty string = no shortcut.
* Defaults (these also appear in the golden): Next `Right`, Previous `Left`, MoveToFolder2 `Enter`, SendToRecycleBin `Delete`, Compare `C`, NextFolder `PageDown`, PreviousFolder `PageUp`,
  FirstImage `Home`, ZoomIn `Add`, ZoomOut `Subtract`, ToggleFit `F`, Skip `Space`, Undo `Z`, Fullscreen `F11`, MoveToFolder `M`, CopyToFolder `Y`, LastImage `End`, ZoomActualSize `D1`,
  ToggleInfoOverlay `I`, ClickZoom `D2`, FitWidth `W`, FitHeight `H`, ToggleKeepZoom `K`, OpenFolder `O`, CustomZoom `D3`, ToggleCaptureMember `""` (empty).
* Optional (may be empty): exactly the 12 in `OPTIONAL_NAMES`, in that order: LastImage, ZoomActualSize, ToggleInfoOverlay, MoveToFolder, CopyToFolder, ClickZoom, FitWidth, FitHeight,
  ToggleKeepZoom, OpenFolder, CustomZoom, ToggleCaptureMember. Mandatory: the other 14 (including the legacy MoveToFolder2).
* `is_optional(name)`: ordinal, case-sensitive, no trimming (`"lastimage"`, `" LastImage"`, `"LastImage "` and `""` are false).
* `PROPERTY_NAMES` is the C# reflection list: the 26 string properties, declaration order. `OPTIONAL_NAMES` is NOT part of it (it is a static field in C#).
  `entries()` returns the 26 `(name, value)` pairs in that order; `get(name)`/`get_mut(name)` look up by exact, case-sensitive property name and return `None` for anything else,
  including `""`, `"next"` and `"OptionalNames"`.
* Serde: PascalCase names, declaration order, a missing property keeps its default, unknown properties are ignored (already declared with `#[serde(rename_all = "PascalCase", default)]`).
  The golden `json` is exactly `serde_json::to_value(default)`. A test must also round-trip it.

`canonicalize(name)` (`ShortcutKeyCanonical.Canonicalize`)
1. `None` gives `""`. Otherwise trim (`str::trim`, Unicode whitespace; U+00A0, U+3000, U+2003, U+0085, VT and FF are trimmed; U+200B, U+FEFF and U+0000 are NOT).
2. Empty after trimming gives `""`.
3. Look the trimmed text up among all 29 aliases AND all 29 canonical names. The comparison is ASCII case-insensitive (`str::eq_ignore_ascii_case`). A match returns the CANONICAL name with
   its table spelling (`"enter"` gives `"Enter"`, `"RETURN"` gives `"Enter"`, `"prior"` gives `"PageUp"`, `"pagedown"` gives `"PageDown"`).
4. **Twist (the one place the general OrdinalIgnoreCase helper is wrong):** C# looks the name up in a `FrozenDictionary` built with `StringComparer.OrdinalIgnoreCase` over ASCII-only keys, and (observed in the golden) that
   structure never matches a non-ASCII input. So text containing ANY non-ASCII character after trimming is never an alias: `"\u{212A}anaMode"` (Kelvin sign, which `eq_ignore_case` would
   equate with `K`), `"Capıtal"`, `"Snapſhot"`, fullwidth `Ｏem1` are all returned trimmed and unchanged. Use `eq_ignore_ascii_case`, NOT `pr_core::text::eq_ignore_case`; the golden has these rows.
5. No match: return the trimmed text unchanged, whatever it is: `"f11"` stays `"f11"`, `"Bogus"`, `"Return,Enter"`, `"Ctrl+Return"`, `"Return+"` (no splitting, no modifiers), `"Add"` and `"OemPlus"` (look-alikes, not aliases).
6. Idempotent: `canonicalize(canonicalize(x)) == canonicalize(x)` and `canonicalize(" " + once + " ") == once`.
A linear scan over `ALIAS_PAIRS` (58 comparisons) is fine; no lazy static needed. No name occurs twice in the table, so the scan order does not matter.

`canonicalize_all(shortcuts, actions)`: for each of the 26 properties set `value = canonicalize(Some(value))` (all 26, mandatory and optional and the legacy MoveToFolder2; an empty optional stays
empty), then for every action `shortcut = canonicalize(Some(&shortcut))`. Nothing else is touched (not `name`, `destination`). The `AppSettings` wrapper of C# also tolerates a null `Shortcuts`/`Actions`
and null list entries; those cannot exist in Rust, so there is nothing to port.

`ReviewAction`
* Field defaults (C# property initialisers): shortcut `Enter`, operation `Move`, destination `Group-2`, confirm `false`, name `Tr.ActionDefaultName(2)` (localized). `ReviewAction::new(name)` is complete.
* `defaults(action_default_name, backup_name)` returns the four actions, in this order: (`action_default_name(2)`, `Enter`, Move, `Group-2`), (`action_default_name(3)`, `F3`, Move, `Group-3`),
  (`action_default_name(4)`, `F4`, Move, `Group-4`), (`backup_name`, `F5`, Copy, `Backup`); confirm false for all. The English catalog says `Action {n}` and `Backup`, the Vietnamese one
  `Loại {n}` and `Sao lưu`; folders are language-neutral. The `Tr` lookup is replaced by the two parameters because `pr-core` cannot see the language catalogs (`pr-l10n`).
* JSON (D-09, config.json `Actions`): `{ "Name", "Shortcut", "Operation", "Destination", "Confirm" }`, `Operation` written as the enum NAME (`Move`, `Copy`, `Recycle`). Only `Serialize` is derived; see
  open questions.

## Open questions

1. `ReviewAction` deserialization: C# fills a missing `Name` with the localized `Tr.ActionDefaultName(2)` of the CURRENT language, which Rust can only do with the catalog.
   Proposal: the settings unit deserializes actions through a private mirror struct with `Option<String>` for the name and fills it from `pr-l10n`; hence no `Deserialize` here.
2. The C# validator and normalizer reflect over the `ShortcutMappings` properties; Rust code in those units must use `PROPERTY_NAMES`/`entries()`/`get_mut()` from this file.
   If they also need to skip `MoveToFolder2` (legacy alias ignored by the validator), they do it by name.
3. JSON `null` for a shortcut string (C# stores a null `string`, then `CanonicalizeAll` skips it) cannot be represented by `String`; with `#[serde(default)]` a `null` is a
   serde error for the field. The settings load pipeline (salvages property by property) must decide what to do. Not tested here.
