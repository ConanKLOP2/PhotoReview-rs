## Required behavior

- `InstanceKeys::for_mode(mode, folder, prefix)` returns the paired mutex and pipe names. Reject a blank prefix.
- Default prefix is `PhotoReview`. For `SingleWindow`, use `Local\\{prefix}_App_{SHA256_HEX(UTF8("app|" + current SID))}`;
  folder spelling must not affect the result. For `PerFolder`, use
  `Local\\{prefix}_{SHA256_HEX(UTF8(canonical key))}`.
- Canonical folder key: null/whitespace becomes the constant `PhotoReview`; otherwise resolve to a full path, trim only
  the ending directory separator, and uppercase invariantly. If path canonicalization throws for the C#-listed invalid
  path exceptions (`ArgumentException`, `NotSupportedException`, `PathTooLongException`), uppercase the original input
  instead of failing lock lookup.
- Pipe name is derived from mutex name, current user SID, and current session id using W6-03b's exact formula. Keep the
  C# `PhotoReview` namespace strings and hashing input byte-for-byte for cross-build discovery.

## Concurrency and safety

- Identity/session data is process-local and read once; do not open or mutate C# application state. No mutex is created
  by this unit. Never use the user's real production prefix in tests; use unique prefixes.
- Windows identity/session lookup is host dependent. Keep pure hashing/canonicalization tests separate from any native
  identity smoke test; if native coverage is added, ignore it with a `native` reason and bound it.
- Mutations expected to be killed: mode branch, folder canonicalization/uppercasing/trailing-separator trim, fallback for
  invalid paths, prefix validation, SHA-256 input separators, and pipe pairing identity/session components.
- Gates: `cargo fmt --all --check`; `cargo clippy -p pr-platform-win --all-targets -- -D warnings`;
  `cargo test -p pr-platform-win`; final integration uses the workspace gates.
