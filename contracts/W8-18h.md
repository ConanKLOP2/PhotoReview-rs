## Semantics (C# is the spec)
1. **`DialogError`** and the `From`s exist so `?` works (`build(..)?`, `run_nested(..)?`). `Display` texts: the C# messages (`AlreadyShown`: "A NativeDialog instance can be shown once."; `CreateFailed`: "CreateDialogIndirectParam failed (Win32 error {code})."; the other two print their inner error).
2. **`NativeDialog::with_chrome`**: builds `DialogInner` with `ModalState::new()` (`result = ID_CANCEL`, nothing allocated), `MetricsState::new()`, `ControlsState::new()`, `EventsState::new()`, `TipState::new()`, `DrawState::new()`; `chrome = chrome.unwrap_or_else(default_chrome)`. No window, no cookie, no OS call. `new(content)` is `with_chrome(content, None)`.
3. **Getters** read the state (`hwnd` = `modal.hwnd`, `is_closed` = `modal.done`, `dpi`, `body_font` = `metrics.font`, `self_ref_data` = `modal.self_cookie as usize`).
4. **`default_chrome()`**: a `thread_local!` `Rc<DarkDialogChrome>` created on first use with `DarkDialogChrome::new(Rc::new(NoPainter))` (D-W8B5-305; `NoPainter` is a private unit struct implementing `ChromePainter` with `false` everywhere); the same `Rc` for the whole thread.
5. **Cookie** (D-W8B5-304): `make_cookie(inner)` = `Box::into_raw(Box::new(Rc::clone(inner))) as isize`; `from_cookie(0)` = `None`; else `Some(NativeDialog { inner: (*ptr).clone() })` (clone the `Rc`, never take ownership); `free_cookie(0)` no-op, else `drop(Box::from_raw(ptr))`. Every `unsafe` block has a `// SAFETY:` comment naming the contract (cookie from `make_cookie`, not freed).
6. **`dialog_proc`** (algorithm in the stub doc). The body is `catch_unwind(AssertUnwindSafe(|| ...))`; on `Err(payload)`: `pending_panic::capture(payload)`, then `dialog.end_modal(ID_CANCEL)` when a dialog was found, result `0`. That `end_modal` runs OUTSIDE the `catch_unwind`: for a modeless dialog it runs `cleanup`, which calls the `closed` callback, and a panic of that callback would unwind out of the `extern "system"` procedure (an abort). So the error arm calls it as `pending_panic::guarded((), AssertUnwindSafe(|| dialog.end_modal(ID_CANCEL)))` too (the first captured payload wins). The unsafe operations: `set_window_long_ptr(hwnd, DWLP_USER, lparam)` (SAFETY: `lparam` is the cookie this crate passed to `create_dialog_indirect_param`; `DWLP_USER` is the dialog's private slot), `from_cookie`. A zero `DWLP_USER` (messages before `WM_INITDIALOG`, after `cleanup`) returns `0` without a dialog.
7. **`handle_message`**: the `match` of the doc, in the C# order, each case one line calling the member of the owning slice. It owns only the answers listed in the C# section. Nothing else; no OS call of its own except `set_window_long_ptr(hwnd, DWLP_MSGRESULT, r)` in the default arm (SAFETY: `DWLP_MSGRESULT` is the dialog's own result slot).
8. **`show_modal` / `show_modeless`**: the numbered steps of the stub docs, one private function `create_window(&self, owner: Hwnd) -> Result<(), DialogError>` may share steps 1 to 6 (the C# duplicates them; the `CleanupGuard` stays in the caller); behaviour identical to each C# method, including: the `Err(Template)` leaves `used = true` and allocates nothing; a `create_dialog_indirect_param` failure sets `hwnd = 0`; `ready` runs only when `!done`; the modal path never runs `run_loop` when `ready` closed the dialog; the modeless path never disables the owner. `get_module_handle()` failing gives instance `0` (the OS then uses the process module).
9. **`end_modal`** exactly as the stub doc: a dialog closed BEFORE it was shown keeps its result: `end_modal(ID_OK)` then `show_modal` creates the window, sees `done`, skips show and loop, cleans up and returns `ID_OK`.
10. **`run_loop`**: with a loop `message_loop.run_nested(&mut || self.is_closed(), Some(&mut |m| self.claim_dialog_message(m)))` (`is_closed` is the `done` getter; there is no `is_done`); the two closures borrow `self` shared. `Ok(true)` -> return `Ok(())`. Without a loop the `GetMessage` loop of the C#; `is_dialog_message` is `unsafe` (SAFETY: `msg` came from `get_message`).
11. **`ModelessFilter`**: registered with `add_message_filter(Rc::new(ModelessFilter { dialog: Rc::downgrade(&self.inner) }))`; the returned `MessageFilterId` is `modal.filter_id` (18k removes it).
12. **No `unwrap`, `expect`, `panic!` or indexing that can panic** in this file (R0003). A hook panic is handled by `dialog_proc`; a panic in `ready` unwinds through the guard (D-W8B5-307).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T3 (arithmetic): `wparam & 0xFFFF` and `(wparam >> 16) & 0xFFFF` on `usize` (mask first, then narrow); `default_button_id as usize` for `DM_SETDEFID` is 18j's; `wparam as u32 != SIZE_MINIMIZED` is 18i's.
- T8 (null vs empty): `owner == 0` means no owner; `closed`/`ready` are `Option`.
- T9 (exception to Result): the four C# throw sites are the four `DialogError` variants; the `catch` of `DialogProc` is `catch_unwind` + `capture`; `catch { Cleanup(); throw; }` is "cleanup, then return the `Err`" (no panic involved) and, for a panic in `ready`, `end_modal` + `resume_unwind`.
- T10 (order): the order of the steps of `show_modal` (owner disabling BEFORE `ShowWindow`; `ready` AFTER `SetForegroundWindow`), of the router cases and of the `Cleanup` call are observable; keep them.
- T1/T2 (strings): none; the class names are the OS ones.
- Handles (R0003): all `!Send`; no `Rc` cycle (content does not hold the handle; the loop holds the filter, the filter holds a `Weak`); `Drop` of the last handle after `cleanup` frees `DialogInner`.
- Re-entrancy: `show_modal(&self)` can be re-entered by a hook (`close()`, `end_modal`); never hold a `RefCell` borrow across `create_dialog_indirect_param`, `run_loop`, a hook or `ready`.
