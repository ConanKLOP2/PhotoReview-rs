- Semantics (exact; the C# is the spec, this list says where Rust differs in shape):
  1. **Error model (three C# `catch`/throw sites).** `source.read` may return `RawHeaderError::{InvalidData, ArgumentOutOfRange, Canceled}`. C# catches ONLY `InvalidDataException when !IsIoFailure` (in `ResolveDimensions` and `ResolveColorSpace`).
     So: `Err(RawHeaderError::InvalidData { io: None, .. })` => swallowed (see 6/7); EVERY other `Err` (`InvalidData` with `io: Some`, and also `ArgumentOutOfRange`/`Canceled`) => propagated unchanged. Do NOT write `if !e.is_io_failure()`:
     that would also swallow `ArgumentOutOfRange`. `try_read_jpeg_frame` / `walk_jpeg_header` themselves swallow nothing (unlike the W5-02b probe): budget exhaustion is an `Err(InvalidData)` there.
  2. **`select_preview_resolved` flow.** `state = previews.to_vec()` (C# `ToList()`, so the caller's list is never touched); `idx = select_preview_core(..)?`; `chosen = state[idx].clone()`; if `chosen.kind == Jpeg`: `chosen = resolve_color_space(source, &chosen)?` and write it back into `state[idx]`.
     Return `PreviewSelection { chosen, resolved_previews: state }`. C# `Replace(state, original, resolved)` finds the slot by REFERENCE; Rust writes by index, which is the same slot (C# lists never hold one object twice; golden `duplicate-equal-previews-resolved-each-in-place`).
     `select_preview` = `.chosen` of it. An empty list is `Ok(PreviewSelection { chosen: None, resolved_previews: vec![] })` with no read (golden `*-empty-previews-reads-nothing`).
  3. **`select_preview_core`.** `jpeg` = indices of `state` whose `kind == Jpeg` (all of them while the enum has one variant). No JPEG => `Some(0)` (dead code, keep). Exactly one => `resolve_dimensions` it, write back, return it (the box is NOT consulted: golden
     `single-known-preview-ignores-box`). Several => stable-sort the INDICES by `state[i].length` DESCENDING (`sort_by(|&a, &b| state[b].length.cmp(&state[a].length))`, the std sort is stable: equal lengths keep input order) and call
     `resolve_dimensions` on EVERY one in that order (C# comment: "no early stop", the choice depends on every pixel size). The ORDER IS OBSERVABLE through the 8 MiB budget (golden `budget-one-block-left-longer-preview-is-walked-first[-input-swapped]`).
  4. **Choosing.** `reqW = box.width`, `reqH = box.height`. `box.is_unbounded()` (both `<= 0`) => best of all resolved candidates. Otherwise keep those with `visW >= reqW` and `visH >= reqH` where `(visW, visH)` = `(height, width)` when
     `pr_imaging::orientation::is_transposed(orientation)` (5..=8) else `(width, height)`, a test applied only for an axis whose request is `> 0` (`reqW > 0 && reqH > 0` => both; only `reqW > 0` => width only; only `reqH > 0` => height only; the C# final `return true` is
     unreachable after the unbounded check: keep it). Candidates non-empty => the SMALLEST by `(score, length)` ascending; empty => the BEST by `(score, length)` descending (same as unbounded). **Ties go to the FIRST candidate in the length-descending order**
     (C# `OrderBy/OrderByDescending` are stable and take `.First()`). `Iterator::max_by`/`min_by_key` return the LAST maximum / FIRST minimum: write explicit loops with a strict comparison (`>` for best, `<` for smallest) or a stable `sort_by` + `first()`;
     goldens `equal-score-equal-length-*`, `equal-everything-unbounded-first-wins`, `equal-score-longer-wins-unbounded`, `equal-score-shorter-wins-in-box`.
  5. **`score`.** Known size means `width > 0 && height > 0` (a NEGATIVE width with a positive height is UNKNOWN: golden `negative-width-known-height-is-unknown-and-walked`). Known: `(if max(width, height) >= 1000 { 1 } else { 0 }, i64::from(width) * i64::from(height))`.
     Unknown: `(0, if length <= 0 { 0 } else { length.wrapping_mul(4) })`: C# `long` arithmetic is unchecked (Directory.Build.props has no overflow check), so `length > i64::MAX / 4` WRAPS: `2^62` scores `(0, 0)`, `i64::MAX` scores `(0, -4)` (goldens
     `unknown-length-2^62-score-wraps-to-zero`, `unknown-length-int64-max-score-wraps-negative`). Tuples compare lexicographically (`(i32, i64)` implements `Ord`). The score is never reported as a dimension.
  6. **`resolve_dimensions`.** Unchanged (same value, not marked) when `header_resolved || (width > 0 && height > 0)`, or `offset < 0 || offset >= source.length() || length < 4`. Otherwise `walk_jpeg_header(source, offset, length, true)`:
     `Ok(walk)` => copy with `width = frame.0`, `height = frame.1` when a frame was found (else both kept), `color_space = walk.color_space` when not `Unknown` (else kept), `header_resolved = true` (also when no frame was found: the APP1s before a lossless or truncated frame were looked at,
     so the colour space is final); `Err(InvalidData { io: None })` => the preview unchanged and NOT marked, so a later call may try again (golden `budget-spent-*`, `*-throw-invalid-*`); other `Err` => propagate. A PARTIALLY known size (`(0, 500)`, `(500, 0)`) is walked and BOTH sides are replaced when a frame is found.
  7. **`resolve_color_space`** (only for the chosen preview, only when `kind == Jpeg`). Unchanged when `header_resolved || color_space != Unknown || offset < 0 || offset >= source.length() || length < 4`. Otherwise `walk_jpeg_header(.., false)` (stops at the first frame-header marker; the size is NOT touched, so a DECLARED size
     wins over the JPEG's own: golden `real-jpeg-declared-size-wins-over-actual`) and a copy with `color_space` (kept when the walk saw none) and `header_resolved = true`. Same error mapping as 6. A known-size preview is therefore walked once, at most, and only if it is the chosen one.
     NOTE (observable): a chosen UNKNOWN-size preview whose `resolve_dimensions` walk failed with a swallowed error is NOT marked resolved, so `resolve_color_space` walks it AGAIN (a second set of reads, `need_frame = false`). That second walk stops at the SOF, so it can succeed where the first ran out of budget on the frame/payload read, and then the preview comes back `header_resolved = true` with width/height STILL 0. Do not "optimise" the retry away.
  8. **`walk_jpeg_header` (the loop is the spec; reads are observable: golden `read_count`, `bytes_charged`).** Range check, in this order and BEFORE any read: `length < 4 || offset < 0 || offset >= source.length()` => `{ frame: None, color_space: Unknown }`.
     `end = min(offset.wrapping_add(length), source.length())` (C# unchecked `long`: `offset = 1`, `length = i64::MAX` wraps to a NEGATIVE end; the next test is `end.wrapping_sub(offset) < 4`, which is then false, so the 2-byte SOI read STILL happens and the loop does not run: goldens
     `soi-at-offset-{1,2}-length-int64-max-overflows-the-end`, `soi-at-offset-2-length-int64-max-minus-1-overflows-the-end`, `soi-at-offset-1-length-int64-max-minus-1-does-not-overflow` (1 + (MAX-1) = MAX, no wrap), `length-int64-max-offset-0-is-clamped`; `offset + length` with plain `+` would panic in debug builds). `end.wrapping_sub(offset) < 4` => none. `read(offset, 2)` must be exactly `[0xFF, 0xD8]` (a shorter or different slice => none; an `Err` propagates).
     `pos = offset + 2`, `fill_bytes = 0`, `segment = 0`, `color_space = Unknown`. Loop `while segment < MAX_JPEG_MARKER_SEGMENTS (512) && pos + 4 <= end`:
     - `head = read(pos, 4)` copied at once into a `[u8; 4]` (the borrow checker forbids keeping the slice across the next read); a shorter slice ends the walk. `head[0] != 0xFF` => break. `marker = head[1]`.
     - `marker == 0xFF` (fill byte): `fill_bytes += 1; if fill_bytes > MAX_JPEG_FILL_BYTES (65 536) => break`; `pos += 1`; `continue` WITHOUT consuming a segment iteration (the C# `segment--` before the `for` increment). Each fill step is a separate 4-byte read (pinned by `read_count`).
     - every other marker: `fill_bytes = 0`. `marker == 0x00 || 0xDA || 0xD9` => break. `marker == 0x01 || 0xD0..=0xD8` (standalone, includes a second SOI) => `pos += 2`, and it DOES consume a segment iteration (goldens `standalone-markers-{511,512}-then-frame`).
     - `seg_len = head[2] << 8 | head[3]`; `seg_len < 2 || pos + 2 + seg_len > end` => break. `payload_len = seg_len - 2`.
     - SOF candidate = `0xC0..=0xCF` except `0xC4`, `0xC8`, `0xCC` (those three are ordinary segments): if `!need_frame` => return what was learned (frame none). `marker > 0xC2 || payload_len < 5` => return none (SOF3 lossless, arithmetic, hierarchical end the walk; the next SOF is NOT searched).
       Else `read(pos + 4, 5)` = precision, height (BE u16), width (BE u16). **The precision is NOT checked** (W5-02b's probe does; golden `sof-precision-12-is-accepted-here`). `frame = Some((width, height))` only when both `> 0`. Either way the walk ends here.
     - `marker == 0xE1 && payload_len >= 14 && color_space == Unknown` (APP1): `read(pos + 4, payload_len)` (up to 65 533 bytes in ONE read) and `is_adobe_rgb_exif(payload)` (used immediately, never stored); when true `color_space = AdobeRgb` and, if `!need_frame`, return at once. A false result leaves
       `Unknown`, so a LATER APP1 can still set it; once `AdobeRgb`, later APP1s are not read at all (goldens `exif-second-app1-adobe`, `exif-first-app1-adobe-second-not`). Only APP1 counts: an EXIF payload in APP2 is ignored.
     - `pos += 2 + seg_len`, `segment += 1`.
     Loop exit without a frame (cap, range exhausted, fill run reaching the end) => none, with the colour space seen so far. `try_read_jpeg_frame` = `walk_jpeg_header(.., true)` mapped to `Some(JpegFrame { width, height, color_space })` when a frame exists.
  9. **`is_adobe_rgb_exif`.** `payload.len() < 14` or not starting with `Exif\0\0` => false. `tiff = payload[6..]`; byte order from `tiff[0..2]` (`II` little, `MM` big, anything else, including `IM`/`MI`, false); `read_u16(tiff, 2) != 42` => false.
     `ifd0 = read_u32(tiff, 4)` (widened to `i64`). `exif_ifd = try_find_long_entry(tiff, ifd0, 0x8769)?`, `interop_ifd = try_find_long_entry(tiff, exif_ifd, 0xA005)?`, `entry = try_find_entry(tiff, interop_ifd, 0x0001)?`, then ALL of: `read_u16(entry + 2) == 2` (ASCII),
     `read_u32(entry + 4) == 4`, `entry + 12 <= tiff.len()`, bytes `tiff[entry + 8 .. entry + 12] == b"R03\0"`. `try_find_long_entry`: entry found AND `type == 4` AND `count == 1`, value = `read_u32(entry + 8)`. `try_find_entry`: `ifd_offset < 8 || ifd_offset + 2 > tiff.len()` => none;
     `count = read_u16(ifd_offset)`; for `i in 0..count`: `entry = ifd_offset + 2 + 12 * i` (i64); `entry + 12 > tiff.len()` => none (stop, do not skip); first entry whose tag equals wins (a malformed first match hides a good second one: golden `first-matching-tag-wins-bad-first-pointer-*`).

One IFD may serve as IFD0, Exif and Interop

## Open questions
1. **Who owns the 3 corpus tests.** They call `RawContainerReaderRegistry::find_reader` (W5-11a) and the file-backed `SourceRawHeaderSource` (W5-12), which do not exist when this unit is scheduled (P-28: start a unit when its dependencies are merged). Recommended: this unit does NOT write
   `tests/preview_selector_corpus.rs`; the lead hands those three tests to whoever merges last of W5-11a / W5-12 (their `// C#:` comments are listed above). Alternative: schedule W5-11b after both and keep the file here. Either way nothing else in this contract changes.
2. **`NoJpegPreviewKind_FallsBackToTheFirstPreview` has no twin** because `EmbeddedPreviewKind` has a single variant (C# casts `7`). If the lead wants a `#[non_exhaustive]`/second variant in W5-01b, add the test then; the stub already keeps the branch.
3. **`is_adobe_rgb_exif` visibility.** `pub` + `#[doc(hidden)]` (recommended; integration tests and the fuzz twin need it). Alternative: `#[cfg(test)]` unit tests inside `preview_selector.rs` and `pub(crate)`; then the integration tests of this file lose 12 tests (the goldens cannot call it).
4. **`read_count` strictness.** A faithful port makes exactly the C# reads, so the golden pins them. A future optimisation (skipping a fill-byte run with one larger read) would change `read_count` but not `bytes_charged`; if the lead wants room for that, relax the comparison to `<=` for the `fill-*` cases only.
5. **Test builders.** `minimal_jpeg(w, h)`, `exif_with_interop_index`, `jpeg_with_exif`, `as_lossless_jpeg`, `fuji_shaped_jpeg` are private to `tests/preview_selector.rs`; W5-12's `RawDecoder` tests need the first three as well (C# `RawDecoderTests.cs:371` calls `PreviewSelectorColorSpaceTests.ExifWithInteropIndex`).

6. **Range-end overflow is reproduced, not fixed.** `offset > 0 && offset + length > i64::MAX` wraps in C# and the walk then reads the SOI and stops. Production callers pass container-derived lengths (bounded by the file), so this is only reachable through hostile callers; the golden pins the C# behaviour. If the lead prefers saturating arithmetic, the golden cases `soi-at-offset-{1,2}-length-int64-max-overflows-the-end` and `soi-at-offset-2-length-int64-max-minus-1-overflows-the-end` change from `ok false` to the clamped (found) result.
7. **`read` count type.** W5-01b fixes `count: i32`; the only non-literal count in the walk is the EXIF payload read (`payload_len <= 65 533`), written `i32::try_from(payload_len)` (cannot fail). If W5-01 settles on `usize` instead, only that one call changes.
