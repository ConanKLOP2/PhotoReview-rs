## Decisions (each has a recommended default; the stubs follow them)
- **D-W8-10c-1 Selected language is the code.** C# `SettingsFormState.SelectedLanguage` is a `LanguageOption` record, which belongs to
  W8-04a (not merged). The only reads of it are `LanguageOptions.ToSetting(selected, current)` (uses `Code` and `IsAuto`, and `IsAuto` is
  a function of `Code` alone) and `ExportTranslation(SelectedLanguage())` (uses the code). So the form stores `Option<String>` (the code,
  `None` = C# null). Lossless for both reads, and it removes the dependency on W8-04a, so this unit is B1. The display name is not needed
  by any reader of the form. Alternative: store `LanguageOption` after W8-04a merges (a type change in 10c and 10d). Lead: confirm in
  `contracts/README.md`.
- **D-W8-10c-2 Number formatting is injected.** The C# presenters format with `CultureInfo.CurrentCulture` (`N0`, `P1`). `pr_l10n` has the
  culture's sign and decimal separator only (`template::NumberCulture`), not the group separator or the percent pattern. A `NumberFormatting`
  trait keeps `pr_l10n` gaps out of the presenters. Production implementation: composition root (W8-09a/b), from the Windows user locale
  (open question OQ-1). Tests: a hand-written en-US implementation.
- **D-W8-10c-3 Texts come from an explicit `&Localizer`.** Not the generated `pr_l10n::tr::*` accessors, which read the global
  `Localizer::current()`. Explicit parameters let tests run in parallel with two languages, with no global state (C# needed the
  `GlobalState` collection). Keys are the constants of `pr_l10n::keys` (`keys::DIAGNOSTICS_NOT_AVAILABLE`, ...), and the one plural key
  is `localizer.format_plural("batchReview.summary", count, args)` (the generated module has `BATCH_REVIEW_SUMMARY_ONE/OTHER` only).
- **D-W8-10c-4 `try_accept` returns `Result<(), String>`.** C# returns `string?` (null = accepted). `Ok(())` is null, `Err(message)` the refusal.
- **D-W8-10c-5 Unit structs with associated functions** mirror the C# static classes (`DiagnosticsPresenter::build`, ...). Only
  `ClickZoomCustomPresenter` holds state.
- **D-W8-10c-6 Deterministic collections.** `BTreeMap` for `ShortcutTexts`, `BTreeSet` for `ContextMenuShown`. The C# containers are
  order-free (lookups only), so this changes no behaviour and keeps `Debug` output stable. No `HashMap` iteration anywhere.

## Semantics (C# behaviour each test checks)
1. **Form state defaults** (C# property initialisers): every string empty, every int `0`, every bool `false`, every double `0.0`,
   `ExifInfoFields` and `TitleBarFields` are `default(struct)` = bits 0 = `NONE` (not their `DEFAULT`), `ShortcutTexts` and
   `ContextMenuShown` empty, `SortModeTag` and `SelectedLanguage` `None`, `ActionsJson` empty.
2. **Form state has no methods** besides `Default`. Missing shortcut keys are NOT an error here: readers (views) use the empty default.
3. **Save result**: `saved()` is `{ Saved, None, None }`. `SettingsFieldError::new(m, f)` keeps both values.
4. **ClickZoomCustom initial text** is the invariant decimal digits of `current_percent` (`150`, `-5` for a negative input).
5. **ClickZoomCustom accepts** exactly the whole numbers in `[MIN_CLICK_ZOOM_PERCENT, MAX_CLICK_ZOOM_PERCENT]` (10 to 800); the accepted
   value is stored (`value()`); a refusal returns `dialog.settingsInvalid.clickZoomPercent` (`{min}` = 10, `{max}` = 800) and keeps the
   last accepted value. Parsing rule in T1.
6. **Diagnostics `build`**, field by field (`C#` line numbers in the source above):
   - `cache_hits`, `cache_misses`, `stat_count`, `session_writes`, `cross_thread_presents`: `grouped_i64(value)`.
   - `hit_rate`: `total = hits.wrapping_add(misses)`; `total == 0` gives `diagnostics.notAvailable`, else
     `percent_one_decimal(hits as f64 / total as f64)`.
   - `source_bytes`: `diagnostics.value.bytes` with `{value}` = `grouped_i64(source_bytes_read)`.
   - `source_reads`: `grouped_i64(source_reads)`.
   - `decode_time`: `unit.milliseconds` with `{value}` = `grouped_i64(decode_milliseconds)`.
   - `present_latency`: `presented_images == 0` gives `diagnostics.notAvailable`; else `diagnostics.value.presentLatency` with `{average}` =
     `grouped_f64(present_milliseconds as f64 / presented_images as f64)` and `{count}` = `grouped_i64(presented_images)`.
   - `explorer_order`: `explorer` is `None` gives `diagnostics.explorerOrder.notQueried`; else `diagnostics.explorerOrder.status` with
     `{status}` = `status_text(status)` and `{detail}` = `reason_text(r)` when `reason` is `Some(r)` (even an empty string), otherwise
     `diagnostics.explorerOrder.itemCount` with `{count}` = `ordered_paths.len()`.
   - `explorer_metadata`: `explorer` is `None` gives `diagnostics.notAvailable` (NOT "not queried": T9); else
     `diagnostics.explorerMetadata` with `{count}` = `sort_columns.len()` and `{groupState}` = `group_state_name`.
   - `source_opens`: `source_open_count == 0` gives the literal `"0"` (not localized); else `diag.sourceOpens.summary` with `{total}` =
     `grouped_i64(source_open_count)` and `{top}` = the entries joined with `diag.list.separator`, each entry being
     `diag.sourceOpens.entry` with `{name}` = `file_name(path)` and `{count}` = the raw integer (T10).
   - `decoder_fallbacks`: `grouped_i64(decoder_fallback_count())` (the pr-core method, T14).
   - `present_histogram`: empty gives `diagnostics.notAvailable`; else each bucket is `diag.histogram.bucket` with `{label}` = the label
     text and `{count}` = `grouped_i64(count)`, joined with the separator, in the snapshot's order.
7. **`reason_text`** (C# `ReasonText`): parse the wire text with `pr_core::catalog::explorer_reason::parse` (code plus details). Detail `i`
   is `details[i]` or `""` when absent. Mapping (argument names are the catalog placeholders; the detail index is the order of the
   placeholders in the text):
   | code (constant) | key | arguments |
   |---|---|---|
   | `TIMEOUT` | `diag.explorerReason.timeout` | none |
   | `CANCELED` | `diag.explorerReason.canceled` | none |
   | `QUERY_FAILED` | `diag.explorerReason.queryFailed` | `errorType` = d0 |
   | `SHELL_UNAVAILABLE` | `diag.explorerReason.shellUnavailable` | none |
   | `NATIVE_VIEW_FAILED` | `diag.explorerReason.nativeViewFailed` | `errorType` = d0, `hresult` = d1 |
   | `NO_MATCHING_WINDOW` | `diag.explorerReason.noMatchingWindow` | `count` = d0 |
   | `COM_CALL_FAILED` | `diag.explorerReason.comCallFailed` | `call` = d0, `hresult` = d1 |
   | `EMPTY_VIEW` | `diag.explorerReason.emptyView` | `hresult` = d0, `count` = d1 |
   | `EMPTY_PATH` / `OUTSIDE_FOLDER` / `DUPLICATE_ITEM` / `INCOMPLETE_SNAPSHOT` | `diag.explorerReason.emptyPath` / `.outsideFolder` / `.duplicateItem` / `.incompleteSnapshot` | none |
   | anything else | `diag.explorerReason.unknown` | `reason` = the WHOLE input text |
8. **`status_text`**: `Available` gives `enum.explorerOrderStatus.available`; `NoMatchingWindow` gives `...noMatchingWindow`;
   `NativeViewUnavailable` gives `...nativeViewUnavailable`; `InvalidSnapshot` gives `...invalidSnapshot`; `TimedOut` gives `...timedOut`;
   `Canceled` gives `...canceled`; `Failed` gives `...failed`. Seven different texts.
9. **`group_state_name`**: `None` -> `"None"`, `Active` -> `"Active"`, `Unknown` -> `"Unknown"` (the .NET member names). The catalog has no
   translation for them, and C# passes the enum unformatted.
10. **`file_name`** (C# `Path.GetFileName`): the text after the last `\` or `/`. Used for the batch and source-open lists (T5).
11. **Batch lines**: `build_item`: `length: Some(n)` gives `batchReview.item` with `{fileName}` = `file_name(path)`, `{size}` =
    `grouped_i64(n)`, `{path}` = the full path; `length: None` gives `batchReview.itemMissing` with `{fileName}`, `{path}`. A size of `0`
    is a size, not missing (T12). `from_paths` gives `length: None` for every path.
12. **`summary(count)`**: `format_plural("batchReview.summary", count, [count])`: one form for exactly 1, the other form otherwise (0, 2, -1).
13. **Skipped files**: `title`, `intro`, `close_text` are `main.skipped.window.title`, `main.skipped.window.intro`, `main.skipped.window.close`.
    `format_entry`: `skipped.entry` with `{path}` = the FULL path (not the file name) and `{reason}` = `skipped.reason.listingInterrupted`
    (`{detail}` = reason) for `SkippedKind::ListingInterrupted`, `skipped.reason.fileUnreadable` (`{detail}` = reason) for
    `SkippedKind::FileUnreadable`. `detail` is the OS message verbatim.

## Traps (the porter reads these before writing code; each one has a test below)
- **T1 Click zoom parsing = .NET `int.TryParse(text, NumberStyles.Integer, Invariant)`.** Allowed: leading and trailing white space made of
  U+0009 to U+000D and U+0020 only (not `char::is_whitespace`, which also takes U+00A0 and others), and one leading `+` or `-`. Refused:
  empty, all white space, `None`, `1 2`, `1,000`, `12.0`, `1e2`, `12x`, values outside `i32`. Trim with an explicit ASCII-white-space
  predicate, then `str::parse::<i32>` (which accepts a leading `+`). Range check after parsing.
- **T2 A refusal keeps the value.** `value()` changes only on `Ok`. Before any accepted text it is `0`, not the initial text.
- **T3 Hit rate zero test uses the sum.** `hits + misses == 0`, not `hits == 0`. The sum wraps like C# `long` (unchecked): `wrapping_add`.
- **T4 Percent and average are doubles.** `(double)hits / total` and `present_ms / (double)presented` divide as f64. Do not integer-divide.
- **T5 `Path.GetFileName` is not `std::path::Path::file_name`.** Rust drops a trailing separator (`C:\a\` gives `a`) and returns `None`
  for `..`; .NET gives `""` for `C:\a\` and `..` for `a\..`. Use the text after the last `\` or `/` (the stub doc). Open question OQ-3
  covers a drive-relative input such as `C:x`, which the app never produces.
- **T6 Culture number formats go through the trait only.** `grouped_i64` is `N0` (grouping), not `i64::to_string`. The source-open count
  inside `diag.sourceOpens.entry` is NOT grouped (C# passes `long` through the format, so the digits are plain). Passing the count
  through `grouped_i64` there is a bug.
- **T7 `explorer: None` means two different texts.** `explorer_order` says "not queried" (`notQueried`), `explorer_metadata` says
  `diagnostics.notAvailable`. Swapping them fails `diagnostics_explorer_snapshot` and `diagnostics_empty_snapshot`.
- **T8 `reason: Some("")` is a reason.** It goes through `reason_text("")`, which gives the unknown text with an empty tail (C# `is { } reason`
  accepts an empty string). Do not test `is_empty()`.
- **T9 The group-state word is the English member name** even in Vietnamese (the enum is passed to the format unformatted in C#).
- **T10 Source opens:** zero count gives the literal `"0"` with no key, and `top` may be empty (the summary still has its separator
  template, so `"1,000 · "` is correct for an empty top list). Duplicated paths in `top` are shown as given.
- **T11 Present latency uses `presented_images`** for both the zero test and the division. `present_milliseconds` alone is wrong.
- **T12 `Some(0)` is a known size.** `batchReview.item` shows `0`. `None` is the only missing case. A `u64` cannot be negative; C#
  `long?` negative sizes do not occur (the catalog never stores one).
- **T13 Closed enum.** `ExplorerOrderStatus` has 7 variants in Rust. C# `StatusText(42)` returns `"42"` (`ToString()` fallback), which has
  no Rust form. The `(ExplorerOrderStatus)42` / `(ExplorerOrderStatus)99` assertions are written as `// DIVERGENCE: closed enum, no
  unknown status (contracts/README.md D5)`, and the test checks the seven texts only.
- **T14 Decoder fallbacks use `decoder_fallback_count()`.** That pr-core method is `iter().sum()`, which panics on overflow in a debug
  build where C# wraps. Real counts never get close to `i64::MAX`. Do not reimplement the sum in the presenter; the lead may ask pr-core for
  a `wrapping` sum (open question OQ-4).
- **T15 `Option::None` versus `SettingsFocusField::None`.** Never `use SettingsFocusField::*`. Write `SettingsFocusField::None` in every
  focus position.
- **T16 Vietnamese strings are checked exactly** (the C# tests compare them): for example `Lệnh gọi Explorer IFolderView2.GetItem(3)
  thất bại (HRESULT 0x80004005).` The Vietnamese localizer is built as in OQ-2; no literal Vietnamese text in the source (D-W8-4).
- **T17 The `ALL_CODES` loop** replaces the C# reflection over `ExplorerReason` literals: the Rust list (12 codes) must be complete; the
  test asserts `ALL_CODES.len() == 12`.
- **T18 No `unwrap`/`expect` on user data.** The presenters never fail: a missing catalog key returns the key text (`Localizer::get`),
  so no error path exists here.

## Open questions (each has a recommended default; the stubs already follow it)
- **OQ-1 Production `NumberFormatting`.** Recommended: the composition root implements it from `pr_l10n::template::NumberCulture` plus the
  Windows user locale's group separator and percent pattern, which `pr_l10n` does not expose yet (a `pr_l10n` change is needed; it is not
  in this unit's owned files). Alternative: extend `NumberCulture` in `pr-l10n` first (a W8-04a change). Lead decides; the trait stays either way.
- **OQ-2 Vietnamese localizer in tests.** Recommended: `LanguageCatalog::try_parse` of `assets/languages/vi.json` with
  `Localizer::create(built_in_english(), &[vi], &[])`, read with `std::fs` in the test file. Pure, no `FileSystem`, no global state.
  Alternative: a `pr-test-support` helper (not in this unit's files).
- **OQ-3 `file_name` for drive-relative paths.** `C:x` and `\\server\share` are not produced by the app's full paths. Recommended: the
  text after the last separator (with `\\server\share` giving `share`), and the test does not pin `C:x`. Verifier: confirm .NET 8 on
  Windows gives the same for `\\server\share` if a Windows .NET runtime is available; otherwise keep the test out.
- **OQ-4 `decoder_fallback_count` overflow.** Recommended: keep the pr-core `sum()` (T14). Alternative: a `wrapping` fold in pr-core,
  a one-line change in a file this unit does not own.
- **OQ-5 en-US percent text.** `string.Format(en-US, "{0:P1}", 0.75)` is `75.0 %` (with a space) in .NET; the test's en-US implementation
  returns that text. The porter confirms the exact space character (U+0020 or U+00A0) in the .NET source of the culture data before fixing
  the expectation; a Windows machine with .NET can print it (`[CultureInfo]::GetCultureInfo('en-US').NumberFormat` in PowerShell).
- **OQ-6 Rounding of `N0`.** `grouped_f64` rounds half away from zero (the W8-01a rule, T5 there). Recommended: keep it; the only test is
  `diagnostics_present_latency_uses_presented_images_and_rounds_half_away` (2.5 gives 3). Alternative: half to even, if .NET proves otherwise.
