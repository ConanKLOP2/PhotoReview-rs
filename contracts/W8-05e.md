## Semantics notes

### Mouse (`mouse_gestures.rs`)
1. **`WheelGestureInterpreter::handle`, exact order (C# `Handle`):**
   (a) if `ctrl_pressed || mode != Navigate`: clear `accumulated`; return `None` if `delta == 0`, else `Zoom`. The clear happens even for a zero delta.
   (b) `Navigate`: if `delta == 0` return `None` (the sum is kept). If `accumulated != 0` and the signs differ, clear it.
   (c) `accumulated = accumulated.wrapping_add(delta)`. If the magnitude is below `NOTCH_DELTA` (120) return `None`.
   (d) `down = accumulated < 0`; clear `accumulated` (excess dropped: at most one image per event); return `Next` if down, else `Previous`.
   Golden checks: `[-119, -1]` gives `[None, Next]`; `[-119, 1]` gives `[None, None]`; `[240, 10]` gives `[Previous, None]` in Navigate
   (the sign of the first event is positive, so the first returns `Previous`, not `Next`; the golden holds the exact answer).
2. **`classify_release`**: if `dragged`: `StartKinetic` when `panned && kinetic_pan_enabled`, else `None`. Otherwise `None` when
   `press_was_consumed || !click_to_zoom_enabled`, else `ClickZoom`.
3. **`decide_click_zoom`**: `Fit` only when `!is_fit && (current_zoom - click_zoom).abs() < SAME_ZOOM_TOLERANCE` (strict). NaN gives `ClickZoom`.
   A difference of exactly 0.001 is NOT the same zoom (C# mutation-gap test). Compute the difference in `f64` exactly as C# does (no rounding).
4. **`click_zoom_factor`**: clamp the integer first (`percent.clamp(MIN, MAX)`), then `as f64 / 100.0`. C# `Math.Clamp(int, int, int)` then `/ 100.0`.
   Output is exact (golden compares `==`, not a tolerance).
5. **`resolve_keyboard_zoom_anchor`**: `Pointer` mode with `Some(p)` returns `p` unchanged. Every other case (`Pointer` with `None`, and
   `ViewportCentre` with any pointer) returns `PointD { x: viewport_width / 2.0, y: viewport_height / 2.0 }`. The division is by `2` in `f64`.
6. **`resolve_middle_click`**: table in the stub doc. `None` gives `None`. Every other variant gives `Some(ReviewCommand::<CONST>)`. The result
   must compare equal to the constant (`ReviewCommand` derives `PartialEq`, so `Some(ReviewCommand::TOGGLE_FIT)` is the assertion form).

### Touchpad (`touchpad_gestures.rs`)
7. **`TouchpadWheelClassifier::is_touchpad`**: `touchpad = hint == Touchpad || delta % NOTCH_DELTA != 0 || (in_gesture && is_within_gap(last_timestamp, timestamp))`.
   Then `in_gesture = touchpad`; if `touchpad` then `last_timestamp = timestamp`. Both branches always update `in_gesture`.
   `%` is Rust's remainder (truncating), same as C#: `-120 % 120 == 0`, `-13 % 120 == -13`.
8. **`is_within_gap(last, now)`**: `let e = now.wrapping_sub(last); e >= 0 && e <= GESTURE_GAP_MS`. Wrap-safe: `(i32::MAX - 10, i32::MIN + 10)` gives 21.
9. **`TouchpadSwipeNavigator::handle`, exact order (C# `Handle`):**
   (a) `distance = max(1, distance_per_image)`. (b) `fresh = !active || !is_within_gap(last_timestamp, timestamp)`. (c) `active = true`;
   `last_timestamp = timestamp`. (These two happen even for a zero delta: a zero message still keeps the swipe alive.)
   (d) `delta == 0` returns `None`. (e) If `fresh`, or (`accumulated != 0` and the sign of `accumulated` differs from `delta`): clear `accumulated`,
   `stepped`, `gesture_total`, `gesture_images`. (f) `accumulated = accumulated.wrapping_add(delta)`; `gesture_total = gesture_total.wrapping_add(delta)`.
   (g) `required = if stepped { distance } else { max(1, round_half_even(distance as f64 * 0.5)) }`. (h) `|accumulated| < required` returns `None`.
   (i) `down = accumulated < 0`; `remainder = accumulated - sign(accumulated) * required`; `accumulated = if |remainder| >= distance { 0 } else { remainder }`;
   `stepped = true`; `gesture_images += 1`; return `Next` if down else `Previous`.
10. **`TouchpadSwipeNavigator::reset`** clears `active`, `accumulated` and `stepped` only. `gesture_total` and `gesture_images` are kept (C# `Reset`).
    They are cleared by the next fresh swipe inside `handle`, so the golden never reads them between a reset and the next `handle`.
11. **`route`**: if `input.ctrl || !enabled || !is_touchpad`: `Ignore` when `input.horizontal`, else `MouseWheel`. Else if `can_pan`: `Pan`.
    Else: `Ignore` when horizontal, else `Navigate`. The `delta` of the input does not affect the result (the golden uses `-30` throughout).
12. **`pan_offset_delta`**: horizontal: `(delta as f64 * PAN_DIP_PER_DELTA_UNIT, 0.0)`. Vertical: `(0.0, delta.wrapping_neg() as f64 * PAN_DIP_PER_DELTA_UNIT)`,
    i.e. the C# `-input.Delta * PanDip`. The negation is done on the integer before the cast, so `delta == 0` gives `+0.0`, never `-0.0`.
    Golden: `delta = 30` vertical gives `(0, -30)`; `delta = -2147483648` vertical gives `(0, -2147483648.0)` (`wrapping_neg` keeps `i32::MIN`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7, applied to this unit)
1. **Banker's rounding (item 4):** C# `Math.Round(double)` rounds half to even. Use `f64::round_ties_even` (stable on the pinned 1.99.0),
   NOT `f64::round` (which rounds half away from zero). Visible cases: `distance 5` gives `required 2` (`2.5`), `distance 3` gives `2` (`1.5`),
   `distance 1` gives `max(1, 0) = 1`, `distance 7` gives `4` (`3.5`), `distance 199` gives `100` (`99.5`). Golden `single step: distance 5 delta -2`
   expects `Next`; `f64::round` would give `None`.
2. **Integer overflow (item 3):** C# int arithmetic is unchecked. Use `wrapping_add` for `accumulated`, `gesture_total`, and `wrapping_neg` for the vertical
   pan. A plain `+`, `-` or `-x` panics in the debug test build for `i32::MIN` or large sums. Golden: `pan offset delta=-2147483648`.
3. **`abs` panics (item 3):** `i32::abs(i32::MIN)` panics in debug. Compare magnitudes with `unsigned_abs()` (`u32`) against `NOTCH_DELTA as u32` or
   `distance as u32`. C# `Math.Abs(int.MinValue)` throws `OverflowException`; that input is unreachable (a WM delta is a 16-bit value and sums are cleared
   at every notch or image), so the golden has no such case. Do not invent an error path.
4. **Sign function:** C# `Math.Sign(0) == 0`; Rust `i32::signum(0) == 0`. The checks are `!= 0 && sign differs`, the same in both languages.
5. **Negative zero (item 4):** no output of this unit may be `-0.0`. `pan_offset_delta` negates the integer (trap 2); `click_zoom_factor` divides a
   non-negative clamped value (min 10). The oracle would write `"-0"`; the golden has none.
6. **Tolerance comparison (mutation gap test):** strict `<` on `|a - b|` in `f64`; C# and Rust agree on NaN (false, so `ClickZoom`).
   Keep the subtraction order `current_zoom - click_zoom` (only its absolute value matters, but do not reorder anyway).
7. **Clamp before divide:** `percent.clamp(MIN, MAX) as f64 / 100.0`, the integer clamp as in C#. Do not clamp the float after dividing.
   Golden holds `-2147483648` and `2147483647` as inputs.
8. **Option vs enum None (item 8):** `WheelOutcomeKind::None` and `PointerReleaseAction::None` are enum variants; `resolve_middle_click` returns
   `Option<ReviewCommand>`. Never write `None` unqualified in this module.
9. **Order of state updates (item 10 lookalike):** `Handle` in both interpreters: the clear branch runs before the add, and the timestamp is written
   before the zero check in the navigator. Re-ordering either one changes the golden outcomes for the zero-delta cases.
10. **Wrap-safe time (item 5-like):** `is_within_gap` uses `wrapping_sub`; `now < last` is "not within the gap" only through the `e >= 0` check
    (golden `within gap last=0 now=-1` expects false).
11. **Undefined enum values:** C# `Resolve((MiddleClickAction)99)` returns `null`. A Rust `MiddleClickAction` is closed (the lenient parse in
    `pr_core` maps unknown text elsewhere, W1-02). The `Undefined` row of `Resolve_NoneAndUndefined_DoNothing` is therefore not ported; `None` is.
    `Resolve_EveryDefinedActionExceptNone` iterates an explicit array of the 10 non-`None` variants (no `Enum.GetValues` in Rust).
12. **Ticks and cumulative state across calls:** `TouchpadSwipeNavigator` and `WheelGestureInterpreter` are stateful; the tests use one instance per
    sequence, as the C# tests do (`Swipe(navigator, ...)` helper and the local `wheel`).
