## Semantics (C# is the spec)
### Ownership graph and lifetimes (D-W8B4M-1)
`MainWindow` (owner handle, `Drop` = `Dispose`) -> `Rc<MainWindowInner>` -> { `Rc<ShellWindow>`, `Win32UiDispatcher` clone, `SharedViewModel`, `Rc<dyn MainViewport>`, `RefCell<Option<D2dRenderSurface>>`, `RefCell<Option<Rc<WindowImageCache>>>`, features, per-feature state }.
Every closure that the window gives away (window events, viewport callbacks, hub handler, cache-cleared listener, posted jobs) holds a **`Weak<MainWindowInner>`** (or only the `MainWindowId` when it must be `Send`); a strong `Rc` there would keep the window alive for ever (same rule as `ShellWindowInner`, D-W8B3H-18). `Rc::new_cyclic` builds the inner state (`weak_self`).
Drop order does not matter for correctness: `dispose_inner` (13h) is the authority and is idempotent; `Drop for MainWindow` calls it with `rethrow = !std::thread::panicking()`.
### Constructor (`MainWindowInner::new`, C# 84-123; the ORDER is behaviour)
1. Copy the collaborators; `mark` defaults to `pr_core::diagnostics::perf::startup_mark`. 2. Build the viewport: `(deps.viewport_factory)(ViewportCallbacks { content: weak -> content_from_viewer, update_fit_size: weak -> update_fit_size })`. A callback whose window is gone returns `ViewportContent`'s empty value / does nothing.
3. Install the size accessor: `size_source.set_viewport_size_fn(Arc::new(move || *published.lock()))` (`ViewportSizeFn` is `Send + Sync`, the viewport is not: D-W8B4M-12), publish the initial `viewport.viewport_size()`, and subscribe `viewport.subscribe_layout_updated` to republish after every layout pass (id in `layout_subscription`).
4. `viewer.borrow_mut().set_dpi_scale(window.dpi_scale())` (the returned changes are dropped: nothing is subscribed yet, as in C#). 5. `register_features()`. 6. Subscribe on the window, in this order: `subscribe_render(on render -> render_frame)`, `ClientSizeChanged`, `DpiChanged`, `subscribe_closing`, `Closed` (ids in `window_subscriptions`). The ORDER of subscriptions is observable: features subscribed in step 5, so their `Closed` runs before `on_closed`; and the startup code subscribes its `Closing` AFTER the window exists, so `on_closing` runs before it.
7. `hub.subscribe_image_changed(on_hub_image_changed)` (id in `hub_subscription`). 8. Register in the thread-local registry (`id` from a process counter). 9. `update_target_decode_box(None)`. 10. `window.set_title(vm.folder_title())` (an `Err` is logged, not thrown: C# `SetTitle` throws only for a refused `SetWindowText`, and a constructor that throws leaks the window). 11. `initialize_viewing()`.
### `register_features` (C# 130-137, ORDER IS BEHAVIOUR)
In this order: scroll bars (13i) BEFORE input (the zoomed image's box covers the bar area, so the bars' mouse handler must see a press first); input (14c); windowing (13k); context menu (14f); keep-warm (16d). Each unit adds exactly ONE line at the end; on a merge conflict keep every line (the C# rule). Until a unit is on master its line is a comment `// 14c: register_input(self)`. The keep-warm line (16d) is `let setup = register_keep_warm(&window_as_keep_warm_window, registration)` where `registration` is the `KeepWarmRegistration` found in `FeatureOptions` or, absent, one built from `options.prefer_warp` (the other members `None`); the result is stored with `set_keep_warm` (controller as `KeepWarmPort`, frame log) and a feature whose `release_renderer` calls `setup.dispose()` FIRST (16d: "13g/13h call it FIRST in release_renderer"; features release in reverse registration order and keep-warm registers last, so this holds). The overlay is NOT in this list (C# attaches it from the startup code: `AttachOverlay`, 15j; it registers a `MainWindowFeature`).
### `attach_renderer` (C# 161-185)
Check order: disposed -> `Err(Disposed)`; surface present -> `Err(RendererAlreadyAttached)`. `SurfaceOptions { prefer_warp, ..Default }` (`allow_tearing` false, `max_frame_latency` 1: the C# record defaults). Surface from the hook or `D2dRenderSurface::create_window_surface(hwnd, options)`; `Err(RenderFault)` -> `Err(Render(..))` and NOTHING is stored (C#: the exception leaves `_surface` null; a retry is allowed). Marks `d3dDeviceReady` then `swapChainReady` (C# emits both even though one call created both). `(w, h) = window.client_size_pixels()`; if `w > 0 && h > 0` and the surface size differs, `surface.resize(w, h, window.dpi_scale())` (an `Err` here is returned and the surface is dropped, nothing stored). Then store the surface, build the cache `D2dGpuImageCache::new(ResourcesBitmapDevice::new(surface.resources().clone()), Rc::new(DispatcherStripeScheduler { dispatcher, window: id }), surface.pixel_width(), surface.pixel_height())` (budget from the SURFACE pixel size, C# `GpuImageCache(surface, dispatcher)`), `attach_viewing()`, `window.set_surface_ready(true)`.
`DispatcherStripeScheduler::schedule_stripe(token)` posts a `Send` action at `UiPriority::Background` that calls `with_window(id, |w| w.run_stripe(token))`; `run_stripe` calls `cache.run_stripe(token)` and logs an `Err`. It never runs the stripe inline.
### `open_initial` (C# 191-221)
`(cw, ch) = client_size_pixels()`; positive -> `update_target_decode_box(Some((cw / dpi, ch / dpi)))`. A `None`/blank (`trim().is_empty()`) path returns here. Else mark `openPathBegin`; for `is_file`: `size_source.startup_prediction()` `Some(p)` -> mark `earlyDecodeBoxMatched` when `p == size_source.target_decode_box()` else `earlyDecodeBoxMismatch`; `vm.prewarm_initial_image(path).is_some()` -> mark `initialDecodeStarted`. Then `vm.set_defer_next_preload_kick(true)`, `changes = vm.open_path(path)` (borrow released), `apply_changes(&changes)` (13h). The C# returns the `Task`; the Rust view model finishes the open through `pump` (the inbox wake, 13h). A blank path completes at once (no error).
### The UI-thread registry and posting (D-W8B4M-6, -11)
`thread_local! { LIVE: RefCell<Vec<(MainWindowId, Weak<MainWindowInner>)>> }`: `with_window(id, f)` upgrades the `Weak` and runs `f` only when the window is alive AND not `disposed`; `with_current_window` takes the newest entry. `post_to_window` and `coalesced_wake` build `Send` actions from an id and a `fn` pointer, never from an `Rc`. `UiLocalPoster` keeps non-`Send` closures in a thread-local FIFO per priority and posts one `Send` wake job per closure; `post_after` waits on a timer thread (a bounded channel wait, no polling, no `Rc` crosses the thread) and then posts the wake job. This single facility replaces `RenderPoster` (16h), `LocalPoster` (15j), `ScheduleOnUi` (16c) and `UiWake` (15j) (see Open questions 6).
### Interim ports (D-W8B4M-4)
`MainViewport`, `PresentationHubPort`, `StartupCloakPort`, `PlacementSavePort`, `KeepWarmPort` are the members of other units' types that this window calls; each trait doc names its owner. At landing the lead replaces `Rc<dyn Trait>` by the concrete type (`Rc<ViewportController>`, `Rc<ShellPresentationHub>`, `Rc<StartupCloak>`, ...) and deletes the trait; no behaviour changes. `viewport_factory` stays (the controller needs `create_viewport_input_hooks` from 14c, which depends on 13h: the factory breaks the cycle 13g -> 14c -> 13h).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7 and the window-specific ones)
- T1 (ownership cycles): no strong `Rc<MainWindowInner>` inside anything the window stores or registers elsewhere; a test counts `Rc::strong_count` of the inner state after construction, after `attach_renderer`, after `dispose` (must be 1 while the owner lives, 0 after it dropped).
- T2 (UI-thread affinity): `MainWindow` is `!Send`; `MainWindowId`, `fn` pointers and `Arc<..+Send+Sync>` are the only things that cross threads. A test `main_window_is_not_send` (compile-time).
- T3 (re-entrancy): `window.set_title`, `SetWindowPos`, `window.close()` and `render_now` re-enter the window procedure and therefore the window's handlers. No `RefCell` borrow of `view_model`, `viewer`, `surface`, `cache`, `image`, `features` is held across such a call (clone the `Rc` out, drop the borrow, call). The constructor holds nothing across `register_features`.
- T4 (shutdown order): the creation order is window -> clock -> viewport -> (attach) surface -> cache -> composer/prefetcher; the release order is the reverse (13h). `attach_renderer` after a failed surface creation leaves no partial state.
- T5 (what must not be caught): a panic in any callback propagates to the top of the UI thread (R0003); `render_now`'s `catch` of C# is the `RenderFault` branch only (13i).
- T6 (numeric): `client_size_pixels / dpi_scale` is `f64` division; the decode box uses the DIP size and `dpi_scale` (13h). `PREVIEW_QUALITY_MULTIPLIER` is `1.15` exactly.
- T7 (C# `null` vs `None`): a blank `initial_path` and `None` are the same; `""` and `"   "` are blank (`string.IsNullOrWhiteSpace`).
