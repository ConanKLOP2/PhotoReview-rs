- Semantics notes:
  1. **Paths.** `ifd0_path(root, tag)` = `format!("{root}/{{ushort={tag}}}")`, `exif_path` = `format!("{root}/exif/{{ushort={tag}}}")`, tag in DECIMAL,
     no padding (271, 272, 306, 33434, 33437, 34855, 36867, 36868, 37386, 41012). The root string is used verbatim (golden `custom-root`); no
     validation, no trailing-slash handling.
  2. **Query order and short-circuit (the oracle records it).** Date: `as_string(EXIF 36867)`, if `None` then `as_string(EXIF 36868)`, if `None` then
     `as_string(IFD0 306)`; the first `Some` stops the chain EVEN when it is `""` or unparsable (golden `date-empty-string-stops-chain`,
     `date-garbage-stops-chain`): the IFD0 date is then not queried. Then ALWAYS, in this order: make (IFD0 271), model (IFD0 272), lens (EXIF 41012),
     iso (EXIF 34855), focal length (EXIF 37386), f-number (EXIF 33437), exposure time (EXIF 33434). Total 8 to 10 queries. A query returning
     the wrong type counts as `None` for the chain (`date-wrong-type-falls-through`).
  3. **`as_string`.** `Text(s)` -> `Some(s.clone())` (empty stays `Some("")`); `Chars(units)` -> `String::from_utf16_lossy(units)`; all else `None`.
     Lone surrogates become U+FFFD where C# keeps them: output goes through UTF-8 in the cache codec (W4-04a) where C# also emits U+FFFD, so the
     persisted bytes match (D5 divergence, comment `// DIVERGENCE:`). Text cleaning (NUL, control chars, 64 cap, trim) is `ExifSummary::create` (W4-04a), NOT here.
  4. **`as_integer`.** `U8`, `U16`, `I16`, `U32`, `I32` widen to `i64` (sign kept for `I16`/`I32`). Arrays (`U16s`, `U32s`, `I16s`, `I32s`) need `len > 0`
     and give element 0. `U64`, `I64`, strings, `Other` give `None`. THE CLR QUIRK: in C# the arms are `ushort[]`, `uint[]`, `short[]`, `int[]` in that
     order and a `short[]` object also satisfies the `ushort[]` type test (and `int[]` the `uint[]` test), so `array[0]` of a negative `short[]` or
     `int[]` is read UNSIGNED: `I16s([-1])` -> `65535`, `I32s([-400])` -> `4294967248`. Implement exactly this (`i64::from(v as u16)`, `i64::from(v as u32)`);
     golden cases `iso-negative-i16-array-clr-reinterpretation` and `...-i32-array-...` pin it (if the oracle shows otherwise the oracle wins and this note
     is corrected). Scalars are NOT affected (`iso-negative-i16` stays `-1` and is dropped by `ExifSummary::create`: ISO must be in `1..=10_000_000`).
  5. **`as_rational`.** `U64(p)` / first of non-empty `U64s` -> `ExifRational { numerator: (p & 0xFFFF_FFFF) as u32, denominator: (p >> 32) as u32 }`, zeros kept
     (`ExifSummary::create` drops them). `I64(p)` / first of non-empty `I64s` -> `n = (p & 0xFFFF_FFFF) as u32 as i32`, `d = (p >> 32) as i32` (arithmetic
     shift, then truncating cast: `unchecked((int)(packed >> 32))`); `Some` only when `n > 0 && d > 0`, as `(n as u32, d as u32)`. Both array arms read element 0
     only (a second element is ignored, `rational-unsigned-array-first-only`). Empty arrays, `U32`, `U16`, `Other` give `None`. Because `QueryValue`
     keeps `U64s` and `I64s` apart, the C# `GetType() == typeof(long[])` guard (CLR treats `long[]` and `ulong[]` as one in type tests) needs no code,
     only the golden cases `rational-arrays-both-signs`.
  6. **Result.** `ExifSummary::create(date, make, model, lens, iso, focal, f_number, exposure)`; `None` when nothing usable is left (`all-nothing-usable`).
     Field order of the call is the C# order (it decides nothing observable, but keep it for the review).
