## Semantics notes

Notation: `sample(i)` (for `i` in `0..count`, 0 = OLDEST) is `samples[(next + CAPACITY - count + i) % CAPACITY]`. All `i64` subtraction/addition/accumulation below is UNCHECKED in C#: use `wrapping_sub` / `wrapping_add` (a debug build would panic on overflow; the golden has such sequences). Every int-to-double conversion is a plain `as f64`.

### `reset()`
`count = 0; next = 0; current = None` (the sample array content is irrelevant).

### `add(timestamp)`
1. `if count > 0 && timestamp <= samples[(next + CAPACITY - 1) % CAPACITY] { return; }` Equal or older than the newest sample: ignored completely (state, `count` and `current` unchanged). With `count == 0` ANY value is accepted (zero and negative included), also right after `reset()`.
2. `samples[next] = timestamp; next = (next + 1) % CAPACITY; if count < CAPACITY { count += 1 }` (when full, the oldest sample is overwritten).
3. `drop_samples_before_a_rate_change()`.
4. `current = compute()`.

### `drop_samples_before_a_rate_change()` (private)
`RECENT = 4`.
1. `if count < RECENT + MIN_SAMPLES (= 8) { return; }`
2. `older_span = sample(count - RECENT - 1).wrapping_sub(sample(0))`; `older_intervals = (count - RECENT - 1)` (at least 3); `older = older_span as f64 / older_intervals as f64`.
3. For `i` in `count - RECENT .. count` (the four newest intervals, oldest of them first): `ratio = sample(i).wrapping_sub(sample(i - 1)) as f64 / older`; `nearest = math_max(1.0, ratio.round_ties_even())`; `if (ratio - nearest).abs() < 0.15 * nearest { return; }` (ONE interval that fits the old period, or a whole multiple of it within 15 %, keeps everything).
4. Only when all four intervals fail: `keep = RECENT + 1 = 5`; copy `sample(count - 5 + k)` for `k` in `0..5` into a temporary array, call `reset()` (clears `current` too, harmless: `add` recomputes it right after), then write the five samples at `samples[next]` advancing `next`, `count += 1` each (so `count == 5`, `next == 5`). Note this does not go through the "increasing" check.
`Math.Round` here is ties-to-even: `ratio.round_ties_even()` (Rust `f64::round_ties_even`, stable since 1.77).

### `compute()` (private) -> `Option<DisplayTiming>`
1. `if count < MIN_SAMPLES { return None; }`
2. `intervals[i] = sample(i + 1).wrapping_sub(sample(i))` for `i` in `0..count - 1` (`n = count - 1 >= 3` values, `i64`).
3. `sorted` = copy of `intervals` sorted ascending (`i64`); `baseline = sorted[sorted.len() / 4] as f64` (integer division: n=3 -> index 0, n=4..7 -> 1, n=8..11 -> 2, ...: the LOWER QUARTILE, not the median). `if baseline <= 0.0 { return None; }` (only reachable through wrapped overflow).
4. `counts[i] = 1.max((intervals[i] as f64 / baseline).round_ties_even() as i64)` (`as i64` saturates, NaN -> 0; the `max(1, ..)` is on `i64`); `refreshes = sum of counts` with `wrapping_add`.
5. `period = (sample(count - 1).wrapping_sub(sample(0)) as f64) / (refreshes as f64)`.
6. Projection: `latest = f64::MAX; ahead: i64 = 0;` for `i` from `count - 1` DOWN to `0`: `latest = math_min(latest, sample(i) as f64 + (ahead as f64) * period)`; then `if i > 0 { ahead = ahead.wrapping_add(counts[i - 1]) }`. Order of evaluation matters (the `ahead` used for sample `i` is the sum of `counts[i..count-1]` of the intervals AFTER it).
7. `Some(DisplayTiming { last_vblank: latest.round_ties_even() as i64, refresh_period: period.round_ties_even() as i64 })`.

### The three numeric traps (each one fails the golden when missed)
- **Banker's rounding.** `Math.Round(x)` is round-half-to-even: `166666.5 -> 166666`, `1001.5 -> 1002`, `1666666.5 -> 1666666`, `2.5 -> 2`, `3.5 -> 4`, `0.5 -> 0`. `f64::round` (half away from zero) is WRONG and breaks 46 of the 109 golden sequences, including every plain 24/60/90/144/165/240 Hz grid.
- **NaN-propagating `Math.Min`/`Math.Max`.** `math_min(a, b)`: if either is NaN return NaN; if `a == b` return the one with the sign bit set when it is a zero (`-0.0` is smaller than `0.0`), else the smaller. `math_max` mirrors it. Do not use `f64::min`/`f64::max` (they ignore a NaN operand).
- **Wrapping integer arithmetic and saturating casts.** Inputs near `i64::MAX`/`MIN` (golden sequences "near Int64.MaxValue/MinValue", "interval overflow wraps negative", "span overflow ...") overflow the subtractions; `wrapping_sub` reproduces C#. `latest.round_ties_even() as i64` saturates at `i64::MAX/MIN` (Rust `as` is saturating and maps NaN to 0, which is exactly .NET 9+ `(long)double`; the project targets .NET 10).

## Traps checklist
§7 items 3 (overflow: wrapping everywhere a C# `long` is added/subtracted), 4 (rounding: ties-to-even, see above), 10 (ring order: `sample(0)` is the oldest; keep the modular index formula), 9 (n/a). The comparison `timestamp <= newest` uses the signed value, not the wrapped difference.
