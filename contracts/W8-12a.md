## Semantics notes (C# is the spec; the interfaces' doc comments are in Vietnamese, translated in the stub docs)

### Mapping rules applied to every interface (D-W8-12a-2/3)
1. `IFoo` becomes trait `Foo` (no `I`; precedent `FrameClock`). `IDisposable` becomes `Drop` of the implementation: nothing in the traits. `nint` is `isize`.
   C# properties become getter methods (`pixel_buffer_id()`); `BudgetBytes { get; set; }` becomes `budget_bytes()` + `set_budget_bytes()` (the setter can fail).
2. **Threading:** everything is UI-thread only. No `Send`/`Sync` bounds anywhere (a Direct2D bitmap is not `Send`); images are shared as `Rc<dyn GpuImage>`.
3. **Exceptions become `Result<_, RenderError>`** only where C# can throw at runtime for a reason a Rust caller can trigger. Calls that cannot fail in C# return `()`.
   `ArgumentNullException` has no variant (references are never null). "Draw call outside BeginDraw/EndDraw" (`InvalidOperationException`, `D2DDrawContext` line 49) cannot
   happen in Rust: `begin_draw` returns `&mut dyn DrawContext` that borrows the surface. `(TextTrimming)7` (out-of-range enum) cannot be built in Rust.
4. **Cache and renderer take `&self`**, surface and draw context take `&mut self` (D-W8-12a-3): the cache is shared by the compositor, the prefetcher and the surface's
   device-recreated handler; the draw context is inherently exclusive.

### IGpuImage / IGpuImageCache (C-10)
5. Key = `PixelBuffer::id()` (INV-1), never the path. `get_or_upload` returns the SAME `Rc` for the same id while cached (C# returns the same object; the test
   `GetOrUpload_SameBuffer_UploadsOnceAndReturnsSameImage` of 12f asserts `Rc::ptr_eq`).
6. `prefetch` takes `&Arc<PixelBuffer>` (D-W8-12a-4): the cache keeps a clone only until the last stripe is uploaded, so a buffer whose owners are gone is dropped, which is the
   Rust form of C# "source disposed midway" (`Prefetch_SourceDisposedMidway_DropsPartialImage`). A buffer already disposed: `Ok(())`, nothing happens (C# `if (pixels.IsDisposed) return`).
7. `set_budget_bytes(negative)` is `Err(ArgumentOutOfRange { param: "value" })` and leaves the budget unchanged (C# throws before assigning); lowering evicts at once.
   `retain` and `get_or_upload` and `prefetch` after dispose are `Err(Disposed { object: "PhotoReview.Shell.Rendering.GpuImageCache" })`; `clear` never fails.
8. Members of the C# class that are NOT in the interface (W8-12f/12g concrete API): `UploadCompleted` event, `TotalGpuBytes`, `Count`, `PendingPrefetchCount`, `Contains`,
   `IsFullyUploaded`, `DefaultStripeBytes = 2 MiB`, `DefaultBudgetScreens = 6`. Not declared here.

### IRenderSurface / IRenderSurfaceFactory / IDrawContext (C-09)
9. `begin_draw` / `end_draw_and_present` / `resize` error messages are the C# strings verbatim (listed in the trait docs and in "Error texts"). `end_draw_and_present` returns
   `Err(InvalidOperation "Unbalanced PushClip/PopClip or PushOpacity/PopOpacity in the frame.")` only AFTER it has ended the draw and presented (C# throws at the end), so the
   frame is on screen and the surface is usable again. Other results (C# `EndDrawAndPresent`): an `EndDraw` HRESULT < 0 that is not a device loss is `Ok(Failed)` (NOT an `Err`); `Present` returns `Occluded` for `DXGI_STATUS_OCCLUDED`, `DeviceRecreated` on device loss, `Failed` for other HRESULT < 0; a surface without swap chain (offscreen/WARP) is `Ok(Presented)`. Sync interval is 0 when `allow_tearing` or the implementation's immediate-present switch is on, else 1. A thread-affinity error (`"D2DRenderSurface must be used on the thread that created it."`) cannot be reached when the implementation is not `Send`; an implementation may still keep the check.
10. `DeviceRecreated` event: `subscribe_device_recreated` / `unsubscribe_device_recreated` with a `u64` id (same pattern as `FrameClock`); an unknown id is a no-op; handlers run
    synchronously on the UI thread inside `resize`/`end_draw_and_present`, after the new device is up, in subscription order. The surface is `&mut` borrowed there, so a handler
    cannot re-enter it (C# could; no C# caller does).
11. `draw_image`: an image that is not the implementation's own type, was released, is incomplete, or belongs to an older device generation is SKIPPED silently (counted in the concrete
    context's `SkippedImageDraws`), never an error. `opacity` has no default argument: callers pass `DEFAULT_IMAGE_OPACITY` (1.0).
12. `try_read_pixels` is `Ok(Some(new Pbgra32 buffer))` on offscreen/WARP, `Ok(None)` on a window surface (C# `false`), `Err(Device)` when the readback fails.
13. `as_oriented` / `OrientedDrawContext` (D-W8-12a-5) exist because trait-typed code needs `DrawImageOriented`: `ImageLayer.TryDraw` (W8-16a) does
    `if (exifOrientation is >= 2 and <= 8 && context is D2DDrawContext oriented) oriented.DrawImageOriented(...) else context.DrawImage(...)`. The Rust twin is
    `if (2..=8).contains(&o) { if let Some(c) = context.as_oriented() { c.draw_image_oriented(..); } else { context.draw_image(..) } }`.

### ITextLayout / ITextRenderer (C-11 text part)
14. `TextLayout` has no `dispose`: dropping the `Box<dyn TextLayout>` returns the lease on the cached native layout (C# `Dispose`). `as_any` mirrors `layout is INativeTextLayout`
    in `DrawText` (a foreign layout makes `draw_text` return `Err(InvalidArgument { param: "layout", message: "The text layout was not created by the Direct2D text renderer." })`).
15. `create_layout` fails with `ArgumentOutOfRange { param: "style" }` for a font size that is not finite and positive (`!(size > 0) || size.is_infinite()`, so NaN, 0, negative, +inf);
    that check is the implementation's (W8-12i), the trait only documents it.
16. `TextStyle` equality is C# record equality: family ordinal case-sensitive, size with `f64_same` (NaN equals NaN, `0.0 == -0.0`), bold. NOT derived `PartialEq` (derived `f64 ==` makes NaN unequal).

### TiledGpuImage / GpuTile (`tiled.rs`; the only logic)
17. `TiledGpuImage::new(pixels, tiles, generation)`: copies `pixel_buffer_id = pixels.id()`, `pixel_width = width()`, `pixel_height = height()`, `layout = layout()`; `uploaded_rows = 0`,
    `is_released = false`; `gpu_bytes = sum over tiles of (tile.spec().texture.width as i64) * (texture.height as i64) * 4` (**texture** rect, which includes the overlap gutter, not the
    core; 4 bytes per pixel; `i64`; `wrapping_add` like C# unchecked `+=`); no tiles gives 0.
18. `is_complete()` is `uploaded_rows >= pixel_height` (`>=`, not `==`; the setter does no validation, so `uploaded_rows > height` is complete).
19. `is_drawable(g)` is `!is_released && is_complete() && generation == g` (equality, not `>=`: an image of a NEWER generation than the caller's is not drawable either).
20. `Cell`/`RefCell` interior mutability because the cache and the holders share the image (`Rc`): `set_uploaded_rows`, `set_released`, `GpuTile::set_bitmap/take_bitmap` take `&self`.
    `GpuTile::with_bitmap(f)` borrows the `RefCell` for the call: `f` must not call back into the same tile (it would panic on `borrow_mut`); document, do not guard.
21. `impl<B: 'static> GpuImage for TiledGpuImage<B>`: the four getters return the stored values, `as_any` returns `self`. `TiledGpuImage<()>` and `TiledGpuImage<u32>` are different
    types: a draw context must downcast to the `B` it actually uses (`ID2D1Bitmap1`).

### Error texts (`RenderError::fmt`, the exact strings; no C# test compares them, they feed the log)
- `Disposed { object }`: `"Cannot access a disposed object.\r\nObject name: '{object}'."` (same form as `PixelBufferError::Disposed`).
- `InvalidOperation { message }`: `message`. `InvalidArgument { param, message }`: `"{message} (Parameter '{param}')"`.
- `ArgumentOutOfRange { param }`: `"Specified argument was out of the range of valid values. (Parameter '{param}')"`.
- `Device { hresult, operation }`: `"{operation} failed with HRESULT 0x{hresult:08X}"` where `hresult` is formatted as `u32` (`hresult as u32`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (item 3, integers): `gpu_bytes` is `i64`; three 16384x16384 textures are 3 221 225 472 bytes, which overflows `i32` (and a naive `i32` multiply overflows per tile at 2^31/4 pixels).
- T2: `gpu_bytes` uses the TEXTURE rect (gutter included), not `core`. A test with a gutter tile (texture wider than core) catches the swap.
- T3: `is_complete` is `>=`; `is_drawable` needs all three conditions and `generation == current`. The C# test covers three of the four failing combinations; the table test below covers all 8.
- T4: `RenderSurfaceOptions::default()` has `max_frame_latency = 1`; do NOT `#[derive(Default)]` (gives 0).
- T5 (item 8/null vs empty): `TextStyle::default().font_family` is `"Segoe UI"`, not empty; `font_size_dip` 12.0.
- T6: enum discriminants are the C# values (`PresentResult` 0..=3, `TextTrimming` 0/1) and are asserted by a test; do not reorder.
- T7: `TextStyle::eq` with NaN sizes (see 16). Mutation target.
- T8: `as_any` on a generic type: `TiledGpuImage<B>` downcasts only to the exact `B`; do not return a reference to an inner field.
- T9: trait methods that C# declares `void` stay `()` (see 3); do not add `Result` "just in case", every consumer would have to handle a case that cannot happen.

## Decisions taken in this contract (D-W8-12a-n; the lead may overrule in `contracts/README.md`)
- **D-W8-12a-1 `TiledGpuImage`/`GpuTile` live in `pr_app::services::render::tiled`, generic over the bitmap handle `B`** (plan says `render::tiled` without a crate). Reason: it implements `GpuImage`
  (a `pr_app` trait) and uses `TileSpec` (W8-01c, `pr_app`), so putting it in `pr_platform_win` would need the reverse dependency (see Problems). Generic `B` keeps `windows` out; W8-12g uses `TiledGpuImage<ID2D1Bitmap1>`.
- **D-W8-12a-2 One error enum `RenderError`** for all four contract families, instead of one per trait.
- **D-W8-12a-3 `&self` for cache and text renderer, `&mut self` for surface and draw context.**
- **D-W8-12a-4 `prefetch(&Arc<PixelBuffer>)`** (the cache needs the buffer after the call returns; `Arc` is the repo's sharing model, `pixels.rs` module doc). `get_or_upload(&PixelBuffer)` borrows (synchronous).
- **D-W8-12a-5 `as_oriented`/`OrientedDrawContext` are additions to the frozen C# surface** (contracts.v1.txt v1.2) needed because a trait-typed caller uses a concrete method. Not an intentional behaviour change: no `Different` row.
- **D-W8-12a-6 `D2DRenderSurfaceFactory` has no Rust counterpart in this unit** (W8-12d writes the 3-line `impl RenderSurfaceFactory`).

## Open questions
1. **Crate layering of the whole render stack (blocks W8-12b onward, lead must decide).** See Problems in the report: `pr-app` depends on `pr-platform-win` (`crates/pr-app/Cargo.toml`), so `pr_platform_win::render`
   cannot implement `pr_app` traits, use `TileSpec`/`RectD`/`ColorF` (all `pr_app`), or implement `GpuImage`. Options: (A) **recommended**: make `pr-app` a pure library without the `pr-platform-win` dependency, make `pr-platform-win`
   depend on `pr-app`, and move `main.rs`, `bin/r0001_spike.rs` and the composition that needs both into a new thin package (for example `pr-shell`, bin `PhotoReviewRs`); the pure modules keep the "no windows crate" rule
   and D-W8-3 holds as written. Cost: one Cargo reshuffle before B3. (B) split out a leaf crate `pr-ui-types` (geometry, `ColorF`, render traits) that both depend on; cost: moves 01a/01c/12a code out of `pr_app`.
   (C) adapters in `pr-app` that wrap concrete platform types; cost: every platform type needs a wrapper and `TiledGpuImage` cannot be shared. This unit's stubs are written for (A)/(B) and are valid for (C) too.
2. **`RenderError` variants.** Recommended: the five above. Alternative: `anyhow`-style string errors; rejected (callers match `Disposed`/`InvalidOperation` in tests).
3. **Shared fakes for W8-15/W8-16.** A recording `DrawContext`, a fake `TextRenderer` (the overlay layout tests read `fake.Requests`) and a fake `GpuImageCache` will be needed by about 12 later units. Recommended: after this unit
   merges, the lead adds `services/render/fakes.rs` under `#[cfg(any(test, feature = "test-support"))]` (a `test-support` feature in `pr-app/Cargo.toml`, precedent `pr-platform-win`), seeded from this unit's test fakes.
   Alternative: each unit copies the fakes from its C# tests (duplicates drift).
4. **`DeviceRecreated` as subscribe/unsubscribe vs a generation counter.** Recommended: keep the C# event shape (matches the cache's handler). Alternative: `device_generation()` polling; rejected here because the
   C# interface has no such member (only the concrete `D2DRenderSurface.DeviceGeneration`).
5. **Oriented drawing seam (D-W8-12a-5).** Recommended: `as_oriented`. Alternative: a plain `draw_image_oriented` on `DrawContext` with a default that falls back to `draw_image` (loses the "context cannot orient" signal that `ImageLayer`
   tests may observe). Decide before W8-16a.
