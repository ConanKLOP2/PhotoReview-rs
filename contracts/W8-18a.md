## Semantics (C# is the spec)
1. **`usable_initial_folder(f)`**: `f` is `Some(non-empty)` AND the path exists as a DIRECTORY (`std::fs::metadata(f).is_ok_and(|m| m.is_dir())`; never panics for a bad path: invalid characters, embedded NUL, a file, a missing path are all `None`) -> `Some(f.to_owned())`, the SAME text; anything else `None`. The golden `folder-picker-policy` (18 cases: trailing separator, `..`, other case, trailing spaces, `\\?\` prefix, forward slashes, drive root, `.`, a file, missing, `|`, NUL) decides edge cases; if `Path::is_dir` and `Directory.Exists` disagree on a case, the golden wins and the difference is a `Different` row only if it cannot be made equal.
2. **`FolderPicker::pick`**: `dialog.show(owner(), title, usable_initial_folder(initial).as_deref())`. The owner closure is called on every `pick` (not cached). `Err` is returned as it is (the C# `COMException` reaches the caller, which wraps it "guarded"; D-W8B5-2 says what `Win32DialogService` does with it).
3. **`NativeShellFolderDialog::show`** (C# 36-54): `create_file_open_dialog()` (`Err` -> `Err`); `configure`; `before_show` hook; `Show(Some(HWND(owner)))`: `Ok` -> read the result; an error whose code is `HRESULT_CANCELLED` -> `Ok(None)`; any other error -> `Err(Hresult(code))`. The COM object is released by drop on every path (the C# `ComInterop.Release`). The dialog is modal and pumps its OWN messages on the calling thread: the caller must be the STA UI thread of the owner window and must hold no `RefCell` borrow across the call.
4. **`configure`** (folder): `dialog.GetOptions()`, `dialog.SetOptions(current | FOLDER_OPTIONS)`; `SetTitle(title)` ONLY when `!title.is_empty()`; `SetFolder(item)` ONLY when the initial folder is `Some(non-empty)`, with `item = create_item_from_path(folder)?` (an `Err` here fails the whole `configure`, as in C#, which throws from `CreateItemFromPath`). Every `Err` is the failing `HRESULT`.
5. **Read the result**: `dialog.GetResult()` -> `IShellItem`; `item.GetDisplayName(SIGDN_FILESYSPATH)` -> `PWSTR`; `take_co_task_string` reads and frees it (`unsafe`, SAFETY: the pointer was allocated by the shell and nobody frees it). A `None` string (null pointer) is `Ok(None)`.
6. **`NativeShellFileDialog`**: `pick_open_file` uses `create_file_open_dialog()` + `OPEN_OPTIONS`, `pick_save_file` uses `create_file_save_dialog()` + `SAVE_OPTIONS`; both go through one private `run(&IFileDialog, ...)`. `configure` (file) follows the C# order in the summary above; the new Rust part is the filter text: `FilterBuffers` holds two `Vec<u16>` per filter (`to_utf16z(name)`, `to_utf16z(pattern)`) and the `COMDLG_FILTERSPEC` array that points into them; `SetFileTypes(&specs)`; the buffers stay alive until `run` has returned (they are a local of `run` that is dropped last, the C# `finally { FreeSpecs }`). `default_extension` is trimmed of LEADING dots only (`trim_start_matches('.')`, C# `TrimStart('.')`).
7. **Cancel detection** uses the HRESULT, not the text. A user closing the window with the X button or `WM_CLOSE` posted to the dialog yields `HRESULT_CANCELLED` (that is what the two C# "closes the window" tests rely on).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (COM apartment): the dialogs need an STA. The shell UI thread is one (host `MessageLoop`); the wrappers do NOT call `CoInitializeEx`. Every native test calls `CoInitializeEx(None, COINIT_APARTMENTTHREADED)` first on its OWN thread and `CoUninitialize` last, and drops every COM pointer BEFORE `CoUninitialize`.
- T2 (filter text lifetime): `SetFileTypes` keeps the pointers; dropping `FilterBuffers` before `Show` returns is a use-after-free. Keep it in a local declared BEFORE the `Show` call and dropped after the result is read.
- T3 (nulls and empties, trap 8): `None` and `Some("")` are the same for title, initial folder, default extension and file name (the C# `string.IsNullOrEmpty`); do not pass an empty string to `SetFolder`/`SetTitle`.
- T4 (HRESULT signedness): `HRESULT_CANCELLED` is `0x800704C7 as i32` (negative); compare the `i32` code, not an unsigned value.
- T5 (modal re-entrancy): while `Show` runs, the window procedure of the owner and the UI dispatcher still run (D-W8B3H-4/-8); the callers (`Win32DialogService`, settings pages) hold no borrow and re-check their state afterwards (the `IFolderPicker` trait comment says the same).
- T6 (paths): returned paths are the file-system path text of the shell item (`SIGDN_FILESYSPATH`), UTF-16 to `String` lossy only if the OS returned unpaired surrogates (cannot happen for a shell file-system path); do not canonicalise or lower-case them.
- T7 (leaks): the `IFileOpenDialog`, the `IShellItem` results and the `PWSTR` (freed by `take_co_task_string`) are released on every path, including `Err` after `GetResult`.
- T8 (R0003): no `unwrap`/`expect`/`panic`; the `before_show` hook is the one call out to arbitrary code, it is a test-only seam and a panic in it propagates (nothing catches it).

## Safety rules (`// SAFETY:` per `unsafe` block)
`take_co_task_string` is the only `unsafe` the unit calls directly (it is `unsafe fn` in 11e): "`pwstr` comes from `GetDisplayName`, was allocated by the shell with `CoTaskMemAlloc`, is read once and freed by the callee". The COM method calls are the safe methods of the windows-rs interfaces (the `windows` crate generates the unsafe parts); `SetFileTypes(&[COMDLG_FILTERSPEC])` needs a SAFETY comment only if the chosen overload is `unsafe`: "the strings behind `pszName`/`pszSpec` are NUL-terminated UTF-16 owned by `FilterBuffers`, which outlives the dialog's use".
