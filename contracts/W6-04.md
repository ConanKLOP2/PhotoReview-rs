## Required behavior

Follow the C# baseline exactly:

1. `GetTiming`/`get_timing` resolves the nearest monitor for a nonzero window. A zero window or unresolved monitor returns the DWM timing directly and does not start the worker. For a resolved monitor, return only a published estimate tagged for that monitor; return `None` until enough samples have been collected and again after a monitor switch or idle reset.
2. Start one background worker on demand. It follows the latest requested monitor, closes the old adapter before opening a new one, resets the estimator/publication when changing monitors, waits for vblanks, adds monotonic QPC timestamps, and publishes the estimator's current `DisplayTiming`. Do not block the caller on vblank collection.
3. If adapter opening fails, a vblank wait returns nonzero, or the native wait entry point/library is unavailable, mark only that monitor failed, log a warning, release the adapter if opened, and return DWM timing for that monitor for `RetryFailedAfterMs = 8000`; retry after the interval. Other monitors remain eligible immediately. Unexpected worker errors are logged as errors and then warn/mark the affected monitor for DWM fallback. If no monitor was selected, forget the dead worker without poisoning monitor zero.
4. Stop the worker after `IdleStopMs = 1500` without calls, clear the stale publication, and close the adapter. A later request starts a fresh worker and measurement. Preserve the C# comparison boundaries (`idle > IdleStopMs`, retry elapsed `< RetryFailedAfterMs`). Use `Stopwatch::frequency`-equivalent ticks and the injected timestamp source for tests.
5. `DwmTiming` reports `None` on native API failure, absent library/entry point, or zero QPC period/vblank; otherwise it maps the two QPC fields to `DisplayTiming`. Keep the static native DWM smoke test separate from fake-based behavioral tests.
6. Match `MONITORINFOEXW` (104 bytes), packed `DWM_TIMING_INFO` layout/size, `MONITOR_DEFAULTTONEAREST`, device-name truncation at 32 UTF-16 units/NUL, GDI DC cleanup on every path, D3DKMT status handling, and adapter close semantics from the C# implementation. No display configuration changes are permitted.

## Native and concurrency safety

- No fixed-delay assertions. A fake `WaitForVBlank` blocks on a channel/semaphore until the test releases one vblank and exposes explicit `opened`, `waiting`, `closed`, warning, and error notifications. Ensure test teardown always releases a blocked worker before joining/disposing fakes.
- Timeouts are finite hang guards around those explicit notifications. Avoid polling and avoid relying on OS scheduler timing.
- Fake adapter IDs are deterministic and closings are recorded so tests prove exactly which handle is closed. Assert no leaked adapter on open/wait/error/idle/monitor-switch paths.
- Keep lock ordering and publication race behavior source-traced against C#: do not hold the state mutex across a blocking vblank wait. Store monitor identity with published timing so a prior monitor's estimate can never answer a new monitor request.
- The native DWM smoke test must not be used as evidence for worker behavior. No real vblank wait is needed to validate the ABI/layout; the DWM smoke test alone calls the OS.
