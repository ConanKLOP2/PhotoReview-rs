## Number formatting (the heart of byte-identical reports)
`fmt_fixed(value, decimals)`: finite -> `format!("{value:.decimals$}")`. Verified: .NET Core 3.0+ and Rust both print the EXACT decimal expansion of the double rounded half-to-even on exact ties (`0.125` F2 -> `0.12`, `0.375` F2 -> `0.38`, `0.25` F1 -> `0.2`, `11.25` F1 -> `11.2`, `2.675` F2 -> `2.67`, `1.005` F2 -> `1.00`, `9.95` F1 -> `9.9`), huge values print every digit (`1e21` F1 -> `1000000000000000000000.0`, `1.7976931348623157e308` -> 309 digits), `-0.0` -> `-0.0`, and a negative value that rounds to zero keeps its sign (`-0.04` F1 -> `-0.0`). NaN -> `NaN`, +inf -> `Infinity`, -inf -> `-Infinity` (Rust would print `inf`: special-case).
`fmt_double(value)` ( = `double.ToString()` = what `{threshold}` prints for 40, 12.5, 1.3 and what System.Text.Json writes): NaN/Infinity/-Infinity as above; `0.0` -> `0`, `-0.0` -> `-0`; otherwise take the shortest round-trip digits and their decimal exponent `e` (value = `d.ddd * 10^e`; Rust's `format!("{:e}", v.abs())` gives `1.2345e-5` style text: split it into the digit string and `e`). Then:
- if `e >= 17` or `e <= -5` -> scientific: `d` or `d.ddd` (a dot only if more than one digit), then `E`, then `+` or `-` ALWAYS, then the exponent with at least two digits. `1e17` -> `1E+17`, `1e-5` -> `1E-05`, `1.2345e-5` -> `1.2345E-05`, `1.5e300` -> `1.5E+300`, `5e-324` -> `5E-324`, `1.7976931348623157e308` -> `1.7976931348623157E+308`, `2.5e-7` -> `2.5E-07`.
- else if `e >= 0` -> plain integer part of `e+1` digits (pad the digits with zeros on the right when there are fewer: `1e16` -> `10000000000000000`, `9.999999999999998e16` -> `99999999999999980`), then `.` and the remaining digits if any: `1234567.85`, `100`, `4503599627370497`.
- else (`-5 < e < 0`) -> `0.` + `-e-1` zeros + digits: `0.0001`, `0.00012345`, `0.05`.
- a minus sign in front for negatives. Examples from the golden: `40`->`40`, `33.333333333333336`, `0.30000000000000004`, `123456789.12345679`, `9007199254740993`->`9007199254740992`.
A reference prototype of exactly this layout matched all 94 numeric golden cases (69 `fmt` here + 25 `json_double` in W1-21). Do not use `{}`/`{:?}`/`{:e}` of Rust directly: `format!("{}", 1e21)` is `1000000000000000000000`, `{:?}` of `10.0` is `10.0`.
Where each is used: `F1` for ms/percent values, `F2` for the R-CONT ratio, `fmt_double` for thresholds/factors (`{sharePct}`, `{ramHitP95Threshold}`, `{factor}`...). C# interpolation of an `int?` that is null prints the EMPTY string (R-CONT workers); an `int` prints plain decimal.

## `RulesConfig`
- `get(rule, key, default)`: `data[rule][key]` or `default`; both lookups are case-sensitive and exact.
- `parse(json, path_for_message)`: strip one leading U+FEFF if present; `serde_json::from_str::<Value>`; syntax error (incl. empty/blank text, comments, trailing commas, text after the value) -> `Err(PerfError::InvalidData(format!("Invalid rules file '{path}': {detail}")))`. Root `null` -> empty config. Root must otherwise be an object, else the same error. For each `(rule, section)`: `null` section -> skipped (all defaults); object section -> every value must be a JSON number (`as_f64()`), else the same error (`"40"`, `null`, `true`, arrays, objects are errors); any other section type -> error. Duplicate keys: the last wins (`serde_json::Map`). The error `detail` is free text (the .NET text cannot match).
- `load(path)`: `std::fs::read` + `csv::decode_bytes` + `parse(text, &path.display().to_string())`; an `io::Error` is returned as `PerfError::Io` (NOT wrapped in `InvalidData`: C# only wraps `JsonException`). The prefix in the message must contain the path exactly as given.

## The evaluators — copy these strings byte for byte
Notation: `F1(x)`=`fmt_fixed(x,1)`, `F2`, `D(x)`=`fmt_double(x)`, `MS(o)` = `"{F1(v)}ms"` when `o` is `Some(v)` and `v` is not NaN, else `"N/A"` (so `Infinity` prints `Infinityms`). `avg` = left-to-right `f64` sum / count (LINQ `Average`). A nav is "eligible" for a share when `final_visual_ms` is `Some(v)` with `v > 0.0`. `Get(r,k,d)` = `cfg.get`; defaults are written as in C# (`40` is the double 40.0). A rule's `note` is `None` unless stated.

**R-IO** `evaluate_r_io(cfg, source_miss_navs)`: `share = Get("R-IO","sourceMissIoSharePct",40)`. `eligible` = eligible navs with `t_read_ms.is_some()`. Empty -> `(None, "0/{source_miss_navs.len()} SourceMiss navs have t_read", note "No source-read timing; only available with PHOTOREVIEW_DIAG_PREREAD. Use the Procmon D02 data to derive open counts.")`. Else `avg_share = avg(t_read/final) * 100.0` -> `(Some(avg_share >= share), "avg(t_read/finalVisual)={F1(avg_share)}% over {eligible.len()} SourceMiss navs (threshold {D(share)}%)")`.

**R-DEC** `evaluate_r_dec(cfg, decode_navs)`: `share = Get("R-DEC","decodeSharePct",40)`; eligible with `t_decode_ms`. Empty -> `(None, "0 SourceMiss/InflightJoin navs have t_decode", note "Not enough decode data.")`. Else `(Some(avg_share >= share), "avg(t_decode/finalVisual)={F1(avg_share)}% over {n} navs (threshold {D(share)}%)")`.

**R-UI** `evaluate_r_ui(cfg, ram_hit_navs, ram_hit_final_p95, frame_time_p95_ms)`: `share = Get("R-UI","ramHitUiSharePct",40)`, `p95_thr = Get("R-UI","ramHitP95Ms",50)`, `frame_thr = Get("R-UI","frameTimeP95Ms",33)`. `avg_share: Option<f64>` = `None` when there is no eligible nav, else `avg((t_input.unwrap_or(0.0) + t_assign.unwrap_or(0.0) + t_render.unwrap_or(0.0)) / final) * 100.0` (sum in that order). `by_share = avg_share.is_some_and(|s| s >= share)`; `by_p95 = !p95.is_nan() && p95 > p95_thr`; `by_frame = frame.is_some_and(|f| f > frame_thr)` (NaN -> false). Evidence = `"avg((t_input+t_assign+t_render)/finalVisual)={A} (threshold {D(share)}%); RamHit finalVisual P95={MS(p95)} (threshold {D(p95_thr)}ms); frameTime P95={B} (threshold {D(frame_thr)}ms)"` with `A` = `"{F1(s)}%"` or `N/A`, `B` = `"{F1(f)}ms"` or `N/A` (NO NaN check on `B`: a NaN frame time prints `NaNms`). If `avg_share` is `None` AND `p95.is_nan()` AND `frame` is `None` -> `(None, evidence, note "No RamHit navs or frame-time data in this group.")`; else `(Some(by_share || by_p95 || by_frame), evidence)`.

**R-PRE** `evaluate_r_pre(cfg, p95, non_ram_hit_share_pct, is_burst)`: `max = Get("R-PRE","ramHitP95MaxMs",50)`; key `nonRamHitShareS3S4Pct` (default 30) when burst else `nonRamHitShareS2Pct` (default 10) -> `thr`. If `p95.is_nan()` -> `(None, "No RamHit navs in this group.")` (no note). Else `triggered = p95 <= max && share >= thr` (NaN share -> false) and evidence `"RamHit finalVisual P95={F1(p95)}ms (threshold ≤{D(max)}ms); non-RamHit share={F1(share)}% (threshold ≥{D(thr)}% for {S3/S4 | S2})"` — the characters are U+2264 `≤` and U+2265 `≥`.

**R-CONT** `evaluate_r_cont(cfg, low_decode, high_decode, low_workers, high_workers)`: `factor = Get("R-CONT","decodeSlowdownFactor",1.3)`. If `low_decode.is_none() || high_decode.is_none() || low_workers == high_workers` (two `None`s are equal!) -> `(None, "Missing a pair of runs with different PHOTOREVIEW_DIAG_PRELOAD_WORKERS to compare.", note "Needs at least 2 runs of the same scenario/mode with different PHOTOREVIEW_DIAG_PRELOAD_WORKERS (D07).")`. Else `ratio = high / low_clamped` where `low_clamped` = `low.max(0.0001)` — but C# `Math.Max(NaN, x)` is NaN while `f64::max` ignores NaN: write `if low.is_nan() { f64::NAN } else { low.max(0.0001) }`. `(Some(ratio >= factor), "t_decode(workers={HW})={F1(high)}ms vs t_decode(workers={LW})={F1(low)}ms, ratio={F2(ratio)} (threshold {D(factor)})")` where `HW`/`LW` are the decimal numbers or the EMPTY string for `None`. The F1 values use the ORIGINAL `low` (negative `-5.0` prints `-5.0ms` while the ratio uses 0.0001).

**R-THREAD** `evaluate_r_thread(cfg, count, t_input_p95)`: `ms_thr = Get("R-THREAD","dispatcherLongOpMs",16)`, `in_thr = Get("R-THREAD","inputP95Ms",16)`. `by_disp = count > 0`; `by_in = t_input_p95.is_some_and(|t| t > in_thr)`. Evidence `"DispatcherLongOp>{D(ms_thr)}ms count={count}; t_input P95={X} (threshold {D(in_thr)}ms)"`, `X` = `"{F1(v)}ms"` or `N/A`. If `count == 0 && t_input_p95.is_none()` -> `(None, evidence, note "No DispatcherLongOp or t_input in this group.")`; else `(Some(by_disp || by_in), evidence)`.

**R-GC** `evaluate_r_gc(cfg, gc)`: `thr = Get("R-GC","gcTimePct",10)`. `None` -> `(None, "No process.json/% time in GC for this group.", note "Needs dotnet-counters (D09) or process.json (D06).")`; else `(Some(v >= thr), "% time in GC={F1(v)}% (threshold {D(thr)}%)")`.

**R-DISK** `evaluate_r_disk(cfg, disk_cache_hit_navs, source_miss_navs)`: `factor = Get("R-DISK","diskVsReadDecodeFactor",1.0)`. `disk` = `t_disk_ms` values of the disk navs that have one; `rd` = for source-miss navs with `t_decode_ms`: `t_read.unwrap_or(0.0) + t_decode`. If either list is empty -> `(None, "diskCacheHit navs={disk.len()}, sourceMiss navs={rd.len()}", note "Needs at least one DiskCacheHit nav and one SourceMiss nav in the same group.")` (the counts are of the FILTERED lists). Else `avg_disk`, `avg_rd`; `(Some(avg_disk >= factor * avg_rd), "avg(t_disk)={F1(avg_disk)}ms vs avg(t_read+t_decode)={F1(avg_rd)}ms (threshold factor {D(factor)})")`.

**R-FOLDER** `evaluate_r_folder(cfg, gens)`: `thr = Get("R-FOLDER","folderT0ToT2Ms",1000)`. `with_t2` = gens with `t2_ms.is_some()`; empty -> `(None, "No folder generation has T2 (first image presented).")`. `worst` = the gen with the LARGEST `t2_ms`, the FIRST of equal ones (C# `MaxBy`; Rust `Iterator::max_by` returns the LAST maximum — write a manual loop with strict `>`). `(Some(worst.t2 > thr), "worst T0->T2={MS(t2)} (gen={generation}, T1 catalogReady={MS(t1)}, T3 {t3_phase}={MS(t3)}; threshold {D(thr)}ms)")` — with an empty `t3_phase` the text is `T3 =N/A`.

## Golden `perf-rules` (how to compare)
- `evaluate`: fields `rule` (R-IO ... R-FOLDER), optional `rules_json` (text of a rules file; write it to a `TempRoot` file and `RulesConfig::load` it; absent -> `RulesConfig::default()`), and the arguments: `navs` / `disk_navs` / `source_miss_navs` (arrays of nav specs, keys as in W1-17: `final_visual`, `t_read`, `t_decode`, `t_input`, `t_assign`, `t_render`, `t_disk`, `kind`...), `ram_hit_final_p95` / `non_ram_hit_share_pct` (numbers or `"NaN"`/`"Infinity"`), `frame_time_p95`, `is_burst`, `low_decode`, `high_decode`, `low_workers`, `high_workers`, `dispatcher_long_op_count`, `t_input_p95`, `gc_time_percent`, `gens` (`gen t1 t2 t3 t3_phase`). Expected `triggered` (bool or null), `evidence` (exact string), `note` (string or null), `result_rule`.
- `get`: `rules_json`, `rule`, `key`, `default` -> `value`.
- `load_error`: `error_type` is `InvalidDataException` -> expect `Err(PerfError::InvalidData(msg))` with `msg.starts_with("Invalid rules file '<path>': ")`; `none` -> `Ok`.
- `fmt`: `text` is a number (`"NaN"`, `"Infinity"`, `"-Infinity"` allowed): `fmt_fixed(v,1) == f1`, `fmt_fixed(v,2) == f2`, `fmt_double(v) == default`.
