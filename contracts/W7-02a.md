## Semantics notes
1. **What is delayed.** Exactly the C# set plus one Rust-only method: `file_exists`, `directory_exists`, `get_file_stat`, **`try_get_file_stat`** (P-12;
   not in the baseline; delay once, then call the INNER `try_get_file_stat` so a denied stat is not folded into `Ok(None)`),
   `try_probe_readable`, `resolve_real_path`: sleep `metadata_latency` once BEFORE delegating (the sleep also happens when the inner call then fails).
   `enumerate_files_with_stat` and `enumerate_readable_files_with_stat`: call the inner method first, return its `Err` untouched with NO sleep, otherwise
   sleep `metadata_latency` once per returned entry and return the list. No delay at all when `metadata_latency == Duration::ZERO` (C# `> TimeSpan.Zero`;
   do not call `sleep(0)`).
2. **What is forwarded untouched, one inner call each, no delay:** `move_file`, `copy_file`, `delete`, `open_append`, `write_all_text_atomic`,
   `read_all_text`, `enumerate_files`, `enumerate_directories`, `create_directory`, `try_delete_empty_directory`, and the two create-new copies.
3. **Every trait method is overridden, including those with default bodies** (same rule as `pr_core::io::counting`, copy its structure). Left-over defaults
   would silently change behaviour: `try_copy_new`/`try_copy_new_with_proof` default to "exists-check then copy" (loses the atomic create-new and would
   charge extra delays through `file_exists`); `enumerate_readable_files_with_stat` default calls `try_probe_readable` on `self` (would delay twice per
   entry); `try_get_file_stat` default calls `self.get_file_stat` (would lose the typed error). `try_copy_new_with_proof` passes the SAME `proof` reference.
4. **`open_read_shared`.** `inner.open_read_shared(path, buffer_size)?` first (an open error is returned as is, nothing wrapped, nothing consumed);
   with a limiter wrap in `ThrottledReadStream`, otherwise return the inner stream unchanged. No latency is charged for the open itself.
5. **`ThrottledReadStream::read`.** Inner read first, then `limiter.consume(read)` when `read > 0` (so a zero-length read and EOF cost nothing and an inner
   error consumes nothing). The count is passed as `i32` saturating (`i32::try_from(read).unwrap_or(i32::MAX)`). All `Read` provided methods
   (`read_to_end`, `read_exact`, `io::copy`) go through `read`, so they are metered too; do not override `read_vectored`/`read_to_end`.
   `Seek` is forwarded untouched (seeking, `Position` and `Length` are free). Stream length for tests: `seek(End(0))` then restore.
6. **Limiter arithmetic (port line by line; all values `f64` except ticks).**
   - `new`: `bytes_per_second <= 0` => `Err(InvalidBandwidth { bytes_per_second })` (C# `ArgumentOutOfRangeException`); `1` and `i64::MAX` are valid.
     Initial state `available_bytes = 0.0` (the bucket starts EMPTY), `last_ticks = time.now_ticks()`.
   - `consume(bytes)`: `bytes <= 0` returns immediately (no lock, no clock read). Otherwise `remaining = bytes as i64`; loop while `remaining > 0`:
     `chunk = min(remaining, bytes_per_second) as i32; consume_chunk(chunk); remaining -= chunk`. So `consume(250_000)` at 100 000 B/s is 3 chunks
     (100 000, 100 000, 50 000).
   - `consume_chunk`: `loop { lock; refill; if available_bytes >= bytes as f64 { available_bytes -= bytes as f64; return }; missing = bytes as f64 - available_bytes;
     wait_secs = missing / bytes_per_second as f64; drop the lock; sleep(max(Duration::from_secs_f64(wait_secs), Duration::from_millis(1))) }`.
     The sleep is OUTSIDE the lock (readers sharing the limiter must not serialize on a held lock). Recover from a poisoned mutex with
     `lock().unwrap_or_else(PoisonError::into_inner)`.
   - `refill`: `now = time.now_ticks(); elapsed = (now - last_ticks) as f64 / TICKS_PER_SECOND as f64; last_ticks = now;` (assignment BEFORE the early
     return, also for a negative elapsed) `if elapsed <= 0.0 { return }; available_bytes = min(bytes_per_second as f64, available_bytes + elapsed * bytes_per_second as f64)`.
     Use `saturating_sub` on ticks to stay panic-free with `i64::MIN`-ish fake clocks.
   - `Duration::from_secs_f64` panics on negative/NaN/overflow: `wait_secs` is always finite and `> 0` here (`missing > 0` because the `>=` test failed,
     `bytes_per_second >= 1`) and at most 1 second (`bytes <= bytes_per_second`, `available >= 0`). Do not add a cap.
7. **Time source.** `SystemTimeSource::now_ticks` = `origin.elapsed().as_nanos() / 100` saturated to `i64`; `sleep` = `std::thread::sleep`. C# used
   `DateTime.UtcNow.Ticks` (wall clock, can jump); `Instant` is monotonic. Documented in PARITY, not observable except under clock changes.
8. **Concurrency model.** `SharedBandwidthLimiter` is `Send + Sync` (a `Mutex<Bucket>` and an `Arc<dyn TimeSource>`); `SlowLinkFileSystem` is `Send + Sync`
   because `FileSystem: Send + Sync` and every field is. No `unsafe`. No global state.
9. **Accepted differences (record as `// DIVERGENCE:` in tests and as notes in the PARITY row):**
   (a) C# `EnumerateFilesWithStat`/`EnumerateReadableFilesWithStat` are lazy iterators that sleep between yielded entries; the trait returns a `Vec`, so Rust
   lists first and sleeps `N * latency` afterwards. Total latency is identical, the interleaving with a caller that consumes entries as they arrive is lost
   (the only caller that cares, the folder scan, collects the list anyway).
   (b) `Duration`/`Arc` cannot be negative/null, so the two constructor guards (`ThrowIfLessThan(metadataLatency, Zero)`, `ThrowIfNull(inner)`) have no image.
   (c) C# `Thread.Sleep(TimeSpan)` truncates to whole milliseconds; Rust sleeps the exact computed duration (never shorter than 1 ms). Timing only.
   (d) `Write` on the stream throws `NotSupportedException` in C#; the Rust type has no `Write` impl (compile-time).
   (e) `Dispose` closing the inner stream is `Drop` of the boxed inner.
   (f) C# `ThrottledReadStream` also forwards `CanRead`/`CanSeek`/`Flush`/`SetLength` and has span and async read overloads that all end in the two metered `Read`s; Rust has the single `Read::read`
   (every provided method goes through it) and no `Flush`/`SetLength` (read-only `ReadSeek`).
- Float-noise trap for the fake-clock tests: the fake sleeps the exact computed `Duration`, converts it to ticks rounding UP, and the refill multiplies a tick-derived `f64` by `bytes_per_second`. For the
  values listed in the tests (0.1 s x 1000, 1 ms x 1000, 0.01 s x 1000, 1 s, 0.5 s) the product is exactly the needed byte count (checked by hand), so the exact `[100 ms]`-style assertions hold. For
  tests that sum many sleeps with arbitrary chunk sizes (`read_to_end`, `limiter_is_shared_between_streams` is fine) assert `total >= expected` and `total <= expected + 5 ms` instead of equality: a last-ulp shortfall
  costs one extra 1 ms floor sleep and is not a bug.
- Traps checklist (§7): 3 (`i32`/`i64`/`f64` arithmetic: `chunk` cast, `bytes_per_second` up to `i64::MAX`; no `as` truncation surprises, see
  `consume` above), 5 (time: ticks are 100 ns, same constant as C#), 9 (each C# `?:` branch is a Rust branch: limiter `None` vs `Some` in `open_read_shared`),
  10 (nothing here leaks a hash order; the oracle sorts names).

## Open questions

  W7-02b only needs `ThrottledReadStream::new` and `SharedBandwidthLimiter::new`.

  `Err(InvalidBandwidth)` to its own exit/diagnostic path the same way (not `unwrap`); not this unit's code.
- `ThrottledReadStream` is `pub` (C# `internal`) because `SlowLinkSourceReader` lives in another module and the integration tests are an external test crate. Alternative: `pub(crate)` plus in-module tests; lead decides.
