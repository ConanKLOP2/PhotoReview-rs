## Semantics (C# is the spec)
### One pass (`Run`, C# 125-159; `RunNested` has the same body between the checks)
1. `pass_count += 1`. 2. `dispatcher.has_high_priority_work()` -> `run_high_priority_batch()`. 3. `poll_clocks()?`. 4. `pump_messages()` -> `Some(exit)` ends `run` with `Ok(exit)`.
5. `has_high_priority_work()` -> next pass. 6. `has_background_work()`: if `!os.is_message_pending()` -> `try_run_background()`; next pass (even when the queue had a message: the message is pumped first). 7. `!os.is_message_pending()` -> `wait()?`. (If a message is pending the pass repeats.)
`run` returns `Err(InvalidOperation { message: "MessageLoop.Run is not re-entrant." })` if already running (checked after `verify_access`); `running` is cleared on every exit (use a drop guard so an `Err` or a resumed panic clears it).
`run_nested(is_done, claim)`: `while !is_done()` { the same steps 1-3; `pump_messages(claim)` `Some(exit)` -> `os.post_quit(exit)`; return `Ok(false)` (WM_QUIT is POSTED AGAIN for the outer loop, lesson #486); `if is_done() break`; steps 5-7 }; `Ok(true)`. `run_nested` may be called while `run` is on the stack (that is its purpose).
### `pump_messages(claim)` (C# 225-260)
For `pumped in 0..MAX_MESSAGES_PER_PASS`: `peek_message(remove = true)` false -> return `None`; `msg.message == WM_QUIT` -> `Some(msg.wParam as i32)` (the cast truncates like C# `(int)message.WParam`); else if `claim` is given and `claim(&mut msg)` is `true` -> `pending_panic::rethrow_pending()`;
else if `!filtered(&msg)` -> `translate_and_dispatch(&msg)`, then `rethrow_pending()`; after each message: `has_high_priority_work()` -> return `None` (Normal work posted by that message runs before the next input message). After 32 messages return `None` (the clocks and the dispatcher get their turn).
`filtered`: snapshot the filter list (a filter may remove itself); for each filter in registration order: `as_raw()` is `Some(raw)` -> `raw.pre_filter_raw_message(&msg)` INSTEAD of the plain callback, else `pre_filter_message(&WindowMessage { hwnd, msg: message, wparam, lparam })`; the first `true` wins.
### `poll_clocks` (C# 285-304) and `wait` (C# 306-353)
`poll_clocks`: for each clock (snapshot) that `is_armed()`: `handle = wait_handle()`; `handle != 0 && os.poll_handle(handle)` -> `on_signaled()?`; **else** `ticks_until_deadline() <= 0` -> `on_deadline()?`. (A signaled clock does not also get `on_deadline` in the same poll.)
`wait`: iterate the clocks; for each armed one: `until_deadline = min(until_deadline, ticks_until_deadline())`; if `wait_handle() != 0` and fewer than `MAX_WAIT_HANDLES` collected, push the handle and remember the owner (a 64th armed clock still counts for the deadline but is not waited on). `timeout = wait_timeout_ms(until_deadline, qpc_frequency())`.
`wait_count += 1`; `outcome = os.wait(&handles, timeout)`: `Failed(e)` -> `Err(Win32 { operation: "MsgWaitForMultipleObjectsEx failed", error: e })`; `Handle(i)` -> `owners[i].on_signaled()?` (the wait consumed the signal: auto-reset object / timer); `Messages`/`Timeout` -> nothing (the next pass looks). Owners are cleared afterwards even on `Err`.
`wait_timeout_ms(until, freq)`: `i64::MAX` -> `INFINITE (0xFFFF_FFFF)`; `<= 0` -> `0`; else `min(ceil(until * 1000 / freq), 0xFFFF_FFFE)` in `i128` (the C# `(untilDeadline * 1000)` overflows `long` above 9.2e15 ticks).
### `Win32LoopOs`
`peek_message` = `user32::peek_message(msg, 0, 0, 0, PM_REMOVE | PM_NOREMOVE)`; `is_message_pending` = peek with `PM_NOREMOVE` into a scratch `Msg`; `translate_and_dispatch` = `translate_message` then `unsafe { dispatch_message }` (`// SAFETY: msg was filled by PeekMessage on this thread`); `poll_handle` = `wait_for_handle(HANDLE(h as _), 0, false).is_signaled()`;
`wait` = `msg_wait_for_multiple_objects_ex(handles, timeout, QS_ALLINPUT, MWMO_INPUTAVAILABLE)` decoded: `WAIT_FAILED` -> `Failed(Win32Error::last())` read immediately; `r < n` -> `Handle(r)`; `r == n` (`WAIT_OBJECT_0 + n`) -> `Messages`; anything else -> `Timeout`. `post_quit` = `post_quit_message`.
### `pending_panic` (C# `WndProcThunk` 16-38)
`capture` keeps the FIRST payload on this thread (`thread_local! RefCell<Option<Box<dyn Any + Send>>>`; C# `??=`); `rethrow_pending` takes it (the slot is empty afterwards) and `std::panic::resume_unwind(payload)`; nothing pending returns. `guarded(on_panic, body)` = `catch_unwind(body)`, on `Err` `capture` and return `on_panic`.
`resume_unwind` does not invoke the panic hook a second time: the hook already ran where the panic started (inside the window procedure), so the message appears once. Document it.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1: MAXIMUM_WAIT_OBJECTS: 64 handles including the message queue slot -> 63 clock handles; the 64th armed clock must not make `MsgWaitForMultipleObjectsEx` fail with `WAIT_FAILED` (test with 70 armed fake clocks).
- T2 (message pump re-entrancy): `run` is not re-entrant, `run_nested` is meant to nest; filters/clocks/handlers may add or remove filters and clocks from inside a callback: every iteration works on a snapshot (`Vec` clone of `Rc`s), never on the `RefCell` borrow (a borrow held across a callback is a panic waiting to happen).
- T3 (WM_QUIT): never swallowed by a nested loop (re-post), `exit_code` is `wParam as i32`; `WM_QUIT` is checked BEFORE the claim/filters so no filter sees it.
- T4 (posted-message wake): the loop itself needs nothing for the dispatcher's wake message: `WM_APP + 1` is an ordinary message that makes `MsgWaitForMultipleObjectsEx` return `Messages` and the next pass drain the queue; `Wait` must therefore NOT wait when `is_message_pending()` (mutant: waiting regardless would sleep on a posted wake).
- T5: Background item only when the OS queue is empty (C# mutant M7); a message posted DURING the Background item makes the next pass pump it before another Background item.
- T6: the order `high-priority drain -> poll clocks -> pump` (input must not run before a pending Normal item; a frame must not be drawn before pending Render work).
- T7: the deadline poll uses `<= 0` (a deadline exactly now fires); a remaining time above 0 rounds UP to whole milliseconds (a deadline in 0.2 ms waits 1 ms, so the loop does not spin with 0 ms waits); only `<= 0` gives 0.
- T8: `PassCount` must stay small when idle (the test asserts "blocked at least 9 times in 10 ticks, at most 100 passes", no spinning).
- T9: a panic resumed from `rethrow_pending` leaves the loop in a defined state: `running` cleared (drop guard), the filter/clock lists intact.
- T10: `peek_message` filter range `(0, 0)` means "all messages" and `hwnd = 0` means "any window of this thread AND thread messages": do not pass a window handle.

## Safety rules (`// SAFETY:` per block)
`Win32LoopOs::translate_and_dispatch` (one `unsafe { dispatch_message(msg) }`: the `Msg` came from `peek_message` on this thread, so `wparam/lparam` match what the target window procedure expects; the procedure itself is panic-guarded). `poll_handle` builds a `HANDLE` from an integer and passes it to the safe `wait_for_handle`: a stale handle only fails the wait.
`pending_panic` has no `unsafe`.

| `InvalidOperationException("MessageLoop.Run is not re-entrant.")` | `HostError::InvalidOperation` |
| `Win32Exception(.., "MsgWaitForMultipleObjectsEx failed")` | `HostError::Win32 { operation: "MsgWaitForMultipleObjectsEx failed", .. }` |
| `ArgumentNullException` (null dispatcher, clock, filter) | unrepresentable |
| `_dispatcher.VerifyAccess()` `InvalidOperationException` | `LoopDispatcher::verify_access` -> `HostError::InvalidOperation` from `new` |
