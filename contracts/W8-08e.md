- Decision **D-08e-1 (the sinks are recorders).** The coordinators take the catalog AND the sink in one call (`FolderLoadCx { catalog: &mut ReviewCatalog, sink: &mut dyn IFolderLoadSink }`, and the same for file actions and duplicates). The view model cannot be the sink, because the sink calls read the
  catalog (count, current index) and drive the presenter, which the call has borrowed. `SinkLog` implements `IFolderLoadSink`, `IFileActionSink`, `ISiblingNavigatorSink` and `IDuplicateCleanupSink` by recording owned `SinkAction`s. After every coordinator call (entry point or event) the view model calls `apply_sink_actions`, which
  replays them IN ORDER with full access, repeating until the log stays empty (a replayed `open_folder` calls the folder coordinator, which records more). The replay is the C# method body of each sink member. Consequence (trap T3): an action sees the state after the whole coordinator step, not in the middle of it.

- Semantics notes:
  1. **Replay bodies** are listed in the stub doc of `apply_sink_action`; each is the C# body at the cited lines. Common tail of the three catalog events: `catalog_changed = true` then `notify_navigation_state_changed()`. `CatalogReady` assigns the event status WITHOUT a report; `Empty*` and `Failed` use the reporting setter.
  2. **`notify_navigation_state_changed`** (1088): `CanNavigateNext`, `CanNavigatePrevious`, `HasImages`, `CurrentHasCapturePair`, `CapturePairBadge`, `CurrentIndex`, `TotalFiles`, `CurrentImage`, `StatusText`, the four EXIF-line properties, and the title. `StatusNeedsAttention` is deliberately absent (as C#).
  3. **`OrderApplied`** (1160): the folder line is re-rendered with the session folder when there is one; without a session the already shown folder and count are kept and only the order flag is set (and only when it was not yet set). The preload is cancelled, then re-centred only when `current_kept && current_index >= 0`.
  4. **`UnreadableRemoved`** (1186): the C# method is `async` only because it awaits the present; here the present is a request. Removed paths are evicted one by one; an eviction error is logged and the loop continues.
  5. **`LateStatus`** (1235): the hint is dropped unless the event status is empty (it must not replace the new folder's "catalog just listed" / "no images" / error text). `ShowLateActionStatus` of the duplicate sink is the same.
  6. **`UpdateSessionPath`** (1264): no session -> nothing; else `current_path`, `updated_utc = now (Utc)`, `persist_session()`.
  7. **`ActionPresent`** sets `controller_present_outstanding`; `apply_sink_actions` ends by delivering `on_present_finished(cx, false)` to the file-action controller when the presenter is idle (08c O2).
  8. **Move / Copy to.** `move_to_folder(force_picker)` / `copy_to_folder(..)` submit `QueuedKind::MoveCopy` (same gate, epoch and pipeline as `run_action`). The turn body is `begin_move_copy`: `get_source` is the SNAPSHOT `(compare selected path, catalog current path)`; the picker is `self.folder_picker`.
     `remember_move_copy_folder` runs inside the controller (its `remember_folder` delegate) after a successful operation, see the stub doc and 08a `SettingsSource::begin_edit` / `commit_edit`.
  9. **EXIF line.** `exif_text` is empty without `presenter.current_photo_info()` (loading, compare mode, nothing shown); `is_exif_line_visible` needs the master switch AND `show_exif_info` AND non-empty text; `exif_automation_name` = catalog text `main.exif.automationName` with `{details}`. The modified time is the catalog entry's
     last write (no disk read), converted with `FormatContextSource::to_local_time`.
- Traps checklist:
  - **T1 Order of recorded calls is preserved**; never reorder or merge actions in the log (a `SetStatus` followed by `ActionPresent` must replay in that order: the present clears the event status for the folder-load path but NOT for the file-action path).
  - **T2 `FolderPresent` clears the event status silently, `ActionPresent` does not** (C# `IFolderLoadSink.PresentAsync` sets `_statusText = ""`; `IFileActionSink.PresentAsync` does not).
  - **T3 State after the step.** A controller that calls `sink.present(next)` and afterwards mutates the catalog in the SAME synchronous step would have presented against the earlier catalog in C#, but presents against the later one after the replay. The 07c/07d/07e stubs describe
    "remove, present, then I/O" (INV-3) and "restore, then present" for undo, which are safe; this contract did NOT check every call site, so the porter verifies it with `RunActionAsync_Move_PresentsNextBeforeMoveCompletes_PreservingInv3` and `UndoAsync_RestoresMovedFile_InsertsSortedAndPresents` and reports any step that changes the catalog after a `present` request.
  - **T4 Preload ordering (R2-F-01).** `preload.cancel()` comes before `preload_around` on every path that re-centres (new folder, order applied, unreadable removal); a test with the recording preload asserts the event order `cancel`, `preload:<index>`.
  - **T5 Eviction is per path** (R2-F-02): never clear the whole cache for a removed image; the next image must stay in RAM (`RunActionAsync_Move_KeepsNextImageCachedAndEvictsOnlyRemovedOne`).
  - **T6 `CatalogChanged` once per callback group**; the change set carries a bool, the tests assert it is true after the callbacks that raised the C# event and false after the others (`SetStatus`, `LateStatus`, `FilesSkipped`).
  - **T7 Skipped entries**: a new catalog clears them ONLY when there were any (no spurious `SkippedEntries` report: `OpeningAFolder_WithNothingSkipped_DoesNotRaiseTheSkippedEntriesChange`).
  - **T8 Settings write**: `remember_move_copy_folder` must not lose another setting that changed in the meantime: it clones the CURRENT settings (store or override) at the time of the call.
  - **T9 Text**: statuses come from `viewmodels::format::status` and the catalog (`main.exif.automationName`); the EXIF line from `format_exif`; no literals (D-W8-4).
  - **T10 Debug**: `SinkLog` and `SinkAction` derive `Debug` (done in the stub).

## Open questions (each has a recommended default; the stubs follow it)
- **O1 The recorder design (D-08e-1) versus per-call sinks owning a `&mut MainViewModel`.** Impossible while the coordinator holds `&mut catalog` from the same view model. Alternative: coordinators own `Rc<RefCell<ReviewCatalog>>` (rejected by D-W8-1). Recommended: as stubbed.
- **O2 `on_failed` text.** `UserFacingError.Describe` has no Rust port; `describe_error` uses `error.to_string()` (the `FolderLoadError` `Display` is already localized). Replace in one place when `UserFacingError` is ported.
- **O3 `faulted` of `on_present_finished`** is always false (08c O2); a faulted present is logged by the presenter.
- **O4 Fire-and-forget preload.** C# `TaskLogging.FireAndLog(() => preload.PreloadAroundAsync(i), "Preload after .. failed")` logs a faulted task; the Rust `IPreloadController::preload_around` returns a `RunHandle` the view model drops. Recommended: drop it (the scheduler logs its own failures); if the scheduler does not, observe the handle with `misc::task_logging::observe_receiver`.
- **O5 `ImageChanging` timing.** The bridge records it during the presenter call (08a); this unit's `notify_navigation_state_changed` does not raise it again.
