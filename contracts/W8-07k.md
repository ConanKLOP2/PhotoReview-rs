- Semantics notes (line numbers are `ImagePresenter.cs`):
  1. **`remove_or_degrade` (719 to 730).** `index = catalog.index_of(path)`; `group` only when `index >= 0`; `survivor` = the first image path of the group that is not `path` (OrdinalIgnoreCase, `pr_core::text::eq_ignore_case`); none: `return catalog.remove(path)`. Else `catalog.remove(path)`, `catalog.restore(survivor, index)`, `catalog.set_current(index)`, return `index`. The survivor becomes a
     STANDALONE entry (the restore carries no group) at the SAME position and is selected. `path` may be a member path of the entry (the catalog resolves members).
  2. **The skip loop (735 to 770).** Rounds: token check; `remove_or_degrade`; empty catalog: reset the presentation state (`current_photo_info`, `info_while_original_shown`, `zoom_detail.reset()`, image `None`, compare clear) and the status `no_images_remaining` WITH attention, end; `next_index` outside `[0, count)`: end; stat the next path (no cancellation);
     token check; only a `Missing` next photo is skipped (loop with `path = next_path`); `Found` AND `Error` end the run with a normal `present(next_index)` so an unreadable photo reports its error instead of being dropped. The skip is iterative: N consecutive missing files cost N stat jobs and ONE extra `present` (`notify_navigation` is called exactly twice in the 200-file test).
  3. **Stale token.** Every round starts with `is_navigation_current(run.token)`; a stale run changes neither the catalog nor the screen (test `StaleToken_*`: the token was taken, then the clock advanced). The token is the CALLER's: `remove_missing_catalog_item(path, token)` may be called with a token the caller took itself (the test does).
  4. **Pair lookup (772 to 791).** See the stub doc: capture-group pair only when requested AND the entry has a group, else the version-keyed `CompareIndex`; keys OrdinalIgnoreCase (the type does it); rebuild when `structural_version` differs from the cache. No lock (UI thread only, `&mut self`).
  5. **`stat_now` (901 to 925).** The classification of `stat_error_means_missing` is the whole behaviour: a path that can never name a file is "missing" so the skip loop does not park on a permanent `Error` item; every other failure keeps the photo (a flaky share never silently loses a photo). `Ok(None)` from the file system is `Missing` (also for a directory).
  6. **`submit_stat` (892).** Always the stat worker thread; never inline. A cancelled token drops the job without an event.
  7. **`try_get_original_dimensions` (848 to 863).** Expected header-read failures give `Ok(None)` and one `AppLog` info line when enabled (`ShowImage original dimensions unknown path=..: <ErrorKind or variant name>: <message>`); everything else is returned.
  8. **`load_compare_preview_blocking` (870 to 884).** `attempt 0` busy: wait `BUSY_RETRY_DELAY` through the injected delay (cancellable by the navigation token), try once more; a second busy result and any other error are returned; the cache key is rebuilt for the path each attempt exactly like C#
     (`get_current_cache_key(path)`); the preview comes from `get_viewer_preview` with zero start delay (the viewer lane, so a pair on screen does not fail fast like a preload).
  9. **`PhotoInfo::from_image` (942 to 948).** File name by .NET `Path.GetFileName` rules (`pr_core::text::dotnet_path::get_file_name`), size = ORIGINAL (post-orientation) size, EXIF as the decoder / cache entry carried it, RAW preview size from `embedded_preview_size()` or 0.
- Traps checklist (MULTI-AGENT-PLAN section 7 items 1, 3, 4, 8, 10 apply; specific items below):
  - **T1 iterative, not recursive.** `on_missing_next_stat` loops through events; it must not call itself or `missing_step` recursively more than one level, and must not call `present` for a skipped file.
  - **T2 degrade order.** `remove` BEFORE `restore`, `restore` BEFORE `set_current`; restoring first would collide with the existing group entry. Use the post-remove `index` unchanged.
  - **T3 `next_index` is not re-read.** `present(next_index)` uses the value computed in the round (C# passes `nextIndex`); a catalog change between the stat request and its result is the caller's problem, as in C#.
  - **T4 `Error` is not `Missing`.** Only `StatOutcome::Missing` is skipped; the `Error` outcome of the next photo is presented (test `NextPhotoStatFailsWithIoError_DoesNotSkipIt` expects `[flaky]` left).
  - **T5 cache key text.** The compare index is keyed OrdinalIgnoreCase; never lower-case with `to_lowercase` (use the index's own lookup).
  - **T6 no I/O on the UI thread.** `stat_now`, `try_get_original_dimensions`, `load_compare_preview_blocking`, `compare_file_size` run on workers only; `has_compare_pair` / `get_compare_pair` read the catalog only (the index build is O(n log n) on the UI thread but cached by version, as in C#).
  - **T7 worker panics** (R0003): `NavigationStatWorker` reports a panic as `StatError::Panicked`; the job body therefore never sends an event for it. The presenter stays at its `Phase` until the next navigation supersedes it; this is the Rust form of a faulted C# task. Test: a panicking file system fake does not kill the stat thread (W2-15 pins that; here only assert the next present works).
  - **T8 `PhotoInfo` equality** is value equality including `exif`; the RAW-info tests of 07h compare whole records.
  - **T9 Windows paths.** File-name and extension rules are .NET's (`dotnet_path`), compare paths OrdinalIgnoreCase (`pr_core::text`), never `Path::file_name` of `std` for text shown to the user.

## Open questions (each has a recommended default; the stubs follow it)
- **O1 `has_compare_pair` takes `&mut self` and the catalog.** C# `HasComparePair(path)` is a pure query over a captured catalog; the cache write forces `&mut self`. Default: `(&mut self, &ReviewCatalog, &str) -> Result<bool, PathError>`. Alternative: `RefCell` cache with `&self` (rejected, D-W8-1). The main view model calls it from a command, where `&mut presenter` is available.
- **O2 `PathError` in `has_compare_pair`.** C# lets the exception escape into the view-model getter. Default: surface it as `Err`; the caller maps it to `false` and logs. Alternative: swallow here. Catalog paths come from a folder scan, so this is unreachable in practice.
- **O3 `stat_error_means_missing` and `io::ErrorKind`.** Default: exactly the C# exception list as Rust kinds (NotFound, InvalidInput, Unsupported, InvalidFilename, raw 206). `PhysicalFileSystem::try_get_file_stat` already folds names the OS rejects into `Ok(None)` (its doc), so no further OS codes are needed; if a Windows code turns out to escape as `Err`, add it
  to the list and to the table test, nothing else changes.
- **O4 Ownership of `ComparePairCache`.** Default: a field of the presenter. Alternative: a free function over an explicit cache owned by the view model. No behavioural difference.
