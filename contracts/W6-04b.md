## Required behavior

- Implement the internal driver API used by W6-04a: nearest monitor for nonzero HWND; open monitor adapter/source;
  wait for vblank and return native status; close adapter; query DWM timing.
- Preserve missing native library and missing entry point as distinct typed failures from adapter open and vblank wait.
  `WindowsDisplayClock` logs the corresponding C# exception type/message and marks only that monitor failed; do not
  collapse either import failure into an NTSTATUS sentinel. If opening fails after creating an HDC, release the HDC
  before propagating the import failure.
- `NativeVBlankDriver::Instance` is a process singleton. Match C# native layouts and calls exactly: `MONITORINFOEXW`
  size 104, packed `DWM_TIMING_INFO` size 292 bytes, `MONITOR_DEFAULTTONEAREST`, device name
  extraction up to first NUL and at most 32 UTF-16 code units, release GDI DC on every path, D3DKMT status handling,
  and adapter-close semantics.
- DWM returns `None` on native API failure, missing DLL/entry point, or zero QPC period/vblank; otherwise map the two
  QPC fields to `DisplayTiming`.
- Keep D3DKMT / Win32 / DWM imports and unsafe blocks in `pr-platform-win` only. Every unsafe block needs a precise
  `// SAFETY:` comment describing pointer lifetime, buffer size, ABI and ownership assumptions.
- Preserve the existing Rust Core abstractions; do not move `DisplayTiming`, `DisplayClock`, or `VBlankEstimator`.

## Tests and safety

- Add bounded pure ABI checks for the `MONITORINFOEXW` size (104 bytes), packed timing-info size (292 bytes: 7 `uint`,
  31 `ulong`, and two 8-byte `UnsignedRatio` fields), and device-name conversion (NUL termination and 32-unit limit).
  These should not invoke real display APIs.
- Native smoke `DwmTiming_Static_ReturnsNullOrAPositiveGrid` must be `#[ignore = "native: requires Windows DWM"]`,
  bounded, and reported as ignored when not run. It is not evidence for worker behavior.
- There are no filesystem or Recycle Bin operations in this unit. Native smoke only queries display timing; never change
  display configuration. Any test-created OS resource must be released on success and failure.
- Mutation expectations: monitor selection constant, `cbSize` and packed layout, 32-unit/NUL conversion, DC cleanup,
  nonzero status handling, DWM native failure/missing entry behavior, zero-field rejection, QPC field mapping, and
  adapter closure.
- Gates: `cargo fmt --all --check`; `cargo clippy -p pr-platform-win --all-targets -- -D warnings`;
  run pure ABI tests by default, native smoke only on Windows with explicit ignore override and a finite harness timeout;
  final integration runs the workspace gates.
