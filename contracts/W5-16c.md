## Semantics notes
1. **Seams instead of P/Invoke.** C# calls `LibRawNativeMethods.*` on a `SafeLibRawHandle`. Rust: `LibRawApi::init() -> Result<Box<dyn
   LibRawSession>, DecodeError>` (null => `InvalidOperation` `INIT_FAILED_MESSAGE`; an unloadable DLL => `DllNotFound`/`EntryPointNotFound`,
   which C# P/Invoke throws from `LibRawInit` and which stay fallbackable: `map_native_error`), every handle call is a `LibRawSession` method,
   `make_mem_image`/`make_mem_thumb` return `Box<dyn ProcessedImage>` or `Err(error_code)`. THIS unit owns the production adapter
   `NativeLibRaw` (1:1 forwarding to W5-15a `native::LibRawHandle<'static>`: `open_buffer` -> `open_shared_buffer`, `set_progress_handler` ->
   `set_cancel_token`, `data()` -> `data().unwrap_or(&[])`); tests implement the seams with scripted fakes that record calls.
   `format_error(code)` (= C# `FormatError`) is passed as `&dyn Fn(i32) -> String` to the pure helpers (`|c| api.format_error(c)` in production).
   `CancelToken::check()` returns `Result<(), Canceled>` and there is no `From<Canceled> for DecodeError`: write `.map_err(|_| DecodeError::Canceled)`
   (or a private helper).
2. **`decode_with_cancel` (C# `Decode(request, ct)`), exact order:** (1) `is_blank_path(request.path)` => `blank_argument_error("request.Path")`;
   (2) `!apply_orientation` => `NotSupported` `ORIENTATION_REQUIRED_MESSAGE`; (3) `cancel.check()` => `Canceled`; (4) `lease = gate.enter(priority, cancel)?`
   (`Busy` = W5-16a `PRELOAD_QUEUE_BUSY_MESSAGE`, never fallbackable); (5) body = `core_override` or `decode_core`, lease held; (6) `Err(OutOfMemory)` =>
   `InvalidOperation` `NOT_ENOUGH_MEMORY_MESSAGE`, all other results unchanged; the lease drops on every path (also on a panic: RAII). `decode` = with
   `CancelToken::none()`; `decode_cancellable` = with the token; `as_cancellable` = `Some(self)`.
3. **`decode_core` (stage order is pinned by 5 tests):** `session = api.init()?`; `set_progress_handler(cancel.clone())`;
   `configure_output` = `set_output_color(1)`, `set_output_bps(8)`, `set_no_auto_bright(1)`, `try_set_use_camera_wb(1, 8, 1)` (result ignored), stage
   `configured` (ALL before open: trap T3); open: `request.bytes` `Some(b)` => `check_result(open_buffer(b.clone()), "open RAW buffer")`, else
   `open_file_with(|p| session.open_wfile(p), path, ..)`; stage `opened`; `admit_decode(&SessionProbe, request, &lease)?`; `check_result(unpack(), "unpack RAW data")`;
   stage `unpacked`; `cancel.check()`; `check_result(dcraw_process(), "process RAW data")`; stage `processed`; `cancel.check()`; `make_mem_image()`:
   `Err(code)` => `cancel.check()` then `create_failure(code, "create decoded image")`; `header = image.header()`; **drop the session** (libraw_close
   frees the 8 B/px working image and only then the pinned bytes); stage `handle-closed`; `!is_supported_bitmap` => `InvalidData`
   `UNSUPPORTED_PROCESSED_IMAGE_MESSAGE`; `rgb_len = validate_source_length(w, h, i64::from(data_size), colors)?` (W5-17, `i32`; to `usize` via
   `try_from`, never `as`); `(tw, th) = request.decode_box().fit(w, h)`; `validate_target_length(tw, th)?`; `pixels = resize_to_buffer(
   image.data().get(..rgb_len) /* None => InvalidData */, w, h, tw, th, colors, cancel)?`; every W5-17 error through `map_resample_error`
   (a `PixelBuffer` OOM becomes `OutOfMemory` and then, in step 6 of semantics 2, `InvalidOperation`, like the C# catch); **drop the image**
   (libraw_dcraw_clear_mem) BEFORE the hand-off; `hand_off(&mut pixels, is_downscaled(tw, th, w, h), w, h, &|| true)`. Every check of a native result uses
   `check_result(code, op, cancel, fmt)`: a failure while canceled is `Canceled` (LibRaw's own `LIBRAW_CANCELLED_BY_CALLBACK` becomes `Canceled` this way).
4. **Admission (`admit_decode`, C# `AdmitDecode` + `EnsureMemoryHeadroom`):** probe `width()`, `height()`; either `<= 0` => skip the estimate (memory
   source NOT read), `mark_worked()`, `Ok`. Else fit, `memory_info.read()`, `classify(decoder_name().as_deref(), structure())`, `estimate_peak_bytes(w, h, tw,
   th, raw_width(), raw_height(), family)`, `has_headroom(estimate, total, load)` false => `InvalidOperation` `NOT_ENOUGH_MEMORY_MESSAGE` and the lease is
   NOT marked; true => `mark_worked()`. The fake probe in the C# test asserts `decoder_name` AND `structure` were read.
5. **Thumbnail trim (`find_end_of_image`, golden `trim-*`, 67 cases).** `len < 4 || b[0] != FF || b[1] != D8` => error. `end = len`; while `end > 2 &&
   b[end-1] in {00, FF}`: `end -= 1`; `end >= 4 && b[end-1] == D9 && b[end-2] == FF` => `end`. Else the structure walk from `i = 2`: loop { `i >= len ||
   b[i] != FF` => None; skip all `FF`; `i >= len` => None; `marker = b[i]; i += 1`; `D9` => `Some(i)`; `00 | 01 | D8 | D0..=D7` => continue; `i + 2 > len` =>
   None; `seg = b[i] << 8 | b[i+1]`; `seg < 2` => None; `i += seg`; `i > len` => None; marker `!= DA` => continue; entropy: loop { `i >= len` => None;
   `b[i] != FF` => `i += 1`; `i + 1 >= len` => None; `next = b[i+1]`; `00 | D0..=D7` => `i += 2`; `FF` => `i += 1`; else break } }. Else the fallback:
   `start = max(2, len - 65536)` (saturating), `i` from `len - 2` DOWN TO `start`: first `FF D9` found; tail pairs `j in i+2 .. len-1` with `b[j] == FF` and
   `b[j+1] in {D8, DA, DB, DD, FE, C0..=CF, E0..=EF}` => None (do not try an earlier EOI); else `Some(i + 2)`. Nothing => error. All arithmetic in `usize`
   with the C# bounds; no slicing that can panic (hardening: the fuzz-style golden rows include 0-, 1- and 3-byte streams).
6. **Extended path (`to_extended_length_path`, golden `extended-path-*`, 25 cases).** Length = `path.encode_utf16().count()` (C# `string.Length`: the
   non-BMP rows prove a `chars().count()` port wrong). `< 248` => None; `starts_with(r"\\?\") || starts_with(r"\\.\")` => None (ordinal, no `/` variants:
   `//./C:/..` IS converted, golden row); `!dotnet_path::is_path_fully_qualified` => None; `dotnet_path::get_full_path` `Err` => None (NUL inside);
   `full.starts_with(r"\\")` => `\\?\UNC\` + `&full[2..]`, else `\\?\` + `full`. `open_file_with`: `code = open(path)`; `code == LIBRAW_IO_ERROR` and an
   extended form exists and `open(ext) == 0` => Ok (2 calls); otherwise `check_result(code /* original */, "open RAW file")` (1 or 2 calls).
7. **Failure map.** `create_failure`: `-100007 | 12` => `InvalidOperation` `NOT_ENOUGH_MEMORY_MESSAGE` (format_error not called); else `InvalidData`
   `LibRaw could not {op}: {format_error(code)}`. Operation texts (verbatim): `open RAW file`, `open RAW buffer`, `read RAW dimensions`, `unpack RAW data`,
   `process RAW data`, `create decoded image`, `unpack embedded thumbnail`, `create embedded JPEG thumbnail`. `check_result(0, ..)` is `Ok` even when canceled.
8. **`read_info` / `read_jpeg_thumbnail`:** see their doc comments. `read_info` has no progress handler and no cancellation (C# `CancellationToken.None`);
   `read_jpeg_thumbnail` checks `cancel` before anything (no `init` call when already canceled), after `unpack_thumb` and at the end; it copies exactly
   `data_size` bytes (`image.data()` is that long; header validated first so `data_size <= 32 MiB`) and returns the trimmed `Vec` (truncate in place).
   Neither touches the gate. `validate_thumbnail_header` message: `LibRaw returned an unsupported or oversized thumbnail (type={type}, width={w},
   height={h}, bytes={data_size}).` (integers in invariant decimal; golden pins it).
9. **Junk files (native golden + corrupt-file tests):** xorshift32, `x = seed (0 -> 1)`; per byte `x ^= x << 13; x ^= x >> 17; x ^= x << 5` (u32 wrapping),
   byte = `x & 0xFF`. Same generator in `oracle/W5-16c.cs` and the Rust test support.
10. **Blank paths.** `is_blank_path`: empty or all `char::is_whitespace` (equals .NET `char.IsWhiteSpace`; golden row with TAB, NBSP, EM SPACE).
    `blank_argument_error(p)` = `InvalidArgument { "The value cannot be an empty string or composed entirely of whitespace. (Parameter '{p}')" }`; the
    parameter names are `request.Path` (decode) and `path` (read_info, read_jpeg_thumbnail). The golden `guard-*` cases are the authority for the text.

## Traps checklist (MULTI-AGENT-PLAN §7 + unit specific)
- T1 (§7.3 arithmetic): header fields are `u16`/`u32`; `w`/`h` to `i32` via `i32::from`; `data_size` vs `MAX_THUMBNAIL_BYTES` in `u32`; trim indices
  `usize` with explicit bounds (`i + 2 > len` before reading); `len - 65536` saturating; never `as` casts that wrap.
- T2 (§7.9 exception -> Result): one `DecodeError` per C# throw: `InvalidArgument` (blank), `NotSupported` (orientation), `Canceled` (every
  `ThrowIfCancellationRequested` and failure-while-canceled), `InvalidOperation` (init null, OOM codes, admission, managed OOM), `InvalidData` (other
  codes, headers, trim, dimensions, unsupported bitmap), `Busy` (gate). INV-12: `InvalidOperation`/`Canceled`/`Busy` are NOT fallbackable, `InvalidData` is.
- T3 (open order, C# comment in `DecodeCore`): output parameters and `use_camera_wb` MUST be set before `libraw_open_*` (identify() adopts the camera
  matrix only then; ORF/PEF/Leaf). Tests pin `["configured"]` for a missing file.
- T4 (memory order, INV-1-adjacent perf rule): the session is dropped BEFORE any BGRA allocation, the processed image before the hand-off. Stages
  `handle-closed` and `source-released` prove it; do not "simplify" by holding both.
- T5 (buffer pin): `open_buffer` keeps the `SourceBytes` alive inside the session until after `libraw_close`; never pass a pointer into a temporary.
- T6 (FFI, ADR / AGENTS.md): NO `unsafe` in `decoder.rs`. The progress callback, its pointer and every FFI call are W5-15a's (`native.rs`);
  the adapter here only forwards safe methods. A porter who needs `unsafe` here has the seam wrong: stop and report.
- T7 (§7.7 Windows paths): lengths in UTF-16 units; `\\?\` / `\\.\` checks are ordinal; `GetFullPath` = W2-00 `get_full_path` (do not use
  `std::path::absolute` directly). DIVERGENCE: a path that is not valid Unicode (lone surrogate, `OsStr::to_str` = None) is opened once, never retried
  (C# can retry it); record a `// DIVERGENCE:` comment and a `Different` note in the PARITY report.
- T8 (§7.8 None vs empty): `decoder_name() == None` is "unknown decoder" (Bayer), `structure() == None` is "unreadable" (conservative Linear for DNG names).
- T9 (process-wide gate): tests that read `full_decode_slots_available()` share ONE static gate per test binary; serialize them with a
  `static GLOBAL_GATE: Mutex<()>` in `tests/support` (C# `[Collection(LibRawNativeDecodeGate.Name)]`); every other test uses `with_gate(private)`.
- T10 (no sleep polling, AGENTS.md): "waiter queued" is observed through `FullDecodeGate::with_waiter_queued` + `std::sync::mpsc`, holder release through
  a `Barrier`/channel inside the stage observer; bound every wait with `recv_timeout(60 s)` (hang guard).
- T11 (parsers never panic): `find_end_of_image` and `to_extended_length_path` get a Rust-only property test (all streams of length 0..=6 over the
  alphabet `{00, 12, D8, D9, DA, FF}`, plus 2 000 xorshift mutants of the minimal JPEG): no panic, result `<= len`.
- INV ids: INV-12 (error kinds above), INV-8 (LibRaw opens the file itself through `libraw_open_wfile`: this is the documented exception to the
  `SourceReader` choke point, exactly as C#; do NOT route it through `SourceReader`), INV-1 (no cache key here; `actual_backend = LibRaw` feeds the key).

## Resolved design decisions
1. **Seam ownership (D51).** The seam traits stay here and THIS unit owns the
   `NativeLibRaw` adapter (W5-15a contract "Downstream"); `ProcessedImageHeader` and `IMAGE_*` are W5-15a's (re-exported); the progress
   callback / `CheckCancellation` port is W5-15a's alone (`set_cancel_token(CancelToken)`), so this unit has no `CancellationState` and no
   `unsafe`. Alternative (W5-15a Open question 4): this unit owns the callback and `set_cancel_token` takes a state pointer: rejected,
   it adds a second `unsafe` site outside `native.rs`.
2. **Memory source.** C# defaults to `ReadGcMemoryInfo`; Rust `new` requires the injected `MemoryInfoSource`, and the Windows composition root supplies its probe, matching the WicDirectDecoder precedent (W4-11c).
3. **Split.** The shared implementation was completed as one W5-16c unit; no W5-16c1/W5-16c2 split is needed.
4. **Private-bytes leak tests** (`*_DoesNotContinuouslyGrowPrivateBytes`): resolved with a test-only `pr-platform-win::test_support::process_private_bytes()` helper using `GetProcessMemoryInfo` (`PrivateUsage`), enabled as a `pr-libraw` dev-dependency feature. The ORF extraction and 200-decode cases, plus the portrait rewritten-corpus case, are implemented in `tests/decoder_native.rs`; all require the pinned LibRaw DLL and RAW corpus for execution.
5. **White-balance test preview decode (resolved):** use W5-14 TurboJPEG via the `pr-turbojpeg` dev-dependency. This decodes the embedded thumbnail and compares its channel ratios against direct daylight/camera-WB LibRaw output; no WPF/WIC parity claim is made for this Rust test.
6. **Global gate in tests:** `with_gate` remains a Rust-only seam (C# has only the static); production always uses the static gate.
