- Semantics notes:
  1. **One error enum.** C# throws; Rust returns `Result<_, DecodeError>`. WAVE-4-PLAN lists "exceptions become one error
     enum" on the W4-01b row too: THIS unit owns the enum (it is the type the traits return); W4-01b must `use` it and
     must not define a second one (see Open questions 1).
  2. **Variant per whitelist element.** `FallbackImageDecoder.IsFallbackable` (W4-12b) is: not fallbackable = FileNotFound,
     DirectoryNotFound, Canceled, OutOfMemory, MemoryAdmission, Busy; fallbackable = NotSupported (+MissingCodec, a
     NotSupportedException subtype, BUT see trap 3), InvalidCast, Overflow, Format, InvalidData, Com, DllNotFound,
     BadImageFormat, EntryPointNotFound; everything else (InvalidOperation, Io, Other, InvalidArgument, Disposed) is not
     fallbackable. The enum has exactly one variant per C# type that line names, so W4-12b is a `match`.
  3. **MissingCodec.** In C# it IS-A `NotSupportedException`, so `IsFallbackable` returns true for it (fallback to WPF, which
     then fails the same way); `WebpHeicRoutingDecoder` sits in front of the fallback so it never reaches it. Rust keeps
     the variant separate and gives `is_not_supported()` = true for it, so W4-12b can reproduce the C# answer with
     `error.is_not_supported() || matches!(...)`. Callers that special-case it (`PreloadScheduler` skips without a log
     line, C# `catch (MissingImageCodecException)` before `NotSupportedException`) match `MissingCodec` first.
  4. **MemoryAdmission is an IOException** (C# base class, chosen so "cannot show this image" handlers keep working):
     `is_io_exception()` is true. `From<io::Error>` NEVER produces `MemoryAdmission` (only decoders do).
  5. **`Display` = `Exception.Message`.** Default messages are the three constants. `Canceled` message is .NET's
     "The operation was canceled." `Io` shows the inner error text. Messages are logged (`FallbackImageDecoder` warns with
     `ex.Message`) and compared by tests, so keep them exact.
  6. **No inner exception field.** C# ctors take an optional inner exception; nothing reads `InnerException` of these three
     types (checked: `IsFallbackable`, `DecodeFailureSourceBytes` key on the exception OBJECT, which W4-01b models
     separately). Rust folds the cause into the message text at the throw site (`busy_with(format!("{why}: {inner}"))`).
  7. **Cancellation.** `CancellationToken` -> `pr_core::sync::CancelToken` (AGENTS: no tokio). `as_cancellable()` replaces
     `decoder is ICancellableImageDecoder` (the only C# use: `PreviewImageService` line 845 picks the token overload). A
     decorator that wraps a cancellable decoder and does NOT forward `as_cancellable` silently turns cancellation off:
     W4-12 wrappers must forward it (INV-1 relevant).
  8. **Ownership.** `IDecodedImage` is shared by RAM cache, presenter and preload, so decode returns
     `Arc<dyn DecodedImage>`; the factory returns `Arc<dyn ImageDecoder>` (C# builds each backend once with a `Lazy`).
     `image_from_pixels` takes `PixelBuffer` BY VALUE (C# "NHẬN quyền sở hữu"): drop = Dispose. The method is not named
     `from_pixels` only because clippy `wrong_self_convention` rejects `from_*(&self)`.
  9. **Thread-safety.** All four traits are `Send + Sync` (C# docs: decoders are stateless/shareable, the codec is
     thread-safe).
  10. **Paths.** `read_info(&self, path: &str)`: D1 (paths in records are `String`; the boundary converts with `Path::new`).

## Open questions
1. **Who owns the error enum, 01b or 01c?** The plan row for W4-01b says "exceptions become one error enum" and the
   row for W4-01c says "traits only". This draft puts `DecodeError` in `decoder_traits.rs` because the traits return it and
   W4-01b's `PixelLease`/`DecodedImage` do not need it. Alternative: move it to `decode_types.rs` (01b) and
   `pub use` it here. Recommended: keep it here; if the 01b draft also defines it, the lead deletes the 01b copy at wiring.
   Impact: only the `use` line in one of the two files.
2. **`PixelLease` borrow representation.** C# `PixelLease(PixelBuffer, owned: false)` borrows a buffer that lives inside
   the platform image. In Rust the borrowing case needs either `Arc<PixelBuffer>` inside the lease or a lifetime tied to
   `&PlatformImage`. `to_pixels(&self, &PlatformImage) -> Result<PixelLease, _>` is written for the `Arc` form (no lifetime
   on `PixelLease`). That is W4-01b/W4-16a's call; if they choose a lifetime, change the signature to
   `PixelLease<'a>`. Recommended: `Arc<PixelBuffer>` (the cache already holds `Arc<dyn Any>`).
3. **`PlatformImage` type.** `Arc<dyn Any + Send + Sync>` mirrors C# `object`. It is defined in this file; W4-01b's
   `DecodedImage::platform_image()` should return it via `crate::decoder_traits::PlatformImage`. Alternative: an enum
   `{ Pixels(Arc<PixelBuffer>), Wpf(..) }`: not possible without WPF types, and the WPF codec has no Rust twin
   (WAVE-4-PLAN scope). Recommended: keep `dyn Any`; `PixelBufferImageCodec` (W4-16b) downcasts.
4. **`ImageDecoderFactory::create` is infallible.** C# `Create` can throw only when a provider delegate throws (a composition
   error). Rust returns `Arc<dyn ImageDecoder>`; a failing provider must surface as a decoder whose calls return `Err`, or
   W4-12a changes the trait to `Result`. Recommended: keep infallible and have W4-12a build an `ErrorDecoder`
   (INV-12: the app must keep running).
