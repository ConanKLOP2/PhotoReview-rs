## Semantics (C# is the spec; the doc comment of every stub function is part of it)
1. **Frame layout is a pure plan (D-W8B5-911).** `layout_plan` is the C# `LayoutControls` against a `DialogMeasure`; the formulas are in its doc comment and are exact. Worked example the Rust test must reproduce by hand (a fake with `dx(n) = 2n`, `dy(n) = 2n`, `line_height = 16`, every text width `0`, every measured height `0`, empty version text; these are `avg = 8`, `line = 16` of the native formulas `(n*avg+2)/4`, `(n*line+4)/8`): margin 20, button height 28, every button width 100, `row_width(LEFT) = 436`, `row_width(RIGHT) = 324`, preferred `(1080, 660)`, minimum `(720, 460)`. Client 900 x 600 (one row, because `436 + 32 + 324 <= 860`): right row `Cancel(556,552,100,28)`, `Apply(668,552,100,28)`, `Save(780,552,100,28)`; left row `Defaults(20,552)`, `Reset(132,552)`, `Export(244,552)`, `Import(356,552)` (100 x 28); `content_bottom = 536`; `nav_width = 225`; header `(20,20,225,0)`; navigation `(20,32,225,504)`; `nav_item_height = 28`; version `(20,536,225,0)`; title `(265,20,615,0)`; `viewport_width = 587`, `viewport_height = 504`; every page container `(265,32,587,504)`; scroll bar `(860,32,20,504)`. Client 700 x 500 (two rows): right row at `top = 452`, `x = 356`; left row `top = 416`, `x = 20`; `content_bottom = 400`; `nav_width = 180`; navigation `(20,32,180,368)`; title `(220,20,460,0)`; `viewport_width = 432`, `viewport_height = 368`; scroll bar `(660,32,20,368)`.
2. **`layout_controls`** = `layout_plan(dialog, w, h, page_count)`; every placement through `dialog.place(id, x, y, width, height)` (the native base clamps negatives to `0`); `dialog.set_list_item_height(NAV_ID, plan.nav_item_height)` right after the placement of `NAV_ID`; `viewport_width/height` stored; `active >= 0` -> `layout_page(active)`. `preferred_size` / `minimum_size` call the pure functions with the dialog as `DialogMeasure` (`NativeDialog` implements it, D-W8B5-501).
3. **`layout_page(index)`**: the two-pass loop of the stub doc. Trap: the builder is borrowed (shared) during the loop, so nothing inside may call a page or `set_control_visible` (the elements only read the surface); the `view.pages` cell is read and written in short borrows around the loop, never inside it. After the passes `update_scroll_bar(index)`. Two passes at most, as the C# `for (pass < 2)`: an offset still above `max` after the second pass is clamped to `max` and the loop ends (no third pass).
4. **Scroll arithmetic** (all pure, `i32` saturating, no panic): `clamp_scroll(v, c, h) = max(0, min(v, max(0, c - h)))`; `bar_line(l) = max(1, l * 2)`; `bar_target`: line up/down `current -/+ line`, page up/down `current -/+ max(line, viewport_height - line)`, `SB_TOP` `0`, `SB_BOTTOM` `i32::MAX` (then clamped), thumb track/position `track_pos`, any other code `current`; `wheel_target(current, delta, l) = current - round_ties_even(delta / 120.0 * 3.0 * l) as i32` (C# `Math.Round` is banker's rounding and the `(int)` cast saturates: T4); `scroll_bar_info`: `None` when `content_height <= viewport_height`, else `{ min: 0, max: content_height - 1, page: max(1, viewport_height) as u32, pos: scroll }`; `ensure_visible_target`: `top < 0` -> `scroll + top - dy4`, else `bottom > viewport_height` -> `scroll + (bottom - viewport_height) + dy4`, else `None`.
5. **`set_scroll(value)`**: `active < 0` -> nothing; `clamped = clamp_scroll(value, content_height[active], viewport_height)`; equal to the stored offset -> nothing; else store and `layout_page(active)` (which clamps again after the layout, because the content height may have changed). `scroll_by_bar(code)` reads `nTrackPos` through `get_scroll_info(item(SCROLL_ID), SB_CTL, SIF_POS | SIF_TRACKPOS)` (a failed read leaves `0`); `scroll_by_wheel(delta)` uses `scroll[max(0, active)]` as the current value (page 0 when none is showing; `set_scroll` then does nothing).
6. **`update_scroll_bar`**: `scroll_bar_info(..)`: `None` -> `show_window(bar, SW_HIDE)`; `Some(info)` -> `show_window(bar, SW_SHOWNA)` and `set_scroll_info(bar, SB_CTL, &SCROLLINFO { cbSize = size_of, fMask = SIF_RANGE | SIF_PAGE | SIF_POS, nMin, nMax, nPage, nPos }, true)`.
7. **`ensure_visible(id)`**: the control's screen rectangle is mapped into the page container with `screen_to_client(item(viewport_id(active)), &mut top_left)`; the height is `rect.bottom - rect.top`. Only for a control of the SHOWING page (`page_of(id) == active`).
8. **`handle_scroll(id, code)`**: `SCROLL_ID` -> `scroll_by_bar(code)` (the code is `LOWORD(wparam)` of `WM_VSCROLL`, delivered by the native base as `code`); else the page that owns `id` gets `on_scroll(id)` (a borrowed page is skipped; out of range ignored).
9. **`PageSurface`**: `place` and `hide` as in the stub docs. Borrow rule: `placement_change` is decided under a short `placed` borrow, the borrow is released, `set_window_pos` runs, THEN `placed` is written (the OS call can send messages to the control that re-enter the dialog procedure). `Hide` of a control that was never placed hides it when its window style still has `WS_VISIBLE` (controls are created `WS_VISIBLE` at 0,0). `combo_drop_height` sends `CB_GETITEMHEIGHT` (0x0154) with `wparam = 0`, `lparam = 0` (integer-only message: safe).
10. **`static_text_color(id)`**: `Muted` -> `DialogColors::from_key("Dark.TextMuted")` (fall back to `DialogColors::text_secondary()` if the key is missing), `Warning` -> `DialogColors::warning()`, `Normal` -> `DialogColors::text()`. A note wins over a warning (conditional order of the C#).
11. **`on_closed`**: the seven steps of the stub doc, in order (step 5 also clears `placed` and `page_combos`: their handles die with the window). It runs in the dialog's `cleanup` (right before the window is destroyed) and also after a captured panic; it must not panic and must not use the page borrows blockingly (`try_borrow_mut`). After step 7 the content no longer references the dialog; the dialog is dropped by its owner, and the test `closing_releases_the_content` (19j) proves the cycle is gone.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T3 (arithmetic): every pure function uses `saturating_*`/`wrapping_*` as the C# unchecked `int` would not overflow in practice; `i32::MAX` targets are clamped, not added to; `max(..).min(..)` instead of `i32::clamp` (min > max must not panic, D-W8B5-703).
- T4 (rounding): `Math.Round(x)` is round-half-to-even: `f64::round_ties_even`, never `f64::round`; the `(int)` cast of a huge value saturates in Rust and is unspecified in C# (not reachable: `delta` is a 16-bit wheel value).
- T10 (order): the placement order of `layout_plan` is the C# call order (the plan is a `Vec`); `SetListItemHeight` follows the navigation list placement.
- Re-entrancy (D-W8B4I-1): `set_window_pos`, `set_scroll_info`, `show_window` and `invalidate_rect` all send messages; no `RefCell` (`placed`, `view.pages`, a builder) is held across them except the shared builder borrow of `layout_page`, which no message handler of a page control touches (they go through `on_command`, which does not need the builder).
- Native `Place` clamps negative sizes: a plan keeps the computed numbers; the golden `viewport_*` are computed BEFORE clamping, as the C#.
- Layout loops run on every resize, scroll, language and DPI change: no allocation per control beyond the `placed` map entry (D-W8B5-911 keeps the one-`SetWindowPos`-per-control cache).
- R0003: no `unwrap`/`expect`/indexing on the UI thread (`get(index)`), no `panic!`.

## Safety rules (`// SAFETY:` per `unsafe` block)
`send_message(combo, CB_GETITEMHEIGHT, 0, 0)`: "integer-only message to a handle the OS validates". `set_scroll_info` / `get_scroll_info`: safe wrappers of 11e (a `SCROLLINFO` with `cbSize` set, read/written during the call). `delete_object(brush)`: "a GDI brush this content created and has not deleted". Nothing else in this slice is `unsafe`.

## Error mapping
| C# | Rust |
|---|---|
| `Math.Clamp(min > max)` throws | `max` then `min`, never panics |
| `_scroll[index]` out of range | `get(index)`; nothing happens |
| `User32.GetScrollInfo` fails | `nTrackPos` stays `0` |
| `SetWindowPos` failure | ignored (the control keeps its old rectangle; the cache is updated only on a successful call: the wrapper returns `Result`, `Err` leaves `placed` unchanged) |
| exception in `OnClosed` | unrepresentable (must not panic); a panic is captured by the base (`pending_panic`) |
