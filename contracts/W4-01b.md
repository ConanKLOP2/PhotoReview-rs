- Semantics notes:
  1. **`DecodeBox::fit` exactness.** Copy the C# branch structure literally. `widthExceeds = Width > 0 && sw > Width`, `heightExceeds`
     likewise; neither exceeds, or `sw <= 0 || sh <= 0`, or unbounded => return the source unchanged (so `(0, 10)` stays `(0, 10)`).
     Otherwise `widthConstrains = Height <= 0 || (Width > 0 && Width*sh <= Height*sw)` with both products in `i64`; when it holds the
     result is `(Width, max(1, sh*Width/sw))`, else `(max(1, sw*Height/sh), Height)`; the division is integer FLOOR in `i64`
     (positive operands, so `/` is floor). The constraining side is the box side exactly, never the floor. Equal ratios (tie) pick the
     WIDTH branch (`<=`). Converting the `i64` result back to `i32`: the C# cast is unchecked, but the value is always `<= source`
     here (the width branch is only reached with `Width < sw`, the height branch with `Height < sh`), so use `i32::try_from(v).unwrap_or(i32::MAX)`; never `as`.
  2. **`fit_stored`.** `!transposed` => `fit(rw, rh)`. `transposed` => `(dw, dh) = fit(rh, rw)` and return `(dh, dw)`. It does NOT look
     at the orientation number: the caller computes `transposed` (W4-02a `is_transposed`).
  3. **`DecodeRequest`.** Plain data. C# defaults: `ApplyOrientation = true`, `Bytes = null`, `TargetHeight = 0`,
     `Priority = Viewer`, `SourceOrientation = null`. `with_box` copies `box.width/height` verbatim into `target_width/target_height`
     (negative values are kept, not clamped); `decode_box()` rebuilds a box from them; `is_downscale_requested` is
     `target_width > 0 || target_height > 0` (so `-3 x 5` is true, `-1 x 0` false). `bytes` is `Option<Arc<[u8]>>` (C#
     `ReadOnlyMemory<byte>?`); an empty buffer is `Some` (C# `HasValue` is true), distinct from `None`.
  4. **`ImageInfo`.** No validation; `width()`/`height()` swap iff `5 <= orientation <= 8` (orientation 0, 9, -1, 255 do NOT swap).
     Inline the range test (`matches!(o, 5..=8)`) or call W4-02a `orientation::is_transposed` if it is merged by then; both are the same.
  5. **`DecodedImage::new` guards, in this order:** `pixel_width < 1` -> `PixelWidthTooSmall`; `pixel_height < 1` ->
     `PixelHeightTooSmall`; `estimated_bytes < 0` -> `NegativeEstimatedBytes`; then, ONLY when the platform image is
     `PlatformImage::Pixels(buf)` and `(buf.width, buf.height) != (pixel_width, pixel_height)` -> `PixelBufferSizeMismatch`. An opaque
     platform image is never size-checked. `estimated_bytes` is NOT compared with the buffer's byte count (golden
     `buffer-ignores-estimate-mismatch`). `original_width/height <= 0` become the pixel size (each axis independently: `0 x 900` keeps
     900 for height only). `orientation` is stored as given (no `Normalize`). Default `actual_backend` is **`WicDirect`** here, while
     the trait default (an image that does not override it) is **`Wpf`**: both must be kept (golden `interface-defaults`).
  6. **`has_known_original`** = `!downscaled || ow > pw || oh > ph`: a downscaled image whose "original" equals or is below the pixel
     size is NOT known (the decoder could not learn it; storing it would poison the cache with the small size). C# class is `internal`;
     keep the function `pub(crate)` or `pub` (W4-14 and W4-08b call it); the stub makes it `pub`.
  7. **`PixelLease`.** `Drop` of the `Owned` variant frees via `PixelBuffer`'s own `Drop` (W4-16a), so no explicit `Dispose`. The
     `Borrowed` variant holds a reference with lifetime `'a`; the C# interface returned borrows from the platform image, which maps to a
     borrow of `&PixelBuffer` inside `PlatformImage::Pixels(Arc<..>)`. If W4-14 cannot live with the lifetime, change `Borrowed` to hold
     `Arc<PixelBuffer>` (open question 3).
  8. **`DecodeFailureSourceBytes`.** Carried as a field instead of `Exception.Data`. `attach` overwrites; `try_get` is `Some` for an
     attached empty buffer; a fresh value is `None`. The key string `PhotoReview.Imaging.SourceBytes` is not persisted anywhere, so it
     has no Rust twin.
  9. **Optional interfaces.** `ISourceReadMetrics`/`IRawPreviewInfo` are `is`-tested in C#; in Rust they are provided trait methods
     (`source_bytes_read`, `embedded_preview_size`) returning `None`. `IRawPreviewInfo` values `0, 0` mean "not a preview": the
     implementer of a RAW image returns `None` in that case instead of `Some((0, 0))`.

## Open questions
1. **Where does the decode error enum live?** The plan row says "exceptions become one error enum". The exceptions that need a variant
   (`DecoderBusyException`, `DecoderMemoryAdmissionException`, `MissingImageCodecException`, plus the generic decode failures that
   `FallbackImageDecoder.IsFallbackable` classifies) are W4-01c's. This unit only offers `DecodeFailureSourceBytes` as an embeddable
   field and `DecodedImageError` for its own constructor. Recommended: W4-01c's `DecodeError` embeds `DecodeFailureSourceBytes` in the
   variants a primary decoder may fail with.
2. **`ExifSummary` ownership.** `Option<ExifSummary>` by value forces a clone when a preview cache reads the same summary into two
   images. If W4-04a makes `ExifSummary` large, switch to `Option<Arc<ExifSummary>>` (the trait method still returns `Option<&ExifSummary>`).
3. **`PixelLease` lifetime vs `Arc`.** `IPlatformImageCodec.ToPixels(object)` becomes `to_pixels(&PlatformImage) -> PixelLease<'_>` in
   W4-01c; if a caller must keep a lease across an `await`/thread hop, `Borrowed(Arc<PixelBuffer>)` is simpler. Decide with W4-01c.
4. **`DecodedImage` is not `Clone`.** The C# class is a reference type shared by the RAM cache, the presenter and the persist worker.
   Rust callers share it as `Arc<dyn DecodedImageView>`; nothing in this unit needs `Clone`.
5. **`path: PathBuf`.** C# `Path` is a `string` that doubles as a label when `Bytes` is given (e.g. `"icc-and-exif.jpg"`); `PathBuf`
   holds that fine. If W4-14 prefers `Arc<Path>` for cheap request cloning on the preload path, change the field type only.
