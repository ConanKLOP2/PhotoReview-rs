## Semantics notes (C# is the spec)
1. **`BitmapDevice` is a seam, not a new concept.** It is exactly the part of C# `DeviceResources` the backend touches (`MaxBitmapSize`, `Generation`, `CreateBitmap`, `ReleaseBitmap`, plus the surface's `DeviceRecreated`). W8-12c implements it (or the porter replaces the
   type parameter by `DeviceResources` if 12c's API is concrete enough). Assumption on 12c (open question 1): `DeviceResources` is shared as `Rc<DeviceResources>` between the surface and this backend, exposes `max_bitmap_size()`, `generation()`, a bitmap leak counter
   (`LiveBitmapCount`), and a way to subscribe to device recreation. `create_bitmap` is `gfx::d2d::create_bitmap_uninitialized(&context, w, h, alpha, D2D1_BITMAP_OPTIONS_NONE)` + counter increment; `release_bitmap` drops the bitmap + counter decrement.
2. **`upload(pixels, with_data)`**: `pixels.bytes()` (disposed buffer: `Err(GfxError { operation: "PixelBuffer::bytes", hresult: E_INVALIDARG })`, never a panic); `limit = effective_tile_limit(device.max_bitmap_size(), self.max_tile_size)`;
   `specs = compute_tiles(width, height, limit, self.gutter)` (an `Err(TileLayoutError)` becomes `Err(GfxError { "compute_tiles", E_INVALIDARG })`; C# let `ArgumentOutOfRangeException` escape); `alpha = alpha_mode_for(pixels.layout())`; per tile
   `bitmap = device.create_bitmap(texture.width, texture.height, alpha)?`; when `with_data`: `gfx::d2d::copy_from_memory(&bitmap, None, &bytes[tile_byte_offset(stride, texture.x, texture.y) as usize..], stride as u32)`. On the first error release every bitmap created so far through
   `device.release_bitmap` (the leak counter must return to its baseline) and return the error. The generation is read AFTER the tiles exist (`device.generation()`), like C#. The returned image has `uploaded_rows == 0`.
3. **`with_data == false`** creates bitmaps with UNDEFINED contents (`create_bitmap_uninitialized`); only the stripes of `upload_rows` fill them. An incomplete image is never drawn (`TiledGpuImage::is_drawable` needs `is_complete`), so undefined texels are never visible.
4. **`upload_rows(image, pixels, start_row, end_row)`**: for each tile `stripe_copy(texture.y, texture.width, texture.height, start_row, end_row)`; `None` or a tile without bitmap (`has_bitmap == false`, an image already released) is skipped; otherwise
   `copy_from_memory(bitmap, Some(D2D_RECT_U { left: 0, top: dest_top, right: dest_right, bottom: dest_bottom }), &bytes[tile_byte_offset(stride, texture.x, source_top)..], stride as u32)`. Neighbouring tiles overlap by the gutter, so a stripe that lies
   in the overlap is written into BOTH tiles (that is what makes seams exact).
5. **`release(image)`**: for every tile `if let Some(b) = tile.take_bitmap() { device.release_bitmap(b) }`. A tile without bitmap is skipped; a second `release` of the same image releases nothing (the cache also guards with `is_released`). Valid after a device recreation: the bitmap
   belongs to the OLD device generation, its COM reference is simply dropped and the leak counter decremented (C# comment on `ReleaseBitmap`).
6. **`effective_tile_limit(device_max, override)`** = `min(min(device_max, 16384), override.unwrap_or(i32::MAX))`. `alpha_mode_for`: `Bgr32 -> D2D1_ALPHA_MODE_IGNORE`, `Pbgra32 -> D2D1_ALPHA_MODE_PREMULTIPLIED`. `tile_byte_offset(stride, x, y)` = `y as i64 * stride as i64 + x as i64 * 4`.
7. **`stripe_copy`**: `top = max(start_row, texture_y)`, `bottom = min(end_row, texture_y + texture_height)`; `None` if `bottom <= top`; `Some { source_top: top, dest_top: (top - texture_y) as u32, dest_bottom: (bottom - texture_y) as u32, dest_right: texture_width as u32 }`. All arithmetic in `i32`
   is safe here (rows <= `i32::MAX`); the casts to `u32` are of non-negative values.
8. **Device recreation**: the backend only forwards the subscription. The cache clears itself in its handler (12f); nothing in this unit calls `Recreate`. The surface (12d) bumps `generation()`, so a stale image that somehow survives is not drawable (`is_drawable(current_generation)`).
9. **The `pr_app` glue (after the layering PR)**: `D2dGpuImageCache` forwards the six `GpuImageCache` trait methods to the policy cache, coerces `Rc<TiledGpuImage<ID2D1Bitmap1>>` to `Rc<dyn GpuImage>`, and maps `CacheError` to `RenderError` (12f "Error mapping"). The constructor reads the
   surface PIXEL size for `default_budget_bytes` (not the DIP size). `PresentationComposer` (W8-16c) needs `is_fully_uploaded` and the `UploadCompleted` event, which are NOT in the 12a trait: see D-W8B3S-5 and open question 2.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (bitmap leak on failure): a failure at tile k must release tiles 0..k-1 through `release_bitmap` (the counter), not only drop them; the C# `LiveBitmapCount` test would show the leak.
- T2 (WARP limit): clamp EVERY device to 16384 (`D3D11_MAX_TEXTURE_DIMENSION`); `max_bitmap_size()` of WARP is 8 388 608 and would produce one giant tile that real GPUs cannot create.
- T3 (`i32` offset overflow): a tall image (20000 x 30000 -> stride 80 000, row 30 000) has a byte offset of 2 400 000 000; compute in `i64`, then index the slice (`as usize` after the range check).
- T4 (pitch and slice length): `copy_from_memory` checks `pitch * (h - 1) + w * 4 <= slice.len()` (11h); the slice MUST start at the tile origin and run to the end of the buffer, not be cut to the tile's own size, or the check fails for the right-hand tiles whose rows continue past the tile.
- T5 (alpha): `Bgr32` uses `IGNORE`, never `PREMULTIPLIED` (the fourth byte is `X`, 0 in decoders; premultiplied would draw the image transparent). `Pbgra32` is already premultiplied: no conversion.
- T6 (uninitialised bitmaps): with `with_data == false` do not copy anything and do not read the bitmap; a debug assertion that a draw call never uses an incomplete image belongs to 12e.
- T7 (generation timing): read `device.generation()` when constructing the image (after tile creation), not at the top of `upload`.
- T8 (old-generation release): `release_bitmap` must work for bitmaps created before the last `Recreate`; do not route it through the new device context.
- T9 (`!Send`): `ID2D1Bitmap1` is `Send` in windows 0.62.2 but the Direct2D factory is single-threaded (D-W8B3G-9 d); the backend and the cache hold `Rc` and are `!Send` by construction. No thread other than the UI thread may call `upload*`.
- T10 (disposed buffer): `pixels.bytes()` after `dispose()` is an `Err`; map it, never `unwrap`.

## Safety rules (every `unsafe` block gets a `// SAFETY:` comment; the lint `undocumented_unsafe_blocks` is on)
- Target: ZERO `unsafe` in this file. The only raw-pointer operation of the C# class (`CopyFromMemory` from `byte*`) is hidden behind the safe, length-checked `gfx::d2d::copy_from_memory` (11h), and the source is a `&[u8]` slice of `PixelBuffer::bytes()`. If the porter finds a reason for `unsafe`, it needs a SAFETY comment naming
  (a) the slice length versus `pitch * (rows - 1) + width * 4`, (b) that the bitmap is a live owned value, (c) the UI thread.
- Thread affinity: UI thread only. The backend never spawns, locks or reads the environment.
- No `ManuallyDrop`, no `mem::forget`, no `from_raw`.

## Error mapping
- Every `ID2D1Bitmap1` creation and copy failure is a `GfxError { hresult, operation }` (`"CreateBitmap"`, `"CopyFromMemory"`), converted by the cache into `CacheError::Backend` and by the 12g adapter into `RenderError::Device { hresult, operation }` (field for field).
- Device loss (`D2DERR_RECREATE_TARGET` from `CopyFromMemory`/`CreateBitmap`): returned as `Err`; `GfxError::is_device_lost()` tells the frame code to recreate the device. This unit does NOT recreate it (12d/12e do).
- Invalid tile layout and a disposed buffer: `GfxError` with `E_INVALIDARG` (0x80070057) and the named operation (T10).
