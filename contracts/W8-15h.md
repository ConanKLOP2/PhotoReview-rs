## Semantics and the Rust shape (C# is the spec)
1. **Who owns the elements.** The `OverlayHost` owns them once (D-W8B4O-4): roots `InfoOverlayHost` (a `LayerElement`: children `StatusPanel`, `FolderInfoPanel`, `ZoomIndicatorPanel`, `CapturePairBadge` in that order) then `ToolbarPanel` (the toolbar's `is_visible` is set `true` explicitly, as C#). C# `Toolbar`/`Status`/... are the closure accessors `with_toolbar(|t| ..)`; mutation inside the module uses `host.root_mut::<ToolbarPanel>(toolbar::PANEL_ID)` and `layer.child_mut::<StatusPanel>(0)` (amendment A1), `OverlayButton` replaces the `ButtonElement` references `_hot`/`_pressed`.
2. **No borrow across a callback (D-W8B4O-7).** The state sits in one `RefCell`. Every method follows: read settings and flags (call `(self.settings)()`, `(self.is_window_active)()` BEFORE borrowing), mutate under a short `borrow_mut`, collect the effects (`request_render`, `clock.request_frame`, tooltip or command calls, `on_*_failed`) in a small local struct, release the borrow, then run the effects. `request_render` is `window.invalidate()` in production (never re-enters synchronously) but tests may count it; the rule keeps `menus.show` and `commands` (15i) safe too.
3. **Single frame subscription (D-W8B4O-8).** `pr_app`'s `Animator` and `FrameDelayTimer` do not subscribe to a clock (W8-15b): the host does. `sync_frame_subscription()` keeps ONE subscription alive exactly while `animator.is_animating() || toolbar_timer.is_running() || info_timer.is_running()` (C# `SubscriberCount > 0` iff one of them listens). The handler captures a `Weak<ShellOverlay>`, converts the host `FrameTick` to the `pr_app` one (same fields) and calls `on_frame`. **Order inside one frame is fixed: animator, toolbar timer, info timer**; the C# tests need it: a fade started by a timer in frame N must get its start timestamp in frame N+1 (`Toolbar_HidesExactlyAfterTheConfiguredDelay...`: at the first frame after the hide the opacity must still be 1, `+/- 0.001`). Subscribe/unsubscribe happen from inside the handler (the host clock allows it).
4. **Time.** `timestamp` defaults to `host::frame_clock::qpc_now`, `ticks_per_second` and `animator_ticks_per_second` to `qpc_frequency()`; a delay in milliseconds becomes `.NET` ticks (`ms * 10_000`) for `FrameDelayTimer::start(now, delay_ticks)` and `Animator::fade_to(.., duration_ticks, ..)` (their contract, W8-15b). `ticks_per_second <= 0` is a programming error (panic with the `AnimatorError`/`FrameDelayError` text).
5. **Fade target type.** `Fade(element, gate, visible, visibleOpacity: f32)`: the toolbar's visible opacity is `ToolbarAutoHidePolicy::target_opacity(percent) as f32`; the gate gets `f64::from(target_f32)` (C# widened the `float`), never the original `f64`. Info layer: `1.0` / `0.0`.
6. **`update` and flags** follow the C# order literally; `apply_model` calls `Status::apply`, `FolderInfoPanel::apply`, `ZoomIndicatorPanel::apply`, `CapturePairBadge::apply` (15d/15e) with the model, always, before the visibility rules.
7. **`arrange`** (layout.rs): `last_client = client`, `last_dpi = if dpi <= 0 { 1 } else { dpi }`, `OverlayLayoutContext::with_renderer_id(client, last_dpi, &*text, text_renderer_id)`, `host.arrange(&context)`. Layout ignores the DPI; the DPI is for drawing and tooltips only. A test pins that the toolbar box is identical at 1.0 and 1.5 (C# `ToolbarKeepsItsBox_WhenOnlyTheDpiChanges`).
8. **Hit testing** (hit_test.rs, z order): the toolbar root is on top, so a point where toolbar and info panels overlap hits the toolbar. `host.hit_test` returns the deepest element; `hit_button` is `Some` only for the five buttons. `hit_test(point)` is false after dispose. Faded-out roots do not answer because `is_hit_test_visible` was set false at the start of the fade (item 9 of the traps) and opacity 0 makes `find_at` return `None`.
9. **Dispose.** `animator.dispose()`, both timers `dispose()`, `unsubscribe` the frame handler, `tooltips.dispose()` (the shared control: the 15j owner must not dispose it twice; it is idempotent), `host.dispose()` (releases text layouts: the fake renderer's live count must reach 0). After it every entry point is a no-op and `hit_test`/`pointer_down` answer false. `Drop` calls `dispose`.

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (re-entrancy, MULTI-AGENT-PLAN 7): see item 2. A test sets `request_render` to a closure that calls back `overlay.hit_test(..)`; no `BorrowMutError`.
- T2 (fade animation): `FadeTargetGate` suppresses re-starts; `fade_to` with the same target keeps the running tween; hit-test visibility flips at once; `Animator::on_frame` writes opacity only on change. The 150 ms in / 200 ms out durations and `Easing::Linear` are constants with tests (the `Advance(1 + 150)` idiom: first frame sets the tween start).
- T3 (hit testing with DPI): this unit is DIP only; `arrange` DPI is stored not used; `effective_dpi(0) == 1`, `effective_dpi(-2) == 1`, `NaN` stays NaN.
- T4 (hot zone): the closed box inflated by 24 on every side, evaluated from the toolbar's current `Bounds` (C# `Toolbar.Bounds`), `left + width + margin` order (policy test W8-06b pins it); the flag starts `true`.
- T5 (z order of overlay vs image): the host draws `InfoOverlayHost` then `ToolbarPanel`; both are drawn by 15i AFTER the image in the same frame. Nothing in 15h draws.
- T6 (settings are live): `(self.settings)()` is called at every evaluation; a test mutates the settings object between calls and calls `settings_changed()`.
- T7 (timer restart rule): the toolbar timer starts only on the kept -> not-kept transition; `FrameDelayTimer::start` while running replaces the deadline (used by `note_info_activity` after `stop`, so it never does).
- T8 (`-0`/NaN): none of the conversions here are rounding-sensitive except `tool` DPI in 15g.
- T9 (identity of buttons): `OverlayButton` ids are the element ids; `from_element_id` of any other id is `None` (a `TextElement` hit is not a button).
- T10 (no `async`): the C# `Func<Task>` commands are 15e's synchronous `OverlayCommands` (D-W8B4O-9).
