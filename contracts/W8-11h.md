## Semantics notes (C# is the spec; the R0001 spike supplies proven calls)
1. `create_factory(debug_level)`: `D2D1CreateFactory::<ID2D1Factory1>(D2D1_FACTORY_TYPE_SINGLE_THREADED, Some(&D2D1_FACTORY_OPTIONS { debugLevel: D2D1_DEBUG_LEVEL(debug_level as i32) }))` (the spike passes `None`
   options, equal to level 0; C# passed an options struct). The factory and everything created from it are used only on the creating thread (trap T1).
2. `create_device_and_context` is `factory.CreateDevice(dxgi_device)` then `device.CreateDeviceContext(D2D1_DEVICE_CONTEXT_OPTIONS_NONE)` (C# lines 279-282; spike lines 305-306). The `IDXGIDevice` comes from `d3d11::dxgi_device`.
3. `create_solid_color_brush(context, color)`: `CreateSolidColorBrush(&color, None)`.
4. `max_bitmap_size` is `GetMaximumBitmapSize()` as `i32`, saturating at `i32::MAX` (16384 on feature level 11, 4096 on 9.3).
5. `target_bitmap_properties(has_swap_chain, dpi_scale)` (pure): format `DXGI_FORMAT_B8G8R8A8_UNORM`; alpha `D2D1_ALPHA_MODE_IGNORE` when `has_swap_chain`, else `PREMULTIPLIED`; `dpiX = dpiY = (96.0 * dpi_scale) as f32`; options
   `TARGET`, plus `CANNOT_DRAW` when `has_swap_chain` (a back buffer cannot be drawn from; an offscreen target can, and can be a `CopyFromBitmap` source); `colorContext = ManuallyDrop::new(None)`.
6. `image_bitmap_properties(alpha_mode, options)` (pure): format B8G8R8A8_UNORM, the given alpha mode, `dpiX = dpiY = 96.0` (a bitmap's DIP size equals its pixel size), the given options, no colour context. Callers:
   `PREMULTIPLIED` for `Pbgra32`, `IGNORE` for `Bgr32` (the X byte is ignored); `CPU_READ | CANNOT_DRAW` for read-back bitmaps; `NONE` for upload bitmaps.
7. `create_target_bitmap`: with `Some(swap_chain)`: `dxgi::back_buffer(swap_chain)` surface, `context.CreateBitmapFromDxgiSurface(&surface, Some(&props))` with `target_bitmap_properties(true, ..)`; with `None`:
   `context.CreateBitmap(D2D_SIZE_U { pixel_width, pixel_height }, None, 0, &props)` with `target_bitmap_properties(false, ..)`. The surface is dropped before returning. It does not call `SetTarget`. `attach_target` then does
   `SetTarget(bitmap)` and `SetDpi(d, d)` (C# order: target first, then dpi); `detach_target` is `SetTarget(None::<&ID2D1Image>)`.
8. `create_bitmap_uninitialized`: `CreateBitmap(size, None, 0, &image_bitmap_properties(alpha, options))`. Contents are undefined until written (C# passed `null` data, "written later by CopyFromMemory").
9. `copy_from_memory(bitmap, dest, pixels, pitch)`: let `rect = dest.unwrap_or(0, 0, bitmap width, bitmap height)`; `rect_w = right - left`, `rect_h = bottom - top`; error `Err(GfxError { E_INVALIDARG, "CopyFromMemory" })` if
   `right <= left`, `bottom <= top`, the rect leaves the bitmap, `pitch < rect_w * 4`, or `pixels.len() < pitch * (rect_h - 1) + rect_w * 4` (computed in `u64`). Only then the call
   `bitmap.CopyFromMemory(dest, pixels.as_ptr().cast(), pitch)` (the HRESULT of the call keeps its error). Pixel format is the bitmap's (BGRA 4 bytes). Used for stripe uploads by W8-12g.
10. `read_pixels(context, source, w, h)`: `w` and `h` equal the source's pixel size; creates the CPU bitmap with `image_bitmap_properties(PREMULTIPLIED, CPU_READ | CANNOT_DRAW)`, `CopyFromBitmap(None, source, None)`,
    `Map(D2D1_MAP_OPTIONS_READ)`, then for each row copies `w * 4` bytes from `bits + y * pitch` into a tight `Vec<u8>` of `w * 4 * h` (pitch >= `w * 4` is checked; the mapped pitch is NOT the row length), and unmaps through a drop
    guard on every path. The result is BGRA premultiplied. Must not run between `BeginDraw` and `EndDraw` of `source`.
11. `end_draw_hresult(context)`: `context.EndDraw(None, None)`; `Ok` is `0`, `Err(e)` is `e.code().0`. The caller (W8-12c) applies the fault seam and `com::is_device_lost`.
12. `dwrite::create_factory()` is `DWriteCreateFactory::<IDWriteFactory>(DWRITE_FACTORY_TYPE_SHARED)`.
13. `create_text_format(factory, family, bold, size, locale)`: `CreateTextFormat(&HSTRING::from(family), None::<&IDWriteFontCollection>, if bold { BOLD } else { REGULAR }, NORMAL, NORMAL, size, &HSTRING::from(locale))`.
    No validation of `size` here (W8-12i rejects non-finite or non-positive sizes with `RenderError::InvalidFontSize` before any native call). An unknown family does not fail: DirectWrite falls back to a default font.
14. `create_text_layout(factory, text, format, max_width)`: `text.encode_utf16().collect::<Vec<u16>>()` (UTF-16 length, no terminating NUL) and `CreateTextLayout(&wide, format, max_width, UNBOUNDED)`. Empty text is valid
    (`EmptyText_HasZeroWidthAndDrawsNothing`). `max_width` is already normalised by W8-12i (`DWriteTextRenderer.NormalizeWidth`: NaN or >= 1 000 000 is `UNBOUNDED`, negative is 0).
15. `layout_metrics` is `GetMetrics` reduced to width, height, `lineCount`. `first_line_is_trimmed` is `GetLineMetrics(Some(&mut [DWRITE_LINE_METRICS; 1]), &mut count)` and `isTrimmed.as_bool()`; a failing call is `false`.

## Safety rules (every `unsafe` block gets a `// SAFETY:` comment; `undocumented_unsafe_blocks` is on)
- Raw pointers appear in four places: `D2D1_BITMAP_PROPERTIES1` passed by pointer (a local that outlives the call), the `CopyFromMemory` source (a slice borrowed for the call; the length check of rule 9 is the soundness argument,
  and the SAFETY comment must quote it), the `Map`ped rows in `read_pixels` (valid until `Unmap`; the guard unmaps in `Drop`, the copy reads only `w * 4` bytes of each of `h` rows after checking `pitch >= w * 4`, and the mapped
  pointer is not null), and `EndDraw` tag pointers (`None`).
- `Map` -> read -> `Unmap` is balanced on every path including `?` early returns: the guard is created right after a successful `Map` and its `Drop` calls `Unmap` once; `Unmap` errors in `Drop` are ignored.
- `ManuallyDrop::new(None)` for `colorContext` never leaks (no interface inside). Never `ManuallyDrop::drop`, never `forget`.
- Thread affinity (trap T1): the factory is single threaded. `ID2D1Factory1` and the others are `Send` in windows 0.62, so the compiler will NOT stop a move: the owning types of W8-12b/12c/12e/12i must be `!Send` (D-W8B3G-9 rule).
  A second device on another thread (keep-warm) creates its OWN factory.
- DirectWrite: `IDWriteFactory` (shared) is free-threaded, but layouts are created and drawn on the UI thread only (W8-12i keeps the cache on the UI thread).
- `unsafe_op_in_unsafe_fn = deny`: all public functions are safe.

## Error mapping
- Every `Err` is a `GfxError` named by the API: `"D2D1CreateFactory"`, `"ID2D1Factory1::CreateDevice"`, `"ID2D1Device::CreateDeviceContext"`, `"ID2D1DeviceContext::CreateSolidColorBrush"`, `"IDXGISwapChain::GetBuffer"` (from `back_buffer`),
  `"ID2D1DeviceContext::CreateBitmapFromDxgiSurface"`, `"ID2D1DeviceContext::CreateBitmap"`, `"ID2D1Bitmap::CopyFromMemory"` / `"CopyFromMemory"` (argument check), `"ID2D1Bitmap::CopyFromBitmap"`, `"ID2D1Bitmap1::Map"`,
  `"DWriteCreateFactory"`, `"IDWriteFactory::CreateTextFormat"`, `"IDWriteFactory::CreateTextLayout"`, `"IDWriteTextLayout::GetMetrics"`.
- Device loss: `D2DERR_RECREATE_TARGET` surfaces from `EndDraw` (`end_draw_hresult`), bitmap creation after a loss (`GfxError::is_device_lost()`), and `CopyFromBitmap`/`Map` on a lost device. Callers recreate the device; this module
  never retries.
- `end_draw_hresult` returns the number, not an `Err`: a failed `EndDraw` is a normal frame result (`PresentResult::Failed`/`DeviceRecreated`).
- `first_line_is_trimmed` swallows its error by design (C# `hr >= 0 && ...`).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (affinity): single-threaded factory; objects of one factory stay on its thread; windows-rs does not enforce it (the interfaces are `Send`). `!Send` owners in `render`.
- T2 (target lifetime): `detach_target` (`SetTarget(None)`) then drop the target bitmap BEFORE `dxgi::resize_buffers` (W8-11g T1). A bitmap created from a back buffer keeps a reference to it.
- T3 (pitch): the `Map`ped pitch is not `w * 4`; copy row by row. A `CopyFromMemory` pitch is the SOURCE row pitch in bytes.
- T4 (DPI): target dpi is `96 * scale` and is set on the context AFTER `SetTarget`; image bitmaps are 96 dpi, so a bitmap's DIP size equals its pixel size (the draw context relies on it).
- T5 (alpha): swap-chain target `IGNORE`, offscreen target `PREMULTIPLIED`; `Bgr32` image bitmaps `IGNORE`. Mixing them changes the read-back alpha byte and the blending.
- T6 (`ManuallyDrop` field): `D2D1_BITMAP_PROPERTIES1` must be initialised with `colorContext: ManuallyDrop::new(None)`; a struct-update from `Default` does not exist for it.
- T7 (device-context overloads): `ID2D1DeviceContext::CreateBitmap` and `::DrawBitmap` (D2D 1.1, `D2D1_BITMAP_PROPERTIES1` / `D2D1_INTERPOLATION_MODE`) shadow the `ID2D1RenderTarget` ones reached through deref (D2D 1.0, `D2D1_BITMAP_PROPERTIES` / `D2D1_BITMAP_INTERPOLATION_MODE`).
  Only the 1.1 forms are used (nearest/linear/high-quality cubic).
- T8 (UTF-16): `encode_utf16` units, not bytes or chars; surrogate pairs count as two. The layout's text positions are UTF-16 offsets.
- T9 (`UNBOUNDED` is finite): DirectWrite needs a finite number; `f32::INFINITY` is not accepted.
- T10 (read-back during a draw): `read_pixels` between `BeginDraw` and `EndDraw` of the source returns an error or stale pixels; the draw context checks (`TryReadPixels` is only valid outside a frame).

## Decisions taken in this contract (D-W8B3G-n; the lead may overrule in `contracts/README.md`)
- **D-W8B3G-6 Audit rule** (as in W8-11g): a row per non-`Reserved` member; "kept" means a helper that returns owned windows types; draw calls on the device context are NOT wrapped (the draw context in 12e owns the state machine).
- **D-W8B3G-9 Missing edges, dependency and affinity rule:** (a) W8-11h native tests need W8-11g; (b) W8-12b..12i also depend on W8-11f; (c) W8-12e needs the crate `windows-numerics` (already locked at 0.3.1 through `windows` 0.62.2) for `Matrix3x2`, `Vector2`
  and `Matrix4x4`: the lead adds it to `[workspace.dependencies]` and `crates/pr-platform-win/Cargo.toml` before 12e starts (not done here: only the lead adds dependencies); (d) the owning render types (`render::device`, surface, text renderer) are `!Send`
  (`PhantomData<*const ()>`), because windows 0.62 marks the D3D/DXGI/D2D/DWrite interfaces `Send` and nothing else enforces the thread rule.

## Open questions
1. **`copy_from_memory` as a safe wrapper vs a raw `unsafe fn`.** Recommended (taken): safe, with the length check, because the stripe uploader (12g) computes offsets and a wrong one would read past the `PixelBuffer`. Cost: one extra comparison per stripe.
   Alternative: expose the raw call and let 12g carry the proof; rejected (spreads `unsafe` into the cache logic).
2. **Should draw-call wrappers (`fill_rectangle`, `draw_bitmap`...) exist in `d2d.rs`?** Recommended: no (D-W8B3G-6): each is one windows-rs call with a `// SAFETY:` in 12e, and the draw context must keep the frame state (balanced clips and opacity) anyway.
3. **Leak guard by handle count** is weak; alternatives (`ID3D11Debug::ReportLiveDeviceObjects`) need the debug layer, which is not installed on `windows-latest`. Recommended: keep the handle-count test as a smoke guard and rely on W8-12b/12c's `LiveBitmapCount`
   port for real leak assertions.
4. **`windows-numerics` as a direct dependency** (D-W8B3G-9 c). Alternative: transmute `[f32; 6]` to the matrix type; rejected (undocumented layout reliance for no gain).
