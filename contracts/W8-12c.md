## Semantics notes (C# is the spec)
1. **`create_bitmap` takes a slice, not a raw pointer.** `data: Option<&[u8]>` with `pitch`; `None` is "contents undefined, written later by `copy_from_memory`". The C# passed the initial data to `CreateBitmapEx`; Rust creates the bitmap with
   `d2d::create_bitmap_uninitialized` and then `d2d::copy_from_memory(&bitmap, None, data, pitch)` (which checks the slice length against the pitch, the C# trusted the caller). If the copy fails the new bitmap is dropped and the count is NOT incremented.
   `live_bitmap_count += 1` happens only after success. A zero or negative size is `Err(ArgumentOutOfRange { param: "pixelWidth" | "pixelHeight" })` (C# would have cast to `uint` and let D2D fail; this is a deliberate hardening, D-W8B3R-8).
2. **`release_bitmap(Some(b))`** drops `b` and decrements; `None` does nothing. The count may go below zero only if a caller releases a bitmap it did not create here (C# same); do not clamp.
3. **`resize`.** Order is fixed: (a) `Err(Disposed)` if disposed; (b) store `clamp_dimension` size and `normalize_dpi_scale` DPI (they stay changed even if later steps fail, as in C#); (c) `release_target`; (d) with a swap chain:
   `d3d11::clear_state_and_flush(d3d)` then `dxgi::resize_buffers(sc, w, h)`; an `Err(GfxError)` here is `Ok(BuffersFailed(hresult))` and the target stays released; (e) `create_target` (its `Err` is `Err(Device)`); `Ok(Resized)`.
   A device loss detected here is the SURFACE's job (it tests `is_device_lost(hr)` and calls `recreate`).
4. **`create_target`**: `d2d::create_target_bitmap(&context, swap_chain.as_ref(), w as u32, h as u32, dpi_scale)` then `d2d::attach_target(&context, &bitmap, dpi_scale)`; stores the bitmap in `state.target`. DPI is `(96.0 * dpi_scale) as f32`.
5. **`release_target`**: `d2d::detach_target(&context)` FIRST, then `state.target = None` (drop). After this the back buffer has no reference from us, which `ResizeBuffers` needs.
6. **`touch_gpu`**: `BeginDraw`, `Clear(0,0,0,1)`, `end_draw_hresult` (NOT the fault hook: the C# calls `Context.EndDraw` directly here), `check` it (`Err(Device { operation: "ID2D1DeviceContext::EndDraw" })`), `d3d11::flush`. On the keep-warm thread this runs against its own offscreen device.
   A failed `EndDraw` leaves the context out of a draw; the next `touch_gpu` starts a new one.
7. **`synchronize`**: probe is created once (`create_bitmap(1, 1, None, 0, PREMULTIPLIED, CPU_READ | CANNOT_DRAW)`), kept in `state.sync_probe` (counted), released by `release_all` through `release_bitmap`. Copy rect (0,0,1,1) from the target, `Map(READ)`, `Unmap` after a successful `Map`.
   Not for the normal draw path.
8. **`to_d2d_interpolation`**: constants 0, 1, 5 (`HIGH_QUALITY_CUBIC` is 5, not 2: the Rust enum discriminant 2 is the C# `ImageInterpolation` value, which is NOT the D2D value; a test pins both).

## Traps checklist (docs/MULTI-AGENT-PLAN.md section 7)
- T1 (the back-buffer trap, D-W8B3G-7): `ResizeBuffers` fails with `DXGI_ERROR_INVALID_CALL` while ANY reference to a back buffer exists: the target bitmap, a clone returned by `target()`, a DXGI surface. Callers (the surface, the draw context) must not hold the
   `ID2D1Bitmap1` from `target()` across `resize`. `resize` itself drops `state.target` before `ResizeBuffers`.
- T2 (`clear_state_and_flush` before `resize_buffers`): required, otherwise the D3D immediate context keeps the old back buffer bound (C# comment at 165).
- T3 (integers, item 3): `pitch` is `u32`, sizes are `i32 >= 1` before the cast; use `u32::try_from(..)` or the clamped value; never `as u32` on a possibly negative `i32`.
- T4 (DPI float): `(96.0 * dpi_scale) as f32` where the product is `f64` (C# `(float)(96 * DpiScale)`); `d2d::target_bitmap_properties` already does it, do not recompute.
- T5 (alpha modes): swap chain target is `IGNORE` + `CANNOT_DRAW`; offscreen target is `PREMULTIPLIED`; image bitmaps follow the layout (`Pbgra32` premultiplied, `Bgr32` ignore). A swapped mode produces wrong colours without any error: a pixel test pins the offscreen case.
- T6 (disposed getters): after `dispose` every method here is `Err(Disposed)` except `release_bitmap` (drops anyway) and `release_target` (no-op).
- T7 (exceptions to Result, item 9): the C# `Resize` returns an HRESULT for one failure and throws for the others; the Rust `Ok(BuffersFailed(hr))` / `Err(Device)` split keeps exactly that distinction. Do not fold them.
- T8: the probe bitmap and every bitmap are COM objects of the CURRENT device; `recreate` drops the probe (`release_all`) and `synchronize` re-creates it lazily after a recreate.

## Safety rules
- One group of `unsafe` remains: `touch_gpu` calls `ID2D1DeviceContext::BeginDraw()` and `Clear(Some(&color))` directly (both `unsafe fn` in windows 0.62.2; SAFETY: the context is alive and owned, the colour is a local that outlives the call, the previous draw was ended) (nothing else, unless a `gfx::d2d` helper proves insufficient). `gfx` wraps the raw-pointer bitmap calls (`create_target_bitmap`, `copy_from_memory`, `read_pixels`).
- Borrow rule: `state` is a `RefCell`; never call `context()` (which borrows) while a `state.borrow_mut()` is live; clone the interface out first.
- Thread: UI thread (or the keep-warm thread for its own instance); `!Send`.

## Error mapping to `RenderError`
Same table as W8-12b (`RenderFault` to `RenderError` field by field). `buffers_failed` is not an error: `BuffersFailed` carries the HRESULT to the surface, which maps a non-loss failure to `Device { hresult, operation: "IDXGISwapChain::ResizeBuffers" }`.
