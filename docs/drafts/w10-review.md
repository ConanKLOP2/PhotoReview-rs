DOC-W10-REVIEW, machine C (cloud), 2026-10-23. Read-only against the C# repo (shallow-then-deepened clone, `7eaee2a2` checked out) and `origin/master` of this repo. No cargo, no tests, no network access other than the git clones. Scope: `contracts/W10-H1..H3`, `W10-R1..R5`, `W10-B1..B3`, `W10-N1..N4`.

## 1. Method

- Every C# file, line number, type name, member name and test name cited in the contracts was looked up at `7eaee2a2` (and at `d92d6aae` and `a6e530f2` where the contract cites those).
- Every backticked `Test_Name` of the contracts was grepped in the C# `tests/`, `tools/`, `src/`; the identifiers that are not C# (environment variables, Win32 names) were grepped in `crates/`, `tools/`, `.github/`.
- Rust paths, line numbers, signatures and env-var names were checked with `git grep` / `sed` on `origin/master` (02e2757 and later).
- Not done: nothing was built or run; hashes of the DLLs and archives were not recomputed; the `docs/drafts/*.yml` / `deny.toml` syntax is DOC-CI-DRAFT-CHECK's job; .NET runtime defaults and WinHTTP behaviour were not probed (the contracts already mark them unverified).

## 4. Needs a decision (not changed; recommendation first)

- **N-1 (recorded as P-50, recommended option applied to W10-N1/N2): where the native DLLs must be staged for the tests.** Facts: `pr-libraw/tests/{availability,native}.rs` and `pr-turbojpeg/tests/availability.rs` need the DLL "next to the test executable" (`target/<profile>/deps` for `cargo test`, loaded by `LoadLibraryExW` with an absolute exe-folder path); only `pr-turbojpeg/tests/decoder_native.rs`, the native module of `pr-turbojpeg/src/native.rs` and one place in `pr-libraw/tests/decoder_native.rs` read `<repo>/native/x64/`. W10-N1 stages only into `native/x64/`, so about half of the 98 ignored tests would skip or fail on a correctly staged machine. Options: (a) the staging script also copies both DLLs into the `deps` folder of the `CARGO_TARGET_DIR` that N2 sets (`target-w10-raw-native`), no code change; (b) change the tests to read `native/x64/` (code change, outside this wave's documents); (c) one DLL copy only in `deps` and drop `native/x64/`. Recommended: (a), because N2 already fixes its own target dir and nothing in `crates/` changes. If chosen, W10-N1 gets a second destination and W10-N2 a pre-run copy step.
- **N-2 (recorded as P-51, recommended option applied to W10-N2/N3): corpus environment variable names.** Facts: `PHOTOREVIEW_RAW_CORPUS_DIR` and `PHOTOREVIEW_RAW_CORPUS_STRICT` are used by 6 Rust test files (arw, cr2, cr3, raf, w5_18, pr-libraw `decoder_native`); `PHOTOREVIEW_RS_RAW_CORPUS_STRICT` by 4 (nef, rw2, pr-libraw `availability`/`native`); `PHOTOREVIEW_RS_RAW_CORPUS_DIR`, which the W10-N3 harness snippet reads, by none. R0002 asks for the `PHOTOREVIEW_RS_` prefix for the Rust app's own variables; test-only variables are not covered by it. Options: (a) keep both names, N2/N3 instruct the operator to set both strict variables, N3's snippet reads the existing `PHOTOREVIEW_RAW_CORPUS_DIR`; (b) unify on the `PHOTOREVIEW_RS_` names in a separate code unit (10 test files); (c) unify on the C# names. Recommended: (a) now, (b) later as its own unit. N2 and N3 were edited only as far as (a) requires.
- **B-1: contract baseline header.** Every W10 contract says "baseline `d92d6aae`" while the spec baseline is `7eaee2a2` since #182. Only the files listed in section 3 changed in that range for the lines these contracts cite (the range also changed `ci.yml`, `release.yml`, `publish-release.ps1`, `verify-release.ps1` in #531, and tests that W10 does not cite). Recommended: leave the headers, rely on section 3 and this note; changing them would claim a re-verification of lines that were not touched.
- **R-1 (information): C# default release package.** After #531 the C# release is the framework-dependent ReadyToRun Win32 `PhotoReview.exe` ("Requires the .NET 10 Runtime"); the checks W10-R1/R4 copy from `verify-release.ps1` (size bounds, forbidden managed files, two DLLs, source archive) belong to its optional Native AOT variant (`Test-AotRelease`, "WP-36"). They are a sound model for a native Rust exe, but the "Requires" text and the size numbers must not be copied (R4 already says so for the sizes). No action needed unless the release notes text is taken from the C# workflow.
- **R-2 (information): shared live-operation marker.** C# `ShellInstanceNames` keeps the `WindowsLiveOperationRegistry` prefix shared between the WPF and Win32 apps so that each journal reconcile skips operations still running in the other (`ShellLaunch.cs` comment, Q-R27). R0002 gives the Rust app its own data root and never reads the C# journal, so W10-R5's coexistence test does not need it; if Rust ever reads a C# journal this changes.
