# E1 implementation evidence (P-300, P-312, P-313), 2026-11-03

Crate: `pr-platform-win`. Branch `fix/hardening-timer-render`. Hardening only: no observable change on the normal path.

## P-300 timer thread spawn failure is logged
- `host/main_window/core.rs`: `timer_queue(log: Option<&dyn Log>)` (private) starts the thread through the new private `start_timer_thread(queue, log, spawn)`; a spawn error is logged with `Log::error`. Only the caller that creates the process-wide queue can report (it is built once).
- Public API: `UiLocalPoster::new` is unchanged; new additive `UiLocalPoster::with_log(Arc<dyn Log>)`. `MainWindowInner` creates its poster with the window log. Posters made without a log (tests) stay silent as before.
- Test: `core::tests::timer_thread_start_failure_is_logged` (failing spawn is logged once with the io error text; a working spawn logs nothing and runs the queue). Not strictly red-first: it exercises a new seam, so it cannot compile on master.

## P-312 BudgetedImageCache does not hold its RefCell across backend upload / upload_rows
- `image_cache/policy.rs`: `get_or_upload`, `prefetch` and `run_stripe` check state under the borrow, release it, call `backend.upload` / `upload_rows`, re-borrow and record the result. `upload_rows` is split into `write_rows` (no borrow) and `finish_rows` (under borrow; returns whether the entry with that serial still exists). Re-checks after the call: cache disposed meanwhile (new image is released, `Err(Disposed)`), the same id cached meanwhile (duplicate released, existing entry kept), entry removed or replaced during a stripe (stripe ends inert, no UploadCompleted, no reschedule).
- Trait doc RULE updated: only `release` must not re-enter (it still runs under the borrow, eviction paths).
- Tests (`tests/render_image_cache_policy.rs`, fake backend with a re-entry hook): `get_or_upload_new_buffer_lets_the_backend_read_the_cache`, `prefetch_lets_the_backend_read_the_cache`, `run_stripe_lets_the_backend_read_the_cache_and_still_completes`, `get_or_upload_completing_a_prefetched_image_lets_the_backend_read_the_cache`, `get_or_upload_disposed_by_the_backend_mid_upload_releases_the_image`. All 5 failed on master with `RefCell already mutably borrowed` (policy.rs:299), pass now; the 48 existing tests stay green.

## P-313 draw_image_oriented / pop_clip on a released device
- `render/draw_context.rs`: `draw_image_oriented` pops only if its push was applied (private `try_push_transform`; public `push_transform` unchanged). `pop_clip` checks the depth first (depth 0 still `Err`), and decrements only when the D2D pop is issued (context present). With a released device the clip stays counted and `end()` unwinds it (and reports unbalanced).
- Tests (in-crate, `DeviceResources::create_offscreen` then `dispose`): `draw_image_oriented_on_a_released_device_keeps_the_callers_transform`, `pop_clip_on_a_released_device_keeps_the_depth_and_end_unwinds_it`, `pop_clip_without_push_is_still_an_error_on_a_released_device`. The first two were verified red by mutating the fix back out.
