# D1 IMPL: P-310, HUD zoom text refresh after an input zoom (2026-11-03)

Owner decision (chat, 2026-11-03): do P-310. Restores C# behaviour (`MainViewModel.cs:140-143`: `DisplayZoomPercent` -> `InfoOverlay.Refresh()`). No deviation vs C#, no C# change.

## What changed
- `crates/pr-app/src/viewmodels/main/commands.rs`: `MainViewModel::on_viewer_zoom_mode_changed` now builds the `ViewerUpdate` with `ViewerChanges` containing `ViewerProperty::DisplayZoomPercent` (was empty). `apply_viewer_update` therefore runs `refresh_overlay()` and the returned `ChangeSet` carries `overlay: ZoomIndicatorText` (and `viewer: DisplayZoomPercent`). The shell host (`pr-platform-win` `ShellInputHost::on_viewer_zoom_mode_changed` -> `self.call(...)`) already forwards the returned `ChangeSet` to the window, so `MainWindowOverlay::on_view_model_changed` marks the HUD model dirty. No pr-platform-win change was needed.

## Why
Before: an input zoom (wheel, click, keys, D1, Fit) returned an entirely empty `ChangeSet`, so the cached HUD model kept the old zoom text (G2 H3 part 2, `docs/reviews/G2-2026-11-03.md`).
