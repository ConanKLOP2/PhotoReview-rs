# P-393: `tool_path_guard.rs` non-Windows twin removed (2026-11-10)

Owner decision 1A (2026-11-10): the up-front replace refusal of `tool_path_guard` is Windows only; the `#[cfg(not(windows))]` twin of
`leaf_refuses_replacement` (former line 297-300, mutants 299:5 x2 and 299:76) is deleted instead of being run on Linux.

## Change

- `crates/pr-bench/src/cli/tool_path_guard.rs`: `replace_leaf` calls `leaf_refuses_replacement` only under `#[cfg(windows)]`; the
  non-Windows twin is removed; the `replace_leaf` doc comment states that non-Windows is not a supported platform of this tool
  (without the guard a plain `rename` decides, which is not .NET `File.Move` behaviour).
- No behaviour change on Windows: the Windows body of `leaf_refuses_replacement` and the call in `replace_leaf` are unchanged.
- Read all `cfg(not(windows))` uses of `pr-bench` first: `tool_path_guard.rs:297` (removed) and `tests/bench_compare_cli.rs:38`
  (a `kill -KILL` fallback in a test helper, a test-only process-timeout path; left as is, it is not production code).
- The rest of `pr-bench` has no Windows-only dependency (it needs only `pr-core`, `pr-imaging`, `pr-perf`), so the crate keeps
  compiling in principle on other targets; this was NOT checked with `cargo check --target`: only `x86_64-pc-windows-msvc` is
  installed and nothing was installed. The removed twin was never run by any CI job (CI builds and tests on `windows-latest`).

## The 2 missed mutants (known equivalents, unchanged by this change)

- `226:9` `delete match arm Some(ERROR_PATH_NOT_FOUND)` in `map_write_error`: the Win32 code 3 is classified by std as
  `ErrorKind::NotFound`, which the fallback arm maps to the same `DirectoryNotFoundException`; the whole domain gives the same visible
  result (run proof: `tests/mut3_tool_path_guard_proofs.rs`).
- `281:62` `replace | with ^` in `FILE_ATTRIBUTE_READONLY | FILE_ATTRIBUTE_DIRECTORY`: the two constants share no bit
  (`0x1`, `0x10`), so `|` and `^` yield the same value `0x11` (equivalent by construction; the `&` variant is caught).

These two were not re-proven by an extra run in this note beyond the suite passing on the original; they stay under the earlier
N4/MUT3 proofs.
