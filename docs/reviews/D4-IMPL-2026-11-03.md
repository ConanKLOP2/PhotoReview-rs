# D4 IMPL, P-92 option A: percent pattern from the OS (2026-11-03)

Decision (owner, 2026-11-03): P-92 option A. `WindowsNumberFormatting::percent_one_decimal` reads the percent pattern from the OS and the hard-coded language table is deleted.

## What changed

- `crates/pr-platform-win/src/shell_startup/locale.rs`: `percent_one_decimal` reads `LOCALE_IPOSITIVEPERCENT` (0 `n %`, 1 `n%`, 2 `%n`, 3 `% n`) and `LOCALE_SPERCENT` through `GetLocaleInfoEx`; patterns 0 and 3 use a plain U+0020 (as .NET). The language table (fr U+202F, tr/fa prefix, 17 languages U+00A0) is gone.
- The locale helpers (`query_locale`, `format_number`) got `*_of(locale, ...)` variants taking an explicit locale name; the user-default wrappers are unchanged. New `pub fn percent_one_decimal_for_locale(name, ratio)` lets tests run all 37 golden cultures on any machine (NLS knows every locale regardless of the user locale). No new `unsafe`; the existing SAFETY comments still apply (the explicit locale is a NUL-terminated 85-unit buffer, same as `locale_name()`).
- Second issue (-0.0 sign): fixed, small. `GetNumberFormatEx` drops the sign of `-0.0`; when `{scaled:.1}` is `-0.0` the magnitude is formatted and `-` is put back, as .NET prints `-0.0%`.

## Tests (`crates/pr-platform-win/tests/shell_startup_locale_percent_golden.rs`)

- Red first: before the change, 86 of 444 golden cases differed (probe over all 37 cultures by explicit name).
- `percent_one_decimal_matches_csharp_for_every_golden_ratio`: un-ignored and rewritten to run all 37 cultures x 12 ratios by explicit locale name (the old version only read the user locale and was `#[ignore]`d).
- `percent_one_decimal_keeps_the_sign_of_a_negative_value_that_rounds_to_zero`: un-ignored, now asserts en-US `-0.0%`, fr-FR `-0,0 %`, `0.0` stays `0.0%`.
- New `percent_one_decimal_uses_the_os_pattern_with_a_plain_space` (de-DE, de-CH, fr-FR, pl-PL, tr-TR).
- `..._matches_csharp_golden_for_a_non_p92_user_locale` replaced by `..._for_a_golden_user_locale` (no P-92 language exemption; it now includes the -0.0 ratio). The en-US guard and the golden-coverage test are unchanged apart from the constant name.

## Cultures that still differ from the golden (NLS is not ICU), not hidden

Measured on this machine (Windows 10 19045); they are excluded in the test by `NLS_DIFFERENT_CULTURES` / `NLS_DIFFERENT_NEGATIVE_CULTURES`:

- All ratios: `fa`, `fa-IR` (NLS decimal `/`, group `,`, symbol `%`, pattern 0 `n %`; ICU `٫`, `٬`, `٪`, pattern 1), `ar` (NLS `.` `,` `%`; ICU Arabic-Indic separators, `٪` and a trailing U+061C), `ru` (NLS pattern 1 `n%`; ICU `n %`).
- Negative ratios only: `sv`, `fi`, `nb` (ICU uses U+2212 minus), `he` (ICU adds U+200E before the minus), `tr` (C# negative pattern gives `-%25,0`, Rust positive pattern gives `%-25,0`; the negative percent pattern `LOCALE_INEGATIVEPERCENT` is not read, outside the decision).
- Every other culture, including `fr`, `de`, `es`, `pl`, `pt`, `it`, `de-CH`, `fr-CH`, all 12 ratios incl. -0.000049, matches.

## Deviation versus C#

None intended for the matching cultures. Remaining differences are the NLS-vs-ICU list above (the Diagnostics hit-rate text only). Suggested PARITY `Different` row: "Percent text (`{ratio:P1}`): Rust reads the Windows NLS percent pattern and symbol; .NET reads ICU. fa, ar, ru differ for all ratios; sv, fi, nb, he, tr differ for negative ratios (minus sign / bidi marks / negative pattern). Test: `percent_one_decimal_matches_csharp_for_every_golden_ratio`." No ADR needed beyond that row unless the owner wants one; suggested wording: "P-92 A: percent placement comes from the OS pattern (LOCALE_IPOSITIVEPERCENT) with a plain U+0020; NLS-vs-ICU data differences for some cultures are accepted."

## Not run

Golden against a machine whose user locale is not en-US (explicit-name test covers the cultures instead); the C# oracle was not regenerated.
