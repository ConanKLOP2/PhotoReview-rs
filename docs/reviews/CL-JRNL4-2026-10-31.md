## The four CL-JRNL3 timeouts

They deadlocked or looped. A killer must fail fast and never hang the run: every killers8 test that can hang runs the work on a spawned worker thread and waits on a channel with `recv_timeout(2 s)`; a deadlock becomes an `expect` failure after at most 2 s (the deadline is an upper bound for a failing run; a passing run takes milliseconds) and the abandoned worker dies with the test process. The test thread never calls the journal itself (that call would block with no deadline), and the journal uses fake storage on a fake path, so the abandoned worker holds no real file handle (an earlier version with `TempRoot` hung in the directory removal on drop; found and fixed, and a first version with a `join` on the first worker hung too).

* `58:50` `256 * 1024` -> `256 / 1024` (window 0): `reverse_read_initial_window_is_256_kib` pins the public constant. Caught (`fin`).
* `312:32` guard -> false and `312:38` `==` -> `!=`: `same_thread_reentry_under_the_gate_completes_instead_of_deadlocking` re-enters the journal from the `read_entries` callback on the owning thread (`read_latest_entry` takes the gate again). Caught (`gate`).
* `327:9` `GateGuard::drop` -> `()`: `gate_is_released_when_the_guard_drops_so_another_thread_can_enter` appends on one thread, then appends and reads on a second one. Caught (`gate`).
* `329:24` `==` -> `!=` in `drop` (depth zero test): caught by the same test (`gate`).

With the real gate mutated by hand, both gate tests fail after about 2 s (`FAILED ... finished in 2.01s`) instead of hanging.

### Equivalent: `914:48` `first_newline + 1` -> `first_newline * 1`

`line_start` becomes `first_newline`, so the chunk handed to `parse_committed_moves` starts with the `\n` that ends the partial first line (an empty line, which the parser ignores) and `new_boundary = start + first_newline` points AT that `\n` instead of after it. The next pass reads `[start', boundary)`, which now ends just before the `\n`: its last line is the complete line without its terminator, which `parse_committed_moves` accepts (a last piece without `\n` is parsed; one trailing `\r` is stripped either way). Every record is parsed exactly once from identical bytes, so no observable result changes. The straddling test above passes with this mutant applied by hand and fails with `- 1`, which confirms that only the `-` variant is observable.
