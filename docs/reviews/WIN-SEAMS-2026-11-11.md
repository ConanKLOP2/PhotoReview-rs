# WIN-SEAMS 2026-11-11 (P-404): transport and open-url seams in pr-platform-win

Rust only (no C# twin). No behaviour change: pure seams extracted so mutants become testable.

## Changes

1. `crates/pr-platform-win/src/http/transport.rs`
   - `Url::parse` no longer slices with `&text[..text.len() - 1]` (mutant 174:53, `-` -> `+`/`/`). New pure `without_terminator(&[u16]) -> &[u16]` uses `split_last().map_or(text, |(_, rest)| rest)`.
     `wide` always returns at least the NUL, so the empty buffer was unreachable; in that case the old code would have panicked on the subtraction and the new code returns the empty slice (documented on the fn).
   - The `previous.is_some_and(|f| f as usize == usize::MAX)` check (mutant 377:48) is now `callback_registration_failed(previous.map(|f| f as usize))`, a pure fn over `Option<usize>`.
   - Tests (lib unit tests, no network): `without_terminator_matches_the_old_slice_for_every_wide_buffer` (differential against the old formula, plus empty / NUL-only buffers),
     `callback_registration_fails_only_for_the_invalid_sentinel` (None, `usize::MAX`, 0, 1, 0x1000, `usize::MAX - 1`), `parse_cracks_a_loopback_url_through_the_terminator_seam` (WinHttpCrackUrl only, no socket).
2. `crates/pr-platform-win/src/dialogs/settings/dialog/host.rs`
   - New `#[doc(hidden)] pub fn open_url_info(verb, file) -> SHELLEXECUTEINFOW` builds the struct; `default_open_url` calls it, then `ShellExecuteExW` as before. Same fields, same values.
   - Test `open_url_info_sets_every_shell_execute_field` (in `tests/d10_settings_glue_killers.rs`) checks cbSize, fMask (exact value, no `SEE_MASK_NOCLOSEPROCESS`), lpVerb and lpFile (pointer identity), nShow, null parameters/directory/hwnd/hProcess.
     It never calls `ShellExecuteExW`.
