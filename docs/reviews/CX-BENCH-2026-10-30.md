## Method and new tests

Normal builds use `<worktree>/target`; mutation uses `<worktree>/target-mut` and
`--output <worktree>/mut-out-bench-GROUP`. Source-copy temp is under
`target/mutants-tmp` to avoid recursive copies. Both builds set
`CARGO_PROFILE_DEV_DEBUG=line-tables-only`, `CARGO_INCREMENTAL=0`,
`CARGO_BUILD_JOBS=2`. One mutation run at a time, `-j 1`, `--baseline skip`,
`--timeout 90`, each chunk bounded by `timeout 1200`. No ordinary test runs in
`target-mut`. Mutation and test commands are saved under `target/cx-bench/`.

New tests live only in
[`w10_bench_killers.rs`](../../crates/pr-bench/tests/w10_bench_killers.rs).
They use TempRoot, fake decoders, an unused fake recycle bin and a manually
advanced link clock. No sleeps, fixture mtime arithmetic, elapsed-time thresholds
or wall-clock assertions. Completion waits have hang guards. The custom decoder
deliberately supplies nonpositive dimensions through `DecodedImageView`, rather
than a validated pixel-buffer constructor that would reject them before reaching
the workload predicate. Positive dimensions are also tested, in every decode
workload. C# baseline `7eaee2a2`,
`src/PhotoReview.Benchmarking/BenchmarkWorkloadRunner.cs`, confirms both dimensions
must be strictly positive in all three branches.

**No production code changed.** The detected behavioral survivors are test
coverage gaps. Rust-only Debug assertions pin useful diagnostic fields and error
Display preserves the underlying path/service error.
