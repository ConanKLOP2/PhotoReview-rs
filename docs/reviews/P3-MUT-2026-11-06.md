Rule B as applied here (P-391, closed 2026-11-05, strict reading): a mutant is closed only if it was caught, is unviable, or was proven equivalent BY A RUN over the WHOLE domain in which mutant and original differ (exhaustive loop, full enumeration, boundary sweep that provably covers the divergent set, structural proof executed in a test). A sampled or random differential, a bounded sequence length, or a reading of the code closes nothing: such a mutant is reported "run-supported, open". A timeout is never caught; every timeout below was re-run until the tests failed by assertion (or is listed as open).

## How it ran

* Harness: `tools/dev/mutants.sh` semantics (preflight of the unmutated test command, `--baseline skip`, `-j 1`, `--native` = `--include-ignored --test-threads=1`), but run from a copy kept OUTSIDE the repo (`C:\Users\PC\Projects\mut3-tmp\mutants-inc.sh`): the only changes are `ROOT` pinned to the worktree and `CARGO_INCREMENTAL=1` (the repo script sets 0; with 1 a mutant rebuild reuses the previous mutant's compile inside one run; every run still starts from a fresh copy of the tree). The repo script is untouched. Own target dir per stream under `C:\Users\PC\Projects\mut3-tmp\<stream>\mut-target-pr-platform-win`, `CARGO_BUILD_JOBS=2`, `MUT_TIMEOUT` 240 s (600 to 900 s for the timeout reruns; the default 90 s produced load-induced timeouts in the first streams). Several streams ran at once on different files or line ranges (P-111: `-F` does not narrow, so batches overlap; the table de-duplicates by the full mutant name `file:line:col: replace ...`, and the best verdict wins in the order caught, unviable, missed, timeout).
* Native: no libraw or turbojpeg DLL is needed by these tests; WIC, Direct2D (WARP) and a desktop session are. All windows are hidden or message-only, nothing is shown, no attended step. The real Recycle Bin is never touched (`recycle_bin*.rs` were not mutated or run).
* Tests excluded because they already FAIL on the unmutated tree of this machine (they cannot catch anything): `wic_cache_image::encode_jpeg_and_decode_are_pinned_by_golden_hash` (PNG payload 349 bytes vs 346 in the golden: Windows WIC build), `wic_decoder::wic_icc_transform_failure_carries_the_localized_sentence` (the known OQ1), `wic_decoder_native::corrupt_files_fail_safely_without_crash` and `wic_decoder_native::golden_wic_direct_decode_matches_csharp` (truncated JPEG sample differs: WIC build). They were skipped with `--skip` after the `--` separator for the W4-11c and W4-11e streams.
* One first run (message_loop.rs, tests `host_*`, `Win32LoopOs` included) was stopped by me (own process tree) after two TIMEOUTs of `Win32LoopOs::peek_message` (`true` makes the real loop spin, a hang, not a failure) and restarted with `--skip Win32LoopOs`; its results are NOT used. The `Win32LoopOs` mutants were redone against the new direct seam tests below.
* The first three streams (message_loop/messages/swap clock, `decoder.rs` from the top, painter `widgets.rs`) ran with the UNMODIFIED `tools/dev/mutants.sh` (`CARGO_INCREMENTAL=0`, default 90 s test timeout) and ended by their budgets; everything started later used the copy above.
* The unmutated run of every new test binary passed before its mutants ran.
* Infrastructure failures, found at the end: the machine ran out of commit memory several times ("The paging file is too small", os error 1455; `link.exe` LNK1102; "only metadata stub"; `E0463`/`E0786` can't find or mmap a crate). cargo-mutants reports a failed BUILD as "unviable", so the raw outcome files of this lane contain unviable verdicts that are not compile errors of the mutant. A classifier over every mutant log (`valid.py`, kept with the lane notes) accepts an "unviable" only if its log has a rustc error that points into `crates/*/src` and none of the infrastructure markers; 40 raw unviable verdicts did not pass and are counted as NOT RUN, not as closed. A "caught" is accepted only if its log contains a failing test (`test result: FAILED`, `panicked at` or a `FAILED` line); a "missed" only if its log shows `test result: ok` and no infrastructure marker. Whether each caught test failure came from the mutant and not from the load of the machine was not re-verified one by one.
* Build cost: the three first streams and the later ones used `--cargo-test-arg=--test=X`, which limits the TEST run only; cargo-mutants still builds every test target of the crate for each mutant (`cargo test --no-run --package=pr-platform-win`), which is why one mutant cost 4 to 10 minutes. `--cargo-arg=--test=X` (used only by the last rerun Z) limits the build as well and would have been about ten times cheaper. Recommended for the next lane; `tools/dev/mutants.sh` passes `--tests` the slow way.
