# D8 implementation: preview cache read OOM (P-150 option A), 2026-11-03

Owner decision P-150 option A: `preview_file::read` maps `io::ErrorKind::OutOfMemory` from `read_to_end` to `PreviewCacheError::OutOfMemory` (entry kept, error propagates) like the write path. Evidence for the question: [G29](G29-CACHE-READ-2026-11-03.md).

## What changed
- `crates/pr-imaging/src/cache/preview_file.rs`: new private seam `read_entry_bytes(&mut dyn Read, declared)` (fallible allocation + `read_to_end`), used by `read`. `ErrorKind::OutOfMemory` becomes `PreviewCacheError::OutOfMemory`; every other read error stays `Io`. Doc of the `OutOfMemory` variant updated.
- Callers: all classify through `is_cache_entry_failure()` (`service/decode.rs` ~l.420 -> `PreviewError::DiskEntry`, kept entry, source not decoded; `disk.rs` `try_read_disk_entry` uses `?`). No call site matches on the variant, so nothing else needed handling. `grep PreviewCacheError::OutOfMemory` shows only preview_file.rs, tests and docs.

## Tests
- Added (unit, `preview_file::tests`): `read_failing_with_out_of_memory_is_out_of_memory_not_a_cache_entry_failure` with a fake failing reader. Red on master (`Io(Custom { kind: OutOfMemory })`), green after the change. No existing test changed.

## Deviation vs C#
C# `FileStream.Read` raises `IOException` (cache-entry failure: entry deleted, source decoded). Rust now keeps the entry and propagates. Only reachable on an OS-level out-of-memory read error.
- PARITY 'Different' wording: "D-06 preview cache read: an OS out-of-memory error while reading a .pv4 entry is OutOfMemory (entry kept, error propagates, P-150 A); C# raises IOException and deletes the entry."
- ADR text: "Reading a cache entry treats io::ErrorKind::OutOfMemory like the write path and the decoder: not a corrupt entry. The Rust port deliberately differs from C# FileStream.Read (IOException)."
