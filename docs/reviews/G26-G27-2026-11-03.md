## ADR text for G26 (restates DV-9, M1)
Context: C# and the first Rust port check the epoch only after the rename. A persist writer stuck in the encode while Clear Cache and a newer writer of the same cache path ran could rename its old payload over the newer file, and the stale cleanup then kept it because a newer claim existed. Decision: the commit step (right before `rename_over`) takes the `owner_epochs` mutex, refuses when a newer claim exists or the epoch is no longer current, and keeps the mutex through the single rename. Consequence: a stale writer never publishes; I/O under that lock is limited to two persist workers and one rename (R0003 exception). Alternatives not chosen: a global lifecycle lock across the encode (blocks Clear Cache); deleting every file of the newer epoch on a stale writer (loses current entries). Undo: stop passing the gate in `persist_one`. Rust differs from C# only on this race.
