## The three seams (default path unchanged)

| Seam | Where | Default | Why it is no behaviour change |
|---|---|---|---|
| `TurboJpegDecoder::with_file_opener(fn(&Path) -> io::Result<File>)`, field `open_file` | `crates/pr-turbojpeg/src/decoder.rs`, used by `load_file` for its single open | `open_shared` (the function `load_file` called before) | `new` stores `open_shared`; `load_file` calls `(self.open_file)(path)` instead of `open_shared(path)`: the same function. `read_header_area` / `extend_header_area` still call `open_shared` directly. |
| `header_block_too_large(bytes, cap)` and `read_completion(event, count)` (private fns) | `crates/pr-platform-win/src/http/transport.rs` | called with `HEADER_CAP` and the real `count` | Pure extraction of the former inline `bytes > 2 * HEADER_CAP + 2` and `Event::Read(bytes) if bytes.len() <= count` arms; same expressions, same error values. A smaller cap or an over-long completion is injected by the unit test as an argument, which no real WinHTTP exchange can produce (WinHTTP refuses a header block above 65 536 characters itself, and returns at most `count` bytes). |
| `FileActionService::with_after_mutation_fault(AfterMutationFault)`, field `after_mutation_fault` | `crates/pr-core/src/file_actions/service.rs`, Recycle arm, right after `tx.mark_mutation_completed()` | `None`: no code runs | Same style as `with_move_override` (a public test seam). Production never sets it, so `single_failure` is never entered with `mutation_completed` set. |

Honest limit of the service seam: it creates a state that production cannot reach (a failure after `mark_mutation_completed`, which the last steps `commit` and the result build never raise). The mutant is killed by a run, but the run asserts what the result reports in that state, not a reachable production path.
