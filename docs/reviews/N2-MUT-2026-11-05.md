# N2: run-proofs and killers for the argued-only equivalents of M1, M2 and M3

Owner rule B: a mutant is closed only if caught, unviable, or proven equivalent BY A RUN (an exhaustive or property test that passes under the mutant on the stated input domain, or a differential test). An equivalence argued only by reading the code stays OPEN. This task took the 19 mutants that M1, M2 and M3 had classified equivalent or open by reading (17 positions; `layout.rs:349:15` counts as `<=` and `==`) and gave each one a run.

Result: 19 of 19 decided, 0 open, 0 NOT RUN, 0 timeout. **3 of the 19 were not equivalent** and are now killed (two of them contradict the M1 claims, one was the open M2 survivor).

## Method

- Four new hand-written test files under `crates/pr-app/tests/` (no golden file, no production change): `n2_viewport_layout_proofs.rs` (6 tests), `n2_render_geometry_proofs.rs` (4), `n2_viewer_state_proofs.rs` (4), `n2_kinetic_pan_proofs.rs` (3).
- Equivalence proofs are of two kinds. (a) A differential test: the private helper is reached through the public API, a model of the ORIGINAL code (and a model of the mutant, with counters that prove the sample reaches the input where the mutated comparison takes the other branch) is compared bit for bit with the REAL function. The real function is the part that runs under the mutant, so an observable mutant fails it. (b) An exhaustive or boundary sweep of the input classes of the function.
- Each mutant was then run with `tools/dev/mutants.sh pr-app <file>... --tests n2_<file> --jobs 1 -F '<exact escaped name>'` (cargo-mutants 27.1.0, `--baseline skip`, preflight ran the new tests, `MUT_TIMEOUT` 240 to 300 s, `CARGO_BUILD_JOBS=2`, own `TEMP` and target dir per process under `C:/Users/PC/Projects/tmp-n2`). Only the new test binary was used, no golden. In cargo-mutants 27.1.0 `-F` is `--re` (the M3 remark that it passes a feature is not true for this version): each log says `Found N mutants`, N equal to the number of `-F` filters. MISSED in these runs is the expected result for a proven equivalent (the proof test passes under the mutant); CAUGHT is the result for a killer.
- Checks: `rustfmt --edition 2024 --check` clean on the four files, `cargo clippy -p pr-app --tests -- -D warnings` clean, `cargo test -p pr-app --test n2_*` green (17 tests).

## What the proofs do and do not cover

- Exhaustive over the input classes of the function: `dotnet_max` (`a = +0.0`), `intersect` (NaN, infinity, both zeros, signs), `format_fixed` (first dropped digit), `GlideFrameClock` (all sequences of length 4 over the alphabet), `greater_than(x, x)`.
- Boundary sweeps over every f64 neighbour: `is_unit` and `is_fit`, plus an exact significand argument executed in the test.
- Sampled differential, not exhaustive over f64^k: the five layout sites (77:16, 349:15 `<=`, 353:22 `<=`, and the unreachable 96:10 and 108:10), `fit_zoom`, `fit_axis_zoom`. The samples include NaN, both infinities, both zeros, `f64::MAX` and its neighbours, 128 ordinary and 128 overflow-scale round-off witnesses and their ulp neighbours; the counters in the tests fail the run if the sample stops reaching the divergent branch. They are bounded runs: a counterexample outside the sample is not excluded. 96:10 and 108:10 are equivalent by control flow (the line is reached only with `a != b` and no NaN); the run confirms the divergence counter is 0.
- The model copies in the test files are copies of the port, not of the C# source; the real function is the only thing compared with them. The two new killers assert the Rust behaviour, which follows the C# formulas literally (`(inf - inf) * 0.5` is NaN in C# too); they were not run against the C# oracle in this task.

## Findings for the owner (text only, no production change)

1. M1's equivalence claims for `layout.rs:361:12` and `layout.rs:349:15 ==` were wrong; both are now killed by hand-written tests. The cause in both cases is the same: lengths are sanitized to be finite on input, but `natural * (box / natural)` can overflow to `+inf` or round above `box` when a bound is near `f64::MAX`, and the pipeline then runs on infinities. The C# code has the same arithmetic, so the NaN offset (361) and the height of 6.7e-304 (349) are parity behaviour, not a Rust bug. Whether the owner wants the extreme-value inputs clamped is a product decision; any such change would break bit-exact parity and needs an ADR.
2. M2's open survivor `render_geometry.rs:479:18` is closed by a searched matrix (above).
3. P-111 remark: in cargo-mutants 27.1.0 `-F` is `--re` and narrows correctly (verified here by the `Found N mutants` lines).
