## Behaviour

Startup reconcile (`reconcile::reconcile_one`, single Recycle, Prepared, not live):

| Source file | Bin answer | Result |
|---|---|---|
| exists | not asked | Failed, `SourceStillExistsAfterRecovery` (unchanged) |
| gone | item in bin (path, size, write time) | Committed |
| gone | no such item | Failed, `PendingUnconfirmed` (new; the Recovery list shows it, retry rules unchanged) |
| gone | bin could not be asked (`Err`) | nothing appended, entry stays Prepared, warning `Journal reconcile: skipped {id}: {error}`, retried at the next start (INV-3..INV-6 kept: never Committed by guess) |
| gone | no bin wired (`OperationJournalOptions::recycle_bin = None`) | Committed as before (C# R15 as is; only unit tests and non-production composition) |

Group Recycle (`group_members` non-empty) is untouched: the decision names the single Recycle only.

## PARITY and ADR wording for the lead

PARITY `Different` row (reconcile unit, e.g. F-14 area):
`Different (P-331, D7): startup reconcile of a single Recycle whose source is gone also asks the Recycle Bin for the item (path, size, write time). In bin: Committed; not in bin: Failed PendingUnconfirmed; bin cannot be asked: stays Prepared. C# baseline e7c2fcd8 (R15) writes Committed on "source gone"; the C# branch feat/reconcile-recycle-bin-check (396d5ac2) has the same rule. Different until that branch merges and the baseline is synced. Proof: pr-core/tests/journal_reconcile_recycle_bin.rs.`

ADR text (`docs/adr/`, P-331):
> Decision. The startup reconcile of a single Recycle entry whose source file is gone no longer trusts the missing source. With a Recycle Bin wired, it
> asks the bin (read-only, same metadata match as restore) and writes Committed only when the item is there. If the item is not there it writes Failed with the
> existing `PendingUnconfirmed` code so the user sees it in Recovery; if the bin cannot be asked it appends nothing and the entry stays Prepared until the next
> start (INV-5: failure is never mistaken for "not found", never for "found"). Group Recycle entries keep the old rule. Reason: a vanished source is equally true
> after a permanent delete or a move away. The C# repo gets the same change (branch `feat/reconcile-recycle-bin-check`); until it merges this is a deliberate difference.
> Consequence: startup reconcile may open the Shell Recycle Bin once per Prepared single-Recycle entry (bounded by 20 s each, on the startup worker).
