## New killers

`crates/pr-app/tests/w8_zoom_killers2.rs` uses TempRoot-owned files, small fake images and a queued runner. No sleeps, fixture-mtime edits, real-time elapsed assertions, real config or Recycle Bin calls.

- Mailbox: zero-duration readiness checks on empty/nonempty queues, ordered drain, clone sharing and exact wake counts. These fail synchronously when send/drain/emptiness/readiness is broken.
- Platform image identity: same versus different allocations for pixels and opaque objects, plus mixed variants.
- RAW state trace: the fake delay receives 300 ms, the timer/decode are pumped separately, visibility effects are ordered, the held original is released on reset, and queued-event/pending-load getters reflect each transition.
- Stale timer: queue an old indicator message, supersede its target, then pump it while the current slot exists. It must not show the current indicator; the current timer must show it. Cancelled queued decodes never reach the fake decoder.
- Rename after successful decode but before pumping: the old `Ok` already in the inbox must be discarded, then the new path must decode and be shown with the new dimensions/path. This directly observes deletion of target `id`, in addition to token/path/key.

The initial remainder run missed the `key` field deletion. The new rename killer requires the new target to complete with the exact `ShowImage` / `OriginalShown` sequence, and also asserts `try_get_known_original_dimensions` under the renamed file's freshly read key. This uses the unchanged file's length/mtime and a real rename inside TempRoot, with no timestamp manipulation. The unmutated source passes both assertions. The isolated key-mutant log fails the expected presentation sequence before reaching the dimensions assertion; the cache assertion is additional coverage, not the claimed failure site of that reproof.

The last scenario corrects the overly broad equivalence explanation in [W9-RENAME-LANE](W9-RENAME-LANE-2026-10-30.md): a service cancellation check cannot retroactively change an `Ok` completion already queued before cancellation. This is a test coverage correction, not a production defect.
