## Missed mutants: equivalence and limited output-only explanations

The raw MISSED count is preserved. G17 predicate equivalents are fully justified below.
Timer slicing, FILE_BUFFER and idle-flush changes are only output/state explanations;
they are **not claimed fully behaviorally equivalent**, because timing, I/O grouping
or failure scheduling can change. Those remain gaps for a strict Done verdict.

- `perf_csv.rs:157:26 > -> >=`: reached only for `is_infinite()` values;
  positive/negative infinity are never zero, so both predicates give the same sign.
- `perf_csv.rs:170:24 > -> >=`: digits initially contain 17 decimal digits of a
  nonzero value (zero returned earlier). Trimming can never shorten below one
  digit under either predicate; if one digit remains it is nonzero and does not
  end in `0`. The loop therefore performs the same iterations.
- `writer.rs:123:38 - -> +`: both paths check cancellation and elapsed >= span
  before sleeping. Neither changes the timer outcome. The mutant only changes
  the sleep slice, capped by TIMER_SLICE (10 ms), and may delay the next check.
  This is equivalence of logical outcome, not a measured claim of equal wake-up latency.
- `perf_csv.rs:39:31 * -> +` and `* -> /`: change FILE_BUFFER capacity
  (65536 -> 1088 / 0). The final byte stream is unchanged. This is equivalence
  of serialized output only; the number/grouping of I/O calls and flush latency
  can change and were not measured. No performance parity claim follows.
- `perf_csv.rs:366:44 > -> ==`: a quiet nonempty buffer skips the first idle
  flush, resets unflushed to zero, then flushes at the next interval.
  `> -> >=` flushes even an empty buffer. Final successful bytes are unchanged,
  but latency/flush-call behavior differs and is not closed by this lane.
- `perf_csv.rs:439:36/43/90/93`: prior W2-FS evidence explains local successful
  opens through std's automatic Windows path prefixing. This lane preserves the
  raw MISSED verdict and does not claim exhaustive/UNC equivalence from that
  historical local probe. The UNC gap remains.
- `perf_csv.rs:456:5` replacements: `#[cfg(not(windows))]` removes this function
  entirely on this Windows host. Both replacements are Windows-unobservable,
  not evidence of behavior on another OS.
