## Proposed wording (the lead adds these to `docs/PROPOSED-DECISIONS.md`)

- **P-310 (G2 H3 part 2, fix)**: After an input zoom the HUD is not refreshed. Make `MainViewModel::on_viewer_zoom_mode_changed` (or the shell input, by forwarding `ViewerUpdate.changes`) include `DisplayZoomPercent` so `apply_viewer_update` runs `refresh_overlay()` (C# `MainViewModel.cs:140-143`). Red test first: in `viewmodels_main_zoom_events.rs`, `on_viewer_zoom_mode_changed` after `set_zoom(2.0)` must return `overlay` containing `InfoOverlayProperty::ZoomIndicatorText`; then a native or e2e check that the HUD shows "200%" after a wheel. This restores C# behaviour, not a deviation. Native confirmation not done.
- **P-311 (G10 M1, decision)**: Keep Rust identical to C# (surface left without target after a failed non-loss `ResizeBuffers`, error returned to the caller, next successful resize recovers) and record it as intentional; or deviate (call `recreate_device()` after that failure, or make `begin_draw_context` return `Err` without target), which needs an ADR and a `Different` PARITY row. Recommendation: keep, since the caller already receives `Err`; revisit only if a real freeze is observed.
- **P-312 (G10 L1, hardening)**: Only when a code path appears that re-enters the cache from a backend or device-recreated hook: release `state.borrow_mut()` around `backend.upload` / `upload_rows` and re-borrow to record the result. No behaviour change; red test with a re-entering fake backend at that time. Until then keep the D-W8B4I-1 note.
- **P-313 (G10 L2, L3, hardening)**: `draw_image_oriented`: pop only when the push was applied; `pop_clip`: decrement the depth only after the D2D pop was issued (or when `context()` is `Some`). Rust-only behaviour for a device released mid-frame; C# throws there. Needs an in-crate test with a released device (inside the `draw_context.rs` tests); low priority, no Different row.
