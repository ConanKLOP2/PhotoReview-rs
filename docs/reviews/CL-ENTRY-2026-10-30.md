Every path through it creates a `Win32UiDispatcher` and a message loop and then opens a real main window (or a failure message box); the default options carry no seam. Running it in a test would open the real GUI, which this lane forbids. These are unobservable in a window-free test, not equivalent: the attended native tests `exe_process` (`exe_with_smoke_argument_shows_window_and_exits_zero`, ignored) would catch `1` and `-1` (smoke exits 0); `0` is only caught by a run that returns a non-zero code (smoke timeout 7 or startup failure 1), which needs an attended machine.
