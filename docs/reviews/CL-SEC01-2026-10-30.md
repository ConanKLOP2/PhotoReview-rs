## 1. Method

`cargo mutants -p <crate> --baseline skip -j 1 --file ... -F ...` with an own `CARGO_TARGET_DIR` (`target-mut`) and `--output`
(`mut-out-sec*`), one process at a time, `--timeout 90` (writer subset: `--timeout 30` to fit the box). Native tests need
`--include-ignored`; the form that works is

    --cargo-test-arg=resolve --cargo-test-arg=-- --cargo-test-arg=--include-ignored --cargo-test-arg=--test-threads=1

(the name filter first, then `--`, then the test-binary flags). Native tests ran under `TempRoot` only (junctions in the
temp folder); the real Recycle Bin, `%LOCALAPPDATA%\PhotoReview` and real config were not touched. `stage-native.ps1` ran first.

## 2. Finding that changes more than these rows: the W2-14 native mutation passes were invalid

`docs/reviews/W2-FS-EVIDENCE-2026-10-29.md` section 2 states that native passes were run with
`--cargo-test-arg=--include-ignored --cargo-test-arg=--test-threads=1`. With the toolchain of this repo cargo rejects that
(`error: unexpected argument '--include-ignored' found`, because the flag lands before the `--`). I ran exactly that form
first by mistake: every one of the 17 mutants was reported "caught" (`*** result: Failure(1)`, no test executed), 17 of 17.
So a mutant reported "caught" in passes 2-7 of that run (about 390 of the 427 `physical.rs` mutants; the same form is
named in the W2 evidence for every pass that needed native tests) is not evidence of a test failure. Direct proof that the
result differs once the arguments are right: the reported "pass 2: 35 / 0 / 0 / 0" covered `final_link_target`
and `immediate_link_target`, yet with the correct arguments (all 64 native `io_physical` tests green, 22 s) three of those
mutants survive (section 3). (The CX lanes already use the correct form, `CX-MUTW4` line 82.) Consequence: X-physical-fs
cannot stay Done.

## 3. SEC-01 / F-05: `final_link_target`, `final_link_target_slow`, `immediate_link_target`

Run 1 (21 mutants, binaries `io_physical` + `w2_sec_killers2`, filter `resolve`, native included): 21 tested, 18 caught,
3 missed, 0 timeout, 0 unviable (the 21 include the new walk function and its seam). Run 2 (the 3 missed, all 64
`io_physical` tests, native included): 3 of 3 still missed.

Doubt 1 of the audit (the `hops += 1` mutant) is confirmed and settled:

- The OS stops a chain of more than 63 reparse points with ERROR_CANT_RESOLVE_FILENAME (1921) itself, so
  `fs::canonicalize` fails with 1921 and `final_link_target` returns it (the `Err(err)` arm) without ever reaching
  `final_link_target_slow`. The slow walk only runs when the OS says the target is unreachable (file/path not found ...),
  i.e. for chains of at most 63 links, where `hops` can never exceed `MAX_FOLLOWED_LINKS`. The cap therefore cannot be
  exercised by any junction (or symlink) chain: the comment at `io_physical.rs:1369` is right and the PARITY row was wrong
  to say the cap survivors "are caught when the native tests are included".
- Proof: the argument above is static (I did not run the junction-only tests against `hops *= 1` with correct arguments); the new seam tests do catch the mutant (table below).
- Fix: no behaviour change. `final_link_target_slow` now delegates to `follow_link_chain(link, step)` (the same loop with the
  one-link step injected) and a `#[doc(hidden)]` `follow_link_chain_for_tests` exposes it, as for other `physical.rs` seams.
  New file `crates/pr-core/tests/w2_sec_killers2.rs` (in-memory link table, no disk):

| Mutant (physical.rs, after the refactor) | Result | Killer |
|---|---|---|
| `hops += 1` -> `-= 1` (usize underflow panic) and `*= 1` (counter never rises; a cycle would never end) | caught | `resolve_chain_of_64_links_fails_with_1921_after_the_64th_hop`, `resolve_link_cycle_fails_with_1921_after_a_bounded_walk` |
| `hops > MAX` -> `>=`, `<`, `==` | caught (63 links must resolve; 64 must fail at the 64th hop) | `resolve_chain_of_exactly_63_links_resolves_to_its_last_target`, `..._64_links_...` |
| `final_link_target_slow` / `follow_link_chain` / seam -> `Ok("")` / `Ok("xyzzy")` | caught | the same plus `resolve_path_that_is_not_a_link_has_no_final_target_and_a_short_chain_returns_its_last` |
| `immediate_link_target` -> `None`, `Some("")`, `Some("xyzzy")`; `== 0` -> `!= 0` | caught | native `resolve_real_path_*junction*` tests |
| `final_link_target` -> `Ok("")` / `Ok("xyzzy")`; guard -> `false` | caught | native junction tests |

Survivors, not killed:

- `physical.rs:983` `match guard is_path_unreachable(&err)` -> `true` (SURVIVES, native included). With the mutation an OS
  error that is neither "unreachable" nor a loop (e.g. bad reparse data) would be followed by hand and return the last
  target instead of failing closed. A loop (1921) gives the same error by the manual walk, so only another error code
  distinguishes the two; such an error needs a malformed reparse point, which a test cannot create without `unsafe`
  (not allowed in `pr-core`). Accepted survivor, not equivalent: this is the fail-closed property of RV-S06.
- `physical.rs:1025` `&` -> `|` and `&` -> `^` in `immediate_link_target` (`attributes & REPARSE == 0`): equivalent.
  For a non-reparse entry `fs::read_link` fails and `.ok()?` returns `None` anyway; the check only saves the call.
  `^` differs only for an entry whose attributes are exactly `REPARSE_POINT`, which `read_link` would then read, still
  yielding the same target for a link.
- `file_exists_full` probe: not re-run (not part of the 21).

Row decision: SEC-01 / F-05 Done -> Partial (the fail-closed guard survivor and the invalid W2-14 native passes; the
destination policy part stays proved by `W3-05-UNDO-MUTATION.md`: 15/15, 12 caught, 3 unviable).
