# E3 implementation: startup and dialogs hardening (P-340, P-341, P-342 + P-170, P-343)

Branch `fix/hardening-startup-dialogs`, crates `pr-shell`, `pr-platform-win`. Owner decision "do all of group B" (chat, 2026-11-03).

## P-340 SharedDialogService forwards every member
- Change: `crates/pr-shell/src/composition/adapters.rs` forwards `prompt_add_external_editor`, `prompt_default_external_editor`, `prompt_rename` to `Win32DialogService` (they were the trait defaults, answering `None`).
- Tests (`crates/pr-shell/tests/composition_adapters.rs`): `shared_dialog_service_forwards_the_three_defaulted_prompts` and `shared_dialog_service_every_member_reaches_the_port_or_a_fake_of_the_service` (recording fake, list `DIALOG_SERVICE_MEMBERS` of all 14 members). Both were red on master (`left: None`, `prompt_rename was not forwarded`), green after.
- Limit: a NEW trait member must be added to the list by hand; Rust cannot enumerate trait members. The compile-time guard is the existing defaulted-method list in the doc comment.

## P-341 LazySecondaryPort::get survives a panicking factory
- Change: `dialog_service.rs`, factory run under `catch_unwind(AssertUnwindSafe(..))`, a panic is kept as `None` (never retried; the factory was already taken).
- Test: `dialogs_service.rs::lazy_secondary_port_get_answers_none_when_the_factory_panics_and_does_not_retry` (red on master: the panic unwound out of `get`).

## P-342 + P-170 cloak deadline thread cannot be spawned
- Change: `shell_startup/cloak.rs`. New `schedule_with_spawner(delay, job, &ThreadSpawner, Option<&dyn Log>)` (`#[doc(hidden)]`, the test seam); `schedule_on_thread` calls it with the real spawner. The job is kept in a slot, so on spawn failure it runs at once on the calling thread (it only posts the reveal to the UI dispatcher) and the error is logged. Before: the job was dropped with the failed closure, the deadline never fired, the window stayed cloaked until a first frame. `StartupCloakOptions` gets `log: Option<Arc<dyn Log>>` (the default scheduler logs through it); `startup/window.rs` passes the graph log. Two test struct literals got `log: None`.
- Tests (`shell_startup_cloak.rs`): spawn failure reveals now and logs one error; without a log still reveals; normal branch runs once on the spawned thread, no log; dropping the handle cancels. The first test is red on master by construction (the job count would be 0); the seam did not exist, so it was written together with the seam.

## P-343 StartupTask::join failures
- Only `run.rs` joins a `StartupTask` (`PhotoReview.EarlyDecodeStart`). `phase_one.rs` only spawns the task; its `h.join()` is the placement `PrefetchHandle`, where `None` is the normal "no saved placement" answer, so nothing is logged there.
- Change: `run.rs::join_logged(task, what, &dyn Log)` logs an info line when the join gave no result; the worker uses the graph log (NullLog when no graph). Behaviour otherwise unchanged.
- Tests: `crates/pr-shell/tests/startup_task_join_log.rs` (panic is logged at info only; success and `Some(None)` are silent).
